# 03 - 内核模块开发

模块（module）是可以在运行时加载到内核里的 `.ko` 文件（kernel object）。它运行在 ring0，与内核本身共享同一地址空间和同一套符号。

> ⚠️ **加载内核模块即获得 ring0 权限。** 一个 `while(1);` 或一次空指针解引用就能让整机崩溃（kernel panic），写坏内核数据结构可以静默提权或绕过所有用户态防护。**只在虚拟机或你完全拥有的测试机上练习。** 宿主机的内核模块请一律在 QEMU 里做。

相关文档：[README](../README.md) · [01-内核构建与调试](01-内核构建与调试.md) · [02-源码结构与阅读方法](02-源码结构与阅读方法.md) · [04-内核安全与攻防](04-内核安全与攻防.md)

### 1.1 `hello.c`

```c
// SPDX-License-Identifier: GPL-2.0
/*
 * 最小内核模块示例。
 * 编译：make
 * 加载：sudo insmod hello.ko
 * 查看：sudo dmesg | tail
 * 卸载：sudo rmmod hello
 */

/* 让本文件里所有 pr_* 调用自动带上 "hello: " 前缀。
 * 必须在任何 #include <linux/printk.h> 之前定义。 */
#define pr_fmt(fmt) KBUILD_MODNAME ": " fmt

#include <linux/module.h>    /* MODULE_LICENSE, module_init/exit, MODULE_* 宏 */
#include <linux/kernel.h>    /* pr_info 等 */
#include <linux/init.h>      /* __init, __exit */

/* 模块元信息：这些会出现在 modinfo 输出里 */
MODULE_LICENSE("GPL");                       /* 必需，否则内核标记为 tainted */
MODULE_AUTHOR("Your Name <you@example.com>");
MODULE_DESCRIPTION("Minimal hello world kernel module");
MODULE_VERSION("1.0");

/*
 * __init 表示这个函数只在加载时执行一次，执行完所占的 .init.text 段
 * 会被释放（见 include/linux/init.h:45）。
 */
static int __init hello_init(void)
{
	pr_info("loaded, version %s\n", "1.0");
	pr_info("hello, kernel! jiffies=%lu\n", jiffies);
	return 0;                 /* 返回 0 = 成功；返回负 errno = 加载失败 */
}

/*
 * __exit 只在模块可卸载时才会被编译进去（见 include/linux/init.h:79）。
 */
static void __exit hello_exit(void)
{
	pr_info("unloaded\n");
}

/*
 * 把上面两个函数注册为模块的入口/出口。
 * 这两个宏展开为 __initcall / __exitcall，
 * 把函数指针放进 .initcall6.init 段，由 do_one_initcall() 在加载时调用。
 * 见 include/linux/module.h:89 (module_init) / :101 (module_exit)
 */
module_init(hello_init);
module_exit(hello_exit);
```

### 1.2 三个必须理解的宏

| 宏 | 作用 | 不写的后果 |
| --- | --- | --- |
| `MODULE_LICENSE("GPL")` | 声明许可证。定义在 `include/linux/module.h:230` | 内核会被标记为 **tainted**（污染），`EXPORT_SYMBOL_GPL` 的符号**无法使用**，部分调试功能被禁用 |
| `module_init(fn)` | 注册加载时调用的函数 | 模块加载后什么也不做（内核会认为它是"无生命"的） |
| `module_exit(fn)` | 注册卸载时调用的函数 | 模块无法卸载（或在卸载时泄漏资源） |

### 1.3 `__init` / `__exit` 是什么

它们是**段属性**，不是语法糖：

```c
/* include/linux/init.h:45 */
#define __init		__section(".init.text") __cold __latent_entropy ...
/* include/linux/init.h:79 */
#define __exit          __section(".exit.text") __exitused __cold notrace
```

- 带 `__init` 的代码被放进 `.init.text` 段，内核启动（或模块加载）完成后**整段内存被释放**。
- 后果：**不要从 `__init` 函数里把函数指针保存下来以后再用** —— 那段内存已经还给系统了，调用它就是执行一段随机数据。这是插件式代码里最常见的一类内核崩溃。
- 同理，`__initdata` 标记的数据也会被释放。

## 2. Makefile

### 2.1 外部模块（推荐，`make -C $KSRC` 写法）

`~/kmod-lab/hello/Makefile`：

```make
# 要构建的模块名。hello.o 由 hello.c 编译而来。
obj-m := hello.o

# 内核源码树或已安装的内核构建目录
# 用源码树：
KDIR ?= /home/rivo/Documents/hack-learn/kernel/src/linux
# 用已安装内核的头（需要 linux-headers-$(uname -r)）：
# KDIR ?= /lib/modules/$(shell uname -r)/build

# 外部构建目录（避免污染 KDIR）。指向一个可写目录。
KBUILD_OUTPUT ?=

PWD := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) $(if $(KBUILD_OUTPUT),O=$(KBUILD_OUTPUT),) M=$(PWD) modules

modules_install:
	$(MAKE) -C $(KDIR) $(if $(KBUILD_OUTPUT),O=$(KBUILD_OUTPUT),) M=$(PWD) modules_install

clean:
	$(MAKE) -C $(KDIR) $(if $(KBUILD_OUTPUT),O=$(KBUILD_OUTPUT),) M=$(PWD) clean

# 把当前目录下除源码外的构建产物删掉（make clean 有时删不掉 .ko）
distclean: clean
	rm -f *.ko *.o *.mod *.mod.c *.symvers *.order .*.cmd
	rm -rf .tmp_versions

.PHONY: all modules_install clean distclean
```

`obj-m` 的语法来自 `Documentation/kbuild/makefiles.rst`。变体：

```make
obj-m := foo.o              # 单个模块
obj-m += foo.o bar.o        # 多个模块
foo-objs := a.o b.o         # foo.ko 由 a.o 和 b.o 链接而成
foo-$(CONFIG_X) += c.o      # 条件加入
ccflags-y += -DDEBUG        # 只对本目录加编译标志
```

### 2.2 ⚠️ 常见误用

| 错误写法 | 问题 |
| --- | --- |
| `obj-m += hello.c` | 要用 `.o`，不是 `.c` |
| `make -C $KSRC` 但没给 `M=` | 会尝试编译整个内核 |
| `M=$KSRC` | `M=` 必须是**外部模块的目录**，不是内核源码树 |
| `obj-m := hello.o` 写成 `obj-M` | 大小写敏感，不会生效 |
| 在 `all:` 里写 `cd $(KDIR) && make ...` | 会改变 `M=` 的语义，模块找不到源码 |
| `PWD` 用 `pwd` 命令而非 `$(shell pwd)` | 在递归 make 中会取错目录 |

### 2.4 内建方式（把模块编进内核本身）

如果你的模块需要跟随内核一起构建，把源码放进内核树并改 Kconfig/Makefile。以 `samples/` 为模板（实测 `samples/trace_printk/` 就是完整范例）：

```bash
# 目录结构（在内核树里）
$KSRC/samples/mymod/
├── Kconfig
├── Makefile
└── mymod.c
```

`Kconfig`：

```
# SPDX-License-Identifier: GPL-2.0-only
config SAMPLE_MYMOD
	tristate "Build mymod example"
	depends on SAMPLES
	help
	  Say Y here to build the mymod example.
	  To compile this as a module, choose M here.
```

`Makefile`：

```make
obj-$(CONFIG_SAMPLE_MYMOD) += mymod.o
```

然后让上一级 `samples/Kconfig` `source "samples/mymod/Kconfig"`、`samples/Makefile` 加 `obj-$(CONFIG_SAMPLE_MYMOD) += mymod/`，再 `make menuconfig` 打开它。

`samples/` 里可以直接照抄的现成例子（实测存在）：`samples/trace_printk/`、`samples/kobject/`、`samples/kfifo/`、`samples/kprobes/`、`samples/ftrace/`、`samples/landlock/`、`samples/seccomp/`、`samples/livepatch/`、`samples/bpf/`。

## 3. 加载、卸载与查看

```bash
# 加载
sudo insmod hello.ko
# 参数形式
sudo insmod hello.ko who=alice times=3

# 查看是否加载 + 参数值 + 依赖
lsmod | head -3
lsmod | grep hello
cat /proc/modules | grep hello
sudo modinfo hello.ko
sudo modinfo -p hello.ko        # 只列参数

# 内核日志
sudo dmesg | tail -5

# 卸载
sudo rmmod hello
sudo dmesg | tail -3
```

### 3.1 工具对照

| 命令 | 作用 | 备注 |
| --- | --- | --- |
| `insmod file.ko` | 加载**指定路径**的模块 | 不处理依赖；参数直接跟 `key=value` |
| `rmmod name` | 卸载模块（名字不带 `.ko`） | 有引用计数时会失败：`Module hello is in use` |
| `modprobe name` | 按模块名加载，**会自动解析并加载依赖** | 需要在 `/lib/modules/$(uname -r)/modules.dep` 中能找到 |
| `modprobe -r name` | 卸载及其不再被使用的依赖 | 比 `rmmod` 安全 |
| `lsmod` | 列出已加载模块（读 `/proc/modules`） | 第三列 `Used by` 是引用计数与使用者 |
| `modinfo file.ko` | 显示 `MODULE_*` 元信息、参数、签名、`vermagic` | 排查版本不匹配第一选择 |
| `dmesg` | 内核日志 | 模块里的 `pr_info` 都在这 |
| `depmod -a` | 重新生成 `modules.dep`、`modules.alias` 等索引 | `make modules_install` 会自动调用 |
| `modprobe --show-depends name` | 打印会加载哪些依赖 | 调试依赖问题 |
| `/sys/module/<name>/` | 模块的 sysfs 视图 | `parameters/`、`sections/`、`holders/` |
| `/proc/kallsyms` | 内核与模块的符号地址 | 需 `CONFIG_KALLSYMS` |

### 3.2 `depmod` 与 `/lib/modules/$(uname -r)/`

```
/lib/modules/7.3.0-rc3-learn/
├── kernel/                     # 模块本体，按源码目录结构镜像放置
│   ├── drivers/char/hello.ko
│   └── fs/ext4/ext4.ko
├── modules.dep                 # 模块 -> 依赖模块 的映射
├── modules.dep.bin             # 上面文件的二进制索引（modprobe 快速查询用）
├── modules.alias               # 设备别名 -> 模块（热插拔用）
├── modules.alias.bin
├── modules.symbols             # 符号 -> 提供该符号的模块
├── modules.symbols.bin
├── modules.builtin             # 编进内核（=y）的模块列表
├── modules.builtin.modinfo
├── modules.softdep
├── modules.devname
├── build -> /home/rivo/.../kernel/src/linux        # 软链接，M= 的 KDIR 常指它
└── source -> /home/rivo/.../kernel/src/linux
```

| 索引文件 | 由谁生成 | 用途 |
| --- | --- | --- |
| `modules.dep` | `depmod` | `modprobe` 据此加载依赖 |
| `modules.alias` | `depmod`（读 `.mod.c` 里的 `MODULE_ALIAS`） | udev 热插拔时按设备 ID 找驱动 |
| `modules.builtin` | `depmod`（读 `modules.builtin.modinfo`） | 区分「编进内核」与「可加载模块」 |
| `build` / `source` 软链接 | `modules_install` | 外部模块的 `KDIR=/lib/modules/$(uname -r)/build` |

**`modprobe` 找不到你的模块**，通常因为：没执行 `make modules_install`（只做了 `insmod`）；或装到了别的版本目录下。检查：

```bash
ls -d /lib/modules/$(uname -r)
find /lib/modules -name 'hello.ko'
sudo depmod -a "$(uname -r)"
modprobe --show-depends hello
```

## 4. 模块参数

模块参数让加载时/运行时可以传值，出现在 `/sys/module/<name>/parameters/`。

```c
// SPDX-License-Identifier: GPL-2.0
#define pr_fmt(fmt) KBUILD_MODNAME ": " fmt

#include <linux/module.h>
#include <linux/moduleparam.h>   /* module_param / module_param_array / MODULE_PARM_DESC */
#include <linux/kernel.h>
#include <linux/init.h>

static int    times   = 1;
static char  *who     = "world";
static bool   verbose;
static unsigned int ids[4];
static int    ids_count;

/* module_param(变量名, 类型, sysfs 权限)
 * 定义见 include/linux/moduleparam.h:139
 * 类型可用：bool, int, uint, long, ulong, charp, short, ushort 等 */
module_param(times, int, 0644);
MODULE_PARM_DESC(times, "重复打印的次数（默认 1）");

module_param(who, charp, 0644);
MODULE_PARM_DESC(who, "打招呼的对象（默认 world）");

module_param(verbose, bool, 0644);
MODULE_PARM_DESC(verbose, "是否输出额外信息");

/* 数组参数，加载时写成 ids=1,2,3,4 */
module_param_array(ids, uint, &ids_count, 0644);
MODULE_PARM_DESC(ids, "一组无符号整数，最多 4 个");

static int __init param_init(void)
{
	int i;

	if (times < 0) {
		pr_err("times 不能为负数（收到 %d）\n", times);
		return -EINVAL;                /* 拒绝加载示例 */
	}

	for (i = 0; i < times; i++)
		pr_info("hello, %s!\n", who);

	if (ids_count) {
		pr_info("ids_count=%d:", ids_count);
		for (i = 0; i < ids_count; i++)
			pr_cont(" %u", ids[i]);    /* pr_cont 续行，不重复前缀 */
		pr_cont("\n");
	}

	if (verbose)
		pr_info("verbose 已开启\n");

	return 0;
}

static void __exit param_exit(void)
{
	pr_info("bye\n");
}

module_init(param_init);
module_exit(param_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Module parameter demo");
```

使用：

```bash
sudo insmod param.ko times=3 who=alice ids=10,20,30 verbose=1
sudo dmesg | tail -8

# 运行时读写（权限位 0644 允许非 root 读，写需要 root）
cat  /sys/module/param/parameters/times
echo 5 | sudo tee /sys/module/param/parameters/times

sudo rmmod param
```

⚠️ **`charp` 权限设为 `0644` 时，任何能写该 sysfs 文件的用户都能让你把 `who` 指向任意地址 —— 这是提权漏洞。** 除 `0444`（只读）外，涉及指针的参数权限一律用 `S_IRUGO`/`0444`，或者加 `module_param_cb()` 自己实现 `set()` 做校验。

`module_param` 的权限常量（`S_IRUGO` 定义在 `include/linux/stat.h:11`，`S_IWUSR` 在 `include/uapi/linux/stat.h:31`）：

| 常量 | 数值 | 含义 |
| --- | --- | --- |
| `S_IRUGO` | 0444 | 所有用户可读（= `S_IRUSR|S_IRGRP|S_IROTH`） |
| `S_IWUSR` | 0200 | 仅 root 可写 |
| `S_IRUGO | S_IWUSR` | 0644 | 所有用户可读，root 可写 |

## 5. 字符设备驱动完整示例

这是「写驱动」的最小完整闭环：注册设备号 → 注册 `cdev` → 实现 `file_operations` → 暴露 `/dev` 节点。

### 5.1 关键 API 与它们在哪

| API | 声明位置 | 作用 |
| --- | --- | --- |
| `alloc_chrdev_region()` | `fs/char_dev.c:233`，声明在 `include/linux/fs.h` | 由内核**动态分配**一个主设备号 |
| `register_chrdev_region()` | `fs/char_dev.c` | 用**指定**的主设备号注册（冲突则失败） |
| `unregister_chrdev_region()` | `fs/char_dev.c` | 释放设备号 |
| `cdev_init()` | `include/linux/cdev.h:23` | 把 `struct cdev` 与 `file_operations` 绑定 |
| `cdev_add()` | `include/linux/cdev.h:29`，实现 `fs/char_dev.c:476` | 把 `cdev` 注册到系统，之后 `open()` 才能找到 |
| `cdev_del()` | `include/linux/cdev.h` | 注销 |
| `class_create()` | `include/linux/device/class.h:226` | 创建 `/sys/class/<name>` |
| `device_create()` | `include/linux/device.h` | 在 class 下创建设备，**udev 会据此自动创建 `/dev` 节点** |
| `copy_to_user()` / `copy_from_user()` | `include/linux/uaccess.h:226` / `:218` | 在内核与用户地址空间之间搬运数据；失败返回**未拷贝的字节数** |
| `container_of()` | `include/linux/container_of.h` | 由成员地址反推外层结构体地址（内核里最常用的宏之一） |

### 5.2 完整源码 `mychardev.c`

```c
// SPDX-License-Identifier: GPL-2.0
/*
 * 最小字符设备驱动：一个 4 KB 的内核缓冲区
 *   echo hello > /dev/mychardev    写入（覆盖式）
 *   cat /dev/mychardev             读出
 */

#define pr_fmt(fmt) KBUILD_MODNAME ": " fmt

#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>
#include <linux/fs.h>            /* struct file_operations, alloc_chrdev_region */
#include <linux/cdev.h>          /* struct cdev, cdev_init, cdev_add */
#include <linux/device.h>        /* class_create, device_create, device_destroy */
#include <linux/uaccess.h>       /* copy_to_user, copy_from_user */
#include <linux/slab.h>          /* kmalloc, kfree */
#include <linux/mutex.h>         /* mutex */
#include <linux/errno.h>

#define DEV_NAME   "mychardev"
#define BUF_SIZE   4096

/* 每个字符设备的私有状态。可以有多个实例，各自一份。 */
struct mydev {
	struct cdev      cdev;
	struct device   *device;
	struct mutex     lock;        /* 保护 buf / buf_len / buf_pos 的一致性 */
	char            *buf;
	size_t           buf_len;     /* 已写入的有效字节数 */
	loff_t           buf_pos;     /* 读/写位置 */
};

static dev_t            mydev_t;      /* 主设备号 + 起始次设备号 */
static struct class    *mydev_class;
static struct mydev     mydev;

/* ---- 打开：每次 open 都拿到同一个 mydev，引用计数由内核维护 ---- */
static int mydev_open(struct inode *inode, struct file *file)
{
	/*
	 * 方式 A：从 inode 的 cdev 反推容器（多个设备实例时用这个）
	 *   struct mydev *dev = container_of(inode->i_cdev, struct mydev, cdev);
	 * 方式 B：单设备时直接引用全局变量（本例）
	 */
	file->private_data = &mydev;
	pr_info("open: pid=%d comm=%s\n", current->pid, current->comm);
	return 0;
}

static int mydev_release(struct inode *inode, struct file *file)
{
	pr_info("release: pid=%d\n", current->pid);
	return 0;
}

/* ---- 读：把内核缓冲区内容拷给用户 ---- */
static ssize_t mydev_read(struct file *file, char __user *ubuf,
			  size_t count, loff_t *ppos)
{
	struct mydev *dev = file->private_data;
	ssize_t ret;

	if (mutex_lock_interruptible(&dev->lock))
		return -ERESTARTSYS;

	if (*ppos >= dev->buf_len) {      /* 已读到末尾 */
		ret = 0;
		goto out;
	}

	/* 不允许读超出有效数据，也不允许读超出用户请求的量 */
	if (count > dev->buf_len - *ppos)
		count = dev->buf_len - *ppos;

	/*
	 * copy_to_user 返回"没能拷贝的字节数"，成功时为 0。
	 * 绝不能用 memcpy 代替：用户指针可能非法、可能指向内核地址。
	 */
	if (copy_to_user(ubuf, dev->buf + *ppos, count)) {
		ret = -EFAULT;
		goto out;
	}

	*ppos += count;
	ret = count;
	pr_info("read: %zd bytes, pos=%lld\n", ret, *ppos);

out:
	mutex_unlock(&dev->lock);
	return ret;
}

/* ---- 写：把用户数据拷进内核缓冲区 ---- */
static ssize_t mydev_write(struct file *file, const char __user *ubuf,
			   size_t count, loff_t *ppos)
{
	struct mydev *dev = file->private_data;
	ssize_t ret;

	if (count > BUF_SIZE)
		count = BUF_SIZE;

	if (mutex_lock_interruptible(&dev->lock))
		return -ERESTARTSYS;

	if (count > BUF_SIZE - *ppos) {
		ret = -ENOSPC;                /* 缓冲区满 */
		goto out;
	}

	if (copy_from_user(dev->buf + *ppos, ubuf, count)) {
		ret = -EFAULT;
		goto out;
	}

	*ppos += count;
	if (*ppos > dev->buf_len)
		dev->buf_len = *ppos;

	ret = count;
	pr_info("write: %zd bytes, pos=%lld\n", ret, *ppos);

out:
	mutex_unlock(&dev->lock);
	return ret;
}

/* ---- ioctl（可选）：注意 arg 是用户态地址，要么拷贝要么校验 ---- */
#define MYDEV_IOC_RESET _IO('M', 0)
#define MYDEV_IOC_SIZE  _IOR('M', 1, int)

static long mydev_ioctl(struct file *file, unsigned int cmd, unsigned long arg)
{
	struct mydev *dev = file->private_data;
	int size;

	switch (cmd) {
	case MYDEV_IOC_RESET:
		mutex_lock(&dev->lock);
		dev->buf_len = 0;
		dev->buf_pos = 0;
		if (file->f_pos != 0)
			file->f_pos = 0;
		mutex_unlock(&dev->lock);
		return 0;
	case MYDEV_IOC_SIZE:
		size = dev->buf_len;
		if (copy_to_user((int __user *)arg, &size, sizeof(size)))
			return -EFAULT;
		return 0;
	default:
		return -ENOTTY;              /* 未实现的命令必须返回 -ENOTTY */
	}
}

/* ---- 文件操作表：内核通过它调用到你的代码 ---- */
static const struct file_operations mydev_fops = {
	.owner          = THIS_MODULE,       /* 引用计数，防止使用中卸载 */
	.open           = mydev_open,
	.release        = mydev_release,
	.read           = mydev_read,        /* 老式接口；新式是 .read_iter */
	.write          = mydev_write,       /* 老式接口；新式是 .write_iter */
	.unlocked_ioctl = mydev_ioctl,
	.llseek         = default_llseek,
};

static int __init mydev_init(void)
{
	int ret;

	/* 1) 分配设备号：主设备号由内核决定 */
	ret = alloc_chrdev_region(&mydev_t, 0, 1, DEV_NAME);
	if (ret) {
		pr_err("alloc_chrdev_region failed: %d\n", ret);
		return ret;
	}
	pr_info("major=%d minor=%d\n", MAJOR(mydev_t), MINOR(mydev_t));

	/* 2) 缓冲区与锁 */
	mutex_init(&mydev.lock);
	mydev.buf = kzalloc(BUF_SIZE, GFP_KERNEL);
	if (!mydev.buf) {
		ret = -ENOMEM;
		goto err_unregister;
	}

	/* 3) 注册 cdev */
	cdev_init(&mydev.cdev, &mydev_fops);
	mydev.cdev.owner = THIS_MODULE;
	ret = cdev_add(&mydev.cdev, mydev_t, 1);
	if (ret) {
		pr_err("cdev_add failed: %d\n", ret);
		goto err_free;
	}

	/* 4) 创建 /sys/class/mychardev 与设备节点（udev 会自动生成 /dev/mychardev） */
	mydev_class = class_create(DEV_NAME);
	if (IS_ERR(mydev_class)) {
		ret = PTR_ERR(mydev_class);
		pr_err("class_create failed: %d\n", ret);
		goto err_cdev;
	}

	mydev.device = device_create(mydev_class, NULL, mydev_t, NULL, DEV_NAME);
	if (IS_ERR(mydev.device)) {
		ret = PTR_ERR(mydev.device);
		pr_err("device_create failed: %d\n", ret);
		goto err_class;
	}

	pr_info("registered, try: echo hi > /dev/%s\n", DEV_NAME);
	return 0;

/* 错误路径必须逐级回退，顺序与上面相反 */
err_class:
	class_destroy(mydev_class);
err_cdev:
	cdev_del(&mydev.cdev);
err_free:
	kfree(mydev.buf);
err_unregister:
	unregister_chrdev_region(mydev_t, 1);
	return ret;
}

static void __exit mydev_exit(void)
{
	device_destroy(mydev_class, mydev_t);
	class_destroy(mydev_class);
	cdev_del(&mydev.cdev);
	kfree(mydev.buf);
	unregister_chrdev_region(mydev_t, 1);
	pr_info("unregistered\n");
}

module_init(mydev_init);
module_exit(mydev_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Minimal character device driver with a 4KB buffer");
MODULE_AUTHOR("Your Name");
```

### 5.4 这份代码里每一处「为什么」

| 代码 | 为什么这样写 |
| --- | --- |
| `.owner = THIS_MODULE` | 防止模块在使用中被卸载（否则卸载后函数指针悬空 = UAF） |
| `copy_to_user` / `copy_from_user` | 用户指针随时可能非法。`memcpy` 会直接 Oops；这两个函数处理缺页并返回错误 |
| 返回值是「未拷贝字节数」 | 常见 bug：写成 `if (copy_to_user(...) < 0)`。**这个函数返回 `unsigned long`，永远不小于 0** |
| `mutex_lock_interruptible()` | 可被信号打断，返回非 0 时**必须**直接返回 `-ERESTARTSYS`，不能继续访问被保护的数据 |
| `kzalloc(BUF_SIZE, GFP_KERNEL)` | `GFP_KERNEL` 表示允许睡眠；若在中断上下文用 `GFP_ATOMIC` |
| 错误路径逐级回退 | `goto` 链是内核标准风格。漏掉任何一级都会导致资源泄漏，多次 `insmod`/`rmmod` 后耗尽 |
| `-ENOTTY` | ioctl 未实现的命令必须返回 `-ENOTTY`，这是 ABI 约定 |
| `_IO` / `_IOR` | ioctl 命令号编码（方向、类型、序号、大小），定义在 `include/uapi/asm-generic/ioctl.h` |

## 6. 并发与锁基础

内核对同一个函数有多个并发执行者：多 CPU、抢占、中断、软中断、内核线程。**你写的每一行代码都可能在任意时刻被打断。**

### 6.1 先问三个问题

1. **这段代码运行在什么上下文？** 进程上下文（可睡眠）/ 软中断 / 硬中断（不可睡眠）。
2. **哪些数据是共享的？** 只读的全局量不需要锁；会被写的就是临界区。
3. **获取锁期间能睡眠吗？** 自旋锁持有期间**不能**睡眠。

### 6.2 互斥量（mutex）—— 可睡眠

适用：进程上下文、临界区较长、需要睡眠（如 `kmalloc(GFP_KERNEL)`、`copy_to_user`）。

```c
#include <linux/mutex.h>

static DEFINE_MUTEX(my_lock);          /* 静态定义 */

mutex_lock(&my_lock);
/* ... 临界区，可以睡眠 ... */
mutex_unlock(&my_lock);

/* 可被打断的版本：返回非 0 表示被信号打断，必须放弃操作 */
if (mutex_lock_interruptible(&my_lock))
	return -ERESTARTSYS;
...
mutex_unlock(&my_lock);

/* 非阻塞尝试 */
if (!mutex_trylock(&my_lock))
	return -EBUSY;
```

规则：**同一把 mutex 不能在硬中断上下文使用**（可能睡眠）。不要在持有 mutex 时再获取自旋锁（顺序反过来会导致优先级反转问题，通常会触发 lockdep 警告）。

### 6.3 自旋锁（spinlock）—— 不可睡眠

适用：临界区极短（几个指令）、可能在中断上下文执行。

```c
#include <linux/spinlock.h>

static DEFINE_SPINLOCK(my_slock);
static unsigned long flags;

/* 进程上下文：必须用 irqsave 版本，防止本 CPU 上中断到来造成死锁 */
spin_lock_irqsave(&my_slock, flags);
/* ... 极短的临界区，绝对不能睡眠/分配带 GFP_KERNEL 的内存/调 copy_to_user ... */
spin_unlock_irqrestore(&my_slock, flags);

/* 中断处理函数里：用普通版本（中断已被禁用） */
spin_lock(&my_slock);
...
spin_unlock(&my_slock);
```

变体选择树：

```
需要禁中断吗？
├── 是（锁可能被中断处理函数获取）
│   ├── 进程上下文  -> spin_lock_irqsave / spin_unlock_irqrestore
│   └── 中断上下文  -> spin_lock / spin_unlock
└── 否（锁只在进程上下文被获取）
    ├── 需要禁抢占？-> 默认 spin_lock 已隐含禁用抢占
    └── 只读为主    -> rwlock_t / spin_lock_bh（软中断场景）
```

**`spin_lock()` 失败的表现是整机挂死**，不是报错。这是内核调试里最难排查的一类问题。用 `CONFIG_PROVE_LOCKING`（lockdep）能提前发现大部分问题。

### 6.4 原子操作

不加锁的计数与标志位：

```c
#include <linux/atomic.h>

static atomic_t refcnt = ATOMIC_INIT(0);

atomic_inc(&refcnt);
atomic_dec(&refcnt);
if (atomic_dec_and_test(&refcnt))     /* 减到 0 返回 true，常用于释放 */
	kfree(obj);

int v = atomic_read(&refcnt);
atomic_set(&refcnt, 1);

/* 位操作 */
static unsigned long flags_bits;
set_bit(0, &flags_bits);
clear_bit(0, &flags_bits);
if (test_and_set_bit(0, &flags_bits))  /* 返回旧值，可做"仅一次"语义 */
	pr_info("already set\n");
```

⚠️ **引用计数不要用 `atomic_t`，用 `refcount_t`** —— 它会检测「从 0 再减」这类下溢，并在检测到错误时 `WARN` 甚至直接阻止（配合 `CONFIG_REFCOUNT_FULL`）。`refcount_t` 的语义差异见 `Documentation/core-api/refcount-vs-atomic.rst`。

```c
#include <linux/refcount.h>
static refcount_t refs = REFCOUNT_INIT(1);
refcount_inc(&refs);
if (refcount_dec_and_test(&refs))
	kfree(obj);
```

### 6.5 RCU 概念

RCU（Read-Copy-Update，读-拷贝-更新）解决「读多写少」的场景：**读者完全不加锁**，写者创建新副本、原子地替换指针、等所有读者离开后释放旧副本。

```c
#include <linux/rcupdate.h>

struct my_node {
	struct list_head list;
	int value;
};

static struct my_node __rcu *global_ptr;   /* __rcu 标记：只能用 rcu 系列访问 */

/* 读者：极低开销，可以在中断上下文执行 */
static int read_value(void)
{
	struct my_node *p;
	int v;

	rcu_read_lock();                       /* 实质只是关抢占 */
	p = rcu_dereference(global_ptr);       /* 带内存屏障的读指针 */
	v = p ? p->value : -1;
	rcu_read_unlock();
	return v;
}

/* 写者：进程上下文 */
static void update_value(struct my_node *new)
{
	struct my_node *old;

	spin_lock(&write_lock);                /* 写者之间互斥 */
	old = rcu_dereference_protected(global_ptr, lockdep_is_held(&write_lock));
	rcu_assign_pointer(global_ptr, new);   /* 带内存屏障的发布 */
	spin_unlock(&write_lock);

	synchronize_rcu();                     /* 等所有现存读者离开 —— 可能睡眠 */
	/* 或 kfree_rcu(old, rcu_head) 延迟释放 */
	kfree(old);
}
```

RCU 的四个必须记住的点：

1. `rcu_read_lock()` **不阻塞任何东西**，只是标记读者区。所以读者区里**不能睡眠**（`CONFIG_PREEMPT_RCU` 下可以，但不要养成习惯）。
2. 写者释放旧对象前**必须** `synchronize_rcu()` 或 `kfree_rcu()`，否则旧对象可能在读者手里被释放 → UAF。
3. `rcu_dereference()` 和 `rcu_assign_pointer()` 里的内存屏障不能省，否则编译器和 CPU 会重排。
4. 所有用 `__rcu` 标记的指针**必须**通过 RCU API 访问，直接解引用会被 `sparse` 警告 —— 这个警告是认真的。

参考：`Documentation/RCU/`、`kernel/rcu/`、`include/linux/rcupdate.h`。

### 6.6 锁选择速查

| 场景 | 用什么 |
| --- | --- |
| 临界区可能睡眠 / 长时间 | `mutex` |
| 临界区只有几条指令，可能在中断上下文 | `spinlock` |
| 读多写少，且读不能阻塞 | `RCU` |
| 读远多于写，但读可以短暂阻塞 | `rw_semaphore`（`rwsem`） |
| 只有一个整数的计数 | `atomic_t` / `refcount_t` |
| 只保护一个指针的发布/获取 | `smp_store_release()` / `smp_load_acquire()` 或 RCU |
| 中断上下文与进程上下文之间传数据 | `spin_lock_irqsave` 或 `kfifo` |

**强烈建议**在做并发实验时打开 lockdep：

```
make menuconfig
  -> Kernel hacking
     -> Lock Debugging (spinlocks, mutexes, etc...)
        [*] Lock debugging: prove locking correctness            (CONFIG_PROVE_LOCKING)
        [*]   Lock usage statistics                              (CONFIG_LOCK_STAT)
        [*] Detect hard and soft lockups                         (CONFIG_LOCKUP_DETECTOR)
```

打开后，锁序错误、在中断上下文睡眠、重复加锁等会立刻报出详细的 warning 与调用栈。

## 7. 常见错误与排查

### 7.1 模块无法加载

| 错误信息 | 原因 | 解决 |
| --- | --- | --- |
| `insmod: ERROR: could not insert module hello.ko: Invalid module format` | **版本不匹配**：`.ko` 的 `vermagic` 与运行内核不符 | `modinfo hello.ko \| grep vermagic` 与 `uname -r` 对比；用同一份源码树编译并加载 |
| `insmod: ERROR: could not insert module hello.ko: Operation not permitted` | 模块签名强制（`CONFIG_MODULE_SIG_FORCE`）或 lockdown 生效 | 在自己的测试内核里关掉 `CONFIG_MODULE_SIG_FORCE`；或给模块签名 |
| `insmod: ERROR: could not insert module hello.ko: File exists` | 同名模块已加载 | `lsmod \| grep hello`；先 `rmmod` |
| `insmod: ERROR: could not insert module hello.ko: Unknown symbol in module` | 用了**未导出**的内核符号 | 见 §7.2 |
| `insmod: ERROR: could not insert module hello.ko: Resource temporarily unavailable` | 初始化失败（`__init` 返回了负 errno） | `dmesg \| tail` 看你自己的 `pr_err` 输出 |
| `insmod: ERROR: ...: Exec format error` | 架构不匹配（比如在 x86_64 上编译 32 位，或交叉编译目标不对） | 检查 `ARCH=` 与 `CROSS_COMPILE=` |
| `module verification failed: signature and/or required key missing` | 内核开了 `CONFIG_MODULE_SIG` 但模块没签 | 内核对未签名模块仅打 taint 标记，通常仍可加载；配合 `CONFIG_MODULE_SIG_FORCE` 则拒绝 |
| `Disabling lock debugging due to kernel taint` | 加载了非 GPL 模块 | 加 `MODULE_LICENSE("GPL")` |

### 7.2 符号未导出（`Unknown symbol` / `undefined!`）

内核不会把所有内部函数暴露给模块。**只有被 `EXPORT_SYMBOL()` / `EXPORT_SYMBOL_GPL()` 标记的符号才能被模块使用**（定义在 `include/linux/export.h:89`、`:90`）。

```bash
# 找到你用的函数，看它是否有 EXPORT_SYMBOL
cd "$KSRC"
grep -rn "EXPORT_SYMBOL.*my_function" --include=*.c .
grep -rn "^[a-z].* my_function(" --include=*.c . | head    # 找不到就是未导出
```

编译时 `modpost` 阶段报：

```
WARNING: modpost: "foo_bar" [hello.ko] undefined!
```

运行时 `insmod` 报：

```
hello: Unknown symbol foo_bar (err -2)
```

**不要**为了绕过它去改内核加 `EXPORT_SYMBOL`（除非你确实在往上游提交）。正确做法是找到公开 API。例如不要直接用 `find_task_by_vpid()`（未导出给一般模块），而要用导出的 `pid_task(find_vpid(pid), PIDTYPE_PID)`。

另外 7.x 引入了**符号命名空间**（symbol namespace）：

```
WARNING: modpost: module hello uses symbol foo_bar from namespace TEST_NS,
but does not import it.
```

解决：在模块里加

```c
MODULE_IMPORT_NS("TEST_NS");   /* 定义见 include/linux/module.h:302 */
```

注意还有一个更严格的变体 `EXPORT_SYMBOL_FOR_MODULES(sym, "mod1,mod2")`（`include/linux/export.h:94`），只允许指定模块使用 —— 如果你的目标符号是这种，趁早换 API。

### 7.3 Oops / panic 的阅读方法

模块里出错时 `dmesg` 会打印一大段。按这个顺序读：

```
[  123.456789] BUG: unable to handle page fault for address: 0000000000000010   ← ① 类型 + 出错地址
[  123.456789] #PF: supervisor read access in kernel mode                        ← ② 读/写/执行 + 内核/用户态
[  123.456789] #PF: error_code(0x0000) - not-present page                        ← ③ 页错误码
[  123.456789] PGD 0 P4D 0
[  123.456789] Oops: 0000 [#1] SMP PTI                                            ← ④ [#1] 表示第一次 Oops
[  123.456789] CPU: 0 PID: 4321 Comm: cat Tainted: G           OE  6.18.0 #1      ← ⑤ 哪个进程干的
[  123.456789] RIP: 0010:mydev_read+0x2a/0x80 [mychardev]                         ← ⑥ 出错指令（最重要）
[  123.456789] Code: ...
[  123.456789] RSP: 0018:ffffa0004122bc30 EFLAGS: 00010286
[  123.456789] RAX: 0000000000000000 RBX: ffff88810a3b4000 RCX: 0000000000000000
...
[  123.456789] Call Trace:                                                        ← ⑦ 调用栈
[  123.456789]  <TASK>
[  123.456789]  mydev_read+0x2a/0x80 [mychardev]
[  123.456789]  vfs_read+0x1c4/0x2f0
[  123.456789]  ksys_read+0x6b/0xd0
[  123.456789]  __x64_sys_read+0x1a/0x20
[  123.456789]  do_syscall_64+0x5f/0x110
[  123.456789]  entry_SYSCALL_64_after_hwframe+0x76/0x7e
[  123.456789] RIP: 0033:0x7f...                                                   ← 用户态 RIP
[  123.456789] Kernel panic - not syncing: Fatal exception                        ← ⑧ 是否 panic
```

阅读清单：

| 位置 | 看什么 | 怎么用 |
| --- | --- | --- |
| ① | 出错地址 | `0x10` 这类小地址 = **空指针**（NULL + 偏移）；`ffff8881...` 这类 = 野指针 |
| ② | `supervisor read/write/instruction fetch` | 读/写/取指；`in kernel mode` 说明是内核自己踩的 |
| ⑥ `RIP` | `mydev_read+0x2a/0x80 [mychardev]` | **函数名 + 偏移**。偏移 0x2a 表示出错指令在 `mydev_read` 起始的 42 字节处 |
| ⑦ `Call Trace` | 反向调用链 | 从下往上读，最上面的内核函数是你的代码 |
| ⑧ | `Kernel panic` | Oops 在中断上下文 / panic_on_oops=1 / 持有锁时发生，会直接挂 |

**把偏移换算成源码行**（最实用的一步）：

```bash
cd ~/kmod-lab/mychardev
# 1) 反汇编并找到 mydev_read 里偏移 0x2a 的指令

# 2) 或用 gdb 直接问

(gdb) list *(mydev_read+0x2a)

# 3) 带调试信息的话，addr2line 也能用
addr2line -e mychardev.ko -f -i $(nm mychardev.ko | awk '/ mydev_read$/{print $1}')
```

对**内核本身**的 Oops（不是你的模块）：

```bash

./scripts/faddr2line vmlinux vfs_read+0x1c4/0x2f0
# 输出形如：
#   vfs_read+0x1c4/0x2f0:

```

### 7.4 「加载成功但系统变慢/卡住」

| 现象 | 可能原因 |
| --- | --- |
| 加载后整机无响应 | `__init` 里死循环；或持有自旋锁时睡眠；或 `spin_lock` 保护范围里有 `schedule()` |
| CPU 占用 100% | 内核线程没退出；`kthread_run()` 创建的线程没在退出路径 `kthread_stop()` |
| `rmmod` 报 `Module is in use` | 引用计数没减；`file_operations.owner` 没设；或 `cdev_del()` 前有未关闭的 fd |
| `rmmod` 报 `Module is busy` 且无法消除 | 忘了 `unregister_chrdev_region()` / `class_destroy()`，或 kthread 未停 |
| 反复 `insmod`/`rmmod` 后内存耗尽 | 错误路径漏了 `kfree` / `kthread_stop` / `unregister_*`。用 `kmemleak` 定位 |
| 加载后 dmesg 出现 `BUG: sleeping function called from invalid context` | 在原子上下文（中断/自旋锁内）调用了可睡眠函数 |

### 8.3 procfs 接口（最省事的用户态出口）

比字符设备更简单的做法是挂一个 procfs 文件。用 `seq_file` 接口（`fs/seq_file.c`）只需实现一个 `show` 回调：

```c
// SPDX-License-Identifier: GPL-2.0
#define pr_fmt(fmt) KBUILD_MODNAME ": " fmt

#include <linux/module.h>
#include <linux/proc_fs.h>     /* proc_create_single, remove_proc_entry */
#include <linux/seq_file.h>    /* seq_printf */
#include <linux/uaccess.h>     /* copy_from_user */
#include <linux/slab.h>
#include <linux/mutex.h>
#include <linux/init.h>

#define PROC_NAME "mymod"

static char *msg;
static DEFINE_MUTEX(msg_lock);

/* 读：cat /proc/mymod */
static int mymod_show(struct seq_file *m, void *v)
{
	mutex_lock(&msg_lock);
	seq_printf(m, "msg = %s\n", msg ? msg : "(empty)");
	seq_printf(m, "jiffies = %lu\n", jiffies);
	seq_printf(m, "pid = %d comm = %s\n", current->pid, current->comm);
	mutex_unlock(&msg_lock);
	return 0;
}

/* 写：echo xxx > /proc/mymod
 * 用 single_open 的 proc 文件默认走 write 回调（.proc_write）。 */
static ssize_t mymod_write(struct file *file, const char __user *ubuf,
			   size_t count, loff_t *ppos)
{
	char *tmp;

	if (count == 0 || count > 256)
		return -EINVAL;

	tmp = memdup_user_nul(ubuf, count);   /* 分配并拷贝，自动补 NUL */
	if (IS_ERR(tmp))
		return PTR_ERR(tmp);

	mutex_lock(&msg_lock);
	kfree(msg);
	msg = tmp;
	mutex_unlock(&msg_lock);

	return count;
}

static int mymod_open(struct inode *inode, struct file *file)
{
	return single_open(file, mymod_show, NULL);
}

static const struct proc_ops mymod_proc_ops = {
	.proc_open    = mymod_open,
	.proc_read    = seq_read,
	.proc_lseek   = seq_lseek,
	.proc_release = single_release,
	.proc_write   = mymod_write,
};

static struct proc_dir_entry *mymod_entry;

static int __init mymod_init(void)
{
	mymod_entry = proc_create(PROC_NAME, 0644, NULL, &mymod_proc_ops);
	if (!mymod_entry) {
		pr_err("proc_create failed\n");
		return -ENOMEM;
	}
	pr_info("created /proc/%s\n", PROC_NAME);
	return 0;
}

static void __exit mymod_exit(void)
{
	remove_proc_entry(PROC_NAME, NULL);
	kfree(msg);
	pr_info("removed /proc/%s\n", PROC_NAME);
}

module_init(mymod_init);
module_exit(mymod_exit);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("procfs interface demo (seq_file based)");
```

测试：

```bash
sudo insmod mymod.ko
cat /proc/mymod
echo "hello from userspace" | sudo tee /proc/mymod
cat /proc/mymod
sudo rmmod mymod
```

注意点：

- 用 `single_open()` 时读接口固定是 `seq_read`；写接口要自己提供。
- `memdup_user_nul()` 比手写 `kmalloc` + `copy_from_user` 更安全（它处理了 `count` 上界与结尾 NUL）。
- `remove_proc_entry()` 必须在 `__exit` 里调用，否则 `/proc/mymod` 会残留成悬空项。
- 若同时允许多个写者，`kfree(msg)` 与 `msg = tmp` 必须在同一把锁内完成，否则是典型的 UAF。
