# 01 · 文件系统与目录结构

> 前置知识：无。本文是后续所有命令文档的地基。
> 涉及命令详解见 [`../commands/01-文件与目录.md`](../commands/01-文件与目录.md)、[`../commands/05-磁盘与文件系统.md`](../commands/05-磁盘与文件系统.md)。

---

## 1. 一切皆文件

Linux 把设备、管道、内核参数、进程信息都抽象成文件。判断一个路径的真实类型用 `stat` 或 `file`：

```bash
$ stat -c '%F' /dev/sda /dev/null /proc/uptime /tmp
block special file
character special file
regular file
directory
```

文件类型共 7 种，在 `ls -l` 第一列用首字符表示：

| 首字符 | 类型 | 例子 |
|--------|------|------|
| `-` | 普通文件 regular file | `/etc/hostname` |
| `d` | 目录 directory | `/etc` |
| `l` | 符号链接 symbolic link | `/usr/lib/libc.so.6` |
| `b` | 块设备 block device | `/dev/sda` |
| `c` | 字符设备 character device | `/dev/tty`、`/dev/null` |
| `p` | 命名管道 FIFO | `mkfifo` 创建 |
| `s` | 套接字 socket | `/run/systemd/private` |

用 `stat -c '%F'` 可以拿到类型的人类可读名称，脚本中比解析 `ls -l` 可靠。

## 2. FHS 目录层次标准

**FHS**（Filesystem Hierarchy Standard，文件系统层次标准）规定了各目录的用途。这是排查"文件应该放哪"的权威依据。

| 路径 | 用途 | 要点 |
|------|------|------|
| `/` | 根 | 所有路径的起点 |
| `/bin` | 基础用户命令 | 现代发行版是 `/usr/bin` 的符号链接 |
| `/sbin` | 系统管理命令 | 同上，指向 `/usr/sbin` |
| `/usr` | 第二大层级，只读的用户程序与数据 | 占系统体积大头 |
| `/usr/bin` | 绝大多数可执行程序 | `command -v ls` 通常指向这里 |
| `/usr/local` | 本地编译安装的软件 | `./configure --prefix=/usr/local` 的默认目标 |
| `/etc` | 系统与服务的**配置文件** | 纯文本、手工编辑 |
| `/var` | 运行中会变化的数据 variable | 日志、队列、数据库 |
| `/var/log` | 日志 | 见 [`12-安全与审计.md`](../commands/12-安全与审计.md) |
| `/tmp` | 临时文件 | 通常 tmpfs，可能重启清空；多用户机器上所有人可写 |
| `/run` | 本次启动的运行时数据 | tmpfs，重启即失 |
| `/home` | 普通用户家目录 | `/home/alice` |
| `/root` | root 的家目录 | 故意不在 `/home` 下 |
| `/opt` | 第三方整包软件 | 如 `/opt/google/chrome` |
| `/srv` | 服务对外提供的数据 | 实践中常被忽略 |
| `/boot` | 内核与引导文件 | `vmlinuz-*`、`initramfs-*`、`grub/` |
| `/lib` | 共享库与内核模块 | 现代是 `/usr/lib` 的符号链接 |
| `/dev` | 设备文件 | 由 udev 动态维护 |
| `/proc` | 内核与进程信息的伪文件系统 | 见下文第 5 节 |
| `/sys` | 内核对象与设备树的伪文件系统 | 见下文第 5 节 |
| `/mnt` `/media` | 临时挂载点 / 可移动介质自动挂载点 | 手工挂载用 `/mnt` |

验证符号链接关系：

```bash
$ ls -ld /bin /sbin /lib
lrwxrwxrwx 1 root root 7 ... /bin -> usr/bin
lrwxrwxrwx 1 root root 8 ... /sbin -> usr/sbin
lrwxrwxrwx 1 root root 7 ... /lib -> usr/lib
```

这就是 **UsrMerge**：`/bin`、`/sbin`、`/lib*` 全部合并进 `/usr` 下，传统布局只在兼容性上保留链接。

## 3. inode：文件的真实身份

**inode**（index node，索引节点）存放文件的元数据：权限、属主、大小、时间戳、数据块指针。**文件名不存放在 inode 里**，而是存放在目录项（dentry）中，目录项把「名字 → inode 号」映射起来。

```bash
$ stat /etc/hostname
  File: /etc/hostname
  Size: 8               Blocks: 8          IO Block: 4096   regular file
Device: 8,3     Inode: 2097155     Links: 1
Access: (0644/-rw-r--r--)  Uid: (    0/    root)   Gid: (    0/    root)
Access: 2026-09-14 09:12:03.114000000 +0800
Modify: 2026-06-01 11:03:44.000000000 +0800
Change: 2026-06-01 11:03:44.000000000 +0800
 Birth: 2026-06-01 11:03:44.000000000 +0800
```

三个时间戳必须分清，取证时极其关键：

| 字段 | 名称 | 何时更新 |
|------|------|----------|
| `Access` | atime 访问时间 | 读文件内容时（`relatime` 挂载下不一定更新） |
| `Modify` | mtime 修改时间 | 文件**内容**改变时 |
| `Change` | ctime 状态变更时间 | **inode 元数据**改变时（改权限、改属主、改名、改内容都算） |
| `Birth` | btime 创建时间 | 文件创建时（部分文件系统才支持） |

💡 `ctime` 无法被 `touch` 伪造（除非改系统时间或直接改磁盘），所以入侵排查常用 `ctime`：`find / -ctime -1`。

**硬链接数**（`Links`）：每多一个硬链接 +1。目录的链接数至少为 2（自身 `.` + 父目录中的条目）。

### 查看 inode 号

```bash
$ ls -i /etc/hostname
2097155 /etc/hostname

# 用 inode 号反查/删除含特殊字符的文件名
$ find /tmp -inum 2097155 -delete
```

### 磁盘满但 `df` 显示有空间

原因通常是 inode 耗尽，而不是块耗尽：

```bash
$ df -i
Filesystem       Inodes  IUsed IFree IUse% Mounted on
/dev/nvme0n1p2 31252480 31252480     0  100% /
```

排查 inode 被大量小文件占满：`find / -xdev -type f | wc -l`，或按目录统计 `for d in /var/*; do echo -n "$d "; find "$d" -xdev | wc -l; done`。

## 4. 硬链接与软链接

```bash
# 硬链接
$ echo hello > /tmp/orig.txt
$ ln /tmp/orig.txt /tmp/hard.txt
$ ls -li /tmp/orig.txt /tmp/hard.txt
2097155 -rw-r--r-- 2 root root 6 ... /tmp/hard.txt
2097155 -rw-r--r-- 2 root root 6 ... /tmp/orig.txt

# 软链接（符号链接）
$ ln -s /tmp/orig.txt /tmp/soft.txt
$ ls -l /tmp/soft.txt
lrwxrwxrwx 1 root root 13 ... /tmp/soft.txt -> /tmp/orig.txt
```

| 对比项 | 硬链接 | 软链接（符号链接） |
|--------|--------|--------------------|
| 本质 | 同一 inode 的另一个目录项 | 独立 inode，内容是目标路径字符串 |
| inode 号 | 与源相同 | 与源不同 |
| 跨文件系统 | ❌ 不行 | ✅ 可以 |
| 指向目录 | ❌ 普通用户不行 | ✅ 可以 |
| 源文件删除后 | 数据仍在，连接数减 1 | 变成「断链」dangling link |
| `ls -l` 显示 | 普通文件样子 | `l` 开头 + `->` |
| 大小 | 与源相同 | 目标路径字符串长度 |

💡 `ls -l` 软链接的 `13` 是目标路径 `/tmp/orig.txt` 的字符数，不是源文件大小。

### 实战陷阱：软链接的尾斜杠

```bash
$ mkdir -p /tmp/realdir && ln -s /tmp/realdir /tmp/linkdir

$ cp -r /tmp/linkdir /tmp/dest1     # 复制链接指向的内容
$ cp -r /tmp/linkdir/ /tmp/dest2    # 有一个尾斜杠，效果同上但更明确
$ cp -a /tmp/linkdir /tmp/dest3     # 保留链接本身
$ cp -P /tmp/linkdir /tmp/dest4     # 复制链接本身（不跟随）
```

`cp -a`（archive）保留权限、时间戳、链接、属主，是备份的正确姿势。要注意 `cp -d` / `-P` 与 `-r` 的组合语义。

🔬 **`rm` 删除软链接不会删源文件**，但如果写 `rm -r /tmp/linkdir/`（带尾斜杠），`rm` 会跟随链接进目录删除内容。这是经典事故。

## 5. `/proc` 与 `/sys` 伪文件系统

这两个目录不占磁盘，内容由内核实时生成。

### `/proc` — 进程与内核状态

| 路径 | 内容 |
|------|------|
| `/proc/<pid>/` | 某进程的目录，`cmdline` 是启动命令（`\0` 分隔），`environ` 是环境变量 |
| `/proc/<pid>/exe` | 指向可执行文件的软链接（删除后仍可恢复运行中的二进制） |
| `/proc/<pid>/fd/` | 该进程打开的所有文件描述符 |
| `/proc/<pid>/cwd` | 进程当前工作目录的软链接 |
| `/proc/cpuinfo` | CPU 详情 |
| `/proc/meminfo` | 内存统计，`free` 的数据源 |
| `/proc/loadavg` | 平均负载 |
| `/proc/mounts` | 当前挂载（等价于 `mount` 输出的解析版） |
| `/proc/version` | 内核版本与编译信息 |
| `/proc/cmdline` | 内核启动参数 |
| `/proc/sys/` | 内核可调参数，即 `sysctl` 的映射 |
| `/proc/net/tcp` | IPv4 TCP 连接表，`ss` 的数据源之一 |

```bash
# 查看某进程完整启动命令（参数间是 NUL，需要 tr 转换）
$ tr '\0' ' ' < /proc/1/cmdline; echo
/sbin/init

# 从已删除的二进制恢复（应急取证常用）
$ cp /proc/1234/exe /tmp/recovered_binary

# 查看进程打开了哪些文件
$ ls -l /proc/1234/fd/
```

🔐 `/proc/<pid>/environ` 常泄露数据库密码、API Key，取证和应急响应必看：

```bash
$ tr '\0' '\n' < /proc/1234/environ | grep -iE 'pass|token|key'
```

### `/sys` — 设备与内核对象

`/sys` 以 `kobject` 为单位组织，写文件即可改内核参数（危险）。

| 路径 | 内容 |
|------|------|
| `/sys/class/net/` | 网络接口，每个目录里 `address` 是 MAC |
| `/sys/block/` | 块设备 |
| `/sys/class/power_supply/` | 电池 / 电源 |
| `/sys/fs/cgroup/` | cgroup v2 层级 |
| `/sys/kernel/` | 内核参数、debug 接口 |

```bash
$ cat /sys/class/net/enp34s0/address
38:9f:ad:0d:39:53

$ cat /sys/class/thermal/thermal_zone0/temp
52000        # 毫摄氏度，即 52.0 °C
```

⚠️ 直接写 `/sys` 或 `/proc/sys` 会立刻改变内核行为。改之前先 `cat` 读原值记下来。

## 6. 挂载机制

Linux 没有「盘符」概念，一棵目录树通过**挂载**把不同文件系统接到某个目录上。

```bash
# 查看当前挂载（人类可读）
$ findmnt
TARGET    SOURCE         FSTYPE OPTIONS
/         /dev/nvme0n1p2 ext4   rw,relatime
├─/boot   /dev/nvme0n1p1 vfat   rw,relatime
└─/tmp    tmpfs          tmpfs  rw,nosuid,nodev

# 只看某目录
$ findmnt /tmp

# 手工挂载
$ sudo mount /dev/sdb1 /mnt/usb
$ sudo mount -o ro /dev/sdb1 /mnt/usb     # 只读挂载，取证必用
$ sudo umount /mnt/usb
```

### 关键挂载选项

| 选项 | 作用 |
|------|------|
| `ro` / `rw` | 只读 / 读写 |
| `noexec` | 禁止在该挂载点执行程序，防御 `/tmp` 提权 |
| `nosuid` | 忽略 SUID/SGID 位，防御 `/tmp` 提权 |
| `nodev` | 不解释设备文件 |
| `relatime` | atime 只在 mtime/ctime 更新或超过 24h 才写，性能与语义的折中 |
| `noatime` | 完全不更新 atime，性能最好 |
| `defaults` | `rw,suid,dev,exec,auto,nouser,async` |

💡 `/etc/fstab` 里加 `noexec,nosuid,nodev` 到 `/tmp`、`/dev/shm` 是最常见的加固项，但注意某些软件（如 Chrome 沙箱、部分安装器）会因此报错。

### 持久化挂载：`/etc/fstab`

```
# <device>            <mountpoint>  <fstype> <options>          <dump> <pass>
UUID=abcd-1234        /             ext4     rw,relatime         0      1
UUID=efgh-5678        /boot         vfat     rw,relatime,fmask=0077 0   2
tmpfs                 /tmp          tmpfs    rw,nosuid,nodev     0      0
```

⚠️ 用 `UUID=` 而非 `/dev/sdX`，因为设备名可能因插拔顺序变化。查 UUID 用 `blkid`。
⚠️ 改 `fstab` 后必须用 `sudo mount -a` 验证，写错会导致系统**开不了机**（进 emergency mode）。

## 7. 路径与通配符

```bash
/          # 根，绝对路径起点
.          # 当前目录
..         # 上级目录
~          # 当前用户家目录
~alice     # alice 的家目录
-          # 上一个工作目录（cd - / git checkout - 都支持）
```

### glob 通配符（由 **shell** 展开，不是命令）

| 模式 | 匹配 |
|------|------|
| `*` | 任意长度任意字符（**不含**隐藏文件的开头点，也不跨 `/`） |
| `?` | 单个字符 |
| `[abc]` | a、b、c 之一 |
| `[a-z]` | 范围 |
| `[!abc]` 或 `[^abc]` | 不在集合中 |
| `{a,b}` | 花括号展开（brace expansion），展开为两个词 |
| `{1..5}` | 序列展开 |

```bash
$ echo *.txt              # 展开为当前目录所有 .txt
$ ls file?.log            # file1.log file2.log
$ cp a.txt{,.bak}         # 等价于 cp a.txt a.txt.bak  （备份神技）
$ mkdir -p proj/{src,doc,test}
$ echo {1..3}{a,b}        # 1a 1b 2a 2b 3a 3b
```

⚠️ 用 `{,.bak}` 前先 `echo` 看一下展开结果，避免误操作。

### 引号规则（必须背熟）

| 写法 | 变量展开 | 通配符展开 | 用途 |
|------|----------|-----------|------|
| `'单引号'` | ❌ | ❌ | 字面量 |
| `"双引号"` | ✅ | ❌ | 含空格/变量的字符串 |
| `` `反引号` `` | 命令替换（旧写法） | ❌ | 别再用 |
| `$()` | 命令替换 | ❌ | 推荐 |
| `\x` | 转义单个字符 | — | 转义空格、`$`、`*` |

```bash
$ name="a b"
$ echo $name      # 输出 a b（看似正常，但作为参数是 2 个词）
$ ls $name        # 变成 ls a b —— 灾难起点
$ ls "$name"      # 正确：一个参数
```

**规则：变量永远加双引号。** 这是 shell 脚本第一大 bug 来源。
