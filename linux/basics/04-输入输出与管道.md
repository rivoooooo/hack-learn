# 04 · 输入输出与管道

> 命令手册：[`../commands/02-文本处理.md`](../commands/02-文本处理.md)。
> 这是 shell 里**最容易出错、也最能提效**的一块。

---

## 1. 三个标准流

每个进程启动时默认打开三个文件描述符：

| fd | 名称 | 默认去向 | 说明 |
|----|------|----------|------|
| `0` | stdin 标准输入 | 键盘 / 终端 | 读数据 |
| `1` | stdout 标准输出 | 终端 | 正常结果 |
| `2` | stderr 标准错误 | 终端 | 错误信息 |

关键点：**stdout 和 stderr 是两条独立通道**，即使它们都显示在终端上。

```bash
# 验证它们确实分开
$ ls /etc/hostname /nonexistent > /tmp/out.txt
ls: cannot access '/nonexistent': No such file or directory
$ cat /tmp/out.txt
/etc/hostname                 # 只有正常结果进了文件
```

## 2. 重定向

| 写法 | 含义 |
|------|------|
| `> file` | stdout 覆盖写入（**文件先被清空**） |
| `>> file` | stdout 追加 |
| `2> file` | stderr 覆盖 |
| `2>> file` | stderr 追加 |
| `&> file` | stdout + stderr 一起（bash 专有） |
| `&>> file` | 追加版 |
| `> file 2>&1` | POSIX 写法，等价于 `&>`（**顺序重要**） |
| `< file` | stdin 来自文件 |
| `<<EOF` | here-doc |
| `<<< "str"` | here-string（bash 专有） |
| `n> file` | 任意 fd n 重定向 |
| `2>&1` | 把 fd 2 指向 fd 1 **当前**的目标 |
| `>&2` | 把 fd 1 指向 fd 2 的目标（常用于脚本里输出错误） |

### ⚠️ 顺序陷阱

```bash
$ cmd > file 2>&1      # ✅ 两个都进文件
$ cmd 2>&1 > file      # ❌ stderr 去终端，stdout 去文件
```

原因：重定向是**从左到右**执行的。第一条先让 fd1 → file，再把 fd2 指向「fd1 现在的目标」即 file。第二条先把 fd2 指向当前 fd1（终端），再改 fd1 → file，所以 stderr 仍在终端。

另一个常见错误：

```bash
$ ls nonexistent 2>&1 1>/dev/null     # stderr 指向终端（保留），stdout 丢弃
$ ls nonexistent >/dev/null 2>&1      # 两者都丢弃（正确姿势）
```

### 常用组合

```bash
# 丢弃所有输出
$ cmd > /dev/null 2>&1

# 只丢弃 stdout，保留 stderr（调试时最有用）
$ cmd 1> /dev/null

# 分开保存
$ cmd > /tmp/stdout.log 2> /tmp/stderr.log

# 同时输出到屏幕和文件（见 tee）
$ cmd 2>&1 | tee /tmp/all.log

# 只保留最后几行错误
$ cmd 2> >(tail -5 >&2)
```

### 禁止覆盖已存在文件

```bash
$ set -o noclobber      # 开启后 > 不能覆盖已存在文件
$ cmd > existing.txt
bash: existing.txt: cannot overwrite existing file
$ cmd >| existing.txt   # 用 >| 强制覆盖
```

## 3. `/dev/null`、`/dev/zero` 等特殊文件

| 设备 | 作用 |
|------|------|
| `/dev/null` | 黑洞，写入丢弃，读取立即 EOF |
| `/dev/zero` | 无限读出不限字节的 `\0`，用于 `dd` 造空文件 |
| `/dev/random` | 阻塞式随机，熵池空时阻塞 |
| `/dev/urandom` | 非阻塞随机，**实践中一律用它** |
| `/dev/full` | 写入永远返回 ENOSPC，测错误处理 |
| `/dev/stdin` `/dev/stdout` `/dev/stderr` | 指向当前进程的 0/1/2 |
| `/dev/tcp/host/port` | bash 内建的重定向网络连接（见下） |

```bash
# 创建 100MB 空文件
$ dd if=/dev/zero of=/tmp/zero.img bs=1M count=100 status=progress

# 💡 不用 dd 也行（更快，稀疏文件）
$ truncate -s 100M /tmp/sparse.img

# bash 的 /dev/tcp：无 nc 时也能测端口
$ timeout 2 bash -c 'echo > /dev/tcp/127.0.0.1/22' && echo OPEN || echo CLOSED
```

`/dev/tcp` 是 **bash 编译时可选特性**，非 bash shell（dash、sh）不支持，脚本可移植性差时用 `nc`。

## 4. 管道

```bash
$ cmd1 | cmd2 | cmd3
```

管道把 `cmd1` 的 **stdout** 接到 `cmd2` 的 **stdin**。stderr **不经过管道**。

```bash
$ find /etc -name '*.conf' 2>/dev/null | wc -l
```

### 管道的关键特性

1. **并行执行**：所有进程同时启动，靠内核缓冲区（通常 64 KiB）与阻塞传递数据。不是「命令1全部跑完再跑命令2」。
2. **退出码**：`$?` 默认是**最后一个命令**的退出码。要管前面的，用 `set -o pipefail`。
3. **管道中的子 shell**：bash 里管道的每一段默认在**子 shell**中执行，变量赋值不会传回父 shell。

```bash
$ echo hello | read x; echo "x=$x"
x=                      # 空的！read 在子 shell 里

# 修复方式
$ read x < <(echo hello); echo "x=$x"
x=hello

$ shopt -s lastpipe      # bash 4.2+，让最后一段在父 shell 执行
$ echo hello | read x; echo "x=$x"
x=hello
```

⚠️ 这是 bash 脚本里最隐蔽的 bug 之一。循环里 `cmd | while read line` 修改的变量在循环外读不到。

### `|&` 与 stderr 进管道

```bash
$ cmd 2>&1 | grep error      # 把 stderr 也导入管道（推荐）
$ cmd |& grep error          # bash 4+ 简写，等价于上一条
```

## 5. `tee`：分叉输出

`tee` 把 stdin 同时写向 stdout 和文件。

```bash
$ cmd | tee output.log              # 屏幕 + 文件
$ cmd | tee -a output.log           # 追加
$ cmd | tee file1 file2             # 写多个文件
$ cmd | sudo tee /etc/foo.conf      # ⭐ 用 sudo 写受保护文件的标准写法
$ cmd | sudo tee -a /etc/foo.conf
```

⚠️ `sudo cmd > /etc/foo.conf` **不生效**：重定向由当前 shell（非 root）执行，会 permission denied。正确写法是 `cmd | sudo tee /etc/foo.conf`，或 `sudo sh -c 'cmd > /etc/foo.conf'`。

💡 利用 `/dev/null` 让 tee 只写文件不写屏幕：

```bash
$ cmd | tee /dev/null | wc -l      # 无意义；正确做法是 cmd | wc -l（直接不 tee）
```

## 6. here-doc 与 here-string

### here-doc

```bash
$ cat <<EOF
Host: $(hostname)
Date: $(date +%F)
EOF
```

| 写法 | 变量/命令展开 | 制表符缩进 |
|------|---------------|-----------|
| `<<EOF` | ✅ 展开 | ❌ |
| `<<"EOF"` 或 `<<'EOF'` | ❌ 原样输出 | ❌ |
| `<<-EOF` | ✅ | ✅ 去掉行首 **Tab** |

⚠️ `<<-` 只去掉 **Tab**，不去空格。用空格缩进的 here-doc 会带上缩进内容。

```bash
# ⭐ 生成配置文件的经典用法（引号防止 $ 被展开）
$ sudo tee /etc/app.conf > /dev/null <<'EOF'
[server]
port = 8080
secret = $KEEP_THIS_LITERAL
EOF
```

### here-string

```bash
$ grep foo <<< "foo bar"
foo bar

$ bc <<< "2^10"
1024

$ while read -r line; do echo "[$line]"; done <<< "$multiline_var"
```

💡 here-string 里也可以有命令替换：`psql <<< "\dt"`。

### 进程替换

```bash
# 把命令输出当成一个文件名
$ diff <(sort a.txt) <(sort b.txt)
$ comm <(sort a.txt) <(sort b.txt)
$ paste <(cut -f1 a.tsv) <(cut -f2 b.tsv)

# 当作输入流（避免子 shell 变量丢失）
$ while read -r line; do count=$((count+1)); done < <(find /etc -type f)
```

## 7. 退出码

```bash
$ ls /nonexistent
$ echo $?
2
```

| 码 | 常见含义 |
|----|----------|
| `0` | 成功 |
| `1` | 通用错误 |
| `2` | 用法/参数错误（shell 内建、grep 无匹配也是 2） |
| `126` | 找到了但无法执行（权限不足） |
| `127` | 命令未找到 |
| `128+N` | 被信号 N 终止（如 `137` = 128+9 = SIGKILL，`130` = SIGINT） |
| `255` | 超出范围或被 `exit -1` |

```bash
$ cmd; echo $?          # 上一条命令的退出码
$ cmd || echo "failed"  # 失败时执行
$ cmd && echo "ok"      # 成功时执行
$ cmd1; cmd2            # 无论成败都执行
$ ! cmd                 # 取反退出码
```

⚠️ `grep` 的退出码有 3 种：0 匹配到、1 没匹配到、2 出错。脚本里 `grep ... || echo "not found"` 无法区分后两者。

### 管道与退出码

```bash
$ false | true; echo $?
0                       # 只看最后一段

$ set -o pipefail
$ false | true; echo $?
1                       # 任一段失败即失败
```

💡 **脚本模板必备前两行**：

```bash
#!/usr/bin/env bash
set -euo pipefail
```

| 选项 | 作用 |
|------|------|
| `-e` | 命令失败立即退出（errexit） |
| `-u` | 使用未定义变量报错（nounset） |
| `-o pipefail` | 管道任一段失败即整体失败 |

⚠️ `set -e` 有坑：`cmd || true`、`if cmd`、`cmd && ...` 中的失败**不会**触发退出（这是设计如此，因为你在显式处理错误）。另外在 `$(...)` 里的失败、以及函数内部的部分场景行为容易反直觉，写关键脚本时要显式检查 `$?`。

## 8. 输出缓冲

程序写 stdout 时通常**块缓冲**（4 KB / 64 KB），写 stderr 是**行缓冲**或不缓冲。重定向到文件/管道时更明显：日志会「卡住」不出现。

```bash
# 强制行缓冲
$ stdbuf -oL cmd | grep foo        # 行缓冲
$ stdbuf -o0 cmd | grep foo        # 不缓冲
$ python3 -u script.py             # Python 的 -u 等价
$ grep --line-buffered foo         # grep 自己行缓冲
$ awk '{print; fflush()}'          # awk 手动 flush
```

💡 `tail -f app.log | grep ERROR` 长时间没输出，第一反应就是缓冲问题，加 `--line-buffered`。

## 9. 组合实战

```bash
# 1. 找出占用最大的 5 个目录，跳过错误
$ du -x / 2>/dev/null | sort -rn | head -5

# 2. 找出监听端口并按端口排序
$ ss -tlnp 2>/dev/null | awk 'NR>1 {print $4}' | sed 's/.*://' | sort -n | uniq

# 3. 日志聚合：统计访问量前十的 IP
$ awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 4. 带进度地打包并校验
$ tar cf - /data | tee >(sha256sum > /tmp/tar.sha) | zstd -T0 > /tmp/data.tar.zst

# 5. 一次性创建多个文件并写入不同内容
$ for i in 1 2 3; do echo "content $i" > /tmp/f$i.txt; done

# 6. 把 stderr 单独留档，stdout 进管道
$ cmd 2> /tmp/err.log | tee /tmp/out.log | wc -l
```
