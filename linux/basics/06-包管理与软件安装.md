## 1. 包管理器解决什么问题

手工编译安装的问题：依赖靠记、升级靠手动、卸载靠 `rm`、无法审计。包管理器统一处理：

| 能力 | 说明 |
|------|------|
| 依赖解析 | 自动安装依赖，检测冲突 |
| 版本管理 | 元数据里记录版本，可查询可回滚 |
| 文件清单 | 记录每个包安装了哪些文件 |
| 完整性校验 | 校验和 / GPG 签名 |
| 数据库 | 已安装包的权威记录，用于审计 |

### 两大体系

| 体系 | 发行版 | 底层格式 | 元数据数据库 |
|------|--------|----------|--------------|
| Debian 系 | Debian、Ubuntu、Kali、Mint | `.deb` | `/var/lib/dpkg/status` |
| RPM 系 | RHEL、CentOS、Fedora、openSUSE、Rocky | `.rpm` | `/var/lib/rpm/` |
| Arch 系 | Arch、Manjaro、EndeavourOS、Omarchy | `.pkg.tar.zst` | `/var/lib/pacman/local/` |
| 独立格式 | Alpine（apk）、Gentoo（portage）、Void（xbps） | — | — |

### 高层 vs 低层

每个体系都分两层：**高层解决依赖，低层操作单个包**。

| 体系 | 高层（自动依赖） | 低层（单个包） |
|------|------------------|----------------|
| Debian | `apt` / `apt-get` | `dpkg` |
| RPM | `dnf` / `yum` / `zypper` | `rpm` |
| Arch | `pacman -S` | `pacman -U` |
| Alpine | `apk add` | `apk add --no-network` |

```bash
# 典型症状：apt 报依赖错误，用 dpkg 手动安装了 .deb
$ sudo dpkg -i pkg.deb
dpkg: dependency problems prevent configuration of pkg
# 修复
$ sudo apt -f install
```

⚠️ **永远不要 `dpkg -i` 后不管依赖**，`apt -f install`（`--fix-broken`）是标准修复动作。

## 2. Debian 系（apt / dpkg）

```bash
# 更新索引（不升级任何软件）
$ sudo apt update

# 升级
$ sudo apt upgrade               # 只升级，不删包、不加新包
$ sudo apt full-upgrade          # 允许为解决依赖而删包/加包
$ sudo apt dist-upgrade          # 同 full-upgrade（旧名）

# 安装 / 删除
$ sudo apt install nginx
$ sudo apt install nginx=1.24.0-1        # 指定版本
$ sudo apt install ./local.deb           # 本地 deb，自动处理依赖 ⭐
$ sudo apt remove nginx                  # 保留配置
$ sudo apt purge nginx                   # 连配置一起删 ⭐

# 清理
$ sudo apt autoremove                    # 删不再需要的自动依赖
$ sudo apt autoclean                     # 删过期的包缓存
$ sudo apt clean                         # 清空 /var/cache/apt/archives

# 查询
$ apt search '^nginx'             # 搜索
$ apt show nginx                  # 详情
$ apt list --installed            # 已安装
$ apt list --upgradable           # 可升级
$ apt-cache policy nginx          # 版本与来源优先级
$ apt-cache depends nginx         # 依赖
$ apt-cache rdepends nginx        # 反向依赖（谁依赖它）
$ apt-cache madison nginx         # 全部可用版本
```

### dpkg 查询已安装文件与归属

🔐 应急响应必备：**确认某个文件属于哪个包**（判断是否为系统文件）。

```bash
$ dpkg -S /usr/bin/passwd          # 文件属于哪个包
passwd: /usr/bin/passwd

$ dpkg -L passwd                   # 包安装了哪些文件
$ dpkg -l | grep nginx             # 已安装包（ii 前缀 = 正常安装）
$ dpkg -s nginx                    # 包状态详情
$ dpkg -l | awk '$1!="ii" {print}' # 🔐 找出状态异常（被删文件/半配置）的包

# 校验包文件的完整性（对比 md5）
$ sudo dpkg -V passwd              # 有输出说明文件被改动过 🔐
```

`dpkg -V` 无输出 = 所有文件与包数据库记录一致；**有输出是排查「二进制被替换」的强信号**。

### 版本锁定

```bash
$ sudo apt-mark hold nginx         # 锁定，阻止升级
$ sudo apt-mark unhold nginx
$ apt-mark showhold
```

### PPAs / 第三方源

```bash
$ sudo add-apt-repository ppa:ondrej/php
$ sudo apt update
```

⚠️ 第三方源等于把 root 权限交给对方。加源前确认 GPG key 来源。源配置在 `/etc/apt/sources.list` 与 `/etc/apt/sources.list.d/`。

## 3. RPM 系（dnf / yum / rpm / zypper）

```bash
# Fedora / RHEL 8+ / Rocky
$ sudo dnf install nginx
$ sudo dnf remove nginx
$ sudo dnf upgrade
$ dnf search nginx
$ dnf info nginx
$ dnf list installed
$ dnf repoquery --requires nginx      # 依赖
$ dnf provides '*/bin/nginx'          # 反查文件属于哪个包 ⭐
$ dnf history                         # 事务历史
$ sudo dnf history undo 42            # 回滚某次事务 ⭐

# 旧版（RHEL 7 / CentOS 7）
$ sudo yum install nginx

# openSUSE
$ sudo zypper install nginx
$ zypper se nginx
$ zypper rm nginx
$ zypper up
```

### rpm 低层查询

```bash
$ rpm -qa | grep nginx
$ rpm -qi nginx                       # 包信息
$ rpm -ql nginx                       # 文件清单
$ rpm -qf /usr/sbin/nginx             # 反查归属 ⭐
$ rpm -qc nginx                       # 只看配置文件
$ rpm -qd nginx                       # 只看文档
$ rpm -V nginx                        # 校验（无输出 = 未改动）🔐
$ rpm -qp --scripts pkg.rpm           # 看包里的安装脚本 🔐 装第三方 rpm 前必看
$ sudo rpm -ivh pkg.rpm               # 安装本地 rpm（不解决依赖）
$ sudo rpm -e --nodeps nginx          # 强制卸载（⚠️ 极其危险）
```

⚠️ `rpm -e --nodeps` 会留下无法解析的依赖断裂，可能让系统无法更新。只在明确知道后果时用。

### GPG 签名

```bash
$ rpm -K pkg.rpm                # 校验签名
$ dnf install --nogpgcheck pkg.rpm   # ⚠️ 跳过签名校验，禁止用于生产
```

## 4. Arch 系（pacman）

```bash
# 同步并安装（-S）
$ sudo pacman -S nginx
$ sudo pacman -S --needed base-devel
$ sudo pacman -Ss nginx             # 搜索仓库
$ sudo pacman -Si nginx             # 仓库中包信息
$ sudo pacman -Syu                  # ⭐ 全系统升级（Arch 不支持部分升级！）
$ sudo pacman -Sy                   # ⚠️ 只更新索引不升级 = 危险的部分升级
$ sudo pacman -Syu --ignore=linux   # 升级但跳过某包

# 删除（-R）
$ sudo pacman -R nginx
$ sudo pacman -Rs nginx             # 连不再被需要的依赖一起删
$ sudo pacman -Rns nginx            # 连配置一起删（最彻底）

# 查询（-Q）
$ pacman -Q                         # 已安装列表
$ pacman -Qe                        # 显式安装的（非依赖）
$ pacman -Qm                        # 外来包（AUR/手动装的）
$ pacman -Ql nginx                  # 文件清单
$ pacman -Qo /usr/bin/nginx         # 反查归属 ⭐
$ pacman -Qk nginx                  # 校验文件是否丢失
$ pacman -Qkk nginx                 # 详细校验（比对 mtime/size）🔐

# 缓存
$ sudo pacman -Sc                   # 清理未安装包的缓存
$ sudo pacman -Scc                  # 清空全部缓存
$ ls /var/cache/pacman/pkg | head   # 缓存目录（可降级用）

# 降级（用缓存里的旧版本）
$ sudo pacman -U /var/cache/pacman/pkg/nginx-1.24.0-1-x86_64.pkg.tar.zst
```

⚠️ **Arch 的部分升级（partial upgrade）是头号事故来源**。永远用 `pacman -Syu`，不要 `pacman -Sy` 后单独装包。

### AUR 助手

```bash
# yay
$ yay -S google-chrome
$ yay -Ss keyword
$ yay -Yc                 # 清理无用依赖

# paru
$ paru -S package
```

⚠️ AUR 包由用户提交，**构建脚本以你的用户身份执行**。装之前必须 `view PKGBUILD`、`paru -G package` 看内容。2025 年曾出现 AUR 恶意包窃取浏览器数据的事件。

## 5. 语言级包管理器

它们**不走系统包管理器**，装在用户目录或虚拟环境里。

```bash
# Python
$ pip install requests
$ pip install --user requests              # 装到 ~/.local/lib
$ pip install -r requirements.txt
$ pip install -e .                         # 可编辑安装（开发）
$ pipx install ruff                        # 隔离安装 CLI 工具 ⭐
$ python3 -m venv .venv && . .venv/bin/activate
$ pip list --outdated

# Node.js
$ npm install -g typescript
$ npm ls -g --depth=0
$ pnpm add lodash
$ yarn add lodash

# 其他
$ cargo install ripgrep
$ go install github.com/junegunn/fzf@latest
$ gem install bundler
$ composer global require laravel/installer
```

⚠️ `sudo pip install` 会污染系统 Python，可能覆盖发行版管理的包，导致 `apt`/`dnf` 自己崩溃。**始终用 venv 或 `pipx`。**

## 6. 从源码编译安装

### 经典三步（Autotools）

```bash
$ wget https://example.com/foo-1.2.3.tar.gz
$ tar xzf foo-1.2.3.tar.gz && cd foo-1.2.3
$ ./configure --prefix=/usr/local --enable-feature
$ make -j"$(nproc)"
$ sudo make install
```

```bash
# 卸载（前提：保留构建目录）
$ sudo make uninstall

# 更稳妥：装到隔离前缀再打包，便于卸载
$ ./configure --prefix=/opt/foo-1.2.3
$ make && sudo make install
# 卸载 = sudo rm -rf /opt/foo-1.2.3
```

### CMake

```bash
$ cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr/local
$ cmake --build build -j"$(nproc)"
$ sudo cmake --install build
```

### Meson

```bash
$ meson setup build --prefix=/usr/local
$ ninja -C build
$ sudo ninja -C build install
```

### 各步骤报错对应的缺失依赖

| 报错 | 缺什么 |
|------|--------|
| `configure: error: C compiler cannot create executables` | 编译器 / `build-essential` |
| `error: 'X.h' file not found` | 开发包 `libX-dev` / `X-devel` |
| `checking for library... no` | `-dev` / `-devel` 包 |
| `Cannot find pkg-config` | `pkg-config` |
| 链接期 `undefined reference` | 缺少链接库或用错顺序 |

```bash
# 找开发包：Debian
$ apt-file search Xlib.h        # 需要 apt install apt-file && apt-file update
# RPM 系
$ dnf provides '*/Xlib.h'
# Arch
$ pacman -F Xlib.h              # 需要先 sudo pacman -Fy
```

### 装到哪里

| 前缀 | 用途 | 需要 sudo |
|------|------|-----------|
| `/usr/local` | 传统本地安装位置，在 PATH 中 | ✅ |
| `/opt/<pkg>-<ver>` | 整包隔离安装，最易卸载 | ✅ |
| `~/.local` | 单用户安装 | ❌ |

```bash
# 装到用户目录的通用写法
$ ./configure --prefix="$HOME/.local"
$ make && make install
$ export PATH="$HOME/.local/bin:$PATH"
```

⚠️ `/usr/local` 下手工装的文件**不受包管理器管理**，不会被 `apt upgrade` 升级，也不会被 `dpkg -S` 查到。这就是所谓的 "`/usr/local` 污染"，长期运维的常见坑。

### 打成本地包（推荐做法）

```bash
# Debian：checkinstall 或 fpm
$ sudo checkinstall make install
$ fpm -s dir -t deb -n foo -v 1.2.3 --prefix /usr/local bin/foo
$ sudo dpkg -i foo_1.2.3_amd64.deb     # 之后可由 dpkg/apt 管理

# Arch：写 PKGBUILD
$ makepkg -si
```

## 7. 容器与沙箱安装

```bash
$ flatpak install flathub org.mozilla.firefox
$ flatpak list
$ flatpak run org.mozilla.firefox
$ flatpak uninstall org.mozilla.firefox

$ snap install code --classic
$ snap list
$ snap remove code

$ distrobox create -i archlinux:latest -n arch
$ distrobox enter arch
```

`--classic` 表示关闭 snap 的沙箱限制（全系统访问），安全性与普通包相同。

## 8. 🔐 软件供应链安全

| 检查项 | 做法 |
|--------|------|
| 来源可信 | 只用官方源；第三方源要有明确责任方 |
| 签名有效 | `apt-key`/`rpm -K`/`pacman-key` 校验通过 |
| 包名钓鱼 | `apt install rdesktop` vs 恶意包 `rdesktopp`；`pip install reqeusts` 类抢注 |
| 安装脚本 | `rpm -qp --scripts`、`dpkg-deb -e`、AUR 的 `PKGBUILD` |
| 完整性 | 对比官方公布的哈希 |

```bash
# 检查 deb 的安装脚本（装第三方 deb 前必看）
$ dpkg-deb -e pkg.deb /tmp/debctl && ls /tmp/debctl
$ cat /tmp/debctl/postinst

# 检查 rpm 的脚本
$ rpm -qp --scripts pkg.rpm

# 检查 pacman 包的构建信息
$ bsdtar -xOf pkg.tar.zst .PKGINFO

# 检查 AUR 的 PKGBUILD（不构建）
$ paru -G package && cat package/PKGBUILD
```

🔐 **已安装包的文件篡改检测**（应急响应）：

```bash
$ sudo dpkg -V                      # Debian 系全量校验
$ sudo rpm -Va | grep -v '^..5'     # RPM 系，过滤只改了 mtime 的
$ sudo pacman -Qkk | grep -v '0 altered files'
```

⚠️ 校验基准是包管理器的本地数据库。如果攻击者同时改了二进制和数据库，校验会通过。对抗方式：用**离线保存的基线**（把 `/var/lib/dpkg/status`、`rpm -qa` 输出、文件哈希存到只读介质）。
