## 1. 网络接口

```bash
# 现代方式（推荐）
$ ip link show                     # 链路层：UP/DOWN、MAC、MTU
$ ip -br link                      # 简洁一行一个接口
$ ip addr show                     # 网络层：IP 地址
$ ip -br addr                      # ⭐ 平时最常用
$ ip -s link                       # 收发统计（错误、丢包）

# 旧方式（已废弃但到处能看到）
$ ifconfig
$ ifconfig eth0 up
```

| 接口名 | 说明 |
|--------|------|
| `lo` | 环回，`127.0.0.1/8` 和 `::1/128` |
| `eth0` / `ens33` / `enp34s0` | 有线网卡（可预测命名，见下） |
| `wlan0` / `wlp3s0` | 无线网卡 |
| `docker0` | Docker 默认网桥 |
| `br-xxxx` | 自定义网桥 |
| `veth*` | 容器对的虚拟以太网 |
| `tun0` / `wg0` / `tailscale0` | VPN 隧道 |
| `virbr0` | libvirt 虚拟网络 |

### 可预测网络接口命名

| 前缀 | 含义 |
|------|------|
| `en` | Ethernet |
| `wl` | Wireless LAN |
| `ww` | Wireless WAN |
| `o` + 序号 | 板载（onboard） |
| `s` + 序号 | 插槽（slot） |
| `p` + 序号 | PCI 位置 |

`enp34s0` = Ethernet + PCI 总线 34 + 槽位 0。

```bash
# 改回传统命名（在内核命令行加）
net.ifnames=0 biosdevname=0

# 临时改 MTU
$ sudo ip link set dev enp34s0 mtu 1400

# 临时加/删 IP
$ sudo ip addr add 192.168.1.50/24 dev enp34s0
$ sudo ip addr del 192.168.1.50/24 dev enp34s0

# 启停接口
$ sudo ip link set enp34s0 down
$ sudo ip link set enp34s0 up
```

⚠️ **用 `ip` 做的改动重启即失效**。持久化用 NetworkManager（`nmcli`）、systemd-networkd、netplan（Ubuntu）或发行版的 `/etc/network/interfaces`。

### 网络配置文件位置

| 工具 | 路径 |
|------|------|
| NetworkManager | `/etc/NetworkManager/system-connections/*.nmconnection` |
| systemd-networkd | `/etc/systemd/network/*.network` |
| netplan (Ubuntu) | `/etc/netplan/*.yaml` |
| Debian 传统 | `/etc/network/interfaces` |
| RHEL 传统 | `/etc/sysconfig/network-scripts/ifcfg-*` |

## 2. 路由

```bash
$ ip route                          # IPv4 路由表
$ ip -6 route                       # IPv6
$ ip route get 8.8.8.8              # ⭐ 查某个目标实际走哪条路由
8.8.8.8 via 10.168.10.1 dev enp34s0 src 10.168.10.108 uid 1000

$ ip neigh                          # ARP/邻居表（等价旧 arp -n）
```

路由表解读：

```
default via 10.168.10.1 dev enp34s0 proto dhcp src 10.168.10.108 metric 100
10.168.10.0/24 dev enp34s0 proto kernel scope link src 10.168.10.108 metric 100
```

| 字段 | 含义 |
|------|------|
| `default` | 默认路由（`0.0.0.0/0`），匹配不到其他规则时用 |
| `via` | 下一跳网关 |
| `dev` | 出口接口 |
| `proto` | 谁装的这条路由（kernel = 直连自动生成，dhcp = DHCP 客户端） |
| `scope link` | 目标在直连链路上，不需要网关 |
| `metric` | 优先级，**数值小优先** |

```bash
# 临时加/删
$ sudo ip route add 192.168.2.0/24 via 10.168.10.254
$ sudo ip route add 10.0.0.0/8 dev tun0
$ sudo ip route del 192.168.2.0/24
$ sudo ip route add default via 10.168.10.1

# 多条默认路由：metric 小的优先
$ ip route show default
```

💡 **排查「能 ping 通 IP 但域名不通」**：那是 DNS 问题，不是路由问题。**排查「同网段通、跨网段不通」**：看默认路由和网关。

### 策略路由（多网卡场景）

```bash
$ ip rule show                 # 规则表（优先级数字小的先匹配）
$ ip route show table 100      # 查看自定义表
$ ip route add default via 10.0.0.1 table 100
$ ip rule add from 192.168.1.10 lookup 100
```

## 3. 端口与服务

```bash
# 列出监听端口（最有用的组合）
$ ss -tunlp
# -t TCP  -u UDP  -n 数字端口  -l 监听  -p 显示进程

$ ss -tunlp4                   # 只要 IPv4
$ ss -tunap                    # 所有状态（含已建立）
$ ss -tunap state established  # 只看已建立连接 ⭐
$ ss -s                        # 汇总统计
$ ss -K dst 1.2.3.4            # ⚠️ 强制关闭到某地址的连接

# 过滤
$ ss -tunlp 'sport = :22'
$ ss -tn state time-wait | wc -l

# 旧工具
$ netstat -tunlp               # 需 net-tools 包，新系统可能没有
$ sudo lsof -i :8080
$ sudo fuser -v 8080/tcp
```

### `ss` 输出字段

| 字段 | 含义 |
|------|------|
| Netid | `tcp` / `udp` / `udplite` / `raw` |
| State | `LISTEN` `ESTAB` `TIME-WAIT` `CLOSE-WAIT` `SYN-SENT` |
| Recv-Q | 接收队列中未被应用读走的字节数 |
| Send-Q | 发送队列中未确认的字节数（LISTEN 时是 backlog） |
| Local Address:Port | `0.0.0.0` = 所有 IPv4 接口，`::` = 所有 IPv6，`127.0.0.1` = 仅本机 |
| Peer Address:Port | 对端 |

⚠️ **`0.0.0.0:port` 与 `127.0.0.1:port` 的安全含义完全不同**。前者暴露给所有网络，包括公网；后者只有本机能访问。把数据库监听在 `0.0.0.0` 是最常见的配置事故。

🔐 **提权枚举第一梯队命令**：

```bash
$ ss -tunlp                    # 有哪些服务在监听
$ ss -tunap state established  # 谁连着谁
$ ps aux                       # 这些进程是谁
$ ls -l /proc/<PID>/cwd /proc/<PID>/exe
```

### 连接状态与排障

| 状态 | 含义 |
|------|------|
| `LISTEN` | 服务端在等连接 |
| `SYN-SENT` | 客户端发了 SYN，等 SYN-ACK（防火墙丢包时会卡在这） ⭐ |
| `SYN-RECV` | 收到 SYN 并回了 SYN-ACK，等 ACK（SYN flood 特征） |
| `ESTAB` | 连接已建立 |
| `TIME-WAIT` | 主动关闭方等待 2MSL（默认 60s） |
| `CLOSE-WAIT` | 收到 FIN 但本地应用没调 close（**应用 bug 信号**）⭐ |
| `LAST-ACK` | 被动关闭方等最后 ACK |

```bash
# 大量 TIME-WAIT（高并发短连接场景）
$ ss -tan state time-wait | wc -l
$ sysctl net.ipv4.tcp_tw_reuse

# 大量 CLOSE-WAIT = 应用没正确关闭连接，通常是代码问题
$ ss -tan state close-wait | head
```

## 4. DNS

```bash
# 查询（dig 最强大）
$ dig example.com
$ dig example.com A              # 指定记录类型
$ dig +short example.com         # 只要答案 ⭐
$ dig MX example.com
$ dig @8.8.8.8 example.com       # 指定 DNS 服务器
$ dig +trace example.com         # 从根开始完整追踪 ⭐ 排查 DNS 权威链路
$ dig -x 8.8.8.8                 # 反向查询 PTR
$ dig +noall +answer example.com # 只输答案段

$ host example.com
$ nslookup example.com
$ nslookup example.com 1.1.1.1

# 系统级的解析测试
$ getent hosts example.com       # ⭐ 走的是系统走的那套（含 /etc/hosts）
$ resolvectl query example.com   # systemd-resolved
$ resolvectl status              # 看当前 DNS 服务器与搜索域
```

### DNS 解析顺序

```
/etc/nsswitch.conf 里的 hosts 行决定顺序，典型为：
hosts: files dns myhostname
       ↓      ↓
     /etc/hosts   DNS 服务器
```

```bash
$ cat /etc/nsswitch.conf | grep '^hosts'
$ cat /etc/hosts
$ cat /etc/resolv.conf           # 传统配置：nameserver / search / options
```

⚠️ 现代系统上 `/etc/resolv.conf` 常是**符号链接**，由 NetworkManager / systemd-resolved 管理，手改会被覆盖：

```bash
$ ls -l /etc/resolv.conf
lrwxrwxrwx ... /etc/resolv.conf -> ../run/systemd/resolve/stub-resolv.conf
```

要永久改，用 `nmcli con mod <con> ipv4.dns "1.1.1.1 8.8.8.8"` 或改 `/etc/systemd/resolved.conf`。

### 记录类型

| 类型 | 用途 |
|------|------|
| `A` | 域名 → IPv4 |
| `AAAA` | 域名 → IPv6 |
| `CNAME` | 别名 |
| `MX` | 邮件服务器 |
| `NS` | 权威域名服务器 |
| `TXT` | 任意文本（SPF、DKIM、域名验证） |
| `SOA` | 区域起始授权 |
| `PTR` | IP → 域名（反向） |
| `SRV` | 服务位置 |

### 排查 DNS 问题

```bash
# 能 ping IP 但不能 ping 域名？
$ ping -c1 1.1.1.1 && ping -c1 example.com

# 换一个 DNS 试试
$ dig @1.1.1.1 example.com +short

# 看系统配了哪些 DNS
$ resolvectl status | grep -i 'DNS Server'
$ cat /etc/resolv.conf

# 检查是否有本地 DNS 缓存/劫持
$ ss -tunlp | grep :53
```

🔐 DNS 是信息搜集的重要来源（子域枚举、邮件服务器、TXT 记录中的内部信息）。

## 5. 抓包与流量分析

```bash
# tcpdump 基础
$ sudo tcpdump -i any -nn                 # 所有接口，不解析名字
$ sudo tcpdump -i enp34s0 port 80
$ sudo tcpdump -i any port 53 -nn
$ sudo tcpdump -i any host 10.0.0.5 and port 22
$ sudo tcpdump -i any 'tcp[tcpflags] & tcp-syn != 0'   # 只看 SYN
$ sudo tcpdump -i any -c 100 -w /tmp/cap.pcap          # 写文件，用 Wireshark 分析 ⭐
$ sudo tcpdump -r /tmp/cap.pcap -nn                    # 读取
$ sudo tcpdump -i any -A port 80                       # ASCII 显示载荷
$ sudo tcpdump -i any -X port 80                       # hex + ASCII
```

### BPF 过滤语法

| 写法 | 含义 |
|------|------|
| `host 1.2.3.4` | 源或目标是该 IP |
| `src host` / `dst host` | 限定方向 |
| `net 10.0.0.0/8` | 网段 |
| `port 80` / `portrange 8000-9000` | 端口 |
| `tcp` / `udp` / `icmp` / `arp` | 协议 |
| `and` / `or` / `not` | 逻辑 |
| `greater 1000` / `less 100` | 包长度 |

🔐 **无 tcpdump 时的替代抓包**：

```bash
# 用 ss 看连接（非抓包）
$ ss -tunap

# 用 /proc/net 直接看原始表
$ cat /proc/net/tcp        # 十六进制端口，需转换
```

`/proc/net/tcp` 端口是十六进制；`0100007F:0016` 表示 `127.0.0.1:22`。

## 6. 防火墙

Linux 上有两套内核框架，用户态工具是它们的前端。

```
iptables / iptables-nft / ufw / firewalld / ipset
        ↓ 都操作
   netfilter（内核）
        ↑ 也可直接操作
     nftables（nft）
```

| 工具 | 说明 |
|------|------|
| `iptables` | 传统，`filter`/`nat`/`mangle`/`raw` 表，链式规则 |
| `nft` | 新一代，统一了 iptables/ip6tables/arptables/ebtables |
| `ufw` | Ubuntu 的简化前端，基于 iptables |
| `firewalld` | RHEL 系，基于 zone 概念 |

### ufw（最简单）

```bash
$ sudo ufw status verbose
$ sudo ufw default deny incoming
$ sudo ufw default allow outgoing
$ sudo ufw allow 22/tcp
$ sudo ufw allow from 10.0.0.0/24 to any port 3306
$ sudo ufw delete allow 22/tcp
$ sudo ufw enable
$ sudo ufw disable
```

⚠️ **`ufw enable` 会立即生效**。若你通过 SSH 连接且没放行 22，会**当场把自己锁在外面**。先 `allow 22/tcp`，再 enable。

### firewalld

```bash
$ sudo firewall-cmd --state
$ sudo firewall-cmd --list-all
$ sudo firewall-cmd --add-port=8080/tcp --permanent
$ sudo firewall-cmd --add-service=https --permanent
$ sudo firewall-cmd --reload
$ sudo firewall-cmd --add-source=10.0.0.0/24 --zone=trusted --permanent
```

⚠️ `--permanent` 的改动必须 `--reload` 才生效；不加 `--permanent` 则只临时生效。

### nftables

```bash
$ sudo nft list ruleset
$ sudo nft list tables
$ sudo nft add table inet filter
$ sudo nft add chain inet filter input '{ type filter hook input priority 0 ; policy drop ; }'
$ sudo nft add rule inet filter input ct state established,related accept
$ sudo nft add rule inet filter input tcp dport 22 accept
$ sudo nft add rule inet filter input iif lo accept
```

### iptables

```bash
$ sudo iptables -L -n -v --line-numbers
$ sudo iptables -t nat -L -n -v
$ sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
$ sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
$ sudo iptables -P INPUT DROP            # ⚠️ 默认拒绝，可能锁死
$ sudo iptables -D INPUT 1               # 按行号删除
$ sudo iptables -F                        # ⚠️ 清空所有规则
```

⚠️ **改远程机器的 iptables 必须用定时回滚保护**：

```bash
# 5 分钟后自动恢复（防把自己锁死）
$ sudo sh -c 'echo "iptables-restore < /root/iptables.bak" | at now + 5 minutes'
# 然后放心改，改好且验证通过后
$ sudo atq && sudo atrm <jobid>
```

## 7. 连通性排查方法论

从下往上，逐层验证：

```
物理/链路层      ip link           接口 UP 吗？有 MAC 吗？
   ↓             ethtool           线插了吗？速率对吗？
IP 层            ip addr           有 IP 吗？掩码对吗？
   ↓             ping <网关IP>      能到网关吗？
   ↓             ip route          有默认路由吗？
网络层可达       ping 8.8.8.8       能出网吗？
   ↓
DNS              dig / getent      域名能解析吗？
   ↓
传输层           nc -zv host port  端口开着吗？
   ↓             ss -tunlp         本机服务在听吗？
应用层           curl -v           协议层返回什么？
```

```bash
# 一条命令走完诊断（交互式）
$ mtr -rwc 10 8.8.8.8        # 报告模式，10 个包
$ traceroute 8.8.8.8
$ tracepath 8.8.8.8          # 无需 root

# 只测端口，不依赖 nc
$ timeout 3 bash -c '</dev/tcp/example.com/443' && echo OPEN

# curl 的详细诊断
$ curl -v https://example.com
$ curl -v --connect-timeout 5 -o /dev/null -s -w '%{http_code} %{time_total}\n' https://example.com
$ curl -k -v https://example.com     # ⚠️ 跳过证书校验，仅调试
```

### `curl -w` 输出时间分解

```bash
$ curl -o /dev/null -s -w '
dns:      %{time_namelookup}\n
connect:  %{time_connect}\n
tls:      %{time_appconnect}\n
ttfb:     %{time_starttransfer}\n
total:    %{time_total}\n' https://example.com
```

| 阶段 | 慢说明什么 |
|------|-----------|
| `time_namelookup` | DNS 慢 |
| `time_connect` | TCP 握手慢（网络/防火墙） |
| `time_appconnect` | TLS 握手慢（证书链、加密协商） |
| `time_starttransfer` | 服务端处理慢 |
| `time_total` | 总耗时 |

### `ping` 输出关键信息

```bash
$ ping -c 4 1.1.1.1
PING 1.1.1.1 (1.1.1.1) 56(84) bytes of data.
64 bytes from 1.1.1.1: icmp_seq=1 ttl=57 time=12.3 ms
--- 1.1.1.1 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3003ms
rtt min/avg/max/mdev = 12.101/12.310/12.667/0.213 ms
```

| 现象 | 可能原因 |
|------|----------|
| `100% packet loss` | 对方不可达 / 被防火墙丢 ICMP / 路由问题 |
| `Destination Host Unreachable` | ARP 失败，同网段目标不在线 |
| `Network is unreachable` | 本机没有到目标的路由 |
| `ttl=` 递减异常 | 路由环路或中间设备做 NAT |
| 丢包 5–20% 且稳定 | 链路质量差、MTU 问题或限速 |

⚠️ **ping 不通不代表服务不可用**。大量主机和云厂商默认屏蔽 ICMP。判断服务可用性用 `nc -zv` 或 `curl`。

## 8. 远程访问

```bash
# SSH
$ ssh user@host
$ ssh -p 2222 user@host
$ ssh -i ~/.ssh/id_ed25519 user@host
$ ssh -v user@host                # 调试连接问题 ⭐
$ ssh -J jump@bastion user@internal    # 跳板机 ⭐
$ ssh -L 8080:localhost:80 user@host   # 本地端口转发（把远端 80 映射到本机 8080）
$ ssh -R 9000:localhost:3000 user@host # 远程端口转发
$ ssh -D 1080 user@host                # SOCKS5 动态转发 🔐
$ ssh -N -f -L 5432:db.internal:5432 user@host   # 只做转发不执行命令
$ ssh user@host 'command'         # 执行单条命令
```

🔐 SSH 隧道是内网穿透和数据外带的重要手法，防御方需监控异常的 `-R`/`-D` 使用。

```bash
# 文件传输
$ scp file.txt user@host:/path/           # ⚠️ scp 已不推荐，用 sftp/rsync
$ rsync -avz --progress src/ user@host:/dst/     # ⭐ 增量同步
$ rsync -avz --delete src/ user@host:/dst/       # ⚠️ 删除目标端多余文件
$ sftp user@host
```

`rsync` 尾部斜杠语义（极易错）：

| 写法 | 效果 |
|------|------|
| `rsync -a src/ dst/` | 把 `src` 的**内容**放进 `dst` |
| `rsync -a src dst/` | 把 `src` **目录本身**放进 `dst`，即 `dst/src` |
