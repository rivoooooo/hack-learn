### cat — 拼接并输出文件内容

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-A`、`--number` 为 GNU

#### 语法
```bash
cat [选项] [文件...]
```

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| `-n` | 给所有行编号 | `cat -n f` |
| `-b` | 编号但跳过空行 | `cat -b f` |
| `-s` | 压缩连续空行为一行 | `cat -s f` |
| `-A` | 显示 `$` 行尾、`^I` 制表符等不可见字符 | `cat -A f` ⭐ |
| `-E` | 只显示行尾 `$` | `cat -E f` |
| `-T` | 制表符显示为 `^I` | `cat -T f` |
| `-v` | 显示非打印字符 | `cat -v f` |

#### 实战示例
```bash
# 场景：查看配置（小文件）
$ cat /etc/hostname

# 场景：快速合并多个文件
$ cat part1.txt part2.txt > whole.txt

# 场景：查看换行符类型（CRLF 还是 LF）⭐
$ cat -A /tmp/win.txt | head -3
line1^M$
line2^M$
#          ^^ ^^
#          │  └─ $ 表示行尾
#          └─ ^M 表示 \r，即 Windows 换行

# 场景：追加而不覆盖
$ cat >> /tmp/notes.txt <<'EOF'
新条目
EOF

# 场景：在文件开头插入内容（cat 不能直接做，需要临时文件）
$ cat - header.txt > /tmp/new && mv /tmp/new header.txt

# 场景：heredoc 写入文件
$ sudo tee /etc/app.conf >/dev/null <<'EOF'
port=8080
EOF
```

#### 常见坑
- ⚠️ **不要用 `cat file | cmd`**（useless use of cat），直接 `cmd < file` 或 `cmd file`。少一个进程、少一次管道拷贝。
- `cat` 读取二进制文件会往终端写乱码，可能改变终端状态（`reset` 恢复）。用 `less` 或 `xxd`。
- `cat > file` 会**先清空 file**，然后等你输入。想追加用 `>>`。误操作 `cat > important.conf` 就直接毁了。
- `cat a.txt b.txt > a.txt` 会**先截断 a.txt**，结果只剩 b.txt 的内容。要合并必须用临时文件。
- 无参数时 `cat` 从 stdin 读，会看起来「卡住」——它在等你输入，`Ctrl+D` 结束。

#### 相关命令
`tac` · `less` · `head` · `tail` · `tee`

### tac — 按行倒序输出

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：非 POSIX，GNU coreutils

```bash
tac [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-s 分隔符` | 用指定分隔符（默认换行） |
| `-b` | 分隔符附加在其前面（配 `-s`） |
| `-r` | 分隔符按正则解释 |

```bash
$ printf 'a\nb\nc\n' | tac
c
b
a

# 场景：日志按时间倒序查看（最新在最上）
$ tac /var/log/app.log | head -20

# 场景：按段落倒序（分隔符为空行）
$ tac -s '' < /tmp/records.txt

# 场景：逆序 CSV 数据行
$ tac data.csv
```

#### 常见坑
- `tac` 用于**大文件**时会一次性读入（需要 seek），比 `tail` 慢。只是看末尾还是用 `tail`。
- 对管道（不可 seek）也能工作，但会先缓冲全部内容。
- 不会保留末尾缺失换行的语义细节：`printf 'a\nb' | tac` 输出 `ba`（b 和 a 之间没有换行），这是常见困惑。

#### 相关命令
`cat` · `tail` · `sort -r`

### less — 分页浏览文件

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`less` 是 `more` 的增强，非 POSIX

```bash
less [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-N` | 显示行号 |
| `-S` | 不折行（横向滚动） |
| `-R` | 正确显示 ANSI 颜色码 ⭐ |
| `-F` | 只有一屏内容时直接退出（适合管道） |
| `-X` | 退出时不清屏（保留内容在终端里） |
| `-i` | 搜索忽略大小写 |
| `+F` | 打开后立即进入跟随模式 |
| `+/模式` | 打开后立即搜索 |
| `-n` | 关闭行号（覆盖 `-N`） |

交互键（必须记住）：

| 键 | 作用 |
|----|------|
| `空格` / `b` | 下/上一屏 |
| `d` / `u` | 下/上半屏 |
| `j` / `k` | 下/上一行 |
| `g` / `G` | 到文件头 / 尾 |
| `/模式` | 向下搜索（`n` 下一个，`N` 上一个） |
| `?模式` | 向上搜索 |
| `F` | 进入/退出跟随模式（等同 `tail -f`） |
| `&模式` | 只显示匹配的行（过滤） |
| `-N` | 切换行号 |
| `m x` / `' x` | 打标记 / 跳到标记 |
| `v` | 用 `$EDITOR` 打开当前文件 |
| `!cmd` | 执行 shell 命令 |
| `q` | 退出 |

```bash
# 场景：看大日志，保留颜色
$ journalctl -xe | less -R

# 场景：看日志实时跟随（比 tail -f 更好用，可搜索可暂停）
$ tail -f /var/log/app.log | less +F
# 按 Ctrl+C 退出跟随模式，然后可以正常搜索滚动；按 F 回到跟随

# 场景：打开就搜索
$ less +/ERROR /var/log/app.log

# 场景：大目录列表分页
$ ls -l /usr/bin | less -S

# 场景：过滤只显示含某关键词的行
$ less /var/log/syslog
# 输入 &ERROR 回车 → 只显示含 ERROR 的行
```

#### 输出解读
底部状态行：`文件名  行号/总行数  百分比  字节数`

搜索时提示 `pattern not found` 表示没有匹配。

#### 常见坑
- 管道输入时按 `F`（跟随）需要有数据持续到达；对已经完全读取的 stdin 无法跟随。
- `less -R` 才显示颜色；不加会看到 `^[[31m` 这类转义序列。
- 用 `less` 看大文件时 `G` 到大文件末尾会慢（需扫全文件）；`tail` 更快。
- `less` 在管道里默认会等待全部输入结束才能显示（除非加 `-F`），对 `tail -f` 类流会「没反应」。这是新手最常见的困惑。
- `less` 读取文件时会**占用文件描述符**；删除正在被 less 打开的文件不会释放磁盘空间，直到退出。

#### 相关命令
`more` · `tail -f` · `most` · `bat`

### more — 简易分页

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：POSIX 工具，功能远弱于 less

```bash
more [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-n` | 每屏 n 行 |
| `-d` | 显示提示 `[Press space to continue, 'q' to quit]` |
| `+n` | 从第 n 行开始 |
| `+/模式` | 从匹配处开始 |

| 交互键 | 作用 |
|--------|------|
| `空格` | 下一屏 |
| `回车` | 下一行 |
| `/模式` | 搜索（**只能向前**，这是 more 最大的短板） |
| `q` | 退出 |

```bash
$ more /etc/services
$ more -d /var/log/syslog
$ more +100 /var/log/syslog
```

#### 常见坑
- **只能向前搜索**，不能回退，这是它被 `less` 取代的主因。
- 一切存在 `more` 的场景都应优先用 `less`（Linux 上 `more` 常是 `less` 的软链接或极简实现）。
- 输出被重定向到文件时 `more` 不生效（没有终端）。

#### 相关命令
`less` · `pg`

### head — 取前 N 行或字节

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：无（`-q`/`-v`/`-z` 为 GNU）

```bash
head [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-n N` | 前 N 行（默认 10）。支持 `-n -5` 表示「除最后 5 行外全部」 |
| `-c N` | 前 N 字节。同样支持 `-c -100` |
| `-q` | 多个文件时不打印文件名头 |
| `-v` | 总是打印文件名头 |
| `-z` | NUL 分隔（配 `grep -z` / `xargs -0`） |

```bash
# 场景：看文件头
$ head -n 5 /etc/passwd

# 场景：除最后 3 行之外的全部（POSIX 风格）
$ head -n -3 /var/log/app.log

# 场景：看 CSV 表头 + 前 3 行数据
$ head -n 4 data.csv

# 场景：按字节截断（生成测试样本）
$ head -c 1024 /dev/urandom > /tmp/sample.bin
$ ls -l /tmp/sample.bin
-rw-r--r-- 1 user user 1024 ... /tmp/sample.bin

# 场景：多个文件时不加分隔标题
$ head -q -n 1 a.txt b.txt

# 场景：取文件前 1 MiB 用于初步分析
$ head -c 1M big.bin > head.bin
```

#### 常见坑
- **`head -n -3` 需要读整个文件**（因为要知道末尾在哪），对巨大文件比 `head -n 3` 慢得多。
- `head -5 file`（省略 `-n`）是历史遗留写法，GNU 支持但 POSIX 已废弃，脚本里写 `-n 5`。
- `head -c` 是按**字节**不是字符，UTF-8 中文会被截断在字符中间产生乱码。
- 多个文件时默认会打印 `==> 文件名 <==` 头，脚本里解析要加 `-q`。

#### 相关命令
`tail` · `sed -n '1,5p'` · `awk 'NR<=5'`

### tail — 取后 N 行或实时跟随

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-f`/`-F` 名称是 GNU，但 BSD 也支持

```bash
tail [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-n N` | 后 N 行（默认 10）；`-n +N` 表示从第 N 行开始到末尾 ⭐ |
| `-c N` | 后 N 字节；`-c +N` 同理 |
| `-f` | 跟随文件增长（follow） |
| `-F` | 同 `-f` 但**文件被轮转/重建后会自动重新打开** ⭐ 推荐 |
| `--pid=PID` | 当该进程退出时停止跟随 |
| `-s N` | 跟随时的轮询间隔秒 |
| `-q` / `-v` | 不打印 / 总是打印文件名 |
| `-z` | NUL 分隔 |

```bash
# 场景：看日志末尾
$ tail -n 50 /var/log/app.log

# 场景：实时跟随，日志被 logrotate 也能继续 ⭐
$ tail -F /var/log/nginx/access.log

# 场景：从第 100 行开始显示（跳过前面）
$ tail -n +100 /var/log/app.log

# 场景：跟随多个日志并带文件名
$ tail -f /var/log/nginx/access.log /var/log/nginx/error.log

# 场景：等某进程结束就停止跟随
$ tail -f --pid=$(pgrep -f myjob) /tmp/job.log

# 场景：日志轮转后旧 fd 仍指向被删文件——找出来
$ sudo lsof +L1 | grep deleted
```

#### 输出解读
`-n +N` 容易记反：`+` 表示「从这个位置开始」，所以 `tail -n +1` 等于整个文件，`tail -n +100` 是第 100 行起。

#### 常见坑
- ⚠️ **`tail -f` 在日志被 logrotate 轮转后会停在旧 inode 上，看不到新日志**。用 `-F`（等于 `--follow=name --retry`）解决。这是「tail -f 突然不输出了」的头号原因。
- `-f` 跟随的是**文件描述符**，`-F` 跟随的是**文件名**。
- 管道 + `tail -f` 时下游程序可能有缓冲，配合 `grep --line-buffered` 或 `stdbuf`。
- `tail -f` 无法跟随 pipe（stdin 不可 seek），只能跟随真实文件。
- `tail` 不显示**被覆盖**（`>` 而非 `>>`）写入的内容：`-F` 在文件被 truncate 后能检测到并从头读，但可能会漏掉中间部分。

#### 相关命令
`head` · `less +F` · `journalctl -f` · `multitail`

### cut — 按列或字符切取

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`--complement`、`--output-delimiter` 为 GNU

```bash
cut [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-d 分隔符` | 指定字段分隔符（默认 Tab） |
| `-f 列表` | 取哪些字段（`1,3` `1-3` `2-` `-2`） |
| `-c 列表` | 按字符位置 |
| `-b 列表` | 按字节位置 |
| `-s` | 不含分隔符的行不输出（默认会原样输出） |
| `--complement` | 取补集（反选） ⭐ |
| `--output-delimiter=串` | 输出时用别的分隔符 |
| `-z` | NUL 分隔 |

```bash
# 场景：取 CSV 第 1、3 列
$ printf 'a,b,c\n1,2,3\n' | cut -d, -f1,3
a,c
1,3

# 场景：取字段范围
$ cut -d: -f1,3-5 /etc/passwd | head -3
root:0:0:root
daemon:1:1:daemon

# 场景：排除某字段（取除第 2 列外的全部）
$ cut -d: -f2 --complement /etc/passwd | head -1
root:x:0:0:root:/root:/bin/bash

# 场景：换输出分隔符（把冒号换成逗号）
$ cut -d: -f1,7 --output-delimiter=',' /etc/passwd | head -3
root,/bin/bash
...

# 场景：取固定字符区间（如日志的时间戳前 19 字符）
$ cut -c1-19 /var/log/syslog | head -3

# 场景：结合 awk 处理多空格分隔（cut 做不到）
$ ps aux | awk '{print $1, $11}' | head -3
```

#### 常见坑
- ⚠️ **`cut -d` 只接受单个字符**。`cut -d', '` 是错的（会被解释成 `,`）。多字符分隔符必须用 `awk -F' '` 或 `sed`。
- 默认分隔符是 **Tab**，不指定 `-d` 时对空格对齐的文本通常无效（因为连续多个空格每个都算分隔符，产生大量空字段）。处理 `ps`/`ls -l` 输出用 `awk` 而不是 `cut`。
- 字段不存在时输出空字符串，不报错。
- 不支持正则、不支持多字符分隔、不支持字段重排。这些需求全部用 `awk`。
- `cut -c` 在 UTF-8 下按**字节**还是**字符**：GNU coreutils 8.22+ 的 `-c` 按字符（多字节安全），`-b` 按字节。老版本 `-c` 按字节，会切坏中文。

#### 相关命令
`awk` · `paste` · `join` · `sed`

### paste — 按行并排合并文件

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：无

```bash
paste [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-d 列表` | 分隔符（默认 Tab），可给多个循环使用 |
| `-s` | 串行模式：把每个文件的**所有行合并成一行** |
| `-z` | NUL 分隔 |

```bash
# 场景：两列并排（默认 Tab 分隔）
$ paste <(seq 1 3) <(seq 11 13)
1	11
2	12
3	13

# 场景：指定分隔符
$ paste -d, a.txt b.txt

# 场景：把一列数据转成一行（-s 串行）
$ printf 'a\nb\nc\n' | paste -sd, -
a,b,c
# ⭐ 这是把多行拼成逗号分隔列表的最简洁写法

# 场景：一列转多列（用 - 读 stdin 多列）
$ seq 6 | paste - - -
1	2	3
4	5	6

# 场景：从两个文件各取一列拼成对照表
$ paste <(cut -d: -f1 /etc/passwd) <(cut -d: -f7 /etc/passwd) | head -3
root	/bin/bash
...
```

#### 输出解读
短文件先耗尽时，后续列输出**空字段**（但仍然输出分隔符）。

#### 常见坑
- 默认分隔符是 **Tab**，不是空格。要空格得 `-d' '`。
- `-s` 会把**整个文件**读进一行，大文件的单行会超长，某些工具（如 `grep` 的某些实现）处理不了。
- 合并时按**行号**对齐，不做键匹配。要按内容匹配用 `join`。
- `paste -d'\0'` 可以不带分隔符合并（但 shell 里 `\0` 会截断，要用 `-d ''` 也不对；正确做法是 `paste -d '\0'` 在某些实现里才有效）。

#### 相关命令
`join` · `cut` · `awk` · `tr '\n' ','`

### sort — 排序

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-h`、`-V`、`-R` 为 GNU 扩展

```bash
sort [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-n` | 按数值排序 ⭐ |
| `-h` | 按人类可读大小（`1K` `2M`）⭐ |
| `-V` | 按版本号语义（`1.10` > `1.9`）⭐ |
| `-r` | 逆序 |
| `-u` | 排序并去重 |
| `-k 字段[,字段]` | 按字段排序 |
| `-t 分隔符` | 字段分隔符 |
| `-f` | 忽略大小写 |
| `-b` | 忽略前导空白 |
| `-g` | 通用数值（支持科学计数法） |
| `-M` | 按月名（JAN<FEB<...） |
| `-R` | 随机（`--random-sort`） |
| `-s` | 稳定排序（相同键保持原顺序） |
| `-z` | NUL 分隔 |
| `-o 文件` | 输出到文件（**可以安全地原地排序**） |
| `--parallel=N` | 并行排序 |
| `-c` | 检查是否已排序（脚本校验用） |

```bash
# 场景：数值排序（不加 -n 会按字典序，10 < 9）
$ printf '9\n10\n2\n' | sort
10
2
9
$ printf '9\n10\n2\n' | sort -n
2
9
10

# 场景：人类可读大小排序
$ du -h /var/* | sort -h -r | head -5

# 场景：按第 3 列数值逆序
$ sort -t, -k3,3n -r data.csv | head -5

# 场景：先按第 1 列升序，再按第 2 列数值降序
$ sort -t, -k1,1 -k2,2nr data.csv

# 场景：统计访问日志的 Top IP（sort | uniq -c | sort -rn 的经典三段式）
$ awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 场景：原地排序（-o 可以安全原地写）
$ sort -u -o list.txt list.txt
# 对比：sort list.txt > list.txt 会清空文件！

# 场景：版本号排序
$ printf '1.9.0\n1.10.0\n1.2.0\n' | sort -V
1.2.0
1.9.0
1.10.0

# 场景：检查是否已排序（脚本里做断言）
$ sort -c sorted.txt && echo "已排序"
```

#### 输出解读
`sort` 默认按 **LC_COLLATE** 决定的字典序，可能不是 ASCII 序。UTF-8 语言环境下大小写混排的结果可能反直觉。

```bash
$ export LC_ALL=C        # ⭐ 强制字节序，脚本里更可预测
```

#### 常见坑
- **不加 `-n` 的意外**：字段里混了非数字（如 `12abc`）时，`sort -n` 视其为 `12`。
- ⚠️ **`sort f > f` 会清空 f**（输出重定向先截断）。必须用 `-o f` 或临时文件。
- `-u` 是「排序后去重**整行**」，不是按某列去重。按列去重需要 `-k` + `awk '!seen[$0]++'`。
- 多字段排序必须写范围 `-k1,1`，只写 `-k1` 会「从第 1 字段到行尾」作为键，结果常常不是你想的。
- `sort` 内存不足时用 `-S` 指定缓冲或依赖自动的临时文件合并（会慢）。
- `LC_ALL=C` 与 `LC_COLLATE=zh_CN.UTF-8` 的排序结果不同，跨机器比较输出前要固定 locale。

#### 相关命令
`uniq` · `awk` · `comm` · `join` · `ls -S`

### uniq — 相邻行去重与计数

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-D`、`--group`、`-i`（GNU 有，BSD 部分缺）

```bash
uniq [选项] [输入 [输出]]
```

| 选项 | 含义 |
|------|------|
| `-c` | 在前面加出现次数 ⭐ |
| `-d` | 只输出有重复的行（每组一次） |
| `-D` | 只输出有重复的行（**全部重复行**） |
| `-u` | 只输出去重后唯一的行 |
| `-i` | 忽略大小写 |
| `-f N` | 跳过前 N 个字段再比较 |
| `-s N` | 跳过前 N 个字符 |
| `-w N` | 只比较前 N 个字符 |
| `-z` | NUL 分隔 |

```bash
# 场景：去重（必须先去重排序）
$ printf 'a\nb\na\n' | uniq
a
b
a                # 未排序，a 不相邻所以没去掉
$ printf 'a\nb\na\n' | sort | uniq
a
b

# 场景：计数排序（日志分析核心）⭐
$ awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -5
   1234 192.168.1.10
    987 10.0.0.5
    ...

# 场景：找出只出现一次的行
$ sort list.txt | uniq -u

# 场景：找出重复的行
$ sort list.txt | uniq -d

# 场景：忽略前 2 个字段比较（日志按时间前缀去重）
$ uniq -f2 access.log

# 场景：统计某字段的取值分布
$ cut -d, -f3 data.csv | sort | uniq -c | sort -rn
```

#### 输出解读
`uniq -c` 的输出格式是「左对齐的计数 + 空格 + 行内容」，脚本解析用 `awk '{print $1}'` 注意行内容可能以空格开头导致字段偏移。

#### 常见坑
- ⚠️ **`uniq` 只处理相邻重复行**。不先 `sort` 就基本没用。这是最高频的误解。
- `uniq -c` 的计数列有前导空格，且行内容若含空格会让 `awk '{print $2}'` 取错。稳妥用 `awk '{c=$1; $1=""; print c, substr($0,2)}'` 或用 `sed 's/^ *//'`。
- `-d` 每组只输出一次，`-D` 输出所有重复行。这两个很容易记混。
- `uniq` 不能按「某列」去重（`-f`/`-s`/`-w` 只能跳过或截断，仍比较整行剩余部分）。真要按列去重用 `awk '!seen[$3]++'`。
- 保留顺序的去重用 `awk '!seen[$0]++'`，不要用 `sort -u`（会打乱顺序）。

#### 相关命令
`sort` · `awk` · `comm` · `tr -s`

### wc — 统计行数/字节

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-m`、`-L` 为 GNU/POSIX 混合

```bash
wc [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-l` | 行数（换行符个数） ⭐ |
| `-w` | 词数（空白分隔） |
| `-c` | 字节数 |
| `-m` | 字符数（多字节按字） |
| `-L` | 最长行的长度 |
| `--files0-from=文件` | 从文件读 NUL 分隔的路径列表 |

```bash
# 场景：统计文件行数
$ wc -l /etc/passwd
42 /etc/passwd

# 场景：只输出数字（脚本里最常用）⭐
$ wc -l < /etc/passwd
42

# 场景：统计目录里所有文件总行数（注意文件名含空格）
$ find /etc -name '*.conf' -print0 | wc -l --files0-from=-

# 场景：找最长的行
$ wc -L /var/log/app.log

# 场景：判断文件是否为空
$ [ "$(wc -c < f)" -eq 0 ] && echo empty

# 场景：统计命令输出的行数
$ ss -tunlp | wc -l
```

#### 输出解读
默认输出三列：`行数 词数 字节数 文件名`。用 `< file` 时没有文件名列。

#### 常见坑
- ⚠️ **`wc -l` 数的是换行符个数，不是行数**。最后一行没有换行符时，`wc -l` 少算 1。`printf 'a\nb' | wc -l` 输出 1，但实际有两行内容。用 `grep -c ''` 或 `awk 'END{print NR}'` 得到真实行数。
- `-c` 是字节，`-m` 是字符。UTF-8 中文一个字 3 字节，两者差异很大。
- `wc -l file1 file2` 最后会有一行 `total`，脚本解析要用 `< file` 或 `--files0-from` 避免。
- 读取 `/dev/null` 和时间统计组合可用于性能测试，但 `time` 的输出是 stderr，别和 `wc` 混在一个管道里。

#### 相关命令
`grep -c` · `awk 'END{print NR}'` · `nl`

### tr — 字符替换/删除/压缩

**常用度**：★★★★☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-C`、字符类语法是 GNU 扩展

```bash
tr [选项] 集合1 [集合2]
```

⚠️ `tr` **只从 stdin 读、只往 stdout 写**，不接受文件名参数。

| 选项 | 含义 |
|------|------|
| `-d` | 删除集合1中的字符 |
| `-s` | 把「集合1中连续重复」压缩成一个 |
| `-c` / `-C` | 取集合1的补集 |
| `-t` | 截断集合1到集合2的长度 |
| `--delete` / `--squeeze-repeats` | 长选项 |

字符集合写法：

| 写法 | 含义 |
|------|------|
| `a-z` | 范围 |
| `[:alpha:]` | 字母 |
| `[:digit:]` | 数字 |
| `[:space:]` | 空白（空格、Tab、换行…） |
| `[:upper:]` / `[:lower:]` | 大小写 |
| `[:punct:]` | 标点 |
| `[^...]` | 取反（也可用 `-c`） |
| `\n` `\t` `\r` | 转义（GNU tr 支持） |

```bash
# 场景：转大写/小写
$ echo 'hello world' | tr 'a-z' 'A-Z'
HELLO WORLD
$ echo 'HELLO' | tr '[:upper:]' '[:lower:]'
hello

# 场景：删除所有数字
$ echo 'a1b2c3' | tr -d '[:digit:]'
abc

# 场景：压缩连续空格 / 空白
$ echo 'a    b     c' | tr -s ' '
a b c

# 场景：把换行换成逗号（多行 → 一行）
$ printf 'a\nb\nc\n' | tr '\n' ','
a,b,c,                       # ⚠️ 末尾多一个逗号
$ printf 'a\nb\nc\n' | paste -sd, -
a,b,c                        # ⭐ 更好的写法

# 场景：删除 Windows 换行符 \r
$ tr -d '\r' < win.txt > unix.txt

# 场景：只看可打印字符（提取二进制里的字符串）
$ tr -cd '[:print:]\n' < binary | head

# 场景：把非数字字符删掉（清洗数据）
$ echo 'tel: +86-138-0000-0000' | tr -cd '0-9'
8613800000000

# 场景：补集替换（把非字母数字换成换行，用于分词）
$ echo 'a,b;c|d' | tr -cs '[:alnum:]' '\n'
a
b
c
d
```

#### 常见坑
- ⚠️ **`tr` 按字符一一映射，不能替换字符串**。`tr 'abc' 'xyz'` 是字符替换，不是字符串替换。多字符替换用 `sed`。
- ⚠️ **`tr` 不识别正则**，`tr -d 'a-z'` 里的 `-` 只有当两边是同一字符类时才是范围。
- `\n` 在 POSIX `tr` 里不一定被解释（历史上只认字面 `n`）。GNU tr 支持 `\n`，但 `\0` 有问题（NUL 会被截断）。跨平台时就写真实换行或用 `paste`。
- `-c` 与 `-C` 在 GNU tr 里针对多字节字符有区别（`-C` 按字符，`-c` 按字节），处理 UTF-8 时用 `-C`。
- 不能原地修改：`tr a b < f > f` 会清空文件。
- `[:space:]` 包含换行，压缩它会把多行合成一行。

#### 相关命令
`sed` · `awk` · `paste -sd` · `iconv`

### sed — 流式行编辑器

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-i` 是 GNU 扩展（BSD/macOS 必须写 `-i ''`）；`-E`（GNU）/ `-r`（POSIX 旧）都表示 ERE

#### 语法
```bash
sed [选项] '脚本' [文件...]
sed -e '命令1' -e '命令2' 文件
```

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| `-n` | 不自动打印，只打印 `p` 显式指定的 ⭐ | `sed -n '1,5p' f` |
| `-e` | 指定脚本（可多个） | `sed -e 's/a/b/' -e 's/c/d/'` |
| `-i[后缀]` | 原地修改文件（GNU） | `sed -i.bak 's/a/b/' f` ⚠️ |
| `-E` / `-r` | 使用扩展正则（ERE） | `sed -E 's/(a|b)/X/'` |
| `-f 文件` | 从文件读脚本 | `sed -f rules.sed f` |
| `-s` | 多文件视为独立（不连续行号） | — |
| `-z` | NUL 分隔输入 | `sed -z 's/\n/,/g'` |

#### 常用命令
| 命令 | 含义 |
|------|------|
| `s/旧/新/标志` | 替换（标志：`g` 全局、`N` 第 N 处、`p` 打印、`i`/`I` 忽略大小写） |
| `Np` / `N,Np` | 打印第 N 行 / 行范围 |
| `Nd` | 删除行 |
| `Na 文本` | 在第 N 行后追加 |
| `Ni 文本` | 在第 N 行前插入 |
| `Nc 文本` | 替换整行为文本 |
| `y/abc/xyz/` | 字符一一替换（同 `tr`） |
| `q` / `Q` | 打印当前行后退出 / 直接退出 |
| `=` | 打印行号 |

**地址（Address）**：

| 写法 | 含义 |
|------|------|
| `5` | 第 5 行 |
| `$` | 最后一行 |
| `1,5` | 1 到 5 行 |
| `/正则/` | 匹配的行 |
| `/起/,/止/` | 从匹配起到匹配止 |
| `0,/正则/` | 从文件开头到第一个匹配（处理「第一处」的经典技巧） |
| `5!` | 取反（除第 5 行外） |

#### 实战示例
```bash
# 场景：替换每行第一次出现的 foo
$ sed 's/foo/bar/' file

# 场景：替换全部
$ sed 's/foo/bar/g' file

# 场景：原地修改并备份 ⭐
$ sed -i.bak 's/8080/9090/g' /etc/app/config.conf
$ ls /etc/app/
config.conf  config.conf.bak

# 场景：只打印匹配行（-n 与 p 必须配对）
$ sed -n '/ERROR/p' /var/log/app.log

# 场景：打印行范围
$ sed -n '100,120p' file
$ sed -n '1,10p' file

# 场景：删除注释行与空行
$ sed -E '/^[[:space:]]*(#|$)/d' config.conf

# 场景：删除行尾空白
$ sed -i 's/[[:space:]]*$//' file

# 场景：在匹配行的下一行插入内容
$ sed '/^\[server\]/a port = 8080' config.ini

# 场景：只替换第 3 行
$ sed '3s/old/new/' file

# 场景：只替换匹配行的内容
$ sed '/^listen/s/80/8080/' nginx.conf

# 场景：只替换第一次匹配（0,/正则/ 技巧）⭐
$ sed '0,/foo/s//bar/' file

# 场景：多次替换（-e 链）
$ sed -e 's/a/X/g' -e 's/b/Y/g' file

# 场景：反向引用（\1 到 \9）
$ echo '2026-09-15' | sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\3\/\2\/\1/'
15/09/2026

# 场景：用其他字符当分隔符（路径里含 / 时）
$ sed 's|/usr/local|/opt|g' file
$ sed 's#/usr/local#/opt#g' file

# 场景：把文件内容合并成一行
$ sed -z 's/\n/,/g' file

# 场景：给每行加前缀
$ sed 's/^/> /' file

# 场景：提取两个标记之间的内容
$ sed -n '/BEGIN/,/END/p' file
```

#### 输出解读
`sed` 默认把「处理后的当前行」打到 stdout。`-n` 关掉这个自动打印，于是只有 `p` 命令能产生输出。**忘记 `-n` 会导致每个匹配行打印两遍**。

#### 常见坑
- ⚠️ **`sed -i` 会破坏硬链接**：GNU sed 的 `-i` 是「写临时文件 + rename」，所以 inode 变了。若文件有硬链接或正在被其他进程持有，行为会意外。`sed -i --follow-symlinks` 也不总能保住链接。
- ⚠️ **BSD/macOS 的 `-i` 必须带参数**：`sed -i 's/a/b/' f` 会把 `'s/a/b/'` 当备份后缀，然后 `f` 当脚本。正确写法 `sed -i '' 's/a/b/' f`。
- `sed` 的正则默认是 BRE（基本正则）：`+` `?` `|` `()` 需要转义。想用 ERE 加 `-E`。
- `sed` **逐行处理**，无法跨行匹配（除非用 `N`/`P`/`D` 或 `-z`）。跨行处理用 `awk` 或 `perl -0777`。
- 替换文本里的特殊字符要转义：`&` 表示「整个匹配」，`/` 要 `\/`，反斜杠要 `\\`。用别的分隔符能减少转义。
- `sed -i` 对**符号链接**默认会替换链接本身（GNU），导致链接被换成普通文件。加 `--follow-symlinks`。
- 大小写不敏感用 `I` 标志：`sed 's/foo/bar/Ig'`（GNU）。POSIX sed 不支持。

#### 相关命令
`awk` · `grep` · `perl` · `tr` · `ed`

### awk — 按字段处理文本

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：GNU awk（gawk）有 `gensub()`、`asort()`、`--csv`；BSD awk（BWK）和 mawk 功能较少

#### 语法
```bash
awk '模式 {动作}' 文件...
awk -F分隔符 '模式 {动作}' 文件
```

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| `-F 分隔符` | 字段分隔符（支持正则、多字符） | `awk -F: '{print $1}' /etc/passwd` |
| `-v 变量=值` | 从外部传变量 ⭐ | `awk -v p="$pat" '$0~p' f` |
| `-f 文件` | 从文件读程序 | — |
| `-O` | 不传（那是 sort 的） | — |
| `--csv` | 按 CSV 规则解析（gawk 5.3+） | `awk --csv '{print $2}' f.csv` |

#### 内置变量
| 变量 | 含义 |
|------|------|
| `$0` | 整行 |
| `$1`..`$NF` | 第 1..最后一个字段 |
| `NF` | 当前行的字段数 |
| `NR` | 已读总行号 |
| `FNR` | 当前文件内的行号 |
| `FS` | 输入字段分隔符（等价 `-F`） |
| `OFS` | 输出字段分隔符（默认空格） |
| `RS` | 输入记录分隔符（默认换行） |
| `ORS` | 输出记录分隔符（默认换行） |
| `FILENAME` | 当前文件名 |
| `ARGC` / `ARGV` | 参数 |
| `RSTART` / `RLENGTH` | `match()` 的结果 |

#### 常用模式
| 写法 | 含义 |
|------|------|
| `NR==5` | 第 5 行 |
| `NR>=3 && NR<=7` | 范围 |
| `/正则/` | 匹配行 |
| `/正则/ && $1>100` | 组合 |
| `!$2` | 第 2 字段为空或 0 |
| `BEGIN{...}` | 读输入前执行 |
| `END{...}` | 读完后执行 |
| `$1~/pat/` | 字段匹配正则 |
| `$1!~/pat/` | 不匹配 |
| `/a/,/b/` | 范围模式 |

#### 实战示例
```bash
# 场景：取第 1 和第 7 字段
$ awk -F: '{print $1, $7}' /etc/passwd | head -3
root /bin/bash
...

# 场景：求和 / 求平均 ⭐
$ awk '{s+=$1} END{print "sum="s, "avg="s/NR}' numbers.txt

# 场景：按第 1 列分组求和（日志分析核心）
$ awk '{a[$1]+=$2} END{for (k in a) print k, a[k]}' data.txt

# 场景：统计每行字段数不等于 7 的异常行
$ awk -F: 'NF!=7 {print NR": "NF" fields"}' /etc/passwd

# 场景：条件过滤 + 格式化输出
$ awk -F: '$3>=1000 && $3<65534 {printf "%-15s UID=%d\n", $1, $3}' /etc/passwd

# 场景：只打印某列非空的行
$ awk -F, '$3!=""' data.csv

# 场景：去重且保留原顺序（uniq 做不到）⭐
$ awk '!seen[$0]++' file.txt

# 场景：按某列去重
$ awk -F, '!seen[$2]++' data.csv

# 场景：取最长的行
$ awk 'length>max {max=length; line=$0} END{print max, line}' file

# 场景：两文件关联（类似 join，但更灵活）
$ awk 'NR==FNR {map[$1]=$2; next} {print $1, map[$1], $2}' map.txt data.txt

# 场景：替换（sub 只第一处，gsub 全部）⭐
$ awk '{gsub(/foo/, "bar"); print}' file
$ awk '{sub(/^[ \t]+/, ""); print}' file        # 去行首空白

# 场景：多字符分隔符（cut 做不到）
$ awk -F'\\|\\|' '{print $2}' file

# 场景：处理 CSV 时把逗号分隔输出成 Tab
$ awk -F, 'BEGIN{OFS="\t"} {print $1,$3}' data.csv

# 场景：打印两个标记之间的行
$ awk '/BEGIN/,/END/' file

# 场景：把相邻 3 行合并成一行
$ awk 'ORS=NR%3?" ":"\n"' file

# 场景：计算每列的 sum（动态列数）
$ awk -F, '{for(i=1;i<=NF;i++) s[i]+=$i} END{for(i=1;i<=NF;i++) printf "%s=%s ", i, s[i]; print ""}' data.csv
```

#### 输出解读
`NR==FNR` 是 awk 里判断「正在读第一个文件」的经典技巧，因为读第一个文件时 `NR` 与 `FNR` 相同。

#### 常见坑
- ⚠️ **`$1` 与 `$ 1` 有区别**：前者是字段，后者是整行（`$0`）。同理 `$NF` vs `$(NF)`。
- `awk` 程序**必须用单引号**（否则 `$1` 被 shell 展开为空）。要传 shell 变量用 `-v`，不要用双引号硬拼。
- `-F` 的值会被 awk 当**正则**处理：`awk -F.` 里的 `.` 匹配任意字符，正确的字面点号是 `-F'\\.'` 或 `-F'[.]'`。
- **字段分隔与 `-F` 的交互**：指定 `-F` 后，`$1` 之前的前导空白不再被自动去掉。
- 修改 `$1`（如 `$1="X"`）会触发**整行重建**，用 `OFS` 重新拼接，可能改变原格式。
- `sub`/`gsub` 只对 `$0` 生效（默认），对某字段要用 `sub(..., $2)`。
- `printf` 不会自动加换行，`print` 会。
- **浮点精度**：awk 用双精度，`0.1+0.2` 有误差。金额计算别用 awk。
- `mawk` 是 Debian/Ubuntu 的默认 `awk`，性能好但缺 `gensub`、`asort`。需要 gawk 特性时显式调用 `gawk`。

#### 相关命令
`sed` · `grep` · `cut` · `sort` · `jq`

### grep — 按模式过滤行

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-P`（PCRE）、`-r`、`-o`、`--color`、`-z` 都是 GNU 扩展；BSD/macOS 基本不支持 `-P`

```bash
grep [选项] 模式 [文件...]
```

#### 高频选项
| 选项 | 含义 |
|------|------|
| `-i` | 忽略大小写 |
| `-v` | 反选（不匹配的行） |
| `-c` | 只输出匹配的行数 |
| `-l` | 只输出含匹配的文件名 |
| `-L` | 只输出**不含**匹配的文件名 |
| `-n` | 显示行号 |
| `-H` | 总是显示文件名 |
| `-h` | 不显示文件名 |
| `-r` / `-R` | 递归（`-R` 跟随符号链接） |
| `-o` | 只输出匹配的部分 ⭐ |
| `-w` | 整词匹配 |
| `-x` | 整行匹配 |
| `-A N` / `-B N` / `-C N` | 显示后/前/前后 N 行上下文 ⭐ |
| `-m N` | 最多匹配 N 次后停止（大文件提速） |
| `-q` | 静默，只用退出码 |
| `-s` | 抑制错误信息（文件不存在等） |
| `-a` | 把二进制当文本处理 |
| `-z` | NUL 分隔 |
| `-P` | 使用 PCRE（需 GNU grep 编译支持） |
| `-E` | ERE（等价 `egrep`） |
| `-F` | 固定字符串（等价 `fgrep`），最快 |
| `--color=auto` | 着色 |
| `--include=GLOB` / `--exclude=GLOB` | 递归时过滤文件 |
| `--exclude-dir=DIR` | 排除目录 |

#### 退出码
| 码 | 含义 |
|----|------|
| `0` | 至少匹配一行 |
| `1` | 没有匹配 |
| `2` | 出错（文件不存在、正则非法） |

#### 实战示例
```bash
# 场景：在文件中找关键词
$ grep -n 'ERROR' /var/log/app.log | head

# 场景：递归搜索代码，排除噪音目录 ⭐
$ grep -rn --include='*.py' --exclude-dir={.git,venv,__pycache__} 'TODO' .

# 场景：显示上下文
$ grep -C 3 'panic' /var/log/kern.log

# 场景：只看匹配的部分（提取 IP）
$ grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' access.log | sort -u

# 场景：反选，去掉注释和空行
$ grep -vE '^\s*(#|$)' config.conf

# 场景：计数
$ grep -c 'POST' access.log

# 场景：找出哪些文件里有匹配（不含内容）
$ grep -rl 'password' /etc/ 2>/dev/null

# 场景：多个模式
$ grep -e 'ERROR' -e 'FATAL' app.log
$ grep -E 'ERROR|FATAL' app.log

# 场景：整个词匹配（避免匹配到 foobar）
$ grep -w 'foo' file

# 场景：大文件只看前 5 条就退出（提速）⭐
$ grep -m5 'ERROR' huge.log

# 场景：只判断是否存在（脚本里用退出码，不产生输出）
$ if grep -q 'pattern' file; then echo found; fi

# 场景：🔐 搜索日志中的敏感信息
$ grep -rIn --exclude-dir={.git,node_modules} -E 'AKIA[0-9A-Z]{16}|BEGIN [A-Z ]*PRIVATE KEY' .

# 场景：PCRE 环视（grep -E 做不到）
$ echo 'price: $100' | grep -oP '(?<=price: \$)\d+'
100

# 场景：统计多少个文件包含匹配
$ grep -rl 'pattern' . | wc -l

# 场景：读文件名列表（含空格）
$ grep -f patterns.txt target.txt
$ grep --include='*.log' -r 'ERROR' /var/log
```

#### 常见坑
- ⚠️ **`grep pattern file` 在模式以 `-` 开头时会被当选项**：用 `grep -- '-foo' file` 或 `grep -e '-foo' file`。
- ⚠️ **BRE 的默认行为**：`grep 'a+b'` 里 `+` 是字面量，不是「一个或多个」。要用 `-E` 或写 `\+`。
- ⚠️ **`grep -r` 会扫二进制文件并打印「Binary file X matches」**，用 `-I` 跳过二进制，或 `-a` 强制当文本。
- **`grep -c` 与 `wc -l` 不同**：`-c` 数的是匹配的**行数**，不是匹配次数。`grep -o | wc -l` 才是次数。
- 递归时若不排除 `.git`，可能扫到几十 GB 的 pack 文件。
- `-q` 与 `-m1` 组合是最快的存在性检查，因为它匹配到就退出，不读完全文。
- `--color=always` 会被传给下游程序（`less`、文件），用 `auto` 或 `always` 配 `less -R`。
- 管道中的缓冲问题：`tail -f log | grep ERROR` 没输出时加 `--line-buffered`。
- `grep -P` 依赖 PCRE 编译选项，有些发行版不带。会报 `grep: support for the -P option is not compiled into this binary`。用 `pcregrep` 或 `rg` 替代。
- 文件名以 `\n` 分隔的极端情况：`grep -rlZ` 输出 NUL 分隔。

#### 相关命令
`ripgrep (rg)` · `ack` · `ag` · `sed -n '/pat/p'` · `awk '/pat/'`

### diff — 比较文件差异

**常用度**：★★★★★ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-y`、`--color`、`-r` 的组合 GNU 更丰富

```bash
diff [选项] 文件1 文件2
diff -r 目录1 目录2
```

| 选项 | 含义 |
|------|------|
| `-u` | 统一格式（`unified`），最常用，能直接喂给 `patch` ⭐ |
| `-c` | 上下文格式（旧） |
| `-y` | 并排显示 |
| `-i` | 忽略大小写 |
| `-w` | 忽略所有空白 |
| `-b` | 忽略空白数量差异 |
| `-B` | 忽略空行 |
| `-r` | 递归比较目录 |
| `-q` | 只报告是否有差异 |
| `-s` | 相同时也报告 |
| `-N` | 缺失文件当空文件（生成可创建文件的补丁） |
| `--color=auto` | 着色 |
| `-Z` | 忽略行尾空白 |
| `--brief` | 同 `-q` |
| `-x PATTERN` | 递归时排除匹配文件 |

```bash
# 场景：统一格式比较（生成补丁的标准格式）⭐
$ diff -u old.conf new.conf
--- old.conf	2026-09-14 10:00:00
+++ new.conf	2026-09-15 11:00:00
@@ -1,4 +1,4 @@
 [server]
-port = 8080
+port = 9090
 [log]
 level = info

# 场景：并排比较（人眼友好）
$ diff -y --width=120 old.txt new.txt

# 场景：只看是否有差异（脚本里用，最小输出）
$ diff -q a b || echo "有差异"

# 场景：递归比较目录，排除噪音 ⭐
$ diff -r -x '*.o' -x '*.pyc' --brief dir1 dir2

# 场景：忽略空白差异（缩进改动不该算差异）
$ diff -uw file1 file2

# 场景：比较并着色，用 less 浏览
$ diff -u a b | less -R

# 场景：🔐 检测配置文件是否被篡改（与备份对比）
$ diff -u /etc/ssh/sshd_config.orig /etc/ssh/sshd_config
```

#### 输出解读
统一格式（`-u`）的头部：

```
--- 旧文件\t时间
+++ 新文件\t时间
@@ -起始行,行数 +起始行,行数 @@
```

块内行首符号：

| 符号 | 含义 |
|------|------|
| `-` | 只在旧文件里有（被删除） |
| `+` | 只在新文件里有（被新增） |
| ` `（空格） | 两边都有（上下文） |

`-y` 并排格式的行间标记：

| 标记 | 含义 |
|------|------|
| `\|` | 有差异 |
| `<` | 只左有 |
| `>` | 只右有 |

#### 常见坑
- ⚠️ **`diff` 默认输出格式（无 `-u`）是「normal diff」**，用 `ed` 风格的编辑指令，不能直接给 `patch` 用（其实可以，但可读性差）。生成补丁**一律用 `-u`**。
- `diff` 的退出码：`0` 相同、`1` 有差异、`2` 出错。脚本里 `diff a b` 在 `set -e` 下会因为「有差异」而中断——要写成 `diff a b || true`。
- `diff -q` 在递归模式下会输出 `Files x and y differ`，解析时注意 `Only in` 也是有效信息（表示某侧缺失）。
- 比较**二进制**要加 `--text`（或 `-a`）才逐行比，否则只报 "differ"。
- `diff` 读文件是流式的，比较两个巨大文件会花时间。只想知道是否相同用 `cmp`。
- `-y` 的宽度默认 130，长行会被截断；加 `--width` 或用 `sdiff`。
- `diff -u` 生成补丁时，若文件是新建的（原来不存在），要加 `-N`，否则 `patch` 无法创建文件。

#### 相关命令
`patch` · `cmp` · `comm` · `vimdiff` · `git diff`

### patch — 应用补丁

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：无

```bash
patch [选项] [原文件 [补丁文件]]
```

| 选项 | 含义 |
|------|------|
| `-p N` | 去掉路径中的前 N 层 ⭐ |
| `-i 补丁` | 从文件读补丁 |
| `-R` | 反向应用（撤销补丁） |
| `--dry-run` | 只测试能否应用，不真改 ⭐ |
| `-b` | 应用前备份原文件（加 `.orig`） |
| `-f` | 强制，不询问 |
| `-s` | 静默 |
| `-d 目录` | 先切到该目录 |
| `-E` | 应用后删除变的空文件 |
| `--merge` | 冲突时合并（类似 git） |
| `-F N` | 允许模糊匹配（跳过 N 行） |

```bash
# 场景：生成并应用补丁 ⭐
$ diff -u orig/hello.c new/hello.c > hello.patch
$ cd orig && patch -p0 < ../hello.patch
patching file hello.c

# 场景：git 风格路径需要 -p1
$ head -2 fix.patch
--- a/src/main.c
+++ b/src/main.c
$ patch -p1 < fix.patch         # 去掉 a/ 这一层

# 场景：先测试（不改文件）⭐
$ patch --dry-run -p1 < fix.patch

# 场景：撤销已应用的补丁
$ patch -R -p1 < fix.patch

# 场景：生成新文件的补丁并应用
$ diff -uN /dev/null newfile.txt > add.patch
$ patch -p0 < add.patch

# 场景：应用失败时生成 .rej 文件，人工处理
$ patch -p1 --merge < fix.patch
$ ls *.rej *.orig
```

#### 输出解读
- `patching file X` — 成功
- `Reversed (or previously applied) patch detected!` — 补丁已应用过，或需要用 `-R`
- `Hunk #1 FAILED at 10` — 上下文不匹配，生成 `.rej`
- `.orig` 是原文件备份（`-b`），`.rej` 是应用失败的块

#### 常见坑
- ⚠️ **`-p` 的层数是最常出错的地方**。`--- a/src/main.c` 需要 `-p1`（去掉 `a`）。手工确认的方式：数 `---` 行里有多少个 `/` 是你的前缀。
- ⚠️ **先 `--dry-run`**，尤其是在源码树上。
- 补丁应用失败会留下 `.rej`/`.orig` 文件，视觉上很脏；`find . -name '*.rej' -delete` 清理。
- `patch` 默认会尝试模糊匹配（跳过行），可能把补丁应用到错误的位置。要严格匹配用 `-F0`。
- 对含 CRLF 的文件打 UNIX 补丁会全军覆没。
- 生产环境**优先用 `git apply`**（更严格、有 `--check`、支持 `--3way`）。

#### 相关命令
`diff` · `git apply` · `quilt` · `git format-patch`

### comm — 比较两个已排序文件

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`--output-delimiter`、`--total` 为 GNU

```bash
comm [选项] 文件1 文件2
```

| 选项 | 含义 |
|------|------|
| `-1` | 不显示只在文件1中的行 |
| `-2` | 不显示只在文件2中的行 |
| `-3` | 不显示两个文件都有的行 |
| `--total` | 末尾输出各列计数（GNU） |
| `--output-delimiter=串` | 列分隔符（GNU） |
| `-z` | NUL 分隔 |

```bash
# 场景：看原始三列输出
$ printf 'a\nb\nc\n' > /tmp/f1; printf 'b\nc\nd\n' > /tmp/f2
$ comm /tmp/f1 /tmp/f2
a                       # 只在 f1（第 1 列）
		b       # 都有（第 3 列，前面是 2 个 Tab）
		c
	d               # 只在 f2（第 2 列，前面 1 个 Tab）

# 场景：交集（两文件都有）⭐
$ comm -12 /tmp/f1 /tmp/f2
b
c

# 场景：差集（只在 f1）
$ comm -23 /tmp/f1 /tmp/f2
a

# 场景：对称差（只在一侧有）
$ comm -3 /tmp/f1 /tmp/f2

# 场景：对比两个用户列表的差异（运维常见）
$ comm -3 <(sort a_users.txt) <(sort b_users.txt)

# 场景：找出新增的软件包
$ comm -13 <(sort before.txt) <(sort after.txt)
```

#### 输出解读
```
第 1 列：只在文件1
第 2 列：只在文件2
第 3 列：两边都有
```
列的区分靠 **Tab 的数量**（1 个 Tab = 第 2 列，2 个 = 第 3 列）。用 `cat -A` 能看清。

#### 常见坑
- ⚠️ **必须两个文件都已排序**（按同一个 locale）。否则输出无意义。这是 comm 最大的前提。
- 列是按 Tab 位置判断的，所以**行内容里不能含 Tab**，否则列会错位。
- `-12`（交集）是最常用组合，要记住「保留哪几列 = 排除其余」。
- `comm` 只比较整行，不能按字段比较。按字段比较用 `join` 或 `awk`。
- `LC_ALL` 影响排序顺序，两个文件必须用**相同 locale** 排序。

#### 相关命令
`sort` · `uniq` · `join` · `diff` · `grep -Fvf`

### join — 按键连接两个文件

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`--header`、`-z` 为 GNU

```bash
join [选项] 文件1 文件2
```

| 选项 | 含义 |
|------|------|
| `-1 N` | 用文件1的第 N 字段作连接键 |
| `-2 N` | 用文件2的第 N 字段作连接键 |
| `-j N` | 两边都用第 N 字段 |
| `-t 字符` | 字段分隔符（默认空白） |
| `-a N` | 也输出文件 N 中没有匹配的行（左/右外连接） |
| `-v N` | **只**输出文件 N 中没有匹配的行 |
| `-o 格式` | 指定输出字段（`-o 1.1,1.2,2.3`） |
| `-i` | 忽略大小写 |
| `-e 串` | 缺失字段的替代串 |
| `--header` | 把首行当表头（GNU） |

```bash
# 场景：按第 1 列连接（类似 SQL 的 INNER JOIN）
$ cat /tmp/a.txt
1 Alice
2 Bob
$ cat /tmp/b.txt
1 100
3 300
$ join /tmp/a.txt /tmp/b.txt
1 Alice 100

# 场景：指定不同键字段
$ join -1 2 -2 1 file1 file2

# 场景：左连接（保留 file1 所有行）⭐
$ join -a1 -e NULL -o 1.1,1.2,2.2 /tmp/a.txt /tmp/b.txt
1 Alice 100
2 Bob NULL

# 场景：按 CSV 的某列连接
$ join -t, -1 1 -2 2 a.csv b.csv

# 场景：找出只在 file1 出现的键
$ join -v1 a.txt b.txt

# 场景：先排序再 join（join 要求输入已排序）
$ join <(sort -k1,1 a.txt) <(sort -k1,1 b.txt)
```

#### 输出解读
默认输出格式：`连接键 + 文件1剩余字段 + 文件2剩余字段`。

#### 常见坑
- ⚠️ **两个文件都必须按连接键排序**。没排序时 join 会漏掉匹配（不报错，只是结果不对），这是最难发现的错误。
- 默认分隔符是**任意连续空白**，且字段的前导空白不算。要按逗号等分隔必须 `-t`。
- `-a` 与 `-v` 容易混：`-a1` 是「保留 file1 全部」，`-v1` 是「只要 file1 独有」。
- 输出字段缺失时默认输出空串，用 `-e` 指定替代值。
- `join` 不能处理一个键对应多个值的笛卡尔积语义（它确实会输出所有组合，但没有 SQL 的 GROUP BY）。
- 文件较大且未排序时，`awk` 的哈希法（`NR==FNR`）比 join 更快。

#### 相关命令
`awk` · `paste` · `sort` · `comm`

### split — 拆分文件

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`--filter`、`-e`、`--numeric-suffixes` 为 GNU

```bash
split [选项] [输入 [前缀]]
```

| 选项 | 含义 |
|------|------|
| `-l N` | 每 N 行一个文件 ⭐ |
| `-b N` | 每 N 字节一个文件（支持 `1M` `1G`） |
| `-n N` | 均匀分成 N 个文件（GNU） |
| `-d` | 用数字后缀（默认字母 `aa ab ac`） |
| `--numeric-suffixes=N` | 从 N 开始编号（GNU） |
| `-a N` | 后缀长度（默认 2） |
| `--additional-suffix=.txt` | 加统一后缀 |
| `--filter='cmd'` | 把每块喂给命令（不写文件）⭐ |
| `-e` | 不生成空文件 |
| `-z` | NUL 分隔 |

```bash
# 场景：大日志按 100 万行拆分
$ split -l 1000000 -d -a 3 --additional-suffix=.log big.log chunk_
$ ls chunk_*
chunk_000.log  chunk_001.log  ...

# 场景：大文件按 100 MiB 分片（传输用）
$ split -b 100M -d --additional-suffix=.part big.iso iso.part.

# 场景：均分给并行处理
$ split -n 4 -d jobs.txt job_

# 场景：拆分并直接压缩（不落中间文件）⭐
$ split -b 100M --filter='gzip > $FILE.gz' big.log part_

# 场景：拆成每块一个 tar 包
$ split -l 1000 --filter='tar czf $FILE.tgz -T -' list.txt part_
```

#### 输出解读
默认后缀是两位字母：`xaa xab ... xaz xba ...`。超过 26×26=676 个文件后需要加 `-a`。

#### 常见坑
- ⚠️ **默认前缀 `x` 和后缀 `aa`**，很容易在目录里堆一堆 `xaa` 之类难识别的文件。**始终指定前缀和后缀**。
- 合并回来用 `cat x* > original`，但**必须确保字母序正确**（`-a` 长度要够，否则 `xaa` 之后 `xab` 正常但跨进位时可能出错）。
- `-l` 按行拆，但**文件最后一行可能没有换行符**，拆出的块拼接后语义可能变化。
- `-n N` 是「均分」，块大小按字节算，可能把一行切断。
- 拆二进制文件只能用 `-b`。

#### 相关命令
`csplit` · `cat` · `parallel` · `tar -M`

### csplit — 按模式拆分文件

**常用度**：★★☆☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：非标准但普遍可用

```bash
csplit [选项] 输入 模式...
```

| 模式 | 含义 |
|------|------|
| `/正则/` | 从匹配行起到下一匹配前，切一段 |
| `/正则/+N` | 从匹配行起再往后 N 行 |
| `/正则/-N` | 从匹配行前 N 行起 |
| `{N}` | 重复前一个模式 N 次 |
| `{*}` | 重复到文件末 |
| `N` | 在第 N 行切 |

| 选项 | 含义 |
|------|------|
| `-f 前缀` | 输出文件前缀（默认 `xx`） |
| `-b 格式` | 后缀格式（`%02d`）⭐ |
| `-n N` | 后缀位数 |
| `-k` | 出错时保留已生成的文件 |
| `-s` / `--quiet` | 不打印输出文件的大小 |
| `--suppress-matched` | 不把匹配行放进输出 |
| `-z` | 不生成空文件（GNU） |

```bash
# 场景：按章节切分 Markdown
$ csplit -f ch -b '%02d.md' book.md '/^## /' '{*}'
$ ls
ch00.md  ch01.md  ch02.md  ...

# 场景：拆日志的每个分隔符段
$ csplit -z -f part -b '%03d.log' app.log '/^-{10,}$/' '{*}'

# 场景：只切出从第一个匹配到文件末
$ csplit -f tail -b '%d.txt' README.md '/^## License/' '{0}'

# 场景：按固定行数切（用普通模式）
$ csplit -f block -b '%d.txt' data.txt 1000 '{*}'
```

#### 输出解读
`csplit` 会打印每个生成文件的名字与字节数（除非 `-s`）。默认前缀 `xx`。

#### 常见坑
- ⚠️ **`csplit` 默认不改原文件，但会覆盖同名输出文件**。前缀设计不当会覆盖已有文件。
- 匹配到的行**会被放进上一段的末尾**（默认），要丢掉用 `--suppress-matched`。这是最容易困惑的点。
- `{*}` 在最后一段匹配后可能报错 `out of range` 并**删除所有已生成文件**（除非 `-k`）。**始终加 `-k`**。
- 模式是从上往下依次匹配的，正则写宽了会吃掉后续段。
- 不支持原地处理，输入必须可 seek 或用管道。

#### 相关命令
`split` · `sed -n '/pat/,/pat/p'` · `awk`

### fold — 按宽度折行

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：无（`-s` 是 POSIX）

```bash
fold [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-w N` | 每行宽度（默认 80） |
| `-s` | 在空格处断行（不切断单词） |
| `-b` | 按字节而不是显示宽度 |
| `-c` | 按字符（默认行为） |

```bash
# 场景：把长行折成 80 列
$ fold -w 80 long.txt

# 场景：尽量在空格断，不切单词 ⭐
$ fold -s -w 72 article.txt

# 场景：把超长的一行拆开便于阅读（如 PEM 证书、base64）
$ base64 -w0 file.bin | fold -w 76 > encoded.txt

# 场景：给终端输出限宽
$ some_command | fold -s -w "$(tput cols)"

# 场景：把文本折成窄栏（生成 ASCII 海报）
$ echo "$(fortune)" | fold -s -w 40
```

#### 输出解读
`fold` 会**插换行符**，所以输出行数变多；它不改变字符内容。

#### 常见坑
- **`-w` 统计的是显示宽度还是字节**取决于 `-b`/`-c`。默认按**列**（字符），但含 Tab 时 Tab 会被算成 1 列而不是实际的 8 列，视觉上不齐。
- `-s` 只在**已有的空格**处断行；如果一行里根本没有空格（比如一个超长 URL），仍然会硬切。
- 对已经有换行的文本，`fold` 会在每个原有换行处也重新计算宽度，只处理「超过宽度」的部分。
- 中文（CJK）字符在终端占 2 列，但 `fold` 按字符算，所以折行后视觉宽度会超标。真正的显示宽度处理要用 `fmt`、`par` 或 Python 的 `textwrap`（配 `wcwidth`）。
- `fold` **不重新排版**（不调整词间距），需要段落重排用 `fmt`（见相关命令）。

#### 相关命令
`fmt` · `par` · `column -c` · `expand` · `unexpand`

### nl — 加行号

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-v`、`-i`、`-l` 是 POSIX；`-b a` 与 `cat -n` 等价

```bash
nl [选项] [文件]
```

| 选项 | 含义 |
|------|------|
| `-b a` | 给**所有**行编号（默认只给非空行编号） |
| `-b t` | 只给非空行编号（默认） |
| `-b n` | 都不编号 |
| `-b p正则` | 只给匹配的行编号 |
| `-n 格式` | 行号格式：`ln` 左对齐、`rn` 右对齐、`rz` 右对齐补零 |
| `-w N` | 行号字段宽度 |
| `-s 串` | 行号与内容的分隔符（默认 Tab） |
| `-v N` | 起始编号（默认 1） |
| `-i N` | 增量（默认 1） |
| `-l N` | `-b a` 下每 N 行算一个「逻辑页」 |

```bash
# 场景：默认行为（空行不编号）
$ printf 'a\n\nb\n' | nl
     1	a

     2	b

# 场景：所有行都编号（= cat -n）
$ printf 'a\n\nb\n' | nl -b a
     1	a
     2	
     3	b

# 场景：右对齐补零，宽度 4
$ printf 'x\n' | nl -n rz -w 4
0001	x

# 场景：只给匹配的行编号
$ nl -b p'ERROR' app.log

# 场景：从 0 开始编号（对齐数组下标）
$ nl -v 0 file

# 场景：自定义分隔符（去掉默认的 Tab，便于 awk 解析）
$ nl -s ': ' file
```

#### 输出解读
默认分隔符是 **Tab**，所以 `awk '{print $1}'` 能正确取行号。若用 `-s ': '`，行号与内容之间是 `: `，内容含空格时解析要小心。

#### 常见坑
- ⚠️ **默认不给空行编号**，这与 `cat -n`（给所有行编号）不同。要一致必须 `nl -b a`。
- 首列有**固定宽度**（默认 6），前导空格会影响脚本解析。`awk '{print $1}'` 安全，`cut -c1-3` 不安全。
- 行号与内容之间是 Tab，不是空格。
- `nl` 只能处理文本文件，不支持 `cat` 的多文件拼接语义（一次只处理一个输入）。
- 只是想加行号且不在意空行，用 `cat -n` 或 `grep -n ''`。

#### 相关命令
`cat -n` · `grep -n` · `awk '{print NR": "$0}'`

### column — 对齐成表格

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：非 POSIX；`util-linux` 提供

```bash
column [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-t` | 自动识别列边界对齐成表 ⭐ |
| `-s 分隔符` | 输入列分隔符（默认空白） |
| `-o 分隔符` | 输出列分隔符（默认两个空格） |
| `-c N` | 输出宽度（用于 `-x`） |
| `-x` | 列优先填充（而非行优先） |
| `-N 名称列表` | 表头名（配合 `--table-*`） |
| `-R 列` | 右对齐指定列 |
| `-J` / `-n` | JSON 输出 / 不用表头（新版） |
| `-T 列` | 只输出指定列 |

```bash
# 场景：把冒号分隔的 passwd 对齐成表 ⭐
$ column -t -s: /etc/passwd | head -3
root    x  0  0  root    /root       /bin/bash
daemon  x  1  1  daemon  /          /usr/sbin/nologin
bin     x  2  2  bin     /bin        /usr/sbin/nologin

# 场景：对齐 mount 输出（mount 本身就不对齐）
$ mount | column -t

# 场景：CSV 转可读表格
$ column -t -s, data.csv | head

# 场景：生成 CSV（对齐后再替换分隔符）
$ column -t -s: -o, /etc/passwd > passwd.csv

# 场景：给输出加表头 ⭐
$ (echo 'USER UID HOME SHELL'; awk -F: '{print $1,$3,$6,$7}' /etc/passwd) | column -t

# 场景：终端输出限宽分栏
$ ls /usr/bin | column -c "$(tput cols)"
```

#### 输出解读
`-t` 会**读完全部输入**才能计算各列宽度，所以是 O(内存)；大文件谨慎。

#### 常见坑
- ⚠️ **`column -t` 需要把整个输入读进内存**来算列宽。对 GB 级输入会吃光内存。
- 默认输出列分隔符是**两个空格**，`-o` 可改（改成一个空格会破坏对齐）。
- `-s` 只接受**单个字符或一个字符串**；多字符分隔符老版本 `util-linux` 支持不好（新版支持）。
- 含 CJK 字符时宽度计算不准（把中文当 1 列），对齐会歪。
- BSD/macOS 的 `column` 选项集与 util-linux 不同。
- `column` 会吃掉空列（连续分隔符），对有空字段的 CSV 要小心。`awk` + `printf` 更可控。

#### 相关命令
`awk printf` · `paste` · `pr -t` · `csvlook`

### rev — 每行字符反转

**常用度**：★★☆☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：非 POSIX，`util-linux` 提供

```bash
rev [文件...]
```

```bash
$ echo 'hello' | rev
olleh

# 场景：反转后排序（实现「按行尾排序」）
$ rev file.txt | sort | rev

# 场景：取路径的最后一段（不依赖 basename）
$ echo '/a/b/c.txt' | rev | cut -d/ -f1 | rev
c.txt

# 场景：反转十六进制串
$ echo 'deadbeef' | rev
feebdaed

# 场景：找出以某后缀结尾的行（把后缀变前缀，简化正则）
$ rev access.log | grep '^tcejorp/eliffa' | rev

# 场景：反转 IP（实现按最后一段排序）
$ echo '192.168.1.10' | rev
01.1.861.291
```

#### 常见坑
- `rev` **按字符反转**，不是按字节。UTF-8 中文不会被打碎（GNU 版本），但组合字符（如带声调的字母）会被拆开，视觉上是错的。
- 不接受长选项、没有 `--help` 之外的选项。
- 反转**不改变行数**，行内的换行位置不动。
- 与 `tac`（按行倒序）不同：`rev` 是把每行**内部**倒过来。

#### 相关命令
`tac` · `sed` · `awk` · `sort`

### strings — 提取可打印字符串

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-t` 参数格式 GNU 与 BSD 略有差异

```bash
strings [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-n N` | 最短长度（默认 4） |
| `-a` / `-` | 扫描整个文件（默认只扫已加载段） ⭐ |
| `-t 进制` | 显示偏移（`d` 十进制、`o` 八进制、`x` 十六进制） |
| `-e 编码` | 编码：`s` 7位、`S` 8位、`b` 16位大端、`l` 16位小端、`B`/`L` 32位 |
| `-f` | 每个字符串前显示文件名 |
| `-o` | 同 `-t o` |

```bash
# 场景：🔐 从二进制/内存镜像中提取线索
$ strings /usr/bin/suspicious_binary | head -20
/lib64/ld-linux-x86-64.so.2
libc.so.6
__libc_start_main
...

# 场景：找可疑的 URL / IP / 域名 ⭐
$ strings -a sample.bin | grep -E 'https?://|([0-9]{1,3}\.){3}[0-9]{1,3}'

# 场景：带偏移（用于定位）
$ strings -a -t x sample.bin | grep 'password'
   4a3d password:

# 场景：提取宽字符（Windows 二进制）
$ strings -e l win.exe | head

# 场景：看 ELF 的动态库依赖之外的硬编码路径
$ strings -a /usr/bin/app | grep '^/etc/'

# 场景：从内存转储提取全部字符串，去重后排序
$ strings -a -n 8 memdump.raw | sort -u | less

# 场景：找 base64 编码的可疑数据
$ strings -a sample.bin | grep -E '^[A-Za-z0-9+/]{40,}={0,2}$'
```

#### 输出解读
`strings` 把连续的可打印字符（默认 ≥4 个）视为一个字符串，跳过不可打印的字节。

#### 常见坑
- ⚠️ **不加 `-a` 时只扫描 ELF 的已加载段**，会漏掉未初始化数据段里的内容。取证务必 `-a`。
- `-n 4` 是默认，找短的关键词（如 `PASS`）要 `-n 2`。
- `strings` **不做编码转换**，UTF-8 中文可能被截成几段（因为多字节字符的字节值落在 ASCII 可打印范围内时算，不在时断）。
- 对**压缩/加密**的数据段，`strings` 几乎提取不到有意义内容。
- 输出量可能巨大（几十万行），必须先 `sort -u` 或 `grep`。
- `-t x` 的偏移在某些实现里对多文件会重置，定位要单文件处理。
- 🔐 提权枚举里，`strings` 常用于看 SUID 二进制里硬编码的路径或口令。

#### 相关命令
`xxd` · `od` · `readelf` · `objdump` · `binwalk`

### iconv — 字符集转换

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：POSIX 定义了 `iconv`，但可用编码集依赖 glibc

```bash
iconv -f 源编码 -t 目标编码 [文件...]
```

| 选项 | 含义 |
|------|------|
| `-f 编码` | 源编码（from） |
| `-t 编码` | 目标编码（to） |
| `-l` | 列出支持的编码 |
| `-c` | 丢弃无法转换的字符（不报错） ⭐ |
| `-s` | 静默（不打印错误） |
| `-o 文件` | 输出到文件 |

```bash
# 场景：GBK 转 UTF-8
$ iconv -f GBK -t UTF-8 legacy.txt -o utf8.txt

# 场景：UTF-16（Windows 常用）转 UTF-8
$ iconv -f UTF-16LE -t UTF-8 win.txt > unix.txt

# 场景：丢弃无法转换的字节（避免中断）⭐
$ iconv -f GB18030 -t UTF-8 -c messy.txt > clean.txt

# 场景：查看支持哪些编码
$ iconv -l | head -20
$ iconv -l | grep -i gb

# 场景：检测文件编码（iconv 不能检测，需 file 或 enca）
$ file -i legacy.txt
legacy.txt: text/plain; charset=iso-8859-1

# 场景：转编码并同时去掉 BOM
$ iconv -f UTF-8 -t UTF-8 file.txt | sed '1s/^\xEF\xBB\xBF//' > nobom.txt

# 场景：处理失败时看到具体位置
$ iconv -f GBK -t UTF-8 legacy.txt
iconv: illegal input sequence at position 12345
```

#### 输出解读
报 `illegal input sequence at position N` 表示从第 N 字节起无法转换，常见于文件里混了多种编码。

#### 常见坑
- ⚠️ **`iconv` 不检测编码，必须你自己指定 `-f`**。猜错会得到乱码或报错。
- ⚠️ **转换失败会中途停止并留下部分输出的文件**。批处理时用 `-c` 或配合 `trap` 清理。
- 输出默认到 stdout，`-o` 才写文件。用 shell 重定向时注意**不要**写回源文件（会先清空）。
- `UTF-8` 与 `UTF8` 都可，但 `UTF-16` 默认指带 BOM 的变体，无 BOM 的要写 `UTF-16LE`/`UTF-16BE`。
- 转了编码**不会**转换换行符（CRLF→LF 是 `dos2unix` 的活）。
- 终端、locale、文件编码三者不一致时看到的乱码要分清是哪一层的问题。

#### 相关命令
`file -i` · `dos2unix` · `enca` · `uconv` · `recode`

### tee — 分流输出

**常用度**：★★★★☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：`-p`、`--output-error` 为 GNU

```bash
tee [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-a` | 追加（默认覆盖） |
| `-i` | 忽略中断信号（不被 Ctrl+C 打断） |
| `-p` | 诊断写到输出而非终端（GNU） |
| `--output-error=模式` | 出错时行为：`warn`/`warn-nopipe`/`exit`/`exit-nopipe` |

```bash
# 场景：同时看和存
$ dmesg | tee /tmp/dmesg.txt | grep -i error

# 场景：⚠️ 用 sudo 写受保护文件的标准姿势 ⭐
$ echo 'export EDITOR=nvim' | sudo tee -a /etc/profile.d/editor.sh
# 对比：sudo echo '...' >> /etc/profile.d/editor.sh  ← 失败！重定向由你的 shell 执行

# 场景：写多个副本
$ ./build.sh 2>&1 | tee build1.log build2.log

# 场景：不显示在屏幕上（把 stdout 丢弃，只留文件）
$ cmd | tee /tmp/out.log > /dev/null

# 场景：只保留最后 N 行同时全量落盘
$ cmd | tee full.log | tail -5

# 场景：并行做校验与保存 ⭐
$ tar cf - /data | tee >(sha256sum > /tmp/tar.sha256) | zstd -T0 > /tmp/data.tar.zst

# 场景：同时给多个消费者
$ cmd | tee >(grep ERROR > err.log) >(grep WARN > warn.log) > /dev/null
```

#### 输出解读
`tee` 的输出顺序是「先写文件，再写 stdout」，所以看到的内容与落盘内容一致。

#### 常见坑
- ⚠️ **`sudo cmd > /etc/file` 不生效**：重定向在**你的** shell 里执行，权限不够。用 `cmd | sudo tee /etc/file` 或 `sudo sh -c 'cmd > /etc/file'`。
- ⚠️ **`tee` 会在管道是最后一段时等待文件写完**，若文件在慢速网络盘上会拖慢整个管道。
- `tee` 不加 `-a` 会**截断文件**。
- 用 `>(...)` 进程替换时输出的顺序不确定，多个消费者写同一终端会交错。
- `tee` 遇到 `SIGPIPE`（下游退出）会终止，导致文件不完整。用 `--output-error=warn-nopipe` 缓解。
- 管道中 `tee` 之后的内容若没有缓冲控制，实时性会下降（`tee` 本身不缓冲，但下游可能）。

#### 相关命令
`>` · `script` · `sudo tee` · `logger`

### xxd — 十六进制转储

**常用度**：★★★★☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：非 POSIX，随 vim 分发；`-r` 反向生成

```bash
xxd [选项] [文件]
```

| 选项 | 含义 |
|------|------|
| `-l N` | 只转储 N 字节 |
| `-s 偏移` | 从指定偏移开始（支持 `-s -N` 从末尾） |
| `-c N` | 每行 N 字节（默认 16） |
| `-g N` | 每 N 字节分组（默认 2） |
| `-p` | 纯 hex 连续输出（无偏移无 ASCII） ⭐ |
| `-r` | 反向：hex 转回二进制 ⭐ |
| `-i` | 输出 C 语言数组格式 |
| `-u` | 大写十六进制 |
| `-b` | 二进制位（bit）转储 |
| `-e` | 小端显示 |
| `-R 何时` | 颜色：`auto`/`always`/`never` |

```bash
# 场景：查看文件头（判断 magic number）
$ xxd -l 64 sample.bin
00000000: 7f45 4c46 0201 0100 0000 0000 0000 0000  .ELF............
00000010: 0300 3e00 0100 0000 5010 0000 0000 0000  ..>.....P.......
#         ↑ ELF magic

# 场景：只看前 16 字节的纯 hex（提取 magic 用于比对）
$ xxd -p -l 16 sample.bin
7f454c46020101000000000000000000

# 场景：hex 转回二进制（修改二进制时）⭐
$ echo '48656c6c6f' | xxd -r -p > hello.bin
$ cat hello.bin
Hello

# 场景：偏移定位（从 0x100 开始读 32 字节）
$ xxd -s 0x100 -l 32 sample.bin

# 场景：从文件末尾往前看
$ xxd -s -32 sample.bin

# 场景：生成 C 数组
$ xxd -i logo.png > logo.h

# 场景：对比两段二进制的字节差异
$ diff <(xxd -p a.bin) <(xxd -p b.bin) | head

# 场景：给二进制打补丁（🔐 修改代码字节）
$ printf '\x90\x90' | dd of=target.bin bs=1 seek=$((0x1234)) conv=notrunc
$ xxd -s 0x1234 -l 4 target.bin
```

#### 输出解读
```
00000000: 7f45 4c46 0201 0100  ...  .ELF....
│         │              │        └─ ASCII 表示（不可打印显示为 .）
│         │              └─ 十六进制字节（每 2 字节一组）
│         └─ 起始偏移（十六进制）
└─ 行首偏移
```

`-b` 模式下显示的是**位**，每个字节 8 位的空间被拆成独立行，极少用。

#### 常见坑
- ⚠️ **`xxd -r -p` 会忽略输入中的非 hex 字符**吗？不会——`-r` 对含空格的格式要求严格。用 `-p` 生成的要配 `-p` 读回。
- `xxd` **不是 POSIX**，最小化容器（Alpine 基础镜像、busybox）里可能没有。替代：`od -A x -t x1z`（POSIX）。
- `xxd -i` 生成的变量名来自文件名，文件名含 `-` 或 `.` 会被替换成 `_`，但与已有符号可能冲突。
- 大文件不要直接 `xxd`（输出爆炸），必须 `-l` 或 `-s` 配合。
- `-s` 的负偏移依赖文件可 seek，管道输入不支持。
- 修改二进制前**一定先备份**，`dd` 写入偏移算错会直接把文件破坏。

#### 相关命令
`od` · `hexdump` · `dd` · `strings` · `radare2`/`rizin`

### od — 进制转储

**常用度**：★★★☆☆ ｜ **所属**：文本处理 ｜ **POSIX/GNU 差异**：POSIX 工具，`-A`/`-t` 是 POSIX 语法

```bash
od [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-A 基数` | 偏移的进制：`d` `o` `x` `n`(不显示) |
| `-t 类型` | 输出类型：`x1` `x2` `x4` `o1` `d1` `u1` `c` `a` `f4` |
| `-j N` | 跳过前 N 字节 |
| `-N N` | 只读 N 字节 |
| `-v` | 不合并重复行（默认重复行会显示 `*`） |
| `-w N` | 每行字节数（默认 16） |
| `-c` | 输出可打印字符或转义名 |
| `--endian=little/big` | 字节序（GNU） |

```bash
# 场景：标准的十六进制转储（POSIX 兼容 xxd 替代）
$ od -A x -t x1z sample.bin | head -3
000000 7f 45 4c 46 02 01 01 00 00 00 00 00 00 00 00 00  >.ELF............<
000010 03 00 3e 00 01 00 00 00 50 10 00 00 00 00 00 00  >..>.....P.......<

# 场景：只看可打印字符（含转义表示）
$ printf 'AB\tC\n' | od -c
0000000   A   B  \t   C  \n
0000005

# 场景：看字节序（判断大小端）
$ printf '\x01\x02\x03\x04' | od -A n -t x4
 04030201
# 小端机器上解释了这 4 字节

# 场景：十进制字节（分析协议）
$ od -A d -t u1 -N 16 file.bin

# 场景：不合并重复行（找连续的零字节位置）
$ od -A x -t x1 -v file.bin | grep -c '00 00 00 00'

# 场景：只看指定区段
$ od -A x -t x1 -j 0x100 -N 32 file.bin
```

#### 输出解读
默认输出**八进制**（POSIX 传统），这与 `xxd` 的默认十六进制不同，所以老手看到 `od` 的乱数字要加 `-t` 明确类型。

#### 常见坑
- ⚠️ **`od` 默认是八进制**，不是十六进制。不加 `-t x1` 会看不懂（这对新手是巨大的困惑点）。
- 重复行会被折叠为 `*`，想全看要 `-v`。
- `-t x1z` 里的 `z` 是「附加可打印字符列」，等价 `xxd` 的右栏。
- BSD/macOS 的 `od` 选项名不同（用 `-t` 相同但少部分选项）。
- 处理 UTF-8 时 `-c` 把多字节字符显示为八进制转义，可读性差。

#### 相关命令
`xxd` · `hexdump` · `base64` · `strings` · `dd`
