### ls — 列出目录内容

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-h`、`--color`、`-Z`、`--time-style` 为 GNU 扩展，BSD/macOS 不支持（BSD 用 `-G` 开颜色）。

#### 语法
```bash
ls [选项] [文件...]
```

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| `-l` | 长格式（权限、属主、大小、时间） | `ls -l /etc` |
| `-a` | 显示以 `.` 开头的隐藏文件 | `ls -a ~` |
| `-A` | 同 `-a` 但不显示 `.` 和 `..` | `ls -A` |
| `-h` | 大小人类可读（配合 `-l`） | `ls -lh` |
| `-t` | 按修改时间排序（新→旧） | `ls -lt` |
| `-S` | 按大小排序（大→小） | `ls -lS` |
| `-r` | 反转排序 | `ls -ltr` |
| `-R` | 递归子目录 | `ls -R` |
| `-d` | 显示目录本身而非其内容 | `ls -ld /etc` |
| `-i` | 显示 inode 号 | `ls -li` |
| `-1` | 每行一个（管道友好） | `ls -1` |
| `-F` | 按类型加后缀（`/` 目录 `*` 可执行 `@` 链接） | `ls -F` |
| `-Z` | 显示 SELinux 上下文 🔐 | `ls -lZ /etc` |
| `--time-style` | 时间格式 | `ls -l --time-style=+%F` |
| `--color=auto` | 自动着色 | 通常在 alias 里 |

#### 实战示例
```bash
# 场景：按修改时间倒序列出最近改动的文件（排查改动最常用）
$ ls -lt /etc | head -5
total 1232
drwxr-xr-x  3 root root   4096 Sep 15 10:22 pacman.d
-rw-r--r--  1 root root    512 Sep 14 18:03 hostname
...

# 场景：只看目录，不看内容
$ ls -d /etc/*/
/etc/X11/  /etc/NetworkManager/  /etc/alsa/ ...

# 场景：找出最大的文件
$ ls -lSh /var/log | head -5

# 场景：显示目录自身权限（不是内容）
$ ls -ld /tmp
drwxrwxrwt 12 root root 4096 Sep 15 09:00 /tmp

# 场景：inode 与硬链接数一起看
$ ls -li /usr/bin/ls
```

#### 输出解读
```
-rw-r--r-- 1 root root 2801 Sep 14 09:12 passwd
│└┬┘└┬┘└┬┘ │  │    │   │     └─ 名称
│ │  │  │  │  │    │   └─ 修改时间
│ │  │  │  │  │    └─ 属组
│ │  │  │  │  └─ 属主
│ │  │  │  └─ 硬链接数（目录则是子目录数+2）
│ │  │  └─ 其他人权限
│ │  └─ 属组权限
│ └─ 属主权限
└─ 文件类型
```

#### 常见坑
- **`ls -l dir` 显示的是 `dir` 里的内容**，要看 `dir` 自己必须 `ls -ld dir`。
- `ls` 的输出**不要用于解析**（文件名可含换行符、空格）。脚本里用 `find -print0` + `xargs -0`，或 `ls -1 | while IFS= read -r`。
- `ls -t` 只按秒精度，同秒内顺序不定；要精确用 `ls -l --time-style=full-iso -t` 或 `find -printf '%T@'`。
- `ls -R` 在巨大目录树（如 `/`）上会卡死终端，用 `tree -L 2` 代替。

#### 相关命令
`stat` · `find` · `tree` · `du`

### cd — 切换工作目录

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`cd` 是 **shell 内建**，不是外部程序，所以 `which cd` 通常查不到。

#### 语法
```bash
cd [目录]
```

#### 高频用法
| 写法 | 效果 |
|------|------|
| `cd` | 回家目录（`$HOME`） |
| `cd -` | 回上一个目录（会在两个目录间来回切换） |
| `cd ..` | 上一层 |
| `cd ../..` | 上两层 |
| `cd ~alice` | 到 alice 的家目录 |
| `cd -- -foo` | 进入名字以 `-` 开头的目录（`--` 结束选项解析） |

```bash
$ cd /var/log
$ pwd
/var/log
$ cd /etc
$ cd -
/var/log
```

#### 常见坑
- `cd` 是内建命令，**子进程里的 `cd` 不影响父 shell**：`(cd /tmp; ls)` 的 `cd` 只作用于子 shell 括号内。
- `cd` 时若 shell 设置了 `CDPATH`，可能跳到你没预期的目录。`echo $CDPATH` 检查。
- 目录名含空格要加引号：`cd "my dir"`。名字以 `-` 开头用 `cd -- -weird`。

#### 相关命令
`pwd` · `pushd` · `popd` · `dirs`

### pwd — 显示当前工作目录

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：无

#### 语法
```bash
pwd [-L|-P]
```

| 选项 | 含义 |
|------|------|
| `-L`（默认） | 逻辑路径，保留符号链接（显示你「怎么走进去的」） |
| `-P` | 物理路径，解析所有符号链接（真实位置） |

```bash
$ ln -s /var/log /tmp/loglink && cd /tmp/loglink
$ pwd              # /tmp/loglink
/tmp/loglink
$ pwd -P           # /var/log
/var/log
```

#### 常见坑
- 脚本里 `$PWD` 与 `pwd` 一般相同，但 `$PWD` 是 shell 变量、可能被篡改；要真实路径用 `pwd -P`。
- 符号链接目录里 `cd ..` 的行为取决于 `set -o physical`（默认逻辑模式，`..` 会回到链接所在目录的上级）。

#### 相关命令
`cd` · `realpath` · `basename`

### mkdir — 创建目录

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：无（`-p`、`-m`、`-v` 都是 POSIX）

#### 语法
```bash
mkdir [-p] [-m 模式] 目录...
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-p` | 递归创建，且已存在不报错 | `mkdir -p a/b/c` |
| `-m` | 指定权限（不受 umask 影响） | `mkdir -m 700 secret` |
| `-v` | 打印创建的每个目录 | `mkdir -pv a/b` |

```bash
# 场景：一次创建项目骨架
$ mkdir -p ~/demo/{src,doc,test,build}
$ find ~/demo -type d
/home/user/demo
/home/user/demo/src
...

# 场景：创建仅自己可访问的目录
$ mkdir -m 700 ~/demo/secret
$ stat -c '%A %n' ~/demo/secret
drwx------ /home/user/demo/secret

# 场景：名含特殊字符
$ mkdir -- '--weird-dir'
$ mkdir 'dir with spaces'
```

#### 常见坑
- 不加 `-p` 时，若目录已存在会报 `File exists` 并返回非零退出码，脚本里加 `set -e` 会中断。
- `mkdir -p` 对**已存在的路径**也返回 0，所以不能用来判断「是不是我创建的」。
- `-m` 的权限是**最终权限**，不受 `umask` 影响（但 `mkdir -p` 时中间目录仍用 `umask`）。

#### 相关命令
`rmdir` · `rm` · `install -d` · `cp -r`

### rmdir — 删除空目录

**常用度**：★★★☆☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：无

```bash
rmdir [选项] 目录...
```

| 选项 | 含义 |
|------|------|
| `-p` | 递归删空父目录（`rmdir -p a/b/c` 依次删 c、b、a） |
| `--ignore-fail-on-non-empty` | 非空时不报错（脚本友好） |
| `-v` | 打印删除的目录 |

```bash
$ mkdir -p /tmp/a/b/c
$ rmdir -p /tmp/a/b/c
$ ls /tmp/a
ls: cannot access '/tmp/a': No such file or directory
```

#### 常见坑
- **只能删空目录**。非空会报 `Directory not empty`。要删非空目录用 `rm -r`。
- `rmdir -p` 从最深层往上删，**任一层的删除失败就停止**，可能留下部分目录。

💡 **安全用法**：脚本里清理目录时用 `rmdir` 而非 `rm -rf`，因为它在目录非空时会报错退出，避免误删真正的内容。

#### 相关命令
`mkdir` · `rm -r`

### rm — 删除文件或目录

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`--preserve-root` 默认开启是 GNU 特性。

#### 语法
```bash
rm [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-f` | 强制，忽略不存在的文件与提示 |
| `-i` | 每个文件都询问 |
| `-I` | 删除超过 3 个文件或递归时问一次（GNU 特有，推荐默认开启） |
| `-r` / `-R` | 递归删目录 |
| `-d` | 删空目录 |
| `-v` | 打印删除的每个文件 |
| `--preserve-root` | 拒绝 `rm -rf /`（GNU 默认开启） |
| `--no-preserve-root` | ⚠️ 关闭上述保护 |

#### 实战示例
```bash
# 场景：删单个文件
$ rm /tmp/old.log

# 场景：确认后再删（-i 逐个问）
$ rm -ri /tmp/project
rm: descend into directory '/tmp/project'? y

# 场景：批量删，但先确认会删哪些
$ ls -d /tmp/build-*
/tmp/build-1  /tmp/build-2
$ rm -r /tmp/build-*

# 场景：安全删除（拒绝空变量导致的路径）
$ find /tmp/empty -maxdepth 0 -type d -exec rm -r {} +
```

#### ⚠️ 危险用法与后果
```bash
$ rm -rf /                                  # GNU 有保护会拒绝，BSD 会真的删
$ rm -rf $DIR/                              # ⚠️ DIR 为空 → rm -rf /  灾难
$ rm -rf "$DIR"/                            # 加引号也没用，"" 仍是空
$ rm -rf /tmp/dir/*                         # ⚠️ * 不匹配隐藏文件，隐藏文件残留
$ rm -rf ~/.cache/*                         # 同上
```

**防御写法**：
```bash
set -u                                  # 未定义变量直接报错退出
: "${DIR:?DIR 未设置}"                   # 显式校验
rm -rf -- "${DIR:?}/"                   # -- 防止路径以 - 开头
```

#### 常见坑
- `rm -rf dir/` 和 `rm -rf dir` 对目录效果相同；但 `rm -rf symlink/`（**带尾斜杠**）会跟随符号链接删除目标内容，`rm -rf symlink` 只删链接本身。⚠️
- `rm` 默认**不删隐藏文件**，`rm -rf dir/*` 会漏掉 `.env`、`.git`。要全删用 `rm -rf dir/{*,.*}`（会报 `.`/`..` 不存在但无害），或直接 `rm -rf dir`。
- 文件名以 `-` 开头要 `rm -- -file`。
- `rm` 不保证数据不可恢复。要真删用 `shred`。
- 别给 `rm` 做 `alias rm='rm -i'` 后又在脚本里依赖交互——脚本会卡住。

#### 相关命令
`rmdir` · `shred` · `trash-put` · `find -delete`

### cp — 复制文件或目录

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-a`、`--reflink` 为 GNU/现代扩展。

#### 语法
```bash
cp [选项] 源... 目标
```

| 选项 | 含义 |
|------|------|
| `-r` / `-R` | 递归复制目录 |
| `-a` | ⭐ archive 模式 = `-dR --preserve=all`，保留权限/时间/链接/属主 |
| `-p` | 保留权限与时间戳 |
| `-d` | 保留符号链接本身（不跟随） |
| `-P` | 同 `-d` |
| `-L` | 跟随所有符号链接（默认对源文件是跟随的） |
| `-i` | 覆盖前询问 |
| `-n` | 不覆盖已存在文件 |
| `-b` | 覆盖前备份（默认加 `~`） |
| `-u` | 只在源更新时复制 |
| `-v` | 显示过程 |
| `--reflink=auto` | 支持的文件系统上做写时复制（省空间、极快） |
| `--parents` | 保留源路径结构 |

#### 实战示例
```bash
# 场景：备份单个文件
$ cp config.yml config.yml.bak

# 场景：复制目录并完整保留属性（备份正确姿势）
$ cp -a /etc/nginx /srv/backup/nginx-$(date +%F)

# 场景：只复制更新的文件（增量同步的轻量版）
$ cp -Ruv src/ /mnt/backup/src/

# 场景：避免覆盖已有文件
$ cp -n new.txt existing.txt     # 不覆盖
$ ls -l existing.txt             # 内容未变

# 场景：先看会复制什么（dry run 思路）
$ cp -Rv --parents ./a/b/c.txt /tmp/dest/

# 场景：快速复制大文件（btrfs/xfs 支持 reflink 时几乎瞬时）
$ cp --reflink=auto bigfile.iso bigfile-copy.iso
```

#### 常见坑
- ⚠️ **`cp -r src dst` 与 `cp -r src/ dst` 语义相同（都复制目录本身）**；但 `rsync` 完全不同（尾部斜杠复制内容）。两者容易搞混。
- `cp -r` 默认**跟随**源里的符号链接（把链接变成真文件）。要保留链接用 `-a` 或 `-d`。
- 目标目录里有同名目录时，`cp -r a b` 会把 `a` 放进 `b/a`；目标不存在时才创建。行为取决于目标是「已存在的目录」还是「路径」。
- `cp -a` 需要 root 才能保留属主；普通用户复制别人的文件会得到 warning 并且属主变成自己。
- 覆盖时**文件内容会先被截断**，若中途中断会得到半截文件。大文件复制考虑 `rsync --partial`。
- `cp` 的「覆盖」会保留原文件的 inode，所以硬链接关系被破坏（对同一 inode 的其他链接不可见）。

#### 相关命令
`mv` · `rsync` · `install` · `dd`

### mv — 移动或重命名

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-t`、`--backup` 为 GNU

#### 语法
```bash
mv [选项] 源... 目标
```

| 选项 | 含义 |
|------|------|
| `-i` | 覆盖前询问 |
| `-n` | 不覆盖 |
| `-f` | 强制覆盖（默认行为） |
| `-u` | 只在源更新时移动 |
| `-v` | 显示过程 |
| `-t 目录` | 指定目标目录（源列表可放前面） |
| `-b` | 覆盖前备份 |
| `--no-clobber` | 同 `-n` |

```bash
# 场景：重命名
$ mv old.txt new.txt

# 场景：移动多个文件到目录
$ mv *.log /var/log/archive/

# 场景：-t 让通配符在末尾也能用
$ mv -t /var/log/archive/ *.log

# 场景：带回滚的重命名（覆盖前备份）
$ mv -b config.yml config.new.yml
$ ls config.yml* 
config.yml~  config.new.yml

# 场景：跨文件系统移动（同一分区是改 inode，跨分区是真复制+删）
$ mv /tmp/big.iso /mnt/usb/big.iso    # ⚠️ 大文件会真的读写一遍
```

#### 输出解读
```bash
$ mv -v a.txt /tmp/
renamed 'a.txt' -> '/tmp/a.txt'      # 同分区：真的是 rename(2)，瞬时完成
$ mv -v /tmp/a.txt /mnt/usb/a.txt
renamed '/tmp/a.txt' -> '/mnt/usb/a.txt'   # 跨设备：底层是 copy + unlink，耗时
$ df -T /tmp /mnt/usb | awk '{print $1, $2}'
```

#### 常见坑
- ⚠️ **`mv` 默认直接覆盖，没有确认**。`mv -i` 能缓解，但脚本里 `-i` 会被忽略（非交互）。
- 同分区 `mv` 是 `rename(2)`，**保留 inode**，所以硬链接关系保持、文件本身没动；跨分区会创建新 inode。
- `mv dir1 dir2`：若 `dir2` 不存在则重命名；若 `dir2` 已存在且是目录，则变成 `dir2/dir1`。这是最容易误判的语义。
- `mv` 一个正在被写入的文件通常没问题（inode 不变），但跨分区时可能复制到一半失败。
- 目录不能移动到它自己的子目录里：`mv a a/b` 报 `Invalid argument`。

#### 相关命令
`cp` · `rename` · `rsync --remove-source-files`

### touch — 创建空文件或修改时间戳

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-d` 的日期格式 GNU 更宽松

```bash
touch [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-a` | 只改 atime |
| `-m` | 只改 mtime |
| `-d 时间` | 用指定时间（支持 `2026-09-15 10:00`、`yesterday`、`2 hours ago`） |
| `-t [[CC]YY]MMDDhhmm[.ss]` | POSIX 时间格式 |
| `-r 参考文件` | 用参考文件的时间 |
| `-c` | 文件不存在时不创建 |
| `-h` | 作用于符号链接本身 |

```bash
# 场景：创建占位文件
$ touch /tmp/lock.file

# 场景：批量创建测试文件
$ touch /tmp/test{01..05}.txt && ls /tmp/test*.txt

# 场景：把 mtime 改成 3 天前（测试 find -mtime）
$ touch -d '3 days ago' /tmp/old.txt
$ find /tmp -name 'old.txt' -mtime +2
/tmp/old.txt

# 场景：让 file2 的时间戳与 file1 一致
$ touch -r /tmp/file1 /tmp/file2

# 场景：只更新 atime / mtime
$ touch -a /tmp/f
$ touch -m /tmp/f
```

#### 常见坑
- ⚠️ **`touch` 改不了 ctime**。`touch` 本身也会更新 ctime（因为改了 inode）。想伪造时间躲过取证是行不通的——`ls -lc` 会暴露真实改动时间。
- `touch a b c` 若其中有文件不存在会**创建它**，不报错。
- 用 `-c` 可以只更新不创建，避免意外造出空文件。
- `-t` 的年份 `YY` 在 69–99 之间解析为 19xx，00–68 解析为 20xx（POSIX 约定）。

#### 相关命令
`stat` · `find -newer` · `date` · `truncate`

### ln — 创建硬链接与符号链接

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-n`、`-r`、`-v` 为 GNU

```bash
ln [选项] 目标 [链接名]
ln -s 目标 链接名
```

| 选项 | 含义 |
|------|------|
| `-s` | 创建符号链接（soft link） |
| `-f` | 已存在则覆盖 |
| `-n` | 目标是符号链接时，直接替换它而不是替换它的目标 ⭐ |
| `-r` | 创建相对路径的符号链接（GNU） |
| `-v` | 显示过程 |
| `-T` | 把链接名当普通文件，不当作目录 |

```bash
# 场景：硬链接（同一 inode）
$ echo hello > /tmp/orig
$ ln /tmp/orig /tmp/hard
$ ls -li /tmp/orig /tmp/hard
2097155 -rw-r--r-- 2 root root 6 ... /tmp/hard
2097155 -rw-r--r-- 2 root root 6 ... /tmp/orig
#       链接数 2，inode 相同

# 场景：更新符号链接（不误删目标目录内容）
$ ln -sfn /opt/app-v2 /opt/app          # ⭐ -n 关键
$ ls -l /opt/app
lrwxrwxrwx ... /opt/app -> /opt/app-v2

# 场景：相对路径符号链接（便于整体搬迁目录）
$ cd /opt && ln -sr app-v2/app current
$ ls -l /opt/current
lrwxrwxrwx ... /opt/current -> app-v2/app

# 场景：为二进制建别名
$ sudo ln -s /usr/local/bin/ripgrep /usr/local/bin/rg
```

#### 输出解读
```bash
$ ls -l /usr/bin/awk
lrwxrwxrwx 1 root root 4 ... /usr/bin/awk -> gawk
#  权限永远显示 rwxrwxrwx（不起作用，权限由目标决定）
#  大小 4 = 目标字符串 "gawk" 的长度
```

#### 常见坑
- ⚠️ **`ln -sf target linkname` 在 `linkname` 是「指向目录的符号链接」时会出问题**：不加 `-n` 时 `ln` 会把 `target` 放到该链接指向的**目录内部**。**始终加 `-n`**。
- 硬链接不能跨文件系统（`Invalid cross-device link`），不能指向目录（普通用户）。
- 目录的硬链接会让文件系统出现环，所以被禁止（`..` 由内核特殊处理）。
- 创建符号链接时的目标路径**不会被检查存在性**，可以指向不存在的路径（产生「断链」）。
- 相对路径符号链接的解析基于**链接所在目录**，不是基于当前目录。这是 `-r` 存在的意义。

#### 相关命令
`readlink` · `realpath` · `stat` · `find -type l`

### stat — 查看文件详细元数据

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-c`/`--printf` 为 GNU（BSD 用 `-f`）

```bash
stat [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-c '格式'` | 自定义输出格式（**脚本首选**） |
| `--printf` | 同 `-c` 但解释反斜杠转义 |
| `-f` | 显示文件系统信息而非文件信息 |
| `-L` | 跟随符号链接 |
| `-t` | 简洁一行格式 |

常用格式符：

| 符 | 含义 | 符 | 含义 |
|----|------|----|------|
| `%n` | 文件名 | `%s` | 大小（字节） |
| `%F` | 文件类型描述 | `%a` | 八进制权限 |
| `%A` | 人类可读权限 | `%U` | 属主名 |
| `%u` | 属主 UID | `%G` | 属组名 |
| `%g` | 属组 GID | `%i` | inode 号 |
| `%h` | 硬链接数 | `%d` | 设备号（十进制） |
| `%t` | 主设备号（十六进制） | `%T` | 次设备号（十六进制） |
| `%x` | atime | `%y` | mtime |
| `%z` | ctime | `%w` | btime（创建时间） |
| `%X` | atime（epoch 秒） | `%Y` | mtime（epoch 秒） |

#### 实战示例
```bash
# 场景：标准输出
$ stat /etc/hostname
  File: /etc/hostname
  Size: 8               Blocks: 8          IO Block: 4096   regular file
Device: 8,3     Inode: 2097155     Links: 1
Access: (0644/-rw-r--r--)  Uid: (    0/    root)   Gid: (    0/    root)
Access: 2026-09-14 09:12:03.114000000 +0800
Modify: 2026-06-01 11:03:44.000000000 +0800
Change: 2026-06-01 11:03:44.000000000 +0800
 Birth: 2026-06-01 11:03:44.000000000 +0800

# 场景：🔐 快速列出所有时间戳（取证用）
$ stat -c '%n | mtime=%y | ctime=%z | btime=%w' /usr/bin/passwd
/usr/bin/passwd | mtime=2026-05-02 10:00:00 | ctime=2026-06-11 21:04:00 | btime=-

# 场景：只看权限与属主
$ stat -c '%A %U:%G %n' /etc/shadow
-rw-r----- root:shadow /etc/shadow

# 场景：找 inode 号（用于按 inode 操作特殊文件名）
$ stat -c '%i' /tmp/'weird
name.txt'

# 场景：文件系统层面信息（含总块数、空闲块、挂载点）
$ stat -f /home
  File: "/home"
    ID: ... Namelen: 255     Type: ext2/ext4
Block size: 4096       Fundamental block size: 4096
Blocks: Total: 122092544  Free: 45123456  Available: 38912345
Inodes: Total: 31252480   Free: 29876543
```

#### 输出解读
| 字段 | 含义 |
|------|------|
| `Device: 8,3` | 主设备号 8（SCSI/SATA 磁盘）、次设备号 3（第 4 个分区） |
| `Size` | 文件字节数 |
| `Blocks: 8` | 实际占用的 512 字节块数 → 8 × 512 = 4096 字节 |
| `IO Block: 4096` | 文件系统的块大小 |
| `Links` | 硬链接数 |
| `Birth` | 创建时间，`-` 表示文件系统不支持（ext4 默认支持，xfs 支持，老旧 fs 不支持） |

#### 常见坑
- `stat -c %s` 给出的是**逻辑大小**；稀疏文件的实际占用看 `Blocks`。`du` 才是实际占用。
- `%c` 是 ctime 的**人类可读**输出，但注意 `stat -c '%z'` 是 ctime，容易和 `%x`（atime）记混。记法：x 在前（access），y 中（modify），z 后（change）。
- 🔐 **`stat` 不会骗人，`ls` 会**：`ls -l` 只显示 mtime，且精度到分钟（默认）或秒。取证必须用 `stat` 看 ctime。
- 磁盘上的 `Size` 与 `du` 不一致很正常（块对齐、稀疏文件、压缩、CoW）。

#### 相关命令
`ls -l` · `file` · `du` · `find -printf` · `getfattr`

### file — 判断文件真实类型

**常用度**：★★★★★ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-i`、`--mime-*` 为 GNU

```bash
file [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-b` | 不输出文件名前缀 |
| `-i` | 输出 MIME 类型 |
| `--mime-type` | 只输出 MIME 类型 |
| `--mime-encoding` | 只输出编码 |
| `-s` | 也检查块/字符设备（用于判断是否真的存在） |
| `-z` | 检查压缩文件内部 |
| `-L` | 跟随符号链接 |
| `-k` | 输出所有匹配的判定（不停在第一个） |
| `-f 清单文件` | 从文件读取待检查路径列表 |

#### 实战示例
```bash
# 场景：不看扩展名判断真实类型
$ file suspicious.jpg
suspicious.jpg: ELF 64-bit LSB executable, x86-64, dynamically linked

# 场景：MIME 类型（Web 服务、上传校验用）
$ file -i upload.png
upload.png: image/png; charset=binary

# 场景：脚本里只要类型
$ file -b --mime-type /usr/bin/ls
application/x-executable

# 场景：批量识别目录里的文件
$ find /tmp -maxdepth 1 -type f -exec file {} +

# 场景：判断是不是真的压缩包
$ file -z archive.gz
archive.gz: POSIX tar archive (gzip compressed data)

# 场景：🔐 检查 PDF 里是否嵌入了脚本
$ file -k malicious.pdf
```

#### 输出解读
| 输出片段 | 含义 |
|----------|------|
| `ELF 64-bit LSB executable, x86-64` | Linux 可执行文件 |
| `ELF 64-bit LSB shared object` | 共享库（`.so`），也可能是 PIE 可执行文件 |
| `ELF 64-bit LSB pie executable` | 位置无关可执行文件（现代默认） |
| `PE32+ executable (console) x86-64, for MS Windows` | Windows 程序 |
| `POSIX tar archive` | tar 包 |
| `ASCII text, with CRLF line terminators` | Windows 换行（做脚本会报 `\r: command not found`） |
| `UTF-8 Unicode text` | 含多字节字符的文本 |
| `data` | 无法识别的二进制 |
| `empty` | 空文件 |
| `symbolic link to ...` | 符号链接 |

#### 常见坑
- `file` **只看文件开头几百字节**（magic number），不能保证准确。伪造 magic 可以骗过它。
- 没有扩展名信息的类型判定是启发式的，`data` 表示「认不出来」而不是「没内容」。
- 对管道/设备文件要加 `-s` 才有意义（否则 `file /dev/sda` 报无法读取）。
- CRLF 的文本文件在 Linux 上执行会报 `bad interpreter: /bin/bash^M`，用 `dos2unix` 或 `sed -i 's/\r$//'` 修。

#### 相关命令
`stat` · `xxd` · `strings` · `readelf` · `mimetype`

### tree — 树状显示目录结构

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：非 POSIX，需安装（`tree` 包）

```bash
tree [选项] [目录]
```

| 选项 | 含义 |
|------|------|
| `-L n` | 只显示 n 层 |
| `-d` | 只显示目录 |
| `-a` | 显示隐藏文件 |
| `-h` | 显示人类可读大小 |
| `--du` | 显示每个目录累计大小 |
| `-P 'pattern'` | 只显示匹配的文件（需 `--matchdirs` 才包含目录） |
| `-I 'pattern'` | 排除匹配项 |
| `--gitignore` | 遵循 `.gitignore` |
| `-f` | 显示完整相对路径 |
| `-i` | 不显示缩进线（便于管道处理） |
| `-X` | 输出 XML |
| `-J` | 输出 JSON |
| `--noreport` | 去掉末尾的统计行 |
| `-C` | 彩色输出 |

#### 实战示例
```bash
# 场景：看项目结构（限 2 层）
$ tree -L 2 ~/demo
/home/user/demo
├── build
├── doc
│   └── design.md
├── src
│   └── main.c
└── test

5 directories, 2 files

# 场景：只列目录
$ tree -d -L 3 /etc/systemd

# 场景：排除噪音目录
$ tree -I 'node_modules|.git|__pycache__' -L 3 .

# 场景：带大小排序找大目录（配合 sort）
$ tree --du -h | grep -E '^[0-9.]+[KMG]' | sort -hr | head -10

# 场景：给文档生成目录树
$ tree -L 3 --charset=ascii --noreport > /tmp/structure.txt
```

#### 输出解读
```
├── 表示还有后续同级项
└── 表示同级最后一项
│   竖线表示父层还有后续
[4.0K]  加 --du 或 -h 时显示大小
```

末行 `N directories, M files` 是统计；脚本里用 `--noreport` 去掉。

#### 常见坑
- 默认**不显示隐藏文件**，要 `-a`。
- 在 `/` 或大仓库上直接 `tree` 会输出几十万行，务必加 `-L`。
- `-P` 只过滤文件时目录会被裁掉，加 `--matchdirs` 才保留匹配的目录。
- `tree` 不是 POSIX 也没有在任何基础镜像里，脚本里别依赖它（用 `find` 或 `ls -R`）。

#### 相关命令
`ls -R` · `find` · `du`

### basename — 取路径中的文件名

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：无

```bash
basename 路径 [后缀]
```

| 选项 | 含义 |
|------|------|
| `-a` | 处理多个路径（GNU） |
| `-s 后缀` | 同时去掉后缀（GNU） |
| `-z` | 用 NUL 分隔输出（GNU） |

```bash
$ basename /var/log/syslog
syslog

$ basename /var/log/syslog .log
syslog

$ basename -s .tar.gz archive-2026.tar.gz
archive-2026

# 处理多个
$ basename -a /etc/hosts /etc/passwd
hosts
passwd

# 批量为一批文件取名字
$ find /data -name '*.csv' -exec basename {} \; | head -3

# 去掉路径末尾的斜杠
$ basename /var/log/
log
```

#### 常见坑
- `basename` **不做文件系统查询**，纯字符串操作。`basename /nonexistent/a/b` 返回 `b` 而不报错。
- 尾部斜杠会被去掉：`basename a/b/` 是 `b`。
- 后缀只去掉一次且必须完全匹配：`basename foo.tar.gz .gz` → `foo.tar`。
- 与 shell 参数展开 `${path##*/}` 等价，脚本里更推荐后者（无外部进程开销）。但 `${path##*/}` 对 `a/b/` 返回空，`basename` 返回 `b`。

#### 相关命令
`dirname` · `realpath` · `readlink -f`

### dirname — 取路径中的目录部分

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：无

```bash
dirname 路径...
```

| 选项 | 含义 |
|------|------|
| `-z` | 用 NUL 分隔（GNU） |

```bash
$ dirname /var/log/syslog
/var/log

$ dirname syslog
.

$ dirname /var/log/
/var

$ dirname /home/user/proj/src/main.c
/home/user/proj/src

# 场景：在脚本里定位自己所在目录（经典写法）
$ cat /tmp/loc.sh
#!/bin/bash
SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)"
echo "$SCRIPT_DIR"
$ bash /tmp/loc.sh
/tmp

# 场景：批量对每个文件做同目录处理
$ for f in /data/*.csv; do
>   d=$(dirname "$f"); b=$(basename "$f" .csv)
>   echo "目录=$d 基名=$b"
> done
```

#### 常见坑
- `dirname foo` 返回 `.`，不是空字符串。
- `dirname /` 返回 `/`；`dirname //` 行为在 POSIX 里是实现的自由度（GNU 返回 `/`）。
- `dirname -foo` 会被当成选项，路径以 `-` 开头要加 `--`。
- 不做文件系统查询，纯字符串。路径不存在也不报错。
- 等价于 shell 的 `${path%/*}`，但 `${path%/*}` 对无斜杠的路径返回原串（不返回 `.`），行为有差异。

#### 相关命令
`basename` · `realpath` · `${BASH_SOURCE[0]}`

### realpath — 解析为绝对规范路径

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：GNU coreutils 8.15+ 提供；`-e`/`-m`/`-L` 为 GNU

```bash
realpath [选项] 路径...
```

| 选项 | 含义 |
|------|------|
| `-e` / `--canonicalize-existing` | 要求路径的每一部分都存在 |
| `-m` / `--canonicalize-missing` | 允许不存在（`-m` 是「missing」） |
| `-L` | 逻辑解析（默认，解析符号链接） |
| `-P` | 物理解析 |
| `-s` | 不解析符号链接，只清理 `.`/`..` |
| `--relative-to=目录` | 输出相对于该目录的路径（GNU） |
| `--relative-base=目录` | 只对在该目录下的路径做相对化 |

```bash
$ realpath ./../etc/../etc/hostname
/etc/hostname

# 场景：解析符号链接到真实位置
$ ln -s /var/log /tmp/link
$ realpath /tmp/link
/var/log

# 场景：不解析符号链接，只规范化
$ realpath -s /tmp/link
/tmp/link

# 场景：允许路径不存在
$ realpath -m /tmp/not/created/yet
/tmp/not/created/yet

# 场景：路径是否存在
$ realpath -e /etc/hostname && echo EXISTS
$ realpath -e /etc/nope || echo MISSING

# 场景：算相对路径
$ realpath --relative-to=/usr /usr/bin/ls
bin/ls
```

#### 常见坑
- **默认不检查存在性**（GNU 行为），路径不存在也会输出规范化结果。要检查必须 `-e`。
- `realpath` 默认解析符号链接；只想清理 `.`/`..` 用 `-s`。
- `readlink -f` 功能基本等价于 `realpath`（但 `readlink -f` 在路径不存在时**不输出**且返回非零，与 `realpath` 相反）。这是脚本里最容易踩的差异。
- 脚本里若受限于 POSIX，可用 `readlink -f` 或自己遍历。

#### 相关命令
`readlink` · `pwd -P` · `ln`

### readlink — 显示符号链接指向

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：`-f`、`-e`、`-m` 是 GNU/BSD 扩展

```bash
readlink [选项] 文件
```

| 选项 | 含义 |
|------|------|
| `-f` | 递归解析所有符号链接，要求最终目标存在（除最后一个组件外） |
| `-e` | 同 `-f` 但要求所有组件都存在 |
| `-m` | 不要求存在（「missing」） |
| `-n` | 不输出末尾换行 |
| `-z` | NUL 结尾 |
| `-v` | 详细输出（错误时） |

```bash
# 场景：看链接指向（单层）
$ readlink /usr/bin/awk
gawk

# 场景：解析到最终真实路径
$ readlink -f /usr/bin/awk
/usr/bin/gawk

# 场景：链式链接
$ ln -s /tmp/a /tmp/b; ln -s /tmp/b /tmp/c
$ readlink /tmp/c
/tmp/b
$ readlink -f /tmp/c
/tmp/a

# 场景：确认路径是否存在（-e 严格）
$ readlink -e /etc/hostname >/dev/null && echo OK

# 场景：脚本里安全取脚本真实路径
$ cat /tmp/self.sh
#!/bin/bash
SELF="$(readlink -f -- "${BASH_SOURCE[0]}")"
echo "$SELF"
```

#### 输出解读
- 不加 `-f` 时：只输出链接内容，**不递归**，且若参数不是符号链接则**无输出、退出码非 0**。
- 加 `-f` 时：输出规范化绝对路径。

#### 常见坑
- ⚠️ `readlink -f` 对不存在的路径**无输出且退出码 1**，而 `realpath` 会输出。依赖这个差异的脚本很容易写出静默 bug。
- 参数不是链接时不加 `-f` 就没输出，脚本里判断要用 `${?}` 或改用 `-f`。
- `readlink` 只处理单层，多级链接要 `-f` 或循环。
- BSD/macOS 的 `readlink` **没有 `-f`**，跨平台脚本要用 `realpath` 或 `python3 -c 'import os;print(os.path.realpath(...))'`。

#### 相关命令
`realpath` · `ln` · `stat -c %N`

### mktemp — 安全创建临时文件/目录

**常用度**：★★★★☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：GNU 支持 `-p`、`--suffix`；POSIX 只定义了 `-d` 和模板

```bash
mktemp [选项] [模板]
```

| 选项 | 含义 |
|------|------|
| `-d` | 创建临时目录 |
| `-p 目录` | 指定父目录（默认 `$TMPDIR` 或 `/tmp`） |
| `--suffix=后缀` | 加后缀 |
| `-t` | 在 `$TMPDIR` 下创建（模板必须给，已废弃写法） |
| `-u` | ⚠️ 只生成名字不创建文件（**不安全，不要用**） |
| `-q` | 失败时静默 |

```bash
# 场景：安全的临时文件
$ f=$(mktemp) && echo "hello" > "$f" && cat "$f"
/tmp/tmp.aB3xY9

# 场景：安全的临时目录
$ d=$(mktemp -d) && echo "$d"
/tmp/tmp.7kQ2Zp
$ mkdir -p "$d/sub" && ls -ld "$d"
drwx------ 3 user user 4096 ... /tmp/tmp.7kQ2Zp
# 注意权限是 700，且名字随机

# 场景：带前缀后缀，便于识别
$ mktemp /tmp/backup-XXXXXX.tar
/tmp/backup-a9Kd2f.tar

# 场景：脚本里的清理模式
$ cat /tmp/job.sh
#!/bin/bash
set -euo pipefail
work="$(mktemp -d)"
trap 'rm -rf "$work"' EXIT          # ⭐ 无论怎么退出都清理
echo "workdir=$work"
```

#### 常见坑
- **模板必须含至少 3 个连续的 `X`**。`mktemp foo` 在很多实现里会失败（GNU 会自动补，但不要依赖）。
- ⚠️ **永远不要用 `-u`**：它只生成名字，在「生成」到「你创建文件」之间存在竞态窗口（TOCTOU），攻击者可抢先创建符号链接。这是历史上的经典漏洞模式。
- `mktemp` 默认用 `$TMPDIR`，若它是攻击者可控的值就危险，加固脚本里显式指定 `/tmp` 或用 `-p`。
- 默认创建的文件权限是 `600`、目录是 `700`，这是安全的默认值（不受 `umask` 放松）。
- 生成的临时文件**不会自动删除**，必须自己 `trap` 清理，否则 `/tmp` 会堆积。

#### 相关命令
`trap` · `$TMPDIR` · `install`

### rename — 批量重命名

**常用度**：★★★☆☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：⚠️ **有两个不兼容的实现**

**两种实现必须分清**：

| 版本 | 语法 | 识别方式 |
|------|------|----------|
| Perl 版（Debian/Ubuntu 默认） | `rename 's/旧/新/' 文件...` | 第一个参数是 Perl 表达式 |
| util-linux 版（RHEL/Arch 默认） | `rename 旧串 新串 文件...` | 第一个参数是字符串 |

```bash
# ---- Perl 版 ----
$ ls
img-1.jpg  img-2.jpg
$ rename 's/\.jpg$/\.jpeg/' *.jpg
$ ls
img-1.jpeg  img-2.jpeg

$ rename 'y/A-Z/a-z/' *            # 全部转小写
$ rename -n 's/foo/bar/' *         # -n 只预览不执行 ⭐
$ rename -v 's/foo/bar/' *         # 显示改了什么

# ---- util-linux 版 ----
$ rename .jpeg .jpg *.jpeg
$ rename -v foo bar *foo*
```

```bash
# 场景：去掉文件名空格
$ find . -name '* *' -exec rename 's/ /_/g' {} +

# 场景：给一批文件加前缀（两种版本都能做的替代方案）
$ for f in *.txt; do mv -- "$f" "backup_$f"; done

# 场景：按序号重命名（rename 做不到，用循环）
$ i=1; for f in *.jpg; do mv -- "$f" "$(printf 'photo_%03d.jpg' $i)"; do ((i++)); done
```

#### 常见坑
- ⚠️ **先 `rename -n` 预览**，正则写错可能把一批文件改成你无法预料的名字。
- 判断本机版本：`rename --version`；Debian 系多为 Perl 版，RHEL/Arch 多为 util-linux 版。
- Perl 版的 `-n`（dry run）和 util-linux 版的 `-n`（no-act）含义相同，但 util-linux 版**不支持正则**。
- 没有 `rename` 时用 `mmv` 或 `for` 循环。
- 改名前注意大小写不敏感文件系统（macOS/Windows 挂载）上的同名冲突。

#### 相关命令
`mv` · `for` 循环 · `mmv`

### install — 复制并同时设置权限与属主

**常用度**：★★★☆☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：无

```bash
install [选项] 源... 目标
install -d [选项] 目录...
```

| 选项 | 含义 |
|------|------|
| `-d` | 创建目录（含父目录），并可设权限 |
| `-m 模式` | 设置权限 |
| `-o 属主` | 设置属主 |
| `-g 属组` | 设置属组 |
| `-b` | 覆盖前备份 |
| `-C` / `--compare` | 只在内容不同时才复制（省 I/O） |
| `-D` | 目标不存在时创建其父目录 |
| `-v` | 显示过程 |
| `-s` | 对可执行文件调 `strip` |
| `-t 目录` | 目标目录 |

```bash
# 场景：安装脚本 + 权限一步到位（不经过 umask）
$ install -m 755 -o root -g root myscript.sh /usr/local/bin/myscript
$ ls -l /usr/local/bin/myscript
-rwxr-xr-x 1 root root ... /usr/local/bin/myscript

# 场景：创建标准目录（一步完成多级 + 权限）
$ sudo install -d -m 750 -o app -g app /srv/app/{data,logs,tmp}
$ ls -ld /srv/app/data
drwxr-x--- 2 app app 4096 ... /srv/app/data

# 场景：只在文件变化时更新（部署脚本常用）
$ install -C -m 644 config.yml /etc/app/config.yml

# 场景：安装配置文件并备份旧版本
$ sudo install -b -m 644 new.conf /etc/app/app.conf
$ ls /etc/app/
app.conf  app.conf~
```

#### 常见坑
- `install` **不用 umask**，权限完全由 `-m` 决定（不指定时默认 `0755`）。这正是它比 `cp` + `chmod` 更好用的原因。
- `install src dst` 当 `dst` 是已存在的**目录**时，会在目录里创建同名文件；`-t` 更明确。
- 不加 `-D` 时，若目标父目录不存在会报错（`-d` 是创建目录，`-D` 是创建父目录）。
- `install` 不能复制目录的内容（没有 `-r`），只能创建目录本身。
- 二进制部署的一个坑：直接覆盖正在运行的可执行文件会得到 `ETXTBSY` 错误。**必须先删旧的或先原子替换**（`install` 到临时名 + `mv`）。

#### 相关命令
`cp` · `chmod` · `chown` · `mkdir -p`

### shred — 覆写后删除（防恢复）

**常用度**：★★☆☆☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：非 POSIX，GNU coreutils

```bash
shred [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-n N` | 覆写 N 次（默认 3） |
| `-z` | 最后再加一次用 0 覆写（掩盖 shred 痕迹） |
| `-u` | 覆写后删除文件 |
| `-f` | 强制（改权限以便覆写） |
| `-v` | 显示进度 |
| `-x` | 精确到字节（默认按块，可能不覆盖末尾） |
| `--random-source=文件` | 随机数据源 |

```bash
# 场景：彻底销毁敏感文件
$ shred -vfz -n 5 /tmp/private.key
shred: /tmp/private.key: pass 1/6 (random)...
...
$ ls /tmp/private.key
ls: cannot access '/tmp/private.key': No such file or directory

# 场景：清扫整个分区（⚠️ 极慢，彻底摧毁数据）
$ sudo shred -vfz /dev/sdb          # ⚠️⚠️ 不可恢复

# 场景：直接删除（不覆写）
$ shred -u file
```

#### ⚠️ 重要限制
`shred` 在以下情况**无法保证数据被覆盖**，官方文档明确说明：

| 场景 | 原因 |
|------|------|
| 日志型文件系统（ext3/4、XFS、btrfs、ZFS） | 覆写会写到新块，旧块里的数据仍在 |
| CoW 文件系统（btrfs、ZFS、APFS） | 同上，且更彻底 |
| 压缩文件系统 | 覆写后旧数据可能仍在压缩块里 |
| RAID / 有快照的存储 | 旧数据在其他副本或快照里 |
| 网络/虚拟文件系统 | 无法控制真实介质 |
| 硬盘的预留空间、缓存盘（SSD 的 FTL） | 物理介质上的副本无法寻址 |
| SSD/NVMe | 磨损均衡使逻辑块与物理块不再一一对应 |

**可靠的替代方案**：
- **全盘加密**（LUKS），然后用 `cryptsetup luksErase` 或销毁密钥。这是唯一实用的方案。
- SSD 用厂商的 Secure Erase（`hdparm --security-erase` 或 `nvme format`）。
- 机械盘整盘擦除：`dd if=/dev/urandom of=/dev/sdX` 或 `blkdiscard`。

#### 常见坑
- 默认 `-n 3` 次随机覆写，大文件会非常慢。
- 对目录要 `shred -vfz -n 5 dir/*`，`shred` 本身不递归。
- 不加 `-u` 时**文件仍然存在**（只是内容被覆写），容易误以为删掉了。
- 不加 `-x` 时按块覆写，**小于一个块的文件末尾可能没被覆盖**。
- 别把 `shred` 当作安全删除的充分条件——见上表。

#### 相关命令
`rm` · `dd` · `cryptsetup` · `blkdiscard`

### truncate — 调整文件大小

**常用度**：★★★☆☆ ｜ **所属**：文件与目录 ｜ **POSIX/GNU 差异**：GNU coreutils

```bash
truncate [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-s 大小` | 设置大小（可带 `+`/`-` 表示增减） |
| `-s +1M` | 增大 1 MiB |
| `-s -100K` | 缩小 100 KiB |
| `-o` | 与 `-s` 同义（旧写法） |
| `-c` | 文件不存在时不创建 |
| `-r 参考文件` | 用参考文件的大小 |

大小后缀：`K`/`KB`（1000）、`KiB`（1024）、`M`/`MiB`、`G`/`GiB`。

```bash
# 场景：创建稀疏文件（不占实际空间）
$ truncate -s 10G /tmp/disk.img
$ ls -lh /tmp/disk.img; du -h /tmp/disk.img
-rw-r--r-- 1 user user 10G ... /tmp/disk.img
0       /tmp/disk.img              # ⭐ 逻辑 10G，实际占 0

# 场景：清空大日志但保留文件的 inode 与权限
$ sudo truncate -s 0 /var/log/big.log
# 对比：> /var/log/big.log 也可，但若有进程持有该 fd 且用 >> 追加，
#       两种方式都保留 inode，前面的内容是"洞"，磁盘不会立即回收

# 场景：把镜像文件按字节截断
$ truncate -s -1048576 /tmp/disk.img       # 末尾减 1 MiB

# 场景：只改大小不创建
$ truncate -c -s 1M /tmp/nonexistent && ls /tmp/nonexistent
```

#### 输出解读
稀疏文件（sparse file）：`ls -lh` 显示逻辑大小，`du` 显示实际占用块。二者差异越大说明「空洞」越多。

#### 常见坑
- **`truncate` 不写数据**，只是改变 inode 里的长度字段。缩小时被截掉的数据**不可恢复**（但磁盘上可能仍有残留，见 `shred` 的限制）。
- 用 `truncate -s 0 logfile` 清空**正在被写入的日志**时，如果写入者用的是追加模式（`O_APPEND`），文件长度会变成从 0 起算，但文件在磁盘上可能出现「空洞」，`ls` 显示的大小会小于实际写入量。用一个新文件或 `logrotate` 更稳妥。
- `-s` 的单位 `M` 是 1000²，`MiB` 是 1024²。`dd` 的 `bs=1M` 是 1024²。**两套约定容易混**。
- 对不支持稀疏的文件系统（如 vfat），`truncate -s 10G` 会真的尝试分配空间。

#### 相关命令
`dd` · `fallocate` · `ls -s` · `du`
