### df — 查看文件系统容量

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`-h`、`-T`、`--total`、`--output` 为 GNU

#### 语法
```bash
df [选项] [文件或目录...]
```

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| `-h` | 人类可读（KiB/MiB/GiB） | `df -h` |
| `-H` | 10 的幂（KB/MB/GB） | `df -H` |
| `-T` | 显示文件系统类型 | `df -hT` |
| `-i` | 显示 inode 使用情况 | `df -i` |
| `-x 类型` | 排除类型（可多次） | `df -x tmpfs -x devtmpfs` |
| `-t 类型` | 只显示某类型 | `df -t ext4` |
| `--total` | 末尾加总计行 | `df -h --total` |
| `-l` | 只显示本地文件系统 | `df -l` |
| `-P` | POSIX 输出格式（一行一个） | `df -P /` |
| `--output=列` | 自定义列 | `df --output=source,fstype,pcent,target` |

#### 实战示例
```bash
# 场景：整体容量（日常必看）
$ df -hT -x tmpfs -x devtmpfs -x overlay
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/nvme0n1p2 ext4  466G  312G  131G  71% /
/dev/nvme0n1p1 vfat  511M   62M  450M  13% /boot

# 场景：inode 是否耗尽 ⭐
# "磁盘满"但 df -h 有空间时的第一步
$ df -i
Filesystem       Inodes  IUsed   IFree IUse% Mounted on
/dev/nvme0n1p2 31252480 31252480       0  100% /
#                              ^^^^^^^ 耗尽了

# 场景：某个目录属于哪个文件系统
$ df -h /var/log /home

# 场景：脚本可解析（用 --output 避免空格对齐问题）⭐
$ df -h --output=target,avail,pcent / | tail -1
Mounted on Avail Use%
/          131G  71%

$ df -P / | awk 'NR==2 {print $4}'      # 可用块数（1024 字节块）
```

#### 输出解读
| 列 | 含义 |
|----|------|
| `Filesystem` | 设备或伪文件系统名 |
| `Size` | 总容量 |
| `Used` | 已用（**包含 root 预留的 5%**） |
| `Avail` | 普通用户可用 |
| `Use%` | 使用率，按 `Used/(Used+Avail)` 算 |
| `Mounted on` | 挂载点 |

⚠️ `Used + Avail ≠ Size`：ext 文件系统默认给 root 预留 5%（`tune2fs -m` 可调），用于防止碎片化和保证 root 能登录清理。所以 **`Use%` 可能显示 100% 而 `Avail` 仍非 0**。

#### 常见坑
- ⚠️ **`df` 显示满、`du` 加起来却很小**。按可能性排序排查：
  1. **文件被删除但进程仍持有 fd** → `sudo lsof +L1`（最常见）⭐
  2. **inode 耗尽**（`df -i` 满，`df -h` 可能不满）
  3. **挂载点被覆盖**（文件被挂载点遮住）→ 挂到临时目录看
  4. **预留块**（`tune2fs -m 0` 释放）
  5. **LVM/快照/CoW 的旧数据**（btrfs、ZFS、LVM 快照）
  6. **已删除但仍被 mmap 的大文件**
- **行数与实际磁盘数不匹配**：tmpfs、overlay、squashfs（snap）、cgroup 都会出现，用 `-x` 过滤。
- **在网络文件系统上可能挂起**（NFS 服务器不可达）。用 `df -l` 只查本地。
- **`-P` 的 POSIX 格式保证一行一个文件系统**（长名字不会换行），脚本解析应该加 `-P`。

#### 相关命令
`du` · `lsblk` · `findmnt` · `lsof +L1` · `ncdu`

### du — 查看目录占用空间

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`-h`、`--max-depth`、`--exclude`、`-t` 为 GNU

```bash
du [选项] [文件或目录...]
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-h` | 人类可读 | `du -sh /var` |
| `-s` | 只显示总计（summary） | `du -sh /var/log` |
| `-a` | 也显示文件 | `du -ah dir` |
| `-d N` / `--max-depth=N` | 递归深度 | `du -h -d1 /` |
| `-c` | 末尾加总计 | `du -shc /var/*` |
| `-x` | 不跨文件系统 | `du -shx /` |
| `-L` | 跟随符号链接 | — |
| `-b` | 按字节 | `du -sb dir` |
| `--apparent-size` | 用逻辑大小而非磁盘占用 | `du --apparent-size -h f` |
| `--exclude=PATTERN` | 排除 | `du -sh --exclude='*.log' /var` |
| `-t 阈值` | 只显示超过阈值的 | `du -h -t 1G -d3 /` |
| `-i` / `--inodes` | 统计 inode 数 | `du -s --inodes /var` |
| `-0` | NUL 分隔（配 `xargs -0`） | `du -0sh /home/*` |

#### 实战示例
```bash
# 场景：某目录总占用
$ du -sh /var/log
1.2G    /var/log

# 场景：找出根下最占空间的目录 ⭐
$ du -xhd1 / 2>/dev/null | sort -h
4.0K    /mnt
1.2G    /var
12G     /home
48G     /usr

# 场景：递归找大目录（Top 10）
$ du -h --max-depth=2 /var 2>/dev/null | sort -h | tail -10

# 场景：只列大于 1G 的目录，限 3 层 ⭐
$ du -h -t 1G --max-depth=3 / 2>/dev/null

# 场景：只看家目录各用户的占用
$ du -sh /home/* 2>/dev/null | sort -h

# 场景：对比逻辑大小与实际占用（稀疏文件诊断）⭐
$ du -h --apparent-size big.img; du -h big.img
10G     big.img
0       big.img

# 场景：统计文件数量（inode 占用）
$ du --inodes -sh /var/spool

# 场景：含空格文件名安全处理
$ du -sz0 /home/* | sort -z -n | xargs -0 du -h
```

#### 输出解读
`du` 默认输出**磁盘实际占用的块数**（按块大小向上取整），不是文件逻辑大小：

- 1 字节的文件在 4 KiB 块的文件系统上占 4 KiB
- 稀疏文件占 0
- 对硬链接**默认只算一次**（避免重复计算）

#### 常见坑
- ⚠️ **`du` 遍历整棵树，在巨大目录上很慢**（尤其 NFS）。先 `du -xhd1 /` 定方向，再逐层深入。
- ⚠️ **`du` 与 `df` 不一致是常态**，原因见 `df` 的常见坑。**第一件事查 `lsof +L1`**。
- ⚠️ **不加 `-x` 会跨挂载点**，统计 `/` 时会把 `/home`（独立分区）、`/mnt/usb` 全算进去，数字失真。
- **`-s` 是 summary（只输出总计），不是「按大小排序」**。排序要接 `sort -h`。
- **无权限的目录会被静默跳过**。加 `2>/dev/null` 会掩盖错误但会漏算。
- **`--apparent-size` 反直觉**：它给的是「看上去的大小」（`ls -l` 的值），不是磁盘占用。
- **`du -sh ./*` 在文件很多时报 `Argument list too long`**，改用 `du -sh --max-depth=1 .`。
- **`du` 在容器里只看到容器可见的文件**。

#### 相关命令
`df` · `ncdu` · `find -size` · `ls -lS` · `dust`

### lsblk — 列出块设备

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有（`util-linux`）

```bash
lsblk [选项] [设备...]
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-f` | 显示文件系统类型、UUID、LABEL、挂载点 | `lsblk -f` |
| `-o 列,...` | 自定义列 | `lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT` |
| `-p` | 完整设备路径 | `lsblk -p` |
| `-n` | 不显示表头（脚本用） | `lsblk -pnro NAME` |
| `-l` | 列表格式（不画树） | `lsblk -l` |
| `-d` | 只显示整盘，不显示分区 | `lsblk -d` |
| `-a` | 显示所有（含空设备） | `lsblk -a` |
| `-m` | 显示权限与属主 | `lsblk -m` |
| `-S` | 显示 SCSI 设备 | `lsblk -S` |
| `-D` | 显示 discard/TRIM 能力 | `lsblk -D` |
| `-J` / `-P` | JSON / 键值对输出 | `lsblk -J \| jq ...` |
| `-b` | 字节为单位 | `lsblk -b` |
| `--inverse` | 反向树（分区→磁盘） | — |

**常用列名**：

| 列 | 含义 | 列 | 含义 |
|----|------|----|------|
| `NAME` | 设备名 | `PATH` | 完整路径 |
| `RM` | 可移动（`1`=USB） ⭐ | `SIZE` | 容量 |
| `RO` | 只读 | `TYPE` | `disk`/`part`/`lvm`/`crypt`/`loop`/`rom` |
| `FSTYPE` | 文件系统类型 | `FSVER` | 文件系统版本 |
| `LABEL` | 卷标 | `UUID` | **文件系统** UUID |
| `PARTUUID` | 分区表 UUID | `PARTLABEL` | 分区标签（GPT） |
| `MOUNTPOINTS` | 挂载点（复数） | `MODEL` | 硬件型号 |
| `SERIAL` | 序列号 | `TRAN` | 传输类型 |
| `ROTA` | 是否旋转盘（0=SSD） ⭐ | `SCHED` | I/O 调度器 |

#### 实战示例
```bash
# 场景：整体设备树 ⭐
$ lsblk
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
nvme0n1     259:0    0 476.9G  0 disk
├─nvme0n1p1 259:1    0   512M  0 part /boot
├─nvme0n1p2 259:2    0   467G  0 part /
└─nvme0n1p3 259:3    0   9.4G  0 part [SWAP]

# 场景：带文件系统信息（写 fstab 前必看）⭐
$ lsblk -f
NAME        FSTYPE FSVER LABEL UUID                                 MOUNTPOINTS
nvme0n1p1   vfat   FAT32       ABCD-1234                            /boot
nvme0n1p2   ext4   1.0         ab12cd34-5678-90ef-abcd-1234567890ab /

# 场景：脚本里取设备路径 ⭐
$ lsblk -pnro NAME,MOUNTPOINT
/dev/nvme0n1p1 /boot
/dev/nvme0n1p2 /

# 场景：🔐 找可移动（USB）设备（取证时只读挂载）
$ lsblk -o NAME,RM,SIZE,TYPE,TRAN,MODEL | awk 'NR==1 || $2==1'

# 场景：判断是不是 SSD
$ lsblk -dno NAME,ROTA
nvme0n1 0

# 场景：查看分区属于哪个物理盘
$ lsblk -sp /dev/nvme0n1p2
/dev/nvme0n1p2
└─/dev/nvme0n1

# 场景：检查 TRIM 支持
$ lsblk -D
NAME      DISC-GRAN DISC-MAX DISC-ZERO
nvme0n1        512B       2T         0
#    ↑ 非 0 = 支持 discard

# 场景：JSON 给脚本
$ lsblk -J -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT | jq -r '.blockdevices[] | select(.type=="part") | "\(.name) \(.size)"'

# 场景：LVM 层次
$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
sda            100G disk
└─sda1         100G part
  └─vg0-lv0    100G lvm  ext4  /data
```

#### 输出解读
树状缩进表示层次：`disk → part → lvm/crypt → 文件系统`。

`TYPE` 取值：`disk` 整盘、`part` 分区、`rom` 光驱、`loop` 环回、`lvm` LVM 逻辑卷、`crypt` dm-crypt、`raid0/1/5/...` 软 RAID、`mpath` 多路径、`zram` 内存压缩块设备。

#### 常见坑
- ⚠️ **`UUID`（文件系统）与 `PARTUUID`（分区表）是两个不同的字段**。fstab 里 `UUID=` 用前者，`PARTUUID=` 用后者，**不能混**。
- **新版是 `MOUNTPOINTS`（复数）**（一个设备可挂多处），老版是 `MOUNTPOINT`（单数）。写脚本要注意。
- **`lsblk` 通常不需要 root**，但某些列需要。
- **设备名（`sda`/`nvme0n1`）可能因插拔顺序变化**，fstab 与脚本里不要依赖它，用 `UUID=` 或 `/dev/disk/by-id/`。
- **`-f` 对未格式化的设备显示空**，不是错误。
- **`RM=1` 是可移动设备**，格式化前要特别小心别写错 USB 盘。
- **容器里看不到宿主的所有设备**（取决于 `/dev` 与 namespace）。
- **`lsblk` 默认按拓扑排序**，不是按名字。`-l` 也一样（用 `-n -l` 时顺序仍按树）。

#### 相关命令
`blkid` · `fdisk -l` · `parted -l` · `df` · `findmnt` · `lsblk -D`

### blkid — 查看设备 UUID 与类型

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
blkid [选项] [设备...]
```

| 选项 | 含义 | 示例 |
|------|------|------|
| （无） | 所有已知设备 | `sudo blkid` |
| `-s 标签` | 只显示指定标签 | `blkid -s UUID -s TYPE` |
| `-o 格式` | `full`（默认）/`value`/`export`/`list` | `blkid -o value -s UUID dev` |
| `-p` | 低层探测（绕过缓存） | `sudo blkid -p /dev/sdb1` |
| `-t 条件` | 按条件找 | `blkid -t TYPE=ext4` |
| `-L 卷标` | 按 LABEL 找设备 | `sudo blkid -L BOOT` |
| `-U UUID` | 按 UUID 找设备 ⭐ | `sudo blkid -U ab12cd...` |
| `-w 文件` | 写缓存 | — |
| `-d` | 不编码非打印字符 | — |

#### 实战示例
```bash
# 场景：所有设备的 UUID
$ sudo blkid
/dev/nvme0n1p1: LABEL="BOOT" UUID="ABCD-1234" TYPE="vfat" PARTUUID="12345678-01"
/dev/nvme0n1p2: UUID="ab12cd34-..." TYPE="ext4" PARTUUID="12345678-02"

# 场景：只要值（写 fstab 用）⭐
$ blkid -s UUID -o value /dev/nvme0n1p2
ab12cd34-5678-90ef-abcd-1234567890ab

# 场景：反查设备路径 ⭐
$ sudo blkid -U ab12cd34-5678-90ef-abcd-1234567890ab
/dev/nvme0n1p2
$ sudo blkid -L BOOT
/dev/nvme0n1p1

# 场景：直接生成 fstab 条目 ⭐
$ dev=/dev/nvme0n1p2
$ printf 'UUID=%s  /  %s  defaults,noatime  0 1\n' \
>   "$(blkid -s UUID -o value "$dev")" \
>   "$(blkid -s TYPE -o value "$dev")"
UUID=ab12cd34-...  /  ext4  defaults,noatime  0 1

# 场景：按类型筛选
$ sudo blkid -t TYPE=ext4

# 场景：对已挂载设备重新探测（不用缓存）
$ sudo blkid -p /dev/nvme0n1p2

# 场景：🔐 找「没有 UUID」的分区（未格式化/可疑）
$ sudo blkid | grep -v UUID
```

#### 输出解读
| 标签 | 含义 |
|------|------|
| `UUID` | **文件系统** UUID（写 fstab 用这个） ⭐ |
| `PARTUUID` | 分区表 UUID（GPT 每个分区都有） |
| `LABEL` | 文件系统卷标 |
| `TYPE` | 文件系统类型 |
| `BLOCK_SIZE` | 块大小（`-p` 时） |
| `SEC_TYPE` | 辅助类型（`vfat` 的 `msdos`） |

#### 常见坑
- ⚠️ **`UUID` 与 `PARTUUID` 不同**，fstab 里是两个不同的字段名。
- ⚠️ **`mkfs` 会生成新 UUID**，导致 fstab 里的 `UUID=` 失效 → **系统起不来**。重新格式化后必须更新 fstab。
- **对未格式化的分区无输出**（不报错、退出码 2）。
- **默认读缓存**（`/run/blkid/blkid.tab`），刚改过的设备要 `-p` 重新探测。
- **需要 root 才能读某些设备的元数据**。
- **`blkid -U` 找不到时无输出且退出码 2**，脚本里要检查退出码而不是输出。
- **LUKS 等加密设备只显示 `TYPE="crypto_LUKS"`**，内部文件系统要打开映射后才可见。

#### 相关命令
`lsblk -f` · `mount` · `udevadm info` · `findmnt`

### findmnt — 查看挂载树

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有（`util-linux`）

```bash
findmnt [选项] [设备|挂载点]
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-T 路径` | 查该路径属于哪个挂载点 ⭐ | `findmnt -T /var/log` |
| `-S 设备` | 按设备查 | `findmnt -S /dev/sdb1` |
| `-t 类型` | 按类型筛选 | `findmnt -t ext4` |
| `-l` | 列表（不画树） | `findmnt -l` |
| `--df` | 类 df 的输出 | `findmnt --df` |
| `-o 列` | 自定义列 | `findmnt -o TARGET,SOURCE,OPTIONS` |
| `-n` | 不显示表头 | `findmnt -rno TARGET` |
| `-r` | 原始输出（不转义） | — |
| `-J` / `-P` | JSON / 键值对 | — |
| `--verify` | 校验 fstab 与当前挂载 ⭐ | `sudo findmnt --verify` |
| `-m` | 显示所有挂载点（含 bind） | — |
| `-A` | 显示所有（含伪文件系统） | — |
| `--poll` | 监听挂载变化 | `findmnt --poll` |

#### 实战示例
```bash
# 场景：挂载树 ⭐
$ findmnt
TARGET    SOURCE         FSTYPE OPTIONS
/         /dev/nvme0n1p2 ext4   rw,relatime
├─/boot   /dev/nvme0n1p1 vfat   rw,relatime,fmask=0077
└─/tmp    tmpfs          tmpfs  rw,nosuid,nodev

# 场景：某目录属于哪个文件系统 ⭐
$ findmnt -T /var/log
TARGET SOURCE         FSTYPE OPTIONS
/      /dev/nvme0n1p2 ext4   rw,relatime

# 场景：类 df 但更准确（含 bind mount 与伪文件系统）
$ findmnt --df

# 场景：校验 fstab 是否有条目没生效 ⭐
$ sudo findmnt --verify
Success, no errors or warnings detected

# 场景：只看本地真实文件系统
$ findmnt -l -t ext4,xfs,btrfs,vfat

# 场景：带 UUID 的自定义列
$ findmnt -o TARGET,SOURCE,FSTYPE,UUID,OPTIONS | head

# 场景：🔐 安全审计——找出缺 nosuid/noexec 的挂载 ⭐
$ findmnt -rno TARGET,OPTIONS -t ext4,xfs,btrfs | grep -v nosuid

# 场景：检查 /tmp 与 /dev/shm 的加固
$ findmnt -o TARGET,OPTIONS -t tmpfs

# 场景：监听挂载变化（调试 systemd automount）
$ findmnt --poll
```

#### 输出解读
| 列 | 含义 |
|----|------|
| `TARGET` | 挂载点 |
| `SOURCE` | 设备或伪文件系统 |
| `FSTYPE` | 文件系统类型 |
| `OPTIONS` | 挂载选项（`rw,relatime,nosuid,noexec,nodev` 等） |

`-o` 还支持 `UUID`、`LABEL`、`PARTUUID`、`PROPAGATION`、`FSROOT`、`USED`、`AVAIL`、`SIZE`。

#### 常见坑
- **`-T` 需要绝对路径**（相对路径按当前目录解析，可能误判）。
- **默认不显示伪文件系统**，要 `-A` 或 `-t` 指定。
- **`--verify` 只检查 fstab 语法与设备存在性**，不检查「能否真的挂载」（如不可达的 NFS 会通过校验）。
- **同一设备可挂载在多个位置**（bind mount），默认只显示一个，`-m` 显示全部。
- **容器里的挂载点与宿主不同**（有 mount namespace 隔离），看到的不是宿主的视图。
- **`-t` 放在 `-T` 之后会被当筛选条件**，选项顺序影响结果。

#### 相关命令
`mount` · `df` · `/proc/mounts` · `findmnt --verify`

### mount — 挂载文件系统

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`--bind`、`--move`、`--make-*` 为 Linux 扩展

#### 语法
```bash
mount [选项] [-t 类型] [-o 选项] 设备 挂载点
mount -a
mount --bind 源 目标
```

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| （无参） | 列出所有挂载 | `mount` |
| `-a` | 挂载 fstab 全部条目 ⭐ | `sudo mount -a` |
| `-t 类型` | 指定文件系统类型 | `-t nfs` |
| `-o 选项` | 挂载选项 | `-o ro,nosuid` |
| `-r` | 只读 ⭐ | `-o ro,noload` |
| `-n` | 不写 `/etc/mtab` | — |
| `--bind` / `-B` | 绑定挂载 ⭐ | `sudo mount --bind /a /b` |
| `--rbind` | 递归绑定 | `mount --rbind /dev /mnt/dev` |
| `--move` | 移动挂载点 | — |
| `--make-private` 等 | 传播类型 | — |
| `-o remount` | 重新挂载改选项 ⭐ | `mount -o remount,ro /` |

#### 常用挂载选项
| 选项 | 含义 |
|------|------|
| `ro` / `rw` | 只读 / 读写 |
| `nosuid` | 忽略 SUID/SGID 🔐 |
| `nodev` | 不解释设备文件 🔐 |
| `noexec` | 禁止执行程序 🔐 |
| `noatime` / `relatime` | atime 策略 |
| `nofail` | 设备不存在不报错（fstab） ⭐ |
| `noload` | 不重放日志（**取证必用**） 🔐 |
| `defaults` | `rw,suid,dev,exec,auto,nouser,async` |
| `uid=` / `gid=` / `umask=` | FAT/NTFS 权限映射 |
| `loop` | 环回挂载文件 |
| `_netdev` | 标记为网络文件系统 |
| `x-systemd.automount` | systemd 按需挂载 |

#### 实战示例
```bash
# 场景：挂载 USB 盘
$ lsblk -f
$ sudo mount /dev/sdb1 /mnt/usb
$ sudo umount /mnt/usb

# 场景：🔐 取证时只读挂载（绝不写证据盘）⭐⭐
$ sudo mount -o ro,noload,noatime /dev/sdb1 /mnt/evidence
#                ↑ noload 阻止 ext4 日志重放（会修改磁盘）

# 场景：挂载 ISO
$ sudo mount -o loop ubuntu.iso /mnt/iso

# 场景：挂载含分区表的磁盘镜像
$ sudo losetup -Pf disk.img
$ sudo mount /dev/loop0p2 /mnt/img

# 场景：重新挂载改选项（不卸载）⭐
$ sudo mount -o remount,ro /
$ sudo mount -o remount,rw /

# 场景：绑定挂载 ⭐
$ sudo mount --bind /var/www /srv/www
$ sudo mount --rbind /dev /mnt/chroot/dev      # 递归（chroot 常用）

# 场景：FAT/NTFS 让普通用户可读写
$ sudo mount -o uid=$(id -u),gid=$(id -g),umask=022 /dev/sdb1 /mnt/usb

# 场景：NFS（加 soft 防止进程卡在 D 状态）⭐
$ sudo mount -t nfs -o soft,timeo=30,retrans=2 nfs-server:/export/data /mnt/nfs

# 场景：CIFS/SMB
$ sudo mount -t cifs -o username=alice,uid=$(id -u) //server/share /mnt/smb

# 场景：改 fstab 后验证 ⭐⭐
$ sudo mount -a
mount: /mnt/data: special device /dev/sdc1 does not exist.
# 有报错立即修复，否则重启会进 emergency mode
```

#### 输出解读
`mount`（无参数）输出：`设备 on 挂载点 type 类型 (选项)`。

`/proc/mounts` 是内核的权威视图，`/etc/mtab` 通常是指向 `/proc/self/mounts` 的符号链接。

#### 常见坑
- ⚠️ **`mount -a` 是改 fstab 后的必经步骤**。写错 fstab 会导致**系统无法启动**。
- ⚠️ **挂载会遮蔽（shadow）挂载点下的原有文件**。原内容不可见但未删除——这是「磁盘满了找不到大文件」的原因之一。
- ⚠️ **取证时绝不能用不带 `noload` 的 `mount`**：ext4 日志重放会**修改证据盘**。更稳妥是先 `dd` 做镜像再分析镜像。
- **`-o loop` 在现代 `mount` 里可自动处理**（`mount file.iso /mnt` 通常能工作）。
- **`user` 选项的语义**：允许该用户挂载 fstab 里列出的这个设备，且自动加 `noexec,nosuid,nodev`。
- **`--bind` 不改变权限与属主**，源和目标看到同一份数据。
- **卸载前要确保没有进程在用**（`lsof +D`、`fuser -m`）。
- **NFS 不加 `soft` 时服务器不可达会让进程进入 `D` 状态且杀不掉**，是生产事故常见原因。

#### 相关命令
`umount` · `findmnt` · `lsblk` · `losetup` · `/etc/fstab`

### umount — 卸载文件系统

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`-l`、`-R` 为 Linux 扩展

```bash
umount [选项] 设备|挂载点
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-l` | 惰性卸载（从命名空间移除，等引用消失真正卸载） | `umount -l /mnt/nfs` |
| `-f` | 强制（仅对网络文件系统有意义） | `umount -f /mnt/nfs` |
| `-R` | 递归卸载（含子挂载） ⭐ | `umount -R /mnt/chroot` |
| `-d` | 同时释放环回设备 | `umount -d /mnt/iso` |
| `-n` | 不写 `/etc/mtab` | — |
| `-v` | 详细 | — |
| `-t 类型` | 只卸载某类型 | — |

#### 实战示例
```bash
# 场景：正常卸载
$ sudo umount /mnt/usb
$ sudo umount /dev/sdb1

# 场景：先查谁在用 ⭐
$ sudo fuser -vm /mnt/usb          # 快
$ sudo lsof +D /mnt/usb            # 慢但更详细

# 场景：踢出占用者后卸载
$ sudo fuser -km /mnt/usb          # ⚠️ 杀掉占用者
$ sudo umount /mnt/usb

# 场景：NFS 挂死的救急 ⭐
$ sudo umount -f /mnt/nfs
$ sudo umount -l /mnt/nfs
$ sudo umount -fl /mnt/nfs

# 场景：递归卸载（容器/chroot 场景）⭐
$ sudo umount -R /mnt/chroot

# 场景：释放环回设备
$ sudo umount -d /mnt/iso
$ sudo losetup -d /dev/loop0       # 手动方式
```

#### 🧪 为什么报 `target is busy`
`umount` 失败的原因从易到难：

| 原因 | 检查方法 |
|------|----------|
| 有 shell 的 cwd 在该目录 | `lsof +D /mnt/x \| grep cwd` |
| 有进程打开了里面的文件 | `lsof +D /mnt/x` |
| 有进程 mmap 了里面的文件 | `lsof +D /mnt/x \| grep mem` |
| 有子挂载没卸 | `findmnt -R /mnt/x` |
| 内核回写未完成 | 稍等或 `sync` |

#### 常见坑
- ⚠️ **`-l`（lazy）不是真卸载**：只是从命名空间摘掉，数据仍在后台回写。**`-l` 之后立刻拔设备会丢数据**，必须先 `sync`。
- ⚠️ **`-f` 只对 NFS 等网络文件系统有意义**，对本地文件系统会报 `Invalid argument`。
- ⚠️ **必须 `sync` 或正常 `umount` 才能安全拔设备**。`async` 挂载下直接拔风险高。
- **卸载后挂载点下的原内容会重新出现**（不要惊讶）。
- **卸载顺序必须是「后挂的先卸」**（栈序）。有子挂载时用 `-R`。
- **`/` 无法卸载**（除非在 `pivot_root` 或关机流程中）。
- **在容器里 `umount` 受 mount namespace 与 `CAP_SYS_ADMIN` 限制**。

#### 相关命令
`mount` · `fuser -m` · `lsof` · `sync` · `losetup -d`

### /etc/fstab — 持久化挂载配置

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：由 `util-linux` / systemd 解析

```
# <设备>                                <挂载点>  <类型>  <选项>                          <dump> <pass>
UUID=ab12cd34-5678-90ef-abcd-12345678  /         ext4    rw,relatime,errors=remount-ro   0      1
UUID=ABCD-1234                         /boot     vfat    rw,relatime,fmask=0077          0      2
/swapfile                              none      swap    sw                              0      0
tmpfs                                  /tmp      tmpfs   rw,nosuid,nodev,size=2G          0      0
nfs-server:/export/data                /mnt/nfs  nfs     _netdev,soft,timeo=30,nofail    0      0
//server/share                         /mnt/smb  cifs    credentials=/root/.smbcreds,uid=1000  0 0
```

#### 字段说明
| 字段 | 含义 |
|------|------|
| 设备 | `UUID=`（推荐）、`LABEL=`、`PARTUUID=`、`/dev/sdX`（不推荐）、伪文件系统名、NFS/CIFS 地址 |
| 挂载点 | 目录路径（空格写成 `\040`） |
| 类型 | `ext4`、`xfs`、`btrfs`、`vfat`、`ntfs`、`exfat`、`swap`、`tmpfs`、`nfs`、`cifs`、`auto` |
| 选项 | 逗号分隔，见 `mount` 的选项表 |
| dump | 是否被 `dump` 备份（现代几乎总是 `0`） |
| pass | `fsck` 顺序：`0` 不检查、`1` 根（最先）、`2` 其他 |

#### 实战示例
```bash
# 场景：生成新分区的 fstab 条目 ⭐
$ dev=/dev/nvme0n1p3
$ mp=/data
$ uuid=$(blkid -s UUID -o value "$dev")
$ type=$(blkid -s TYPE -o value "$dev")
$ echo "UUID=$uuid  $mp  $type  defaults,noatime,nosuid,nodev  0  2" | sudo tee -a /etc/fstab

# 场景：改完必须验证 ⭐⭐
$ sudo mount -a
# 无输出 = 全部成功

# 场景：更严格的校验
$ sudo findmnt --verify
$ sudo systemd-analyze verify /etc/fstab

# 场景：模拟挂载（不真的挂）
$ sudo mount -a -v --fake

# 场景：swap 文件写入 fstab
$ echo '/swapfile  none  swap  sw  0 0' | sudo tee -a /etc/fstab
$ sudo swapon -a

# 场景：路径含空格
$ echo 'UUID=xxx  /mnt/my\040disk  ext4  defaults  0 2' | sudo tee -a /etc/fstab

# 场景：按需挂载网络盘（加快启动）⭐
$ echo 'nfs-server:/data  /mnt/data  nfs  _netdev,nofail,x-systemd.automount,x-systemd.idle-timeout=60  0 0' | sudo tee -a /etc/fstab
```

#### ⚠️ 常见错误与后果
| 错误 | 后果 |
|------|------|
| 用 `/dev/sdX` 而非 UUID | 设备名变化后起不来 |
| UUID 写错 / 格式化后未更新 | 开不了机，进 emergency mode |
| 挂载点不存在且没 `nofail` | 开不了机 |
| 网络盘没 `_netdev`/`nofail` | 网络未就绪时卡住启动 |
| 语法错误 | 进 emergency mode |
| 把 `/` 的 pass 写 `0` | 不检查根文件系统 |
| 同时挂载一个设备到两处且都有 pass | fsck 冲突 |

**救援流程**：
```bash
# 1. systemd emergency mode，输入 root 密码
# 2. 让根可写
$ mount -o remount,rw /
# 3. 修 fstab
$ vim /etc/fstab
# 4. 验证
$ mount -a
# 5. 重启
$ reboot

# 完全进不去时用 Live USB
$ sudo mount /dev/nvme0n1p2 /mnt
$ sudo mount /dev/nvme0n1p1 /mnt/boot
$ sudo vim /mnt/etc/fstab
$ sudo mount --rbind /dev /mnt/dev
$ sudo mount --rbind /proc /mnt/proc
$ sudo mount --rbind /sys /mnt/sys
$ sudo chroot /mnt
```

#### 常见坑
- ⚠️ **改完 fstab 必须 `mount -a`**，这是重启前发现问题的唯一机会。
- ⚠️ **systemd 会把 fstab 转换成 `.mount` unit**（如 `/data` → `data.mount`）。同样路径若已有 `.mount` unit，会与 fstab 冲突，以 unit 为准。
- **`nofail` 让挂载失败不影响启动**，但服务可能因目录为空而出错。数据盘建议 `nofail` + 应用侧检查。
- **`x-systemd.automount` 实现按需挂载**，网络盘尤其值得。
- **在 fstab 里给 `/tmp`、`/dev/shm`、`/var/tmp` 加 `noexec,nosuid,nodev` 是标准加固项**，但可能破坏 Chrome 沙箱、部分安装器。
- **NFS 的 `soft` vs `hard`**：`soft` 超时返回错误（可能丢数据但不挂死），`hard` 无限重试（可能让进程卡在 `D`）。需权衡。
- **CIFS 密码不要写在 fstab 里**（所有用户可见），用 `credentials=/path/file` 且该文件 `600`。

#### 相关命令
`mount -a` · `findmnt --verify` · `blkid` · `systemctl daemon-reload`

### fdisk — 分区表工具

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有；`util-linux` 版支持 GPT，老版本只支持 MBR

```bash
fdisk [选项] 设备
fdisk -l [设备]
```

| 选项 | 含义 |
|------|------|
| `-l` | 列出分区表（**只读，最常用的安全操作**） ⭐ |
| `-o 列` | 自定义 `-l` 的输出列 ⭐ |
| `-t 类型` | 指定分区表类型（`dos`/`gpt`/`sun`/`sgi`） |
| `-b 大小` | 扇区大小 |
| `-u` | 单位（sectors/cylinders） |
| `-s 分区` | 打印分区大小（已废弃） |

**交互模式命令**：

| 命令 | 作用 | 命令 | 作用 |
|------|------|------|------|
| `m` | 帮助 | `p` | 打印分区表 ⭐ |
| `n` | 新建分区 | `d` | 删除分区 ⚠️ |
| `t` | 改分区类型 | `a` | 切换启动标志 |
| `w` | **写入并退出** ⚠️ | `q` | 不保存退出 ⭐ |
| `g` | 新建 GPT 表 ⚠️ | `o` | 新建 MBR 表 ⚠️ |
| `x` | 专家模式 | `F` | 列出未分配空间 |
| `i` | 分区详情 | `v` | 校验分区表 ⭐ |

#### 实战示例
```bash
# 场景：查看所有磁盘的分区表 ⭐
$ sudo fdisk -l

Disk model: Samsung SSD 990 PRO 1TB
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
Disklabel type: gpt
Disk identifier: 12345678-1234-1234-1234-123456789ABC

Device           Start        End    Sectors   Size Type
/dev/nvme0n1p1    2048    1050623    1048576   512M EFI System
/dev/nvme0n1p2 1050624  980420607  979369984   467G Linux filesystem
/dev/nvme0n1p3 980420608 1000215182   19794575   9.4G Linux swap

# 场景：只关心设备、大小、类型
$ sudo fdisk -l -o Device,Size,Type
$ sudo fdisk -l /dev/nvme0n1 -o Device,Start,End,Sectors,Size,Type

# 场景：🧪 在环回设备上练习分区（不碰真盘）⭐
$ truncate -s 1G /tmp/practice.img
$ sudo losetup -Pf /tmp/practice.img
$ sudo fdisk /dev/loop0
# 交互：g（新建 GPT）→ n（新建分区，默认全用）→ p（检查）→ w（写入）
$ sudo partprobe /dev/loop0
$ lsblk /dev/loop0
loop0   1G disk
└─loop0p1 1G part
$ sudo mkfs.ext4 /dev/loop0p1

# 场景：交互查看（用 q 退出，安全）
$ sudo fdisk /dev/nvme0n1

...
Command (m for help): q
```

#### 输出解读
| 字段 | 含义 |
|------|------|
| `Disk model` | 硬件型号 |
| `Sector size (logical/physical)` | 逻辑/物理扇区大小（512/4096 说明是 4Kn 兼容盘） |
| `Disklabel type` | `gpt` 或 `dos`（MBR） |
| `Disk identifier` | 磁盘 GUID（GPT）或签名（MBR） |
| `Start` / `End` | **单位是扇区**，不是字节 ⚠️ |
| `Type` | `EFI System`、`Linux filesystem`、`Linux swap`、`Linux LVM` 等 |

#### ⚠️ 危险操作
```bash
Command: g        # ⚠️ 新建 GPT 表 → 抹掉现有分区信息（数据仍在但无法访问）
Command: w        # ⚠️⚠️ 立即写盘，不可逆，没有撤销
```

#### 常见坑
- ⚠️ **交互模式里 `w` 是写盘，`q` 是不保存退出**。按错 `w` 会立刻改分区表。**养成用 `q` 退出的习惯**。
- ⚠️ **改完分区表要让内核重读**：`partprobe`、`partx -u`、`blockdev --rereadpt`，否则 `/dev/sda3` 节点不出现。
- ⚠️ **改已有分区的起点会破坏文件系统**（数据不会自动搬移）。
- ⚠️ **对已挂载的分区改分区表极度危险**（内核分区缓存不一致）。
- **`fdisk` 不支持创建重叠分区**，`parted` 在某些情况下允许。
- **MBR 限制**：最多 4 个主分区、单分区最大 2 TiB。**GPT 支持 128 个分区、极大容量、有备份表**。现代系统一律用 GPT。
- **`-l` 需要 root**（读设备元数据）。
- **容器里通常不可用**（无 `/dev` 访问或缺 `CAP_SYS_ADMIN`）。

#### 相关命令
`parted` · `gdisk` · `partprobe` · `lsblk` · `blkid` · `partx`

### gdisk / sgdisk — GPT 分区工具

**常用度**：★★★☆☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有（`gdisk` 包）

`gdisk` 是交互式；**`sgdisk` 是脚本友好的一次性命令**。

```bash
gdisk 设备
sgdisk [选项] 设备
```

#### sgdisk 常用命令
| 选项 | 含义 | 示例 |
|------|------|------|
| `-p` | 打印分区表 | `sudo sgdisk -p /dev/sda` |
| `-l 设备` | 列出（只读） | — |
| `-n 分区号:起始:结束` | 新建分区 | `-n 3:0:+10G` |
| `-d 分区号` | 删除 | `-d 3` |
| `-t 分区号:类型码` | 改类型 | `-t 3:8300` |
| `-c 分区号:名字` | 改分区名 | `-c 3:"mydata"` |
| `-u 分区号:GUID` | 改分区 GUID | — |
| `-g` | 创建新 GPT 表 ⚠️ | — |
| `-z` | 清除 GPT ⚠️ | — |
| `-Z` | 清除 GPT 与 MBR ⚠️ | — |
| `-b` | 备份分区表到文件 ⭐ | `-b=/root/sda.gpt.bak` |
| `-l 文件` | 从备份恢复 | `-l=/root/sda.gpt.bak` |
| `-e` | 把备份 GPT 移到磁盘末尾（修复用） | `sudo sgdisk -e /dev/sda` |
| `-v` | 校验 ⭐ | `sudo sgdisk -v /dev/sda` |
| `-F` / `-f` | 修复 | — |
| `-i 分区号` | 分区详情 | — |
| `-L` | 列出所有类型码 | — |

#### 实战示例
```bash
# 场景：查看 GPT 分区表
$ sudo gdisk -l /dev/nvme0n1
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048         1050623   512.0 MiB  EF00  EFI System
   2         1050624       980420607   467.0 GiB  8300  Linux filesystem

# 场景：重大操作前备份分区表 ⭐⭐
$ sudo sfdisk -d /dev/nvme0n1 > /root/nvme0n1-$(date +%F).parttable
$ sudo sgdisk -b=/root/nvme0n1.gpt.bak /dev/nvme0n1

# 场景：恢复分区表
$ sudo sgdisk -l=/root/nvme0n1.gpt.bak /dev/nvme0n1
$ sudo partprobe /dev/nvme0n1

# 场景：脚本化创建分区 ⭐
$ sudo sgdisk -n 3:0:+10G -t 3:8300 -c 3:"mydata" /dev/nvme0n1
$ sudo partprobe /dev/nvme0n1
$ sudo mkfs.ext4 -L mydata /dev/nvme0n1p3

# 场景：删除分区
$ sudo sgdisk -d 3 /dev/nvme0n1

# 场景：校验并修复 GPT（磁盘被截短后常见问题）⭐
$ sudo sgdisk -v /dev/nvme0n1
$ sudo sgdisk -e /dev/nvme0n1
$ sudo sgdisk -f /dev/nvme0n1
```

#### GPT 分区类型码（常用）
| 码 | 含义 | 码 | 含义 |
|----|------|----|------|
| `ef00` | EFI System | `ef02` | BIOS boot |
| `8300` | Linux filesystem | `8301` | Linux reserved |
| `8200` | Linux swap | `8e00` | Linux LVM |
| `fd00` | Linux RAID | `0700` | Microsoft basic data |

#### 常见坑
- ⚠️ **`sgdisk -Z` 清除 GPT 与 MBR 两处签名**（彻底抹掉分区表）；`-z` 只清 GPT。数据还在，但分区表没了要靠 `testdisk` 恢复。
- ⚠️ **GPT 在磁盘末尾有备份表**。磁盘被截短（虚拟机扩容后缩小）会让备份表位置错乱，需要 `-e` 修复。
- **分区类型码写错不影响数据访问**（Linux 不强制检查），但会影响 UEFI 启动识别。
- **`-n 3:0:+10G` 里的 `0` 表示自动选择起始扇区**（第一个可用位置），`+10G` 是相对大小。
- **改完必须让内核重读**：`partprobe` 或 `partx -u`。
- **`gdisk` 对 MBR 磁盘会提示转换**，不要盲目按 `w`。

#### 相关命令
`fdisk` · `parted` · `sfdisk` · `partprobe` · `testdisk`

### parted — 现代分区工具

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：GNU 工具，非 POSIX

```bash
parted [选项] 设备 [命令 [参数]]
```

| 选项 | 含义 |
|------|------|
| `-l` | 列出所有设备分区表 ⭐ |
| `-s` | 脚本模式（**危险：无交互确认**） ⚠️ |
| `-a 对齐` | 对齐方式（`optimal`/`none`/`minimal`） |
| `-m` | 机器可解析输出 ⭐ |

| 命令 | 作用 |
|------|------|
| `print` | 打印分区表 ⭐ |
| `mklabel 类型` | 创建分区表（`gpt`/`msdos`） ⚠️ |
| `mkpart 类型 文件系统 起始 结束` | 新建分区 |
| `rm 编号` | 删除 ❌ **无确认** ⚠️ |
| `resizepart 编号 结束位置` | 调整分区边界 ⭐ |
| `set 编号 标志 on/off` | 设置标志（`boot`/`esp`/`lvm`/`raid`） ⭐ |
| `name 编号 名字` | 命名分区（GPT） |
| `unit 单位` | 切换单位（`MiB`/`GiB`/`%`/`s`） ⭐ |
| `align-check 类型 编号` | 检查对齐 |
| `rescue 起始 结束` | 尝试恢复丢失分区 🔐 |
| `quit` | 退出 |

#### 实战示例
```bash
# 场景：查看所有磁盘 ⭐
$ sudo parted -l
Model: Samsung SSD 990 PRO 1TB (nvme)
Disk /dev/nvme0n1: 512GB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start   End    Size   File system  Name  Flags
 1      1049kB  538MB  537MB  fat32        EFI   boot, esp
 2      538MB   502GB  501GB  ext4         root

# 场景：机器可解析输出（脚本用）⭐
$ sudo parted -m /dev/nvme0n1 unit MiB print

# 场景：脚本化创建 GPT 并分区 ⚠️
$ sudo parted -s /dev/sdb mklabel gpt
$ sudo parted -s /dev/sdb mkpart primary ext4 1MiB 100%
$ sudo parted -s /dev/sdb set 1 esp on
$ sudo partprobe /dev/sdb

# 场景：在线扩容的两步（虚拟机扩盘后）⭐
$ sudo parted -s /dev/nvme0n1 resizepart 2 100%
$ sudo partprobe /dev/nvme0n1
$ sudo resize2fs /dev/nvme0n1p2

# 场景：交互模式（更安全）
$ sudo parted /dev/sdb
(parted) print
(parted) rm 3                  # ⚠️ 立即生效，没有确认
(parted) quit

# 场景：🔐 恢复丢失的分区
$ sudo parted /dev/sdb rescue 1MiB 500GiB
```

#### 输出解读
`parted` 的 `Start`/`End` **默认单位是 GB/MB（10 的幂）**，这与 `fdisk` 的扇区单位不同。要明确单位用 `unit MiB print` 或 `unit s print`。

`Sector size (logical/physical)` 是扇区大小。

#### ⚠️ 危险操作
- ⚠️ **`rm` 立即生效，没有确认提示**。
- ⚠️ **`parted -s` 完全无交互**，脚本写错直接改盘。
- ⚠️ **`mklabel` 会清除整个分区表**。

#### 常见坑
- ⚠️ **单位默认是 GB/MB（1000 进制）而不是 GiB/MiB**。这是与其他工具最大的差异（`print` 会显示 501GB 而不是 466GiB）。
- ⚠️ **`parted` 可以操作已挂载的分区**（会警告但能继续），但内核不会立即重读，生产上不要这么做。
- **`resizepart` 只改分区表，不改文件系统**。文件系统扩容要额外的 `resize2fs` / `xfs_growfs`。
- **分区名（`name`）在分区表里，LABEL 在文件系统里**，两者不同。
- **`parted` 对 NVMe 要写整盘设备名**（`/dev/nvme0n1`，不是 `p1`）。
- **新版 `parted` 对 ext4 的文件系统识别可能受限**（显示为空），但分区操作正常。

#### 相关命令
`fdisk` · `gdisk` · `sfdisk` · `resize2fs` · `xfs_growfs` · `partprobe`

### mkfs — 创建文件系统

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`mkfs` 是前端，`mkfs.ext4`、`mkfs.xfs` 是各文件系统实现

```bash
mkfs -t 类型 [选项] 设备
mkfs.类型 [选项] 设备
```

> ⚠️ **`mkfs` 会销毁设备上的一切数据，没有确认，没有撤销。**

#### 实战示例
```bash
# 场景：列出支持的类型
$ ls /sbin/mkfs.*
/sbin/mkfs.ext4  /sbin/mkfs.vfat  /sbin/mkfs.xfs  /sbin/mkfs.btrfs  /sbin/mkfs.f2fs

# 场景：ext4（最通用）
$ sudo mkfs.ext4 -L mydata -m 1 /dev/sdb1
#               │         └─ 只保留 1% 给 root（默认 5%）
#               └─ 卷标
$ sudo mkfs -t ext4 /dev/sdb1

# 场景：xfs（大文件、高并发场景）
$ sudo mkfs.xfs -f -L mydata -m crc=1,reflink=1 /dev/sdb1
$ sudo mkfs.xfs -b size=4096 -d agcount=8 /dev/sdb1

# 场景：btrfs（支持快照、子卷、压缩）
$ sudo mkfs.btrfs -L mydata /dev/sdb1
$ sudo mkfs.btrfs -d raid1 -m raid1 /dev/sdb1 /dev/sdc1

# 场景：vfat（U 盘 / UEFI 分区）
$ sudo mkfs.vfat -F 32 -n USBDRIVE /dev/sdb1
$ sudo mkfs.vfat -F 12 /dev/sdb1          # FAT12（< 16MB）

# 场景：exFAT（大 U 盘，跨平台）
$ sudo mkfs.exfat -n USB64 /dev/sdb1

# 场景：NTFS
$ sudo mkfs.ntfs -f -L Windows /dev/sdb1

# 场景：F2FS（闪存优化）
$ sudo mkfs.f2fs -l flashdata /dev/nvme1n1

# 场景：🧪 在镜像文件上练习（安全）⭐
$ truncate -s 512M /tmp/practice.img
$ mkfs.ext4 -F -L practice /tmp/practice.img
$ sudo mkdir -p /mnt/practice
$ sudo mount -o loop /tmp/practice.img /mnt/practice
$ df -h /mnt/practice
$ sudo umount /mnt/practice

# 场景：🔐 格式化前的最后确认 ⭐⭐
$ findmnt -S /dev/sdb1 && echo "⚠️ 已挂载，不要格式化！"
$ sudo lsblk -f /dev/sdb1
$ sudo blkid /dev/sdb1
```

#### 输出解读
`mke2fs` 输出会显示：
- `Creating filesystem with N 4k blocks and M inodes`
- `Filesystem UUID: ...`（**记下它，要写进 fstab**）⭐
- `Superblock backups stored on blocks: 32768, 98304, ...`（救急用）⭐

#### ⚠️ 危险操作与后果
```bash
$ sudo mkfs.ext4 /dev/sda1        # ⚠️ 若 sda1 是系统分区 → 系统损毁
$ sudo mkfs.ext4 /dev/nvme0n1     # ⚠️⚠️ 写整盘 → 所有分区全没了
```

**防御措施**：
1. 格式化前 `findmnt -S /dev/X` 与 `lsblk -f` 双重确认。
2. 用 `blkid -s UUID` 确认是你预期的设备。
3. 用 `/dev/disk/by-id/` 这种不随插拔变化的路径。
4. 给 `mkfs` 做 alias，先打印设备信息再确认。

#### 常见坑
- ⚠️ **`mkfs` 没有任何确认提示**，执行即生效。
- ⚠️ **`mkfs` 生成新 UUID**，旧的 fstab、crypttab、GRUB 配置全部失效。**格式化有数据的分区后必须更新 fstab**。
- ⚠️ **`mkfs.ext4` 对已挂载设备默认拒绝**（`is mounted; will not make a filesystem here!`），`-F` 可强制——**不要用 `-F` 绕过这个保护**。
- ⚠️ **`mkfs.xfs` 对已有文件系统的设备也拒绝**，必须 `-f`。这是比 ext4 更好的默认行为。
- **`mkfs` 不分区**，只是在已有分区（或整盘）上建文件系统。整盘直接建是合法的但不便管理。
- **`-L` 卷标长度有限**（ext4 最多 16 字符，vfat 最多 11）。
- **`mkfs.ext4` 的 `-m` 是 root 预留百分比**。数据盘可设 `0` 或 `1` 释放空间。
- **`-E stride=` / `stripe-width=` 对 RAID 有性能意义，但一次性设定无法修改**（要重建）。
- **SSD 建议加 `-E lazy_itable_init=1` 并配合 `fstrim`**。
- **大容量设备上 `mkfs.ext4` 很慢**（初始化 inode 表），用 `-E lazy_itable_init=1` 让内核延迟初始化。

#### 相关命令
`mkfs.ext4` · `mkfs.xfs` · `mkswap` · `wipefs` · `blkid` · `tune2fs`

### mkswap / swapon — 交换空间

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
mkswap [选项] 设备或文件
swapon  [选项] [设备]
swapoff [选项] 设备
```

| mkswap 选项 | 含义 |
|-------------|------|
| `-L 标签` | 设置标签 |
| `-U UUID` | 设置 UUID |
| `-f` | 强制 |

| swapon / swapoff 选项 | 含义 |
|-----------------------|------|
| `-a` | 启用/关闭 fstab 里所有 swap 条目 ⭐ |
| `-s` / `--show` | 显示当前交换空间 ⭐ |
| `--show=列` | 自定义列 |
| `-p 优先级` | 优先级（数字大优先使用） |
| `-e` | 优雅（`swapoff` 时尽量移动数据） |

#### 实战示例
```bash
# 场景：创建交换分区
$ sudo mkswap -L SWAP /dev/nvme0n1p3
Setting up swapspace version 1, size = 9.4 GiB
LABEL=SWAP, UUID=...

# 场景：创建交换文件（不分区也能加 swap）⭐
$ sudo fallocate -l 4G /swapfile       # 或 dd if=/dev/zero bs=1M count=4096
$ sudo chmod 600 /swapfile             # ⚠️ 必须 600
$ sudo mkswap /swapfile
$ sudo swapon /swapfile
$ free -h
               total        used        free      shared  buff/cache   available
Mem:            15Gi       8.0Gi       2.1Gi       1.2Gi       5.6Gi       6.5Gi
Swap:          4.0Gi          0B       4.0Gi

# 场景：持久化（写 fstab）⭐
$ echo '/swapfile  none  swap  sw  0 0' | sudo tee -a /etc/fstab
$ sudo swapon -a
$ sudo swapon --show
NAME      TYPE       SIZE USED PRIO
/swapfile file          4G   0B   -2

# 场景：查看交换空间 ⭐
$ swapon --show=NAME,SIZE,USED,PRIO
$ cat /proc/swaps

# 场景：调优先级（多 swap 时）
$ sudo swapoff /swapfile && sudo swapon -p 10 /swapfile

# 场景：关闭交换（⚠️ 内存不足会失败）
$ sudo swapoff /swapfile
$ sudo swapoff -a

# 场景：调整 swappiness ⭐
$ sysctl vm.swappiness
vm.swappiness = 60
$ sudo sysctl -w vm.swappiness=10                                  # 临时
$ echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf    # 持久
```

#### 输出解读
- `/proc/swaps` 是权威数据源，`swapon --show` 读它。
- `PRIO` 为正时数值大的优先；为负表示自动分配（较新创建的优先级更低）。
- `free -h` 的 `Swap` 行显示总量与已用。

#### 常见坑
- ⚠️ **交换文件权限必须是 `600`**，否则 `swapon` 报 `insecure permissions`（防止其他用户读到你被换出的内存，那里面有密码）。🔐
- ⚠️ **`truncate`/`fallocate` 创建的稀疏文件不能做 swap**。要用 `dd if=/dev/zero` 实际写。**btrfs/xfs 上 `fallocate` 的 swap 文件可能被 `swapon` 拒绝**（extent 映射问题）。
- ⚠️ **`swapoff -a` 在内存不足时会把 swap 内容读回内存，可能直接 OOM**。先看 `free -h` 的 available。
- **`mkswap` 不清除原有数据**，只写 swap 头。旧数据仍可能被读出（🔐 取证价值），也可能残留敏感信息。
- **加密交换是敏感系统的必选项**（`/etc/crypttab` 或 fstab 里用 `/dev/mapper/swap`），否则被换出的密码会留在磁盘上。
- **zram / zswap 是现代替代方案**：zram 在内存里压缩交换（无磁盘 I/O），zswap 在换出前压缩。内存大的机器可完全不用磁盘 swap。
- **`swappiness` 语义**：`0` = 只在内存压力极大时才用 swap；`100` = 尽可能用。SSD 上可设 10–20。
- **SSD 上频繁 swap 会消耗写入寿命**（除非有 zram 或加密映射）。

#### 相关命令
`free` · `vmstat` · `zramctl` · `sysctl vm.swappiness` · `fallocate`

### fsck — 文件系统检查与修复

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`fsck` 是前端，各文件系统有独立实现

```bash
fsck [选项] [文件系统...]
fsck.类型 [选项] 设备
```

| 选项 | 含义 |
|------|------|
| `-A` | 检查 fstab 里所有文件系统（按 pass 顺序） |
| `-p` | preen 模式：只自动修复可安全修复的问题 ⭐ 推荐 |
| `-a` | 自动修复（不询问） |
| `-y` | 所有问题都答 yes ⚠️ |
| `-n` | **只检查不修复（只读，最安全）** ⭐⭐ |
| `-f` | 强制检查（即使标记为 clean） |
| `-v` | 详细 |
| `-r` | 交互式（默认） |
| `-t 类型` | 只检查某类型 |
| `-C` | 进度条（ext 系） ⭐ |
| `-N` | 只显示会做什么（dry run） ⭐ |
| `-M` | 不检查已挂载的 |
| `-P` | 与 `-A` 同用，先检查根 |

#### 实战示例
```bash
# 场景：🧪 检查镜像文件（安全练习）⭐
$ truncate -s 100M /tmp/test.img
$ mkfs.ext4 -F /tmp/test.img
$ sudo fsck.ext4 -fC /tmp/test.img
e2fsck 1.47.0 (5-Feb-2023)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
/tmp/test.img: 11/25600 files (0.0% non-contiguous), 6072/102400 blocks

# 场景：只检查不修复（最安全）⭐
$ sudo fsck -n /dev/sdb1

# 场景：自动修复（设备必须未挂载）⭐
$ sudo umount /dev/sdb1
$ sudo fsck -p /dev/sdb1

# 场景：ext4 强制完整检查 + 进度条
$ sudo fsck.ext4 -fC /dev/sdb1

# 场景：dry run（看会执行什么）
$ sudo fsck -N /dev/sdb1
fsck from util-linux 2.39
[/sbin/fsck.ext4 (1) -- /dev/sdb1] fsck.ext4 /dev/sdb1

# 场景：设置自动检查间隔
$ sudo tune2fs -c 30 /dev/sdb1      # 每 30 次挂载检查一次
$ sudo tune2fs -i 30d /dev/sdb1     # 每 30 天检查一次

# 场景：🔐 取证时只读检查（绝不修复！）⭐⭐
$ sudo fsck.ext4 -n /dev/sdb1

# 场景：XFS 用独立工具
$ sudo xfs_repair -n /dev/sdb1      # 只检查
$ sudo xfs_repair -L /dev/sdb1      # ⚠️ 清除日志（可能丢数据）

# 场景：btrfs
$ sudo btrfs check --readonly /dev/sdb1
```

#### 输出解读
`e2fsck` 的 5 个 Pass：

| Pass | 检查内容 |
|------|----------|
| 1 | inode、块、大小 |
| 2 | 目录结构 |
| 3 | 目录连通性 |
| 4 | 引用计数 |
| 5 | 组摘要信息 |

最后一行格式：`设备: clean, N/M files, X/Y blocks`。

#### 常见坑
- ⚠️ **绝不要对已挂载的读写文件系统运行 `fsck`**，会损坏文件系统。ext4 在已挂载时会拒绝，但 `-f` 可能绕过——**不要这么做**。
  - 例外：根文件系统在启动时的只读阶段，或 `xfs_repair -n`（只读）。
- ⚠️ **`-y` 会自动修复所有问题**，在损坏的盘上可能把可恢复的数据「修」没了。**生产环境先 `-n` 看报告再决策**。
- ⚠️ **`xfs_repair -L` 会清除日志**（可能丢最近未落盘的事务），只在日志损坏时用。
- **btrfs 不用 `fsck`**，用 `btrfs check`（建议只读模式）。
- **ZFS 不用 `fsck`**，用 `zpool scrub`。
- **`fsck` 修复会在 `/lost+found` 里放孤儿文件**，这是预期行为。
- **`fsck` 无法检测所有损坏**（静默数据损坏、坏块）。那些要靠 SMART、`badblocks`、`btrfs scrub`。
- **`-C` 进度条只支持 ext 系**。

#### 相关命令
`tune2fs` · `e2fsck` · `xfs_repair` · `btrfs check` · `badblocks` · `dumpe2fs`

### tune2fs / dumpe2fs — ext 系列调参与元数据

**常用度**：★★★☆☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有（`e2fsprogs`）

```bash
tune2fs  [选项] 设备
dumpe2fs [选项] 设备
```

| tune2fs 选项 | 含义 |
|--------------|------|
| `-l` | 显示超级块信息（同 `dumpe2fs -h`） ⭐ |
| `-m N` | root 预留百分比（默认 5） ⭐ |
| `-L 标签` | 设置卷标 |
| `-U UUID` | 设置/清除 UUID ⭐ |
| `-c N` | 每 N 次挂载检查一次（`0` = 禁用） |
| `-i 间隔` | 检查间隔（`30d`/`6m`/`1w`） |
| `-j` | 加日志（ext2 → ext3） |
| `-O 特性` | 开关特性 ⚠️ |
| `-e 行为` | 出错行为（`continue`/`remount-ro`/`panic`） |
| `-E 扩展选项` | `resize=`、`stride=`、`lazy_itable_init` |
| `-f` | 强制 |

| dumpe2fs 选项 | 含义 |
|---------------|------|
| （无） | 完整块组信息 |
| `-h` | 只显示超级块 ⭐ |
| `-o superblock=N` | 用备份超级块 |
| `-f` | 强制 |

#### 实战示例
```bash
# 场景：看文件系统超级块信息 ⭐
$ sudo tune2fs -l /dev/nvme0n1p2

Last mounted on:          /

# 场景：释放预留空间（数据盘不需要 5%）⭐
$ sudo tune2fs -m 1 /dev/nvme0n1p2

# 场景：禁用定期检查（大容量盘 fsck 太慢）
$ sudo tune2fs -c 0 -i 0 /dev/nvme0n1p2

# 场景：改卷标
$ sudo tune2fs -L data2 /dev/nvme0n1p2

$ sudo tune2fs -U random /dev/sdb1
```

#### 输出解读
| 字段 | 含义 |
|------|------|
| `Filesystem state` | `clean` 或 `not clean`（后者需要 fsck） ⭐ |
| `Filesystem features` | 启用的特性，`has_journal` = 有日志 |
| `Reserved block count` | root 预留块数 |
| `Mount count` / `Maximum mount count` | 挂载次数与触发 fsck 的阈值 |
| `Last checked` / `Check interval` | 上次检查时间与间隔 |
| `Journal inode` | 日志的 inode 号 |
| `Lifetime writes` | 累计写入量（估算 SSD 寿命） ⭐ |

#### 常见坑
- ⚠️ **`tune2fs -O` 改特性可能让文件系统不被旧内核挂载**，某些特性无法安全关闭（如 `^has_journal`）。**改特性前必须备份**。
- ⚠️ **`-U` 改 UUID 后必须同步更新 fstab、crypttab、GRUB 配置**，否则系统起不来。
- ⚠️ **`-m 0` 完全去掉预留**会让 root 在磁盘满时也无法登录清理。**数据盘 `-m 1`，系统盘保持默认 5%**。
- **`tune2fs` 大部分操作可在已挂载的文件系统上执行**（它是 online 的），改某些特性需要未挂载。
- **`-c 0 -i 0` 禁用自动检查后，损坏只能靠手动 fsck 或运行时错误发现**。启用 `metadata_csum` 能更早发现问题。
- **`dumpe2fs` 输出很长**（每个块组一段），用 `-h` 只看超级块。
- **`Lifetime writes` 精度有限**，只统计块设备层写入。准确评估 SSD 寿命用 `smartctl`。

#### 相关命令
`e2fsck` · `resize2fs` · `debugfs` · `smartctl` · `mkfs.ext4`

### resize2fs / xfs_growfs — 在线调整文件系统大小

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
resize2fs  [选项] 设备 [大小]        # ext2/3/4
xfs_growfs [选项] 挂载点             # XFS（只能扩，参数是挂载点）
btrfs filesystem resize [大小] 挂载点
```

| resize2fs 选项 | 含义 |
|----------------|------|
| （无大小） | 扩展到设备/分区全部大小 ⭐ |
| `大小` | 目标大小（`50G`、`+10G`） |
| `-M` | 缩到最小 |
| `-P` | **打印最小尺寸（不修改）** ⭐ |
| `-f` | 强制 |
| `-z` | 撤销上次的在线调整（仅 ext4 online） |

| xfs_growfs 选项 | 含义 |
|-----------------|------|
| `-n` | **只显示不修改（dry run）** ⭐ |
| `-d` | 扩展数据部分（默认） |
| `-l` | 扩展日志部分 |
| `-D 块数` | 数据部分目标大小 |

#### 实战示例
```bash
# ===== 扩容流程（最常见）=====

# 步骤 1：查看当前分区与文件系统
$ lsblk /dev/nvme0n1
$ df -hT /data

# 步骤 2：确认设备末尾有未分配空间（虚拟机扩盘后）
$ sudo parted /dev/nvme0n1 print free

# 步骤 3：扩容分区边界（⚠️ 只扩，不要动起始位置）⭐
$ sudo growpart /dev/nvme0n1 2
# 或
$ sudo parted -s /dev/nvme0n1 resizepart 2 100%
$ sudo partprobe /dev/nvme0n1

# 步骤 4：扩容文件系统
# ext4：可以在线扩容（已挂载） ⭐
$ sudo resize2fs /dev/nvme0n1p2
Filesystem at /dev/nvme0n1p2 is mounted on /; on-line resizing required
old_desc_blocks = 30, new_desc_blocks = 58
The filesystem on /dev/nvme0n1p2 is now 244096000 (4k) blocks long.

# XFS：只能扩，参数是**挂载点**
$ sudo xfs_growfs /data
data     =               bsize=4096   blocks=26214400, imaxpct=25
data     =               blocks=39321600

# btrfs：在线可扩可缩
$ sudo btrfs filesystem resize max /data
$ sudo btrfs filesystem resize -10G /data      # ⚠️ 缩前确保有足够空闲

# ===== 缩容流程（ext4，⚠️ 高风险）=====
$ sudo umount /dev/sdb1
$ sudo e2fsck -f /dev/sdb1                     # ⚠️ 必须先检查
$ sudo resize2fs /dev/sdb1 50G                 # 先缩文件系统
$ sudo parted -s /dev/sdb1 resizepart 1 51GiB  # 再缩分区（分区必须 ≥ 文件系统）
$ sudo mount /dev/sdb1 /data

# 场景：查看最小可缩到的尺寸 ⭐
$ sudo resize2fs -P /dev/sdb1
Estimated minimum size of the filesystem: 12345678

# 场景：dry run
$ sudo xfs_growfs -n /data

# 场景：LVM 扩容的完整顺序 ⭐
$ sudo pvresize /dev/sdb
$ sudo lvextend -l +100%FREE /dev/vg0/lv0
$ sudo resize2fs /dev/vg0/lv0
```

#### 输出解读
- `resize2fs` 报告 `old_desc_blocks` / `new_desc_blocks` 和最终块数。
- `xfs_growfs` 显示扩展前后的 `blocks`。
- `btrfs filesystem resize` 显示 `Resize device id 1 from X to Y`。

#### 常见坑
- ⚠️ **顺序绝对不能错**：
  - **扩容：先扩分区，再扩文件系统**
  - **缩容：先缩文件系统，再缩分区**
  - **顺序反了会永久损坏数据**。
- ⚠️ **XFS 不支持缩小**（官方明确）。要缩小只能备份 → 重建 → 恢复。
- ⚠️ **缩容前必须 `e2fsck -f`**，`resize2fs` 会拒绝在未检查的文件系统上缩小。
- ⚠️ **缩容的分区边界必须 ≥ 文件系统大小**，否则数据落在分区外，直接损坏。
- ⚠️ **ext4 的缩容不支持在线**，必须卸载。
- **`resize2fs` 在线扩容需要 `resize_inode` 特性**（现代 ext4 都有）。
- **扩容不会自动扩展分区**，只扩文件系统会失败（`The filesystem is already N blocks long`）。
- **`xfs_growfs` 用的是挂载点而不是设备**（`xfs_growfs /dev/sdb1` 会报错）。
- **`growpart` 是 cloud-utils 里的便捷工具**，比手动 `parted` 安全（会检查是否已占满）。

#### 相关命令
`parted` · `growpart` · `lvextend` · `pvresize` · `btrfs filesystem resize` · `fsck`

### dd — 块级复制与转换

**常用度**：★★★★★ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：`status=progress`、`iflag`/`oflag` 部分值为 GNU 扩展

```bash
dd if=输入 of=输出 [选项]
```

> ⚠️ **`dd` 有 "disk destroyer"（磁盘毁灭者）的绰号。`of=` 写错一个字符就可能毁掉系统盘。**

#### 高频选项
| 选项 | 含义 | 示例 |
|------|------|------|
| `if=` | 输入文件/设备 | `if=/dev/sdb` |
| `of=` | 输出文件/设备 ⚠️ | `of=/dev/sdc` |
| `bs=` | 块大小（默认 512） ⭐ | `bs=1M` |
| `ibs=` / `obs=` | 输入 / 输出块大小 | — |
| `count=N` | 复制 N 个块 ⭐ | `count=100` |
| `skip=N` | 输入跳过 N 块 | — |
| `seek=N` | 输出跳过 N 块 | — |
| `conv=选项` | `notrunc`、`noerror`、`sync`、`fsync`、`ucase`、`lcase` ⭐ | `conv=noerror,sync` |
| `iflag=` | `direct`、`fullblock`、`skip_bytes` | `iflag=direct` |
| `oflag=` | `direct`、`sync`、`append` | `oflag=direct` |
| `status=progress` | 显示进度 ⭐ | — |

⚠️ `bs=1M` 是 1024×1024；`bs=1MB` 是 1000×1000。**两者相差 4.8%**。

#### 实战示例
```bash
# 场景：创建空/随机文件
$ dd if=/dev/zero of=/tmp/100M.bin bs=1M count=100 status=progress
104857600 bytes (105 MB, 100 MiB) copied, 0.085 s, 1.2 GB/s

$ dd if=/dev/urandom of=/tmp/rand.bin bs=1M count=10 status=progress

# 场景：写零清空分区（⚠️ 不可恢复）
$ sudo dd if=/dev/zero of=/dev/sdb1 bs=1M status=progress

# 场景：🔐 磁盘取证镜像（必加 conv=noerror,sync）⭐⭐
$ sudo dd if=/dev/sdb of=/mnt/evidence/sdb.img bs=64K conv=noerror,sync status=progress
$ sha256sum /mnt/evidence/sdb.img | tee /mnt/evidence/sdb.img.sha256
#            │                    └─ conv=sync 用零填充坏块，保持偏移对齐
#            └─ conv=noerror 遇到读错误继续（不中断）

# 场景：🔐 更好的取证工具（有断点续传、坏块记录）⭐
$ sudo dcfldd if=/dev/sdb of=/mnt/evidence/sdb.img hash=sha256 hashlog=hash.txt
$ sudo dc3dd if=/dev/sdb of=/mnt/evidence/sdb.img hash=sha256 log=dd.log
$ sudo ddrescue -d -r3 /dev/sdb /mnt/evidence/sdb.img /mnt/evidence/sdb.map

# 场景：制作可启动 U 盘（⚠️ 三次确认设备名！）⭐⭐
$ lsblk                                        # 先确认
$ sudo dd if=archlinux.iso of=/dev/sdb bs=4M oflag=sync status=progress conv=fsync
$ sync
# ⚠️ 是 /dev/sdb（整盘），不是 /dev/sdb1（分区）

# 场景：读/写特定偏移（直接改二进制）
$ sudo dd if=/dev/sdb of=/tmp/mbr.bin bs=512 count=1               # 读 MBR
$ sudo dd if=/tmp/mbr.bin of=/dev/sdb bs=512 count=1 conv=notrunc  # 写回
$ printf '\x90\x90' | dd of=target.bin bs=1 seek=$((0x1234)) conv=notrunc

# 场景：测试磁盘读写速度 ⭐
$ dd if=/dev/zero of=/tmp/testfile bs=1M count=4096 oflag=direct status=progress
$ dd if=/tmp/testfile of=/dev/null bs=1M iflag=direct status=progress
$ rm -f /tmp/testfile

# 场景：备份分区表
$ sudo dd if=/dev/sda of=/root/sda-mbr.bak bs=512 count=1

# 场景：边读边压（省空间）
$ sudo dd if=/dev/sdb bs=1M conv=noerror,sync | zstd -T0 > /mnt/sdb.img.zst

# 场景：给正在跑的 dd 看进度（另一个终端）
$ sudo kill -USR1 <dd_pid>
```

#### 输出解读
```
104857600 bytes (105 MB, 100 MiB) copied, 0.085 s, 1.2 GB/s
│                      │          │      └─ 平均速度
│                      │          └─ 耗时
│                      └─ 人类可读大小
└─ 字节数
100+0 records in
100+0 records out
│    └─ partial records out（不完整记录数）
└─ full records in
```

`bs` 大小显著影响速度：`512` → ~50 MB/s；`64K–1M` → 快；`4M–16M` → 最快（但内存占用高）。

#### ⚠️ 典型案例与后果
```bash
$ dd if=ubuntu.iso of=/dev/sda          # ⚠️⚠️ 毁掉系统盘（本应写 sdb）
$ dd if=/dev/zero of=/dev/nvme0n1       # ⚠️⚠️ 抹掉整盘（含分区表）
$ dd if=/dev/sda of=/dev/sda            # ⚠️ 自己读自己写
```

**防御**：
1. 执行前**三次确认** `of=` 的设备名。
2. 用 `/dev/disk/by-id/` 路径（不随插拔顺序变化）。
3. 首次执行先 `count=1` 或用 `of=/dev/null` 验证 `if`。
4. 生产环境用更安全的工具（`ddrescue`、桌面上的 balenaEtcher）。

#### 常见坑
- ⚠️ **`bs=1M` 是 1024×1024，`bs=1MB` 是 1000×1000**。
- ⚠️ **`dd` 默认不做 `fsync`**。写完没落盘就拔设备会丢数据。加 `conv=fsync` 或 `oflag=sync`。
- ⚠️ **取证镜像必须 `conv=noerror,sync`**，否则遇到第一个坏块就中断。但 `sync` 会用零填充，与原始数据不同（要记录在案）。
- ⚠️ **`dd` 不检查 `of=` 是否是系统盘**，也不检查剩余空间。
- **`dd` 没有进度显示**（除非 `status=progress`，或 `kill -USR1`）。
- **小块读写非常慢**，`bs` 太大又占内存。
- **读写速度受页缓存影响**：写文件时 `dd` 报告的「速度」可能只是写进内存。要真实测试用 `oflag=direct`。
- **`dd` 复制稀疏文件会展开它**（变实心）。反过来用 `dd conv=sparse`，或 `cp --sparse=always`。
- **`dd if=/dev/urandom` 在无熵池的虚拟机里可能极慢**。用 `/dev/zero` 或 `openssl enc -aes-256-ctr` 替代。

#### 相关命令
`dcfldd` · `ddrescue` · `dc3dd` · `truncate` · `fallocate` · `hdparm`

### losetup — 环回设备

**常用度**：★★★☆☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
losetup [选项] [环回设备] [文件]
```

| 选项 | 含义 | 示例 |
|------|------|------|
| `-f` | 找第一个空闲环回设备 ⭐ | `sudo losetup -fP disk.img` |
| `-a` | 列出所有环回设备 ⭐ | `sudo losetup -a` |
| `-j 文件` | 显示该文件关联的设备 | `losetup -j disk.img` |
| `-d 设备` | 分离 | `sudo losetup -d /dev/loop0` |
| `-D` | 分离所有 | `sudo losetup -D` |
| `-P` | 读取分区表并创建分区设备 ⭐ | `-fP` |
| `-r` | 只读 🔐 | `-fr` |
| `-o 偏移` | 从偏移开始 | `-o $((2048*512))` |
| `--sizelimit 大小` | 限制大小 | — |
| `-c` | 让内核重读大小（镜像扩容后） ⭐ | `sudo losetup -c /dev/loop0` |
| `-O 列` | 自定义 `-a` 的输出列 ⭐ | `losetup -a -O NAME,BACK-FILE` |
| `-J` | JSON 输出 | — |

#### 实战示例
```bash
# 场景：把镜像文件当块设备挂载 ⭐
$ sudo losetup -fP disk.img
$ lsblk
loop0
├─loop0p1
└─loop0p2
$ sudo mount /dev/loop0p2 /mnt/img

# 场景：查看所有环回设备 ⭐
$ sudo losetup -a
/dev/loop0: []: (/home/user/disk.img)
$ sudo losetup -a -O NAME,BACK-FILE,SIZELIMIT,RO

# 场景：查看某文件关联的设备
$ sudo losetup -j disk.img

# 场景：指定偏移（直接挂某个分区）
$ sudo losetup -o $((2048*512)) --sizelimit 1G /dev/loop1 disk.img
$ sudo mount /dev/loop1 /mnt/data

# 场景：🔐 只读挂载（取证）⭐
$ sudo losetup -fr /dev/loop0 evidence.img
$ sudo mount -o ro,noload /dev/loop0 /mnt/evidence

# 场景：分离
$ sudo losetup -d /dev/loop0
$ sudo losetup -D

# 场景：mount 自动处理（现代 mount 的便利）
$ sudo mount -o loop,ro disk.img /mnt/img
$ sudo umount -d /mnt/img                      # -d 同时分离环回设备

# 场景：镜像扩容后重新识别 ⭐
$ truncate -s +1G disk.img
$ sudo losetup -c /dev/loop0                   # 让内核重读大小
$ sudo partprobe /dev/loop0
$ sudo resize2fs /dev/loop0p1

# 场景：稀疏镜像（省磁盘）
$ truncate -s 10G sparse.img
$ sudo losetup -fP sparse.img
$ ls -lh sparse.img; du -h sparse.img
-rw-r--r-- 1 root root 10G ... sparse.img
0       sparse.img
```

#### 输出解读
`losetup -a` 格式：`/dev/loopN: [主:次]: (文件路径)`。

`lsblk` 里 `loop` 类型的设备会与分区（`loop0p1`）一起显示（需要 `-P`）。

#### 常见坑
- ⚠️ **不加 `-P` 不会自动识别分区**，`/dev/loop0p1` 不会出现。要 `-P` 或 `partprobe`。
- ⚠️ **忘记 `losetup -d` 会占用环回设备**（默认 8 个），用 `losetup -a` 检查残留。残留会让后续操作找不到空闲设备。
- ⚠️ **镜像被环回设备占用时无法删除**（`Device or resource busy`），先 `-d`。
- **`mount -o loop` 创建的环回设备默认只读**；`losetup` 创建的默认可写。取证要显式 `-r`。
- **对稀疏镜像做 `dd`/`cp` 会展开它**，用 `cp --sparse=always`。
- **`mount -o loop` 在容器里可能不工作**（需要 `CAP_SYS_ADMIN` 和 `/dev/loop*`）。
- **挂载 btrfs/xfs 镜像前要确认文件系统是 clean 的**，否则会触发日志恢复（修改镜像）。
- **`losetup -c` 是让内核重读大小**（镜像扩容后必做）。

#### 相关命令
`mount -o loop` · `partprobe` · `truncate` · `qemu-img` · `blkid`

### fallocate — 预留空间

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：Linux 特有（`util-linux`）

```bash
fallocate [选项] 文件
```

| 选项 | 含义 |
|------|------|
| `-l 大小` | 长度（必填） ⭐ |
| `-o 偏移` | 起始偏移 |
| `-n` | **不实际分配**，只改文件大小（稀疏） ⭐ |
| `-d` | 释放范围（打洞） ⭐ |
| `-z` | 零填充（写入零） ⭐ |
| `-c` | 折叠范围 |
| `-i` | 插入范围 |
| `-x 范围` | 只保留该范围 |
| `-h` | 人类可读大小 |

```bash
# 场景：快速创建大文件（比 dd 快几个数量级，但会真的占空间）⭐
$ fallocate -l 10G /tmp/big.img
$ ls -lh /tmp/big.img; du -h /tmp/big.img
-rw-r--r-- 1 user user 10G ... /tmp/big.img
10G     /tmp/big.img

# 场景：创建稀疏文件（不占实际空间）⭐
$ truncate -s 10G /tmp/sparse.img
$ ls -lh /tmp/sparse.img; du -h /tmp/sparse.img
-rw-r--r-- 1 user user 10G ... /tmp/sparse.img
0       /tmp/sparse.img

# 场景：快速创建交换文件（比 dd 快）⭐
$ sudo fallocate -l 4G /swapfile
$ sudo chmod 600 /swapfile
$ sudo mkswap /swapfile
# ⚠️ btrfs/xfs 上 fallocate 的交换文件可能被 swapon 拒绝，此时必须用 dd

# 场景：给文件打洞（释放中间空间）
$ fallocate -d -o 1G -l 512M bigfile

# 场景：预留空间（防止关键写入因磁盘满而失败）⭐
$ fallocate -l 100M /var/log/reserve.space

# 场景：为数据库预分配（避免碎片）
$ fallocate -l 50G /var/lib/postgresql/data/base.img

# 场景：零填充（避免泄露磁盘旧数据）🔐
$ fallocate -l 1G -z /tmp/safe.img
```

#### 输出解读
- `fallocate -l` 分配**真实磁盘块**，`du` 与 `ls` 一致。
- `fallocate -n`（等效 `truncate -s`）只改大小，不分配块（`du` 显示 0）。

#### 常见坑
- ⚠️ **`fallocate` 依赖文件系统支持 `fallocate(2)`**。在 tmpfs、FAT、NFS、部分旧版 ext4 上会报 `Operation not supported`。
- ⚠️ **`fallocate` 不做零填充**（除非 `-z`），**内容可能是磁盘上的旧数据**（信息泄露风险）。🔐 用 `-z` 或 `dd if=/dev/zero`。
- ⚠️ **btrfs/xfs 上的 `fallocate` 交换文件可能被 `swapon` 拒绝**，这类文件系统上必须用 `dd`。
- **`fallocate -l` 会立即占用空间**（与 `truncate` 相反），对「测试磁盘满」很有用。
- **`fallocate` 比 `dd` 快得多**（不实际写数据），创建 100G 文件几乎瞬时。
- **稀疏文件不能做 swap**，且某些工具（`tar`、`cp` 默认）会展开它。
- **`fallocate -d` 打洞后读该区域返回零**（不是原来的数据）。

#### 相关命令
`truncate` · `dd` · `mkswap` · `du --apparent-size` · `ls -s`

### sync — 刷写磁盘缓存

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：POSIX 定义了无参数的 `sync`；`-d`/`-f` 为 GNU

```bash
sync [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| （无参） | 刷写所有文件系统 ⭐ |
| `文件...` | 只刷写这些文件所属的文件系统 |
| `-d` | 只刷数据（不刷元数据） |
| `-f` | 刷写指定文件系统的元数据 |

```bash
# 场景：拔 USB 前刷写 ⭐⭐
$ sync
$ sudo umount /mnt/usb
# 现在可以安全拔出

# 场景：关键数据立即落盘
$ echo "important" > /critical/file
$ sync /critical/file

# 场景：查看脏页与回写状态 ⭐
$ grep -E 'Dirty|Writeback' /proc/meminfo
Dirty:              1234 kB
Writeback:             0 kB

# 场景：监控回写压力（另一个终端）
$ watch -n1 "grep -E 'Dirty|Writeback' /proc/meminfo"

# 场景：dd 时保证落盘（用 conv=fsync 更好）
$ dd if=data of=/dev/sdb bs=1M conv=fsync
```

#### 输出解读
`/proc/meminfo` 的关键字段：

| 字段 | 含义 |
|------|------|
| `Dirty` | 已修改但未写回磁盘的数据量 |
| `Writeback` | 正在写回磁盘的数据量 |
| `WritebackTmp` | FUSE 的临时回写 |

#### 常见坑
- ⚠️ **`sync` 是全局的，会阻塞调用者直到所有脏页落盘**（可能几分钟）。繁忙服务器上会造成明显的 I/O 尖峰。
- ⚠️ **`sync && 拔设备` 仍不 100% 安全**：U 盘、SD 卡有自己的缓存，需要 `umount` 或 `hdparm -F` 让设备刷新自己的缓存。
- ⚠️ **`sync` 对 `O_DIRECT` 写入的程序无意义**（它们已绕过缓存）。
- **`sync` 不能保证「数据不会因磁盘固件 bug 而丢失」**（消费级 SSD 断电时可能丢数据）。
- **`sync` 没有进度提示**（Linux）。要看进度用 `watch` 监控 `Dirty`。
- **容器里 `sync` 只刷写容器可见的文件系统**。
- **不要在 `set -e` 的循环里频繁 `sync`**，会让脚本慢几个数量级。
- **`fsync()`/`fdatasync()` 是单文件粒度的**，程序应在写完关键数据后调用它们，而不是全局 `sync`。

#### 相关命令
`umount` · `dd conv=fsync` · `/proc/meminfo` · `fsync(2)`

### ncdu — 交互式磁盘占用分析

**常用度**：★★★★☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：第三方工具，非 POSIX

```bash
ncdu [选项] [目录]
```

| 选项 | 含义 |
|------|------|
| `-x` | 不跨文件系统 ⭐ |
| `-o 文件` | 导出扫描结果为 JSON ⭐ |
| `-f 文件` | 导入已导出的结果并浏览 ⭐ |
| `--exclude 模式` | 排除 ⭐ |
| `-X 文件` | 从文件读排除规则 |
| `--exclude-caches` | 排除有 `CACHEDIR.TAG` 的目录 |
| `-L` | 跟随符号链接 |
| `-r` | 只读模式（禁止删除） ⭐ |
| `--si` | 10 的幂 |
| `-q` | 减少屏幕刷新 |

#### 交互键
| 键 | 作用 | 键 | 作用 |
|----|------|----|------|
| `↑↓ jk` | 移动 | `→` `l` | 进入目录 |
| `←` `h` | 返回上级 | `s` | 按大小排序 ⭐ |
| `n` | 按名字排序 | `a` | 表观大小 |
| `d` | 删除选中项 ⚠️ ⭐ | `i` | 项目信息 |
| `e` | 显示隐藏文件 | `r` | 重新扫描当前目录 ⭐ |
| `g` | 切换显示模式 | `q` | 退出 |

```bash
# 场景：交互式找出谁占用了空间 ⭐⭐
$ ncdu -x /
# 用方向键进入各目录，按 d 删除不需要的大文件

# 场景：扫描并导出，之后离线分析（服务器上很有用）⭐
$ ncdu -o /tmp/scan.json -x /
# 把 json 下载到本地
$ ncdu -f /tmp/scan.json

# 场景：排除噪音
$ ncdu -x --exclude /proc --exclude /sys --exclude /var/lib/docker /

# 场景：只读（防止误删，共享服务器安全）
$ ncdu -r /data

# 场景：只看某目录
$ ncdu ~/Downloads
```

#### 输出解读
```
ncdu 1.19 ~ Use the arrow keys to navigate, press ? for help
--- /home/user --------------------------------------------------------
    4.2 GiB [##########] /Downloads
    1.8 GiB [####      ] /Documents
  512.3 MiB [##        ] /Videos
```
左列是大小，`#` 是直观的比例条，右列是名字。顶部显示 `Total disk usage` / `Apparent size` / `Items`。

#### 常见坑
- ⚠️ **`d` 键会真删文件**（虽然要确认），共享环境用 `-r` 只读模式。
- ⚠️ **不指定 `-x` 会跨挂载点扫描**，把 `/mnt` 下的其他盘、`/proc` 全算进来，结果失真。
- **扫描大文件系统要几分钟**（要遍历所有 inode）。服务器上建议 `-o` 导出后本地分析。
- **需要目录读权限**，无权限目录被跳过（显示为不可访问）。
- **删除不走回收站**，直接 `unlink`。
- **不能替代 `du`**：交互式的，脚本里用 `du`。
- **`ncdu` 与 `du` 的数字可能略有差异**（块取整、硬链接处理），大体量上一致。

#### 相关命令
`du` · `df` · `dust` · `gdu`

### smartctl — 硬盘健康状态

**常用度**：★★★☆☆ ｜ **所属**：磁盘与文件系统 ｜ **POSIX/GNU 差异**：非 POSIX，`smartmontools` 提供

```bash
smartctl [选项] 设备
```

| 选项 | 含义 |
|------|------|
| `-a` | 全部信息（最常用） ⭐ |
| `-H` | 健康状态（PASSED / FAILED） ⭐ |
| `-i` | 设备信息（型号、序列号、固件） |
| `-A` | SMART 属性表 ⭐ |
| `-x` | 扩展信息（含 NVMe 详细） ⭐ |
| `-l selftest` | 自检日志 |
| `-l error` | 错误日志 ⭐ |
| `-t short` / `-t long` | 启动短/长自检 |
| `-X` | 中止自检 |
| `-d 类型` | 指定设备类型（`nvme`/`sat`/`scsi`/`megaraid,N`） ⭐ |
| `--scan` | 扫描所有设备 ⭐ |
| `--json` | JSON 输出 ⭐ |

#### 关键 SMART 属性（必须监控）
| ID | 名称 | 危险信号 |
|----|------|----------|
| 5 | Reallocated_Sector_Ct | **> 0 且增长** → 盘在坏 |
| 187 | Reported_Uncorrect | **> 0** → 不可纠正错误 |
| 188 | Command_Timeout | 增长 → 盘响应慢 |
| 196 | Reallocated_Event_Count | 增长 → 重映射增加 |
| 197 | Current_Pending_Sector | **> 0** → 待重映射扇区 ⭐ |
| 198 | Offline_Uncorrectable | **> 0** → 离线扫描发现坏块 ⭐ |
| 199 | UDMA_CRC_Error_Count | 增长 → **线缆/SATA 控制器问题**（不是盘） |
| 177 | Wear_Leveling_Count | SSD 磨损（低值危险） |
| 231 | SSD_Life_Left | SSD 剩余寿命百分比 |
| 241 | Total_LBAs_Written | 累计写入量（评估寿命） |

NVMe 关键字段：

| 字段 | 危险信号 |
|------|----------|
| `Critical Warning` | **非 0 就是警告** ⭐ |
| `Available Spare` | 低于阈值 → 备用块耗尽 |
| `Percentage Used` | > 90% → 接近寿命终点 |
| `Media and Data Integrity Errors` | **> 0** → 数据完整性错误 ⭐ |
| `Unsafe Shutdowns` | 增长 → 断电/崩溃 |

#### 常见坑
- ⚠️ **NVMe 盘不加 `-d nvme` 可能读不到完整 SMART**。`smartctl --scan` 会自动识别。
- ⚠️ **RAID 控制器后面的盘要指定 `-d megaraid,N`**，否则看到的是虚拟盘。
- ⚠️ **USB 硬盘盒（USB-SATA 桥）经常不支持 SMART 透传**，需要 `-d sat`，有些设备根本不支持。
- ⚠️ **`smartctl -a` 需要 root**。
- **看 `RAW_VALUE` 比看 `VALUE` 可靠**：`VALUE` 是归一化值，不同厂商语义不同。
- **自检（`-t long`）持续几小时到几十小时**，且降低性能。生产环境用 `-t short` 或调度到维护窗口。
- **`-t long` 期间断电会得到 `Interrupted (host reset)`**。
- **SMART 可被固件篡改**（尤其消费级 SSD 与恶意固件）。不能只依赖 SMART。
- **监控建议**：定期采集 `smartctl --json` 到监控系统，对关键属性做**趋势告警**而非只看阈值。

#### 相关命令
`nvme smart-log` · `hdparm` · `badblocks` · `smartd` · `lsblk`

```bash
$ sudo hdparm -tT /dev/nvme0n1
/dev/nvme0n1:
 Timing cached reads:   45678 MB in  2.00 seconds = 22839.00 MB/sec
 Timing buffered disk reads: 3456 MB in  3.00 seconds = 1152.00 MB/sec

# 场景：查看电源状态 / 让盘休眠
$ sudo hdparm -C /dev/sda
/dev/sda:
 drive state is:  active/idle
$ sudo hdparm -y /dev/sda
$ sudo hdparm -S 240 /dev/sda          # 20 分钟后自动休眠

# 场景：检查是否支持 TRIM
$ lsblk -D
NAME      DISC-GRAN DISC-MAX DISC-ZERO
nvme0n1        512B       2T         0
#    ↑ 非 0 = 支持 discard

# 场景：定期 TRIM（systemd 已内置 timer）⭐
$ systemctl status fstrim.timer
$ sudo systemctl enable --now fstrim.timer
$ sudo fstrim -av
/: 45.2 GiB (48514170880 bytes) trimmed on /dev/nvme0n1p2

# 场景：dry run 看会丢弃多少 ⭐
$ sudo blkdiscard -n /dev/sdb1
blkdiscard: BLKDISCARD would discard 1073741824 bytes

# 场景：安全模式（只丢弃本来就是零的区域，不泄数据）
$ sudo blkdiscard -s /dev/sdb1

# 场景：⚠️⚠️ 全盘丢弃（会清空设备的映射）——不要对系统盘用！
$ sudo blkdiscard -f /dev/nvme1n1

# 场景：🔐 SSD 安全擦除（彻底清除 + 恢复出厂性能）⭐⭐
$ sudo hdparm --user-master u --security-set-pass p /dev/sda
$ sudo hdparm --user-master u --security-erase p /dev/sda
# ⚠️⚠️ 不可恢复！执行前必须备份
#    某些盘需在 BIOS 里把 frozen 改为 not frozen 才能执行

# 场景：NVMe 的安全擦除（用 nvme-cli）
$ sudo nvme format /dev/nvme0 -s 2 -f       # -s 2 = crypto erase
$ sudo nvme sanitize /dev/nvme0 -a 2        # block erase
```

#### 输出解读
- `hdparm -tT`：`cached reads` 是内存/缓存速度，`buffered disk reads` 是真实磁盘速度。
- `lsblk -D` 的 `DISC-GRAN` 非 0 表示支持 TRIM。
- `fstrim -av` 显示每个文件系统 TRIM 掉的字节数。

#### 常见坑
- ⚠️ **`blkdiscard` 不可恢复地清空设备**（发送 TRIM，SSD 控制器立即擦除映射）。对非 SSD 或虚拟磁盘尤其危险。
- ⚠️ **`hdparm --security-erase` 需要先 `--security-set-pass`**，且部分主板的 BIOS 会把盘设为 "frozen"，需先休眠/热插拔解锁。**搞错密码会让盘永久锁死**。
- ⚠️ **`hdparm -W 0`（关写缓存）会严重降低性能**，只在特定可靠性需求下用。
- ⚠️ **`hdparm` 的选项对 NVMe 大多无效**（NVMe 用 `nvme-cli`）。`hdparm` 是 ATA/SATA 时代的工具。
- **`blkdiscard` 对不支持 discard 的设备会失败**（先用 `lsblk -D` 检查）。
- **`fstrim` 比 `blkdiscard` 安全得多**（只对文件系统的空闲块发 TRIM），日常用 `fstrim` 或 `fstrim.timer` 即可。
- **虚拟机磁盘的 discard 需要显式配置**（QEMU 的 `discard=unmap`、VMware 的 space reclamation），否则无效。
- **`hdparm --security-erase` 不支持 NVMe 盘**，NVMe 用 `nvme format` / `nvme sanitize`。

#### 相关命令
`fstrim` · `nvme` · `lsblk -D` · `smartctl` · `blkdiscard`
