### chmod — 修改权限位

**常用度**：★★★★★ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`-R`、`--reference`、`X` 都是 POSIX

#### 语法
```bash
chmod [选项] 模式 文件...
chmod --reference=参考文件 目标
```

#### 模式写法
**八进制**（三个位或四位带特殊位）：

| 数字 | 含义 |
|------|------|
| `644` | `rw-r--r--` |
| `755` | `rwxr-xr-x` |
| `600` | `rw-------`（私钥） |
| `4000` | SUID，如 `4755` |
| `2000` | SGID，如 `2775` |
| `1000` | Sticky，如 `1777` |

**符号**：`[ugoa][+-=][rwxXst]`

| 符号 | 含义 |
|------|------|
| `u` `g` `o` `a` | 属主 / 属组 / 其他人 / 全部 |
| `+` `-` `=` | 增加 / 移除 / 精确设置 |
| `r` `w` `x` | 读 / 写 / 执行 |
| `X` | 仅对目录或已有 x 的文件加执行 ⭐ |
| `s` | SUID/SGID |
| `t` | Sticky |

#### 高频选项
| 选项 | 含义 |
|------|------|
| `-R` | 递归 |
| `-v` | 显示每个改动 |
| `-c` | 只在有改动时显示 |
| `--reference=文件` | 复制参考文件的权限 |

#### 实战示例
```bash
# 场景：脚本加执行位
$ chmod +x deploy.sh
$ chmod 755 deploy.sh

# 场景：私钥必须是 600（否则 ssh 拒绝使用）
$ chmod 600 ~/.ssh/id_ed25519
$ chmod 700 ~/.ssh

# 场景：递归给目录加执行但不动普通文件 ⭐
$ chmod -R u+rwX,g+rX,o= /srv/share
#               ^ X 关键：只给目录和已可执行的文件加 x

# 场景：只去掉其他人的写权限
$ chmod -R o-w /srv/share

# 场景：精确设置（o= 会清空其他人所有权限）
$ chmod u=rw,g=r,o= secret.txt
$ stat -c '%A' secret.txt
-rw-r-----

# 场景：SGID 共享目录
$ sudo chmod 2775 /srv/team

# 场景：Sticky 目录（只有属主能删自己的文件）
$ sudo chmod 1777 /srv/pub
$ ls -ld /srv/pub
drwxrwxrwt ...

# 场景：🧪 给 SUID 程序打标（实验用）
$ sudo cp /bin/bash /tmp/bash_suid && sudo chmod 4755 /tmp/bash_suid
$ ls -l /tmp/bash_suid
-rwsr-xr-x 1 root root ... /tmp/bash_suid
$ /tmp/bash_suid -p -c 'id'    # ⚠️ 演示 SUID 提权原理，实验后立即删除
$ sudo rm -f /tmp/bash_suid

# 场景：复制权限
$ chmod --reference=/etc/passwd /tmp/newfile
```

#### 输出解读
`ls -l` 里特殊位显示规则：

| 显示 | 含义 |
|------|------|
| `s`（属主位，小写） | SUID 且属主有执行权 |
| `S`（大写） | SUID 但属主**无**执行权（无效标志） |
| `s`（属组位） | SGID 且有执行权 |
| `t`（其他人位，小写） | Sticky 且其他人有执行权 |
| `T`（大写） | Sticky 但其他人无执行权 |

#### 常见坑
- ⚠️ **`chmod -R 777 path` 是安全事故**。它会：
  1. 让所有配置文件里的密钥、证书对所有人可读
  2. 让所有脚本对所有人可写 → 任意用户可植入代码
  3. 让目录对所有人可写 → 可删除/替换文件
  4. 如果服务会执行这些脚本，等于给出 RCE
- ⚠️ **`chmod -R +x` 会把所有文本文件变成可执行**，用 `X`（大写）代替。
- **`chmod` 对符号链接改的是目标**（不是链接本身）。`chmod -h` 在 GNU 里被忽略（符号链接的权限无意义）。
- **`chmod` 在 Windows 挂载（NTFS/FAT）或某些网络文件系统上无效**，会静默失败。`ls` 显示的权限是伪造的。
- **删除文件不由文件自身权限决定，而是所在目录的 `w`**。所以「文件是 444 但还是被删了」是正常的。
- SUID 在**脚本**上被内核忽略（`#!/bin/sh` 的脚本加 SUID 无效），只对 ELF 二进制生效。这是个常见的安全误解。
- 挂载了 `nosuid` 的分区上 SUID 完全失效。

#### 相关命令
`chown` · `chgrp` · `umask` · `setfacl` · `chattr` · `stat`

### chown — 修改属主与属组

**常用度**：★★★★★ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`--from`、`-h`、`--reference` 为 GNU 扩展

```bash
chown [选项] [属主][:属组] 文件...
```

| 选项 | 含义 |
|------|------|
| `-R` | 递归 |
| `-h` | 作用于符号链接本身（不跟随） |
| `--reference=文件` | 用参考文件的属主属组 |
| `--from=旧属主[:旧属组]` | 只在当前属主匹配时才改 ⭐ |
| `-v` / `-c` | 显示过程 / 只在改动时显示 |
| `-f` | 抑制错误信息 |
| `--dereference` | 跟随符号链接（默认） |

```bash
# 场景：改属主
$ sudo chown alice file.txt

# 场景：同时改属主和属组（推荐写法）
$ sudo chown alice:devteam file.txt

# 场景：只改属组（两种写法）
$ sudo chown :devteam file.txt
$ sudo chgrp devteam file.txt

# 场景：属组设成属主的主组（省略属组名）
$ sudo chown alice: file.txt

# 场景：递归改家目录（注意隐藏文件也要包含）
$ sudo chown -R alice:alice /home/alice
$ sudo chown -R alice:alice /home/alice/{*,.[!.]*}

# 场景：条件修改（只把 alice 的文件改成 bob）⭐
$ sudo chown --from=alice bob *.txt

# 场景：改符号链接自身而非目标
$ sudo chown -h alice symlink

# 场景：清空所有者（修复 uid 不存在的文件）
$ ls -l /mnt/data | head
-rw-r--r-- 1 1002 1002 ... file1
$ sudo chown -R root:root /mnt/data
```

#### 常见坑
- ⚠️ **`chown` 默认跟随符号链接**，改的是**目标**。如果链接指向 `/etc/shadow` 而你以为在改链接，后果严重。**不确定时加 `-h`**。
- ⚠️ **`-R` 不改变符号链接指向的内容**（配合默认的 `-h` 行为在不同版本上有差异，GNU 的 `-R` 默认不跟随递归中的链接）。要明确行为就写清楚。
- 普通用户**不能**把文件给别的用户（`chown` 需要 CAP_CHOWN，即 root）。唯一的例外是自己文件的属组（需属于该组）。
- **chown 的数字 UID**：可以直接 `chown 1000:1000 f`，用于 UID 没有对应用户名的情况。
- NFS 挂载上 `chown` 常报 `Operation not permitted`，因为 NFS 的 `root_squash` 把 root 映射成 `nobody`。
- chown 后 **SUID/SGID 位会被清除**（安全设计），重新部署二进制后要重新 `chmod u+s`。
- 递归 chown 大量文件很慢，且会**更新 ctime**（可能触发备份/同步工具的「文件变了」）。用 `--from` 减少无用改动。

#### 相关命令
`chmod` · `chgrp` · `getfacl` · `usermod`

### chgrp — 只修改属组

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`--reference`、`--from` 为 GNU

```bash
chgrp [选项] 组 文件...
```

| 选项 | 含义 |
|------|------|
| `-R` | 递归 |
| `-h` | 作用于符号链接本身 |
| `--reference=文件` | 用参考文件的组 |
| `--from=旧组` | 条件修改 |
| `-v` / `-c` | 显示过程 |

```bash
$ sudo chgrp devteam /srv/project
$ sudo chgrp -R www-data /var/www
$ sudo chgrp --reference=/etc/group /tmp/f
```

#### 常见坑
- 与 `chown :组` 等价，选哪个纯看习惯；**`chown 用户:组` 能一步做两件事**，所以批量操作用 `chown` 更省。
- 普通用户只能把文件改组为自己**所属的组**（POSIX）。GNU 在某些系统上还要求是文件属主。
- 不会清除 SUID（只有属主变化时 chown 才清 SUID）。

#### 相关命令
`chown` · `chmod` · `groups` · `newgrp`

### umask — 设置默认权限掩码

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`-S` 显示符号形式（bash 内建，非外部命令）

```bash
umask [-S] [掩码]
```

| 写法 | 含义 |
|------|------|
| `umask` | 显示当前掩码（八进制） |
| `umask -S` | 显示符号形式 |
| `umask 022` | 设为 022 |
| `umask u=rwx,g=rx,o=` | 符号形式设置 |
| `umask -p` | 输出可重新执行的 `umask` 命令（脚本用） |

```bash
# 场景：查看当前掩码
$ umask
0022
$ umask -S
u=rwx,g=rx,o=rx

# 场景：验证新文件的权限由 umask 决定
$ umask 022; touch /tmp/f1; mkdir /tmp/d1
$ stat -c '%A %n' /tmp/f1 /tmp/d1
-rw-r--r-- /tmp/f1        # 666 & ~022 = 644
drwxr-xr-x /tmp/d1        # 777 & ~022 = 755

# 场景：严格掩码（只自己可访问）
$ umask 077; touch /tmp/secret; stat -c '%A' /tmp/secret
-rw-------

# 场景：团队共享掩码
$ umask 027; touch /tmp/team; stat -c '%A' /tmp/team
-rw-r-----

# 场景：在脚本里临时收紧（用子 shell 隔离）⭐
$ (umask 077; echo secret > /tmp/key.txt)
$ stat -c '%A' /tmp/key.txt
-rw-------

# 场景：在脚本里保存与恢复
$ old=$(umask); umask 077
$ # ... 敏感操作 ...
$ umask "$old"
```

#### 输出解读
| umask | 新建文件 | 新建目录 |
|-------|----------|----------|
| `022` | `644` | `755` |
| `002` | `664` | `775` |
| `027` | `640` | `750` |
| `077` | `600` | `700` |

计算方式：`新建权限 = 基准权限 & ~umask`。文件基准 `666`（**永不含 x**），目录基准 `777`。

#### 常见坑
- ⚠️ **`umask` 只影响新建的文件，不改已存在的**。这是最常见的误解。
- ⚠️ **`umask` 是 shell 内建**，`umask` 在脚本里设置只影响该脚本及其子进程，不会影响父 shell——除非用 `. script.sh`（source）。
- **文件基准是 666**，所以无论 `umask` 多少，新建的普通文件都不会有执行位。要可执行必须显式 `chmod +x`。
- `umask` 不能给文件**增加**权限，只能收紧。
- 系统级默认值在 `/etc/profile`、`/etc/login.defs`（`UMASK`），用户级在 `~/.bashrc`。用 PAM 的系统还会读 `/etc/pam.d/*`。
- 图形环境下启动的进程（从桌面启动的应用）可能不经过 shell，`umask` 来自 `pam_umask` 或 `systemd` 的 `UMask=` 设置，与终端里的 `umask` 不同。
- **`umask 000` 看似「放权」实际危险**，它让所有新建文件对所有人可读写。调试临时用可以，但别留在配置里。

#### 相关命令
`chmod` · `mkdir -m` · `install -m` · `pam_umask`

### setfacl — 设置访问控制列表

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：非 POSIX，`acl` 包提供

```bash
setfacl [选项] 规则 文件...
```

| 选项 | 含义 |
|------|------|
| `-m 规则` | 修改/添加 ACL 条目 |
| `-x 规则` | 删除指定条目 |
| `-b` | 删除所有 ACL（保留基础权限） |
| `-k` | 删除默认 ACL |
| `-R` | 递归 |
| `-d` | 作用于**默认 ACL**（新文件会继承） ⭐ |
| `-n` | 不重新计算 mask |
| `-L` | 跟随符号链接 |
| `-P` | 不跟随符号链接 |
| `--set=规则` / `-M 文件` / `-X 文件` | 精确设置 / 从文件读 |
| `--restore=文件` | 从 `getfacl` 备份恢复 ⭐ |
| `--test` | 只测试不修改 |

**规则格式**：`类型:主体:权限`

| 类型 | 含义 |
|------|------|
| `u:` / `user:` | 用户（省略主体是文件属主） |
| `g:` / `group:` | 组 |
| `o:` / `other:` | 其他人 |
| `m:` / `mask:` | 有效权限掩码 ⭐ |

```bash
# 场景：给单个用户读权限
$ sudo setfacl -m u:bob:r /var/log/app.log
$ getfacl /var/log/app.log
# file: var/log/app.log
# owner: root
# group: root
user::rw-
user:bob:r--
group::r--
mask::r--
other::r--

# 场景：给用户读写执行（目录）
$ sudo setfacl -m u:bob:rwx /srv/shared

# 场景：给组加权限
$ sudo setfacl -m g:audit:rx /srv/shared

# 场景：递归 + 默认 ACL（新文件自动继承）⭐
$ sudo setfacl -R -m u:bob:rx /srv/shared
$ sudo setfacl -R -d -m u:bob:rx /srv/shared
# 之后在 /srv/shared 里新建的文件也带 bob 的条目

# 场景：删除某个条目
$ sudo setfacl -x u:bob /srv/shared

# 场景：清空所有 ACL
$ sudo setfacl -b /srv/shared

# 场景：备份与恢复 ACL ⭐
$ getfacl -R /srv/shared > /tmp/acl.bak
$ sudo setfacl --restore=/tmp/acl.bak

# 场景：验证修改前先测
$ sudo setfacl --test -m u:bob:rx /srv/shared

# 场景：查看 mask 是否是瓶颈
$ sudo setfacl -m m::rx /srv/shared
```

#### 输出解读
`getfacl` 输出的关键行：

| 行 | 含义 |
|----|------|
| `user::rw-` | 属主权限（对应 `ls -l` 的第 2-4 位） |
| `user:bob:r--` | 命名用户条目 |
| `group::r--` | 属组权限（对应 `ls -l` 的第 5-7 位） |
| `mask::r--` | **所有命名条目与属组的有效权限上限** ⭐ |
| `other::r--` | 其他人权限 |

`ls -l` 中权限末尾的 `+` 表示「有扩展 ACL」。

#### 常见坑
- ⚠️ **`mask` 会覆盖命名条目的权限**。`setfacl -m u:bob:rwx f` 后若 `mask::r--`，bob 实际只有 `r`。这是 ACL 最容易踩的坑。用 `-n` 保留 mask 或显式设 `m::rwx`。
- ⚠️ 设置 ACL 会**改变 `ls -l` 里属组的显示**：属组那三位现在显示的是 `mask` 而非 `group::` 的原始值。
- 用 `cp`/`rsync` 复制会**丢失 ACL**。必须 `cp -a`（含 `--preserve=all`）或 `rsync -A`。
- `tar` 备份需要 `--acls` 选项才保留。
- 文件系统必须支持 ACL 且挂载时启用（ext4/xfs 默认启用；某些 NFS/CIFS 不支持）。
- 默认 ACL 是 `-d` 设置的，只对**目录**有意义，且不递归到已有文件。
- `chmod` 会重算 mask，可能改变命名条目的实际权限。改权限后要重新 `getfacl` 确认。

#### 相关命令
`getfacl` · `chmod` · `chown` · `setfattr`

### getfacl — 查看访问控制列表

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：非 POSIX

```bash
getfacl [选项] 文件...
```

| 选项 | 含义 |
|------|------|
| `-R` | 递归 |
| `-a` | 只显示文件 ACL（不含默认 ACL） |
| `-d` | 只显示默认 ACL |
| `-c` | 不显示注释头（便于脚本处理） |
| `-t` | 表格形式（每行一条，含文件名） ⭐ |
| `-p` | 不删除路径中的前导斜杠（保证 restore 正确） ⭐ |
| `-L` / `-P` | 跟随 / 不跟随符号链接 |
| `-n` | 显示数字 UID/GID |
| `-e` | 显示有效权限（考虑 mask） |

```bash
# 场景：查看
$ getfacl /srv/shared
# file: srv/shared
# owner: root
# group: root
user::rwx
user:bob:r-x
group::r-x
mask::r-x
other::---

# 场景：脚本友好（无注释头）
$ getfacl -c file

# 场景：每行一条，含文件名
$ getfacl -t file
user::rw-
group::r--
other::r--

# 场景：查看有效权限（mask 之后真正生效的）
$ getfacl -e file

# 场景：找目录里所有有 ACL 的文件 🔐
$ getfacl -R -c -t /srv/shared | awk -F: 'NF>2' | head

# 场景：备份（必须配 -R -p 才能正确 restore）⭐
$ getfacl -R -p /srv/shared > /tmp/acl.bak
$ sudo setfacl --restore=/tmp/acl.bak
```

#### 输出解读
若 `mask::` 有效值是 `r--` 而 `user:bob:rwx`，bob 实际只能读。用 `getfacl -e` 能看到真实的 `effective:` 权限。

#### 常见坑
- 备份 ACL **必须加 `-p`**，否则路径中的前导 `/` 被去掉，`--restore` 会在当前目录创建错误的路径。
- 只有 `ls -l` 末尾有 `+` 时才有扩展 ACL，但 `getfacl` 对任何文件都能输出（没有 ACL 时只有基础条目）。
- `-t` 输出的格式是 `user:bob:r--` 这种，含文件名时是 `user:bob:r--\tfilename`，awk 解析要用 Tab。
- ACL 信息存放在文件的扩展属性（`system.posix_acl_access`）里，用 `getfattr -d -m -` 也能看到二进制形式。

#### 相关命令
`setfacl` · `ls -l` · `getfattr`

### chattr — 修改文件属性

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有；支持度取决于文件系统

```bash
chattr [+-=属性] 文件...
```

常用属性：

| 属性 | 含义 | 影响 |
|------|------|------|
| `i` | immutable 不可变 | **无法修改、删除、改名、加链接**，root 也不行 ⭐ |
| `a` | append only 只能追加 | 只能 `>>`，不能覆盖或截断 ⭐ |
| `A` | 不更新 atime | 省 I/O |
| `c` | 自动压缩 | 需文件系统支持 |
| `d` | 不参与 dump | — |
| `e` | extent 格式 | ext4 自动设置，不可改 |
| `j` | 日志模式 | 需支持 |
| `s` | 安全删除（块清零） | 不可靠 |
| `u` | 可恢复删除 | 极少实现 |
| `S` | 同步写入 | 每次写都落盘，极慢 |
| `C` | 无 CoW（btrfs） | 跳过写时复制 |

| 选项 | 含义 |
|------|------|
| `-R` | 递归 |
| `-V` | 详细输出 |
| `-f` | 抑制错误 |
| `-v 版本` | 设置文件版本号 |

```bash
# 场景：保护关键文件不被改（含被 root 改）🔐
$ sudo chattr +i /etc/passwd /etc/shadow /etc/sudoers
$ echo hacked | sudo tee -a /etc/passwd
tee: /etc/passwd: Operation not permitted      # ⭐ 即使 root 也改不了
$ sudo chattr -i /etc/passwd                    # 需要先解锁才能改

# 场景：日志只能追加（防篡改）
$ sudo chattr +a /var/log/audit/audit.log
$ echo fake >> /var/log/audit/audit.log          # 允许
$ sudo truncate -s 0 /var/log/audit/audit.log
truncate: cannot open '/var/log/audit/audit.log' for writing: Operation not permitted

# 场景：🔐 应急响应中先锁定证据文件
$ sudo chattr +i /tmp/evidence/*.log /tmp/evidence/memory.dump

# 场景：查看某文件属性
$ sudo lsattr /etc/passwd
----i---------e------- /etc/passwd

# 场景：解除所有不可变文件（改配置前）
$ sudo chattr -i /etc/passwd /etc/shadow
```

#### 输出解读
`lsattr` 输出的 20 个字符位与上表对应，`e` 位在 ext4 上总是置位（正常）。

#### 常见坑
- ⚠️ **`+i` 后连 `rm -rf` 都删不掉**，且报错信息是 `Operation not permitted`（看起来像权限问题，实际是被属性锁定）。**删不掉文件时先 `lsattr`**。
- ⚠️ **`+i` 会阻塞包管理器**：`apt upgrade` 装新版本 openssh 时若 `/etc/ssh/sshd_config` 被 `+i`，升级会失败。加固文档常忽略这点。
- ⚠️ **重装系统/在新机器上复制 `fstab` 时不要带 `i` 属性**（用 `cp -a` 或 `tar` 会尝试保留，某些工具会失败）。
- `a` 属性下 `logrotate` 会失效（它要 rename/truncate）。
- **只在 ext2/3/4、xfs（部分）、btrfs 等支持**。tmpfs、NFS、FAT、overlayfs（容器层）上可能无效或报 `Operation not supported`。容器里 `chattr +i` 通常失败。
- 🔐 恶意软件会用 `chattr +i` 锁住自己的组件，排查时 `lsattr -R /` 很慢，优先检查 `/etc/`、`/usr/lib/systemd/system/`、`~/.config/autostart/`、`/var/spool/cron/`。
- `chattr` 需要 CAP_LINUX_IMMUTABLE（root）。

#### 相关命令
`lsattr` · `chmod` · `attr`/`getfattr` · `ls -l`

### lsattr — 查看文件属性

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
lsattr [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-R` | 递归 |
| `-d` | 显示目录自身而非其内容 |
| `-a` | 包括隐藏文件 |
| `-l` | 显示属性长名（更可读） ⭐ |
| `-p` | 显示项目/文件编号 |
| `-v` | 显示文件版本号 |
| `-V` | 程序版本（注意与 `-v` 不同） |

```bash
# 场景：查看单个文件属性
$ sudo lsattr /etc/passwd
--------------e------- /etc/passwd

# 场景：属性长名（更容易读）⭐
$ sudo lsattr -l /etc/passwd
/etc/passwd    Extents

# 场景：找被锁定的文件（常见位置优先）🔐
$ sudo lsattr -R /etc /usr/lib/systemd/system /var/spool/cron 2>/dev/null | grep -E '^....i'
----i---------e------- /etc/passwd

# 场景：看目录自身（不加 -d 会列目录内容）
$ sudo lsattr -d /etc

# 场景：全盘扫描不可变文件（慢，慎用）
$ sudo lsattr -R -l / 2>/dev/null | grep -i immutable
```

#### 输出解读
```
----i---------e------- /etc/passwd
│   │         │
│   │         └─ e = extent（ext4 正常标志）
│   └─ i = immutable 不可变
└─ 未设置的位显示 -
```

属性顺序（20 位）：`suSDiadAcBZXEjItTNCFe`（不同内核版本略有差异，用 `-l` 看长名最稳）。

#### 常见坑
- **不加 `-d` 时，参数是目录会列目录内容**，要看目录本身加 `-d`。
- `-v` 是「文件版本号」，`-V` 是「程序版本」，容易打错。
- 在 tmpfs、overlayfs（容器）、NFS 上通常只显示 `e` 位或直接报不支持。
- 普通用户也能 `lsattr`（只读），但需要有目录的读+执行权限。
- 属性是文件系统的特性，同一份数据在不同文件系统上可能显示不同。
- `lsattr -R /` 会非常慢（要遍历所有 inode）；用 `timeout` 限制或只扫关键目录。

#### 相关命令
`chattr` · `ls -l` · `getfattr`

### useradd — 创建用户

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：⚠️ **Linux 与 BSD 不兼容**：BSD 的 `useradd` 是交互式的

#### 语法
```bash
useradd [选项] 用户名
```

#### 高频选项
| 选项 | 含义 |
|------|------|
| `-m` | 创建家目录（**部分发行版默认不创建**！） ⭐ |
| `-M` | 不创建家目录 |
| `-d 路径` | 指定家目录 |
| `-s shell` | 登录 shell |
| `-G 组,...` | 附加组（逗号分隔，**无空格**） |
| `-g 组` | 主组 |
| `-u UID` | 指定 UID |
| `-c 注释` | GECOS 字段（全名等） |
| `-e 日期` | 账号过期日（`YYYY-MM-DD`） |
| `-f N` | 密码过期后多少天禁用账号（`-1` 表示不禁用） |
| `-p 哈希` | 直接给密码哈希（**不是明文**） ⚠️ |
| `-r` | 创建系统用户（UID < 1000，不建家目录） |
| `-k 目录` | 家目录骨架（默认 `/etc/skel`） |
| `-D` | 显示/设置默认值 |
| `-o` | 允许 UID 重复（⚠️ 危险） |

```bash
# 场景：标准用户（家目录 + bash）
$ sudo useradd -m -s /bin/bash -c 'Alice Wang' alice

# 场景：带附加组
$ sudo useradd -m -s /bin/bash -G sudo,docker,devteam alice

# 场景：服务账号（无家目录、无登录 shell）
$ sudo useradd -r -s /usr/sbin/nologin -d /nonexistent myservice

# 场景：指定 UID（与外部系统对齐，如 NFS）
$ sudo useradd -m -u 1500 -s /bin/bash alice

# 场景：带过期时间
$ sudo useradd -m -e 2026-12-31 -f 30 tempuser

# 场景：创建后设密码
$ sudo passwd alice
$ echo 'alice:Str0ng!Pass' | sudo chpasswd

# 场景：查看系统默认设置
$ useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes

# 场景：改默认值（写入 /etc/default/useradd）
$ sudo useradd -D -s /bin/bash -e 2027-01-01
```

#### 输出解读
创建后检查：
```bash
$ getent passwd alice
alice:x:1001:1001:Alice Wang:/home/alice:/bin/bash
$ sudo getent shadow alice
alice:!:20345:0:99999:7:::
#      ↑ ! 表示密码未设置（账号被锁），需 passwd 解锁
```

#### 常见坑
- ⚠️ **Debian/Ubuntu 上 `useradd` 默认不创建家目录，也不设置 shell**，必须显式 `-m -s`。`adduser` 是友好的 Perl 包装脚本，会自动做这些。
- ⚠️ **`-p` 需要密码哈希，不是明文**。`useradd -p mypassword` 会把 `mypassword` 当哈希写进去，登录永远失败。生成哈希：`openssl passwd -6 'mypassword'`。
- `-G` 多个组用**逗号且无空格**：`-G a,b` 正确，`-G "a, b"` 会失败或创建奇怪的组名。
- `useradd` 不加 `-m` 时家目录不存在，用户登录后会看到 `Could not chdir to home directory`。
- 新账号默认是**锁定状态**（shadow 里是 `!`），必须 `passwd` 或 `chpasswd` 才能登录。
- `-o`（允许 UID 重复）会让文件属主判断混乱，几乎不该用。
- `-r` 创建的账号在 `/etc/login.defs` 的 `SYS_UID_MIN/MAX` 范围内，与普通账号区分。
- 用户名规则：小写字母、数字、下划线、短横线，**不能以数字或 `-` 开头**（`useradd` 会拒绝，但手工写 `/etc/passwd` 能绕过——这是后门手法之一 🔐）。

#### 相关命令
`adduser` · `usermod` · `userdel` · `passwd` · `chage` · `groupadd`

### usermod — 修改用户

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
usermod [选项] 用户名
```

| 选项 | 含义 |
|------|------|
| `-aG 组,...` | **追加**附加组（`-a` 不能省！） ⚠️ |
| `-G 组,...` | **覆盖**附加组（不加 `-a`） |
| `-g 组` | 改主组 |
| `-d 路径` | 改家目录（不加 `-m` 只改字段，不移动文件） |
| `-m` | 配合 `-d` 移动家目录内容 ⭐ |
| `-s shell` | 改登录 shell |
| `-l 新名` | 改名（不改家目录名） |
| `-L` | 锁定账号（shadow 里加 `!`） |
| `-U` | 解锁 |
| `-u UID` | 改 UID |
| `-e 日期` | 账号过期日（空字符串取消） |
| `-f N` | 密码失效后的宽限天数 |
| `-c 注释` | 改 GECOS |
| `-p 哈希` | 直接设哈希（少用） |
| `-r` | 配合 `-d` 时把家目录内容移到新位置（部分版本） |

```bash
# 场景：加一个附加组（最常见的用法）⭐
$ sudo usermod -aG docker alice
# ⚠️ 漏掉 -a 的后果：
$ sudo usermod -G docker alice    # ❌ 把 alice 从其他所有附加组里踢出去了
$ groups alice
alice : alice docker              # sudo 组没了！

# 场景：改 shell
$ sudo usermod -s /usr/sbin/nologin alice
$ sudo usermod -s /bin/bash alice

# 场景：移动家目录
$ sudo usermod -d /data/home/alice -m alice

# 场景：锁定/解锁账号
$ sudo usermod -L alice
$ sudo usermod -U alice

# 场景：改名（注意家目录不会自动改）
$ sudo usermod -l alicia -d /home/alicia -m alice

# 场景：改 UID（要同时修文件属主）
$ sudo usermod -u 2000 alice
$ sudo find / -xdev -user 1001 -exec chown -h 2000 {} +

# 场景：设置账号过期
$ sudo usermod -e 2026-12-31 alice
$ sudo usermod -e '' alice        # 取消过期

# 场景：连锁定加禁用 shell（彻底断掉登录）
$ sudo usermod -L -s /usr/sbin/nologin alice
```

#### 常见坑
- ⚠️ **`usermod -G` 不加 `-a` 会清空其他附加组**。这是最高频的运维事故，可能直接把用户的 sudo 权限删掉，甚至锁死自己。
- ⚠️ **`-L` 只加 `!` 前缀，不禁止其他登录方式**（如 SSH key 认证仍可能可用）。彻底禁用要同时改 shell 为 `nologin`。
- **改 UID/GID 后必须手工修文件属主**：`usermod` 不会自动改。用 `find / -xdev -user 旧UID -exec chown -h 新UID {} +`。
- `-l` 改名后，**已有进程仍持有旧用户名**（内核里存的是 UID，用户名的映射在每次查表时解析），日志里可能出现混淆。
- `-d` 不加 `-m` 只改 `/etc/passwd` 的字段，家目录还在老地方，用户登录会找不到家目录或创建新的空目录。
- 用户已登录时改 UID/GID 会导致部分文件仍属于旧 UID，出现「僵尸属主」。
- 修改当前登录用户自己的组，需要重新登录才生效（进程的组凭证在登录时固定）。

#### 相关命令
`useradd` · `userdel` · `gpasswd` · `chage` · `usermod -aG`

### userdel — 删除用户

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
userdel [选项] 用户名
```

| 选项 | 含义 |
|------|------|
| `-r` | 同时删除家目录和邮件池 ⭐ |
| `-f` | 强制（即使用户已登录） ⚠️ |
| `-Z` | 删除 SELinux 用户映射 |

```bash
# 场景：删除用户并清理家目录 ⭐
$ sudo userdel -r alice

# 场景：只删账号保留数据（有风险的，见下）
$ sudo userdel alice

# 场景：强制删除（用户在线时）
$ sudo pkill -u alice              # 先终止其进程
$ sudo userdel -r -f alice

# 场景：删除后检查残留 🔐
$ find / -xdev -nouser -o -nogroup 2>/dev/null | head
$ grep '^alice:' /etc/passwd /etc/shadow /etc/group
```

#### ⚠️ 重要风险：UID 复用

```
1. 删除 alice (UID 1001)，不加 -r
2. 家目录 /home/alice 和文件属主仍是 1001
3. 创建 bob 时系统把 1001 分给 bob
4. bob 就能读写 alice 遗留的所有文件
```

这是**真实的权限提升路径**。防御方式：
- 删除时一律 `-r`
- 或删除后用 `find / -xdev -nouser -ls` 找出并处理孤立文件
- 或设置 `UID_MIN` 高于历史最高 UID，并保留 `/etc/passwd` 历史记录

```bash
# 找出所有属主已被删除的文件（🔐 应急与清理必做）
$ find / -xdev -nouser -o -xdev -nogroup 2>/dev/null | head -20
```

#### 常见坑
- ⚠️ **`userdel` 不带 `-r` 会留下家目录、邮件池（`/var/spool/mail/`）和孤立文件**。
- ⚠️ **`-f` 会直接操作而不检查用户是否登录**，可能打断正在运行的服务。
- 用户还有**正在运行的进程**时，`userdel` 通常能成功但进程继续运行（文件属主变成数字 UID）。要彻底清理先 `pkill -u`。
- 删除用户**不会删除其 cron 任务、at 任务、systemd user 服务**，要手工清理：
  ```bash
  $ sudo crontab -r -u alice
  $ sudo rm -f /var/spool/cron/atjobs/a*    # 按需
  $ sudo loginctl disable-linger alice
  $ sudo rm -rf /var/lib/systemd/linger/alice
  ```
- 删除系统用户（`-r` 创建的服务账号）时**不要加 `-r`**，否则可能删掉服务数据目录。先确认该账号的家目录不是数据目录。
- 用户是某个组的唯一成员时，组会残留（要 `groupdel`）。

#### 相关命令
`useradd` · `usermod` · `groupdel` · `find -nouser`

### groupadd — 创建组

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
groupadd [选项] 组名
```

| 选项 | 含义 |
|------|------|
| `-g GID` | 指定 GID |
| `-r` | 创建系统组（GID < 1000） |
| `-f` | 组已存在时成功退出（幂等，脚本友好） ⭐ |
| `-o` | 允许 GID 重复 |
| `-p 密码` | 设组密码（少用） |
| `-R 根目录` | chroot 到该目录操作 |

```bash
# 场景：创建普通组
$ sudo groupadd devteam

# 场景：指定 GID
$ sudo groupadd -g 2000 devteam

# 场景：创建系统组
$ sudo groupadd -r docker

# 场景：幂等创建（脚本里常用）⭐
$ sudo groupadd -f devteam

# 场景：查看
$ getent group devteam
devteam:x:2000:alice,bob
```

#### 常见坑
- 组名规则同用户名（小写、数字、下划线、短横线）。
- GID 与已有组重复会报 `GID '2000' already exists`，除非 `-o`（不推荐）。
- 组的**密码字段**（`/etc/group` 第二列）通常是 `x`，实际密码在 `/etc/gshadow`。几乎没有场景需要组密码。
- 用户加入组的两种方式：`usermod -aG`（附加组）或 `gpasswd -a`。
- `-R` 的 chroot 用法在维护外部系统时有用（从 Live USB 修系统）。

#### 相关命令
`groupmod` · `groupdel` · `gpasswd` · `usermod -aG`

### groupmod — 修改组

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
groupmod [选项] 组名
```

| 选项 | 含义 |
|------|------|
| `-n 新名` | 改组名 |
| `-g GID` | 改 GID |
| `-o` | 允许 GID 重复 |

```bash
# 场景：改组名（组成员关系保持）
$ sudo groupmod -n devops devteam

# 场景：改 GID（必须同时修文件属主）⭐
$ sudo groupmod -g 3000 devteam
$ sudo find / -xdev -gid 2000 -exec chgrp -h 3000 {} +

# 场景：检查结果
$ getent group devteam
$ ls -l /srv/team
```

#### 常见坑
- ⚠️ **改 GID 不会修改任何文件的属组**，必须手工 `find -gid` 修。否则会出现「组名显示为空」的文件（`ls -l` 里显示数字 GID）。
- 改组名不影响成员关系，但**正在运行的进程的组名映射会在下次查询时改变**（日志可能出现混乱）。
- 组名改名后，`/etc/sudoers` 里按组名的规则（`%devteam`）**会立即失效**，记得同步改。
- 不能改成已存在的组名。

#### 相关命令
`groupadd` · `groupdel` · `chgrp` · `find -gid`

### groupdel — 删除组

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
groupdel [选项] 组名
```

| 选项 | 含义 |
|------|------|
| `-f` | 强制删除（即使有用户以它为主组） |

```bash
# 场景：删除组
$ sudo groupdel devteam

# 场景：先移除所有成员
$ sudo gpasswd -d alice devteam

$ sudo groupdel devteam

# 场景：删除后检查孤立的组属主文件
$ find / -xdev -nogroup 2>/dev/null | head
```

#### 常见坑

### gpasswd — 管理组成员

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
gpasswd [选项] 组
```

| 选项 | 含义 |
|------|------|
| `-a 用户` | 把用户加入组（append） ⭐ |
| `-d 用户` | 把用户从组移出 |
| `-M 用户列表` | **设置**整个成员列表（逗号分隔，覆盖） |
| `-A 管理员列表` | 设置组管理员 |
| `-r` | 删除组密码 |
| `-R` | 限制访问（开启组密码机制） |

```bash
# 场景：加入组 ⭐
$ sudo gpasswd -a alice docker

# 场景：移出组
$ sudo gpasswd -d alice docker

# 场景：一次性设置成员（覆盖）
$ sudo gpasswd -M alice,bob,carol devteam

# 场景：与 usermod 的对比
$ sudo gpasswd -a alice docker       # 追加，不会误删其他组 ✅
$ sudo usermod -aG docker alice      # 等价，但漏 -a 就出事 ⚠️
```

#### 输出解读
- `Adding user alice to group docker`
- `Removing user alice from group docker`

#### 常见坑
- ⚠️ **`-M` 是覆盖而非追加**，会把没列出的成员全部移出。
- 用 `gpasswd -a` 是**追加语义**，比 `usermod -G` 安全得多，**推荐用 `gpasswd` 避免漏 `-a` 的事故**。
- 加入组后**已登录的会话不会立即生效**，需要重新登录（或用 `newgrp`）。
- 组管理员（`-A`）只能管理自己管理的组的成员，是普通用户提权的一种合法手段（如果给了管理员权限）。

#### 相关命令
`usermod -aG` · `groupadd` · `newgrp` · `groups`

### passwd — 修改用户密码

**常用度**：★★★★★ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：无（但 `-S`、`-l`、`-u`、`-e` 是 Linux 扩展）

```bash
passwd [选项] [用户名]
passwd 选项            # 修改当前密码策略
```

| 选项 | 含义 | 需要 root |
|------|------|-----------|
| （无） | 修改自己的密码 | ❌ |
| `用户名` | 修改指定用户密码 | ✅ |
| `-l` | 锁定（shadow 加 `!` 前缀） | ✅ |
| `-u` | 解锁 | ✅ |
| `-d` | 删除密码（空密码，⚠️ 极危险） | ✅ |
| `-e` | 强制下次登录改密码 ⭐ | ✅ |
| `-S` | 显示密码状态 ⭐ | ✅ |
| `-n N` | 最短使用天数 | ✅ |
| `-x N` | 最长使用天数 | ✅ |
| `-w N` | 过期前警告天数 | ✅ |
| `-i N` | 过期后宽限天数 | ✅ |
| `-k` | 只在密码过期时更新 | ❌ |

```bash
# 场景：改自己的密码（交互，不回显）
$ passwd
Current password:
New password:
Retype new password:
passwd: password updated successfully

# 场景：root 改别人密码（不需要旧密码）
$ sudo passwd alice

# 场景：查看密码状态 ⭐
$ sudo passwd -S alice
alice P 2026-09-15 0 99999 7 -1
#     │ │         │ │     │ │
#     │ │         │ │     │ └─ inactive 天数
#     │ │         │ │     └─ warn 天数
#     │ │         │ └─ max 天数
#     │ │         └─ min 天数
#     │ └─ 最后修改日期
#     └─ 状态：P=有密码 L=锁定 NP=无密码

# 场景：锁账号（临时停用）
$ sudo passwd -l alice
$ sudo passwd -S alice
alice L 2026-09-15 0 99999 7 -1

# 场景：强制下次登录改密码
$ sudo passwd -e alice
$ sudo passwd -S alice
alice P 1970-01-01 0 99999 7 -1      # 日期归零 = 已过期

# 场景：设置密码有效期策略
$ sudo passwd -n 7 -x 90 -w 14 -i 7 alice

# 场景：🔐 检查所有账号的密码状态
$ for u in $(cut -d: -f1 /etc/passwd); do
>   s=$(sudo passwd -S "$u" 2>/dev/null)
>   case "$s" in *" NP "*) echo "⚠️ 无密码: $u";; esac
> done
```

#### 输出解读
`passwd -S` 的状态码：

| 码 | 含义 |
|----|------|
| `P` / `PS` | 已设置密码 |
| `L` / `LK` | 已锁定 |
| `NP` | 无密码（**可以空密码登录！**） 🔐 |

#### 常见坑
- ⚠️ **`passwd -d` 删除密码 = 无密码即可登录**。如果 `/etc/ssh/sshd_config` 里 `PermitEmptyPasswords yes`，直接就是一个远程后门（默认是 `no`，但很多加固不完全的设备会开）。
- ⚠️ **`passwd -l` 只加 `!` 前缀，不阻止 SSH 密钥认证**。要彻底禁用登录必须同时改 shell 为 `nologin` 或 `usermod -L` + 修改 `sshd_config`。
- **密码强度由 PAM（`pam_pwquality`/`pam_cracklib`）强制**，配置在 `/etc/security/pwquality.conf`。`passwd` 报 `BAD PASSWORD` 是 PAM 的策略，不是 `passwd` 本身。
- **密码哈希算法**由 `/etc/login.defs` 的 `ENCRYPT_METHOD` 和 PAM 决定。现代默认是 SHA-512（`$6$`）或 yescrypt（`$y$`）。
- **`passwd` 在非交互环境会失败**（没有 TTY 无法输入）。脚本里用 `chpasswd`。
- 修改别人的密码需要 root；`passwd 用户名` 作为普通用户会报 `You may not change the password for ...`。
- 🔐 shadow 里的哈希可以用 `john` / `hashcat` 离线破解。**权限必须是 400 或 640 root:shadow**。

#### 相关命令
`chpasswd` · `chage` · `usermod -L` · `openssl passwd` · `mkpasswd`

### chpasswd — 批量修改密码

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
chpasswd [选项]
# 从 stdin 读入 用户名:密码 格式的行
```

| 选项 | 含义 |
|------|------|
| `-e` | 输入已是**加密后**的哈希 ⭐ |
| `-c 方法` | 加密方法（`SHA512` `YESCRYPT` 等） |
| `-m` | 用 MD5（❌ 已不安全） |
| `-R 根目录` | chroot 操作 |

```bash
# 场景：单条非交互改密码 ⭐
$ echo 'alice:NewP@ss123' | sudo chpasswd

# 场景：批量改（从文件）
$ cat /tmp/users.txt
alice:Pass1
bob:Pass2
$ sudo chpasswd < /tmp/users.txt
$ rm -f /tmp/users.txt        # ⚠️ 立即删除明文密码文件

# 场景：支持冒号以外的分隔符
$ printf 'alice:Pass1\n' | sudo chpasswd

# 场景：用已有的哈希（避免明文传输）
$ hash=$(openssl passwd -6 'MyPass')
$ echo "alice:$hash" | sudo chpasswd -e

# 场景：脚本里随机生成密码
$ pw=$(openssl rand -base64 12)
$ echo "alice:$pw" | sudo chpasswd
$ echo "alice 的密码：$pw"

# 场景：chroot 环境下改（救援模式）
$ sudo chpasswd -R /mnt/sysroot < /tmp/users.txt
```

#### 常见坑
- ⚠️ **明文密码会进入 shell 历史、进程列表、日志**。用 heredoc 或管道，避免 `chpasswd <<< "..."`（bash 的 here-string 在某些情况下会写临时文件）。
- ⚠️ **`/tmp/users.txt` 里的明文密码必须立即删除**，且注意 umask（`umask 077` 后创建）。
- **密码中的冒号会被当分隔符**（`alice:pa:ss` 会被解析成密码 `pa` 和多出的内容）。密码含冒号要换用 `chpasswd` 不支持的方式，或先改密码。
- 不支持指定用户列表以外的字段（第三列会报错）。
- 密码仍需满足 PAM 强度策略，不过 `chpasswd` **默认不检查**（`-c` 相关配置除外）。这意味着可以用它设置弱密码——也是攻击者常用的持久化手段。 🔐
- 用 `-e` 时输入必须是完整哈希（含 `$6$...`），不能是明文。

#### 相关命令
`passwd` · `chage` · `openssl passwd` · `mkpasswd`

### chage — 密码有效期策略

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux 特有

```bash
chage [选项] 用户名
```

| 选项 | 含义 |
|------|------|
| `-l` | 列出当前策略 ⭐ |
| `-d 日期` | 最后修改日期（`0` = 强制下次登录改） |
| `-m N` | 最短使用天数 |
| `-M N` | 最长使用天数 |
| `-W N` | 过期前警告天数 |
| `-I N` | 过期后宽限天数 |
| `-E 日期` | 账号过期日（`-1` 或空 = 永不过期） |
| `-i` | 交互模式 |
| `-R 根目录` | chroot |
| `-R` | 见上 |

```bash
# 场景：查看账号策略 ⭐
$ sudo chage -l alice
Last password change                                    : Sep 15, 2026
Password expires                                        : Dec 14, 2026
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 90
Number of days of warning before password expires       : 7

# 场景：设置密码 90 天过期
$ sudo chage -M 90 -W 14 -I 7 alice

# 场景：强制下次登录改密码
$ sudo chage -d 0 alice

# 场景：账号在特定日期过期（临时账号）
$ sudo chage -E 2026-12-31 tempuser

# 场景：取消账号过期
$ sudo chage -E -1 alice

# 场景：🔐 找出永不过期的账号
$ for u in $(cut -d: -f1 /etc/passwd); do
>   exp=$(sudo chage -l "$u" 2>/dev/null | awk -F: '/Account expires/{gsub(/^ +/,"",$2);print $2}')
>   [ "$exp" = "never" ] && echo "永不过期: $u"
> done

# 场景：批量设置策略
$ for u in dev1 dev2 dev3; do sudo chage -M 90 -W 14 "$u"; done
```

#### 输出解读
| 字段 | 来源 |
|------|------|
| Last password change | `/etc/shadow` 第 3 字段（自 1970-01-01 起的天数） |
| Password expires | 第 3 + 第 5 字段（max） |
| Password inactive | 第 7 字段（inactive） |
| Account expires | 第 8 字段（expire） |
| Minimum / Maximum | 第 4 / 5 字段 |
| Warning | 第 6 字段 |

#### 常见坑
- ⚠️ **`chage -d 0` 是「强制改密码」的标准手法**，但也常被攻击者用来判断/重置。值 `0` 表示 1970-01-01，即「已过期」。
- ⚠️ **账号过期（`-E`）与密码过期（`-M`）是两件不同的事**：
  - 密码过期 → 用户还能登录，但被强制改密码
  - 账号过期 → 完全无法登录
- **`chage` 只改 `/etc/shadow` 的策略字段，不检查现有密码强度**。
- 设 `-M 0` 表示「密码永不过期」，不是「立即过期」（这违反直觉）。
- 日期格式是 `YYYY-MM-DD`，也接受 `-1`（永不过期）。
- 🔐 审计发现的常见问题：`Max days` 是 `99999`（永不过期）且 `Account expires` 是 `never`，不符合等保/CIS 要求。

#### 相关命令
`passwd` · `usermod -e` · `chpasswd` · `login.defs`

### su — 切换用户

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`-` 与 `-l` 等价；`-c` 是 POSIX

```bash
su [选项] [-] [用户名]
```

| 选项 | 含义 |
|------|------|
| `-` / `-l` / `--login` | **模拟完整登录**：加载目标用户环境、切到其家目录 ⭐ |
| `-c '命令'` | 执行单条命令后退出 |
| `-s shell` | 指定 shell |
| `-m` / `-p` | 保留当前环境（保留 `$HOME` `$USER` 等） |
| `-g 组` | 指定主组 |
| `-G 组` | 指定附加组 |
| `-w 变量=值` | 设置环境变量（GNU） |
| `--session-command` | 不创建新会话 |

```bash
# 场景：切到 root（完整登录环境）⭐
$ su -
# 提示符变成 root，$HOME=/root，PATH 含 /usr/sbin

# 场景：切到其他用户
$ su - alice
$ su alice          # 只换身份，环境不变

# 场景：验证环境差异
$ su alice -c 'echo "HOME=$HOME PATH=$PATH"'
HOME=/home/alice PATH=/usr/local/bin:/usr/bin:/bin
$ su - alice -c 'echo "HOME=$HOME"'
HOME=/home/alice
# 对比 PWD 与 PATH 的差异

# 场景：以某用户执行单条命令
$ su - postgres -c 'psql -c "\l"'
$ su -c 'systemctl restart nginx' root

# 场景：保留当前环境
$ export FOO=bar
$ su -m alice -c 'echo $FOO'
bar

# 场景：指定 shell
$ su -s /bin/sh nobody -c 'id'
```

#### 输出解读
不加 `-` 时 `$HOME`、`$PATH`、`$USER`、`$LOGNAME`、`$SHELL` 等**大多保持原用户的值**，而 `$USER` 反映的是**有效**用户（可能不一致）。

#### 常见坑
- ⚠️ **`su alice` 不带 `-` 是最常见的错误**：环境变量、PATH 都是原用户的，导致「我的脚本手动能跑，su 过去就 command not found」。
- ⚠️ **`su` 需要目标用户的密码**（除了 root → 任何用户）。
- ⚠️ **`su` 会把密码和会话记录在 `/var/log/secure`（RHEL）或 `/var/log/auth.log`（Debian）**，但**不记录执行了什么命令**（除非配了 `pam_tty_audit`）。
- `su -c` 的命令会经过 shell 解析，有注入风险；参数里带引号的嵌套要小心。
- **`su` 不会重置 `$DISPLAY` 和 `XAUTHORITY`**，所以图形程序可能报 `cannot open display`。
- **`su` 的历史遗留问题**：默认允许所有用户 `su` 到任何用户（只要知道密码）。要限制，用 PAM 的 `pam_wheel`（只有 `wheel`/`sudo` 组成员能 `su`）或设 `su` 的二进制权限为 `4750 root:wheel`。
- 🔐 **`su` 的 SUID 位 + `pam_rootok`** 使 root 无需密码。普通用户若有 SUID 的 `su` 且知道 root 密码即可提权（合法行为）。
- 频繁 `su -c` 会不断创建登录会话，`journalctl` / `last` 会有大量记录。

#### 相关命令
`sudo` · `runuser` · `login` · `machinectl shell`

### sudo — 以其他身份执行命令

**常用度**：★★★★★ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：非 POSIX

#### 语法
```bash
sudo [选项] 命令
sudo -u 用户 命令
```

#### 高频选项
| 选项 | 含义 |
|------|------|
| `-u 用户` | 以指定用户身份（默认 root） ⭐ |
| `-g 组` | 以指定组身份 |
| `-i` | 启动目标用户的**登录 shell**（含环境） ⭐ |
| `-s` | 启动目标用户的 shell（**保留当前环境**） |
| `-l` | 列出当前用户的 sudo 权限 🔐 ⭐ |
| `-l -U 用户` | 查看指定用户的权限（需权限） |
| `-k` | 立即让缓存的凭证失效 |
| `-K` | 清除凭证并重启计时 |
| `-n` | 非交互，若无免密则直接失败（脚本用） ⭐ |
| `-S` | 从 stdin 读密码（脚本用，⚠️ 不安全） |
| `-b` | 后台执行 |
| `-e 文件` | 用 sudoedit 编辑文件（安全编辑受保护文件） |
| `-v` | 校验并刷新凭证时间戳 |
| `-E` | 保留当前环境变量 |
| `-H` | 把 `$HOME` 设为目标用户的家目录 |

```bash
# 场景：以 root 执行
$ sudo systemctl restart nginx

# 场景：以其他服务用户执行
$ sudo -u postgres psql
$ sudo -u www-data php /var/www/app/artisan migrate

# 场景：进 root 的登录 shell
$ sudo -i
$ sudo -i -u postgres     # 以 postgres 开登录 shell

# 场景：root shell 但保留当前环境
$ sudo -s

# 场景：🔐 提权枚举第一步——看自己能干什么 ⭐
$ sudo -l
Matching Defaults entries for alice on web01:
    env_reset, mail_badpass,
    secure_path=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

User alice may run the following commands on web01:
    (ALL : ALL) ALL
    (root) NOPASSWD: /usr/bin/systemctl restart nginx
    (root) /usr/bin/find /var/log -name "*.log" -exec cat {} \;

# 上面第 2 条 → GTFOBins 查 systemctl → 可提权
# 第 3 条 → find -exec 可执行任意命令

# 场景：脚本里判断是否有免密 sudo
$ sudo -n true 2>/dev/null && echo "有免密 sudo" || echo "需要密码"

# 场景：安全编辑受保护文件（自动用临时文件 + 校验）
$ sudo -e /etc/nginx/nginx.conf

# 场景：保留环境（用于脚本需要特定变量时）
$ sudo -E /usr/local/bin/deploy.sh

# 场景：以 root 后台运行
$ sudo -b /usr/local/bin/longjob
```

#### 输出解读
`sudo -l` 输出格式：

```
(可切换用户:可切换组) 命令或 NOPASSWD: 命令
```

| 模式 | 风险 |
|------|------|
| `(ALL : ALL) ALL` | 完全 root 权限 |
| `NOPASSWD: /usr/bin/X` | 无密码执行 X → 查 GTFOBins |
| `/usr/bin/cat /etc/*` | 通配符可能被绕过（`/etc/../root/...`） |
| `(root) /path/to/script.sh` | 若脚本可被用户写入 → 直接提权 ⚠️ |
| `SETENV: /usr/bin/X` | 可传环境变量 → 可能 `LD_PRELOAD` 提权 ⚠️ |
| `!/usr/bin/X` | 显式拒绝 |

#### 常见坑
- ⚠️ **`sudo cmd > /etc/file` 不生效**：重定向由你的 shell 执行。用 `cmd | sudo tee /etc/file` 或 `sudo sh -c 'cmd > /etc/file'`。
- ⚠️ **改 `/etc/sudoers` 必须用 `visudo`**。语法错误会让所有 sudo 失效，可能永久锁死系统外。
- ⚠️ **`sudo -S` 从 stdin 读密码会留在 shell 历史里**，且可能被 `ps` 看到。
- **`-i` 与 `-s` 的环境差异**很重要：`-s` 继承当前 `$PATH` 和环境，可能被劫持；`-i` 用目标用户的干净环境，更安全。
- **`secure_path`**：sudo 默认用固定的 PATH（`/etc/sudoers` 里的 `secure_path`），这正是为了防御 PATH 劫持。破坏它（`-E` 或 `env_reset` 关闭）是安全风险。
- **sudo 的凭证默认缓存 5 分钟**（`timestamp_timeout`），之后需要重新输密码。在共享终端上要 `sudo -k` 结束。
- 🔐 **`sudo` 是提权枚举的核心**：`sudo -l` → 对每个可执行文件查 https://gtfobins.github.io/ → 大量常见命令（`find`、`vim`、`less`、`awk`、`tar`、`systemctl`、`python`、`cp`、`env`）在有 sudo 权限时都能逃逸成 root。
- 🔐 **sudo 会记录到 `/var/log/auth.log`（Debian）或 `/var/log/secure`（RHEL）**，以及 journald（`journalctl -t sudo`）。取证时必看。
- **`sudo` 的日志可能有延迟**（`syslog` 缓冲），应急时直接看 journal。

#### 相关命令
`su` · `visudo` · `doas` · `pkexec` · `run0`

### visudo — 安全编辑 sudoers

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：非 POSIX

```bash
visudo [选项]
```

| 选项 | 含义 |
|------|------|
| （无） | 编辑 `/etc/sudoers` |
| `-f 文件` | 编辑指定文件 |
| `-c` | 只做语法检查（不编辑） ⭐ |
| `-s` | 严格模式（更严的语法检查） |
| `-q` | 安静 |
| `-x 文件` | 导出当前 sudoers 到文件 |

```bash
# 场景：编辑 sudoers
$ sudo visudo
# 打开 $EDITOR，保存时自动检查语法；有错会提示
>>> sudoers file: syntax error, line 12 <<<
What now? (e=edit, x=exit without saving, Q=quit and save)
#          ⭐ 选 x 退出不保存，避免锁死

# 场景：只检查语法
$ sudo visudo -c
/etc/sudoers: parsed OK
/etc/sudoers.d/90-cloud-init-users: parsed OK
parsed OK - 共 2 个文件

# 场景：把自定义规则放进 sudoers.d（推荐，避免改主文件）
$ sudo visudo -f /etc/sudoers.d/90-deploy
# 写入：
# %deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart myapp
$ sudo chmod 440 /etc/sudoers.d/90-deploy

# 场景：检查 sudoers.d 里的文件权限是否合规
$ sudo ls -l /etc/sudoers.d/
-r--r----- 1 root root 123 ... 90-deploy
```

**sudoers 规则格式**：

```
用户 主机=(可切换用户:可切换组) [NOPASSWD:|SETENV:|PASSWD:] 命令列表
```

```
# 示例
root    ALL=(ALL:ALL) ALL
%wheel  ALL=(ALL:ALL) ALL
%dev    ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx
alice   web01=(root) /usr/bin/apt update
Defaults   env_reset, secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
Defaults   !visiblepw
Defaults   timestamp_timeout=5
Defaults   logfile="/var/log/sudo.log"
Defaults   passwd_tries=3
```

常用 `Defaults`：

| 项 | 作用 |
|----|------|
| `secure_path=` | 固定 PATH，防劫持 ⭐ |
| `env_reset` | 清除环境（默认开） |
| `timestamp_timeout=N` | 凭证缓存分钟数（`0` = 每次都要密码） |
| `passwd_tries=N` | 密码尝试次数 |
| `logfile=` | sudo 日志文件 |
| `!visiblepw` | 不回显密码 |
| `requiretty` | 要求 TTY（会破坏很多自动化，现代多已关闭） |
| `use_pty` | 在伪终端里执行（防止 TTY 注入攻击） ⭐ |
| `log_input` / `log_output` | 记录输入/输出（审计） |
| `!authenticate` | 免密码执行（全局，⚠️ 危险） |

#### 常见坑
- ⚠️ **绝不直接 `vim /etc/sudoers`**。语法错误会让所有 sudo 失效，且你可能没有其他提权方式（例如唯一的 root 密码都不知道）。
- ⚠️ **`/etc/sudoers.d/` 里的文件必须有正确权限**：`0440`，属主 root。否则 sudo 会**忽略整个文件**（不报错！）。文件名也不能含 `.` 或 `~`。
- ⚠️ **`#include`/`@includedir` 顺序**：`/etc/sudoers` 里通常最后 `@includedir /etc/sudoers.d`，后定义的同用户规则可能覆盖前面的。用 `sudo -l` 验证实际生效的结果。
- **`%组` 用的是系统组名**（不在 sudoers 里定义），改 `/etc/group` 就改变了 sudo 权限。
- **`visudo -c` 是部署脚本里必须的校验步骤**。CI 里改 sudoers 后跑一次，能在锁死前发现问题。
- 🔐 **sudoers 是提权的常见目标**：如果某文件在 `/etc/sudoers.d/` 里但属主不是 root 或权限是 666，任何用户都可以写入任意 sudo 规则。排查：
  ```bash
  $ sudo find /etc/sudoers.d -type f ! -user root -o -type f -perm /022
  ```
- `sudo` 会忽略 `sudoers` 里指向不存在文件的 `include`（如果有 `#includedir` 指向不存在的目录则报错）。

#### 相关命令
`sudo -l` · `su` · `getent group` · `journalctl -t sudo`

### id — 查看用户身份

**常用度**：★★★★★ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`-Z`（SELinux）为 Linux 扩展

```bash
id [选项] [用户名]
```

| 选项 | 含义 |
|------|------|
| （无） | UID、GID、组、SELinux 上下文 |
| `-u` | 只显示有效 UID（`-un` 显示名字） |
| `-g` | 只显示有效 GID（`-gn` 名字） |
| `-G` | 所有组 ID（`-Gn` 名字） |
| `-n` | 显示名字而非数字 |
| `-r` | 显示**真实** ID 而非有效 ID ⭐ |
| `-Z` | 显示 SELinux 上下文 🔐 |

```bash
# 场景：完整身份
$ id
uid=1000(alice) gid=1000(alice) groups=1000(alice),10(wheel),998(docker)

# 场景：只看用户名/UID
$ id -un
alice
$ id -u
1000

# 场景：所有组名（脚本里判断是否在组内）⭐
$ id -Gn
alice wheel docker

# 场景：判断是否在某组（脚本）
$ id -Gn | grep -q '\bdocker\b' && echo "在 docker 组"

# 场景：真实 vs 有效 UID（SUID 场景的关键区别）⭐
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd
$ /tmp/showids               # 一个打印 uid 的小程序，通过 SUID 运行
real uid=1000, effective uid=0

$ id -u     # 有效
0
$ id -ur    # 真实
1000

# 场景：查看其他用户
$ id alice
$ id -Gn postgres

# 场景：🔐 查 SELinux 上下文
$ id -Z
unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
```

#### 输出解读
```
uid=1000(alice) gid=1000(alice) groups=1000(alice),10(wheel),998(docker)
│                │               └─ 附加组列表（第一个是主组）
│                └─ 主组
└─ 有效 UID
```

#### 常见坑
- ⚠️ **`id -u` 是「有效 UID」**，不是真实 UID。在 SUID 上下文里两者不同。要真实 UID 用 `id -ur`。
- **`id` 看不到「进程实际能做什么」**：Linux capability 机制让 uid=0 的进程也可能没有某些权限（`--no-new-privs`、capability bounding set）。用 `capsh --print` 看能力集。
- **`groups` 显示的值会因当前会话的组凭证缓存而与 `/etc/group` 不一致**：加入组后要重新登录才生效。`id -G` 读的是当前进程的组列表。
- 容器里的 `id` 反映容器内的用户命名空间映射，宿主机上同一个视角是不同的 UID（`/proc/<pid>/uid_map`）。
- 脚本里判断「是否 root」**不要用 `$USER`**（可伪造），用 `id -u` 或 `$EUID`（bash 内建，不可伪造）：
  ```bash
  [ "$EUID" -eq 0 ] || { echo "需要 root"; exit 1; }
  ```

#### 相关命令
`whoami` · `groups` · `who` · `capsh` · `getent`

### whoami — 显示当前用户名

**常用度**：★★★★★ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：`whoami` 非 POSIX（POSIX 是 `id -un`）

```bash
whoami
```

```bash
$ whoami
alice

# 与相关命令的区别
$ whoami       # 有效用户名（走 geteuid）
alice
$ logname      # 登录时的用户名（走 getlogin，可能失败/不同）
alice
$ echo "$USER" # 环境变量，可被伪造 ⚠️
alice
$ id -un       # 与 whoami 相同
alice

# 场景：SUID 环境下三者差异 ⭐
$ /tmp/suid_whoami
effective user: root
real user: alice
login name: alice
```

#### 常见坑
- ⚠️ **`$USER` 是环境变量，能被任意改写**，脚本里不能用它做权限判断。用 `$EUID` / `id -u` / `whoami`。
- **`whoami` 显示的是有效用户**（`geteuid`），`logname` 显示登录用户。SUID 场景下两者不同。
- **`whoami` 在 `su` / `sudo` 后显示新身份**，而 `logname` 可能仍显示原身份或失败（`logname: no login name`）。
- 容器/`nsenter` 环境下 `/proc/self/uid_map` 决定映射，`whoami` 显示的是命名空间内的名字。

#### 相关命令
`id` · `logname` · `who` · `w`

### who — 查看当前登录用户

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：无（`-a`/`-b` 等为扩展）

```bash
who [选项] [文件]
```

| 选项 | 含义 |
|------|------|
| （无） | 用户名、终端、登录时间、（远程主机） |
| `-a` | 全部信息（等同多个选项组合） |
| `-b` | 系统上次启动时间 |
| `-r` | 当前运行级别（runlevel） |
| `-H` | 显示表头 |
| `-u` | 显示空闲时间 |
| `-q` | 只显示登录用户数与用户名列表 ⭐ |
| `-T` | 显示终端是否为可写（`+` / `-` / `?`） |
| `-l` | 列出等待登录的终端 |
| `-d` | 列出已死的进程 |

```bash
$ who
alice    tty1         2026-09-15 08:30
bob      pts/0        2026-09-15 09:12 (10.0.0.55)
root     pts/1        2026-09-15 09:45 (10.0.0.66)

$ who -q
alice bob root
# 用户数=3

$ who -b
         system boot  2026-09-14 22:01

$ who -H -u
NAME     LINE         TIME             IDLE          PID COMMENT
alice    tty1         2026-09-15 08:30   .            1234

$ who -r
         run-level 5  2026-09-14 22:01
```

#### 输出解读
| 字段 | 含义 |
|------|------|
| 用户名 | 登录用户 |
| `tty1` | 本地终端（物理控制台） |
| `pts/0` | 伪终端（SSH、终端模拟器） |
| 时间 | 登录时间 |
| `(10.0.0.55)` | 远程来源 IP/主机名 |
| `IDLE` | 空闲时间（`.` 表示 <1 分钟） |

#### 常见坑
- **`who` 读的是 `/var/run/utmp`**，只有**交互式登录**才记录。`su`、`sudo -i`、脚本里的非登录会话**不会出现**。所以 `who` 看不到全部活动用户。
- 容器里 `who` 常是空的（没有 utmp 记录）。
- **`who` 的输出可被 root 篡改**（写 utmp）。取证时应交叉验证 `ss -tnp`（SSH 连接）、`ps -ef`（进程）、`last`（wtmp 历史）。
- `who -T` 的 `+` 表示终端可写，`-` 表示不可写（可能被 `mesg n` 关掉），`?` 表示无法确定。
- SSH 会话在 `who` 里显示为 `pts/N`，且**一个用户可能有多个 pts**。

#### 相关命令
`w` · `users` · `last` · `loginctl list-sessions` · `who -a`

### last — 查看登录历史

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：非 POSIX，`util-linux` 提供

```bash
last [选项] [用户...] [tty...]
```

| 选项 | 含义 |
|------|------|
| `-n N` | 显示 N 条 |
| `-F` / `--fulltimes` | 显示完整进入/退出时间（含日期与年份） ⭐ |
| `-i` | 显示 IP 而非主机名（取证优先） ⭐ |
| `-x` | 也显示关机/运行级别变更记录 |
| `-d` | 显示非本地登录的远程主机 |
| `-R` / `--nohostname` | 不显示主机名 |
| `-a` / `--hostlast` | 主机名放最后一列 |
| `-f 文件` | 读指定文件（默认 `/var/log/wtmp`） |
| `-t YYYYMMDDHHMMSS` | 只看某时间之后的记录（GNU） |
| `-w` / `--fullnames` | 不截断用户名 |

```bash
# 场景：最近登录 ⭐
$ last -n 10
alice    pts/1        10.0.0.55        Tue Sep 15 09:45   still logged in
bob      pts/0        10.0.0.66        Tue Sep 15 09:12 - 10:30  (01:18)
reboot   system boot  7.2.3-arch1-3    Mon Sep 14 22:01   still running

# 场景：🔐 某用户的登录历史
$ last -i alice
alice    pts/1        10.0.0.55        Tue Sep 15 09:45   still logged in

# 场景：🔐 完整时间戳（取证）
$ last -F -i -n 20
alice    pts/1        10.0.0.55        Tue Sep 15 09:45:12 2026   still logged in

# 场景：所有重启记录
$ last -x reboot | head

# 场景：谁在什么时候退出
$ last -F -x shutdown

# 场景：失败登录（要看 /var/log/btmp）
$ sudo lastb -F -i | head -20    # ⚠️ 需要 root，/var/log/btmp 通常 0600

# 场景：读取备份的 wtmp
$ last -f /var/log/wtmp.1
```

#### 输出解读
| 字段 | 含义 |
|------|------|
| 用户名 | 或 `reboot` / `shutdown` / `runlevel` |
| tty | 终端 |
| 来源 | IP 或主机名 |
| 起止时间 | 登录时间 - 登出时间 |
| 时长 | `(01:18)` 或 `still logged in` / `gone - no logout` |

特殊记录：

| 显示 | 含义 |
|------|------|
| `reboot` | 系统启动 |
| `shutdown` | 系统关机 |
| `gone - no logout` | 没有正常的登出记录（崩溃或强制断电） |
| `crash` | 宕机 |

#### 常见坑
- 🔐 **wtmp 是二进制文件，可被 root 伪造或删除**（`> /var/log/wtmp`）。攻击者的标准清理动作之一。所以 `last` 的输出**不能单独作为结论**。
- **`wtmp` 会被轮转**（`logrotate`），历史只保留几周。要长期审计必须转发到远端或装 auditd。
- **`lastb` 读 `/var/log/btmp`**，权限 `0600 root:utmp`，普通用户看不到。
- **容器里 `last` 通常为空**（没有 utmp/wtmp 维护）。
- `-i` 把主机名解析成 IP，**取证必须用 `-i`**，否则主机名可能被 DNS 反向解析成误导性的值。
- **`-F` 才能看到年份**，默认格式省略年份，跨年分析会出错。
- `last` 输出的**时间可能是本地时区**，跨时区取证要统一到 UTC（`TZ=UTC last -F`）。

#### 相关命令
`who` · `w` · `lastlog` · `lastb` · `journalctl -u sshd` · `faillock`

### lastlog — 查看各用户最后登录时间

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：非 POSIX

```bash
lastlog [选项]
```

| 选项 | 含义 |
|------|------|
| `-u 用户` | 只看指定用户 |
| `-t N` | 只看最近 N 天的登录 ✅ |
| `-b N` | 只看 N 天前的登录 ✅ |
| `-C` / `--clear` | 清空 lastlog 记录 |
| `-S N` | 设置记录为 N 天前 |

```bash
# 场景：所有用户的最后登录时间 ⭐
$ lastlog
用户名        端口       来自              最后登录时间
root             pts/1    10.0.0.66       二 9月 15 09:45:12 +0800 2026
alice            pts/0                    二 9月 15 09:12:44 +0800 2026
bob              **从未登录过**
...
nobody                                      **从未登录过**

# 场景：🔐 找出从未登录或长期未登录的账号（可删除的僵尸账号）
$ lastlog | grep -E '从未登录|\*\*Never'
$ sudo lastlog -b 90      # 90 天前登录过的

# 场景：只看某用户
$ lastlog -u alice

# 场景：只看最近 7 天登录过的
$ lastlog -t 7
```

#### 输出解读
- `**从未登录过**` — 账号创建后从未使用（**服务账号或后门账号的信号**） 🔐
- 端口为 `pts/N` — 远程或伪终端登录
- 端口为空 — 多为服务账号

#### 常见坑
- 🔐 **`**从未登录过**` 的账号值得关注**：可能是遗留账号或攻击者创建的后门。但也可能是正常的服务账号。
- `/var/log/lastlog` 是**稀疏文件**，大小按最大 UID 分配（可能几个 GB，但实际占用极小）。用 `du` 看实际占用。
- `lastlog` **只在 PAM 配置了 `pam_lastlog` 时更新**，某些最小化系统上可能不记录。
- 容器里通常不维护 lastlog。
- **`lastlog` 不显示 IP 而显示主机名**（取决于 PAM 配置），跨时区/主机名解析问题同 `last`。
- `-C` 会**清空所有记录**，⚠️ 破坏取证数据，别在生产上随手用。

#### 相关命令
`last` · `lastb` · `who` · `journalctl -u sshd`

### groups — 查看用户所属组

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：无

```bash
groups [用户名...]
```

```bash
# 场景：当前用户的所有组
$ groups
alice wheel docker

# 场景：其他用户的组
$ groups alice
alice : alice wheel docker

# 场景：多个用户
$ groups alice bob

# 场景：脚本里判断是否在组内 ⭐
$ groups | tr ' ' '\n' | grep -qx docker && echo "在 docker 组"
$ id -Gn | tr ' ' '\n' | grep -qx docker && echo "在 docker 组"   # 更可移植

# 场景：查看组的所有成员
$ getent group docker
docker:x:998:alice,bob
```

#### 输出解读
- 不加参数时，第一个组是**当前进程的主组**，其余是附加组。
- 加用户名参数时，格式是 `用户名 : 主组 附加组...`。

#### 常见坑
- ⚠️ **`groups` 看的是当前进程的组凭证，不是 `/etc/group`**。刚 `usermod -aG` 加入组后，当前会话仍看不到新组（要重新登录或用 `newgrp`）。验证用 `getent group` 看数据库。
- **在脚本里 `groups` 的输出是基于「当前进程」的**，若脚本以不同用户运行结果不同。
- 主组与附加组的区分在 `groups` 无参数时只能靠位置（第一个）。要明确判断用 `id -g`（主组）与 `id -G`（全部）。
- 组名含空格是不可能的（系统不允许），所以 `tr ' ' '\n'` 是安全的。

#### 相关命令
`id` · `getent group` · `newgrp` · `gpasswd -a`

### newgrp — 切换当前有效组

**常用度**：★★☆☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：无

```bash
newgrp [-] [组]
```

| 写法 | 含义 |
|------|------|
| `newgrp devteam` | 启动一个新的 shell，主组为 devteam |
| `newgrp -` | 同 `su -` 语义，重新初始化环境 |

```bash
# 场景：临时切换到某组（不必重新登录）
$ id -gn
alice
$ newgrp devteam
$ id -gn
devteam
$ exit            # 退回原 shell
$ id -gn
alice

# 场景：新建文件时使用该组的权限
$ cd /srv/team
$ newgrp devteam
$ touch newfile   # 属组是 devteam
$ ls -l newfile
-rw-r--r-- 1 alice devteam 0 ... newfile
```

#### 输出解读
`newgrp` 会启动一个**子 shell**，所以 `exit` 会回到原来的 shell（有嵌套感）。

#### 常见坑
- ⚠️ **`newgrp` 启动子 shell，所有环境变量改动不会带回**。在脚本里用会「看起来没生效」。
- **`newgrp` 会重置某些环境变量**（它本质是新的登录式 shell 启动）。不加 `-` 也常影响 `$PATH`。
- **组有密码时会要求输入组密码**（组密码机制已基本废弃，现代系统都是 `x`）。
- 需要重新登录才能让新组生效的场景，`newgrp` 是唯一临时绕过方式之一。
- `newgrp` 在某些 shell 里是内建，在另一些里是外部命令，行为略有差异。

#### 相关命令
`groups` · `sg` · `id` · `gpasswd`

### getent — 查询系统账号数据库

**常用度**：★★★★☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux（glibc）特有，但广泛可用

```bash
getent 数据库 [键...]
```

常用数据库（来自 `/etc/nsswitch.conf`）：

| 数据库 | 内容 |
|--------|------|
| `passwd` | 用户账号 |
| `shadow` | 密码哈希（需 root） |
| `group` | 组 |
| `gshadow` | 组密码 |
| `hosts` | 主机名解析（**走 DNS**） ⭐ |
| `services` | 服务名与端口 |
| `protocols` | 协议 |
| `networks` | 网络名 |
| `netgroup` | 网络组 |
| `sudoers` | sudo 规则（配了 nsswitch 时） |
| `aliases` | 邮件别名 |

```bash
# 场景：查用户（含 LDAP/SSSD 等外部源）⭐
$ getent passwd alice
alice:x:1000:1000:Alice:/home/alice:/bin/bash
$ getent passwd | wc -l              # 所有用户数（含目录服务）

# 场景：查组
$ getent group docker
docker:x:998:alice,bob

# 场景：查主机名解析（走 nsswitch，含 /etc/hosts 和 DNS）⭐
$ getent hosts example.com
93.184.216.34    example.com

# 场景：查服务对应的端口
$ getent services ssh
ssh                  22/tcp
$ getent services 443
https                443/tcp

# 场景：按 UID 查（不带名字）
$ getent passwd 1000

# 场景：脚本里判断用户是否存在 ⭐
$ getent passwd alice >/dev/null && echo exists || echo missing

# 场景：🔐 列出所有 UID=0 的账号（后门检测）
$ getent passwd | awk -F: '$3==0 {print $1}'

# 场景：🔐 列出所有可登录 shell 的账号
$ getent passwd | awk -F: '$7 !~ /(nologin|false|sync|shutdown|halt)$/ {print $1" "$7}'

# 场景：对比本地文件与系统视图的差异
$ diff <(cut -d: -f1 /etc/passwd | sort) <(getent passwd | cut -d: -f1 | sort)
```

#### 输出解读
`getent` 的格式与对应的 `/etc/*` 文件相同（冒号分隔），但**数据来源可能是 LDAP/SSSD/NIS**，而 `cat /etc/passwd` 只有本地文件。

#### 常见坑
- ⚠️ **`cat /etc/passwd` 与 `getent passwd` 不等价**：后者包含 LDAP/SSSD 等外部源的用户。**判断账号是否存在必须用 `getent`**。
- **`getent shadow` 需要 root**，普通用户会得到空结果或部分结果（取决于 NSS 配置）。
- `getent hosts` **走完整的 NSS 链**（`/etc/hosts` → DNS），比 `dig` 更贴近「程序实际怎么解析」。
- `getent` 在 `nsswitch.conf` 配了慢速源（如不可达的 LDAP）时会**挂起很久**。
- 某些加固系统（SELinux/apparmor）会限制 `getent` 的访问。
- `getent passwd` 的输出顺序不保证（本地文件在前，但目录服务顺序取决于实现）。

#### 相关命令
`id` · `groups` · `resolvectl query` · `nsswitch.conf`

### faillock — 查看与重置登录失败计数

**常用度**：★★★☆☆ ｜ **所属**：权限与用户 ｜ **POSIX/GNU 差异**：Linux PAM 模块 `pam_faillock` 的一部分

```bash
faillock [选项] [用户名]
```

| 选项 | 含义 |
|------|------|
| （无） | 显示当前用户的失败记录 |
| `--user 用户` | 指定用户 ⭐ |
| `--reset` | 清除某用户的计数 ⭐ |
| `--dir 目录` | 计数文件目录（默认 `/var/run/faillock`） |

```bash
# 场景：查看自己的失败记录
$ faillock
alice:
When                Type  Source                                           Valid
2026-09-15 09:10:22 RHOST 10.0.0.99                                        V
2026-09-15 09:10:31 RHOST 10.0.0.99                                        V

# 场景：🔐 查看某用户的失败登录（应急必看）
$ sudo faillock --user alice
When                Type  Source                                           Valid
2026-09-15 09:10:22 RHOST 10.0.0.99                                        V

# 场景：账号被锁定后解锁 ⭐
$ sudo faillock --user alice --reset
$ sudo faillock --user alice
alice:
When                Type  Source                                           Valid

# 场景：找出被锁定的账号
$ sudo faillock --user alice --reset --dir /var/run/faillock   # 需要逐个查
$ for u in $(getent passwd | awk -F: '$3>=1000 && $3<65534 {print $1}'); do
>   n=$(sudo faillock --user "$u" 2>/dev/null | grep -c ' V$')
>   [ "$n" -gt 0 ] && echo "$u 有 $n 次失败"
> done

# 场景：查看 PAM 配置的锁定阈值
$ grep -A6 'pam_faillock' /etc/pam.d/system-auth /etc/pam.d/password-auth 2>/dev/null
$ cat /etc/security/faillock.conf
deny = 5
unlock_time = 900
```

#### 输出解读
| 列 | 含义 |
|----|------|
| When | 失败时间 |
| Type | 失败类型：`RHOST`（远程）、`TTY`（本地终端）、`USER` |
| Source | 来源（IP/终端） |
| Valid | `V` 表示仍计入锁定阈值，`I` 表示已失效 |

#### 常见坑
- **`faillock` 只在系统配了 `pam_faillock` 时才有效**。较老的系统用 `pam_tally2`（命令是 `pam_tally2`）。检查 `/etc/pam.d/` 里用的是哪个。
- **计数文件在 `/var/run/faillock/`（tmpfs）**，**重启即清空**。要持久化审计必须看 `/var/log/secure` 或 `journalctl`。
- 🔐 **失败次数高的来源 IP 是攻击信号**。`faillock --user X` 的 `Source` 列会给出攻击者 IP。
- `--reset` 需要 root，且会**清除该用户的全部计数**（可能掩盖攻击痕迹，取证时要先备份输出）。
- `deny` 值与 `unlock_time` 在 `/etc/security/faillock.conf`（或 PAM 行内参数）。改完不需要重启服务。
- 用 `pam_tally2` 的系统上 `pam_tally2 --user X --reset` 是等价命令。

#### 相关命令
`pam_tally2` · `lastb` · `journalctl -u sshd` · `fail2ban-client`
