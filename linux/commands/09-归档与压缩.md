# 09 · 归档与压缩命令

> 返回总索引：[`README.md`](README.md)。
> 相关：[`01-文件与目录.md`](01-文件与目录.md)、[`05-磁盘与文件系统.md`](05-磁盘与文件系统.md)。

> 归档（archive）与压缩（compress）是两件事：
> - **归档**：把多个文件打包成一个（`tar`）
> - **压缩**：把数据变小（`gzip`、`xz`、`zstd`）
> `tar.gz` 就是「tar 打包 + gzip 压缩」的组合。

## 压缩算法对比

| 算法 | 后缀 | 压缩率 | 速度 | 内存 | 适用 |
|------|------|--------|------|------|------|
| **gzip** | `.gz` | 中 | 快 | 低 | 通用，兼容性最好 ⭐ |
| **bzip2** | `.bz2` | 好 | 慢 | 中 | 已较少用（被 xz 取代） |
| **xz** | `.xz` | **最好** | 很慢 | **高** | 追求最小体积（发布包） ⭐ |
| **zstd** | `.zst` | 好 | **很快** | 低 | **现代首选** ⭐⭐ |
| **lz4** | `.lz4` | 差 | **极快** | 极低 | 实时/日志 |
| **lzo** | `.lzo` | 差 | 极快 | 低 | 内核（`zram`、squashfs） |
| **zip** | `.zip` | 中 | 快 | 低 | 跨平台（Windows 兼容） |
| **7z** | `.7z` | 最好 | 慢 | 高 | 追求最小体积 |

**经验法则**：能选就用 `zstd`（速度与压缩率的最佳平衡）；发布给别人的包用 `xz`；需要 Windows 用户解压用 `zip`。

### tar — 归档工具

**常用度**：★★★★★ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：`--zstd`、`--auto-compress`、`--exclude` 位置语义 GNU 更宽松

#### 语法
```bash
tar [选项] [归档文件] [文件...]
```

#### 必背选项（记住「主操作 + 压缩 + 文件」三段）
| 选项 | 含义 |
|------|------|
| `-c` | **创建**归档 ⭐ |
| `-x` | **解出**归档 ⭐ |
| `-t` | **列出**内容（不改动任何文件） ⭐ |
| `-f 文件` | 指定归档文件名（**必须紧跟 `-f`**） ⚠️ |
| `-v` | 详细（列出处理的文件） ⭐ |
| `-z` | gzip（`.tar.gz`/`.tgz`） ⭐ |
| `-j` | bzip2（`.tar.bz2`） |
| `-J` | xz（`.tar.xz`） ⭐ |
| `--zstd` | zstd（`.tar.zst`） ⭐ |
| `-a` / `--auto-compress` | **按文件后缀自动选压缩** ⭐⭐ |
| `-C 目录` | 先切到该目录（**创建与解出都能用**） ⭐⭐ |
| `--exclude=模式` | 排除 ⭐ |
| `--exclude-from=文件` | 从文件读排除规则 |
| `--strip-components=N` | 解出时去掉前 N 层目录 ⭐⭐ |
| `-p` | 保留权限（`-x` 时） ⭐ |
| `--same-owner` / `--no-same-owner` | 保留/不保留属主 ⭐ |
| `--numeric-owner` | 用数字 UID/GID（跨系统） ⭐ |
| `-h` | 跟随符号链接（默认不跟随，存链接本身） |
| `-T 文件` | 从文件读路径列表 ⭐ |
| `--null` | 配 `-T`，用 NUL 分隔路径 ⭐ |
| `-S` | 处理稀疏文件 |
| `-X 文件` | 排除规则文件 |
| `-P` | 保留绝对路径（**默认会去掉前导 `/`**） ⚠️⭐ |
| `--totals` | 显示总计 |
| `--checkpoint` | 显示进度（`--checkpoint-action=dot`） ⭐ |
| `-W` | 校验 |
| `--format=格式` | `gnu`/`pax`/`posix`/`ustar` ⭐ |

#### 实战示例
```bash
# 场景：创建归档 ⭐
$ tar cf archive.tar dir/
$ tar czf archive.tar.gz dir/
$ tar cJf archive.tar.xz dir/
$ tar caf archive.tar.zst dir/          # ⭐ -a 自动按后缀选压缩
$ tar czf archive.tar.gz -C /var/log app.log error.log   # ⭐ -C 切目录，路径更干净

# 场景：⭐ 用 --auto-compress 更省心
$ tar caf backup-$(date +%F).tar.zst /srv/data

# 场景：列出内容（不改文件）⭐⭐
$ tar tf archive.tar.gz
$ tar tvf archive.tar.gz | head           # 含权限、属主、大小
$ tar tvf archive.tar.gz | grep -E '\.conf$'
$ tar tvf archive.tar.gz | awk '{print $3, $6}' | head   # 大小 + 路径

# 场景：解出 ⭐
$ tar xf archive.tar.gz                  # ⭐ GNU tar 能自动识别压缩
$ tar xzf archive.tar.gz -C /tmp/dest    # 解到指定目录
$ tar xf archive.tar.gz --strip-components=1 -C /tmp     # ⭐ 去掉顶层目录

# 场景：⭐ 先看再解（安全习惯）
$ tar tf suspicious.tar.gz | head -20
$ tar tvf suspicious.tar.gz | grep -E '^l|\.\./|^/'     # 🔐 检查符号链接与路径穿越
$ tar xf suspicious.tar.gz -C /tmp/safe

# 场景：排除噪音文件 ⭐
$ tar czf code.tar.gz --exclude='.git' --exclude='node_modules' --exclude='*.pyc' ./project
$ tar czf code.tar.gz --exclude-from=/tmp/exclude.txt ./project

# 场景：只归档某些文件（从列表）⭐
$ find /var/log -name '*.log' -print0 | tar czf logs.tar.gz --null -T -
$ tar czf subset.tar.gz -T /tmp/filelist.txt

# 场景：增量/差异备份（-g 快照文件）⭐
$ tar czg /tmp/snapshot.snar -f full-$(date +%F).tar.gz /srv/data        # 全量
$ tar czg /tmp/snapshot.snar -f inc-$(date +%F).tar.gz  /srv/data        # 增量
$ ls /tmp/snapshot.snar*

# 场景：保留权限与属主（备份/迁移必用）⭐⭐
$ sudo tar czpf etc-backup.tar.gz --numeric-owner /etc
$ sudo tar czpf etc-backup.tar.gz --same-owner /etc
$ # 解出时保留
$ sudo tar xzpf etc-backup.tar.gz -C /mnt/newroot

# 场景：跨系统迁移（避免 UID 映射错误）⭐
$ sudo tar cpf sysbackup.tar --numeric-owner --one-file-system \
>   --exclude=/proc --exclude=/sys --exclude=/dev --exclude=/run \
>   --exclude=/tmp --exclude=/mnt --exclude=/media /
$ # ⭐ --one-file-system 不跨挂载点（避免挂载点递归）

# 场景：打包并通过 SSH 传输（不落中间文件）⭐⭐
$ tar czf - /srv/data | ssh user@host 'tar xzf - -C /backup/'
$ ssh user@host 'tar czf - /data' | tar xzf - -C /local/backup/

# 场景：分卷归档（超过单文件限制时）
$ tar czf - /data | split -b 2G - /backup/data.tar.gz.part-
$ cat /backup/data.tar.gz.part-* | tar xzf - -C /restore

# 场景：与 find 组合（按时间挑文件）⭐
$ find /var/log -name '*.log' -mtime -7 -print0 | tar caf recent-logs.tar.zst --null -T -

# 场景：⭐ 用 zstd 快速大归档（多线程）
$ tar cf - /data | zstd -T0 -19 -o data.tar.zst
$ zstd -d -c data.tar.zst | tar xf - -C /restore

# 场景：查看归档内某文件内容（不完整解出）⭐
$ tar xOf archive.tar.gz path/to/file.txt
$ tar xOf archive.tar.gz etc/nginx/nginx.conf | head

# 场景：追加文件到未压缩归档 ⚠️
$ tar rf archive.tar newfile.txt
$ # ⚠️ 只能对未压缩的 .tar 追加；.tar.gz 无法追加

# 场景：校验归档完整性 ⭐
$ gzip -t archive.tar.gz && echo OK
$ xz -t archive.tar.xz && echo OK
$ zstd -t archive.tar.zst && echo OK
$ tar tf archive.tar.gz >/dev/null && echo "归档可读"

# 场景：显示进度（大归档）
$ tar caf big.tar.zst --checkpoint=1000 --checkpoint-action=dot /data
$ tar cf - /data | pv | zstd -T0 -o big.tar.zst          # ⭐ pv 显示吞吐

# 场景：🔐 提权排查——找归档里的敏感文件与 SUID
$ tar tvf suspicious.tar.gz | grep -E '^-rws|^-..s'
$ tar tvf suspicious.tar.gz | grep -E '/etc/(shadow|passwd|sudoers)|\.ssh/|id_rsa'

# 场景：🔐 检查归档是否含路径穿越（Zip Slip / Tar Slip）⭐⭐
$ tar tf suspicious.tar.gz | grep -E '^/|\.\./|^\.\.'
# 有输出说明归档试图写到目标目录之外 → 解出时要当心
$ # 安全解出：用 -C 到隔离目录，且不用 -P、不用 --absolute-names
```

#### 输出解读
`tar tvf` 的输出格式（类似 `ls -l`）：
```
-rw-r--r-- root/root      1234 2026-09-15 09:30 etc/nginx/nginx.conf
drwxr-xr-x root/root         0 2026-09-15 09:30 etc/nginx/
lrwxrwxrwx root/root        13 2026-09-15 09:30 etc/nginx/mime.types -> /etc/mime.types
│          │    │           │  │                 │                       └─ 链接目标
│          │    │           │  │                 └─ 路径
│          │    │           │  └─ 时间
│          │    │           └─ 大小
│          │    └─ 属主/属组
│          └─ 权限（首字符 - 文件 d 目录 l 链接）
└─ 权限位
```

**`-f` 的位置极其重要**：`tar -cvzf` 与 `tar -czf` 都行，但 `tar -czvf archive.tar.gz` 里 `-f` 后必须紧跟文件名。写成 `tar -czf dir/ archive.tar.gz` 会把 `dir/` 当归档名 ⚠️。

#### 常见坑
- ⚠️ **`-f` 与归档名之间不能有其他参数**。历史上 `tar cfv` 可以，但**现代 tar 要求 `-f` 后紧跟文件名** ⭐。
- ⚠️ **导出时默认去掉绝对路径的前导 `/`**（防止解出时覆盖系统文件）。要保留用 `-P`，但**解出时用 `-P` 是危险的** ⭐。
- ⚠️ **`--exclude` 的位置影响匹配**：老 GNU tar 要求 `--exclude` 在要排除的文件**之前**，新版本较宽松。稳妥写法是把 `--exclude` 放在文件列表前面 ⭐。
- ⚠️ **`tar` 默认不跟随符号链接**（存链接本身），这是正确的备份行为。要存链接的内容用 `-h`（很少需要）。
- ⚠️ **解出时默认按当前用户属主**（除非 root 且没有 `--no-same-owner`）。备份/恢复要用 `-p` 与 `--numeric-owner` ⭐。
- ⚠️ **`tar xf` 解出到当前目录**，会覆盖同名文件且**没有提示**。养成先 `tvf` 看的习惯 ⭐。
- **`tar` 的压缩是单线程的**（`-z`/`-J`），大文件用 `pigz` 或 `tar cf - | zstd -T0` 更快 ⭐。
- **`--one-file-system` 很重要**：不加会递归进 `/proc`、`/sys`、挂载的 NFS（可能卡死）⭐。
- **归档里的路径默认带 `./` 前缀**，解出时会创建 `./dir`，用 `--strip-components` 或先 `-C` 控制 ⭐。
- **`tar` 不支持硬链接与 ACL 的完整保留**，除非加 `--acls`/`--xattrs`/`--hard-dereference` ⭐。
- **`tar` 对超大文件（>8GB）需要 `--format=posix` 或 `gnu`**，`ustar` 不支持。

`gzip` · `xz` · `zstd` · `cpio` · `rsync` · `pigz` · `split` · `pv`

### gzip / gunzip — gzip 压缩解压

**常用度**：★★★★★ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：无（`-k`、`-l`、`-r` 是常见扩展）

```bash
gzip [选项] [文件...]
gunzip [选项] [文件...]
zcat [文件...]
```

| 选项 | 含义 |
|------|------|
| `-d` / `--decompress` | 解压（`gunzip` 的等价） ⭐ |
| `-k` / `--keep` | **保留原文件** ⭐⭐ |
| `-c` / `--stdout` | 输出到 stdout（**保留原文件**） ⭐ |
| `-l` / `--list` | 列出压缩信息 ⭐ |
| `-1` .. `-9` | 压缩级别（`-1` 最快，`-9` 最小，默认 `-6`） ⭐ |
| `-r` | 递归处理目录 |
| `-f` | 强制（对已有输出文件） |
| `-t` / `--test` | **只校验完整性** ⭐ |
| `-q` | 安静 |
| `-v` | 详细 |
| `-S 后缀` | 自定义后缀 |
| `--rsyncable` | 让输出对 rsync 更友好（增量传输） ⭐ |

```bash
# 场景：⚠️ 默认会删除原文件
$ ls big.log
big.log
$ gzip big.log
$ ls big.log*
big.log.gz                   # 原文件没了！

# 场景：⭐ 保留原文件（必须记住）
$ gzip -k big.log
$ ls big.log*
big.log  big.log.gz

# 场景：解压 ⭐
$ gunzip big.log.gz
$ gzip -dk big.log.gz        # 保留 .gz

# 场景：⭐ 管道用法（最灵活）
$ gzip -dc big.log.gz | head -20
$ cat big.log | gzip > big.log.gz          # 压缩 stdin
$ zcat big.log.gz | grep ERROR

# 场景：查看压缩信息 ⭐
$ gzip -l big.log.gz
         compressed        uncompressed  ratio uncompressed_name
              12345             1234560  99.0% big.log
$ gzip -lv big.log.gz        # 含压缩方法
$ zcat big.log.gz | wc -l    # 解压后的行数

# 场景：校验完整性 ⭐
$ gzip -t archive.tar.gz && echo "OK" || echo "损坏"
$ gzip -tv archive.tar.gz

# 场景：压缩级别对比（时间 vs 体积）⭐
$ for lvl in 1 6 9; do
>   /usr/bin/time -f "级别 $lvl: %e 秒" gzip -$lvl -kc big.log > /tmp/big-$lvl.gz 2>/tmp/t-$lvl
>   cat /tmp/t-$lvl; ls -lh /tmp/big-$lvl.gz | awk '{print "  体积: " $5}'
> done

# 场景：递归压缩目录里的文件（每个文件单独压）
$ gzip -rk /var/log/old/
$ find /var/log -name '*.log' -exec gzip -k {} +

# 场景：配 rsyncable（增量同步更高效）⭐
$ gzip --rsyncable -k big.log

# 场景：压缩日志时保留原始 mtime
$ gzip -k -N big.log          # -N 保留原名与时间戳 ⭐
```

#### 输出解读
| 后缀 | 含义 |
|------|------|
| `.gz` | 标准 gzip |
| `.tgz` | `tar` + `gzip` |
| `.Z` | 老的 compress（不同格式，用 `uncompress`） |
| `.zst` / `.xz` / `.bz2` | 其他算法（gzip 不能处理） |

`gzip -l` 的 `ratio` 是压缩率（`99.0%` 表示压到原来的 1%）。

#### 常见坑
- ⚠️⚠️ **`gzip file` 会删除原文件**。要保留必须 `-k` ⭐⭐。这是新手最常见的「原文件不见了」。
- ⚠️ **`gzip` 只能压缩单个文件**，不能压目录。要压目录先用 `tar czf` ⭐。
- ⚠️ **gzip 不支持「多个文件打包成一个 .gz」**。`gzip a b c` 会生成 `a.gz b.gz c.gz` ⭐。
- **`gzip` 对已经压缩的数据（JPEG、MP4、zip）几乎无效果**，白白花时间 ⭐。
- **`gzip -9` 比 `-6` 只小 1–3%，但慢一倍**。默认 `-6` 是合理平衡 ⭐。
- **`.gz` 文件不含原始文件名**（默认），`-N` 才存（但也需要 `gunzip -N` 才能恢复）⭐。
- **`gzip` 的 CRC32 只能检测随机错误，不是密码学校验**（恶意篡改可绕过）🔐。
- **`gzip` 是单线程的**，大文件用 `pigz`（多线程，兼容 `.gz` 格式）⭐。

#### 相关命令
`gunzip` · `zcat` · `zgrep` · `tar -z` · `pigz` · `bzip2` · `xz` · `zstd`

### bzip2 / bunzip2 — bzip2 压缩解压

**常用度**：★★★☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：无

```bash
bzip2 [选项] [文件...]
bunzip2 [选项] [文件...]
bzcat [文件...]
```

| 选项 | 含义 |
|------|------|
| `-d` | 解压 ⭐ |
| `-k` | 保留原文件 ⭐ |
| `-c` | 输出到 stdout ⭐ |
| `-z` | 压缩（默认） |
| `-1` .. `-9` | 压缩级别（默认 `-9`） ⭐ |
| `-t` | 校验 ⭐ |
| `-f` | 强制 |
| `-v` | 详细 |
| `-s` | 用较少内存（**解压慢但省内存**）⭐ |

```bash
# 场景：压缩（默认删原文件）⚠️
$ bzip2 big.log
$ ls big.log* 
big.log.bz2

# 场景：保留原文件 ⭐
$ bzip2 -k big.log

# 场景：解压 ⭐
$ bunzip2 big.log.bz2
$ bzip2 -dk big.log.bz2
$ bzcat big.log.bz2 | head

# 场景：校验 ⭐
$ bzip2 -t archive.tar.bz2 && echo OK

# 场景：与 gzip 的对比 ⭐
$ lg=big.log
$ /usr/bin/time -f "gzip -6:  %e 秒" gzip -6 -kc "$lg" > /tmp/a.gz
$ /usr/bin/time -f "bzip2 -9: %e 秒" bzip2 -9 -kc "$lg" > /tmp/a.bz2
$ ls -lh /tmp/a.gz /tmp/a.bz2

# 场景：低内存环境解压 ⭐
$ bzip2 -ds big.log.bz2 > big.log

# 场景：用 tar 处理
$ tar cjf archive.tar.bz2 dir/
$ tar xjf archive.tar.bz2 -C /tmp/

# 场景：并行版本（更快）
$ pbzip2 -p"$(nproc)" -k big.log
$ lbzip2 -k big.log
```

#### 输出解读
| 后缀 | 含义 |
|------|------|
| `.bz2` | bzip2 |
| `.tbz` / `.tbz2` | tar + bzip2 |

bzip2 用 **Burrows-Wheeler 变换 + Huffman 编码**，压缩率通常比 gzip 好 10–20%，但**慢 2–5 倍**。

#### 常见坑
- ⚠️ **`bzip2` 默认删除原文件**（同 gzip），要 `-k` ⭐。
- ⚠️ **`bzip2` 的默认级别是 `-9`**（最慢），而不是像 gzip 那样默认 `-6`。想快就显式给低级别 ⭐。
- ⚠️ **`bzip2` 解压需要的内存很少（默认几百 KB），但 `-s` 更少**——大块大小的 `.bz2`（`-9` 压的）解压时要 3.5 MB+，嵌入式环境可能不够 ⭐。
- **`.bz2` 已被 xz/zstd 取代**：xz 压得更小，zstd 快得多。bzip2 主要用于兼容旧系统 ⭐。
- **bzip2 是单线程**，用 `pbzip2` / `lbzip2` 并行 ⭐。
- **bzip2 不能压缩目录**，要先用 tar。

#### 相关命令
`bunzip2` · `bzcat` · `pbzip2` · `tar -j` · `gzip` · `xz`

### xz / unxz — xz 压缩解压

**常用度**：★★★★☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：无（LZMA2 算法）

```bash
xz [选项] [文件...]
unxz [选项] [文件...]
xzcat [文件...]
```

| 选项 | 含义 |
|------|------|
| `-d` | 解压 ⭐ |
| `-k` | 保留原文件 ⭐ |
| `-c` | 输出到 stdout ⭐ |
| `-0` .. `-9` | 压缩级别（默认 `-6`） ⭐ |
| `-e` | 极端模式（**更慢但更小**） ⭐ |
| `-T N` | **多线程**（`-T0` = 用所有核） ⭐⭐ |
| `-l` | 列出压缩信息 ⭐ |
| `-t` | 校验 ⭐ |
| `-f` | 强制 |
| `-v` | 详细 |
| `--format=` | `xz`/`lzma`/`raw` ⭐ |
| `-S 后缀` | 自定义后缀 |
| `--memlimit=` | 限制内存（解压大文件时可能需要） ⭐ |

```bash
# 场景：压缩（默认删原文件）⚠️
$ xz big.log
$ ls big.log*
big.log.xz

# 场景：保留原文件 ⭐
$ xz -k big.log

# 场景：多线程压缩大文件（xz 的现代版本支持）⭐⭐
$ xz -T0 -9 -k big.log
$ xz -T0 -e -k big.log              # 极端模式

# 场景：解压 ⭐
$ unxz big.log.xz
$ xz -dk big.log.xz
$ xzcat big.log.xz | head

# 场景：查看压缩信息 ⭐
$ xz -l big.log.xz
Strms  Blocks   Compressed Uncompressed  Ratio  Check   Filename
    1       1     12,345 KiB   1,234,567 KiB  0.010  CRC64   big.log

$ xz -lv big.log.xz

# 场景：校验 ⭐
$ xz -t archive.tar.xz && echo OK

# 场景：多线程 + 与 gzip 对比 ⭐
$ /usr/bin/time -f "gzip -6: %e 秒" gzip -6 -kc big.log > /tmp/a.gz
$ /usr/bin/time -f "xz -T0 -6: %e 秒" xz -T0 -6 -kc big.log > /tmp/a.xz
$ ls -lh /tmp/a.gz /tmp/a.xz

# 场景：限制内存解压（大 xz 文件在低内存机器上）⭐
$ xz -d --memlimit=100MiB big.tar.xz
$ xz -dc --memlimit=100MiB big.tar.xz | tar xf - -C /tmp/

# 场景：xz 与 tar 组合 ⭐
$ tar cJf archive.tar.xz dir/
$ tar xJf archive.tar.xz -C /tmp/
$ tar tf archive.tar.xz | head

# 场景：并发版（pixz，更快且保持 .xz 格式）⭐
$ pixz -t -p"$(nproc)" big.log
$ pixz -d big.log.xz

# 场景：🧪 用 xz 压缩内核源码（发布包常用）
$ ls linux-6.12.tar.xz
$ xz -l linux-6.12.tar.xz
```

#### 输出解读
| 后缀 | 含义 |
|------|------|
| `.xz` | xz 容器格式（LZMA2） |
| `.txz` | tar + xz |
| `.lzma` | 老的单流 LZMA（兼容用） |

`xz -l` 的字段：

| 字段 | 含义 |
|------|------|
| `Strms` | 流数量（多线程会产生多流） ⭐ |
| `Blocks` | 块数量 |
| `Ratio` | 压缩率（**越小越好**） |
| `Check` | 完整性校验算法（`CRC64`/`CRC32`/`SHA256`） ⭐ |

#### 常见坑
- ⚠️ **`xz` 默认删除原文件**，要 `-k` ⭐。
- ⚠️⚠️ **`xz` 解压需要大量内存**（压缩级别越高越多）。`-9` 压的文件解压可能需要**几百 MB 到几 GB**。低内存环境要用 `--memlimit` 或 `-T1` 压缩（单流）⭐。
- ⚠️ **`xz -9` 非常慢**（比 gzip 慢 10 倍以上）。大文件用 `-T0` 并行或降低级别 ⭐。
- ⚠️ **xz 的「多流」文件不能被旧版解压器处理**（`-T0` 会产生多流）。要用单流兼容用 `-T1` ⭐。
- ⚠️ **xz 对损坏非常敏感**：一个字节损坏可能导致整个文件无法解压（不像 gzip 能恢复前面的部分）⭐。
- **xz 对「已经压缩的数据」也几乎无效** ⭐。
- **xz 的压缩率通常是 gzip 的 1/2 到 1/3，但速度慢 5–10 倍**。**现代更推荐 zstd**（速度快得多，压缩率接近）⭐。
- **`tar xJf` 的 `J` 是大写**，容易打成小写 `j`（那是 bzip2）⚠️。

#### 相关命令
`unxz` · `xzcat` · `pixz` · `tar -J` · `gzip` · `zstd` · `lzma`

### zstd — 现代快速压缩

**常用度**：★★★★★ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：非 POSIX，Facebook 开源（Zstandard）

```bash
zstd [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-d` / `--decompress` | 解压 ⭐ |
| `-k` / `--keep` | **保留原文件**（zstd 默认就保留！） ⭐ |
| `-c` | 输出到 stdout ⭐ |
| `-o 文件` | 输出文件名 ⭐ |
| `-1` .. `-19` | 压缩级别（默认 `3`） ⭐ |
| `--ultra -20` .. `-22` | 极端级别（更慢更小） |
| `-T N` / `-T0` | **多线程** ⭐⭐ |
| `-l` | 列出信息 ⭐ |
| `-t` | **校验** ⭐ |
| `--rm` | **压缩后删除原文件**（需显式指定） ⭐ |
| `-f` | 强制 |
| `-v` | 详细 |
| `--long=N` | 长距离匹配（大文件提升压缩率） ⭐ |
| `-D 字典文件` | 用字典（小文件场景） ⭐ |
| `--train` | 训练字典 ⭐ |
| `-r` | 递归 |
| `--adapt` | 自适应调整级别（I/O 受限时有用） ⭐ |

```bash
# 场景：压缩（⭐ 默认保留原文件，比 gzip/xz 更安全）
$ zstd big.log
$ ls big.log*
big.log  big.log.zst

# 场景：压缩后删原文件
$ zstd --rm big.log
$ zstd -k big.log              # -k 是默认行为，可写可不写

# 场景：多线程（zstd 的强项）⭐⭐
$ zstd -T0 -19 -k big.log
$ zstd -T0 -3 -k big.log       # 快得多的级别

# 场景：不同级别的速度与体积对比 ⭐
$ for lvl in 1 3 9 19; do
>   /usr/bin/time -f "zstd -$lvl: %e 秒" zstd -T0 -$lvl -kc big.log > /tmp/b-$lvl.zst 2>/tmp/t
>   cat /tmp/t; ls -lh /tmp/b-$lvl.zst | awk '{print "  体积: " $5}'
> done

# 场景：解压 ⭐
$ zstd -d big.log.zst
$ zstd -dc big.log.zst | head
$ unzstd big.log.zst

# 场景：查看信息与校验 ⭐
$ zstd -l big.log.zst
Frames  Skips  Compressed  Uncompressed  Ratio  Check  Filename
     1      0    12.34 MiB     123.4 MiB  0.100  XXH64  big.log
$ zstd -t archive.tar.zst && echo OK
$ zstd --test big.log.zst

# 场景：与 tar 组合（推荐的大归档方式）⭐⭐
$ tar cf - /data | zstd -T0 -19 -o data.tar.zst
$ zstd -dc data.tar.zst | tar xf - -C /restore
$ tar --zstd -cf data.tar.zst /data              # 现代 tar 支持 --zstd
$ tar --zstd -xf data.tar.zst -C /restore

# 场景：⭐ 比 xz 快得多、比 gzip 小得多
$ /usr/bin/time -f "xz -6:    %e 秒" xz -6 -kc big.log > /tmp/a.xz
$ /usr/bin/time -f "zstd -19: %e 秒" zstd -T0 -19 -kc big.log > /tmp/a.zst
$ /usr/bin/time -f "gzip -6:  %e 秒" gzip -6 -kc big.log > /tmp/a.gz
$ ls -lh /tmp/a.xz /tmp/a.zst /tmp/a.gz

# 场景：字典压缩（大量小文件，如日志/JSON）⭐⭐
$ zstd --train /var/log/*.log -o /tmp/log.dict --maxdict=110KB
$ zstd -D /tmp/log.dict -19 -k small.log
$ zstd -D /tmp/log.dict -d small.log.zst

# 场景：长距离匹配（大文件/数据库导出的压缩率提升明显）⭐
$ zstd --long=27 -T0 -19 -k dump.sql

# 场景：递归压缩目录里每个文件
$ zstd -r -k -T0 /var/log/old/

# 场景：🖥 系统里的 zstd 应用
$ cat /sys/block/nvme0n1/queue/ 2>/dev/null | head
$ systemctl status systemd-zram-setup@zram0 2>/dev/null | head
$ # btrfs 支持 zstd 压缩：
$ mount | grep -i compress
$ # 内核模块与 initramfs 也用 zstd

# 场景：校验与恢复（帧式结构，部分损坏可恢复）⭐
$ zstd -t big.log.zst
$ zstd --list big.log.zst
$ zstd -d big.log.zst -o /tmp/restore.log
```

#### 输出解读
| 后缀 | 含义 |
|------|------|
| `.zst` | zstd |
| `.tzst` | tar + zstd（`.tar.zst` 更常见） |

`zstd -l` 的字段：

| 字段 | 含义 |
|------|------|
| `Frames` | 帧数量（**多帧意味着部分损坏可跳过**） ⭐ |
| `Check` | 校验算法（`XXH64` 默认） ⭐ |
| `Ratio` | 压缩率 |

**zstd 的级别含义**：

| 级别 | 特点 |
|------|------|
| `-1` | 极快（比 gzip -1 快，压缩率相近） |
| `-3` | **默认，速度与压缩率的甜点** ⭐ |
| `-9` | 接近 gzip -9 的体积，快得多 ⭐ |
| `-19` | 接近 xz 的体积，比 xz 快 ⭐ |
| `-22`（`--ultra`） | 极限压缩，很慢（仅归档用） |

#### 常见坑
- ⚠️ **`zstd` 默认保留原文件**（与 gzip/xz 相反）——这是更安全的设计，但要**意识到这一点以免占双份空间** ⭐。
- ⚠️ **`zstd -T0` 的多线程在极小文件上反而更慢**（线程开销）。小文件用单线程 ⭐。
- ⚠️ **`zstd -19` 的解压速度仍然很快**（比 xz 好得多），但**压缩很慢**。归档场景值得用 ⭐。
- ⚠️ **`--long` 需要解压端也有足够内存**（窗口大小），可能造成兼容问题 ⭐。
- ⚠️ **字典压缩需要解压端有同一个字典**，适合固定场景（如日志流水线），不适合通用分发 ⭐。
- **`zstd` 的格式是「帧」结构**，支持并发与拼接（`cat a.zst b.zst | zstd -d` 可工作）⭐。
- **旧版发行版的 tar 可能不支持 `--zstd`**，用管道写法更可移植 ⭐。
- **`zstd` 不需要 `-k`**（默认保留），别习惯性写成 gzip 风格 ⭐。

#### 相关命令
`tar --zstd` · `zstdcat` · `unzstd` · `gzip` · `xz` · `lz4` · `zram`

### lz4 — 极快压缩

**常用度**：★★★☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：非 POSIX

```bash
lz4 [选项] [文件...]
```

| 选项 | 含义 |
|------|------|
| `-d` | 解压 ⭐ |
| `-c` | 输出到 stdout ⭐ |
| `-1` .. `-12` | 压缩级别（默认 `1`，`-9` 以上更慢） ⭐ |
| `-k` | 保留原文件 ⭐ |
| `--rm` | 压缩后删除原文件 ⭐ |
| `-t` | 测试 ⭐ |
| `-l` | 列出信息 |
| `-m` | 多文件（**每文件独立**，可分别解压） ⭐ |
| `--fast=N` | 更快（牺牲压缩率） ⭐ |
| `-B N` | 块大小（`4`–`7`，默认 `7` = 4MB） ⭐ |
| `-T N` | 多线程 ⭐ |
| `-b` | 基准测试 ⭐ |
| `--content-size` | 记录原始大小（便于进度显示） ⭐ |

```bash
# 场景：压缩（默认删原文件？取决于版本）⚠️
$ lz4 big.log big.log.lz4
$ lz4 -k big.log             # 明确保留

# 场景：解压 ⭐
$ lz4 -d big.log.lz4
$ lz4 -dc big.log.lz4 | head
$ unlz4 big.log.lz4

# 场景：多线程大文件 ⭐
$ lz4 -T0 -9 -k big.log

# 场景：测试与信息
$ lz4 -t big.log.lz4 && echo OK
$ lz4 -l big.log.lz4

# 场景：⭐ 速度基准测试（对比其他算法）
$ lz4 -b1 big.log
$ lz4 -b9 big.log
$ /usr/bin/time -f "lz4 -1:  %e 秒" lz4 -1 -c big.log > /tmp/a.lz4
$ /usr/bin/time -f "zstd -3: %e 秒" zstd -3 -c big.log > /tmp/a.zst
$ /usr/bin/time -f "gzip -6: %e 秒" gzip -6 -c big.log > /tmp/a.gz
$ ls -lh /tmp/a.lz4 /tmp/a.zst /tmp/a.gz

# 场景：与 tar 组合
$ tar cf - /data | lz4 -1 > data.tar.lz4
$ lz4 -dc data.tar.lz4 | tar xf - -C /restore

# 场景：多文件模式（每文件独立压缩）
$ lz4 -m -k /var/log/*.log
$ ls /var/log/*.lz4 | head

# 场景：核心里用 lzo 而不是 lz4（zram 场景）⭐
$ cat /sys/block/zram0/comp_algorithm 2>/dev/null
$ echo lz4 | sudo tee /sys/block/zram0/comp_algorithm

# 场景：squashfs 用 lz4（快速文件系统镜像）⭐
$ mksquashfs /data /tmp/data.sqfs -comp lz4 -Xhc

# 场景：🖥 实际应用场景
$ # 1) 内核 initramfs（快速启动）
$ lsinitcpio /boot/initramfs-linux.img 2>/dev/null | head -3 || lsinitramfs /boot/initrd.img-$(uname -r) | head -3
$ # 2) 实时日志压缩
$ tail -f /var/log/app.log | lz4 -1 | split -b 100M - /tmp/log-lz4-
```

#### 输出解读
| 后缀 | 含义 |
|------|------|
| `.lz4` | lz4 帧格式 |
| `.tlz4` | tar + lz4（不常见） |

`lz4 -l` 的字段：`Frame / Type / Block / Compressed / Uncompressed / Ratio / Checksum / Filename`。

#### 常见坑
- ⚠️ **`lz4` 的压缩率很差**（通常只比 gzip 差），**它的价值在速度**（解压速度可达 GB/s 级）⭐。
- ⚠️ **`lz4` 默认级别是 `-1`**（最快），要更小体积用 `-9` 或 `-12`（但会失去速度优势）⭐。
- ⚠️ **`lz4` 的 `-m` 多文件模式与单文件模式的输出格式不同**（一个 `.lz4` 内含多个帧），解压时要 `-m` ⭐。
- ⚠️ **`lz4` 的块大小影响压缩率与内存**（`-B7` 是 4MB，解压时需要相应内存）⭐。
- **旧版 `lz4` 不支持 `-T`（多线程）**（1.9+ 才支持）⭐。
- **`.lz4` 不适合长期归档**（压缩率不佳），**适合「需要快速处理的大数据」**（日志、缓存、initramfs）⭐。
- **lz4 与 lzo 是不同格式**（`.lzo` 要用 `lzop`）⭐。

#### 相关命令
`lz4cat` · `unlz4` · `lzop` · `zstd` · `zram` · `mksquashfs`

```bash

$ zip -r -9 -q code.zip src/ --exclude '*.pyc' --exclude '.git/*'

# 场景：排除模式 ⭐
$ zip -r code.zip . -x '*.git/*' 'node_modules/*' '*.log'
$ zip -r code.zip . -x '*.git/*' -x 'node_modules/*'

# 场景：加密 zip（🔐 注意 zip 的加密强度）⭐
$ zip -e -r secret.zip docs/
Enter password:
Verify password:
$ # ⚠️ Info-ZIP 用传统的 ZipCrypto（弱，可被已知明文攻击）
$ # 强加密用 7z -p 或 gpg
$ 7z a -p -mhe=on -mx=9 secret.7z docs/

# 场景：列出内容 ⭐
$ unzip -l archive.zip
Archive:  archive.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
     1234  2026-09-15 09:30   file1.txt
     5678  2026-09-15 09:30   project/file2.py
---------                     -------
     6912                     2 files
$ unzip -v archive.zip        # 含压缩率与方法 ⭐

# 场景：解压 ⭐
$ unzip archive.zip
$ unzip -o archive.zip -d /tmp/dest        # 覆盖
$ unzip -n archive.zip -d /tmp/dest        # 不覆盖
$ unzip archive.zip '*.txt'                # 只解某类文件 ⭐
$ unzip -j archive.zip -d /tmp/flat        # ⭐ 不保留目录结构

# 场景：⭐ 先看再解（避免 Zip Slip 与覆盖）
$ unzip -l archive.zip | head -20
$ unzip -l archive.zip | grep -E '\.\./|^/|^[A-Za-z]:'    # 🔐 路径穿越检查
$ unzip -o archive.zip -d /tmp/safe/

# 场景：测试完整性 ⭐
$ unzip -t archive.zip
No errors detected in compressed data of archive.zip.
$ zip -T archive.zip

# 场景：只解一个文件到 stdout ⭐
$ unzip -p archive.zip path/to/file.txt | head
$ unzip -p archive.zip config.json | jq .

# 场景：更新归档（只加新文件）⭐
$ zip -u archive.zip newfile.txt
$ zip -r -u archive.zip src/              # 更新变化的部分
$ zip -df archive.zip -x '*.bak'          # ⭐ 从归档删除匹配的文件

# 场景：跨平台（Windows 中文文件名乱码）⭐⭐
$ unzip -O gbk archive.zip -d /tmp/
$ unzip -O cp936 archive.zip
$ # ⭐ -O 指定字符编码（需要 Info-ZIP 编译时支持）
$ # 替代：用 7z 或 iconv
$ 7z x -mcp=936 archive.zip -o/tmp/

# 场景：修复损坏的 zip（部分恢复）⭐
$ zip -FF broken.zip --out fixed.zip
$ zip -FF broken.zip --out fixed.zip -fz

# 场景：🔐 检查 zip 里的可疑内容
$ unzip -l suspicious.zip | grep -E '\.(exe|dll|scr|bat|ps1|hta|lnk|js|vbs)$'
$ unzip -l suspicious.zip | grep -E '^ *[0-9]+.*\s(\S+)$' | wc -l
$ mkdir -p /tmp/review && unzip -o suspicious.zip -d /tmp/review
$ file /tmp/review/* | grep -v text

# 场景：🔐 加密 zip 的密码破解（授权环境 / 忘记密码）
$ zip2john encrypted.zip > /tmp/zip.hash
$ john /tmp/zip.hash --wordlist=/usr/share/wordlists/rockyou.txt
$ fcrackzip -u -D -p /usr/share/wordlists/rockyou.txt encrypted.zip
$ # ⚠️ 仅限自有文件或授权测试
```

#### 输出解读
`unzip -l` 的列：`Length`（**未压缩**大小）、`Date`、`Time`、`Name`。

`unzip -v` 额外有 `Method`（`Defl:N` = 标准 deflate、`Stored` = 不压缩）、`CmpSize`、`Ratio`、`CRC-32` ⭐。

`zip` 的压缩方法：

| 方法 | 说明 |
|------|------|
| `Stored` | 不压缩（`-0`） |
| `Defl:N` | 标准 deflate（默认） |
| `Defl:9` | 最大 deflate（`-9`） |
| `BZIP2` / `LZMA` | 需要特殊编译支持 ⭐ |

#### 常见坑
- ⚠️⚠️ **`zip -r archive.zip dir` 会包含 `dir` 本身**（解压后得到 `dir/...`）。要只打包内容，先进目录再 `zip -r ../archive.zip .` ⭐。
- ⚠️ **`unzip` 默认会询问是否覆盖**，脚本里要显式 `-o`（覆盖）或 `-n`（不覆盖），否则会**卡在交互提示** ⭐。
- ⚠️ **`zip -P 密码` 会把密码留在 shell 历史和进程列表里**。用 `-e` 交互输入或 `zip -e` 配合 `read -s` ⭐。
- ⚠️ **Info-ZIP 的 `-e` 用 ZipCrypto，非常弱**（已知明文攻击可恢复）。保密用途要用 `7z -mhe=on -p` 或 `gpg` ⭐。
- ⚠️ **Zip Slip 漏洞**：恶意 zip 里含 `../../etc/cron.d/x` 这类路径可在解压时写到目标目录外。**解压不可信 zip 前必须检查路径** ⭐⭐。
- ⚠️ **`zip` 不能压标准输入**（只能压文件），要与 tar 结合或先落盘 ⭐。
- ⚠️ **zip 的时间戳只到 2 秒精度**（DOS 格式），且**时区处理有历史 bug** ⭐。
- **单个文件超过 4GB 需要 Zip64**（现代 zip 默认启用，但老工具可能不识别）⭐。
- **`zip` 保存的是「DOS 属性」，不保留 Unix 权限位**（除非用 `-X` 与 Info-ZIP 的扩展）⭐。
- **中文文件名在 Windows 上是 GBK，在 Linux 上是 UTF-8**，跨平台必乱码。用 `-O` 或 7z ⭐。
- **`unzip` 不保留符号链接**（会解成普通文件，除非 zip 是用 `-y` 创建的）⭐。

#### 相关命令
`7z` · `tar` · `gpg` · `zip2john` · `fcrackzip`

### 7z — 7-Zip 格式

**常用度**：★★★★☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：`p7zip` 包；官方是 Windows 版，Linux 用 `p7zip` 或 `7zip`

```bash
7z [命令] [归档] [文件...]
7za [命令] [归档] [文件...]
7zr [命令] [归档] [文件...]
```

| 命令 | 作用 |
|------|------|
| `a` | 添加（创建/追加） ⭐ |
| `x` | **解压并保留目录结构** ⭐ |
| `e` | 解压但不保留目录结构 ⚠️ |
| `l` | 列出内容 ⭐ |
| `t` | 测试 ⭐ |
| `d` | 从归档删除 |
| `u` | 更新 |
| `r` | 重命名归档内文件 |
| `h` | 帮助与**支持的格式** ⭐ |
| `i` | 显示格式与编解码器信息 ⭐ |

| 选项 | 含义 |
|------|------|
| `-p密码` | 密码 ⚠️ |
| `-mhe=on` | **同时加密文件名**（7z 特有） 🔐 ⭐ |
| `-mx=N` | 压缩级别（`0` 不压，`9` 最大） ⭐ |
| `-mmt=N` | 线程数 ⭐ |
| `-o目录` | 输出目录（**没有空格！**） ⚠️ |
| `-x!模式` | 排除 ⭐ |
| `-r` | 递归 |
| `-sdel` | 压缩后删除源文件 ⚠️ |
| `-m0=方法` | 指定压缩算法（`LZMA2`/`LZMA`/`PPMd`/`BZip2`/`Deflate`/`Copy`） ⭐ |
| `-t类型` | 指定归档类型（`7z`/`zip`/`tar`/`gzip`/`xz`） ⭐ |
| `-so` / `-si` | 输出/输入 stdout ⚠️（某些操作不支持） |
| `-y` | 全部回答 yes ⭐ |
| `-bb进度` | 显示进度（`-bb1`） |

```bash
# 场景：创建 7z（压缩率最好）⭐
$ 7z a archive.7z dir/
$ 7z a -mx=9 -mmt=8 archive.7z dir/
$ 7z a -t7z -m0=lzma2 -mx=9 -mfb=64 -md=64m archive.7z dir/    # ⭐ 调优参数

# 场景：🔐 加密 7z（强加密 + 隐藏文件名）⭐⭐
$ 7z a -p -mhe=on -mx=9 secret.7z docs/
Enter password:
Verify password:
$ # ⭐ -mhe=on 让文件名也被加密（zip 做不到）
$ # 7z 用 AES-256，比 zip 的 ZipCrypto 强得多

# 场景：列出内容 ⭐
$ 7z l archive.7z
$ 7z l -slt archive.7z | head -40      # 技术细节（含 CRC、方法）

# 场景：解压 ⭐
$ 7z x archive.7z                       # 保留目录结构
$ 7z x archive.7z -o/tmp/dest           # ⚠️ -o 后不能有空格
$ 7z x archive.7z -o/tmp/dest -y        # ⭐ -y 覆盖不询问
$ 7z e archive.7z                       # ⚠️ 不保留目录结构（可能同名冲突）

# 场景：解压加密的 7z ⭐
$ 7z x -p secret.7z
$ 7z x -pMyPassword secret.7z -o/tmp/    # ⚠️ 密码会留在历史里

# 场景：测试完整性 ⭐
$ 7z t archive.7z
Everything is Ok

# 场景：查看支持的格式与编解码器 ⭐
$ 7z i | head -30
$ 7z h | head -20

# 场景：⭐ 7z 也能处理其他格式（万能工具）
$ 7z l archive.zip
$ 7z x archive.tar.gz
$ 7z x archive.tar.xz
$ 7z x archive.rar          # 需要 p7zip-rar / 7zip-rar 插件 ⭐
$ 7z x archive.iso
$ 7z a backup.tar.zst dir/   # 创建 zstd 压缩的 tar
$ 7z a -tgzip out.gz file

# 场景：处理 Windows zip 的中文乱码 ⭐⭐
$ 7z x legacy-gbk.zip -mcp=936 -o/tmp/out
$ 7z l legacy-gbk.zip -mcp=936

# 场景：排除文件 ⭐
$ 7z a code.7z . -xr!'.git' -xr!'node_modules' -xr!'*.log'

# 场景：只解压归档中的某类文件 ⭐
$ 7z x archive.7z '*.conf' -o/tmp/conf
$ 7z x archive.7z -r 'config/*'

# 场景：压缩后删除源文件（移动语义）⚠️
$ 7z a -sdel moved.7z dir/

# 场景：分卷（大归档）⭐
$ 7z a -v2g big.7z /data
$ ls big.7z.001 big.7z.002 ...
$ 7z x big.7z.001 -o/restore        # 只指定第一个分卷即可

# 场景：🔐 审计归档里的可疑文件
$ 7z l suspicious.7z | grep -E '\.(exe|dll|scr|bat|ps1|vbs|js|lnk)$'
$ 7z l -slt suspicious.7z | grep -E 'Path =|Encrypted|Method ='
$ mkdir -p /tmp/review && 7z x suspicious.7z -o/tmp/review -y
$ file /tmp/review/* | grep -v 'text\|empty'

# 场景：🔐 7z 密码破解（授权环境）
$ 7z2hashcat archive.7z > /tmp/7z.hash   # 需要 7z2hashcat 工具
$ john /tmp/7z.hash --wordlist=rockyou.txt
$ hashcat -m 11600 /tmp/7z.hash rockyou.txt
```

#### 输出解读
`7z l` 的列：`Date`、`Time`、`Attr`、`Size`、`Compressed`、`Name`。`Attr` 里 `D` 表示目录，`A` 表示有属性 ⭐。

`7z l -slt`（技术列表）的关键字段：

| 字段 | 含义 |
|------|------|
| `Path` | 路径 |
| `Size` / `Packed Size` | 原始/压缩后大小 |
| `Modified` | 修改时间 |
| `Attributes` | 属性 |
| `CRC` | 校验值 ⭐ |
| `Encrypted` | **是否加密**（`+`/`-`） 🔐 ⭐ |
| `Method` | 压缩方法（如 `LZMA2:24`） ⭐ |
| `Solid` | 是否固实压缩 ⭐ |
| `Blocks` | 流数量 |

**固实压缩（Solid）**：把所有文件作为一个数据流压缩，压缩率更高，但**改一个文件要重压整包**，且**部分损坏无法恢复其他文件** ⭐。

#### 7z vs zip
| 维度 | 7z | zip |
|------|-----|-----|
| 压缩率 | **好得多** ⭐ | 中 |
| 加密强度 | **AES-256** ⭐ | ZipCrypto（弱） |
| 隐藏文件名 | ✅ `-mhe=on` ⭐ | ❌ |
| 跨平台兼容 | 需装 7-Zip | **Windows 原生支持** ⭐ |
| 速度 | 慢（尤其 `-mx=9`） | 快 |
| 分卷 | ✅ | 需第三方 |

#### 常见坑
- ⚠️⚠️ **`-o目录` 后不能有空格**！`7z x a.7z -o /tmp/dest` 会被解析成 `-o` 加空目录名，结果是解到当前目录 ⭐⭐。
- ⚠️ **`7z e`（不保留目录结构）会在同名文件时冲突或覆盖**，通常应该用 `x` ⭐。
- ⚠️ **`-p密码` 会留在 shell 历史与进程列表里**。用交互式 `-p`（不带值）⚠️。
- ⚠️ **`-mhe=on` 只在创建时指定**（且只对 7z 格式有效），对已有归档无效 ⭐。
- ⚠️ **`.rar` 的解压需要额外的 rar 插件**（`p7zip-rar` 或 `7zip` 的 rar 模块），且**发行版可能因许可问题不含它** ⭐。
- ⚠️ **固实压缩的归档无法随机访问**（要按顺序解压），且**一字节损坏会让后续都读不了** ⭐。
- **`7z` 与 `7za` 与 `7zr` 的区别**：
  - `7z`：完整版（依赖外部编解码库）
  - `7za`：独立版（内置常用编解码）
  - `7zr`：仅 7z 格式（最小）
- **`7z` 的压缩级别 `-mx=9` 很慢**，日常用默认或 `-mx=5` ⭐。
- **`p7zip` 已停止维护**，新项目用 `7zip`（官方 Linux 版）⭐。
- **`7z` 不支持 Unix 权限位的完整保留**（它是跨平台格式）⭐。

#### 相关命令
`zip` · `tar` · `gpg` · `7z2hashcat` · `hashcat -m 11600`

### rar / unrar — RAR 格式

**常用度**：★★☆☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：`rar`（创建，**专有软件**）与 `unrar`（解压，免费）

> ⚠️ **`rar` 的创建工具是专有/试用软件**（有 40 天试用期）。`unrar` 免费但**许可证不允许用于创建 RAR**。

```bash
rar [命令] 归档 文件...
unrar [命令] 归档
```

| rar 命令 | 作用 |
|----------|------|
| `a` | 添加/创建 ⭐ |
| `x` | 解压（保留路径） ⭐ |
| `l` | 列出 ⭐ |
| `t` | 测试 |
| `e` | 解压（不保留路径） |
| `u` | 更新 |
| `d` | 删除 |

| unrar 命令 | 作用 |
|------------|------|
| `x` | 解压并保留路径 ⭐ |
| `e` | 解压但不保留路径 ⚠️ |
| `l` | 简短列表 ⭐ |
| `lt` | 详细列表 |
| `t` | 测试 ⭐ |
| `p` | 输出到 stdout ⭐ |
| `v` | 详细列表（同 `lt`） |

| 常用选项 | 含义 |
|----------|------|
| `-p密码` | 密码 ⚠️ |
| `-hp密码` | **连文件名一起加密** 🔐 ⭐ |
| `-m0`..`-m5` | 压缩级别（`0` 存储，`5` 最大） ⭐ |
| `-v大小` | 分卷（`-v2g`） ⭐ |
| `-r` | 递归 ⭐ |
| `-x模式` | 排除 ⭐ |
| `-y` | 全部确认 ⭐ |
| `-o+` / `-o-` | 覆盖 / 不覆盖 ⭐ |
| `-ep1` | 不保留顶层目录 |
| `-ma版本` | RAR 格式版本（`4` 或 `5`） ⭐ |
| `-rr N%` | 恢复记录（容错） ⭐ |
| `-re` | 恢复卷 |

```bash
# 场景：创建 RAR（⚠️ 需要 rar 工具）
$ rar a archive.rar dir/
$ rar a -m5 -md4g archive.rar dir/         # 最高压缩

# 场景：🔐 加密 RAR（含文件名）⭐
$ rar a -p -hp secret.rar docs/
$ # -hp 加密文件名与内容（-p 只加密内容）

# 场景：列出 ⭐
$ unrar l archive.rar
$ unrar lt archive.rar                # 详细（含 CRC）
$ rar l archive.rar

# 场景：解压 ⭐
$ unrar x archive.rar
$ unrar x archive.rar /tmp/dest/      # 解到指定目录
$ unrar e archive.rar                 # ⚠️ 不保留目录结构
$ unrar x -o+ archive.rar             # 覆盖
$ unrar x -o- archive.rar             # 不覆盖
$ unrar -y x archive.rar              # 全部确认 ⭐

# 场景：测试完整性 ⭐
$ unrar t archive.rar
$ rar t archive.rar

# 场景：只解压某类文件 ⭐
$ unrar x archive.rar '*.txt'
$ unrar x archive.rar 'config/*'

# 场景：输出到 stdout ⭐
$ unrar p archive.rar path/to/file.txt | head

# 场景：分卷解压 ⭐
$ unrar x archive.part1.rar
$ ls archive.part*.rar
archive.part1.rar  archive.part2.rar  archive.part3.rar

# 场景：带恢复记录的 RAR（抗损坏）⭐
$ rar a -rr5p archive.rar dir/
$ unrar r archive.rar                 # 尝试修复

# 场景：🔐 检查 RAR 里的可疑内容
$ unrar l suspicious.rar | grep -E '\.(exe|dll|scr|bat|ps1|lnk)$'
$ unrar l suspicious.rar | grep -E '\.\./|^/'
$ unrar l -p- suspicious.rar          # 尝试列出（若是加密会失败）

# 场景：🔐 RAR 密码破解（授权环境）
$ rar2john encrypted.rar > /tmp/rar.hash
$ john /tmp/rar.hash --wordlist=rockyou.txt
$ hashcat -m 13000 /tmp/rar.hash rockyou.txt
$ # ⚠️ RAR5 的破解比 RAR4 慢得多（KDF 更强）

# 场景：🧪 用 7z 处理 RAR（避免装 rar）⭐
$ 7z l archive.rar
$ 7z x archive.rar -o/tmp/out
$ # 需要 7z 的 rar 插件
```

#### 输出解读
`unrar lt` 的字段：

| 字段 | 含义 |
|------|------|
| `Name` | 路径 |
| `Type` | `File` / `Directory` |
| `Size` | 原始大小 |
| `Packed` | 压缩后大小 |
| `Ratio` | 压缩率 |
| `CRC32` | 校验 |
| `Attributes` | 属性 |
| `Host OS` | 创建时操作系统 |
| `Flags` | 加密、固实等标志 🔐 |

#### 常见坑
- ⚠️ **`rar`（创建）是专有软件**，很多发行版不预装，需从 rarlab.com 下载。**`unrar` 免费但许可证禁止用于创建** ⭐。
- ⚠️ **`unrar e` 不保留目录结构**，同名文件会互相覆盖。默认用 `x` ⭐。
- ⚠️ **RAR5 格式的固实压缩 + 强 KDF** 让密码破解极慢（设计上如此）⭐。
- ⚠️ **`-hp`（加密文件名）与 `-p`（只加密内容）不同**，前者更安全但列表也需要密码 ⭐。
- ⚠️ **`.rar` 在 Linux 上的支持不如 zip/7z 好**，跨平台分发优先用 zip 或 7z ⭐。
- **RAR 的恢复记录（`-rr`）能修复一定比例的损坏**（对光盘/传输错误有用）⭐。
- **`unrar` 和 `unrar-free` 不同**：`unrar-free` 不支持 RAR5 与部分特性 ⭐。
- **分卷 RAR 只需指定第一个文件**（`.part1.rar`），但所有分卷必须都在 ⭐。
- **RAR 是专有格式**，无法自己实现完整兼容（无公开的完整规范）。

#### 相关命令
`7z` · `zip` · `rar2john` · `john` · `hashcat`

### cpio — 归档与复制

**常用度**：★★★☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：POSIX 定义了三种模式；GNU cpio 支持更多格式

```bash
cpio -o [选项]           # 创建归档（copy-out），从 stdin 读文件名列表
cpio -i [选项]           # 解出归档（copy-in）
cpio -p [选项] 目标目录   # 复制（pass-through），不创建归档
```

| 选项 | 含义 |
|------|------|
| `-o` / `--create` | 创建归档 ⭐ |
| `-i` / `--extract` | 解出 ⭐ |
| `-p` / `--pass-through` | 复制模式 ⭐ |
| `-d` / `--make-directories` | 自动创建目录 ⭐ |
| `-v` | 详细 ⭐ |
| `-t` | 列出内容（不改动） ⭐ |
| `-m` | 保留 mtime ⭐ |
| `-u` | 无条件覆盖 ⭐ |
| `--no-absolute-filenames` | **去掉绝对路径（安全）** 🔐 ⭐ |
| `--absolute-filenames` | 保留绝对路径 ⚠️ |
| `-H 格式` | 归档格式（`bin` `odc` `newc` `crc` `tar` `ustar` `hpbin` `hpodc`） ⭐ |
| `-F 文件` | 用指定归档文件（替代 stdin/stdout） ⭐ |
| `-A` | 追加到已有归档 ⭐ |
| `-L` | 跟随符号链接 |
| `-0` / `--null` | 输入用 NUL 分隔（配 `find -print0`） ⭐⭐ |
| `--quiet` | 安静 |
| `-a` | 重置 atime |
| `-B` | 用 5120 字节块 |

```bash
# 场景：最经典的用法（与 find 管道配合）⭐⭐
$ find /path -depth -print0 | cpio --null -ov --format=newc > archive.cpio

# 场景：解出 ⭐
$ cpio -idv < archive.cpio
$ cpio -idmv < archive.cpio                 # 保留 mtime
$ cpio -idv --no-absolute-filenames < archive.cpio    # 🔐 安全解出

# 场景：列出内容 ⭐
$ cpio -tv < archive.cpio
$ cpio -tv < archive.cpio | head -20

# 场景：⭐ 处理内核 initramfs（cpio 最实际的用途）
$ ls /boot/initramfs-linux.img
$ # 解出 initramfs
$ mkdir -p /tmp/initrd && cd /tmp/initrd
$ zstd -dc /boot/initramfs-linux.img 2>/dev/null | cpio -idmv
$ # 或（gzip 压缩的 initramfs）
$ zcat /boot/initrd.img-$(uname -r) | cpio -idmv
$ ls
bin  dev  etc  init  ...

$ # 重新打包 initramfs
$ find . -print0 | cpio --null -o --format=newc | zstd -T0 > /tmp/new-initramfs.img

# 场景：提取 RPM 的内容（不安装）⭐⭐
$ rpm2cpio package.rpm | cpio -idmv -D /tmp/unpacked
$ ls /tmp/unpacked
$ rpm2cpio package.rpm | cpio -t | head    # 只列出
$ rpm2cpio package.rpm | cpio -idmv './etc/*' -D /tmp/only-etc    # 只提某类

# 场景：提取 DEB 与 tar 的混淆场景（tar 更合适）
$ ar p package.deb data.tar.xz | tar xJf - -C /tmp/

# 场景：pass-through 模式（相当于带归档语义的复制）⭐
$ find /src -depth -print0 | cpio -pdmv --null /dst
$ # ⭐ 与 cp -a 类似，但保留完整的目录结构与属性

# 场景：追加到已有归档（仅 newc 格式）⭐
$ find /more -depth -print | cpio -oA -H newc -F archive.cpio

# 场景：🔐 安全解出不可信归档（防路径穿越）⭐⭐
$ cpio -idv --no-absolute-filenames --quiet < suspicious.cpio
$ # 或先检查列表
$ cpio -tv < suspicious.cpio | grep -E '^l|\.\./|^/'

# 场景：🧪 与 tar 的对比 ⭐
$ # tar：更友好，支持压缩、有 -C、排除更灵活
$ # cpio：流式、与 find 配合好、initramfs 标准格式
$ find /etc -name '*.conf' -print0 | cpio -o0 -H newc > /tmp/etc.cpio
$ ls -lh /tmp/etc.cpio
$ tar czf /tmp/etc.tar.gz $(find /etc -name '*.conf')
$ ls -lh /tmp/etc.tar.gz
```

#### 输出解读
`cpio -tv` 的输出格式：
```
-rw-r--r--   1 root     root         1234 Sep 15 09:30 etc/nginx/nginx.conf
│            │ │        │            │    │             └─ 路径
│            │ │        │            │    └─ 时间
│            │ │        │            └─ 大小
│            │ │        └─ 属组
│            │ └─ 属主
│            └─ 硬链接数
└─ 权限
```

`cpio -o` 的块统计输出：
```
12345 blocks
```
（块大小默认 512 字节，所以 `12345 × 512 ≈ 6.3 MB`）⭐

**cpio 的三种模式**：

| 模式 | 输入 | 输出 | 用途 |
|------|------|------|------|
| `-o`（copy-out） | 文件名列表（stdin） | 归档（stdout） | 创建归档 |
| `-i`（copy-in） | 归档（stdin） | 文件 | 解出 |
| `-p`（pass-through） | 文件名列表（stdin） | 直接复制 | 复制（无归档） |

#### 常见坑
- ⚠️ **`cpio -o` 从 stdin 读文件名列表，归档写到 stdout**。方向搞反会得到空归档或挂起 ⭐。
- ⚠️ **必须用 `-print0` + `--null`**，否则含空格/换行的文件名会出错 ⭐。
- ⚠️ **`cpio -i` 默认会覆盖已存在文件**（且比归档中旧的也会覆盖，除非用 `-u` 的反面）。行为与 tar 不同 ⭐。
- ⚠️ **`cpio` 默认会保留归档里的绝对路径**（可能覆盖系统文件）。**始终加 `--no-absolute-filenames`** 🔐 ⭐。
- ⚠️ **`cpio` 不自己做压缩**，要配 `gzip`/`zstd` 管道 ⭐。
- **`cpio` 的格式选择**：`newc` 是 initramfs 的标准（支持 >2GB 文件、CRC）⭐；`odc` 是老的 POSIX 格式（限制文件名 255 字节）。
- **`cpio` 对「空目录」的处理需要 `-d`**（自动创建目录）⭐。
- **`find -depth` 很重要**：确保先处理目录内容再处理目录本身（避免目录 mtime 被后续修改）⭐。
- **现代场景下 `cpio` 主要用于 initramfs 与提取 RPM**，通用归档用 tar ⭐。

#### 相关命令
`tar` · `find -print0` · `rpm2cpio` · `dracut` · `mkinitcpio` · `pax`

### ar — 静态库归档

**常用度**：★★★☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：GNU binutils 版；BSD 版选项不同

```bash
ar [选项] 归档 [成员...]
```

| 选项 | 含义 |
|------|------|
| `-r` | 插入/替换成员 ⭐ |
| `-q` | 快速追加（不检查重复） |
| `-d` | 删除成员 |
| `-t` | 列出成员 ⭐ |
| `-p` | 打印成员内容到 stdout ⭐ |
| `-x` | 解出成员 ⭐ |
| `-v` | 详细 ⭐ |
| `-s` | 写索引（等同 `ranlib`） ⭐ |
| `-c` | 创建归档（不警告） |
| `-D` | 确定性模式（**可复现构建**） ⭐⭐ |
| `-U` | 不确定模式（用真实时间戳/UID/GID） |
| `-M` | 用 MRI 脚本 |
| `-a` / `-b` / `-i` | 位置修饰（在成员前/后插入） |
| `--plugin` | 用插件（如 LTO） |

**修饰符**（与 `-r`/`-d` 配合）：`a`（后）、`b`（前）、`i`（前）。

```bash
# 场景：🔥 `ar` 最实际的用途——检查 .deb 包结构 ⭐⭐
$ ar t package.deb
debian-binary
control.tar.zst
data.tar.zst
# ⭐ .deb 就是 ar 归档，含三个成员

$ ar p package.deb debian-binary
2.0

$ # 只看控制信息（含安装脚本）
$ ar p package.deb control.tar.zst | zstd -dc | tar tvf - | head
$ ar p package.deb control.tar.zst | zstd -dc | tar xf - -C /tmp/debctl
$ cat /tmp/debctl/postinst        # 🔐 安装脚本

$ # 解出全部成员（不安装）
$ mkdir -p /tmp/deb-extract && cd /tmp/deb-extract
$ ar x /path/package.deb
$ ls
control.tar.zst  data.tar.zst  debian-binary
$ tar xf data.tar.zst -C /tmp/deb-data
$ find /tmp/deb-data -type f -perm -4000    # 🔐 找 SUID

# 场景：创建静态库（编译原理）⭐⭐
$ cat > /tmp/add.c <<'EOF'
int add(int a, int b) { return a + b; }
EOF
$ cat > /tmp/mul.c <<'EOF'
int mul(int a, int b) { return a * b; }
EOF
$ gcc -c /tmp/add.c -o /tmp/add.o
$ gcc -c /tmp/mul.c -o /tmp/mul.o
$ ar rcs /tmp/libmath.a /tmp/add.o /tmp/mul.o
$ ar t /tmp/libmath.a
add.o
mul.o
$ nm /tmp/libmath.a | grep ' T '
0000000000000000 T add
0000000000000000 T mul

# 场景：⭐ 确定性构建（可复现，CI 必须）
$ ar rcsD /tmp/libmath.a /tmp/add.o /tmp/mul.o
$ # 或全局设：export ARFLAGS=rcsD
$ # ⭐ -D 会归零时间戳/UID/GID/权限，让构建可复现

# 场景：查看归档内容 ⭐
$ ar t /tmp/libmath.a
$ ar tv /tmp/libmath.a
rw-r--r-- 0/0   1234 Jan  1 00:00 1970 add.o

# 场景：解出成员 ⭐
$ cd /tmp/out && ar x /tmp/libmath.a
$ ls
add.o  mul.o

# 场景：删除成员
$ ar d /tmp/libmath.a mul.o
$ ar t /tmp/libmath.a

# 场景：更新索引（符号表）
$ ar s /tmp/libmath.a
$ ranlib /tmp/libmath.a        # 等价

# 场景：🔐 检查静态库里的符号（可能含后门）⭐
$ nm -C /tmp/libmath.a | grep -E ' T | t ' | head
$ strings /tmp/libmath.a | grep -E 'http|/tmp/|curl' | head

# 场景：用静态库链接程序 ⭐
$ cat > /tmp/main.c <<'EOF'
#include <stdio.h>
int add(int, int);
int main(void) { printf("%d\n", add(2, 3)); return 0; }
EOF
$ gcc /tmp/main.c /tmp/libmath.a -o /tmp/test && /tmp/test
5
$ gcc /tmp/main.c -L/tmp -lmath -o /tmp/test2       # 用 -l 形式

# 场景：🔐 检查 .deb 的成员（避免用 dpkg-deb 时被 hook）
$ file package.deb
package.deb: Debian binary package (format 2.0), ...
$ ar t package.deb | head
$ ar p package.deb control.tar.xz | xz -dc | tar tvf - | head
```

#### 输出解读
`ar tv` 的输出：
```
rw-r--r-- 0/0   1234 Jan  1 00:00 1970 add.o
│          │     │    │              └─ 成员名
│          │     │    └─ 时间戳
│          │     └─ 大小
│          └─ UID/GID
└─ 权限（-D 模式下归零）
```

**`ar` 的两个实际用途**：
1. **`.deb` 包的本质是 ar 归档**（含 `debian-binary`、`control.tar.*`、`data.tar.*`）⭐
2. **静态库 `.a` 是 ar 归档**（成员是 `.o` 文件）⭐

#### 常见坑
- ⚠️ **`.deb` 是 ar 归档，但 `.a` 用 GNU ar 的标准格式**：两者格式兼容，但 **`.deb` 的成员名以 `debian-binary` 开头**，且 ar 的格式必须是「GNU 或 BSD 变体」（用 `ar t` 能读）⭐。
- ⚠️ **不要用 `ar` 修改 `.deb`**（会破坏签名与校验），只用 `ar t` / `ar p` / `ar x` **读取** ⭐。
- ⚠️ **静态库必须用 `-D`（确定性模式）**才能可复现构建。否则时间戳会让两次构建的字节不同 ⭐⭐。
- ⚠️ **`ar` 的 `-q` 不检查重复**，重复添加同名成员会让链接器行为异常 ⭐。
- ⚠️ **改了成员后必须 `ar s`（更新索引）**，否则链接器找不到符号 ⭐。
- **GNU ar 与 BSD ar 的选项集不同**（BSD 的 `ar` 用 `-r`/`-t`/`-x` 但少一些修饰符）⭐。
- **`.a` 静态库会显著增大可执行文件**（代码被复制进去），且**更新库需要重新链接** ⭐。
- **`ar` 的默认格式有多个变体**（GNU、BSD、DRI），跨平台时用 `--format` 指定 ⭐。
- **现代构建系统用 `ar` 是通过 `gcc-ar`/`llvm-ar`**（为了处理 LTO），不直接调用 ⭐。

#### 相关命令
`ranlib` · `nm` · `objdump` · `gcc-ar` · `dpkg-deb` · `tar`

### pax — POSIX 归档

**常用度**：★★☆☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：POSIX 标准归档工具（替代 tar 与 cpio 的 POSIX 版本）

```bash
pax [选项] [模式] [文件...]
```

| 模式 | 作用 |
|------|------|
| `-r` | **读**归档（解出） ⭐ |
| `-w` | **写**归档（创建） ⭐ |
| `-r -w` | 复制（相当于 cpio 的 pass-through） ⭐ |

| 选项 | 含义 |
|------|------|
| `-f 归档` | 归档文件（`-` = stdin/stdout） ⭐ |
| `-v` | 详细 ⭐ |
| `-d` | 仅匹配目录 |
| `-x 模式` | 排除 ⭐ |
| `-t` | 列出 |
| `-0` | NUL 分隔（配 `find -print0`） ⭐ |
| `-z` | gzip 压缩（**GNU/BSD 扩展，非 POSIX**） ⭐ |
| `-j` / `-J` | bzip2 / xz（扩展） |
| `-H` / `-L` | 跟随/不跟随符号链接 |
| `-X` | 不跨越设备边界 ⭐ |
| `-P` | 保留绝对路径 ⚠️ |
| `-o 格式` | 输出格式（`ustar`/`posix`/`gposix`/`bposix`） ⭐ |
| `-s 替换` | 路径替换（类 sed） ⭐ |
| `-p 保留` | 保留属性（`e`=权限、`m`=mtime、`o`=属主、`a`=atime） ⭐ |
| `-T 时间范围` | 按 atime/mtime 过滤 ⭐ |
| `-U` | 解出时按归档里的属主 ⭐ |
| `-n` | 只匹配第一个文件 |
| `-N` | 用每个文件的 mtime |

```bash
# 场景：创建归档（写模式）⭐
$ find /path -print0 | pax -w0zv -f archive.tar.gz
$ pax -wv -f archive.tar dir/
$ pax -wv -f archive.tar.gz -z dir/          # ⭐ -z gzip 压缩

# 场景：指定格式（跨平台兼容）⭐
$ pax -w -f archive.tar -x ustar dir/
$ pax -w -f archive.tar -x posix dir/        # POSIX.1-2001 格式
$ pax -w -f archive.tar -x gposix dir/       # GNU 扩展

# 场景：解出 ⭐
$ pax -rv -f archive.tar.gz
$ pax -rv -f archive.tar -C /tmp/dest        # ⚠️ pax 没有 -C（要用 cd）
$ cd /tmp/dest && pax -rv -f /path/archive.tar

# 场景：列出内容 ⭐
$ pax -v -f archive.tar | head
$ pax -f archive.tar -v -r -n /dev/null 2>/dev/null || pax -v -r -f archive.tar -n | head

# 场景：过滤（pax 的独特能力）⭐
$ pax -w -f small.tar -z -T '@2026-09-01' -T '@2026-09-15' /data
$ # -T 按 mtime 范围过滤

# 场景：排除模式 ⭐
$ pax -w -f archive.tar -x '*.log' -x '.git/*' dir/
$ pax -w0 -f archive.tar $(find dir -print0 | grep -zv '\.git')

# 场景：路径替换（重命名归档中的路径）⭐⭐
$ pax -w -f archive.tar -s ',^/old/prefix,/new/prefix,' -s ',\.txt$,.bak,p' dir/
$ # -s 语法与 sed 类似：-s /正则/替换/修饰符
$ # 修饰符：g=全局、p=打印、i=忽略大小写

# 场景：复制模式（-r -w）⭐
$ mkdir -p /dst && cd /src && pax -rw -p e . /dst
$ # ⭐ 相当于 cp -a，但能保留 POSIX 属性

# 场景：保留属性 ⭐
$ pax -rw -p emo -f - src/ | (cd /dst && pax -rw -p emo)
$ # e=权限, m=mtime, o=属主

# 场景：🧪 与 tar/cpio 的对比 ⭐
$ # pax 的定位：POSIX 标准化的 tar + cpio 替代
$ # 优点：标准、支持大文件、支持路径替换、格式可控
$ # 缺点：实际使用少、选项不直观、GNU tar 更强大且更普及
$ tar czf a.tar.gz dir/ && pax -wzv -f b.tar.gz dir/
$ ls -lh a.tar.gz b.tar.gz
$ tar tzf a.tar.gz | head && pax -v -f b.tar.gz | head

# 场景：🔐 检查与安全解出
$ pax -v -f suspicious.tar | grep -E '^l|\.\./|^/'
$ cd /tmp/safe && pax -rv -f /path/to/suspicious.tar
$ # 不要用 -P（保留绝对路径）
```

#### 输出解读
`pax -v -f archive` 的输出格式与 `tar tv` 类似：
```
-rw-r--r--  1 root   root      1234 Sep 15 09:30 etc/nginx/nginx.conf
```

**pax 的三个模式与 tar/cpio 的对应**：

| pax | tar | cpio |
|-----|-----|------|
| `-w`（写） | `tar -c` | `cpio -o` |
| `-r`（读） | `tar -x` | `cpio -i` |
| `-rw`（复制） | — | `cpio -p` |

#### 常见坑
- ⚠️ **`pax` 没有 `-C` 选项**（这一点不如 tar 方便），要 `cd` 或 `-s` 替换路径 ⭐。
- ⚠️ **`-z`/`-j`/`-J` 是扩展**（POSIX pax 不含压缩），跨系统时可能不支持 ⭐。
- ⚠️ **`pax` 的实现差异较大**（GNU/BSD/libarchive 版行为不同），依赖它写可移植脚本很危险 ⭐。
- ⚠️ **`pax` 的 `-x` 在写模式是「格式」，在读模式是「排除」**（语义完全不同）⚠️ 极易误用 ⭐。
- ⚠️ **`-s` 替换语法容易写错**（正则与分隔符），先用 `-n`（dry run）验证。
- **很多系统上 `pax` 是到 `tar` 或 `libarchive` 的符号链接**（实际用的是别的实现）⭐。
- **`pax` 在现代 Linux 上使用极少**（tar 与 cpio 更普及），主要出现在 BSD 与 POSIX 兼容性要求高的场景 ⭐。
- **GNU tar 的 `-H pax` 能生成 POSIX pax 格式的归档**，比直接用 pax 更常见 ⭐。

#### 相关命令
`tar` · `cpio` · `libarchive` · `bsdtar`

### zcat / zless / zgrep — 直接读压缩文件

**常用度**：★★★★☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：各发行版提供的集合不同（`zutils` 提供统一前端）

```bash
zcat [文件...]            # 解压到 stdout
zless [文件...]           # 用 less 分页
zgrep [选项] 模式 [文件...]  # 在压缩文件里搜索
zmore [文件...]           # 用 more 分页
zdiff / zcmp              # 比较
znew / zipsplit           # 格式转换 / 分卷
```

| 工具 | 对应的未压缩工具 | 说明 |
|------|------------------|------|
| `zcat` | `cat` | 解压到 stdout ⭐ |
| `zless` | `less` | 分页浏览 ⭐ |
| `zmore` | `more` | 分页 |
| `zgrep` | `grep` | **搜索压缩文件** ⭐⭐ |
| `zegrep` / `zfgrep` | `egrep` / `fgrep` | 对应的正则变体 |
| `zdiff` | `diff` | 比较压缩文件 |
| `zcmp` | `cmp` | 字节比较 |

**`zutils` 的统一前端**（Arch/Debian 有提供）：

| 工具 | 说明 |
|------|------|
| `zcat` | 支持 gz/bz2/xz/zst/lz4 **自动识别** ⭐⭐ |
| `zgrep` | 同上 |
| `ztest` | 测试完整性 |
| `zupdate` | 重新压缩到指定格式 |
| `zcmp` / `zdiff` | 比较 |

```bash
# 场景：读 gzip 文件 ⭐
$ zcat app.log.gz | head -20
$ zcat app.log.gz | wc -l
$ zcat app.log.gz > app.log              # 解压到文件

# 场景：⭐ 在压缩日志里搜索（最常用）
$ zgrep 'ERROR' /var/log/app.log.2.gz
$ zgrep -c 'ERROR' /var/log/*.gz
$ zgrep -n 'timeout' app.log.*.gz
$ zgrep -A3 -B1 'Exception' app.log.1.gz | head -20
$ zcat app.log.gz | grep -n 'pattern'    # 等价写法（更慢，因为多一个进程）

# 场景：⭐ 搜索多个压缩文件并带文件名
$ zgrep -H 'ERROR' /var/log/app.log*.gz | head
$ zgrep -l 'CRITICAL' /var/log/*.gz      # 只输出含匹配的文件名 ⭐

# 场景：分页浏览 ⭐
$ zless app.log.gz
$ zless -R app.log.gz                    # 保留颜色
$ # 在 zless 里可以正常用 / 搜索、G 到末尾

# 场景：比较两个压缩文件 ⭐
$ zdiff a.log.gz b.log.gz
$ zdiff <(zcat a.log.gz) <(zcat b.log.gz)     # 或用进程替换

# 场景：测试完整性（批量）⭐
$ for f in /var/log/*.gz; do gzip -t "$f" || echo "损坏: $f"; done
$ ztest /var/log/*.gz 2>/dev/null            # zutils 版

# 场景：⭐ 在压缩文件里统计（不用解压到磁盘）
$ zcat access.log.gz | awk '{print $1}' | sort | uniq -c | sort -rn | head -10
$ zgrep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' access.log.gz | sort -u | head

# 场景：🧪 处理多种压缩格式（zutils 的自动识别）⭐⭐
$ zcat app.log.gz
$ zcat app.log.bz2
$ zcat app.log.xz
$ zcat app.log.zst
$ # ⭐ zutils 版 zcat 不需要关心格式

# 场景：格式转换 ⭐
$ zcat old.log.gz | zstd -T0 -19 -o new.log.zst
$ zupdate -z -k app.log.gz                     # 原地重新压缩

# 场景：zdiff 用于配置备份对比 ⭐
$ zdiff nginx.conf.1.gz nginx.conf.2.gz
$ zcat nginx.conf.1.gz | diff - nginx.conf     # 与当前文件比较

# 场景：🔐 在压缩日志里检索入侵痕迹 ⭐⭐
$ zgrep -E 'Failed password|Invalid user' /var/log/auth.log*.gz | tail -20
$ zgrep -h 'Accepted publickey' /var/log/auth.log*.gz | awk '{print $1, $2, $9, $11}' | sort -u
$ zcat /var/log/nginx/access.log*.gz | awk '{print $1}' | sort | uniq -c | sort -rn | head -20
$ zgrep -E '\.\./|union.*select|<script' /var/log/nginx/access.log*.gz | head

# 场景：🔐 检查压缩归档里是否含敏感文件 ⭐
$ zcat suspicious.gz | strings | grep -E 'BEGIN.*PRIVATE KEY|AKIA[0-9A-Z]{16}' | head
$ zcat archive.gz | tar tvf - | grep -E '/etc/(shadow|passwd)|\.ssh/'
```

#### 输出解读
`zcat` 等工具本质是「先解压再喂给原工具」，所以**输出格式与对应的未压缩工具完全一致** ⭐。

**工具的实现方式**：

| 类型 | 行为 |
|------|------|
| 脚本包装（gzip 包提供） | 用 `gzip -dc \| 原工具` ⭐ |
| `zutils`（统一前端） | **自动识别格式**并调用对应解压器 ⭐⭐ |

判断本机是哪种：
```bash
$ file "$(command -v zcat)"
/usr/bin/zcat: symbolic link to /usr/bin/zutils
$ zcat --version 2>&1 | head -2
zutils 1.12
```

#### 常见坑
- ⚠️ **`zgrep` 的 `-H` 与 `-l` 行为**：`zgrep` 会为每个文件起一个 `gzip -dc` 子进程，**大量文件时很慢**。可以改用 `zcat f1 f2 f3 | grep` （gzip 版支持多文件）⭐。
- ⚠️ **`zcat` 对 `.bz2`/`.xz`/`.zst` 的支持取决于实现**：gzip 包的 `zcat` **只认 gzip**。要处理多种格式装 `zutils` 或显式用 `bzcat`/`xzcat`/`zstdcat` ⭐⭐。
- ⚠️ **`zcat` 不加参数会读 stdin**（可能挂起等输入）⭐。
- ⚠️ **`zless` 的搜索是在解压后的内容上做的**，所以能看到全部内容（不像 `less` 直接开 `.gz` 会显示乱码）⭐。
- **`zmore` 与 `zless` 都受 `PAGER`/`LESS` 环境影响** ⭐。
- **`zgrep` 的退出码与 `grep` 相同**（0 匹配、1 无匹配、2 出错）⭐。
- **对「多流 gzip」文件（`cat a.gz b.gz`）`zcat` 能正确处理**（gzip 格式支持拼接）⭐。
- **`zcat > file` 会解压到磁盘**，大文件要确认空间够 ⭐。

#### 相关命令
`gzip -dc` · `less` · `grep` · `zutils` · `zstdcat` · `xzcat` · `bzcat`

### pigz / pbzip2 / pixz — 并行压缩

**常用度**：★★★☆☆ ｜ **所属**：归档与压缩 ｜ **POSIX/GNU 差异**：第三方工具，需单独安装

| 工具 | 对应算法 | 兼容格式 | 说明 |
|------|----------|----------|------|
| `pigz` | gzip | `.gz` | **多线程 gzip** ⭐ |
| `pbzip2` | bzip2 | `.bz2` | 多线程 bzip2 |
| `lbzip2` | bzip2 | `.bz2` | 另一个 bzip2 并行实现 |
| `pixz` | xz | `.xz` | 多线程 xz（**且支持索引**）⭐ |
| `zstd -T0` | zstd | `.zst` | **zstd 原生就多线程** ⭐⭐ |
| `xz -T0` | xz | `.xz` | 新版 xz 原生多线程 ⭐ |
| `lz4 -T0` | lz4 | `.lz4` | 新版 lz4 多线程 |

```bash
# 场景：⭐ pigz 是 gzip 的多线程替代（完全兼容 .gz 格式）
$ pigz big.log
$ pigz -k big.log                        # 保留原文件
$ pigz -p"$(nproc)" -9 -k big.log        # ⭐ -p 指定线程数
$ pigz -d big.log.gz                     # 解压
$ pigz -dc big.log.gz | head

# 场景：速度对比（单线程 vs 多线程）⭐⭐
$ /usr/bin/time -f "gzip  -9: %e 秒" gzip  -9 -kc big.log > /tmp/a.gz
$ /usr/bin/time -f "pigz  -9: %e 秒" pigz  -9 -kc big.log > /tmp/b.gz
$ ls -lh /tmp/a.gz /tmp/b.gz
$ cmp <(zcat /tmp/a.gz) <(zcat /tmp/b.gz) && echo "内容一致（格式兼容）"

# 场景：⭐ 与 tar 组合（大归档的推荐做法）
$ tar cf - /data | pigz -p"$(nproc)" -9 > data.tar.gz
$ pigz -dc data.tar.gz | tar xf - -C /restore
$ tar --use-compress-program="pigz -p$(nproc) -9" -cf data.tar.gz /data   # ⭐
$ tar --use-compress-program=pigz -xf data.tar.gz -C /restore

# 场景：zstd 原生多线程（最简单的选择）⭐⭐
$ zstd -T0 -19 -k big.log
$ tar cf - /data | zstd -T0 -19 -o data.tar.zst

# 场景：xz 原生多线程（新版）⭐
$ xz -T0 -9 -k big.log
$ tar cf - /data | xz -T0 -9 > data.tar.xz

# 场景：pixz（xz 的并行版，带索引）⭐
$ pixz -p"$(nproc)" -9 big.log
$ pixz -d big.log.xz
$ pixz -t -l big.log.xz            # 列出索引（pixz 特性）⭐

# 场景：pbzip2（bzip2 并行）⭐
$ pbzip2 -p"$(nproc)" -9 -k big.log
$ pbzip2 -d big.log.bz2
$ tar cf - /data | pbzip2 -p"$(nproc)" > data.tar.bz2

# 场景：⭐ 各算法在归档场景的实际对比（同一份数据）
$ data=/tmp/testdata
$ du -sh "$data"
$ /usr/bin/time -f "gzip -6:    %e 秒" gzip -6 -c "$data" > /tmp/x.gz
$ /usr/bin/time -f "pigz -6:    %e 秒" pigz -p0 -6 -c "$data" > /tmp/x1.gz
$ /usr/bin/time -f "xz -T0 -6:  %e 秒" xz -T0 -6 -c "$data" > /tmp/x.xz
$ /usr/bin/time -f "zstd -T0 -9:%e 秒" zstd -T0 -9 -c "$data" > /tmp/x.zst
$ /usr/bin/time -f "zstd -T0 -19:%e 秒" zstd -T0 -19 -c "$data" > /tmp/x19.zst
$ ls -lh /tmp/x.gz /tmp/x1.gz /tmp/x.xz /tmp/x.zst /tmp/x19.zst

# 场景：🧪 备份脚本（并行 + 校验 + 进度）⭐⭐
$ cat /tmp/backup.sh
#!/bin/bash
set -euo pipefail
src=/srv/data
dst=/backup
ts=$(date +%F-%H%M%S)
out="$dst/data-$ts.tar.zst"
threads=$(nproc)

echo "开始备份 $src -> $out（$threads 线程）"
tar -C / -cf - "${src#/}" \
  | zstd -T"$threads" -19 --check -o "$out"

echo "校验中..."
zstd -t "$out" && echo "校验通过"
sha256sum "$out" > "$out.sha256"
ls -lh "$out"

# 场景：清理旧备份（保留最近 7 天）
$ find /backup -name 'data-*.tar.zst' -mtime +7 -delete

# 场景：🖥 用 pigz 压缩日志（不阻塞写入的日志轮转）⭐
$ logrotate 配置里可以直接用：
$ cat /etc/logrotate.d/app
/var/log/app/*.log {
    daily
    rotate 14
    compress
    compresscmd /usr/bin/pigz
    compressoptions -p4 -9
    uncompresscmd /usr/bin/unpigz
    delaycompress
    missingok
    notifempty
    create 0640 app app
}
```

#### 输出解读
并行压缩的**输出格式与单线程版本完全兼容**（`.gz`/`.bz2`/`.xz`/`.zst` 标准格式），所以：
- `pigz` 压的文件可以用 `gzip -d` 解压 ⭐
- `pbzip2` 压的可以用 `bunzip2` 解压 ⭐
- 但有**多流**的文件（`xz -T0`）可能不被很老的解压器支持 ⚠️

**并发效率的实际限制**：

| 场景 | 并行效果 |
|------|----------|
| 大文件、CPU 密集压缩（`-9`/`-19`） | **接近线性加速** ⭐ |
| 小文件、低压缩级别 | 有限（线程开销占比大） |
| I/O 受限（慢磁盘） | 无提升（瓶颈不在 CPU） |
| 内存受限 | 可能 OOM（每线程都要缓冲） ⚠️ |

#### 常见坑
- ⚠️ **`pigz -p0` 表示用所有核**（与 `--processes 0` 相同）⭐。
- ⚠️ **`pigz` 的输出对 `gzip -d` 兼容，但 `pigz -d` 输出会带多成员的语义**（拼接的 `.gz` 会被整体处理）⭐。
- ⚠️ **`pigz -9` 的内存占用是 `gzip -9` 的 N 倍**（N = 线程数），大文件 + 多线程可能 OOM ⭐。
- ⚠️ **`xz -T0` 会产生「多流」文件**，某些工具（旧版 `xz`、部分 tar 实现）不能读。要兼容用 `-T1` ⭐。
- ⚠️ **`pbzip2` 与 `lbzip2` 的 `.bz2` 格式兼容，但 `bunzip2` 解压需要的内存较多** ⭐。
- **`zstd` 与 `xz` 的新版本已原生支持多线程**，第三方并行工具的收益变小（这两者现在优先选）⭐⭐。
- **解压通常不需要并行**（解压比压缩快得多，且大多是顺序的）⭐。
- **`tar --use-compress-program` 是让 tar 调用任意压缩器的通用方法** ⭐⭐。
- **`logrotate` 支持 `compresscmd` 指定并行压缩器**，对日志量大时很有用 ⭐。

#### 相关命令
`gzip` · `xz` · `zstd` · `bzip2` · `tar --use-compress-program` · `pv` · `logrotate`
