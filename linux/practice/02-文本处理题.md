### 1. 统计访问日志里 404 有多少条 ⭐

**场景**：运维群里说「今天 404 有点多」，你要给个确切数字。

**要求**：打印 `data/access.log` 中状态码为 404 的行数。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方法一：grep -c 直接计数
grep -c ' 404 ' data/access.log

# 方法二：awk 按字段精确比较（更严谨）
awk '$9==404' data/access.log | wc -l
awk '$9==404 {n++} END{print n+0}' data/access.log
```

**预期输出**：

```text
231
```

**解析**：

- `grep -c` 数的是「**匹配的行数**」，不是「匹配的次数」。一行里出现三次 `404` 也只算 1。
- ⚠️ **`grep '404'` 是错的**：它会误命中「时间戳里含 404」「字节数含 404」等情况。所以参考答案里前后各加了一个空格 `' 404 '` 来锚定字段边界。
- 最严谨的是 `awk '$9==404'`：`$9` 是第 9 个空格分隔字段（状态码），`==` 是**数值比较**。注意日志里如果某字段为空，字段号会整体左移，这是用字段号分析日志的固有风险。
- 💡 `END{print n+0}` 里的 `+0` 技巧：如果一条都没匹配到，`n` 是未初始化变量，`print n` 会输出空行；`n+0` 强制转成数字 0。
- `grep -c` 只匹配一次就够、比 `wc -l` 快，因为它不必真正遍历到底（其实还是要读完，但没有输出开销）。

</details>

### 2. 找出日志里所有「非 INFO」的行 ⭐

**场景**：`app.log` 里 90% 是 `INFO` 噪音，你只想看异常部分。

**要求**：统计并打印所有不是 `INFO` 的行。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 统计非 INFO 行数
grep -vc 'INFO' projects/logs/app.log

# 打印非 INFO 行
grep -v 'INFO' projects/logs/app.log | head -20

# 更精确：只要 WARN 和 ERROR
grep -E '\[(WARN|ERROR)\]' projects/logs/app.log | head -5
```

**预期输出**：

```text
200
```

**解析**：

- `-v`（`--invert-match`）反转匹配：输出**不匹配**的行。这是它最常见的用途——「排除噪音」。
- `-c` 和 `-v` 可以组合：`grep -vc PATTERN` 数「不匹配的行数」（注意不是「匹配次数」）。
- ⚠️ 常见坑：`grep -v 'INFO'` 会把**任何位置**含 `INFO` 的行都排除掉，包括 `msg=processing INFO item` 这种。要精确就用 `-E '\[(WARN|ERROR)\]'` 锚定格式，或 `awk '$3=="[ERROR]"'`。
- `-v` 的另一个高频用法是排除注释和空行：`grep -vE '^\s*(#|$)' config.conf`。

</details>

### 3. 一行命令列出各状态码各自出现了多少次 ⭐⭐

**场景**：你要一份状态码分布表，用来判断「是不是有大量 5xx」。

**要求**：输出「次数 + 状态码」，按次数从多到少排序。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方法一：awk 字段 + sort + uniq -c（经典三连）
awk '{print $9}' data/access.log | sort | uniq -c | sort -rn

# 方法二：加个表头，对齐显示
awk '{print $9}' data/access.log | sort | uniq -c | sort -rn \
  | awk '{printf "%-6s %5d\n", $2, $1}'

# 方法三：用 column 对齐
awk '{print $9}' data/access.log | sort | uniq -c | sort -rn | column -t

# 方法四：纯 awk 一次搞定（少两次进程）
awk '{c[$9]++} END{for(k in c) printf "%-6s %5d\n", k, c[k]}' data/access.log | sort -k2 -rn
```

**预期输出**：

```text
607  200
231  404
57   403
56   500
49   301
```

**解析**：

- **`sort | uniq -c` 的顺序不能颠倒**：`uniq` 只合并**相邻**的重复行。不先 `sort`，同一状态码散落在各处，`uniq -c` 会把它们当成不同组各自计数，结果全错。
- `sort -rn`：`-n` 按数值排序、`-r` 逆序。**不加 `-n` 会按字符串排**，于是 `9` 排在 `100` 前面、`57` 排在 `607` 前面。
- `uniq -c` 的输出格式是「`右对齐的次数` + `空格` + `原行`」，所以后续取字段时 `$1` 是次数、`$2` 是内容。
- 💡 `uniq` 其它常用参数：`-d` 只显示重复过的、`-u` 只显示没重复的、`-i` 忽略大小写、`-f N` 跳过前 N 个字段再比较。

</details>

### 4. 提取所有客户端 IP，并按访问量排序 ⭐⭐

**场景**：判断是否有单 IP 刷接口。

**要求**：列出每个 IP 的请求数，降序排列。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方法一：grep -o 只输出匹配部分
grep -oE '^([0-9]{1,3}\.){3}[0-9]{1,3}' data/access.log \
  | sort | uniq -c | sort -rn

# 方法二：awk 直接取字段（日志第 1 个字段就是 IP，推荐）
awk '{print $1}' data/access.log | sort | uniq -c | sort -rn

# 只列出不重复的 IP 清单
grep -oE '^([0-9]{1,3}\.){3}[0-9]{1,3}' data/access.log | sort -u

# 只看 Top 5
awk '{print $1}' data/access.log | sort | uniq -c | sort -rn | head -5
```

**预期输出**：

```text
    146 10.0.0.11
    145 203.0.113.9
    145 192.168.1.5
    144 203.0.113.10
    143 10.0.0.13
    140 10.0.0.12
    137 192.168.1.7
```

**解析**：

- **`grep -o` 的价值**：默认 grep 输出整行，`-o`（`--only-matching`）只输出**匹配到的片段**。这是「从一团文本里抽字段」的关键选项，配合 `-E` 正则用。
- `-E`（`--extended-regexp`，等价 `egrep`）让 `+`、`?`、`|`、`()`、`{}` 不用转义。基本正则（BRE）里 `+` 要写成 `\+`、`()` 要写成 `\(\)`，非常别扭，**日常一律用 `-E`**。
- `sort -u` = `sort | uniq` 的合并写法，去重且有序，比两步快。
- 💡 统计「不重复项个数」只需要 `| sort -u | wc -l`。
- 💡 反过来「找出只访问了 1 次的 IP」（可能是扫描器）：
  ```bash
  awk '{print $1}' data/access.log | sort | uniq -c | awk '$1==1'
  ```

</details>

### 5. 报错日志要看上下文，光看错误行不够 ⭐⭐

**场景**：`app.log` 里的 `ERROR` 行本身没信息，得看它前后的行才能定位是哪个请求出的问题。

**要求**：打印每个 `ERROR` 及其前 2 行、后 1 行，并显示行号。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 前 2 行 + 后 1 行
grep -n -B2 -A1 'ERROR' projects/logs/app.log | head -30

# 前后各 3 行（-C 3 等价于 -B3 -A3）
grep -n -C3 'ERROR' projects/logs/app.log | head -20

# 只看前 3 个 ERROR（-m 限制匹配次数，到数就停）
grep -n -A1 -m3 'ERROR' projects/logs/app.log

# 上下文分隔符改成一个空行（默认是 --）
grep -n -A1 --group-separator='' -m3 'ERROR' projects/logs/app.log
```

**预期输出**：

```text
49-2026-09-15 10:49:27 [INFO] worker-1 request=49 msg=processing item 49
50:2026-09-15 10:50:30 [ERROR] worker-2 request=50 msg=processing item 50
51-2026-09-15 10:51:33 [INFO] worker-3 request=51 msg=processing item 51
--
99-2026-09-15 10:39:57 [INFO] worker-3 request=99 msg=processing item 99
100:2026-09-15 10:40:00 [ERROR] worker-0 request=100 msg=processing item 100
```

**解析**：

- 上下文行的**分隔符不同**：匹配行用 `:`（如 `50:`），上下文中用 `-`（如 `49-`）。所以在 `grep -A/-B` 的输出里，**看 `:` 还是 `-` 就知道哪行是真正命中的**。这是个非常实用的小技巧。
- `-B` = before、`-A` = after、`-C` = context（两边都有）。数字是可选的，不写默认 2。
- 多个匹配的上下文**重叠时**，grep 只输出一次、不重复。
- `--group-separator=''` 去掉默认的 `--` 分隔行，便于再管道给别的工具。
- ⚠️ 大文件上 `grep -C` 会显著变慢（需要维护环形缓冲），并且可能与 `-c` 语义冲突（`-c` 只数匹配行，不数上下文行）。
- 💡 用 `awk` 做「带上下文」的替代方案（更可控）：
  ```bash
  awk '/ERROR/{for(i=NR-2;i<=NR+1;i++) want[i]=1} {line[NR]=$0} END{for(i=1;i<=NR;i++) if(want[i]) print i": "line[i]}' projects/logs/app.log | head
  ```

</details>

### 6. 正则里的 `.` `*` `[]` 把结果搞乱了 ⭐⭐

**场景**：你要在配置里搜字面量 `a.b`，但 `grep 'a.b'` 把 `axb`、`a1b` 也搜出来了。类似地，搜 IP `192.168.1.5` 时，点号变成了「任意字符」。

**要求**：给出「按字面量搜索」和「正确写正则」两种解法。

<details><summary>参考答案</summary>

```bash
# 造一个小样本
printf 'a.b\naxb\na1b\n' > /tmp/re-demo.txt

# ❌ 正则里的 . 匹配任意单个字符
grep 'a.b' /tmp/re-demo.txt
# a.b
# axb      ← 不该出现
# a1b      ← 不该出现

# ✅ 方法一：-F 固定字符串模式，全部按字面量处理
grep -F 'a.b' /tmp/re-demo.txt
# a.b

# ✅ 方法二：转义元字符（BRE 里 \. 是字面量点）
grep 'a\.b' /tmp/re-demo.txt

# 用 -E 时也一样要转义
grep -E 'a\.b' /tmp/re-demo.txt
```

**搜索 IP 的正确姿势**：

```bash
cd /tmp/linux-practice

# ❌ 192.168.1.5 里的 . 会匹配任意字符，可能误命中
grep '192.168.1.5' data/access.log | wc -l

# ✅ 转义点号
grep '192\.168\.1\.5' data/access.log | wc -l

# ✅ 用字段精确匹配（最稳）
awk '$1=="192.168.1.5"' data/access.log | wc -l

# ✅ 反向：排除某个 IP
awk '$1!="192.168.1.5"' data/access.log | wc -l
```

**解析**：

正则元字符（BRE 和 ERE 共有的）：

| 字符 | 含义 |
|------|------|
| `.` | 任意单个字符 |
| `*` | 前一项重复 0 次或多次 |
| `[]` | 字符类，`[^...]` 取反 |
| `^` / `$` | 行首 / 行尾（不是字符串首尾！） |
| `\` | 转义 |
| `+` `?` `\|` `()` `{}` | **仅 ERE（`-E`）**，BRE 里要写 `\+` `\?` `\|` `\(\)` `\{\}` |

- `grep -F`（`--fixed-strings`，等价 `fgrep`）把整个模式当纯文本，**不做任何正则解释**。搜代码里的 `a.b`、`foo[0]`、`a+b`、`http://` 这类含元字符的内容时，`-F` 是最省心的。
- 想同时搜多个字面量：`grep -F -e 'a.b' -e 'c[d]' file`，或 `grep -Ff 模式文件`。
- 💡 判断「这个 `grep` 到底怎么解释的」：`echo 'a.b' | grep -o --color=always 'a\.b'`，或用 `-E` 时打开 `--color=always` 看高亮范围。

</details>

### 7. 在一堆配置文件里找哪个文件设了端口 ⭐⭐

**场景**：`projects/` 下有多层目录和多种文件，你要找出所有 `.conf` 里包含 `port` 的地方。

**要求**：递归搜索，只要 `.conf` 文件，显示文件名和行号。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 只搜 *.conf，带文件名和行号
grep -rn --include='*.conf' 'port' projects/

# 排除某个目录
grep -rn --include='*.conf' --exclude-dir=backup 'port' .

# 只列出命中的文件名（不看内容）
grep -rl --include='*.conf' 'port' projects/

# 忽略大小写
grep -rni --include='*.conf' 'port' projects/

# 用 find + xargs 的 POSIX 写法（BSD/macOS 的 grep 没有 --include）
find projects/ -name '*.conf' -exec grep -Hn 'port' {} +
```

**预期输出**：

```text
projects/src/app.conf:3:port   = 8080
```

**解析**：

- `-r` 递归、`-n` 行号、`-H` 强制显示文件名（搜多个文件时 `grep` 会自动加，搜单个文件时默认不加，脚本里显式加 `-H` 更保险）。
- `--include` / `--exclude` / `--exclude-dir` 是 **GNU 扩展**。POSIX grep 没有，所以脚本要在多平台跑时用 `find | xargs grep`。
- `-l`（小写 L）只输出文件名，`-L`（大写）输出**不含**匹配的文件名——后者常用来「找出哪些配置文件没设置某个必填项」。
- 现代替代 `rg` 更快且默认递归、默认忽略 `.gitignore` 和二进制：
  ```bash
  rg -n --glob '*.conf' 'port' projects/
  ```
- 🔐 排查常见组合（找配置里的凭据）：
  ```bash
  grep -rniE '(pass(word|wd)?|secret|token|api[_-]?key)\s*[:=]' /etc /var/www 2>/dev/null | head
  ```

</details>

### 8. 把配置里的端口从 8080 改成 9090 ⭐⭐

**场景**：`projects/src/app.conf` 里 `port = 8080`，要改成 `9090`。

**要求**：先预览效果，确认无误。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 第 1 步：不改文件，只打印替换后的结果
sed 's/8080/9090/' projects/src/app.conf

# 第 2 步：只看确实被改的那一行
sed -n 's/8080/9090/p' projects/src/app.conf
#       ↑ -n + p 组合：只打印"被替换成功"的行

# 第 3 步：确认后原地修改（并留备份）
cp projects/src/app.conf /tmp/app.conf.bak
sed -i 's/8080/9090/' projects/src/app.conf
grep port projects/src/app.conf
```

**预期输出**：

```text
port   = 9090
```

**解析**：

- `sed 's/旧/新/'` **只替换每行的第一处**。要替换全部出现加 `g`：`s/8080/9090/g`。这是 `sed` 最高频的坑。
- `sed` 默认**把结果输出到 stdout，不改原文件**。改文件必须 `-i`。
- `s///` 的分隔符可以换：路径里有 `/` 时用 `s#/a/b#/c/d#` 或 `s|/a/b|/c/d|`，避免一堆 `\/`。
- `sed -n 's/.../.../p'` 是「干跑」的经典写法：只有发生替换才打印，非常直观地告诉你「哪些行会被改」。
- 💡 只替换**第 N 处**：`sed 's/x/y/2'`。只替换包含某关键词的行：`sed '/^listen/ s/0.0.0.0/127.0.0.1/'`。
- 💡 精确锚定，避免误伤：`sed -E 's/^(port\s*=\s*)8080/\19090/'`，用 `^` 锚定行首 + 保留前缀。

</details>

### 9. 只看 / 只删文件的某几行 ⭐⭐

**场景**：`sales.csv` 9 行，你要①只看第 3 到 5 行；②打印除第 3 到 5 行之外的所有行。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 看第 3~5 行（-n + p）
sed -n '3,5p' data/sales.csv

# 删除第 3~5 行（其余全部输出）
sed '3,5d' data/sales.csv

# 只看偶数行
sed -n '0~2p' data/sales.csv          # GNU sed 扩展：从第 0 行起每隔 2 行
awk 'NR%2==0' data/sales.csv          # 可移植写法

# 只看最后一行
sed -n '$p' data/sales.csv
tail -n 1 data/sales.csv

# 只删除最后一行
sed '$d' data/sales.csv

# 跳过前 3 行（等价 tail -n +4）
sed '1,3d' data/sales.csv
```

**解析**：

- **`sed -n` 里的 `-n` 不能省**：不加时 sed 默认把每行都打印一遍，`sed '3,5p'` 会输出「全文 + 3~5 行重复一次」。
- 地址形式：

  | 写法 | 含义 |
  |------|------|
  | `3p` | 第 3 行 |
  | `3,5p` | 第 3 到 5 行 |
  | `3,+2p` | 第 3 行及其后 2 行 |
  | `$p` | 最后一行 |
  | `/re/p` | 匹配正则的行 |
  | `/a/,/b/p` | 从匹配 `a` 的行到匹配 `b` 的行 |
  | `0~2p` | 从第 0 行起，每隔 2 行（GNU 扩展） |

- 💡 `/开始/,/结束/p` 是提取配置块的神器：
  ```bash
  sed -n '/^### cat/,/^$/p' ../commands/02-文本处理.md
  ```
- 💡 `awk 'NR>=3 && NR<=5'` 是同样效果的另一种写法，可读性对新手更友好。

</details>

### 10. `sed -i` 改完发现改错了，怎么回滚 ⭐⭐⭐

**场景**：你要批量把 `projects/logs/app.log` 里的 `worker-0` 改成 `w0`。改完之后才意识到改错了。

**要求**：给出「改之前就留好退路」的标准做法，并说明 `-i` 的三个陷阱。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方案一（最推荐）：-i 带后缀，GNU sed 会自动留备份
#             先复制一份到 /tmp 练手，不动沙盒原文件
cp projects/logs/app.log /tmp/app.log
sed -i.bak 's/worker-0/w0/g' /tmp/app.log
ls -l /tmp/app.log*                     # app.log 和 app.log.bak
grep -c 'w0' /tmp/app.log               # 500
grep -c 'worker-0' /tmp/app.log         # 0

# 发现问题了 —— 回滚（一行）
mv /tmp/app.log.bak /tmp/app.log
grep -c 'worker-0' /tmp/app.log         # 500  ← 复原

# 方案二：先 diff 出补丁，能回滚也能给别人评审
diff -u /tmp/app.log.bak /tmp/app.log > /tmp/app.patch
patch -R /tmp/app.log < /tmp/app.patch  # -R 反向应用 = 撤销

# 方案三：显式指定备份扩展名（GNU sed）
sed -i'suffix' 's/worker-0/w0/g' /tmp/app.log
```

**解析**：

- **`sed -i` 的危险性**：它的实现是「创建一个临时文件，写完再 `rename` 覆盖原文件」。这意味着：
  1. **原文件的 inode 变了**。如果别的进程正通过文件描述符读写这个文件（比如一个还在跑的日志服务），它写到**旧的、已经被 unlink 的 inode** 上，你的修改对它是「隐形」的，而且磁盘空间不会释放。
  2. **硬链接会被断开**。`a` 和 `b` 是硬链接，`sed -i a` 之后 `b` 仍然指向旧内容。
  3. **软链接会被替换成普通文件**。`sed -i link` 之后 `link` 不再是链接，目标文件**没被修改**。这是极其经典的坑：

     ```bash
     echo "target content" > /tmp/t.txt
     ln -sf /tmp/t.txt /tmp/l.txt
     sed -i 's/target/TARGET/' /tmp/l.txt
     ls -l /tmp/l.txt      # -rw-r--r-- ... /tmp/l.txt   ← 已经不是软链接了！
     cat /tmp/t.txt        # target content             ← 目标文件纹丝不动
     ```

     要对软链接的**目标**做修改，用 `sed -i --follow-symlinks ...`（GNU sed）或先 `readlink` 拿到真实路径。
- **BSD/macOS 的 `sed -i` 必须跟一个参数**：`sed -i '' 's/a/b/'`（给空字符串 = 不留备份），`sed -i.bak 's/a/b/'`。GNU 与 BSD 的 `-i` 语法**不兼容**，跨平台脚本要么判断，要么改用 `perl -pi -e`（两边语法一致）。
- **最稳妥的批量改文件流程**：
  ```bash
  # ① 先干跑，看会改哪些行
  grep -rn 'worker-0' .
  # ② 备份（tar 一份最省事）
  tar czf /tmp/backup-$(date +%F).tgz projects/
  # ③ 逐个文件改，改完立即 diff 验证
  for f in $(grep -rl 'worker-0' .); do sed -i.bak 's/worker-0/w0/g' "$f"; done
  ```
- ⚠️ **别在真实系统文件上用 `sed -i`**（`/etc/fstab`、`/etc/passwd`、`/etc/sudoers`）。这些文件要用它们各自的专用工具（`visudo`、`vipw`），因为这些工具会做语法校验和加锁。

</details>

### 11. 把配置文件里的注释和空行全部去掉 ⭐⭐

**场景**：你要对比两台机器的配置差异，但注释和空行导致 `diff` 输出一片红。

**要求**：输出「只有生效配置行」的版本。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 造一个带注释和空行的样本
cat > /tmp/cfg-demo.conf <<'EOF'
# 这是注释
listen = 0.0.0.0

# 端口
port = 8080

   
debug = false
EOF

# 方法一：sed 多条编辑（-e 可重复）
sed -e '/^\s*$/d' -e '/^\s*#/d' /tmp/cfg-demo.conf

# 方法二：一条 sed 用地址 + 删除，等价写法
sed -E '/^\s*(#|$)/d' /tmp/cfg-demo.conf

# 方法三：grep -v（最简单好记）
grep -vE '^\s*(#|$)' /tmp/cfg-demo.conf

# 方法四：awk（顺便去掉行尾空格）
awk 'NF && $1 !~ /^#/' /tmp/cfg-demo.conf
```

**预期输出**：

```text
listen = 0.0.0.0
port = 8080
debug = false
```

**解析**：

- `\s`（空白）是 **GNU 扩展**，POSIX 要写 `[[:space:]]`。跨平台脚本用后者：

  ```bash
  grep -vE '^[[:space:]]*(#|$)' config.conf
  ```

- `awk 'NF'` 是最短的非空行过滤：`NF` 为 0 表示这行没有任何字段（即空行或纯空白），`NF` 作为条件时「非零即真」。
- `awk '$1 !~ /^#/'`：`!~` 是「不匹配」运算符；`$1` 是第一个字段，天然忽略了行首空白。
- 💡 只去掉**整行注释**（`^\s*#`），保留行尾注释（`port = 8080  # 端口`），需要区分对待：

  ```bash
  sed -E 's/\s*#.*$//' config.conf | grep -v '^$'   # 连行尾注释也去掉
  ```

- 💡 对比配置时更推荐「保留行号地忽略注释」：
  ```bash
  diff <(grep -vE '^\s*(#|$)' a.conf) <(grep -vE '^\s*(#|$)' b.conf)
  ```

</details>

### 12. 从日志行里「抽取字段并重排」，用 sed 的反向引用 ⭐⭐⭐

**场景**：日志行是

```
192.168.1.5 - GET /login 200
```

你要把它重排成

```
GET /login -> 200 from 192.168.1.5
```

**要求**：不借助 `awk`，只用一个 `sed` 表达式完成。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

echo '192.168.1.5 - GET /login 200' \
  | sed -E 's#^([0-9.]+) .* (GET|POST) ([^ ]+) ([0-9]{3})$#\2 \3 -> \4 from \1#'

# 预期输出：GET /login -> 200 from 192.168.1.5
```

**实用的变体：把 `key = value` 变成 `key=value`**

```bash
cd /tmp/linux-practice
sed -nE 's/^\s*([a-z_]+)\s*=\s*(.*)$/\1=\2/p' projects/src/app.conf
```

**预期输出**：

```text
listen=0.0.0.0
port=8080
debug=true
workers=4
log_level=info
```

**解析**：

- **反向引用**：`s///` 的「模式」里用 `\(...\)`（ERE 下 `(...)`）分组，在「替换」里用 `\1` `\2` 引用。这是 `sed` 做「字段重排」的核心能力。
- `[0-9.]+` 里的 `[...]` 是字符类，`.` 在类内是**字面量**，所以 `[0-9.]` 匹配「数字或点」。
- `[^ ]+` 匹配「一个或多个非空格字符」——比 `.*` 精确，不会贪婪地吃掉后面的内容。
- **`^` 和 `$` 锚定整行**很重要：不加锚点时，如果一行的某部分不匹配，`sed` 会在**行内其它位置**再做尝试，可能产生奇怪结果。加锚点 = 「必须整行匹配」，语义清晰。
- 换分隔符 `s#...#...#`：因为模式和替换里都有 `/`，用 `#` 当分隔符就不用写一堆 `\/`。
- 💡 练习方法：`echo '输入' | sed -E 's/模式/替换/'`，反复改模式直到输出符合预期，比对着文档推理快得多。
- ⚠️ `sed` 的正则功能比 `awk`/`perl` 弱（没有惰性匹配、没有 `\d`、没有环视）。复杂提取改用 `awk` 或 `perl -pe`：
  ```bash
  perl -pe 's/^([\d.]+) .* (GET|POST) (\S+) (\d{3})$/$2 $3 -> $4 from $1/'
  ```

</details>

### 13. 打印日志的第 1 和第 7 个字段 ⭐

```bash
cd /tmp/linux-practice

awk '{print $1, $7}' data/access.log | head -3
```

**预期输出**：

```text
203.0.113.9 49446
10.0.0.12 30698
192.168.1.7 55041
```

（具体数字取决于沙盒随机种子，但你看到的应该是「IP + 数字」两列。）

**⚠️ 先看清字段结构再动手**：

```bash
head -1 data/access.log | awk '{for(i=1;i<=NF;i++) print i": "$i}'
```

```text
1: 203.0.113.9

3: -
```

  - 或干脆用支持 Nginx 日志格式的工具（`goaccess`、`lnav`）。
- `$0` 是整行，`print` 不带参数等于 `print $0`。
- 💡 `awk '{print $NF}'` 取**最后一个**字段，`$(NF-1)` 是倒数第二个。这个写法不受字段总数变化影响，比硬编码数字健壮。

### 14. 分析 CSV：用 `-F` 指定分隔符，并自定义输出分隔符 ⭐⭐

**场景**：`data/sales.csv` 是逗号分隔，你要打印「姓名 | 部门 | 金额」三列，用 ` | ` 分隔。

**要求**：用一条 `awk` 命令完成。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方法一：-F 指定输入分隔符，-v OFS 指定输出分隔符
awk -F, -v OFS=' | ' 'NR>1{print $2,$3,$4}' data/sales.csv

# 方法二：手动补分隔符
awk -F, 'NR>1{print $2" | "$3" | "$4}' data/sales.csv

# 方法三：用输出重定向到 column 对齐（中文字符对齐会偏，但结构清晰）
awk -F, -v OFS='\t' 'NR>1{print $2,$3,$4}' data/sales.csv | column -t -s $'\t'

# 处理「字段本身含逗号」的 CSV 要用专门的解析器
python3 -c "
import csv
with open('data/sales.csv') as f:
    for row in csv.DictReader(f):
        print(row['name'], '|', row['dept'], '|', row['amount'])
"
```

**预期输出**：

```text

Bob | 运维 | 880.00
Carol | 研发 | 1500.75

Frank | 研发 | 450.10
Grace | 市场 | 990.90
Heidi | 运维 | 1780.00
```

**解析**：

- `-F,` 指定输入分隔符（等价于 `BEGIN{FS=","}`）。
- `-v OFS=' | '` 设置输出字段分隔符。**注意 `OFS` 只在 `print` 的字段**之间生效**——`print $2" "$3` 这种字符串拼接里 `OFS` 不起作用，所以要显式写。

### 15. 挑出金额大于 1000 的记录 ⭐⭐

**场景**：你要从 `sales.csv` 里筛出「金额 > 1000」的行。

**要求**：打印姓名、部门、金额。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 数值比较（注意 $4 会被自动转成数字）
awk -F, 'NR>1 && $4 > 1000 {printf "%-6s %-4s %8.2f\n", $2, $3, $4}' data/sales.csv

# 组合条件：金额 > 1000 且部门是研发
awk -F, 'NR>1 && $4>1000 && $3=="研发" {print $2, $4}' data/sales.csv

# 只要「不满足」的行
awk -F, 'NR>1 && !($4>1000) {print $2, $4}' data/sales.csv
```

**预期输出**：

```text
Alice  研发    1200.50
Carol  研发    1500.75
Eve    运维    2200.00
Heidi  运维    1780.00
```

**解析**：

- **`awk` 的数值比较会自动做类型转换**：`$4` 是字符串 `"1200.50"`，但在 `>` 的上下文里 awk 把它转成数字。所以 `$4 > 1000` 是**数值比较**；如果你写 `$4 > "1000"`，awk 会因为右边是「非数字字符串」而退化成**字符串比较**（`"8" > "1000"` 为真！），这是大坑。
- **`==` 的字符串/数值陷阱**：
  ```bash
  awk '$1==1'      # 数值比较：匹配 "1"、"01"、"1.0"、甚至 " 1 "
  awk '$1=="1"'    # 字符串比较：只匹配完全等于 "1" 的
  ```
  处理状态码、ID 这类「本质上是标识符」的字段，**建议用字符串比较**，能避免把 `4040` 当成 `404`。
- `!` 可以取反整个条件：`!(cond)`。`&&` 与 `||` 是短路求值。
- `printf` 的格式：`%-6s` 左对齐最小宽度 6、`%8.2f` 右对齐宽度 8 保留 2 位小数、`\n` 换行。**注意 `printf` 不会自动加换行**，必须自己写 `\n`。
- 💡 按「多个值的区间」筛：`awk '$4>=1000 && $4<2000'`；按正则筛：`awk '$3 ~ /研|运/'`。

</details>

### 16. 统计总金额、平均值、条目数 ⭐⭐

**场景**：给一份销售数据做个一行报表。

**要求**：输出 `合计 / 平均 / 条数`。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

awk -F, 'NR>1{s+=$4; n++}
         END{printf "合计=%.2f  平均=%.2f  行数=%d\n", s, s/n, n}' data/sales.csv

# 顺便算最大值、最小值
awk -F, 'NR>1{
           s+=$4; n++
           if(mx==""||$4+0>mx) mx=$4+0
           if(mn==""||$4+0<mn) mn=$4+0
         }
         END{printf "合计=%.2f 平均=%.2f 最大=%.2f 最小=%.2f 条数=%d\n", s, s/n, mx, mn, n}' data/sales.csv
```

**预期输出**：

```text
合计=9302.50  平均=1162.81  行数=8
```

**解析**：

- `awk` 的处理模型：模式-动作对，逐行执行；`END{}` 在所有行读完后执行一次。所以累计变量（`s`、`n`）在读取阶段累加，在 `END` 里输出。
- **`printf` 的 `%.2f` 是保留小数的唯一途径**。`print s/n` 会输出 `1162.8125`（awk 用 `OFMT` 默认 `%.6g`）。金额、比例、平均值一律用 `printf`。
- `s/n`：`awk` 里**未初始化变量在算术上下文中是 0**，所以如果文件为空，`s/n` 是 `0/0` → 报 `division by zero` 错误。稳妥写法：`END{ if(n>0) printf ... else print "无数据" }`。
- `if(mx==""||...)` 是为了处理「第一行」的情况——awk 不像 Python 有 `None`，判断「是否已初始化」最简单的方式是跟空字符串比。
- 💡 用 `-v` 从外部传变量：
  ```bash
  awk -F, -v threshold=1000 '$4>threshold' data/sales.csv
  ```
- 💡 `sum` 的整数场景可以用 `int()` 或 `%d`：`printf "%d", s`。

### 17. 按部门汇总金额：`awk` 关联数组做 group by ⭐⭐⭐

**场景**：`sales.csv` 里每个部门有多条记录，你要算出每个部门的**总金额**和**人数**。

**要求**：输出 `部门 总金额 人数`，按部门名排序。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

awk -F, 'NR>1 { sum[$3] += $4; cnt[$3]++ }
         END  { for (d in sum) printf "%-6s %9.2f 元  %d 人\n", d, sum[d], cnt[d] }' \
  data/sales.csv | sort

# 按金额降序排列（sort 放在 END 之后按第二列数值逆序）
awk -F, 'NR>1 { sum[$3] += $4 } END { for (d in sum) printf "%-6s %.2f\n", d, sum[d] }' \
  data/sales.csv | sort -k2 -rn

# 纯 awk 排序（无 sort），用 asort 是 gawk 扩展（需要事先定义比较函数）
# 通常直接管道给 sort 更简单、更可移植
```

**预期输出**：

```text
市场      1291.15 元  2 人
研发      3151.35 元  3 人
运维      4860.00 元  3 人
```

**解析**：

- **`awk` 的数组是关联数组（哈希表）**，下标是字符串。`sum[$3] += $4` 就是「按部门累加金额」——这是 awk 最强的用法，等价于 SQL 的 `GROUP BY`。
- `for (d in sum)` 遍历的**顺序是不确定的**（哈希序）。所以**一定要另外 `| sort`**，否则每次运行输出顺序可能不同，脚本就没法做 diff 验证了。
- 一个数组套两个统计量（`sum` 和 `cnt`）是最常用的模式。也可以用二维下标 `a[$3","$5]` 做多键分组。
- `printf "%-6s"` 里的 6 是**字节最小宽度**：中文字符在 UTF-8 下占 3 字节，`%-6s` 对「研发」（6 字节）刚好不补空格，对「市场」（6 字节）也一样。所以中文列宽会看起来「不齐」——这是字节宽度 vs 显示宽度的差异，不是 bug。要精确对齐得用 `column -t`。
- 💡 完整版 group by（含占比）：
  ```bash
  awk -F, 'NR>1{a[$3]+=$4; t+=$4} END{for(k in a) printf "%-6s %9.2f (%5.1f%%)\n", k, a[k], a[k]/t*100}' data/sales.csv | sort
  ```

</details>

### 18. `NR` `NF` `$0` `$NF` 的用法与差异 ⭐⭐

**场景**：你需要一套「检查文件质量」的命令：总行数、空行位置、每行字段数、给每行加序号。

**要求**：分别用 `awk` 实现这四件事。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ① 总行数（注意：不读文件就取不到 NR，要放 END）
awk 'END{print NR}' data/sales.csv

# ② 找空行（或字段数为 0 的纯空白行）
awk 'NF==0 {print "空行在第 " NR " 行"}' projects/logs/app.log

# ③ 每行的字段数，去重看有几种
awk '{print NF}' data/access.log | sort -u

# ④ 给每行加行号（同时保留原行）
awk '{printf "%4d: %s\n", NR, $0}' data/sales.csv | head -3

# 其它常用内置变量演示
awk '{print NR": 首字段="$1"  末字段="$NF"  整行="$0}' data/sales.csv | head -2

# 多文件时 NR 与 FNR 的差异
awk '{print FILENAME, NR, FNR, $0}' data/fruit.txt data/files.csv | head -8
```

**预期输出**：

```text
$ awk 'END{print NR}' data/sales.csv
9

$ awk '{print NF}' data/access.log | sort -u
10

$ awk '{printf "%4d: %s\n", NR, $0}' data/sales.csv | head -3
   1: id,name,dept,amount,date
   2: 1,Alice,研发,1200.50,2026-01-03
   3: 2,Bob,运维,880.00,2026-01-03
```

**解析**：

| 变量 | 含义 |
|------|------|
| `NR` | 已读入的**总**记录数（跨文件累加） |
| `FNR` | 当前文件的记录数（每个文件重新从 1 开始） |
| `NF` | **当前行的字段数** |
| `$0` | 整行原文 |
| `$NF` | 最后一个字段（`$NF` = `$` 后面跟 `NF` 的值） |
| `$(NF-1)` | 倒数第二个字段 |
| `FILENAME` | 当前文件名 |
| `FS` / `OFS` | 输入 / 输出字段分隔符 |
| `RS` / `ORS` | 输入 / 输出记录（行）分隔符 |
| `NR` 在 `END` 里 | 就是总行数 |

- **`$NF` 的写法反直觉但要记牢**：`$` 后面可以是「变量名」，awk 会取这个变量的值作为字段号。所以 `$NF` 不是「一个叫 NF 的字段」，而是「第 NF 个字段」。
- **`$0` 赋值会重新分割字段**：`{$0="a b c"; print $2}` 输出 `b`。反过来，修改 `$1`、`$2` 之后 `$0` 会被按 `OFS` 重新拼接。这个特性很有用（比如「只改第 3 列」）：
  ```bash
  awk -F, -v OFS=, '{$3="新部门"; print}' data/sales.csv | head -3
  ```
- `NR` 和 `FNR` 的差异在多文件处理时是必修：`awk 'FNR==1{print "=== "FILENAME" ==="} {print}' a b` 是「给每个文件加标题」的标准写法。
- **`NR==1` vs `FNR==1`**：`NR==1` 只匹配整个输入的第一行；`FNR==1` 匹配每个文件的第一行。

</details>

### 19. 用 `cut` 按列切取 ⭐⭐

**场景**：`sales.csv` 你要取第 2 列和第 4 列；`access.log` 你要取每行前 4 个字符看 IP 前缀。

**要求**：给出按分隔符取字段和按字符位置取字符两种用法。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ① 按分隔符取字段
cut -d, -f2,4 data/sales.csv          # 第 2、4 列
cut -d, -f2- data/sales.csv           # 第 2 列到结尾
cut -d, -f1-3 data/sales.csv          # 第 1~3 列
cut -d, --complement -f3 data/sales.csv  # 反选：除第 3 列外全部（GNU）
cut -d, -f2-4 --output-delimiter='|' data/sales.csv  # 自定义输出分隔符（GNU）

# ② 按字符位置取
cut -c1-4 data/access.log | head -3   # 每行前 4 个字符
cut -c1,3,5 file                      # 第 1、3、5 个字符
cut -c5- file                         # 第 5 个字符到行尾

# ③ 按字节取
cut -b1-4 data/access.log | head -3
```

**预期输出**：

```text
$ cut -d, -f2,4 data/sales.csv
name,amount
Alice,1200.50
Bob,880.00
...

$ cut -c1-4 data/access.log | head -3
203.
10.0
192.
```

**解析**：

- `-d` 指定**单个字符**作分隔符，`-f` 指定字段号。**`cut` 不支持多字符分隔符**，也不支持「按连续空白分割」（`-d' '` 会把连续空格算成多个空字段）。要处理这两种情况只能用 `awk`。
- `-c` 是**字符**、`-b` 是**字节**。在纯 ASCII 下两者一样；在 UTF-8 下 `cut -c1-2` 会正确地按**字符**切（不切坏汉字），而 `cut -b1-2` 会把一个汉字切成乱码。**所以处理中文用 `-c`**。
- ⚠️ `cut` 的传统实现（POSIX）**完全看不到字段顺序**：`cut -f2,1` 和 `cut -f1,2` 输出一样，都是按原文件列序。要真正重排用 `awk '{print $2, $1}'`。
- `--complement` 和 `--output-delimiter` 是 GNU 扩展，BSD `cut` 没有。
- 💡 `cut` 的常见替代：
  ```bash
  awk -F, '{print $2, $4}' OFS=, data/sales.csv   # 支持重排、支持多字符分隔
  ```

</details>

### 20. 各种各样的排序需求 ⭐⭐

**场景**：你要按金额从大到小排 `sales.csv`（跳过表头），按文件大小排目录，按时间去重排日期。

**要求**：给出四种排序场景的命令。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ① 按第 4 列（金额）数值降序，跳过表头
{ head -1 data/sales.csv; tail -n +2 data/sales.csv | sort -t, -k4 -nr; }

# ② 按第 3 列（部门）字符串升序，同一部门内按金额数值降序
{ head -1 data/sales.csv; tail -n +2 data/sales.csv | sort -t, -k3,3 -k4,4nr; }

# ③ 按人类可读大小排序（du -h 的输出）
du -sh * | sort -rh | head -5

# ④ 去重 + 排序
printf '2026-01-03\n2026-01-05\n2026-01-03\n2026-01-04\n' | sort -u

# ⑤ 按月份名排序（-M）
printf 'Feb\nJan\nDec\nMar\n' | sort -M

# ⑥ 稳定排序 & 版本号排序
printf 'v2.10\nv2.9\nv2.1\n' | sort -V
```

**预期输出**：

```text
$ sort -t, -k4 -nr
（表头后，Eve 2200 → Heidi 1780 → Carol 1500.75 → ...）

$ du -sh * | sort -rh | head -5
168K	bin
160K	archive
152K	projects
100K	data
8.0K	my dir

$ sort -V
v2.1
v2.9
v2.10
```

**解析**：

| 参数 | 作用 | 不加会怎样 |
|------|------|-----------|
| `-n` | 按数值排 | `10` 排在 `9` 前面 |
| `-r` | 逆序 | 升序 |
| `-M` | 按月份名 | 按字母序（Apr 在最前） |
| `-h` | 按人类可读大小（`1K`/`2M`/`3G`） | `9M` 排在 `1G` 前面 |
| `-V` | 版本号排序（自然序） | `v2.10` 排在 `v2.9` **前**面 |
| `-t` | 指定字段分隔符 | 默认按「空白到非空白」的转换分割 |
| `-k N` | 从第 N 个字段开始比较 | 整行比较 |
| `-k N,M` | 只用第 N 到 M 字段作为排序键 | — |
| `-u` | 去重（按排序键去重，不是整行） | 保留重复 |
| `-s` | 稳定排序（相等时保持原序） | GNU sort 默认也是稳定的（`-s` 保证） |
| `-f` | 忽略大小写 | `Z` 排在 `a` 前面（按 ASCII） |

- **`-k4 -nr` 和 `-k4,4 -nr` 的差别**：`-k4` 表示「从第 4 个字段开始，延伸到行尾」作为排序键，所以当第 4 字段相同时会继续比较第 5 字段。`-k4,4` 明确「只用第 4 个字段」。做多级排序时**一定要写 `-k N,N`**，否则结果可能不是你要的。
- **`-n` 的位置**：`-rn`、`-nr` 都对（都是短选项）。但 `-k4nr` 这种把 `n` 和 `r` 粘在 `-k` 后面的写法，含义是「这个键按数值逆序」——**只对当前键生效**。多键排序时要写清楚：`-k3,3 -k4,4nr`。
- ⚠️ **`sort` 的 locale 影响**：默认按当前 locale 排，`LC_ALL=C` 会改成按字节排。「中文排序顺序每次不一样」通常是 locale 问题。要可复现就固定 `LC_ALL=C sort`。
- ⚠️ 大文件排序会占用大量内存和临时磁盘空间（`sort` 用 `/tmp` 做外排）。`sort -S 1G -T /data/tmp` 可以指定内存上限和临时目录。

</details>

### 21. 统计每个单词出现了多少次 ⭐⭐

**场景**：`fruit.txt` 里是「名称 数量」，你要统计每个名称出现了几次、总数量是多少。

**要求**：给出「出现次数」和「数量求和」两份统计。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 出现次数：必须 sort 后才能 uniq -c
awk '{print $1}' data/fruit.txt | sort | uniq -c | sort -rn

# 总数量：awk 关联数组求和
awk '{sum[$1] += $2} END{for (k in sum) printf "%-8s %4d\n", k, sum[k]}' data/fruit.txt | sort

# 一起输出
awk '{c[$1]++; s[$1]+=$2}
     END{for (k in c) printf "%-8s 出现=%d 合计=%d\n", k, c[k], s[k]}' data/fruit.txt | sort
```

**预期输出**：

```text
      3 apple
      2 banana
      1 cherry

apple      37
banana     20
cherry    100

apple    出现=3 合计=37
banana   出现=2 合计=20
cherry   出现=1 合计=100
```

**解析**：

- **`uniq -c` 的铁律：先 `sort`**。`uniq` 内部只比较**相邻两行**，这是为了能流式处理超大文件（不需要把整个文件装进内存）。所以「去重/计数」的标准管道永远是 `sort | uniq -c`。
- `sort -rn` 里的 `-n` 不能省。`uniq -c` 的输出是「`   3 apple`」，前面有空格对齐，但因为 `sort` 会去掉前导空白再比较，所以 `-n` 能正确识别数字。
- 💡 常用变体：
  ```bash
  sort file | uniq -c | sort -rn | head -10     # Top 10 频次
  sort file | uniq -d                           # 只显示重复过的
  sort file | uniq -u                           # 只显示没重复的
  sort file | uniq -c | awk '$1==1'             # 只出现一次的（可能是异常项）
  ```
- 💡 统计「英文文本里的词频」（需要先切词 + 统一大小写）：
  ```bash
  tr -cs '[:alpha:]' '\n' < some.txt | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn | head -20
  ```
  `tr -cs` 的意思是「把**非**（complement）字母的字符**压缩**（squeeze）成一个换行」——正好是「按词切分」。

</details>

### 22. `tr` 做大小写转换、删除、压缩 ⭐⭐

**场景**：你要①把日志里的 `ERROR` 转成小写便于统一匹配；②删掉文件名列表里的 `\r`；③把连续空格压成一个。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ① 大小写转换
echo 'Hello WORLD' | tr '[:upper:]' '[:lower:]'      # hello world
echo 'Hello WORLD' | tr '[:lower:]' '[:upper:]'      # HELLO WORLD
echo 'Hello WORLD' | tr 'A-Z' 'a-z'                  # 同样效果

# ② 删除字符
printf 'a\r\nb\r\n' | tr -d '\r'                     # 去掉所有 CR
printf 'abc123def456\n' | tr -d '0-9'                # abcdef

# ③ 压缩重复字符（squeeze）
printf 'a    b\t\tc\n' | tr -s ' '                   # a b\t\tc  ← 只压空格
printf 'a    b\t\tc\n' | tr -s '[:space:]' ' '        # a b c  ← 空白全部压成一个空格
printf 'aaabbbcc\n' | tr -s 'a-z'                    # abc

# ④ 字符替换（一对多：把分隔符统一）
echo 'a-b_c:d' | tr '-_:' '///'                      # a/b/c/d

# ⑤ 补集 + 切词（词频统计常用）
echo 'hello, world! foo 123' | tr -cs '[:alpha:]' '\n'
```

**解析**：

- `tr` 的输入**只能来自 stdin**，不能直接给文件名（`tr 'a' 'b' file` 是错的）。所以永远要 `tr ... < file` 或 `... | tr`。
- `tr` 按**字节/字符位置一一对应**地替换：`SET1` 的第 1 个字符换 `SET2` 的第 1 个，以此类推。`SET2` 比 `SET1` 短时，`SET2` 的最后一个字符会重复使用（所以 `tr 'a-z' 'A-Z'` 只给一个字符也没问题）。
- 三个核心参数：

  | 参数 | 作用 | 记忆 |
  |------|------|------|
  | `-d` | 删除 `SET1` 里的字符 | **d**elete |
  | `-s` | 压缩 `SET1` 里连续重复的字符为一个 | **s**queeze |
  | `-c` | 取补集（`SET1` 之外的字符） | **c**omplement |

  三者可组合：`tr -cs '[:alpha:]' '\n'` = 「把非字母的连续字符压成一个换行」。
- **字符类必须用 `[:...:]` 且外面还有一层 `[]`**：`[:upper:]` 是「字符类名」，在 `tr` 的 SET 里写成 `'[:upper:]'`。写成 `'[A-Z]'` 也行，但在某些 locale 下 `A-Z` 的范围依赖于排序规则，`[:upper:]` 更可靠。
- ⚠️ `tr` 处理的是**字节**：`tr` 对 UTF-8 多字节字符（中文）会按单字节处理，可能产出乱码。要处理 Unicode 的大小写转换得用 `sed`/`perl`/`python`。
- 💡 清掉 Windows 换行（CRLF → LF）：
  ```bash
  tr -d '\r' < win.txt > unix.txt
  # 或者 sed -i 's/\r$//' file
  ```

</details>

### 23. 数一数文件有多少行、多少词、多少字节 ⭐

**场景**：你要快速掌握一个文件的规模，并验证上一步操作有没有改变行数。

**要求**：分别输出 `sales.csv` 的行数、词数、字节数，以及 `access.log` 最长行的长度。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

wc -l data/access.log                 # 1000
wc -lwc data/sales.csv                # 行 词 字节
wc -w data/sales.csv                  # 词数
wc -c data/sales.csv                  # 字节数
wc -L data/access.log                 # 最长行长度（88）
wc -l < data/access.log               # 只要数字，不要文件名

# 常用场景：统计某类文件总行数
find . -name '*.csv' -exec wc -l {} + | tail -1
```

**预期输出**：

```text
$ wc -lwc data/sales.csv
  9   9 288 data/sales.csv

$ wc -L data/access.log
88 data/access.log

$ wc -l < data/access.log
1000
```

**解析**：

| 参数 | 统计 |
|------|------|
| `-l` | 行数（**换行符个数**） |
| `-w` | 词数（按空白分隔的「词」） |
| `-c` | 字节数 |
| `-m` | 字符数（UTF-8 下与 `-c` 不同） |
| `-L` | 最长行的**显示宽度** |

- ⚠️ **`wc -l` 数的是换行符，不是「行」**。如果文件末尾**没有换行符**，最后一行不会被计入。所以 `wc -l` 的结果可能比「实际行数」少 1。
  ```bash
  printf 'a\nb' | wc -l     # 1（实际有 2 行内容）
  printf 'a\nb\n' | wc -l   # 2
  ```
- `wc -l < file`（**输入重定向**）只输出数字，不输出文件名。这在脚本取变量时很重要：
  ```bash
  n=$(wc -l < file)      # 干净，n 就是纯数字
  n=$(wc -l file)        # n 会是 "1000 file"，后续算术会报错
  ```
- `-c` 与 `-m` 的区别：`wc -c` 按字节，`wc -m` 按字符（受 `LC_ALL` 影响）。沙盒里 `sales.csv` 里有 16 个汉字（研发×3、运维×3、市场×2），每个汉字 UTF-8 下占 3 字节，所以 `wc -c` 是 **288**，`wc -m` 是 `288 - 16*3 + 16 = ` **256**。两者相差 32，就是「多字节字符」的开销。
- 💡 判断「文件是否为二进制」：`grep -IL . file`（不含匹配 → 二进制）或 `file`。

</details>

### 24. 完整日志分析：Top 10 IP + 状态码分布 + 流量 ⭐⭐⭐

**场景**：你要给一份 `access.log` 出一份「一小时运维速报」，包含：
1. 请求量最高的 5 个 IP（含占比）
2. 各状态码的次数（按次数降序）
3. 总响应字节数与 5xx 占比

**要求**：用管道组合出这三块内容。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

TOTAL=$(wc -l < data/access.log)
echo "总请求数: $TOTAL"
echo

echo "=== Top 5 IP（含占比） ==="
awk '{print $1}' data/access.log \
  | sort | uniq -c | sort -rn | head -5 \
  | awk -v t="$TOTAL" '{printf "%-16s %6d  %5.1f%%\n", $2, $1, $1/t*100}'

echo
echo "=== 状态码分布 ==="
awk '{print $9}' data/access.log \
  | sort | uniq -c | sort -rn \
  | awk '{printf "%-5s %6d\n", $2, $1}'

echo
echo "=== 流量与错误率 ==="
awk '{ bytes += $10
       if ($9 == 500) e500++
       n++ }
     END { printf "总响应字节: %.2f MB\n", bytes/1024/1024
           printf "5xx 请求数: %d (%.1f%%)\n", e500, e500/n*100 }' data/access.log
```

**预期输出**：

```text
总请求数: 1000

=== Top 5 IP（含占比） ===
10.0.0.11          146   14.6%
203.0.113.9        145   14.5%
192.168.1.5        145   14.5%
203.0.113.10       144   14.4%
10.0.0.13          143   14.3%

=== 状态码分布 ===
200     607
404     231
403      57
500      56
301      49

=== 流量与错误率 ===
总响应字节: 47.61 MB
5xx 请求数: 56 (5.6%)
```

**解析**：

- **`awk -v t="$TOTAL"`** 把 shell 变量传进 awk。**不要用 `awk '...'  $TOTAL`** 或直接写 `$TOTAL`——awk 会把 `$TOTAL` 解释成「第 TOTAL 个字段」。
- shell 变量在**双引号**里才会被展开，`awk -v t="$TOTAL"` 里必须加引号。
- 一次遍历（single pass）比多次 `awk` 高效：`bytes`、`e500`、`n` 三个累计量在同一个 `awk` 里搞定。日志上 GB 级别时，这个差别非常明显。
- **`$9` 和 `$10` 的健壮性**：前面第 13 题说过，时间戳里的空格会让字段号右移。**生产环境的日志分析一定要先 `head -1` 确认字段号**，或者用 `-F'"'` 按引号切分后再数。
- 💡 加时间维度的分析（每分钟请求量，用于发现尖刺）：
  ```bash
  # 时间戳形如 [15/Sep/2026:01:07:13 → 取到分钟
  awk -F'[:[]' '{print $3":"$4}' data/access.log | sort | uniq -c | sort -rn | head -10
  ```
- 💡 只看异常的请求行，便于人工核对：
  ```bash
  awk '$9>=400 {print $1, $7, $9}' data/access.log | head -20
  ```

### 25. 两份名单求交集/差集，并输出一张对齐的报表 ⭐⭐⭐

**场景**：`a.txt` 是「本周活跃用户」，`b.txt` 是「上周活跃用户」。你要一份报表，列出：
- 两周都活跃的（交集）
- 只在**上**周活跃、本周流失的（差集）
- 并集总数

**要求**：用 `sort` + `comm` 完成，并输出表格化结果。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 准备数据
printf 'Alice\nBob\nCarol\nDave\n'  > /tmp/a.txt
printf 'Bob\nCarol\nEve\n'          > /tmp/b.txt

# ① 求交集（-12 = 隐藏第1列和第2列，只留第3列）
echo "=== 两周都活跃 ==="
comm -12 <(sort /tmp/a.txt) <(sort /tmp/b.txt)

# ② 只在上周活跃（本周流失）
echo "=== 本周流失 ==="
comm -13 <(sort /tmp/a.txt) <(sort /tmp/b.txt)

# ③ 只在本周活跃（新增）

comm -23 <(sort /tmp/a.txt) <(sort /tmp/b.txt)

# ④ 并集总数
echo "=== 并集 ==="
sort -u /tmp/a.txt /tmp/b.txt
echo "总数: $(sort -u /tmp/a.txt /tmp/b.txt | wc -l)"

# ⑤ 输出对齐报表
{

    inb=$(grep -qx "$u" /tmp/b.txt && echo "是" || echo "否")
    printf '%-8s %-8s %-8s\n' "$u" "$ina" "$inb"
  done
} | column -t
```

**预期输出**：

```text
=== 两周都活跃 ===
Bob
Carol
=== 本周流失 ===
Eve
=== 本周新增 ===
Alice
Dave
=== 并集 ===
Alice
Bob
Carol
Dave
Eve
总数: 5

用户   本周  上周
----   ----  ----
Alice  是    否
Bob    是    是
Carol  是    是
Dave   是    否
Eve    否    是
```

**解析**：

- **`comm` 的参数是一个三位掩码**，非常容易记错：

  | 参数 | 含义 | 输出 |
  |------|------|------|
  | （无） | 三列全显示 | 只在文件1 / 只在文件2 / 共有 |
  | `-1` | 隐藏第 1 列 | 只在文件2 / 共有 |
  | `-2` | 隐藏第 2 列 | 只在文件1 / 共有 |
  | `-3` | 隐藏第 3 列 | 只在文件1 / 只在文件2 |
  | `-12` | 只留第 3 列 | **共有（交集）** |
  | `-13` | 只留第 2 列 | 只在文件 2 |
  | `-23` | 只留第 1 列 | 只在文件 1 |

  记忆法：**数字表示「隐藏哪一列」**，三列的顺序固定是「文件1独有 / 文件2独有 / 共有」。

- ⚠️ **`comm` 要求输入已经排好序**，而且排序规则必须一致（locale 要相同）。没排序时它会直接报 `comm: file 1 is not in sorted order` 并给出错误结果。所以永远写成 `comm -12 <(sort a) <(sort b)`。
- `<(...)` 是**进程替换**（process substitution），把命令输出伪装成一个文件。这是 bash/zsh 特性，`sh`（dash）不支持——脚本里用 `#!/bin/bash` 才保险。
- 集合运算的替代方案：
  ```bash
  # 交集（用 grep -F 的 -x 整行匹配读另一个文件）
  grep -Fxf b.txt a.txt
  # 差集（-v 取反）
  grep -Fvxf b.txt a.txt
  # 并集去重
  cat a.txt b.txt | sort -u
  ```
  `grep -Fxf` 在大文件上比 `comm` 慢（要逐行扫），但**不需要预先排序**，写起来更省事。
- 💡 `paste` 是把两个文件**并排拼接**（按行号对齐），`join` 是**按共同键关联合并**（像 SQL JOIN）：
  ```bash
  paste -d: a.txt b.txt                     # 按行号并排
  join <(sort j1) <(sort j2)                # 按第 1 列做内连接
  ```
  两者都要求输入有序（`join` 必须有序），`paste` 不要求但也没有「匹配」概念。
