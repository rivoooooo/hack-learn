### 1. 我把终端切到别处去了，先确认自己在哪 ⭐

**场景**：你打开终端，不知道当前处于哪个目录，也不确定这个路径是真的还是软链接拼出来的。

**要求**：分别打印「逻辑路径」和「解析掉所有软链接后的真实物理路径」。

<details><summary>参考答案</summary>

```bash
pwd          # 打印逻辑路径（$PWD，可能含未解析的软链接）
pwd -P       # 打印物理路径（一路解析软链接后的真实位置）
```

**解析**：

- `pwd` 是 shell 内建命令，默认打印 `$PWD` 这个变量，它记录的是你「进来时用的路径」。如果你是 `cd` 进一个软链接目录，`pwd` 会显示软链接的名字。
- `pwd -P` 走 `getcwd(3)` 系统调用，内核返回的是解析后的真实路径。
- 二者不一致时，说明当前位置的路径中存在软链接。这在你排查「`cd` 到了以为的地方但其实不是」时非常关键。

**验证**：

```bash
mkdir -p /tmp/demo/a/b && ln -sfn /tmp/demo/a/b /tmp/demo/link
cd /tmp/demo/link
pwd        # /tmp/demo/link
pwd -P     # /tmp/demo/a/b        ← 真实位置
```

</details>

### 2. 看目录时总要加一堆参数，我想看清「隐藏文件 + 权限 + 时间 + inode」 ⭐

**场景**：审计一个目录，需要一次看全：权限、属主、大小、修改时间、软链接指向、隐藏文件。

**要求**：列出 `/tmp/linux-practice/data` 的全部内容（含隐藏项），并说明输出里每一项的含义。

<details><summary>参考答案</summary>

```bash
ls -la /tmp/linux-practice/data
```

**解析**：

| 参数 | 作用 |
|------|------|
| `-a` | 显示以 `.` 开头的隐藏文件，并额外显示 `.`（自身）与 `..`（父目录） |
| `-l` | 长格式：权限、硬链接数、属主、属组、大小、时间、名字 |
| `-h` | 大小带单位（`4.0K` 而不是 `4096`） |
| `-i` | 显示 inode 号 |
| `--time-style=long-iso` | 时间显示成 `2026-09-15 18:16`，比默认的 `Sep 15 18:16` 更适合复制 |

长格式逐列解读：

```
drwxr-xr-x  2  rivo rivo  4096 Sep 15 18:16  .
│└┬┘└┬┘└┬┘  │   │    │     │        │        └─ 文件名
│ │  │  │   │   │    │     │        └────────── 修改时间（mtime）
│ │  │  │   │   │    │     └─────────────────── 大小（目录是元数据大小，不是内容总和）
│ │  │  │   │   └────┴───────────────────────── 属组 / 属主
│ │  │  │   └────────────────────────────────── 硬链接数（目录 = 直接子目录数 + 2）
│ │  │  └────────────────────────────────────── 其他人权限 other
│ │  └───────────────────────────────────────── 属组权限 group
│ └──────────────────────────────────────────── 属主权限 user
└────────────────────────────────────────────── 类型：d 目录 / - 普通文件 / l 软链接
                （s 出现在 user 的 x 位 = SUID；t 出现在 other 的 x 位 = Sticky）
```

💡 只看隐藏文件：`ls -d .[!.]* 2>/dev/null`。`ls -A` 和 `-a` 的区别是 `-A` 不显示 `.` 与 `..`。

</details>

### 3. 在两个目录之间来回跳，每次都敲长路径太累 ⭐

**场景**：你在 `/tmp/linux-practice/projects/src` 和 `/tmp/linux-practice/data` 之间反复切换。

**要求**：用最少的按键完成一次「跳过去再跳回来」。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice/projects/src
cd /tmp/linux-practice/data
cd -            # 跳回 /tmp/linux-practice/projects/src，并打印该路径
cd -            # 再跳回 /tmp/linux-practice/data（- 永远指向上一个目录）
```

**解析**：

- `cd -` 等价于 `cd "$OLDPWD"`，且会把切换后的路径打印出来（所以你能看见自己到了哪）。
- `cd` 不带参数 = `cd "$HOME"`（等价 `cd ~`）。
- `cd ..` 上一级；`cd ../..` 上两级。
- `cd` 时 `-` 之后加空格可以补全，不用手动敲。

💡 配合 `pushd`/`popd` 可以维护一个目录栈（`dirs -v` 查看），比 `cd -`（只能记一层）更灵活。

</details>

### 4. 一个路径里混着 `~`、`..`、软链接，我要拿到它的绝对规范形式 ⭐⭐

**场景**：脚本里收到一个用户输入的相对路径 `../data/softlink.txt`，你想拿到「解析软链接后 + 去掉 `..` + 变成绝对路径」的最终结果。

**要求**：打印该文件的规范绝对路径；再打印它作为软链接本身指向的目标（不解析）。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice/projects
realpath ../data/softlink.txt          # 绝对 + 规范化 + 解析软链接
readlink -f ../data/softlink.txt       # 同上
readlink ../data/softlink.txt          # 只打印软链接里存的原始目标字符串
realpath -m ./not-exist/../x.txt       # -m：路径不存在也能算出来（不校验存在性）
```

**预期输出**：

```text
/tmp/linux-practice/data/original.txt      ← realpath / readlink -f 的结果
/tmp/linux-practice/data/original.txt      ← softlink 的目标（沙盒里它就是绝对路径）
```

**解析**：

- `realpath` 与 `readlink -f` 功能几乎相同，都做「相对转绝对 + `..`/`.` 折叠 + 软链接解析」。区别：`realpath` 要求路径**中间**的目录都存在（末段可以不存在），`readlink -f` 更宽松一点；脚本里 `realpath` 更常见。
- `readlink`（不带 `-f`）**不做任何解析**，就是把软链接文件里存的那串字符原样打印出来。这正是你要找「这个链接指向哪」时该用的。
- 排查断链：`readlink` 有输出但 `test -e` 为假 → 目标不存在。见第 12 题。

⚠️ 注意 `realpath` 与 `readlink -f` 在**末段是软链接**时都会解析；如果你要的是「软链接自身所在的目录」，用 `dirname`/`readlink -f "$(dirname "$f")"`。

</details>

### 5. 一次建出多层目录，中间层不存在也不能报错 ⭐

**场景**：部署脚本要创建 `/tmp/linux-practice/projects/logs/2026/09`，但 `logs/2026` 还不存在。

**要求**：一条命令建出整条路径，且无论哪一层已存在都不报错。

<details><summary>参考答案</summary>

```bash
mkdir -p /tmp/linux-practice/projects/logs/2026/09
# 一次建多个：
mkdir -p /tmp/linux-practice/{conf,run,tmp}/sub
```

**解析**：

- `-p`（parents）做两件事：① 逐级创建缺失的父目录；② 目录已存在时不报错（幂等）。脚本里**永远用 `mkdir -p`**。
- 反例：`mkdir a/b/c` 在 `a` 不存在时直接失败 `No such file or directory`。
- `-m 750` 可以在创建时直接指定权限：`mkdir -p -m 750 /tmp/demo/private`。
- 想建目录同时知道权限是否被 `umask` 改过，用 `mkdir -m` 时权限**不受 umask 影响**（`-m` 是显式指定）。

💡 需要「临时目录」时不要手搓名字，用 `mktemp -d`：它保证名字唯一且权限是 `700`，不会被人抢注。

```bash
d=$(mktemp -d) && echo "$d"    # /tmp/tmp.lXeFO0
```

</details>

### 6. 创建空文件，然后把它的修改时间改成三天前 ⭐

**场景**：测试脚本时需要一个空文件；另外要伪造一个「三天前修改过」的日志文件，用来测试日志轮转逻辑。

**要求**：创建 `/tmp/linux-practice/backup/empty.txt`；再创建 `/tmp/linux-practice/backup/old.log` 并把它的 mtime 改成 3 天前。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice
touch backup/empty.txt
touch backup/old.log
touch -d '3 days ago' backup/old.log

# 验证
ls -l --time-style=long-iso backup/empty.txt backup/old.log
stat -c '%n  修改时间=%y' backup/old.log
```

**解析**：

- `touch 已存在的文件`：内容不动，只把 atime/mtime 更新为当前时间（这就是它做「时间戳」的本职）。
- `touch 不存在的文件`：创建一个 0 字节文件。
- `-d` 接受人类可读时间：`'3 days ago'`、`'2026-01-01 08:00'`、`'next Monday'`、`@1700000000`（Unix 时间戳）。
- 只改 mtime 用 `-m`，只改 atime 用 `-a`，指定参考文件用 `-r otherfile`。
- `-c`（`--no-create`）：文件不存在时**不要**创建，只更新时间——脚本里常用来安全地「标记」已存在的文件。

⚠️ `touch` 不会 truncate 已有文件的内容，但如果你想要「清空」，用 `: > file` 或 `truncate -s 0 file`，那是**不可逆**的。

</details>

### 7. `cp` 丢了权限和时间：备份目录后才发现不对 ⭐⭐

**场景**：你把一个项目目录「备份」到 `/tmp/linux-practice/backup/`，结果发现：软链接变成了普通文件、权限全部重置成默认、修改时间全变成现在。

**要求**：给出正确的备份方式，并说明普通 `cp -r` 为什么不行。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ❌ 常见错误：软链接被跟随后复制成实体文件，权限/时间也丢
cp -r projects backup/projects-bad

# ✅ 正确：归档式复制
cp -a projects backup/projects-good

# 也可以显式写全
cp -rpd projects backup/projects-good2     # -r 递归 -p 保留属性 -d 保留链接自身

# 对比结果
ls -l backup/projects-bad/src backup/projects-good/src
stat -c '%n %y' backup/projects-bad/src/app.conf backup/projects-good/src/app.conf
```

**解析**：

| 参数 | 作用 | 不加会怎样 |
|------|------|-----------|
| `-a` | `-dR --preserve=all` 的缩写 | — |
| `-d` | 复制软链接**自身**，不跟随 | 软链接被解析，复制成实体文件 |
| `-p` | 保留 mode、ownership、timestamps | 权限按 `umask` 重算、mtime 变现在 |
| `-R`/`-r` | 递归目录 | 直接报 `omitting directory` |
| `-u` | 只复制更新的（增量） | 全量覆盖 |
| `-i` | 覆盖前询问 | 静默覆盖 |
| `-n` | 不覆盖已存在 | — |

- `-a` = `-dR --preserve=all`，其中 `all` 包含 mode、ownership、timestamps、links、xattr、context。**备份就用 `-a`**。
- 跨机器/跨用户时 `-p` 想保留属主需要 root，普通用户会保留不了 ownership（这是正常的，会用 `cp: failed to preserve ownership` 警告）。
- 真正的大规模备份/同步该用 `rsync -aH --delete` 或 `tar`，见 [`../commands/06-网络.md`](../commands/06-网络.md) 的 `rsync` 一节。

</details>

### 8. 把文件改名，顺便把一批文件挪到别处 ⭐

**场景**：`app.conf.new` 是配置文件的新版本，你想把旧的重命名成 `app.conf.old`，新的改名为 `app.conf`；再把 `data/files.csv` 移到 `archive/` 下。

**要求**：完成这些操作并验证。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice/projects/src
mv app.conf app.conf.old        # 同目录 mv = 重命名
mv app.conf.new app.conf        # 新的顶上

cd /tmp/linux-practice
mv data/files.csv archive/      # 移到目录下，保持原名
mv data/fruit.txt archive/renamed-fruit.txt   # 移动同时改名

ls -l projects/src archive
```

**解析**：

- `mv` 是「改名」和「移动」**同一个操作**：都在改目录项（dentry），所以同分区内瞬间完成、不复制数据。
- **跨文件系统**（比如从 `/tmp` 挪到 `/home`，不同挂载点）时 `mv` 会退化成「复制 + 删除」，此时大文件会明显变慢，且中途断电可能两头都不完整。
- ⚠️ `mv a b` 里如果 `b` 是**已存在的目录名**，则变成「把 `a` 移进 `b/`」，而不是「把 `a` 改名成 `b`」。这是最常见的误操作。想强制改名用 `mv -T a b`（`-T` = 把目标当普通文件，不做目录推断）。
- 覆盖已存在文件时用 `-i` 交互确认，或 `-n` 不覆盖。`alias mv='mv -i'` 是很多发行版默认就有的。
- 批量改名（模式替换）：`rename 's/\.txt$/.text/' *.txt`，注意 `rename` 有两个互不兼容的实现（`util-linux` 版是 `rename 旧 新 文件...`），先 `rename --version` 确认。

</details>

### 9. ⚠️ 删掉一整个目录，但我要先确认删的是哪个 ⭐

**场景**：`/tmp/linux-practice/` 下有一堆测试产物要清理。你希望**先看一眼**将被删的内容，确认无误再删。

**要求**：给出「先预览、再删除」的两步操作。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 第 1 步：预览（不删任何东西）
ls -la backup/
find backup/ -maxdepth 2

# 第 2 步：确认后删
rm -rf backup/projects-bad

# 更稳的写法：用一个明显的临时目录名，避免手滑
rm -rf ./backup/projects-bad
```

**⚠️ 后果说明**：

- `rm` **不进回收站、不可撤销**。`rm -rf /` 会尝试删除整个系统（GNU 核心工具有 `--preserve-root` 默认保护，但仍会摧毁其余全部数据）。
- 真正致命的三个写法：
  - `rm -rf $DIR/` —— 当 `$DIR` 为空字符串时变成 `rm -rf /`
  - `rm -rf /tmp/test /tmp/data` —— 中间**多了一个空格**，第二个路径也被删
  - `rm -rf *` 在错误目录执行
- 安全复现建议（**只在 `/tmp` 下练**）：先 `cp -a` 备份。

**安全写法模板**：

```bash
# ① 变量一定加引号并校验非空
DIR=/tmp/linux-practice/backup/projects-bad
[ -n "$DIR" ] && [ "$DIR" != "/" ] && rm -rf -- "$DIR"

# ② 用 find 限制范围（-delete 前先去掉 -delete 跑一遍看输出）
find /tmp/linux-practice/backup -maxdepth 1 -name 'projects-bad' -print
find /tmp/linux-practice/backup -maxdepth 1 -name 'projects-bad' -delete

# ③ 删除前先落到 trash
mv backup/projects-bad /tmp/trash-$$
```

**解析**：

- `--` 表示「选项结束」，能防住以 `-` 开头的恶意文件名（比如你误删的文件叫 `-rf`）。
- `rm -r` 删目录、`rm -d` 只删空目录（`rmdir` 的等价物）、`rm -f` 忽略不存在的报错并强制（不询问）。
- 想「覆写后再删」（对抗数据恢复）：`shred -u file`，注意在 SSD/CoW 文件系统（btrfs、ZFS）上不保证有效。

</details>

### 10. 判断两个文件是不是同一份数据 ⭐⭐

**场景**：`/tmp/linux-practice/data/` 下有 `original.txt` 和 `hardlink.txt`，你想知道它们是「同一个文件的两种名字」还是「两份独立但内容相同的拷贝」。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice/data

# 方法一：比 inode 号（最权威）
ls -li original.txt hardlink.txt
stat -c '%n  inode=%i  硬链接数=%h' original.txt hardlink.txt

# 方法二：判断是否指向同一 inode（脚本里用）
[ original.txt -ef hardlink.txt ] && echo "同一个文件" || echo "不同文件"

# 对比：内容相同但 inode 不同
md5sum original.txt hardlink.txt
```

**预期输出**：

```text
478938 -rw-r--r-- 2 rivo rivo 15 ... data/hardlink.txt
478938 -rw-r--r-- 2 rivo rivo 15 ... data/original.txt
        ↑ inode 号完全相同，硬链接数 = 2
```

**解析**：

- **inode 才是文件的真实身份**，文件名只是目录里「名字 → inode」的一条映射。硬链接 = 新增一条指向同一 inode 的映射，所以 inode 号相同、`stat` 的 Links 计数为 2。
- `[ a -ef b ]` 是 shell 的「同一文件」测试，内部就是比 `st_dev` + `st_ino`，比 `md5sum` 更快也更准（内容相同但 inode 不同时它返回假，这才是你要的语义）。
- `md5sum` 相同只说明**内容**相同，不能说明是同一文件——两份独立拷贝也会得到相同哈希。
- 硬链接的限制：不能跨文件系统、不能指向目录（防止目录树成环）。软链接没有这些限制。

</details>

### 11. 软链接和硬链接的区别，用命令亲自验证 ⭐⭐

**场景**：你要给同事讲清楚软链接和硬链接，不想只背概念。

**要求**：设计一组操作，从**删除源文件后**的行为、**跨文件系统**、**能否指向目录**三个角度证明两者不同。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice/data
ls -li original.txt hardlink.txt softlink.txt
```

```text
478938 -rw-r--r-- 2 rivo rivo 15 ... hardlink.txt     ← 普通文件，同 inode
478938 -rw-r--r-- 2 rivo rivo 15 ... original.txt
478939 lrwxrwxrwx 1 rivo rivo 37 ... softlink.txt -> /tmp/linux-practice/data/original.txt
        ↑ 类型 l，权限恒为 rwxrwxrwx（无意义），大小 = 目标路径字符串长度
```

**实验一：删掉源文件，看谁还活着**

```bash
cd /tmp/linux-practice
cp -a data /tmp/hl-test && cd /tmp/hl-test    # 在副本上做，不动沙盒
ls -li original.txt hardlink.txt softlink.txt
rm original.txt
echo "--- 删除 original.txt 之后 ---"
cat hardlink.txt               # ✅ 内容还在（inode 未释放）
cat softlink.txt               # ❌ No such file or directory（断链）
ls -l softlink.txt             # 仍然显示 lrwxrwxrwx，指向"不存在的目标"
```

**实验二：跨文件系统**

```bash
ln /tmp/hl-test/hardlink.txt /dev/shm/hl-x      # ❌ Invalid cross-device link
ln -s /tmp/hl-test/hardlink.txt /dev/shm/sl-x   # ✅ 软链接可以，因为它只存路径字符串
```

**实验三：指向目录**

```bash
ln /tmp/linux-practice/data /tmp/dirlink         # ❌ hard link not allowed for directory
ln -s /tmp/linux-practice/data /tmp/dirlink      # ✅ 可以
```

**解析**：

| 对比项 | 硬链接 | 软链接（符号链接） |
|--------|--------|-------------------|
| 本质 | 目录里多一条「名字 → inode」映射 | 一个独立文件，内容是目标路径字符串 |
| inode | 与源文件**相同** | **不同**，有自己的 inode |
| `ls -l` 第一列 | `-` 普通文件 | `l` |
| 删除源文件 | 内容仍在（Links 减 1） | 断链 |
| 跨文件系统 | ❌ | ✅ |
| 指向目录 | ❌（防止环） | ✅ |
| 相对路径解析 | 无意义 | 相对于**软链接所在目录**，不是当前目录 |
| `stat` 大小 | 等于文件内容大小 | 等于目标路径字符串长度 |

- 「文件被删除」的真实含义是：**硬链接计数归零**才释放 inode 与数据块。所以 `rm` 一个还有硬链接的文件不会丢数据。
- 软链接的权限位永远显示 `rwxrwxrwx`，实际权限由**目标文件**决定（Linux 不检查软链接自身权限）。
- 💡 复制软链接时 `cp a b` 会跟随、复制成实体文件；要保留链接用 `cp -a`（或 `-d`）。
- 💡 尾斜杠语义差别（经典坑）：`cp -a link/ dest` 中 `link` 后加 `/` 会**跟随**链接，把目标目录的内容复制出来。加不加 `/` 结果完全不同，见 [`../basics/01-文件系统与目录结构.md`](../basics/01-文件系统与目录结构.md) 的「实战陷阱：软链接的尾斜杠」。

</details>

### 12. 找出目录里所有的「断链」 ⭐⭐

**场景**：服务迁移后，配置目录里一堆软链接指向了已经删掉的旧路径，程序启动时报 `No such file or directory`，但 `ls` 看起来文件都在。

**要求**：一条命令列出 `/tmp/linux-practice/data` 下所有失效的软链接及其目标。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方法一：find -xtype l（xtype 看的是"跟随链接之后的类型"，l 表示跟随失败退化成链接）
find data -xtype l -printf '%p  ->  %l\n'

# 方法二：-type l 后再用 test 判断目标是否存在（语义更直白）
find data -type l ! -exec test -e {} \; -print

# 方法三：列出所有软链接，用颜色/属性人工区分
ls -l data/*link*
```

**预期输出**：

```text
data/broken_link  ->  /nonexistent/path
```

**解析**：

- `find -xtype l` 的含义：`-xtype` 对软链接做「跟随之后判断类型」。正常软链接跟随成功后会变成 `f`/`d`，**跟随失败（断链）时才保持 `l`**，所以 `-xtype l` 精确命中断链。
- 反过来 `-type l` 会命中**所有**软链接，包括好的。
- `! -exec test -e {} \;` 里 `!` 是 `find` 的取反，`\;` 表示对每个文件单独执行一次 `test`（用 `+` 会失效，因为 `test` 不接受多参数这种用法）。
- 🔐 安全视角：攻击者常把 `/etc/ld.so.preload`、动态库、cron 脚本做成指向自己目录的软链接。审计时除了找断链，还要看**软链接指向哪里**：
  ```bash
  find /etc /usr/lib -type l -printf '%p -> %l\n' | grep -vE '^\S+ -> (/usr|/lib)' | head
  ```

💡 修复断链：`ln -sfn 新目标 链接名`。注意 `-n`（`--no-dereference`）——不加它时如果目标是目录，会在目标目录**内部**建一个新链接，而不是替换链接本身。

</details>

### 13. 只看文件的前 N 行、后 N 行、第 N 行 ⭐

**场景**：`sales.csv` 第一行是表头，你需要跳过表头只看数据；另一个场景是要监控日志的最新 20 行。

**要求**：分别取出「表头」「纯数据行」「最后 20 行」「第 5 行」。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

head -n 1 data/sales.csv              # 表头
tail -n +2 data/sales.csv             # 从第 2 行到结尾（跳过表头）
tail -n 20 data/access.log            # 最后 20 行
head -n 20 data/access.log            # 前 20 行
sed -n '5p' data/sales.csv            # 只要第 5 行
awk 'NR==5' data/sales.csv            # 同上
sed -n '3,5p' data/sales.csv          # 第 3 到 5 行
```

**解析**：

- `tail -n +2` 里的 `+2` 是「从第 2 行开始」，`+` 号是关键；`tail -n 2` 是「最后 2 行」。**`+` 号记错就完全变意思**。
- `head -c 20 file` 按**字节**取，`head -n 20` 按行取。日志文件里混了字节取法会把多字节 UTF-8 字符截断成乱码（`file` 会报 `Non-ISO extended-ASCII text`）。
- `sed -n '5p'` 里的 `-n` 必须加，否则 sed 默认会把所有行都打印一遍、变成「全文 + 第 5 行重复一次」。
- 处理超大文件时 `head`/`tail` 比 `cat` 快得多：`head` 读到够就退出（不读完整个文件），`tail -n` 虽然要读到结尾但只保留环形缓冲。

💡 取「中间某个区间」用 `sed -n 'A,Bp'`；取「倒数第 3 行」用 `tail -n 3 | head -n 1`。

</details>

### 14. 实时盯着日志，还要看清输出里的换行符到底是什么 ⭐⭐

**场景**：两个需求。① 部署时想实时看日志的新增行；② 从 Windows 传过来的配置文件在 Linux 下解析异常，怀疑是 CRLF 换行。

**要求**：① 持续输出 `/tmp/linux-practice/projects/logs/app.log` 的新行；② 查明 `/tmp/linux-practice/data/sales.csv` 的换行符类型。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ① 实时跟随
tail -f projects/logs/app.log
# 文件被「重建」（如 logrotate 切割）时 -f 会失效，改用：
tail -F projects/logs/app.log
# 只看含 ERROR 的新行
tail -f projects/logs/app.log | grep --line-buffered ERROR

# ② 检查换行符
cat -A data/sales.csv | head -2
file data/sales.csv
```

**预期输出（②）**：

```text
id,name,dept,amount,date$
1,Alice,研发,1200.50,2026-01-03$
```

**CRLF 的话会显示成**：

```text
id,name,dept,amount,date^M$
                          ↑ 多出来一个 ^M
```

**解析**：

- `cat -A` = `-vET`：`$` 标行尾、`^I` 标 Tab、`^M` 标 `\r`（CR）、其它不可打印字符用 `M-`/`^` 记法。**排查换行符/制表符/奇怪不可见字符的第一手段**。
- 相关命令：`dos2unix file`、`sed -i 's/\r$//' file`（去掉行尾 CR）、`tr -d '\r' < win.txt > unix.txt`。
- `tail -f` 与 `tail -F`：`-F` = `--follow=name --retry`，按**文件名**跟随并重试，日志轮转（文件被 rename + 新建同名）后能自动接上。生产环境一律用 `-F`。
- 管道里 `grep` 会因为输出不是终端而启用块缓冲（默认 4KB），导致「日志刷了但你看不到」。加 `--line-buffered` 让它逐行输出。同理 `awk` 需要 `fflush()`，`stdbuf -oL 命令` 也能强制行缓冲。
- `less +F` 是更好的交互式跟随：`Ctrl+C` 暂停后可以像普通 `less` 一样上下翻看，`F` 回到跟随模式；`Shift+F` 退出跟随。

💡 一个日志里同时跟多个文件：`tail -F a.log b.log`，输出会自动加 `==> 文件名 <==` 分隔。

</details>

### 15. 通配符没按预想展开，把不该删的也匹配上了 ⭐⭐

**场景**：你想对 `/tmp/linux-practice/my dir/` 下所有 `.txt` 操作，结果把中文文件也带上了；另一次 `rm *.log` 差点匹配到不相关的东西。

**要求**：说清 `*`、`?`、`[]`、`**`、`{}`、`[!]` 各自的匹配规则，并演示如何**先安全预览**再执行。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice/my dir

# ① 先预览展开结果（最关键的一步）
echo *.txt          # 打印 shell 展开后的结果，不执行任何命令
printf '%s\n' *.txt

# ② 各种 glob
echo *              # 匹配任意长度字符，不包括以 . 开头的隐藏文件
echo ?	             # 匹配「恰好一个」任意字符
echo [ch]*          # 匹配 c 或 h 开头的名字
echo [!c]*          # 匹配「不是」c 开头的名字（[!...] = 取反，等价于 [^...]）
ls {a,b}*           # 匹配 a* 或 b*
echo {1..3}         # 大括号展开 → 1 2 3
echo pre{a,b}post   # → preapost prebpost
```

**解析**：

- **glob 由 shell 展开，不是命令做的**。`rm *.log` 里 `rm` 收到的其实是 shell 展开后的一串文件名。理解这点，就能理解为什么「文件名叫 `-rf`」会出事——`rm` 把它当选项了；用 `rm -- *` 或 `rm ./-rf` 规避。
- `*` **不匹配**以 `.` 开头的文件（`.` 和 `..` 也永不匹配），所以 `rm *` 不会删隐藏文件。要连隐藏文件一起：`rm -rf ./* ./.[!.]*`（更稳的是 `find`）。
- `?` 只匹配**一个**字符；`*` 匹配**零个或多个**。
- `[]` 里可以写范围 `[0-9]`、字符集 `[abc]`、取反 `[!abc]`。`-` 在中间才是范围，放开头/结尾是字面量。
- `**` 递归匹配多级目录，但**只有开启 `globstar` 才有意义**：`shopt -s globstar` 后 `**/*.log` 才会递归。默认没开时 `**` 等同于 `*`。
- `{}` 是**大括号展开**（brace expansion），发生在 glob 展开**之后**，匹配的是字面量组合，不查文件系统，所以 `echo {a,b}` 即使 `a`、`b` 不存在也会输出。这是它和 `[]` 最本质的区别。
- ⚠️ **没有匹配项时的行为**：bash 默认把 `*.xyz` 原样传给命令，于是 `rm *.xyz` 会变成 `rm '*.xyz'`（报错 `No such file`）；但 `cat *.xyz` 会去读一个真的叫 `*.xyz` 的文件。用 `shopt -s nullglob` 让无匹配时展开为空，`shopt -s failglob` 让它直接报错。

**安全模板**：

```bash
# 任何破坏性命令之前，先 echo 一遍
echo rm -rf /tmp/linux-practice/my\ dir/*.txt
# 确认输出无误后，去掉 echo 执行
```

</details>

### 16. 文件名里有空格和特殊字符，脚本里全乱了 ⭐⭐

**场景**：`/tmp/linux-practice/my dir/hello world.txt` 和 `/tmp/linux-practice/data/特殊*字符.txt` 这两个文件名里分别有空格和 `*`。你写的循环把它们拆成了好几个「文件」。

**要求**：安全地遍历并打印这些文件的内容/名字。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# ❌ 错误：for 按 IFS（空格/制表/换行）分词，"hello world.txt" 被拆成两个词
for f in $(find . -name '*.txt'); do echo "$f"; done

# ✅ 正确一：for 直接遍历 glob（glob 展开的结果不做二次分词）
for f in "my dir"/*.txt; do echo "[$f]"; done

# ✅ 正确二：find -print0 + xargs -0（最稳，支持任意字节的文件名）
find . -name '*.txt' -print0 | xargs -0 -I{} echo "[{}]"

# ✅ 正确三：find -exec（不经过 shell 分词）
find . -name '*.txt' -exec echo "[{}]" \;

# ✅ 正确四：while read + 进程替换
while IFS= read -r -d '' f; do echo "[$f]"; done < <(find . -name '*.txt' -print0)

# 访问带特殊字符的名字
cat 'data/特殊*字符.txt'        # 单引号把 * 变成字面量
cat data/特殊\*字符.txt         # 反斜杠转义
cat ./data/*字符.txt            # 让 glob 自己匹配
```

**解析**：

- **只要文件名可能含空格/换行/glob 字符，就必须用「数组」或「NUL 分隔」传递**。`$(...)` 命令替换会按 `IFS` 分词，这是 shell 最大的经典坑。
- `find ... -print0` 用 `\0`（NUL）分隔。**NUL 是文件名中唯一不可能出现的字节**（`/` 也不能出现，但它是路径分隔符），所以这是唯一 100% 安全的方案。对应消费者：`xargs -0`、`while read -d ''`、`tar --null -T -`、`grep -Z`。
- `find -exec cmd {} \;` 每个文件启动一次进程（安全但慢）；`-exec cmd {} +` 批量传参（快，但要求命令本身能接受多个文件名，且不能把 `{}` 放在中间）。
- `-I{}` 让 `xargs` 每个参数单独替换一次（类似 `\;`），不加 `-I` 时 `xargs` 会一次传多个。
- 💡 想「看一眼」实际字节：`ls -b`（把不可打印字符转义显示）、`printf '%q\n' "$f"`（输出可安全粘回 shell 的引用形式）。

</details>

### 17. 单引号、双引号、反引号，用错了结果完全不同 ⭐⭐

**场景**：你要写一行输出 `今天是 $DATE，当前目录是 /tmp/linux-practice`，其中 `$DATE` 必须是字面量，而路径要展开。

**要求**：给出正确的引号用法，并解释三种引号/替换的区别。

<details><summary>参考答案</summary>

```bash
DATE=2026-09-15

echo '今天是 $DATE，当前目录是 '"$PWD"      # 单引号原样 + 双引号展开 → 今天是 $DATE，当前目录是 /tmp/linux-practice
echo "今天是 \$DATE，当前目录是 $PWD"        # 双引号里用 \ 转义 $  ← 更常用
```

```bash
# 各种引用/替换对比
echo '$HOME'        # $HOME           单引号：完全字面量，什么都不展开
echo "$HOME"        # /home/rivo      双引号：展开变量、命令替换、算术、转义
echo $HOME          # /home/rivo      不加引号：会分词 + glob 展开 ← 危险
echo `date +%F`     # 2026-09-15      反引号：老式命令替换
echo $(date +%F)    # 2026-09-15      $()：现代写法，可嵌套、可读
echo "${HOME}dir"   # /home/rivodir   ${} 限定变量名边界
echo $((2+3))       # 5               算术展开
```

**解析**：

| 写法 | 变量展开 | 分词 | glob 展开 | 备注 |
|------|---------|------|-----------|------|
| `'...'` | ❌ | ❌ | ❌ | 最安全，字面量 |
| `"..."` | ✅ | ❌ | ❌ | **默认应该用这个** |
| `...`（裸） | ✅ | ✅ | ✅ | 只在确定无空格/无 glob 时使用 |
| `` `...` `` | 命令替换 | — | — | 不可嵌套，已被 `$()` 取代 |
| `$(...)` | 命令替换 | — | — | 推荐 |

- **双引号是默认选择**：`"$var"` 保证变量值里的空格不会导致分词。`[ -n $x ]` 在 `x` 为空时会变成 `[ -n ]`（单参数测试，结果为真！），`[ -n "$x" ]` 才是对的。
- 单引号内**无法**出现单引号本身（`'` 会立刻结束引用）。要在单引号里放单引号，用 `'\''` 拼接，或改用双引号。
- `$'...'`（ANSI-C 引用）会解释转义序列：`echo $'a\tb\nc'` 会输出真正的 Tab 和换行。
- 💡 在 `echo` 里打印带 `-` 开头的内容用 `echo -- "$x"`，或用 `printf '%s\n' "$x"`（`printf` 行为更可预测）。

</details>

### 18. 大括号展开批量造测试数据，比写循环快 ⭐⭐

**场景**：你要快速造出 `app-01.log` 到 `app-05.log`、`backup-2026-09-01` 到 `backup-2026-09-03` 这样的测试文件/目录。

**要求**：用大括号展开一行造出来（不要写 `for` 循环），并说明它和 glob 的区别。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice
mkdir -p /tmp/demo

# ① 数字序列（可补零）
touch /tmp/demo/app-{01..05}.log
ls /tmp/demo

# ② 字母序列
touch /tmp/demo/disk-{a..e}.img

# ③ 逗号列表 + 笛卡尔积
mkdir -p /tmp/demo/{dev,prod}/{logs,conf}
find /tmp/demo -maxdepth 2 -type d | sort

# ④ 定步长
echo {0..20..5}          # 0 5 10 15 20

# ⑤ 和 glob 组合
touch /tmp/demo/{app,web}-{01..03}.{log,txt}
ls /tmp/demo | sort
```

**解析**：

- 大括号展开（brace expansion）**在 glob 之前执行**，是纯文本替换，不查文件系统。所以 `echo {x,y}` 即使 `x`、`y` 不存在也照常输出。
- `{01..05}` 会自动补零；`{1..5}` 不补零。这个差别在排序时很关键：`app-10.log` 会排在 `app-2.log` **前面**（字符串序），补零后 `app-02.log` 才是正确顺序。
- `{a..e}`、`{e..a}` 支持逆序。
- **`{a,b}` ≠ `[ab]`**：前者是文本展开（即使无匹配也产生结果），后者是 glob 匹配（必须文件存在才展开）。`ls {a,b}.txt` 在文件不存在时会把 `{a,b}.txt` 原样传给 `ls` 并报错。
- 和 glob 一样，**展开结果会做分词**，所以造出的名字如果含空格仍需引号处理。

</details>

### 19. 给危险命令加别名，让手滑有缓冲 ⭐⭐

**场景**：你经常在服务器上敲 `rm`，想默认就有确认；另外想给 `ls -la`、`grep --color` 之类的常用组合设个短名字。

**要求**：定义一个别名、查看它、临时绕过它、并让它永久生效。

<details><summary>参考答案</summary>

```bash
# 定义（当前 shell 立即生效）
alias rm='rm -i'
alias ll='ls -alF --color=auto'
alias grep='grep --color=auto'
alias du1='du -h --max-depth=1 | sort -rh'

# 查看
alias                 # 列出全部
alias ll              # 看某个

# 临时绕过别名（三种）
\rm 文件              # 反斜杠前缀：让 shell 跳过别名查找
command rm 文件       # command 内建：跳过别名与函数
/usr/bin/rm 文件      # 直接写全路径

# 永久生效：写进启动文件
echo "alias ll='ls -alF --color=auto'" >> ~/.bashrc
source ~/.bashrc      # 或 . ~/.bashrc
```

**解析**：

- **别名只对交互式 shell 生效**（默认），脚本里不生效。所以「`alias rm='rm -i'` 之后脚本就安全了」是错觉。脚本里要安全必须自己写 `rm -i` 或用 `set -o noclobber` 之类。
- 别名的展开规则：**只在命令行第一个词位置**展开；展开结果如果又是个别名会继续展开（但不会无限递归）。`sudo rm` 中的 `rm` **不会**触发你的别名（因为它是 `sudo` 的参数），所以 `alias sudo='sudo '`（末尾有空格）可以让 `sudo` 后第一个词也走别名展开。这是安全加固里一个常见技巧。
- 别名**不能带参数**。需要参数就用函数：

  ```bash
  mkdir() { command mkdir -p "$@"; }     # 让 mkdir 默认带 -p
  ```

- 持久化的位置（见 [`../basics/05-环境变量与Shell启动过程.md`](../basics/05-环境变量与Shell启动过程.md)）：
  - `~/.bashrc`：交互式非登录 shell（新开终端）——**最常用**
  - `~/.bash_profile` / `~/.profile`：登录 shell（SSH 登录、图形界面登录）
  - `/etc/bash.bashrc`（Debian）/ `/etc/bashrc`（RHEL）：全用户
- ⚠️ 登录 shell 与交互式 shell 的加载顺序不同，容易出现「SSH 上去别名没生效」。判断方法：`shopt -q login_shell && echo 登录shell || echo 非登录`。

</details>

### 20. 刚才那条很长的命令想再跑一次，但不想重敲 ⭐

**场景**：你五分钟前敲了一条很长的 `find`+`xargs` 管道，现在想改一个参数重跑。

**要求**：给出至少三种「找回并复用历史命令」的方法。

<details><summary>参考答案</summary>

```bash
# ① 交互式反向搜索：按 Ctrl+R，输入关键词，再按 Ctrl+R 继续往前找，回车执行
#    （此为终端快捷键，不是命令）

# ② 列出最近历史，人工挑
history
history 20              # 最近 20 条
history | grep find     # 过滤

# ③ 直接用编号重跑
history | tail -5       # 看到编号，例如 512
!512                    # 重跑第 512 条
!!                      # 重跑上一条
!find                   # 重跑最近一条以 find 开头的命令
sudo !!                 # 上一条命令加 sudo 再来一遍

# ④ 上一条命令的最后一个参数（Alt+. 或）
mkdir -p /tmp/linux-practice/very/long/path
cd !$                   # $ 指"最后一个参数"

# ⑤ 先打印不执行（危险命令必用）
!find:p                 # 打印展开后的命令，确认无误再去掉 :p 执行

# ⑥ 控制历史文件
echo "$HISTFILE"                    # 历史文件位置（默认 ~/.bash_history）
echo "$HISTSIZE $HISTFILESIZE"      # 内存条数 / 文件条数上限
history -c                          # 清空当前会话历史
history -d 512                      # 删除第 512 条
history -w                          # 立刻把内存历史写入文件
```

**解析**：

- **历史默认只在 shell 退出时写入 `~/.bash_history`**。多终端同时在用时，各自的历史会互相覆盖。解决办法：让历史即时追加。

  ```bash
  # 追加到 ~/.bashrc
  shopt -s histappend          # 退出时"追加"而不是"覆盖"
  PROMPT_COMMAND='history -a'  # 每敲一条命令就立刻写文件
  HISTCONTROL=ignoreboth       # 不记录"以空格开头"和"重复"的命令
  HISTTIMEFORMAT='%F %T '      # 给 history 加上时间戳
  ```

- `HISTCONTROL=ignorespace` 之后，**以空格开头的命令不进历史**。这是「不想让密码留在 `~/.bash_history`」的常用手法。
- 🔐 **安全提示**：`~/.bash_history` 是攻击者拿 shell 后必看的第一批文件之一（`history`、`cat ~/.bash_history`）。所以命令行里直接写密码（`mysql -p'pass'`）极其危险。反过来，排查入侵时也要检查历史：
  ```bash
  cat ~/.bash_history | grep -iE 'wget|curl|nc |base64|chmod \+x|/tmp/' 
  ```
- `!$`、`!$`、`!*` 属于「历史展开」（history expansion），**在脚本里默认关闭**，只在交互式 shell 生效。

</details>

### 21. 忘了命令怎么用，怎么最快查到 ⭐

**场景**：你记得有个命令能「按关键词搜索命令说明」，也知道 `tar` 的参数特别难记。

**要求**：给出「按关键词找命令」和「看某个命令某一段帮助」的具体做法。

<details><summary>参考答案</summary>

```bash
# ① 按关键词搜命令名与一句话描述（等价 man -k）
apropos 'list directory'
man -k copy

# ② 只看一句话说明
whatis ls passwd chmod

# ③ 看完整手册
man ls
man 5 passwd          # 明确指定手册章节：5 = 文件格式
man -a passwd         # 依次看所有章节的同名条目

# ④ 在手册页内部搜索（进入 man 后按 /）
#    /-t   向下搜索 "-t"
#    n / N 下一个 / 上一个
#    g / G 开头 / 结尾
#    q     退出

# ⑤ 只要选项列表，不要读全文
man ls | col -b | sed -n '/^OPTIONS/,/^[A-Z]/p'
ls --help
tar --help

# ⑥ 找"某命令的手册页文件在哪"
man -w ls
whereis ls

# ⑦ 记不住 tar 参数时，用更傻瓜的速查
tldr tar        # 需安装 tldr：npm i -g tldr 或 pacman -S tldr
```

**解析**：

- `apropos` 就是 `man -k`，它搜的是 `whatis` 数据库（`mandb` 生成）。报 `nothing appropriate` 通常是数据库没建：`sudo mandb`（Debian）或 `sudo makewhatis`（RHEL）。
- **man 的章节号必须记住**，否则会看到不想要的那个 `passwd`：

  | 章节 | 内容 | 例子 |
  |------|------|------|
  | 1 | 用户命令 | `man 1 passwd` → 改密码的命令 |
  | 2 | 系统调用 | `man 2 open` |
  | 3 | C 库函数 | `man 3 printf` |
  | 4 | 设备文件 | `man 4 tty` |
  | 5 | **文件格式 / 配置文件** | `man 5 passwd` → `/etc/passwd` 的字段定义 |
  | 7 | 杂项约定 | `man 7 signal`、`man 7 glob` |
  | 8 | 系统管理命令 | `man 8 mount` |

- `man 7 signal` 是查「信号编号与含义」的权威来源，比 `kill -l` 全。
- `--help` vs `man`：`--help` 是程序自己实现的简短提示，`man` 是随包安装的完整文档。GNU 工具两者都全；有些精简发行版（Alpine、容器镜像）**只装了 `--help` 没装 `man`**。
- 💡 把 man 输出存成文本：`man ls | col -b > ls.txt`（`col -b` 去掉退格符等终端控制字符，否则会满是 `^H`）。
- 🔐 排查「命令被人替换过」时，`man -w ls` 与 `command -v ls` 的路径是否属于同一个包，是重要线索。

</details>

### 22. 同一个名字有多个来源，我要知道到底在执行哪个 ⭐⭐

**场景**：你定义了 `ls` 的别名，又装了个同名函数，还不确定 `PATH` 里哪份二进制会被执行。`which` 给出的答案还和实际执行的不一致。

**要求**：列出某个命令名的**所有**来源，并确定实际生效的那一个。

<details><summary>参考答案</summary>

```bash
# 列出所有来源：别名 → 函数 → 内建 → 文件
type -a ls
type -a echo
type -a cd
type -a ll

# 只看最终会执行哪一个
type ls
command -v ls

# 传统工具（只看 PATH 里的可执行文件，看不到别名/函数/内建 ← 这就是它"不准"的原因）
which ls
which -a ls

# 命令相关文件都在哪
whereis ls

# 查手册位置
man -w ls
```

**预期输出示例**：

```text
$ type -a ls
ls is aliased to `ls -alF --color=auto'     ← 别名优先
ls is /usr/bin/ls
$ type -a echo
echo is a shell builtin                     ← 内建优先于外部文件
echo is /usr/bin/echo
$ type -a cd
cd is a shell builtin
$ command -v ll
                                            ← 没定义过 ll，无输出（退出码 1）
```

**解析**：

- **命令查找优先级**：别名 → 函数 → 内建 → `$PATH` 里的可执行文件。`which` 只查最后一步，所以它经常「答非所问」。
- `type` 是 shell 内建（bash/POSIX 都有），能看到全部来源；`type -a` 列出所有匹配；`type -t` 只输出类型单词（`alias`/`function`/`builtin`/`file`/`keyword`），适合脚本判断。
- `command -v` 是 POSIX 标准，脚本里写它比 `which` 可移植（`which` 本身可能没装，是个外部程序）。`command -v x >/dev/null 2>&1 || echo "不存在"` 是判断命令存在性的标准写法。
- `type -p ls` ≈ `type -P` 只查文件，忽略别名/函数/内建。
- 💡 用 `hash -r` 清掉 shell 的命令路径缓存（你刚装了新版本、shell 还在用旧路径时）。

</details>

### 23. 查文件的完整元数据，不只 `ls` 那一行 ⭐⭐

**场景**：你要确认一个文件：确切大小（字节）、inode、占用的磁盘块、三个时间戳（atime/mtime/ctime）、以及它到底是文本还是二进制。

**要求**：给出 `/tmp/linux-practice/data/sales.csv` 与 `/tmp/linux-practice/bin/ls-copy` 的完整元数据，并解释三个时间戳。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

stat data/sales.csv
stat bin/ls-copy

# 只要特定字段（脚本友好）
stat -c '大小=%s  块数=%b  inode=%i  权限=%a(%A)  属主=%U:%G' data/sales.csv
stat -c '%n  mtime=%y' data/*.csv

# 判断真实类型（不看后缀）
file data/sales.csv bin/ls-copy data/broken_link data/softlink.txt

# 只看文件类型名
stat -c '%F' data/sales.csv bin/ls-copy
```

**预期输出（节选）**：

```text
  File: data/sales.csv
  Size: 288           Blocks: 8          IO Block: 4096   regular file
Device: 0,56         Inode: 478930      Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/    rivo)   Gid: ( 1000/    rivo)
Access: 2026-09-15 18:17:41  ← atime
Modify: 2026-09-15 18:16:47  ← mtime
Change: 2026-09-15 18:16:47  ← ctime
 Birth: 2026-09-15 18:16:47  ← 创建时间（仅部分文件系统支持）

$ file bin/ls-copy
bin/ls-copy: ELF 64-bit LSB pie executable, x86-64, ...
$ file data/broken_link
data/broken_link: broken symbolic link to /nonexistent/path
```

**解析**：

| 时间戳 | 含义 | 什么时候变 |
|--------|------|-----------|
| **atime** | 上次**读取**内容 | `cat`/`grep` 等读操作（很多挂载用 `relatime`/`noatime` 抑制它） |
| **mtime** | 上次**修改内容** | `echo >>`、`sed -i`、写文件 |
| **ctime** | 上次**修改 inode 元数据** | `chmod`、`chown`、**以及内容修改**（因为内容变了 inode 里的 mtime/size 也变） |

- **最容易混淆的是 ctime**：改权限会更新 ctime 但**不更新 mtime**，所以 `find -mtime` 抓不到「只被人改了权限」的文件。要抓权限改动得看 ctime（`find -cnewer`、`find -ctime`）。
- `Blocks: 8` × 512 字节 = 4096 字节，即这个 288 字节的文件实占了 1 个 4K 块。**`ls -l` 显示的是逻辑大小（288），`du` 显示的是实占（4K）**，两者不同是正常的。
- `file` 通过**读取文件头部的魔数**判断类型，不依赖后缀名。所以 `mv a.txt a.png` 后 `file` 依然说是文本。🔐 排查上传点后门时必用。
- `stat -c` 的常用格式符：`%n` 名、`%s` 大小、`%i` inode、`%h` 硬链接数、`%a` 权限（八进制）、`%A` 权限（符号）、`%U/%G` 属主/属组名、`%F` 类型、`%y` mtime 人类可读、`%Y` mtime 秒级时间戳。

💡 `stat -f` 看**文件系统**级别信息（不是文件），比如 `stat -f -c '%T' /tmp` 打印文件系统类型名。

</details>

### 24. 用 `find` 造一个目录树概览（系统没装 `tree`）⭐

**场景**：`tree` 很好用但很多最小化安装里没有。你要用 `find` 输出一个可视化的目录树。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 方案一：find + sed 手工缩进（无限层级，替换路径里的 / 为 "  "）
find . -print | sort | sed -e 's;[^/]*/;|__;g;s;__|; |;g'

# 方案二：更清爽的两级概览
find . -maxdepth 2 -printf '%y %p\n' | sort

# 方案三：只要目录，按层级看
find . -type d | sort

# 方案四：用 ls 递归（简单粗暴，但层级不直观）
ls -R .

# 方案五：装了 tree 就用 tree
# tree -L 2 --dirsfirst /tmp/linux-practice
```

**预期输出（方案二）**：

```text
d ./archive
d ./archive/old
d ./backup
d ./bin
...
f ./data/access.log
f ./data/sales.csv
l ./data/broken_link
l ./data/softlink.txt
```

**解析**：

- `find -printf` 的 `%y` 输出类型字符（`d` 目录 / `f` 普通文件 / `l` 软链接 / `p` 管道 / `s` socket / `b`/`c` 块/字符设备），`%p` 是路径。一行一个文件，非常适合再管道给别的工具。
- `sed 's;[^/]*/;|__;g'` 这招的原理：把「非斜杠字符 + 斜杠」重复替换成缩进标记，实现按层级加前缀。
- `find` 默认会**先列目录再列内容**（广度优先的味道），但**不排序**，所以配合 `sort` 结果才稳定。
- 常用「树形统计」组合：

  ```bash
  # 每个目录各有多少个文件
  find . -type f -printf '%h\n' | sort | uniq -c | sort -rn
  # 目录总数 / 文件总数
  echo "目录 $(find . -type d | wc -l) 个，文件 $(find . -type f | wc -l) 个"
  ```

- 💡 装 `tree`：`sudo pacman -S tree` / `sudo apt install tree`。常用参数：`-L 2` 限层级、`-d` 只看目录、`-h` 带人类可读大小、`--du` 显示每目录总大小、`-P '*.log'` 只显示匹配项。

</details>

### 25. 所有 `.txt` 文件里的内容里，哪几个含 "password" ⭐⭐

**场景**：安全自查：你要扫一遍项目目录下所有文本文件，找出提到 `password` 的行。

**要求**：递归搜索，输出带行号、带文件名，并排除二进制文件的干扰。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 基本递归搜索
grep -rn 'password' .

# 只看是否命中（不看内容），列出文件名
grep -rl 'password' .

# 只看 .txt，忽略大小写，带行号
grep -rni --include='*.txt' 'password' .

# 排除某个目录
grep -rn --exclude-dir=backup 'password' .

# 统计每个文件命中多少行
grep -rc 'password' .
```

  ```bash
  rg -t txt 'password'                # 只搜文本类文件
  ```

- 🔐 排查后门/泄密时的常用组合：

  ```bash
  grep -rniE '(password|passwd|secret|token|api[_-]?key)\s*=' /var/www 2>/dev/null | head
  ```

### 26. 找出「最近 1 天内改过的」文件，而不是「最近 1 天前改过的」 ⭐⭐

**场景**：你部署完服务，想确认真实被改动的文件清单。你写了 `find . -mtime 1` 但结果不符合预期。

**要求**：分别找出「24 小时内修改过的」和「修改时间在 1 天以前（严格说是 2 天前）的」文件，并说清 `-mtime` 的语义。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

# 「过去 1 个 24 小时内」修改过 —— 这是你要的
find . -mtime -1 -type f

# 「恰好 1~2 天前之间」修改过
find . -mtime 1 -type f

# 「2 天前或更早」修改过
find . -mtime +1 -type f

# 沙盒里能验证的例子（f1 是 30 天前，f2 是 10 天前，f3 是刚创建）
find archive/old -type f -mtime +7
find archive/old -type f -newermt '2026-09-01'

# 更精确的边界：用 -newermt（按真实时间点，不按整数天）
find . -type f -newermt '2026-09-14 18:00' ! -newermt '2026-09-15 18:00'

# 用参考文件做边界
find . -type f -newer /tmp/linux-practice/data/sales.csv
find . -type f ! -newer /tmp/linux-practice/data/sales.csv
```

**预期输出**：

```text
$ find archive/old -type f -mtime +7
archive/old/f2.txt        ← 10 天前
archive/old/f1.txt        ← 30 天前
```

**解析**：

- **`-mtime n` 的 n 是「天数，向下取整」，比较对象是「24 小时前的整点」**，不是精确时刻。手册原文：`-mtime n` 表示「文件数据最后一次修改发生在 `n*24` 小时之前」。
  - `-mtime -1`：修改时间在**过去 24 小时内**
  - `-mtime 1`：修改时间在 **24~48 小时之间**
  - `-mtime +1`：修改时间**超过 48 小时**（注意不是「超过 24 小时」！）
- **所以「7 天前的文件」≠ `-mtime +7`，「1 天前的文件」≠ `-mtime +1`**。这是最容易记错的点。想要「精确的 N 天前」用 `-newermt`：

  ```bash
  find . -newermt "$(date -d '7 days ago' +%F)"    # 7 天零点之后
  find . ! -newermt "$(date -d '7 days ago' +%F)"  # 7 天零点之前
  ```

- 同类参数：`-atime`（访问）、`-ctime`（inode 变更）、`-mmin`/`-amin`/`-cmin`（按**分钟**，`-mmin -30` = 半小时内）。
- 💡 时间边界用**参考文件**最省事：`touch -d '7 days ago' /tmp/ref && find . -newer /tmp/ref`。这也是 `logrotate`、`find -delete` 清理脚本里的惯用写法。

</details>

### 27. 我的脚本在 `cd` 之后行为不对 ⭐⭐⭐

**场景**：你写了个脚本，运行时中途 `cd` 到了别的目录，之后脚本里所有相对路径都指向了错误的位置。而且脚本执行完，你的终端也被带走了（当前目录变了）。

**要求**：解释原因，并给出两种正确的写法。

<details><summary>参考答案</summary>

```bash
# ❌ 有问题的写法
cd /tmp/linux-practice/data
cp sales.csv /tmp/x.csv          # 相对路径依赖当前目录，脆弱
# 脚本结束后，你的终端也停在了 /tmp/linux-practice/data

# ✅ 写法一：用子 shell 隔离（( ... ) 会在子进程里执行，不影响父 shell）
(
  cd /tmp/linux-practice/data || exit 1
  cp sales.csv /tmp/x.csv
)
pwd                              # 仍然在原地 ← 隔离成功

# ✅ 写法二：在脚本里显式保存/恢复（trap 保证异常退出也恢复）
OLD_PWD="$PWD"
trap 'cd "$OLD_PWD"' EXIT
cd /tmp/linux-practice/data
cp sales.csv /tmp/x.csv

# ✅ 写法三（最推荐）：根本不用 cd，全用绝对路径
cp /tmp/linux-practice/data/sales.csv /tmp/x.csv
```

**解析**：

- 用 `bash script.sh` 或 `sh script.sh` 运行脚本时，脚本在**子进程**里跑，`cd` **不会**影响你的终端。
- 但用 **`source script.sh` / `. script.sh`** 运行时，脚本在**当前 shell**里逐行执行，`cd` 会直接改变你的当前目录——这就是「终端被带走」的原因。
- 排查「为什么我的相对路径失效」的通用手段：

  ```bash
  # 脚本开头把关键路径固定下来
  SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
  cd "$SCRIPT_DIR" || exit 1        # 让脚本"永远从自己所在目录开始"
  ```

  `${BASH_SOURCE[0]}` 是脚本自身的路径（`$0` 在被 `source` 时是 shell 名，不可靠）。
- `trap '...' EXIT` 注册的是「无论正常结束还是被中断都会执行」的清理动作，比在结尾手写 `cd` 更可靠。
- ⚠️ `cd` 失败时如果不处理，后续命令会在**错误的目录**继续执行（比如在 `/` 下 `rm -rf *`）。所以 `cd "$dir" || exit 1` 里的 `|| exit 1` 绝不能省。用了 `set -e` 会自动退出，但 `cd` 在 `if`/`||` 上下文里不触发 `set -e`，所以还是显式写清楚好。
- 相关：`pushd`/`popd` 是「进目录 + 自动记录返回点」的一对命令，`pushd /tmp/x && ... && popd` 也是可读的做法。

</details>

### 28. 复制时权限和属主不对，要「复制并同时设定权限」 ⭐⭐

**场景**：你要把一个脚本部署到 `/tmp/linux-practice/bin/`，要求：内容来自源文件、权限设成 `750`、目录不存在时自动创建。

**要求**：用**一条**命令完成（不要 `cp` 之后再来一条 `chmod`）。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

install -m 750 -D data/sales.csv /tmp/deploy/bin/sales.csv
ls -l /tmp/deploy/bin/sales.csv
```

**预期输出**：

```text
-rwxr-x--- 1 rivo rivo 288 ... /tmp/deploy/bin/sales.csv
```

**解析**：

- `install` 是「复制 + 设置属性」的合体：`-m` 设权限（**不受 umask 影响**）、`-o`/`-g` 设属主属组、`-D` 自动创建所有缺失的父目录、`-d` 变成「只建目录」模式。
- 和 `cp` 的关键差别：`cp` 新建文件的权限是 `源权限 & ~umask`（还会取决于源文件权限），`install -m` 是**精确指定**。这正是 `make install`、部署脚本里都用它的原因。
- 常用参数：

  | 参数 | 作用 |
  |------|------|
  | `-m 755` | 指定权限 |
  | `-o root -g root` | 指定属主属组（需 root） |
  | `-D` | 创建父目录 |
  | `-d dir` | 创建目录（可跟 `-m`） |
  | `-t DIR` | 把多个源文件复制到目录 DIR |
  | `-p` | 保留源文件的 mtime |
  | `-b` / `--backup` | 覆盖前备份 |

- ⚠️ `install -m 4755` 可以造 SUID 程序，这属于**危险操作**：一个配置错误的 SUID 二进制就是一条本地提权路径。除非明确需要（如 `sudo`、`passwd` 这类系统工具），否则不要给自己的程序加 SUID。练习时只在 `/tmp` 下、用沙盒里那个无实际功能的 `bin/suid-demo`。

</details>

### 29. `~`、`$HOME`、`~user` 什么时候会展开，什么时候不会 ⭐⭐

**场景**：你在脚本里写了 `cp ~/config app.conf`，但当 `~` 被放在引号里或赋值给变量后，它就变成了字面量的两个字符。

**要求**：列出所有「波浪号展开」的场景与陷阱。

<details><summary>参考答案</summary>

```bash
echo ~                    # /home/rivo
echo ~/x                 # /home/rivo/x
echo "~/x"                # ~/x            ← 双引号内不展开！
echo '~/x'                # ~/x            ← 单引号内不展开
p=~/x;  echo "$p"         # /home/rivo/x   ← 赋值时已展开，之后引用就没事
p="~/x"; echo "$p"        # ~/x            ← 引号内赋值，没展开
echo ~root                # /root          ← 指定用户的 home
echo ~nosuchuser          # ~nosuchuser    ← 用户不存在则原样保留
echo $(echo ~/x)          # 展开后再做命令替换
```

**解析**：

- **波浪号展开发生在变量展开之前，且只在「词的开头」和「未被引用的 `:` 后」生效**：

  ```bash
  echo a~b                 # a~b            ← ~ 不在词首，不展开
  PATH=~/bin:/sbin         # 展开；冒号后的部分只有紧随 ~ 才展开
  export P=~/a:~/b         # 两个都展开
  ```

- 判定顺序：**波浪号展开 → 参数展开 → 命令替换 → 算术展开 → 分词 → glob**。因为波浪号最先，所以 `echo "$HOME/x"` 和 `echo ~/x` 结果一样，但 `echo '~/x'` 不同（引号先阻止了它）。
- `~` 只在**交互式 shell / 脚本**里由 shell 展开。**配置文件里写的 `~` 不会被展开**——`/etc/fstab`、systemd 的 `ExecStart=`、`.desktop`、`sudoers` 里的 `~` 都是**字面量**，必须写绝对路径。这是极高频的坑。
- 相关变量：`$HOME`（推荐在脚本用）、`$USER`/`$LOGNAME`、`$PWD`/`$OLDPWD`、`$SHELL`。
- 💡 `cd` 不带参数就是用 `$HOME`；`cd ~-` 等价 `cd -`。

</details>

### 30. 一次说清：把散在各个目录的日志汇总到一处 ⭐⭐⭐

**场景**：`/tmp/linux-practice` 下所有 `.log` 文件散落在三层目录里。老板要一个汇总文件 `/tmp/all-logs.txt`，格式是：

```
===== 相对路径 =====
（该文件的完整内容）
```

**要求**：写一条命令生成 `/tmp/all-logs.txt`，并统计汇总文件的总行数。

<details><summary>参考答案</summary>

```bash
cd /tmp/linux-practice

find . -type f -name '*.log' -printf '%P\n' | sort | while IFS= read -r f; do
  printf '===== %s =====\n' "$f"
  cat "./$f"
done > /tmp/all-logs.txt

wc -l /tmp/all-logs.txt
```

**更短的写法（用 `-exec`）**：

```bash
cd /tmp/linux-practice
find . -type f -name '*.log' | sort | xargs -I{} sh -c 'echo "===== {} ====="; cat "{}"' > /tmp/all-logs.txt
wc -l /tmp/all-logs.txt
```

**解析**：

- `-printf '%P\n'` 输出的是「去掉 `find` 起始点前缀」的相对路径（`%p` 会带上 `./`），这样文件里显示的就是干净的相对路径。
- 用 `while IFS= read -r` 而不是 `for f in $(find ...)`：前者不会因为文件名含空格而断裂（见第 16 题）。
- 重定向 `> /tmp/all-logs.txt` 只加在 `done` 后面，作用在**整个 while 循环**上——只打开一次文件，效率高。如果写在循环体里的某条命令后面，每次迭代都会重新打开并覆盖。
- `xargs -I{}` 是每个文件一次进程；文件名含空格时 `{}` 会被 `sh -c` 正确引用（因为 `xargs` 传参时用的就是原始字符串）。
- 💡 汇总时如果想保留「每个文件的修改时间」，用 `stat`：

  ```bash
  find . -type f -name '*.log' -exec stat -c '%y  %n' {} + | sort
  ```

- ⚠️ 汇总到同一个目录时**注意别把输出文件本身也匹配进去**（`find . -name '*.log'` 如果输出文件也叫 `.log` 就会被自己读到）。把输出写到 `/tmp`（不在搜索范围内）或用 `-prune` 排除。

</details>
