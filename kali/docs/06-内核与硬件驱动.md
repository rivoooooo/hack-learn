## 核心知识

### Kali 内核 ≠ 上游内核

Kali Linux 的内核是**打过补丁的 Debian 内核**，差异分两类（官方原话）：一类是编译期**补丁（patch）**，一类是运行期 **sysctl** 默认值。

**编译期补丁**

- **WiFi 注入补丁（kali-wifi-injection.patch）**：这是 Kali 做无线渗透的根基，让支持的网卡在 monitor 模式下能注入数据帧。补丁源码在 Kali 的 GitLab 内核仓库 `debian/patches/features/all/` 下。
- **carl9170 网卡开启 sniffer mode**：为 `carl9170` 系列芯片打开监听/混杂标志。
- **Odroid VU7 触摸屏支持（dwav-usb-mt-driver.patch）**：为 ARM 设备加触摸驱动。

⚠️ 补丁不可撤销——除非你**重新编译内核**（做法见 [12-开发与打包](12-开发与打包.md) 与 <https://www.kali.org/docs/development/recompiling-the-kali-linux-kernel/>）。

**sysctl 默认值（可用 `kali-tweaks` 改回）**

| 项 | Kali 默认 | 上游默认 | 为什么 |
|----|-----------|----------|--------|
| `dmesg` | 任意非特权用户可读 | 仅特权用户 | 方便渗透时看内核环缓冲 |
| 特权端口（<1024） | **关闭**，所有端口非特权 | 仅 root 可绑定 | Kali 2020.1 起默认非 root，减少 `sudo` 频率 |

这两项都可以通过 `kali-tweaks` 交互式恢复成传统行为。

### 与其它发行版的差异

- Debian/Ubuntu **默认带** `nouveau` 开源 NVIDIA 驱动；Kali 官方推荐改装**闭源 NVIDIA 驱动 + CUDA**，因为渗透工具（hashcat、无线破解）依赖 CUDA/OpenCL 算力。
- Ubuntu 有自动的 “Additional Drivers” GUI；Kali 需要你手动确认 `contrib` / `non-free` / `non-free-firmware` 组件已启用。
- Kali 是**滚动发行**（基于 Debian Testing），内核更新频繁，因此**显卡闭源驱动（DKMS）极易在升级后失配**，这是 Kali 相对 Ubuntu LTS 最容易踩的坑。

### 驱动排查的三板斧

```bash
# 1. 这块设备到底在不在总线上？
lspci -nn            # PCI/PCIe 设备（含显卡、有线网卡、部分无线）
lsusb                # USB 设备（USB 无线网卡走这里）
lsusb -t             # USB 树状结构，看驱动绑定

# 2. 内核给它绑了什么驱动？有没有报错？
lspci -nnk           # 加 -k 会显示 "Kernel driver in use" / "Kernel modules"
dmesg -T | tail -50  # -T 把时间戳变成人类可读
journalctl -xe       # systemd 日志的尾部

# 3. 模块层面
lsmod | grep -i nvidia
modprobe -r nouveau  # 卸载模块
```

`dmesg -T`、`lspci -nnk` 是官方 [11-故障排查](11-故障排查.md) 与无线排查文档反复提到的组合。

## 关键文档精读

### Kernel Configuration

- **它解决什么问题**：解释「为什么 Kali 的内核和别人的不一样」，以及怎么改回去。
- **操作步骤**：
  ```bash
  kali-tweaks   # 交互式，可恢复 dmesg 受限 / 特权端口 1024 以下
  ```
  若要看/改补丁，只能重新编译内核，补丁清单在：
  <https://gitlab.com/kalilinux/packages/linux/-/blob/kali/master/debian/patches/series>
- **验证方式**：
  ```bash
  dmesg | head          # 非 root 能读 → 说明 dmesg 未受限
  cat /proc/sys/net/ipv4/ip_unprivileged_port_start   # Kali 默认应为 0
  ```
- **坑**：`kali-tweaks` 只能改 sysctl 类默认值，**改不了补丁**。你以为「关掉某个开关就回到上游行为」是不成立的。

### Install NVIDIA GPU Drivers

- **它解决什么问题**：在物理机或 VM 里装闭源 NVIDIA 驱动，让 hashcat 用上 GPU。
- **操作步骤**（官方原文命令）：
  ```bash
  # 0. 确认 contrib / non-free 已启用
  grep "contrib non-free" /etc/apt/sources.list.d/kali.sources
  # 期望输出：Components: main contrib non-free non-free-firmware

  # 1. 先更新系统并装当前内核头文件
  sudo apt update
  sudo apt -y full-upgrade -y
  sudo apt install linux-headers-$(uname -r) -y
  [ -f /var/run/reboot-required ] && sudo reboot -f

  # 2. 独立显卡：直接确认型号
  lspci | grep -i vga
  lspci -s 07:00.0 -v      # 注意用你自己的 PCI 地址

  # 2'. Optimus 笔记本：装 nvidia-detect 探测
  sudo apt install -y nvidia-detect
  nvidia-detect
  ```
- **验证方式**：
  ```bash
  nvidia-smi                                   # 能看到 GPU 表和驱动版本
  lspci -s 07:00.0 -v | grep -i "kernel driver"  # 应显示 nvidia，不再是 nouveau
  sudo apt install -y hashcat && hashcat -I      # CUDA Info / OpenCL Info 都要出现显卡
  sudo apt install -y mesa-utils
  glxinfo | grep -i "direct rendering"           # 期望：direct rendering: Yes
  ```
- **坑**：
  - **Live 启动不支持**装 NVIDIA 驱动，必须先安装到磁盘。
  - 官方**不推荐在 VM 里折腾**，教程不覆盖。
  - `nvidia-detect` 在 Kali 这种滚动发行上可能报 `Failed to identify your Debian suite.`——这是已知现象，不代表失败。
  - hashcat 仍认不到 GPU 时，官方给了「卸载 apt 装的驱动 → `init 3` 进文本模式 → 跑 NVIDIA 官方 `.run` 安装包」的兜底流程：
    ```bash
    sudo su -
    init 3
    sudo apt remove nvidia*
    sudo ./Nvidia-<your version>.run
    sudo reboot
    ```
  - Optimus 笔记本装完后可能**只有外接屏亮、内置屏黑**，需要在 `/etc/X11/xorg.conf` 里为内置屏指定 `modesetting` + 集显的 `BusID`（用 `lspci | grep -i vga` 查）。

### Kali Branches

- **它解决什么问题**：搞清楚「我到底该用哪个源」，以及各分支的稳定度排序。
- **操作步骤**：切分支要改 APT 源，见 [kali-apt-sources](https://www.kali.org/docs/general-use/kali-apt-sources/)。
- **核心模型**（官方给出的流向图）：
  ```text
  debian-experimental -> debian-unstable -> debian-testing -> kali-dev -> kali-rolling -> kali-last-snapshot
  ```
  - `kali-rolling`：**默认，绝大多数人该用的**。由工具从 `kali-dev` 挑选并验证可安装后并入。
  - `kali-last-snapshot`：对应最后一次版本发布（点发布），最稳。
  - `kali-experimental` / `kali-bleeding-edge`：**部分分支（partial）**，必须叠加在 `kali-rolling` 之上，不能单独用。
  - `kali-dev`：**开发用，会周期性损坏，官方明确警告不要给终端用户用**。
- **验证方式**：
  ```bash
  grep -r "Suites:" /etc/apt/sources.list.d/ 2>/dev/null
  cat /etc/apt/sources.list 2>/dev/null
  ```
  Kali 2026.2 之后新装系统用 `/etc/apt/sources.list.d/kali.sources`（deb822 格式）；更早的系统仍是 `/etc/apt/sources.list`。
- **坑**：`kali-rolling` 和 `kali-last-snapshot` **不要同时启用**——它们各自都是完整发行版，同时开会打架。部分分支才需要叠加。

### Kali Network Repositories（APT 源）

- **它解决什么问题**：源写错了、镜像太慢、或想换分支时的正确写法。
- **操作步骤**：手写源文件时，Kali 官方的标准条目是
  ```text
  # 新版 deb822 格式：/etc/apt/sources.list.d/kali.sources
  Types: deb
  URIs: http://http.kali.org/kali/
  Suites: kali-rolling
  Components: main contrib non-free non-free-firmware
  Signed-By: /usr/share/keyrings/kali-archive-keyring.gpg
  ```
  ```text
  # 旧格式：/etc/apt/sources.list
  deb http://http.kali.org/kali kali-rolling main contrib non-free non-free-firmware
  ```
- **验证方式**：
  ```bash
  sudo apt update           # 无 Err
  apt policy                # 看各源优先级与命中
  ```
  换镜像可用官方镜像列表：<https://http.kali.org/>。
- **坑**：`http.kali.org` 是**镜像重定向器（mirrorlist）**，不是单台服务器，指向它才能真正就近下载。别抄成某个具体镜像域名的 URL。

### Kali Bleeding Edge

- **它解决什么问题**：官方仓库里某个工具版本太旧，但你不想等。
- **操作步骤**（官方给的两种方式）：
  - 交互式：编辑源时用 `kali-tweaks`（选择 “Bleeding Edge” 选项）。
  - 非交互式：手动加源指向 `http://http.kali.org/kali kali-bleeding-edge main contrib non-free non-free-firmware`。
  ```bash
  sudo apt update
  sudo apt install -t kali-bleeding-edge <包名>   # 只从 bleeding-edge 取某个包
  ```
- **验证方式**：
  ```bash
  apt policy <包名>      # 看候选版本是否来自 kali-bleeding-edge
  ```
- **坑**：官方原话标题就是「Caution: watch for the blood」——该分支**可能非常不稳定**。用完记得切回 `kali-rolling` 的稳定版本，不要长期挂着。

### Resolving APT Errors Caused by an Expired Kali Linux Signing Key

- **它解决什么问题**：`apt update` 报 `EXPKEYSIG` 或 `Missing key` —— 本地 `kali-archive-keyring` 太旧。
- **背景**：Kali 仓库签名密钥**每 2–3 年轮换一次**。若你的机器很久没更新 keyring，密钥过期后 apt 就拒绝信任源。
- **操作步骤**：
  ```bash
  sudo apt update                      # 先复现，确认是 EXPKEYSIG / Missing key
  sudo apt install -y kali-archive-keyring   # 预防路径：保持 keyring 最新
  ```
  恢复路径是从 `archive.kali.org` 拉取当前密钥放入 `/etc/apt/trusted.gpg.d/`——**精确命令以官方页面为准**：
  <https://www.kali.org/docs/general-use/gpgkey-expiry/>
- **坑**：密钥轮换期正好叠加「系统长期没开机」，会出现「apt 更新不了 → 也就更新不了 keyring」的死锁，只能手动取密钥。

### Packages That Behave Differently With Non-root

- **它解决什么问题**：Kali 从 2020.1 起默认非 root，很多工具行为变了，here 是官方说明，目前重点讲 **nmap**。
- **要点**：
  - root：默认 **SYN 扫描（`-sS`）**，只发一个 SYN 包，快，但需要原始套接字能力。
  - 非 root：默认降级为 **connect 扫描（`-sT`）**，要走完整三次握手，慢且包更多。
- **验证方式**：
  ```bash
  nmap -v <目标> | grep -i "scan"    # 观察实际使用的扫描类型
  sudo nmap -sS <目标>               # 用 sudo 显式拿 root 能力
  ```
- **坑**：写脚本/写报告时，别默认「nmap 就是 SYN 扫描」——非 root 下它不是。

## 实操清单

- [ ] 确认内核版本与补丁状态：`uname -r`、`dmesg | head`、`cat /proc/sys/net/ipv4/ip_unprivileged_port_start`
- [ ] 用 `kali-tweaks` 浏览一遍可切换的内核默认值（dmesg、特权端口）
- [ ] 列出 PCI/USB 设备并确认驱动绑定：`lspci -nnk`、`lsusb -t`
- [ ] 确认 APT 源组件完整：`grep "contrib non-free" /etc/apt/sources.list.d/kali.sources`（旧系统查 `sources.list`）
- [ ] 确认当前分支：`apt policy`
- [ ] 需要 GPU 破解时：装 `linux-headers-$(uname -r)` → 装 NVIDIA 驱动 → `nvidia-smi` → `hashcat -I`
- [ ] 升级内核后主动检查 DKMS：`ls /lib/modules`、`dkms status`
- [ ] 记录一次 `apt full-upgrade` 前会**被移除**的包清单（避免误删桌面组件）

## 排错

| 现象 | 原因 | 解决 |
|------|------|------|
| `apt update` 报 `EXPKEYSIG ED444FF07D8D0BF6` | 本地 Kali 签名密钥过期 | 升级 `kali-archive-keyring`；必要时手动从 `archive.kali.org` 取新密钥放入 `/etc/apt/trusted.gpg.d/` |
| `apt update` 通过 `sqv` 报 `Missing key 827C8569...` | 新版 apt 用 `sqv` 校验，keyring 缺密钥 | 同上，更新 keyring |
| `apt upgrade` 报 `E: Broken packages` | 滚动发行里 `upgrade` 不肯删包 | 改用 `sudo apt full-upgrade` |
| `The following packages have been kept back` | apt 不敢删依赖者 | 显式 `sudo apt install <包名>` 看它要删什么，确认后再装 |
| 内核升级后黑屏 / 卡在光标 | DKMS 模块（NVIDIA 等）未随新内核重建 | 见 [11-故障排查](11-故障排查.md)：装 `linux-headers-<新内核>` 后 `sudo dkms autoinstall -k <新内核>` |
| `lspci -s XX -v` 显示 `Kernel driver in use: nouveau` | 还在用开源驱动 | 按 NVIDIA 文档装闭源驱动；必要时先 `blacklist nouveau` |
| 非 root 跑 nmap 很慢 | 降级成 connect 扫描 | 用 `sudo nmap -sS`，或理解并接受 `-sT` |
| `nvidia-detect` 报 `Failed to identify your Debian suite` | Kali 是滚动发行，`nvidia-detect` 需要稳定版号 | 已知现象，无视；直接按 GPU 型号装 |
