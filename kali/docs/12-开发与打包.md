## 核心知识

### Kali 与 Debian 的关系（打包必须先搞懂这一层）

Kali 是 **Debian Testing 的派生**（见 [13-政策法规与社区](13-政策法规与社区.md) 的政策原文）：

- **绝大多数包直接从 Debian 原样导入**，Kali 不重新打包。
- 一部分从 Debian Unstable / Experimental 摘取（为了更好的体验或关键 bug 修复）。
- 只有为了实现 Kali 独有特性才 **fork** 包，且一直在努力减少 fork 数量。
- Kali **额外**有大量安全/渗透领域的包（<https://pkg.kali.org/>），其中大部分符合 Debian 自由软件指南，Kali 有意把这些包**回馈给 Debian**。

**包的流向**（来自官方分支说明）：

```text
debian-experimental → debian-unstable → debian-testing → kali-dev → kali-rolling → kali-last-snapshot
```

因此「给 Kali 打包」这件事的本质是：**写一个符合 Debian Policy 的包**，然后走 Kali 的分支流程。

### Debian 包的三层结构

```text
foo_1.2.3.orig.tar.gz      # ① 上游原始 tarball（未改动的源码）
foo_1.2.3-0kali1.debian.tar.xz  # ② Debian 侧的修改（debian/ 目录 + 补丁）
foo_1.2.3-0kali1.dsc       # ③ 描述与控制文件（签名后的「清单」）
        ↓ 构建
foo_1.2.3-0kali1_all.deb   # 二进制包
foo_1.2.3-0kali1_amd64.changes  # 上传用的变更文件
```

**`debian/` 目录的关键文件（官方表格）**：

| 文件 | 作用 |
|------|------|
| `debian/changelog` | 记录何时/为何/由谁更新；**决定包版本号** |
| `debian/control` | 包的元数据（`apt` 里看到的就是它） |
| `debian/copyright` | 哪个部分是什么许可（**包的许可可以与我们做的打包工作不同**） |
| `debian/rules` | 如何安装这个包（一个 Makefile，**必须用 TAB 缩进**） |
| `debian/source/format` | 源码包格式 |
| `debian/watch` | 指向上游，用来探测新版本（可选的，但官方「强烈推荐」） |
| `debian/<包名>.install` | 把哪些文件装到哪（**目标路径不要写前导斜杠**） |
| `debian/<包名>.lintian-overrides` | 二进制包的 lintian 豁免 |
| `debian/source/lintian-overrides` | **源码包**的 lintian 豁免（位置不同！） |

**`debian/control` 的关键字段**：

| 字段 | 含义 |
|------|------|
| `Maintainer` | Kali 里统一写成 `Kali Developers <devel@kali.org>` |
| `Uploaders` | 具体负责打包的个人 |
| `Build-Depends` | **构建**这个包需要什么（缩进 1 个空格、行尾带逗号） |
| `Depends` | **运行**这个包需要什么 |
| `Architecture` | 能装在什么架构上（纯脚本类工具一般是 `all`） |
| `Description` | 短描述（≤60 字符）+ 长描述（缩进 1 个空格，约 70 字符换行） |
| `Homepage` / `Vcs-Browser` / `Vcs-Git` | 上游与源码位置 |

**Python 3 包的四个标配 Build-Depends**：`debhelper-compat`、`dh-python`、`python3-all`、`python3-setuptools`。

**`debhelper-compat` 兼容级别**：**只能升不能降**，级别越高 debhelper 自动做的事越多。

### 打包工具链

| 工具 | 作用 |
|------|------|
| `dh_make` | 生成 `debian/` 骨架 |
| `gbp`（git-buildpackage） | 用 Git 管理上游 tarball、生成变更、构建 |
| `sbuild` | **在隔离 chroot 里构建**（能做到「这里能构建，别处也能构建」） |
| `lintian` | 包质量检查器 |
| `uscan` | 按 `debian/watch` 探测上游新版本 |
| `quilt` | 管理补丁（`debian/patches`） |
| `dput` | 上传 |
| `kaboxer` | 用容器打包「依赖过期库 / 需要隔离」的应用 |

⚠️ **`sbuild` vs 裸 `gbp buildpackage`**：不用 sbuild 就必须自己装齐 `Build-Depends`（例如 `sudo apt install -y dh-python python3-all python3-setuptools python3-requests`）；用 sbuild 则会自动在 chroot 里解决依赖，但**需要网络**，因此**更慢**。

### 版本号约定

Kali 包的版本号形如 `4.4.4-0kali1`：
- `4.4.4` 是上游版本；
- `-0kali1` 是 Debian revision，Kali 用 **`0kaliN`**（数字 `0` 让它在与 Debian 的版本比较中排在前）。

`debian/changelog` 里要改三处：**distribution**（为本地测试是 `UNRELEASED`，正式提交改成 `kali-dev`）、**version**、**log 条目**。

## 关键文档精读

### Setting up a system for packaging

- **它解决什么问题**：从零搭一台干净的打包机（官方推荐用 VM）。
- **磁盘建议（官方原文）**：**80 GB 以上**能同时处理几个包；如果用 `mr` 拉取**所有**打包仓库，建议 **200 GB+**。
- **操作步骤**：

  **① 装工具**
  ```bash
  sudo apt update
  sudo apt install -y sbuild mmdebstrap uidmap apt-file gitk git-lfs myrepos \
                      debhelper devscripts dput lintian quilt
  ```

  **② 用户与密钥**——**必须用普通用户（默认 Kali 用户即可）**，官方强调：**要真正登录切换到该用户，不能 `su`**（某些环境变量相关步骤 `su` 不生效）。
  ```bash
  ssh-keygen -t rsa
  gpg --gen-key
  # 把公钥加到 GitLab：https://gitlab.com/-/profile/keys
  sudo apt install -y xclip
  cat ~/.ssh/id_rsa.pub | xclip
  ```

  **③ 环境变量**
  ```bash
  grep -q DEBFULLNAME ~/.profile \
    || echo "export DEBFULLNAME='First Last'" >> ~/.aliases
  grep -q DEBEMAIL ~/.profile \
    || echo "export DEBEMAIL=email@domain.com" >> ~/.aliases
  ```
  > 官方原文如此（写进 `~/.aliases`），**邮箱必须与 GPG 密钥一致**。

  **④ `~/.gbp.conf`**
  ```ini
  [DEFAULT]
  pristine-tar = True
  cleaner = /bin/true

  [buildpackage]
  export-dir = $HOME/kali/build-area/
  ignore-branch = True
  ignore-new = True
  sign-tags = True

  [dch]
  ignore-branch = True
  multimaint-merge = True

  [import-orig]
  filter-pristine-tar = True
  sign-tags = True

  [pq]
  patch-numbers = False
  ```
  `pristine-tar` 用来**高效地在 Git 里存一份上游 tarball**；`export-dir` 让构建产物落在 git checkout 之外。

  **⑤ `~/.devscripts`**（用 `gpg -k` 查出自己的 key id 填进 `DEBSIGN_KEYID`）
  ```bash
  gpg -k
  cat <<EOF > ~/.devscripts
  DEBRELEASE_DEBS_DIR=$HOME/kali/build-area/
  DEBRELEASE_UPLOADER=dput

  DEBCHANGE_AUTO_NMU=no
  DEBCHANGE_MULTIMAINT_MERGE=yes
  DEBCHANGE_PRESERVE=yes
  DEBCHANGE_RELEASE_HEURISTIC=changelog

  DEBSIGN_KEYID=<你的 GPG key id>

  DEBUILD_LINTIAN_OPTS="--color always -I"

  USCAN_DESTDIR=$HOME/kali/upstream/
  EOF
  mkdir -pv $HOME/kali/{build-area,upstream}
  ```

  **⑥ git 配置**（`user.name` / `user.email` **必须与 GPG 密钥信息一致**，否则后面会报 `Secret Key Not Available`）
  ```bash
  git config --global user.name "First Last"
  git config --global user.email email@domain.com
  git config --global user.signingkey <你的 GPG key id>
  git config --global commit.gpgsign true
  ```

  **⑦ `debian/changelog` 专用合并驱动**
  ```bash
  cat <<EOF >> ~/.gitconfig
  [merge "dpkg-mergechangelogs"]
           name = debian/changelog merge driver
           driver = dpkg-mergechangelogs -m %O %A %B %A
  EOF
  mkdir -pv ~/.config/git/
  grep mergechangelogs ~/.config/git/attributes \
    || echo "debian/changelog merge=dpkg-mergechangelogs" >> ~/.config/git/attributes
  ```

  **⑧ `~/.quiltrc`**
  ```ini
  export QUILT_PATCHES=debian/patches
  QUILT_DIFF_ARGS="--no-timestamps --no-index -p ab --color=auto"
  QUILT_DIFF_OPTS="-p"
  QUILT_PUSH_ARGS="--color=auto"
  QUILT_REFRESH_ARGS="--no-timestamps --no-index -p ab"
  ```

  **⑨ sbuild 配置 `~/.config/sbuild/config.pl`**
  ```perl
  # build 'Architecture: all' packages
  $build_arch_all = 1;
  # build the source package
  $build_source = 1;
  # do not run the clean target on the host
  $clean_source = 0;
  # run lintian, show informational tags
  $run_lintian = 1;
  $lintian_opts = ['-I'];

  # enable network access during builds
  $enable_network = 1;

  # use the unshare backend
  $chroot_mode = "unshare";
  # keep the chroot tarball for a week
  $unshare_mmdebstrap_auto_create = 1;
  $unshare_mmdebstrap_keep_tarball = 1;
  $unshare_mmdebstrap_max_age = 604800;
  # perform the builds in /var/tmp/
  $unshare_tmpdir_template = "/var/tmp/sbuild.XXXXXXXXXX";

  # adjust chroots for Kali
  push @{$unshare_mmdebstrap_extra_args}, "kali-*", [
    '--components=main contrib non-free non-free-firmware',
    '--include=kali-archive-keyring',
    '--setup-hook=sed -i s/https/http/ "$1"/etc/apt/sources.list',
  ];
  ```
  - **加速技巧**：注释掉 `$unshare_tmpdir_template`，构建改在 `/tmp/`（内存+swap）里进行，**不写磁盘**。
    ⚠️ **官方警告**：**大包会吃满 RAM 而失败**——靠加大 swap 缓解。
  - **构建失败时进 shell 调试**：
    ```perl
    $external_commands = {
      "build-failed-commands" => [ [ '%SBUILD_SHELL' ] ],
    };
    ```

  **⑩ 缓存代理 approx**（省带宽）
  ```bash
  sudo apt install -y approx
  ```
  `/etc/approx/approx.conf` 里在 Debian 映射下面加一行：
  ```text
  kali            http://kali.download/kali
  ```
  ⚠️ **官方明确警告**：**不要写 `http://http.kali.org/kali`**——它是重定向器，**不能作为缓存代理的后端，会导致 hash sum mismatch**。用 `kali.download` 或就近镜像。
  最后让 sbuild 用代理：
  ```perl
  push @{$unshare_mmdebstrap_extra_args}, "*", [
    '--aptopt=Acquire::HTTP::Proxy "http://localhost:9999";',
  ];
  ```
  ```bash
  rm ~/.cache/sbuild/*     # 清掉旧构建环境，让新配置立即生效
  ```

- **验证方式**：
  ```bash
  sbuild --version
  gpg -k                     # 确认 key id
  cat ~/.config/sbuild/config.pl
  ls ~/kali/build-area ~/kali/upstream
  ```

### Introduction to packaging step-by-step example

- **它解决什么问题**：完整走一遍给 Python 3 应用（Instaloader）打包的过程。
- **操作步骤（官方原命令，提炼为主线）**：

  **① 建目录**
  ```bash
  mkdir -p ~/kali/packages/instaloader/ ~/kali/upstream/
  ```
  - `~/kali/packages/`：**我们要创建的包**的源码
  - `~/kali/upstream/`：**上游应用源码的压缩包**（尽量用 tag release）

  **② 下载上游 tarball**（按 Debian 命名规范存成 `.orig.tar.gz`）
  ```bash
  wget https://github.com/instaloader/instaloader/archive/refs/tags/v4.4.4.tar.gz \
    -O ~/kali/upstream/instaloader_4.4.4.orig.tar.gz
  ```
  > 没有 tag release 时可以用最新 git commit，但**优先用 tag**。

  **③ 初始化 Git 并导入上游**
  ```bash
  cd ~/kali/packages/instaloader/
  git init
  git status && git log
  gbp import-orig ~/kali/upstream/instaloader_4.4.4.orig.tar.gz
  git log && git branch -v
  ```
  会获得三个分支：`upstream`（上游源码）、`pristine-tar`（导入元数据）、`master`。

  **④ 切到 Kali 约定分支 `kali/master`**
  ```bash
  git checkout -b kali/master
  git branch -D master
  git branch -v
  ```

  **⑤ 用 `dh_make` 生成 `debian/` 骨架**
  ```bash
  dh_make --file ~/kali/upstream/instaloader_4.4.4.orig.tar.gz -p instaloader_4.4.4
  # 类型选 single
  rm debian/*.docs debian/README* debian/*.ex debian/*.EX
  rm -r debian/upstream
  ls -R debian/
  ```
  > `--file` 用来指定 `orig.tar.gz` 位置；如果它就在上一层目录，则可以省略。

  **⑥ 收集信息**（许可证、依赖、维护者、描述）
  ```bash
  cat LICENSE
  ls                              # 找 AUTHORS.md / CREDIT* / docs/
  cat AUTHORS.md
  grep -C 3 -i install README.rst
  cat setup.py
  # 依赖查本仓库里有没有：pkg.kali.org 或 apt-cache
  apt-cache search --names-only python3-requests
  apt-cache show python3-requests
  ```
  官方还给了从 git 记录里挖作者邮箱的技巧：
  ```bash
  git clone https://github.com/instaloader/instaloader/ /tmp/instaloader
  cd /tmp/instaloader/
  git --no-pager log -s --format="%ae" | sort -u | grep -v '@users.noreply.github.com'
  ```

  **⑦ 改 `debian/changelog`**（改 distribution、version、log）
  ```text
  instaloader (4.4.4-0kali1) kali-dev; urgency=medium

    * Initial release

   -- Joseph O'Gorman <gamb1t@kali.org>  Thu, 02 Jul 2020 17:59:47 -0400
  ```

  **⑧ 改 `debian/control`**（完整成品）
  ```text
  Source: instaloader
  Section: misc
  Priority: optional
  Maintainer: Kali Developers <devel@kali.org>
  Uploaders: Joseph O'Gorman <gamb1t@kali.org>
  Rules-Requires-Root: no
  Build-Depends:
   debhelper-compat (= 13),
   dh-python,
   python3-all,
   python3-requests,
   python3-setuptools,
  Standards-Version: 4.6.1
  Homepage: https://instaloader.github.io/
  Vcs-Browser: https://gitlab.com/kalilinux/packages/instaloader
  Vcs-Git: https://gitlab.com/kalilinux/packages/instaloader.git

  Package: instaloader
  Architecture: all
  Depends:
   python3-requests,
   ${misc:Depends},
   ${python3:Depends},
  Description: Download media along with their metadata from Instagram
   Downloads public and private profiles, hashtags, user stories, feeds
     and saved media
   Downloads comments, geotags and captions of each post.
   Automatically detects profile name changes and renames the target
     directory accordingly
   Allows fine-grained customization of filters and where to store
     downloaded media
  ```
  > 注意：`Build-Depends` / `Depends` **缩进 1 个空格并以逗号结尾**；`Description` 也缩进 1 个空格。
  > 有 `setup.py` 时，依赖要**同时**出现在 `Build-Depends` 和 `Depends` 里。
  > `Architecture` 从 `any` 改成 `all`（脚本类工具适用所有架构）。

  **⑨ 改 `debian/copyright`**（上游 + 打包两部分；**打包工作的许可应与应用一致**）
  ```text
  Format: https://www.debian.org/doc/packaging-manuals/copyright-format/1.0/
  Source: https://github.com/instaloader/instaloader
  Upstream-Name: instaloader

  Files: *
  Copyright:
   2016-2020 Alexander Graf <mail@agraf.me>
   2016-2020 André Koch-Kramer <koch-kramer@web.de>
  License: MIT

  Files: debian/*
  Copyright: 2020 Joseph O'Gorman <gamb1t@kali.org>
  License: MIT

  License: MIT
   ...（MIT 全文，缩进 1 空格）...
  ```

  **⑩ 改 `debian/rules`**（**TAB 缩进**）
  ```make
  #!/usr/bin/make -f

  #export DH_VERBOSE = 1
  export PYBUILD_NAME = instaloader

  %:
  	dh $@ --with python3 --buildsystem=pybuild
  ```
  > 有 `setup.py` 才加 `--buildsystem=pybuild`。

  **⑪ 加 `debian/watch`**（探测上游新版本，**两空格缩进**）
  ```text
  version=4
  opts=uversionmangle=s/(\d)[_\.\-\+]?((RC|rc|pre|dev|beta|alpha|a)\d*)$// \
    https://github.com/instaloader/instaloader/tags .*/v?(\d\S+)\.tar\.gz
  ```
  验证：
  ```bash
  uscan -vv --no-download
  ```
  > **常见坑**：不处理 rc/beta/alpha 的版本号会导致 `4.4.4rc3` 排在 `4.4.4` 之前——`uversionmangle` 就是干这个的。

  **⑫ 加 `.install` 与 helper-script**（**目标路径不写前导斜杠**）
  ```bash
  mkdir -p debian/helper-script/
  cat debian/helper-script/instaloader
  #!/bin/sh
  exec python3 /usr/share/instaloader/instaloader.py "$@"

  cat debian/instaloader.install
  instaloader.py usr/share/instaloader/
  instaloader usr/share/instaloader/
  debian/helper-script/instaloader usr/bin/
  ```

  **⑬ 构建**
  ```bash
  git add debian/
  git commit -m "Initial release"
  gbp buildpackage --git-builder=sbuild
  # 想在提交前试跑：gbp buildpackage --git-builder=sbuild --git-export=WC
  ```
  > 官方明确：**不改编译产物、只想试值**时用 `--git-export=WC`，免得把调试 commit 塞进历史。

  **⑭ 手工安装测试**
  ```bash
  sudo apt install ~/kali/build-area/instaloader_4.4.4-0kali1_all.deb
  instaloader
  ```

  **⑮ 上传分享**
  ```bash
  git remote add origin git@gitlab.com:kalilinux/packages/instaloader.git
  git push --all
  git push --tags
  ```
  然后在 <https://bugs.kali.org/> 开票，建议收录这个工具，工具团队会接手。

- **验证方式**：`lintian` 无 error；`ls ~/kali/build-area/` 里出现 `.deb` / `.dsc` / `.changes` / `.buildinfo`。
- **坑（官方明列的）**：
  - **`dpkg` 的「文件覆盖」类错误**：`source-is-missing` 之类属于**源码包**错误，要放 `debian/source/lintian-overrides`；`no-manual-page` 属于**二进制包**错误，放 `debian/<包名>.lintian-overrides`。放错位置会报 `unused-override`。
  - 构建报 `unable to load addon python3 ... dh-python` → `sudo apt install -y dh-python`。
  - `gbp buildpackage` 会因**未提交的改动**报 `can't get HEAD:debian/changelog`。
  - 长描述约 **70 字符换行**（就近取整词）。
  - 官方成品仍有小瑕疵：usage 输出里显示 `instaloader.py`（带扩展名）而命令名是 `instaloader`，需要额外打补丁——留作后续练习。

### Rebuilding a Source Package

- **它解决什么问题**：只想改一个包的源码然后重编（不改打包流程）。
- **三步流程（官方原话）**：用 `apt` 拉源码 → 改 → 用 Debian 工具重建。
- **操作步骤**：
  ```bash
  # 0. 确认 deb-src 已启用
  grep ^Types: /etc/apt/sources.list.d/kali.sources     # 应为 "Types: deb deb-src"

  # 1. 拉源码（以 libfreefare 为例）
  sudo apt update
  apt source libfreefare
  cd libfreefare-0.4.0/

  # 2. 改代码
  vim examples/mifare-classic-format.c

  # 3. 查构建依赖（无输出 = 依赖已满足）
  dpkg-checkbuilddeps
  # 输出示例：dpkg-checkbuilddeps: Unmet build dependencies: dh-autoreconf libnfc-dev libssl-dev

  # 4. 装构建依赖
  sudo apt install -y dh-autoreconf libnfc-dev libssl-dev

  # 5. 构建
  dpkg-buildpackage

  # 6. 安装新包
  sudo dpkg -i ../libfreefare*.deb
  ```
- **验证方式**：`dpkg -l libfreefare` 看版本；`dpkg-checkbuilddeps` 无输出。
- **坑**：`deb-src` 没启用的话 `apt source` 直接失败——这是第一步就卡住的常见原因。

### Recompiling the Kali Linux Kernel

- **它解决什么问题**：给内核加驱动/补丁/特性。
- **⚠️ 官方提示**：**全局的无线注入补丁在 Kali 内核里默认已存在**，不用自己打。
- **操作步骤**：
  ```bash
  # 1. 装构建依赖
  sudo apt install -y build-essential libncurses5-dev fakeroot xz-utils

  # 2. 下载内核源码（装的是"上游源码"的二进制包，不是 kali 的源码包 linux）
  sudo apt install -y linux-source-4.9
  ls /usr/src
  # linux-config-4.9  linux-patch-4.9-rt.patch.xz  linux-source-4.9.tar.xz

  # 3. 解压（不要直接在 /usr/src 下编译，没必要要特殊权限）
  mkdir -p ~/kernel/
  cd ~/kernel/
  tar -xaf /usr/src/linux-source-4.9.tar.xz

  # 4. 复用当前内核配置（比从头配省事得多）
  cp /boot/config-4.9.0-kali1-amd64 ~/kernel/linux-source-4.9/.config
  # 需要改配置时：
  make menuconfig

  # 5. 构建（生成最多 5 个 deb 包）
  make clean
  make deb-pkg LOCALVERSION=-custom KDEB_PKGVERSION=$(make kernelversion)-1
  ls ../*.deb

  # 6. 安装并重启
  sudo dpkg -i ../linux-image-4.9.0-kali1-custom_4.9.2-1_amd64.deb
  reboot
  ```
  `make deb-pkg` 生成的包：`linux-image-<ver>`（内核+模块）、`linux-headers-<ver>`、`linux-firmware-image-<ver>`（Debian/Kali 源码构建时可能没有）、`linux-image-<ver>-dbg`、`linux-libc-dev`。
- **验证方式**：
  ```bash
  uname -r          # 重启后应出现 -custom 后缀
  ls /boot/vmlinuz-*
  ```
- **⚠️ 坑与回滚**：
  - 示例里的 `4.9` 是官方旧文档的版本，**实际要换成你要编的版本**。
  - **内核编译非常耗时**。
  - **回滚方式（官方原话）**：如果新内核起不来，**用 GRUB 菜单启动原来的 Kali 内核**去修问题。
  - 不要在低电量/低磁盘空间下做这件事。

### Creating A Custom Kali ISO

- **它解决什么问题**：构建自己的 Kali ISO（预置工具、换桌面、改壁纸、无人值守安装）。
- **两种镜像、两套脚本（官方明确已拆成两个仓库）**：
  | 镜像 | 工具 | 仓库 | 说明 |
  |------|------|------|------|
  | **Live Image** | live-build | `kalilinux/build-scripts/kali-live` | 不改变系统，适合做 USB |
  | **Installer Image** | simple-cdd（用 debian-cd 生成 Debian-Installer） | `kalilinux/build-scripts/kali-installer` | 安装时可挑桌面与 metapackage |

  > 旧的 `live-build-config` 现在重定向到 `kali-live`；**`kali-live` 里已经不再有 `--installer` 参数**。

- **操作步骤（Kali 环境，官方推荐）**：
  ```bash
  sudo apt update
  # Live 镜像依赖 + 仓库
  sudo apt install -y git live-build cdebootstrap curl
  git clone https://gitlab.com/kalilinux/build-scripts/kali-live.git
  # Installer 镜像依赖 + 仓库
  sudo apt install -y git simple-cdd debian-cd curl
  git clone https://gitlab.com/kalilinux/build-scripts/kali-installer.git

  # 构建默认 Live ISO
  cd kali-live/
  ./build.sh --verbose
  # 输出：GENERATED KALI IMAGE: ./images/kali-linux-rolling-live-amd64.iso

  # 构建 Installer ISO
  cd kali-installer/
  ./build.sh --verbose
  ```
  `--verbose` 把输出打到屏幕（否则只进 `build.log`）；`--debug` 输出更多。

- **重建最新发布版镜像**：
  ```bash
  cd kali-installer/
  time ./build.sh \
    --verbose \
    --distribution kali-last-snapshot \
    --version 2026.2 \
    --subdir kali-2026.2
  # GENERATED KALI IMAGE: ./images/kali-2026.2/kali-linux-2026.2-installer-amd64.iso
  ```
  （同一组参数在 `kali-live/` 里也能用。）

- **换桌面（Live）**：
  ```bash
  ./build.sh --variant gnome --verbose
  ./build.sh --variant kde --verbose
  # 可选：{xfce,gnome,kde,mate,e17,lxde,i3}
  ```

- **控制包含哪些包**：
  - Installer 默认：`kali-config/installer-default/packages`
    → 并改 `simple-cdd/profiles/kali.postinst` 底部的安装命令（如 `apt install -y 你的包`）
  - Live 默认：`kali-config/variant-default/package-lists/kali.list.chroot`
  - Live 非默认桌面：`kali-config/variant-<桌面>/package-lists/kali.list.chroot`
  - 这些清单默认包含 `kali-linux-default` metapackage，**注释掉它就能换成手工清单**。

- **叠加文件**：把文件放进 `kali-config/common/includes.chroot/`（chroot 阶段）等 `includes.{chroot,binary,installer}` 目录。

- **Hooks**：参考 `kali-config/common/hooks/`。

- **换架构**：
  ```bash
  ./build.sh --verbose --arch amd64
  ./build.sh --verbose --arch arm64
  ```

- **完整参数**：
  ```text
  ./build.sh --help
  Usage: ./build.sh [<option>...]

    --distribution <arg>
    --proposed-updates
    --arch <arg>
    --verbose
    --debug
    --variant <arg>
    --version <arg>
    --subdir <arg>
    --get-image-path
    --no-clean
    --clean
    --help
  ```
  （`kali-installer/build.sh` 参数相同，仅去掉 Live 专属的 `--proposed-updates`。）

- **在非 Kali 的 Debian 系系统上构建**：
  ```bash
  sudo apt update
  sudo apt full-upgrade -y
  wget https://http.kali.org/pool/main/k/kali-archive-keyring/kali-archive-keyring_2022.1_all.deb
  wget https://http.kali.org/pool/main/l/live-build/live-build_20230502+kali3_all.deb
  sudo apt install -y git live-build simple-cdd cdebootstrap curl
  sudo dpkg -i kali-archive-keyring_2022.1_all.deb
  sudo dpkg -i live-build_20230502+kali3_all.deb

  cd /usr/share/debootstrap/scripts/
  (echo "default_mirror http://http.kali.org/kali"; sed -e "s/debian-archive-keyring.gpg/kali-archive-keyring.gpg/g" sid) > /tmp/kali
  sudo mv /tmp/kali .
  sudo ln -s kali kali-rolling

  cd ~/
  git clone https://gitlab.com/kalilinux/build-scripts/kali-live.git
  cd kali-live/
  ./build.sh --verbose
  ```
  ⚠️ 官方提示：**必须确认 `kali-archive-keyring_20YY.X` 与 `live-build_20YYMMDD+kaliX` 是最新版**。
  视宿主版本，可能需要在 `build.sh` 里**注释掉 debootstrap 版本检查的 `exit 1`**。
- **坑**：构建**很慢**（要下载全部所需包），官方调侃「正好去喝一杯」。

### Packaging Applications with Kaboxer

- **它解决什么问题**：有些应用**没法正常打包**（依赖已从 Kali 移除的过时库，或行为会破坏系统上其它应用）。Kaboxer 把这类应用**装进容器**，同时**像普通应用一样 `apt install` 并从菜单启动**。
- **原理**：预先构建好**应用镜像**推到 Docker registry → 用户安装包时**透明地拉取镜像** → 用 `kaboxer` 命令启停容器。通过 `dh_kaboxer` 与专用 buildsystem 集成到 debhelper。
- **前置**：
  ```bash
  sudo apt install -y kaboxer
  git clone https://gitlab.com/kalilinux/tools/kaboxer.git
  cd kaboxer/hello-kbx
  groups                # 需要属于 docker 或 kaboxer 组
  sudo adduser $USER kaboxer   # 不属于则加（需重开会话）
  # Kali 2020.4+ 的初始用户应已在 kaboxer 组
  ```
- **操作步骤**：
  **① 写 Dockerfile**（关键：把版本写进 `/kaboxer/version`）
  ```dockerfile
  FROM debian:stable-slim
  RUN apt update && apt install -y \
      python3 \
      python3-prompt-toolkit
  COPY ./hello /usr/bin/hello
  RUN mkdir /kaboxer \
   && hello version > /kaboxer/version
  ```

  **② 写 `hello-cli.kaboxer.yaml`**
  ```yaml
  application:
    id: hello-cli
    name: Hello World for Kaboxer (CLI)
    description: >
      hello-kbx is the hello-world application demonstrator for Kaboxer
  packaging:
    revision: 1
  components:
    default:
      run_mode: cli
      executable: /usr/bin/hello cli
  ```
  关键字段：`executable`（容器里怎么启动）、`run_mode`（应用形态，如 `cli`）。

  **③ 构建并运行**
  ```bash
  kaboxer build hello-cli
  # 构建失败信息很少，改用 docker build 看具体错误：
  docker build -f hello-cli.Dockerfile -t kaboxer/hello-cli .
  kaboxer run hello-cli
  ```
  官方示例里第一次运行报 `PermissionError: [Errno 13] Permission denied: '/var/lib/hello-kbx'`，因为该目录（会被挂到容器 `/data`）需要 root 创建，**正式安装时由包管理器创建**。示例里改用 `/tmp/hello-kbx` 绕过：
  ```bash
  sed -i 's;/var/lib/hello-kbx;/tmp/hello-kbx;' *.kaboxer.yaml
  ```

  **④ 加 Debian 打包文件**（三处改动）
  - `debian/control` 的 `Build-Depends` 加 `kaboxer`；
  - `debian/control` 的 `Depends` 里保留 `${misc:Depends}`（`dh_kaboxer` 会注入对 Docker/Kaboxer 的依赖）；
  - `debian/rules` 改成：
    ```make
    #!/usr/bin/make -f

    %:
    	dh $@ --with=kaboxer --buildsystem=kaboxer
    ```

  **⑤ 镜像来源，二选一**
  - 推到 registry 并在 yaml 里指向它：
    ```yaml
    container:
      type: docker
      origin:
        registry:
          url: https://registry.gitlab.com
          image: kalilinux/packages/hello-kbx/hello
    ```
  - 或把镜像打**进包里**（⚠️ **包会非常大**）：
    ```make
    export DH_KABOXER_BUILD_STRATEGY=tarball
    ```

- **更多特性**：
  - **多组件共享容器**：组件里声明 `reuse_container: true`；
  - **组件间私有网络**：组件里声明
    ```yaml
    networks:
      - hello-kbx
    ```
    这样 server 组件**不对宿主暴露端口**，但 cli 组件可通过 `hello-server-kbx` 主机名访问它（自动路由）。
  - **菜单集成 / 命令行助手**、**GitLab CI 自动化构建**（远程 include 官方通用 CI 文件，构建镜像并推到项目的 Docker registry）。
- **验证方式**：
  ```bash
  kaboxer run hello-cli
  man kaboxer        # kaboxer(1)
  man kaboxer.yaml   # kaboxer.yaml(5)
  ls /usr/share/doc/kaboxer/examples/hello-kbx
  ```
- **坑**：`kaboxer build` 的**报错信息很少**，调试一律用 `docker build`。

### ARM Build Scripts / ARM Cross-Compilation / Preparing a Kali Linux ARM chroot

- **它们解决什么问题**：
  - **ARM Build Scripts**：官方生成预构建 ARM 镜像用的**同一套脚本**（仓库里还有更多设备的脚本，不止官网列出的那批）。
  - **ARM Cross-Compilation**：在 x86 Kali 上搭 **ARM 交叉编译环境**（装依赖、下载 Linaro 工具链、设环境变量）——**这是很多「自定义 ARM 镜像」教程的起点**，需要 root 权限。
  - **Preparing a Kali Linux ARM chroot**：手工 bootstrap 出 ARM rootfs（装工具、开交叉编译、指定架构与包、构建 rootfs、chroot 内手工配置、清理）。
- **要点**：自定义 ARM 镜像的通用五步（官方多篇「Custom * Image」都是这个骨架）：
  1. 创建 Kali rootfs
  2. 创建镜像文件
  3. 分区并挂载镜像
  4. 复制并修改 Kali rootfs
  5. 编译该设备的内核与模块
- **⚠️ 坑**：ARM 镜像 / 内核构建是**开发者级任务**，官方把这些文档归在 development 下就是这个意思；操作错误会把设备刷成砖。

### Contributing run-time tests with autopkgtest

- **它解决什么问题**：Kali 是滚动发行，**偶尔会因为依赖变化导致包坏掉**。官方为此搭了自动化运行时测试，希望你贡献测试。
- **要点**：
  - 需要了解 `autopkgtest` 的背景；
  - 学会组织测试文件结构；
  - 通过示例学习；
  - **本地可以跑测试**验证。
- **验证方式**：本地运行 `autopkgtest`（具体命令以官方页面为准）：
  <https://www.kali.org/docs/development/contributing-runtime-tests/>

### Building Custom Kali ISOs / Generate an Updated Kali ISO

- **Building Custom Kali ISOs**：live-build 动手工作坊，讲「Live Build 的强大之处」——你可以做出**带自定义工具、桌面、服务**的分支。
- **Generate an Updated Kali ISO**：用 Debian 的 live-build 脚本**当场生成更新版 ISO**；官方建议**在已装好的 Kali 环境里**做；第一步是装上 live-build 相关包，然后运行构建脚本。

## 实操清单

- [ ] 打包用**独立 VM**，磁盘 80 GB+（用 `mr` 拉全部仓库则 200 GB+）
- [ ] 按官方步骤装齐 sbuild / devscripts / lintian / quilt 等工具
- [ ] 生成 SSH 与 GPG 密钥，SSH 公钥加到 GitLab
- [ ] `DEBFULLNAME` / `DEBEMAIL` / `DEBFULLNAME` 与 GPG 密钥**保持一致**
- [ ] `git config user.email` 与 GPG **必须一致**（否则报 Secret Key Not Available）
- [ ] 配好 `~/.gbp.conf`、`~/.devscripts`、`~/.quiltrc`、`~/.config/sbuild/config.pl`
- [ ] approx 配置里用 `kali.download`，**绝不用 `http.kali.org`**
- [ ] 改一个包的流程：`grep ^Types: kali.sources` → `apt source` → 改 → `dpkg-checkbuilddeps` → `dpkg-buildpackage` → `dpkg -i`
- [ ] 新包流程：建目录 → `wget` 存 `.orig.tar.gz` → `git init` → `gbp import-orig` → 切 `kali/master` → `dh_make` → 改 6 个文件 → `gbp buildpackage --git-builder=sbuild`
- [ ] 提交前用 `--git-export=WC` 试跑，别污染 git 历史
- [ ] lintian 报错分清是**源码包**还是**二进制包**，放对 override 目录
- [ ] 编内核前备份当前可用内核（GRUB 里留着能回滚）
- [ ] 自定义 ISO 先确认要 Live 还是 Installer，克隆对应仓库
- [ ] Kaboxer 应用调试一律用 `docker build` 看真实错误

## 排错

| 现象 | 原因 | 解决 |
|------|------|------|
| `apt source` 报找不到源码 | 未启用 `deb-src` | 在 `kali.sources` 里 `Types: deb deb-src` |
| `dpkg-checkbuilddeps` 报 unmet | 缺构建依赖 | 按输出 `sudo apt install -y <列出的包>` |
| `gbp buildpackage` 报 `can't get HEAD:debian/changelog` | 改动未提交 | `git add debian/ && git commit`，或加 `--git-export=WC` |
| `dh: error: unable to load addon python3` | 缺 `dh-python` | `sudo apt install -y dh-python` |
| lintian `unused-override` | override 放错包类型 | 源码包错放 `debian/source/lintian-overrides`，二进制包错放 `debian/<包名>.lintian-overrides` |
| 提交后报 `Secret Key Not Available` | git user.email 与 GPG 不一致 | 按官方提示统一为 `gpg -k` 里的身份 |
| approx 报 hash sum mismatch | 用了 `http.kali.org` 作后端 | 改成 `kali.download` 或就近镜像 |
| sbuild 构建把内存吃爆 | 用了 `/tmp`（内存+swap）作构建目录 | 恢复 `$unshare_tmpdir_template`，或加大 swap |
| sbuild 构建失败想看现场 | 需要进构建环境 | 加 `$external_commands = { "build-failed-commands" => [ [ '%SBUILD_SHELL' ] ] };` |
| 新内核起不来 | 内核配置或补丁有问题 | **用 GRUB 菜单启动原 Kali 内核**再修 |
| `make deb-pkg` 报缺依赖 | 未装 build-essential 等 | `sudo apt install -y build-essential libncurses5-dev fakeroot xz-utils` |
| 非 Kali 宿主上 build.sh 报 debootstrap 版本不够 | 版本检查过严 | 按官方说明注释掉 `exit 1` |
| `kaboxer build` 失败但没信息 | 工具本身报错少 | 用 `docker build -f <file>.Dockerfile -t kaboxer/<app> .` |
| `kaboxer run` 报 `Permission denied: /var/lib/...` | 挂载目录未创建（正式安装由包管理器创建） | 示例中用 `/tmp/...`；正式包交给 `dh_kaboxer` |
| `kaboxer` 权限不足 | 用户不在 `docker`/`kaboxer` 组 | `sudo adduser $USER kaboxer` 后**重开会话** |
