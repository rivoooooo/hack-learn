## 1. APT 源配置

来源：[Kali Network Repositories](https://www.kali.org/docs/general-use/kali-apt-sources/)

官方开篇就警告：

> 仓库这个话题总是很长，而且经常出现。**人们经常搞错并混淆。**
> 请在动手前花时间读完下面的信息和相关引用。

### 1.1 当前正确配置（Kali 2026.2 起）

```bash
grep -v '^#' /etc/apt/sources.list.d/kali.sources
```

期望输出（官方给出的标准内容）：

```text
Types: deb
URIs: http://http.kali.org/kali/
Suites: kali-rolling
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/kali-archive-keyring.gpg
```

### 1.2 旧格式（Kali 2026.2 之前）

```bash
grep -v '^#' /etc/apt/sources.list | sort -u
```

```text
deb http://http.kali.org/kali kali-rolling main contrib non-free non-free-firmware
```

### 1.3 从旧格式迁移到新格式

```bash
sudo apt update
sudo apt modernize-sources
```

官方说明：如果你的系统只有旧的 `/etc/apt/sources.list` 而没有 `kali.sources`，
用 `apt modernize-sources` 可以自动完成转换。

### 1.4 关键历史变更

| 时间 | 变更 |
|------|------|
| Kali 2020.3 起 | 安装完成后**默认启用**网络仓库，即使安装时没有网络 |
| Kali 2026.2 起 | 网络仓库配置迁移到 `/etc/apt/sources.list.d/kali.sources` |

### 1.5 官方列出的"为什么我的源不对"

- 你切换过分支
- 你用了硬编码的其它镜像

⚠️ **对照不上就别再装包**。源错了会出现装不上包、收不到更新、甚至装到不兼容版本。

### 1.6 镜像选择

```bash
# 官方镜像池（会自动就近跳转）
http://http.kali.org/kali/

# 换成 HTTPS 的更安全写法（把 URIs 改成）
https://http.kali.org/kali/
```

💡 国内网络慢时可以换国内镜像站（清华 TUNA、中科大 USTC 等），
但**只换 URI，不要换 Components 和 Signed-By**。
换完必须 `sudo apt update` 验证签名通过。

## 2. 分支怎么选

来源：[Kali Branches](https://www.kali.org/docs/general-use/kali-branches/)

官方分类：

### 2.1 主分支（完整发行版，二选一）

| 分支 | 官方定义 | 建议 |
|------|----------|------|
| `kali-rolling` | **默认主分支，大多数人都该用它**。持续更新，从 `kali-dev` 拉取（确认有问题的包稳定后）再合并 `kali-rolling-only` 的包。偶尔会有包 bug 溜进来（源自 debian-testing 的 bug） | ✅ 日常使用 |
| `kali-last-snapshot` | 每个新版本发布时冻结代码，把 `kali-rolling` 合并进来；用户拿到的是版本之间的全部更新。因为包不再更新（直到下个点版本），且经过发布测试，**更稳定，是"最安全"的选项** | ✅ 需要稳定可复现的环境 |

> 这两个分支各自都提供完整的 Kali 发行版。**你应该用其中之一，但同时启用两个没有意义。**

### 2.2 部分分支（必须配合 `kali-rolling` 使用）

> 它们不能单独使用，因为**不包含完整的 Kali 发行版**。
> 普通用户通常不需要，只有在非常特殊的情况下才用。

| 分支 | 定位 |
|------|------|
| `kali-experimental` | 进行中的包的暂存区 |
| `kali-bleeding-edge` | 从上游 git 仓库**自动更新**的包，**可能非常不稳定** |

⚠️ `kali-bleeding-edge` 是"我想要最新代码"的陷阱：它可能在任何时候坏掉。
🔗 见 [Kali Bleeding Edge](https://www.kali.org/docs/general-use/kali-bleeding-edge/)（官方用 NVIDIA 驱动举例说明如何配合多用分支）。

### 2.3 开发分支（**不是给终端用户用的**）

| 分支 | 说明 |
|------|------|
| `kali-dev` | Kali 的开发版本，由 `kali-dev-only` + `kali-debian-picks` + `debian-testing` 三者合成。主要用于把 Debian 的更新与 Kali 的改动合并 |
| `kali-dev-only` | 含 Kali 专有包的开发发行版，自动合并进 `kali-dev` |
| `kali-rolling-only` | 需要快速进入 `kali-rolling` 的包所在的仓库 |

### 2.4 切换分支

官方指向 apt sources 页面。做法就是改 `Suites:` 字段：

```bash
# 示例：切到 last-snapshot（先备份原配置！）
sudo cp /etc/apt/sources.list.d/kali.sources /etc/apt/sources.list.d/kali.sources.bak
sudo sed -i 's|Suites: kali-rolling|Suites: kali-last-snapshot|' /etc/apt/sources.list.d/kali.sources
sudo apt update
sudo apt full-upgrade -y
```

⚠️ 切分支会有降级/升级大量包，**务必先打快照**。

## 3. 什么时候该更新

来源：[Updating Kali](https://www.kali.org/docs/general-use/updating-kali/)（更新于 2026-05-14）

官方建议（这段建议比命令本身重要）：

> - 默认安装的 Kali，应该**每隔几天到几周**检查一次更新。
> - 如果需要某个工具的新版本，或听说有安全更新，可以缩短周期。
> - **但一个好习惯是：在正式测试（engagement）之前确认所有工具可用，而在测试期间不要更新。**
> - 因为 Kali 是滚动发行版，**偶尔会有问题溜进 rolling，可能弄坏你正需要用的工具。**
>
> 如果你用的是 `last-snapshot`，在下个版本发布前你不会收到更新。
> Kali **一年发布四次**，遵循宽松的季度节奏。

💡 **这条建议值得背下来**：打比赛/做项目前更新，做的时候别动。
滚动发行版的最大风险不是"不安全"，而是"计划外的变更把你正在用的工具弄坏了"。

### 标准更新流程

```bash
# 1. 先确认源配置正确（见第 1 节）
cat /etc/apt/sources.list.d/kali.sources

# 2. 更新索引
sudo apt update

# 3. 完整升级（注意是 full-upgrade 而不是 upgrade）
sudo apt full-upgrade -y
```

🔬 `upgrade` vs `full-upgrade` 的区别：
`upgrade` 遇到需要**移除或安装新包**才能满足依赖的情况会跳过该包；
`full-upgrade`（旧名 `dist-upgrade`）会**主动增删包**来满足依赖。
滚动发行版必须用 `full-upgrade`，否则你会长期卡在一堆"被保留"的包上。

```bash
# 看看有哪些包被"保留"了（说明用 upgrade 升不上去）
apt list --upgradable 2>/dev/null | wc -l
```

⚠️ `full-upgrade` 可能移除你依赖的包。升级前看一眼它会做什么：

```bash
sudo apt full-upgrade --dry-run
```

## 4. 常见 APT 错误与修复

### 4.1 签名密钥过期（最常见）

**现象**（来自 [gpgkey-expiry](https://www.kali.org/docs/general-use/gpgkey-expiry/) 的官方输出）：

```text
Err:1 https://http.kali.org/kali kali-rolling InRelease
  Sub-process /usr/bin/sqv returned an error code (1), error message is:
  Missing key 827C8569F2518CC677FECA1AED65462EC8D5E4C5, which is needed to verify signature.
Warning: An error occurred during the signature verification.
```

**原因**：Kali 团队每 **2–3 年**会延长或更换 APT 仓库签名密钥。
很久没更新过 `kali-archive-keyring` 包的用户就会遇到。

**修复**：

```bash
sudo wget https://archive.kali.org/archive-keyring.gpg -O /usr/share/keyrings/kali-archive-keyring.gpg
sudo apt update
```

**预防**（官方建议）：

- 定期保持系统更新，尤其是 `kali-archive-keyring` 包
- **如果你的 Kali 安装超过 2 年，它可能已不再受支持**，考虑升级到最新版本

### 4.2 其它常见错误速查

| 错误信息 / 现象 | 原因 | 处理 |
|-----------------|------|------|
| `Could not get lock /var/lib/dpkg/lock-frontend` | 另一个 apt/dpkg 进程在跑 | 等它结束；`ps aux \| grep -E 'apt\|dpkg'` 确认后再说，⚠️ 不要直接删锁文件 |
| `E: Unable to locate package xxx` | 源里没有 / 源配置错 / 索引没更新 | `sudo apt update`；`apt-cache search xxx`；查 [Removed Tools](https://www.kali.org/docs/tools/removed-tools/) |
| `E: Unmet dependencies` / `--fix-broken` | 依赖被破坏（升级中断最常见） | `sudo apt --fix-broken install` |
| `Hash Sum mismatch` | 镜像不同步 / 代理缓存 | 换镜像；清缓存 `sudo apt clean`；`sudo rm -rf /var/lib/apt/lists/*` 后重新 update |
| `The following packages have been kept back` | 需要增删包才能升级 | 用 `sudo apt full-upgrade` |
| 装完某个 DE 后桌面崩了 | `kali-desktop-*` 冲突（如 KDE + Xfce） | 见 [03 篇第 5 节](03-系统配置与优化.md#5-切换桌面环境) |

🔗 官方专页：[Handling common APT problems](https://www.kali.org/docs/troubleshooting/handling-common-apt-errors/)

### 4.3 dpkg 被中断后的恢复

```bash
sudo dpkg --configure -a        # 继续配置未完成的包
sudo apt --fix-broken install   # 修复依赖
sudo apt full-upgrade -y
```

## 5. Python 生态：不要再用 `pip install`

来源：[Installing Python Applications via pipx](https://www.kali.org/docs/general-use/python3-external-packages/)

**自 Kali 2024.4 起，官方强烈不建议用 pip 安装外部 Python 包**，改用 **pipx**。
官方原话：

> 表面上它提供了相似的用户体验，但在底层它克服了 pip 唯一突出的问题：**缺乏环境隔离**。

尝试 `sudo pip install` 或 `pip install --user` 会直接报错：

```text
error: externally-managed-environment

× This environment is externally managed
╰─> To install Python packages system-wide, try apt install
    python3-xyz, where xyz is the package you are trying to install.
    ...
    If you wish to install a non-Kali-packaged Python application,
    it may be easiest to use pipx install xyz, which will manage a
    virtual environment for you.
```

### 三种正确做法

| 需求 | 做法 |
|------|------|
| 装 Kali 打包过的 Python 库 | `sudo apt install python3-xyz` |
| 装**命令行工具**类 Python 应用 | `pipx install xyz` |
| 给自己的项目装依赖 | `python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt` |

```bash
# pipx 基本用法
sudo apt install -y pipx
pipx ensurepath          # 把 ~/.local/bin 加进 PATH（重开终端生效）
pipx install 工具名
pipx list                # 看装了哪些
pipx upgrade-all         # 批量升级
pipx uninstall 工具名
```

🔬 **为什么这个变化很重要**：Kali 里几乎所有安全工具都是 Python 写的。
如果你用 `sudo pip install` 往系统 Python 里塞包（尤其是 `requests`、`pycryptodome`、
`impacket` 这类），**很可能把系统自带的工具搞坏**——这类"跑着跑着某个工具突然 ImportError"
的问题，绝大多数源于此。

⚠️ 与安全工具的关联：
- `impacket`、`pwntools` 等工具应通过 `apt` 或 `pipx` 安装，不要 `sudo pip install`
- 需要特定版本的库时，用 venv，不要污染系统环境

🔗 另见：[Using EoL Python Versions](https://www.kali.org/docs/general-use/using-eol-python-versions/)
（工具依赖老 Python 时的处理方式）。

## 6. Flatpak 与 Snap

当某个 GUI 应用（浏览器、编辑器等）不在 Kali 仓库里时，**不要**去加 Ubuntu 的 PPA，
用沙箱化的包管理器隔离安装。

### 6.1 Flatpak

来源：[Installing Flatpak](https://www.kali.org/docs/tools/flatpak/)

```bash
sudo apt update
sudo apt install -y flatpak
sudo flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
```

可选（让 GNOME 软件中心支持 Flatpak）：

```bash
sudo apt install gnome-software-plugin-flatpak
```

让 Flatpak 应用用系统主题：

```bash
mkdir -p ~/.themes
cp -a /usr/share/themes/* ~/.themes/
sudo flatpak override --filesystem=~/.themes/
```

```bash
# 常用命令
flatpak search 关键词
flatpak install flathub 应用ID
flatpak run 应用ID
flatpak list
flatpak update
```

### 6.2 Snap

来源：[Installing snapd](https://www.kali.org/docs/tools/snap/)

```bash
sudo apt update
sudo apt install -y snapd
sudo systemctl enable --now snapd apparmor
```

官方提醒：**注销后重新登录或重启系统**，以确保 snap 的路径被正确更新。

⚠️ 与安全测试的关联：Snap 与 AppArmor 绑定较深，在某些 Kali 场景下可能出现
权限冲突。做内核/容器相关实验时留意。

## 7. Tor 与被移除的工具

### 7.1 Tor Browser

🔗 [Installing Tor Browser on Kali Linux](https://www.kali.org/docs/tools/tor/)

```bash
sudo apt update
sudo apt install -y torbrowser-launcher
torbrowser-launcher
```

⚠️ 使用 Tor 的注意事项：
- 只对**授权目标**使用匿名网络
- 不要在 Tor 里登录你的个人账号（会直接暴露身份）
- 浏览器指纹与 Java/JavaScript 是常见去匿名化路径

### 7.2 找不到某个工具？

先查官方移除清单：[Removed Tools From Kali](https://www.kali.org/docs/tools/removed-tools/)

常见原因：上游废弃、许可证问题、功能被合并、安全考量。

```bash
# 三步排查法
apt-cache search 关键词          # 1. 换关键词搜
apt-cache search 关键词 | grep -i kali
dpkg -S $(command -v 命令名)     # 2. 已知命令反查属于哪个包
apt-file search /path/to/file    # 3. 按文件路径搜（需先 apt install apt-file）
```

## 🧪 练习

1. **读懂你的源配置**
   ```bash
   grep -v '^#' /etc/apt/sources.list.d/kali.sources 2>/dev/null \
     || grep -v '^#' /etc/apt/sources.list | sort -u
   ```
   逐行解释 `Types` / `URIs` / `Suites` / `Components` / `Signed-By` 的含义。

2. **观察依赖爆炸**：`apt-cache depends kali-linux-default | wc -l`，
   再对比 `apt-cache depends kali-linux-core | wc -l`，解释差异。

3. **模拟一次"装不上"**（在快照里）：
   ```bash
   sudo mv /usr/share/keyrings/kali-archive-keyring.gpg /tmp/
   sudo apt update          # 观察报错
   sudo mv /tmp/kali-archive-keyring.gpg /usr/share/keyrings/
   sudo apt update          # 观察恢复
   ```

4. **对比 `upgrade` 与 `full-upgrade`**：
   ```bash
   sudo apt upgrade --dry-run | tail -20
   sudo apt full-upgrade --dry-run | tail -20
   ```

5. **pipx 实战**：用 `pipx install` 装一个 Python 命令行工具，
   然后用 `pipx list` 查看它被隔离在哪个虚拟环境里；
   再尝试 `pip3 install` 同一个包，观察 `externally-managed-environment` 报错。
