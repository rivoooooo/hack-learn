## 核心知识

### 排错的通用方法论（官方 Basics 页）

官方给的顺序是：**先看日志 → 再看命令输出 → 最后 Google**。官方甚至把 Google 称为「最重要的工具」。

**日志文件地图（官方原表）**：

| 路径 | 内容 |
|------|------|
| `/var/log/` | 绝大多数日志的总目录 |
| `/var/log/syslog` | 内核与其他程序/服务消息 |
| `/var/log/apt/history.log`、`/var/log/apt/term.log`、`/var/log/dpkg.log` | **软件包更新出错必看这三处** |
| `/var/log/auth.log` | 系统授权事件（登录、sudo、SSH） |
| `/var/log/dmesg` | 内核环缓冲 |
| `/var/log/message` | 系统消息 |
| `/var/log/Xorg.0.log` | X 服务器日志 |
| `/var/log/lightdm/lightdm.log` | LightDM 事件（Kali 默认登录管理器） |
| `/var/log/kern.log` | 仅内核消息 |
| `~/.xsession-errors` | X 图形会话内的错误 |

**诊断命令清单（官方列举）**：`journalctl`、`dmesg`、`ip`、`service`、`systemctl`、`df`、`top`、`dpkg`、`apt`、`ps` / `kill`、`tail -f`。

> **官方建议**：图形工具不报错时，**改用命令行跑一遍**，通常就能看到真正的错误。

### APT 的六类问题（官方 Handling common APT problems）

**第 0 条（最重要）**：**先跑 `apt update`**。官方原话：「这是 APT 的工作方式，绕不过去，能解决你遇到的最诡异的问题」。

```bash
sudo apt update
```

**① `E: Broken packages`（用 `apt upgrade` 时）**
- 原因：这不是真错误。`apt upgrade` 是**保守**升级——**绝不删包**；而 Kali 是滚动发行，经常需要删掉旧包才能升级。
- 解决：改用 `apt full-upgrade`。
  ```bash
  sudo apt full-upgrade
  ```
- ⚠️ `full-upgrade` 会删包，**可能（罕见地）删掉重要包导致系统不可用**。官方建议：**留意「将被移除」的清单，如果这个清单很大就停下来**，过几天再试，APT 可能会给出更好的方案；或者去 <https://bugs.kali.org> 报 bug。

**② `The following packages have been kept back`**
- 原因：APT 不敢动某个包（通常因为它会连带删掉别的包）。
- 解决：**显式安装它**（对已安装包执行 `apt install` 其实就是升级）：
  ```bash
  sudo apt install kali-desktop-xfce
  # 输出会告诉你它会 REMOVE 什么，例如 pipewire-media-session
  # 确认可以接受后再回车
  ```

**③ 「需要更新版本，但没有新版本可用」**
- 原因：多见于用 `kali-dev` / `kali-experimental` 时。要么包还在测试中（几周内会进仓库），要么有依赖冲突待解决。
- 解决：查 Debian 的包页面或 <https://bugs.kali.org/> 确认状态，**通常几周内自愈**。

**④ 包试图覆盖文件导致报错**
- 原因：文件在包之间搬家，但缺了 `Replaces` 之类的字段。
- 解决：**先重试安装/升级**；仍不行则忽略覆盖错误：
  ```bash
  sudo apt -o dpkg::options::="--force-overwrite" install <包名>
  ```
  ⚠️ `--force-overwrite` 是绕过校验，属于**最后手段**。

**⑤ `EXPKEYSIG` / 签名错误**
```text
The following signatures were invalid: EXPKEYSIG ED444FF07D8D0BF6 Kali Linux Repository <devel@kali.org>
```
- 原因：本地 `kali-archive-keyring` 里的密钥过期（密钥每 2–3 年轮换）。
- 解决：见 [06-内核与硬件驱动](06-内核与硬件驱动.md) 的签名密钥一节，或官方专页 <https://www.kali.org/docs/general-use/gpgkey-expiry/>。

**⑥ 新版 apt 用 `sqv` 报 `Missing key 827C8569F2518CC677FECA1AED65462EC8D5E4C5`**
- 原因：同 ⑤，只是校验后端换成了 `sqv`，报错形态不同。

### 图形问题的两类根因

**根因 A：内核更新后 DKMS 模块没重建**

Kali 是滚动发行，内核更新频繁。宿主的 **DKMS 模块（NVIDIA、VirtualBox、部分 WiFi 驱动）** 如果没拿到新内核的 headers，就不会为新内核重建，**重启后图形会话起不来，只剩光标闪烁**。

**根因 B：GNOME 49 起废弃 X11 会话**

GNOME 49 开始**内置 X11 会话支持被弃用并默认关闭**。老系统升级后可能出现黑屏或没有登录界面，日志里能看到：
```text
Unit gnome-session-x11@gnome-login.target not found.
```
解决方向是**确保 Wayland 被正确启用**。

## 关键文档精读

### The Basics of Troubleshooting

- **它解决什么问题**：给你一套「去哪看、用什么命令」的索引。
- **操作步骤**：
  ```bash
  journalctl -xe              # systemd 日志尾部 + 解释
  dmesg -T | tail -50         # 内核消息，时间戳可读
  sudo tail -f /var/log/syslog
  sudo tail -f /var/log/apt/term.log   # 看升级过程到底哪一步炸了
  df -h                       # 是不是没空间了
  top                         # 是不是有进程吃满 CPU/内存
  ```
- **坑**：官方明确说，**图形工具不弹错误时，用命令行跑它**——绝大多数错误只在 stderr 里。

### Handling common APT problems

- **它解决什么问题**：APT 报错六类的标准答案。
- **操作步骤与验证**：见上文「核心知识」的 ①–⑥。
- **验证方式**：
  ```bash
  sudo apt update && sudo apt full-upgrade
  sudo apt --fix-broken install     # 依赖破损的兜底修复
  sudo dpkg --configure -a          # 有包卡在 half-configured 时
  ```
  > 上面两条是本篇基于「Debian 包管理常识」补充的通用兜底手段，**不在官方该页正文中**，使用前请确认系统状态。
- **坑**：
  - `apt upgrade` 在 Kali 上**近乎无用甚至有害**（官方原话），**始终用 `apt full-upgrade`**。
  - 别用网上抄的「卸载某包」偏方，例如音频问题里 **千万不要卸载 `pipewire-pulse`**（见下）。

### Graphics issues on bare-metal installation

- **它解决什么问题**：物理机上装完/升级完内核后黑屏、只有光标，或 GNOME 登录不上。
- **操作步骤**：

  **① 加 APT 钩子，自动装 headers 并重建 DKMS**（官方推荐，长期有效）：
  ```bash
  sudo tee /etc/apt/apt.conf.d/99-kernel-headers-dkms >/dev/null <<'EOF'
  DPkg::Post-Invoke {"bash -c 'set -e; newk=$(ls -1 /lib/modules 2>/dev/null | sort -V | tail -1); if [ -n $newk ] && [ ! -d /usr/src/linux-headers-$newk ]; then echo [apt] Installing headers for $newk >&2; apt-get -y install linux-headers-$newk || true; fi; if command -v dkms >/dev/null; then dkms autoinstall -k $newk || true; fi'";};
  EOF
  ```
  这个钩子是**保守的**：装 headers 或编译模块失败都会被忽略，**不会阻塞系统升级**。

  **② 手动一次性修复（刚装了新内核）**：
  ```bash
  newk=$(ls -1 /lib/modules | sort -V | tail -1)   # 取最高的内核版本，不是 uname -r
  sudo apt-get update
  sudo apt-get install -y "linux-headers-$newk" || echo "linux-headers-$newk not available"
  if command -v dkms >/dev/null; then sudo dkms autoinstall -k "$newk"; fi
  ```

  **③ 调整 GRUB 内核命令行（可选）**：
  ```bash
  sudo sed -i 's/^GRUB_CMDLINE_LINUX_DEFAULT=.*/GRUB_CMDLINE_LINUX_DEFAULT="quiet splash acpi=strict loglevel=3"/' /etc/default/grub
  sudo update-grub
  ```
  ⚠️ **不要在不懂硬件的情况下去禁用 ACPI**——会让内核无法与平台固件交互，**包括 GPU 在内的设备可能失效**。降低启动详细度也会让排错更难。

  **④ 装 NVIDIA 驱动前先禁用 `nouveau`**：
  ```bash
  sudo modprobe -r nouveau || true
  echo "blacklist nouveau" | sudo tee /etc/modprobe.d/blacklist-nouveau.conf
  sudo update-initramfs -u
  sudo reboot
  ```
  ⚠️ **回滚方式**（如果黑到进不了图形界面）：`Ctrl+Alt+F3` 进 TTY 或用 Live USB：
  ```bash
  sudo rm /etc/modprobe.d/blacklist-nouveau.conf
  sudo update-initramfs -u
  sudo reboot
  ```

  **⑤ 已经升级完、只剩光标闪**（从 TTY `Ctrl+Alt+F3..F6` 登录后）：
  ```bash
  sudo apt update && sudo apt upgrade -y
  sudo apt install -y "linux-headers-$(uname -r)" || echo "headers not available for $(uname -r)"
  sudo dkms autoinstall -k "$(uname -r)" || true
  sudo reboot
  ```

  **⑥ GNOME on Wayland**：先确认 Wayland 没被 GDM 关掉：
  ```bash
  sudo grep -r "Wayland" /etc/gdm3/
  # /etc/gdm3/daemon.conf:#WaylandEnable=true   ← 被注释=默认，正常
  ```
  然后在 `/etc/default/grub` 的 `GRUB_CMDLINE_LINUX_DEFAULT` 里加（**按需选，不是全加**）：
  ```text
  nvidia_drm.modeset=1                              # 让驱动早启动阶段/唤醒后能管显示
  nvidia_drm.fbdev=1                                # 强制驱动管帧缓冲（<540.x 驱动有用）
  nvidia.NVreg_PreserveVideoMemoryAllocations=1      # 挂起时保留显存，修唤醒后花屏
  ```
  ```bash
  sudo update-grub && sudo reboot
  ```
  官方明确：**低于 550.163.01 的 NVIDIA 驱动在 GNOME + Wayland 上有多种问题**，且**没有「一招通杀」的修复**——上面的参数是用户反馈有效的选项，效果取决于显卡/驱动/内核组合。
- **验证方式**：
  ```bash
  cat /proc/cmdline              # 确认 GRUB 参数已生效
  dkms status                    # 模块是否已为当前内核构建
  lsmod | grep -E 'nvidia|nouveau'
  echo $XDG_SESSION_TYPE         # 当前是 wayland 还是 x11
  ```
- **坑**：`/lib/modules` 排序用 `ls | sort -V | tail -1` 取**最新**内核，而 `uname -r` 是**当前运行**的内核——两者不同，别混用。

### Troubleshooting Wireless Drivers

- **它解决什么问题**：网卡不工作/不能监听/不能注入的四级排查。
- **官方最重要的两句话**：
  > **90% 报给我们的无线问题，都是因为没读 aircrack-ng 文档。进 monitor 模式前必须先跑 `airmon-ng check kill`。**
  > **仔细读任何错误信息——它们绝大多数会直接告诉你哪里错了。**

- **操作步骤（官方四步）**：

  **1. 完全没有接口**
  - 这真是无线网卡吗？（官方：「我们见过好几次」）
  - 设备插好了吗？
  - `lsusb` / `lspci` 里能看到吗（手机除外）？可以更新 pci.ids / usb.ids。
  - `dmesg` 里有没有驱动加载/失败的信息？
  - **是 VM 吗？** 除 USB 网卡外，VM 里的卡**不可用**（VMware/VirtualBox/QEMU 会虚拟化所有 PCI 设备）。USB 卡有没有**挂载到 VM**？
  - `dmesg` 什么都没有又不是 VM → 试最新的 `compat-wireless`（有时还需要固件）。

  **2. 有接口但什么都做不了**
  - 读错误信息。
  - 没有错误信息就 `dmesg | tail`——它基本会告诉你原因。
  - 可能缺固件。
  - 检查 `rfkill`、硬件开关、BIOS 选项。

  **3. 没有 monitor 模式**
  - **厂商提供的 STA 驱动（Ralink、Broadcom 等）一律不支持 monitor 模式。**
  - **`ndiswrapper` 不支持且永远不会支持 monitor 模式。**
  - airodump-ng/Wireshark 抓不到包 → 查 `rfkill`、硬件开关、BIOS 选项。

  **4. 注入（injection）**
  - 用 `aireplay-ng -9` 测试（先确保卡已用 `airmon-ng` 进了 monitor 模式）。
  - `airmon-ng` 不显示芯片组信息：**不是大问题**，只是没从卡里读到，不影响卡的能力。
  - 有 monitor 没注入 → 查 `rfkill`、硬件开关、BIOS 选项。
  - **网络管理器会干扰 aircrack 工具**：跑 `airmon-ng check kill` 杀掉这些进程。

- **验证方式**：
  ```bash
  iw dev
  airmon-ng
  airmon-ng check kill
  airmon-ng start wlan0
  aireplay-ng -9 wlan0mon
  rfkill list
  dmesg -T | grep -i -E 'firmware|wlan|80211'
  ```
- **坑**：VM 里用内置无线网卡**永远不行**；必须是 USB 网卡并**在虚拟化软件里显式挂载到 VM**。

### Fixing Dual Boot

- **它解决什么问题**：GRUB 菜单里只剩 Kali，另一个系统（例如 Debian/Windows）不见了。
- **前提（官方列举）**：
  1. Kali 是与其他系统并存的双系统；
  2. **GRUB 是 Kali 装的**（表现是 GRUB 菜单用了 Kali 的主题）。如果 GRUB 是**另一个 Linux 发行版**装的，这篇文档帮不了你。
- **操作步骤**：
  ```bash
  cat /etc/default/grub | grep GRUB_DISABLE_OS_PROBER
  # 期望看到未注释的：GRUB_DISABLE_OS_PROBER=false
  # 若看到 #GRUB_DISABLE_OS_PROBER=false，先取消注释：
  sudo sed -i 's/#GRUB_DISABLE_OS_PROBER=false/GRUB_DISABLE_OS_PROBER=false/' /etc/default/grub
  cat /etc/default/grub | grep GRUB_DISABLE_OS_PROBER
  # 重建引导菜单
  sudo update-grub
  ```
- **验证方式**：看 `update-grub` 输出里必须出现这两类行：
  ```text
  Warning: os-prober will be executed to detect other bootable partitions.
  Found Debian GNU/Linux 12 (bookworm) on /dev/sda2
  ```
  第一行说明在探测其他系统，第二行说明**找到了**。有了就重启，GRUB 菜单应该两个系统都在。
- **坑**：如果压根没有 `GRUB_DISABLE_OS_PROBER` 这一行，或 GRUB 属于别的发行版，请改用对应发行版的方式修 GRUB。

### Troubleshooting Installations Failures

- **它解决什么问题**：安装到一半出现「红屏」，怎么把日志取出来定位原因。
- **操作步骤**：
  1. 在红屏界面点 **Continue**，进入 **Debian installer main menu**。
  2. 选 **save debug logs**。
  3. 选 **在安装机上起一个 web 服务器**（官方说这是最方便的方式）。
  4. 用另一台机器访问该 web 服务器，**下载/查看安装日志**。
  5. 重点看有没有异常或明显的错误信息。
- **官方给的典型例子（磁盘空间不足）**，日志长这样：
  ```text
  Aug 19 23:45:05 base-installer: error: The tar process copying the live system failed (only 152937 out of 286496 files have been copied, last file was ).
  Aug 19 23:45:05 main-menu[927]: (process:7553): tar: write error: No space left on device
  Aug 19 23:45:05 main-menu[927]: WARNING **: Configuring 'live-installer' failed with error code 1
  ```
  看到 `No space left on device` 就知道是空间不够。
- **常见原因（官方开头列举）**：ISO 下载损坏或不完整、目标机磁盘空间不足等。
- **验证方式**：安装前先校验镜像：
  ```bash
  sha256sum kali-linux-*.iso
  # 与官网 SHA256SUMS 对照；并使用 SHA256SUMS.gpg 验证
  ```
  详见 <https://www.kali.org/docs/introduction/download-images-securely/>。
- **坑**：红屏本身**不告诉你原因**，必须抓日志。

### No sound on Kali 2023.2

- **它解决什么问题**：升级到 Kali 2023.2 后没声音。
- **背景**：Kali 2023.2 起用 **PipeWire** 处理音频（XFCE 与 GNOME）。此前是 PulseAudio。**KDE 桌面仍用 PulseAudio**。PipeWire 提供兼容层 `pipewire-pulse`，老应用无感迁移。
- **⚠️ 官方强烈警告**：**千万不要卸载 `pipewire-pulse`**！网上到处流传的「卸载它」是**旧版 Kali 的过时偏方**，现在卸载会**让系统坏得更彻底**。
- **操作步骤**：
  ```bash
  # 1. 正常升级即可自动装上 PipeWire
  sudo apt update
  sudo apt full-upgrade -y
  # 升级完立刻重启，确认 PipeWire 起来且音频正常

  # 2. 仍无声 → 装 pipewire-audio metapackage
  sudo apt install --mark-auto -y pipewire-audio
  # 再次重启

  # 3. 仅物理机：部分较新 Intel 声卡需要固件
  sudo apt update
  sudo apt install -y firmware-sof-signed
  # 再次重启
  ```
- **VMware Workstation 音爆/断续**：官方指向 PipeWire 官方 wiki 的虚拟机音频卡顿条目：
  <https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Troubleshooting#stuttering-audio-in-virtual-machine>
- **验证方式**：
  ```bash
  systemctl --user status pipewire pipewire-pulse wireplumber
  pactl info
  wpctl status
  dmesg -T | grep -i -E 'sof|snd'
  ```
- **坑**：`firmware-sof-signed` 只对**物理机**有意义（VM 里不适用）。

### Fixing PostgreSQL 'collation version mismatch'

- **它解决什么问题**：系统升级后，Metasploit / GVM / BloodHound 等工具报 PostgreSQL 排序规则版本不匹配。
- **报错形态（官方原文）**：
  ```text
  WARNING:  database "postgres" has a collation version mismatch
  DETAIL:  The database was created using collation version 2.40, but the operating system provides version 2.41.
  HINT:  Rebuild all objects in this database that use the default collation and run ALTER DATABASE postgres REFRESH COLLATION VERSION, or build PostgreSQL with the right library version.
  ```
- **原因**：系统 glibc 升级后排序规则版本变了（`2.40` → `2.41`），而数据库还是按旧版本建的。
- **操作步骤（官方原命令）**：
  ```bash
  sudo runuser -u postgres -- psql -c 'ALTER DATABASE postgres REFRESH COLLATION VERSION; ALTER DATABASE template1 REFRESH COLLATION VERSION;'
  ```
  注意**两个库都要刷**：`postgres` 和 `template1`（模板库不刷，以后新建的库还会带同样的毛病）。
- **验证方式**：
  ```bash
  sudo runuser -u postgres -- psql -c '\l'      # 看各库的 collation 信息
  # 或重启工具看告警是否消失
  sudo systemctl restart postgresql
  ```
- **坑**：如果库已损坏（数据层面），官方 HINT 里提到的「rebuild all objects」才需要真正执行——**先做备份**。

### Discovering Problems With Download Speed

- **它解决什么问题**：下载镜像很慢，怎么定位是哪个镜像的问题并向官方报告。
- **原理（官方解释）**：
  ```text
  你点下载 → 请求打到 cdimage.kali.org（重定向器）
           → 它判断你的来源地，把你导向最合适的镜像
           → 下载在该镜像上真正开始
  ```
- **操作步骤：找出你被导到哪个镜像**
  ```bash
  curl -i https://cdimage.kali.org/kali-2026.2/kali-linux-2026.2-installer-amd64.iso
  # 看输出：
  # Location: https://mirror.vinehost.net/kali-images/... ← 你被导到的镜像
  # Link: <...>; rel=duplicate; pri=1; geo=ae             ← 备选镜像（带地理与优先级）
  ```
  （也可以直接在浏览器下载页右键复制下载链接。）
- **测速取证**：
  ```bash
  wget https://kali.download/base-images/kali-2026.2/kali-linux-2026.2-installer-amd64.iso
  # 看输出里的 "31.6MB/s" 这类速度值
  ```
- **报告**：把**镜像 URL + 实测速度**带上，提交 bug：
  <https://www.kali.org/docs/community/submitting-issues-kali-bug-tracker/>
- **换镜像**：从 [社区镜像列表](https://www.kali.org/docs/community/kali-linux-mirrors/) 里挑一个，把链接里的 `README` 替换成具体的 `kali-2026.2/kali-linux-2026.2-installer-amd64.iso`（即 `kali-images/` 后面的部分）。
- **坑**：`cdimage.kali.org` 与 `http.kali.org` 都是**重定向器**，本身不存文件；直接把它们当作下载源是常见误解。

### Minimum Install Setup Information

- **它解决什么问题**：最小安装（没有 `kali-linux-headless`、没有任何 `kali-tools-*`）之后想补齐工具。
- **操作步骤**：
  ```bash
  # 快速补齐一整套工具
  sudo apt update && sudo apt install -y kali-linux-headless
  # 或按需安装 metapackage，见：
  # https://www.kali.org/docs/general-use/metapackages/
  ```
- **相关主题**：APT 源与分支（[06-内核与硬件驱动](06-内核与硬件驱动.md)）、Python 2 已 EOL 的处理（<https://www.kali.org/docs/general-use/using-eol-python-versions/>）。
- **WSL 场景**：最小安装的 Kali WSL 想上 GUI → 装 Win-KeX，见 [09-WSL与云环境](09-WSL与云环境.md)。
- **Docker 场景**：最小安装的容器想加工具 → 见 [08-容器与虚拟化](08-容器与虚拟化.md) 的 Kali Docker 镜像用法与 systemd 相关说明。

### Common Cloud Based Setup Information

- **它解决什么问题**：**云镜像是刻意做轻量的**，只带核心工具。缺什么就补什么。
- **官方思路**：用 **metapackage** 一次性补齐；或按需装单个工具。
- **操作步骤**：
  ```bash
  sudo apt update && sudo apt install -y kali-linux-headless
  ```
  想上 GUI：参考 AWS 文档的 `ssh -X` 或 RDP 隧道方案（见 [09-WSL与云环境](09-WSL与云环境.md)）。

### Windows Anti-virus Warning

- **它解决什么问题**：从官网下 Kali 镜像时 Windows 杀软报毒。
- **原因（官方说明）**：**Kali 里包含大量被 Windows 标记为恶意的渗透测试工具**，杀软对镜像/ISO 里这些文件报警是**预期行为**，不是镜像被污染。
- **操作步骤**：
  - 先**校验 SHA256**（<https://www.kali.org/docs/introduction/download-images-securely/>）确认文件完整；
  - 在校验通过的前提下，**在杀软里为下载目录/VM 目录加排除**。
- **⚠️ 风险提示**：加排除会**降低宿主机的检测能力**，只在**明确授权的测试环境**这样做（参见 [08-容器与虚拟化](08-容器与虚拟化.md) 的同类提示）。**先校验、后排除**，顺序不能反——否则可能真的放过了被篡改的镜像。

## 实操清单

- [ ] 遇到任何问题，先跑 `sudo apt update`（APT 类问题九成靠它）
- [ ] 建一个排错信息包：`journalctl -xe`、`dmesg -T | tail -50`、`df -h`、`free -h` 各留一份
- [ ] 硬件/驱动问题：`lspci -nnk`、`lsusb -t`、`dmesg -T`
- [ ] 内核升级后主动检查：`dkms status`、`ls /lib/modules`
- [ ] APT 报错先分清是哪一类（broken packages / kept back / overwrite / 签名）
- [ ] 装 NVIDIA 前先 `blacklist nouveau`，并**记下回滚命令**
- [ ] 无线问题严格按四步走，**注入前先 `airmon-ng check kill`**
- [ ] GRUB 丢系统：`GRUB_DISABLE_OS_PROBER=false` + `sudo update-grub`
- [ ] 安装红屏：从 installer main menu 抓 debug logs，**不要瞎重装**
- [ ] 音频问题：升级 + 重启 + `pipewire-audio` +（物理机）`firmware-sof-signed`
- [ ] PostgreSQL 报排序规则：刷新 `postgres` 与 `template1` 两个库
- [ ] 下载慢：`curl -i` 找出镜像 → `wget` 测速 → 报 bug

## 排错

| 现象 | 原因 | 解决 |
|------|------|------|
| `apt upgrade` 报 `E: Broken packages` | `upgrade` 不删包，滚动发行需要删包 | `sudo apt full-upgrade` |
| 包被 `kept back` | APT 不敢连带删包 | 显式 `sudo apt install <包名>`，看它要删什么再决定 |
| `apt update` 报 `EXPKEYSIG` / `Missing key` | 本地密钥过期 | 升级 `kali-archive-keyring`；必要时手动取新密钥 |
| 装包报文件覆盖错误 | 包之间文件搬家缺 `Replaces` | 先重试；必要时 `-o dpkg::options::="--force-overwrite"` |
| 包卡在 half-configured | 安装被中断 | `sudo dpkg --configure -a`，再 `sudo apt --fix-broken install` |
| 内核升级后黑屏只剩光标 | DKMS 模块未为新内核重建 | 从 TTY 装 `linux-headers-$(uname -r)` + `dkms autoinstall`；长期用 APT 钩子 |
| GNOME 登录黑屏，日志 `gnome-session-x11@gnome-login.target not found` | GNOME 49 起默认禁 X11 会话 | 启用/检查 Wayland；按需加 `nvidia_drm.modeset=1` 等参数 |
| 禁用 nouveau 后进不了图形界面 | nouveau 是当前唯一可用的显示驱动 | `Ctrl+Alt+F3` 进 TTY，删除 `/etc/modprobe.d/blacklist-nouveau.conf` 后 `update-initramfs -u` |
| `lsusb` 看不到 USB 无线网卡 | 未挂载到 VM / 供电不足 | 在虚拟化软件里挂载 USB 设备；用带外接供电的 OTG/转接线 |
| 有 wlan 接口但抓不到包 | 缺固件 / 被 rfkill 或硬件开关挡住 | `dmesg \| tail` 看原因；`rfkill list`；查硬件开关与 BIOS |
| 无法进入 monitor 模式 | 用了厂商 STA 驱动或 ndiswrapper | 换用受支持芯片组与驱动；`ndiswrapper` 永远不行 |
| 有 monitor 无注入 | 网络管理器占用网卡 | `airmon-ng check kill` 后重试 `aireplay-ng -9` |
| GRUB 里只剩 Kali | `os-prober` 被禁用 | `/etc/default/grub` 里取消注释 `GRUB_DISABLE_OS_PROBER=false`，`sudo update-grub` |
| 安装红屏 | ISO 损坏 / 磁盘空间不足等 | installer main menu → save debug logs → 看日志 |
| 升级 2023.2 后无声 | PipeWire 迁移未完成 | 升级后重启；仍无声装 `pipewire-audio`；物理机装 `firmware-sof-signed`；**别卸 `pipewire-pulse`** |
| Metasploit/GVM 报 collation mismatch | glibc 升级导致排序规则版本变化 | `sudo runuser -u postgres -- psql -c 'ALTER DATABASE postgres REFRESH COLLATION VERSION; ALTER DATABASE template1 REFRESH COLLATION VERSION;'` |
| 下载镜像极慢 | 被重定向到慢镜像 | `curl -i` 找出镜像 → `wget` 测速 → 报 bug 或手动换镜像 |
| 云主机里工具很少 | 云镜像是刻意轻量的 | `sudo apt install -y kali-linux-headless` |
| Windows 杀软报毒 | Kali 自带大量被标记的工具 | 先校验 SHA256，确认完整后再加杀软排除（仅授权环境） |
