## 1. 先看清当前网络状态

排查任何网络问题，都从这四条命令开始：

```bash
# 1. 网卡与地址
ip -br addr                    # 简洁视图
ip addr show                   # 详细（含 MAC、状态）

# 2. 路由表
ip route

# 3. DNS 配置
resolvectl status 2>/dev/null || cat /etc/resolv.conf

# 4. 连通性
ping -c 3 1.1.1.1              # 通 = 链路 OK
ping -c 3 www.kali.org         # 通 = DNS OK
```

### 分层定位法

| 现象 | 问题层 | 下一步 |
|------|--------|--------|
| `ip link` 显示接口 `DOWN` | 链路层 | 检查网线/虚拟网卡/`ip link set eth0 up` |
| 接口 UP 但无 IP | 网络层 | DHCP 没拿到地址，检查虚拟机网络模式 |
| `ping 1.1.1.1` 通但 `ping 域名` 不通 | DNS | 查 `/etc/resolv.conf`、`resolvectl` |
| 能 ping 通 IP 但连不上端口 | 传输层/防火墙 | `ss -tulnp \| grep 端口`、检查防火墙与安全组 |
| 只有某些域名不通 | 代理 / DNS 污染 | 见第 3 节 |

### 桌面环境下的网络管理

Kali 桌面版默认使用 **NetworkManager**：

```bash
nmcli device status            # 设备状态
nmcli connection show          # 连接配置
nmcli device wifi list         # 扫描 Wi-Fi
nmcli device wifi connect "SSID" password "密码"

# 图形界面
nm-connection-editor
```

💡 **虚拟机网络模式选择**（VirtualBox/VMware）：

| 模式 | 能否访问外网 | 能否被局域网其他机器访问 | 用途 |
|------|--------------|--------------------------|------|
| NAT | ✅ | ❌ | 默认，最省事 |
| 桥接（Bridged） | ✅ | ✅ | **渗透测试常用**：靶机能扫到你的 Kali |
| 仅主机（Host-only） | ❌ | 仅宿主机 | 隔离的实验网络 |
| 内部网络（Internal） | ❌ | 仅同网络内的虚拟机 | 搭建纯隔离靶场 |

⚠️ **常见错误**：Kali 用 NAT、靶机用桥接 → 两边互相扫不到。
搭靶场时把 Kali 和靶机放在**同一个**网络里。

## 2. Kali 的网络相关定制

Kali 为了**能连上老旧的、有漏洞的系统**，在某些客户端上默认放宽了安全策略。
这是 Kali 很独特、也很容易被忽略的设计。

### 2.1 SSH 客户端：Strong Security vs Wide Compatibility

来源：[SSH Configuration](https://www.kali.org/docs/general-use/ssh-configuration/)（自 Kali 2022.1 起）

| 模式 | 行为 | 默认 |
|------|------|------|
| **Strong Security** | 强制使用更安全的算法，拒绝老旧协议 | ✅ **默认** |
| **Wide Compatibility** | 启用旧密钥交换算法（如 `diffie-hellman-*-sha1`）与旧密码套件（如 CBC） | 需手动开 |

切换方式（官方步骤）：

```bash
kali-tweaks
# 进入 Hardening 菜单 → 在 Strong Security 与 Wide Compatibility 之间选择
```

🔬 官方说明这个切换的实现原理：

> 这是通过**创建或删除**配置文件 `/etc/ssh/ssh_config.d/kali-wide-compat.conf` 实现的。

💡 为什么要有 Wide Compatibility？官方解释得很清楚：
老旧的 SSH 服务往往处于生命末期，**更容易发现漏洞或其它问题**——
所以渗透测试需要能连上去。这也是 Kali 的定位使然。

### 2.2 ssh1：已从 OpenSSH 移除的功能

当功能老到被 OpenSSH **彻底删除**（而不只是默认禁用）时，Wide Compatibility 也无能为力，
此时需要另一个客户端包 `ssh1`。

官方说明：

> 这个包实际上是**冻结在 OpenSSH 7.5**（2017 年 3 月发布）的版本。
> 它提供 `ssh1`、`scp1`、`ssh-keygen1` 三个二进制。
> 为什么是 7.5？因为这是**最后一个支持 SSH v.1 协议**的 OpenSSH 版本。
> 后来它还变得有用，因为可以继续用其它被移除的特性，尤其是 **DSA 密钥**
> （支持在 9.8 版本中被移除）。

```bash
# Kali 2024.4 起默认已安装；老系统手动装：
sudo apt install -y openssh-client-ssh1

dpkg --listfiles openssh-client-ssh1 | grep bin/
# /usr/bin/scp1
# /usr/bin/ssh-keygen1
# /usr/bin/ssh1

ssh1 -V
# OpenSSH_7.5p1 Debian-17, OpenSSL 3.3.2 3 Sep 2024
```

### 2.3 GSS-API 支持的变化

官方说明（**自 Kali 2026.3 起**）：

> SSH 客户端**不再包含 GSS-API 密钥交换支持**。
> 需要该功能的用户可以安装替代包 `openssh-client-gssapi` 恢复。

💡 什么时候需要 GSS-API？在企业内网用 **Kerberos 认证**做 SSH 登录时（AD 环境常见）。

### 2.4 Samba 客户端：默认就是 Wide Compatibility

来源：[Samba Configuration](https://www.kali.org/docs/general-use/samba-configuration/)（自 Kali 2021.4 起）

⚠️ 注意这个**和 SSH 相反**：

| 客户端 | 默认模式 |
|--------|----------|
| SSH | Strong Security（严格） |
| **Samba** | **Wide Compatibility（宽松）** |

> 这意味着**旧协议（LANMAN1、LANMAN2、NT1）默认启用**。
> 这与标准行为不同——标准行为会禁用它们以强制走更安全的通道。

```bash
kali-tweaks
# Hardening 菜单 → 在 Wide Compatibility（默认）与 Strong Security 之间选择
```

🔬 实现原理（官方）：

> 通过修改 Samba 配置文件 `/etc/samba/smb.conf` 中的 `client min protocol` 设置实现。

```bash
# 观察当前设置
grep -E 'client min protocol|client max protocol' /etc/samba/smb.conf
testparm -sv 2>/dev/null | grep -i 'protocol'
```

💡 **对渗透测试的意义**：SMBv1（NT1）是 **EternalBlue（MS17-010）** 这类漏洞的载体。
Kali 默认允许用旧协议，正是为了能连上那些没打补丁的目标。

⚠️ **对防守方的意义**：如果你们内网还有 SMBv1 在跑，这就是高风险项。
禁用方法（在 Samba 服务端）：

```ini
# /etc/samba/smb.conf
[global]
   server min protocol = SMB2
```

## 3. 代理与隧道

### 3.1 代理的五种层级

渗透测试里"走代理"往往指完全不同的事情，先分清楚：

| 层级 | 工具 | 作用范围 | 典型用途 |
|------|------|----------|----------|
| 应用层 | 浏览器代理设置、`curl -x` | 单个应用 | 抓 Web 流量 |
| HTTP(S) 代理 | Burp Suite / ZAP | 应用配置了代理的流量 | 拦截改包 |
| 环境变量 | `http_proxy` 等 | 大部分命令行工具 | 让 apt/curl/wget 走代理 |
| 系统级 | `proxychains4` | 强行劫持任意程序的连接 | 让不支持代理的工具走 SOCKS |
| 网络层 | VPN（OpenVPN/WireGuard）、`sshuttle` | 全部流量 | 访问内网、隐藏来源 |

### 3.2 环境变量代理（最常用）

```bash
# 临时生效
export http_proxy="http://127.0.0.1:8080"
export https_proxy="http://127.0.0.1:8080"
export no_proxy="localhost,127.0.0.1,::1,内网网段"

# 注意大小写都要设（不同程序读的不一样）
export HTTP_PROXY="$http_proxy"
export HTTPS_PROXY="$https_proxy"
```

⚠️ **`no_proxy` 一定要设**，否则连本机靶场都会被塞进代理，导致各种诡异的连接问题。

### 3.3 给 apt 配代理

```bash
sudo tee /etc/apt/apt.conf.d/99proxy >/dev/null <<'EOF'
Acquire::http::Proxy "http://127.0.0.1:8080";
Acquire::https::Proxy "http://127.0.0.1:8080";
EOF

# 验证
sudo apt update
```

删除该文件即可恢复直连。

### 3.4 proxychains：让不支持代理的程序走 SOCKS

Kali 中的包名是 **`proxychains-ng`**（命令为 `proxychains4`）。

```bash
sudo apt install -y proxychains-ng

# 配置文件
sudo vim /etc/proxychains4.conf
```

关键两处配置：

```ini
# 1. 代理链类型（常用 strict_chain 或 dynamic_chain）
strict_chain

# 2. 文件末尾配置实际的代理服务器
[ProxyList]
socks5 127.0.0.1 1080
```

```bash
# 在命令前加前缀即可
proxychains4 nmap -sT -Pn -p 80,443 目标IP
proxychains4 curl http://目标/
```

⚠️ **三个必踩的坑**：

1. **必须用 `-sT`**：proxychains 走 TCP 代理，无法转发原始套接字，
   所以 `nmap` 的 SYN 扫描（`-sS`）**不可用**。
2. **必须加 `-Pn`**：ICMP 探测会被代理吃掉，导致主机被判为 down。
3. **DNS 处理**：默认 `proxy_dns` 会让 DNS 也走代理。
   内网场景常需要关掉它才能解析内网域名。

### 3.5 sshuttle：不需要 root 的"穷人 VPN"

`sshuttle` 在 Kali 工具索引中（分类：命令与控制）。

```bash
# 把 10.10.10.0/24 的流量通过跳板机转发
sudo sshuttle -r 用户@跳板机 10.10.10.0/24

# 配合 SSH 密钥更顺
sshuttle -r 用户@跳板机 --ssh-cmd "ssh -i ~/.ssh/id_rsa" 10.10.10.0/24
```

💡 与 proxychains 的区别：sshuttle 基于 iptables 透明转发，
**能处理所有 TCP 流量甚至 DNS**，不需要每个命令加前缀。
缺点是需要 root（或 `CAP_NET_ADMIN`），且只支持 TCP。

### 3.6 Tor

```bash
sudo apt update
sudo apt install -y torbrowser-launcher
torbrowser-launcher
```

🔗 [Installing Tor Browser on Kali Linux](https://www.kali.org/docs/tools/tor/)

⚠️ 使用 Tor 的红线：

- 只对**明确授权**的目标使用
- **绝不要**在 Tor 会话里登录个人账号，这直接摧毁匿名性
- 浏览器指纹、JS、字体、时区都是去匿名化路径
- Tor 不等于"隐身"，出口节点可以看到未加密流量

## 4. 远程访问 Kali

### 4.1 SSH 服务端

Kali 默认**不启动** SSH 服务（回忆 [01 篇](01-Kali介绍与版本.md#2-三个最关键的设计决定)：
网络服务默认被 systemd 钩子禁用）。

```bash
# 安装并启动（⚠️ 只在你需要远程访问时才开）
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh

# 确认监听
ss -tlnp | grep :22
```

常用服务端加固配置（`/etc/ssh/sshd_config`）：

```ini
PermitRootLogin no                    # 禁止 root 直接登录
PasswordAuthentication no             # 只用密钥（配好密钥后再改）
PubkeyAuthentication yes
Port 22                               # 改非标准端口能挡掉扫描器，但不是安全措施
AllowUsers kali                       # 白名单
```

```bash
sudo sshd -t          # 检查配置语法（改完必做）
sudo systemctl restart ssh
```

💡 免密登录（客户端侧）：

```bash
ssh-keygen -t ed25519 -C "kali@lab"
ssh-copy-id 用户@远端
```

⚠️ **`PermitRootLogin yes` 是重大风险**，见 [03 篇第 2 节](03-系统配置与优化.md#2-启用-root-账户不推荐但要知道怎么做)。

### 4.2 浏览器里的 Kali

Kali 官方提供两种"用浏览器访问 Kali 桌面"的方案：

| 方案 | 原理 | 官方文档 |
|------|------|----------|
| **noVNC** | VNC → WebSocket → 浏览器 | [novnc-kali-in-browser](https://www.kali.org/docs/general-use/novnc-kali-in-browser/) |
| **Guacamole** | 无客户端远程桌面网关（支持 RDP/VNC/SSH） | [guacamole-kali-in-browser](https://www.kali.org/docs/general-use/guacamole-kali-in-browser/) |

**核心命令**（官方 noVNC 方案）：

```bash
# 安装
sudo apt install -y novnc

# 启动 VNC 服务
vncserver :1

# 启动 websockify，把 6080 端口的 HTTP 转成 VNC
websockify -D --web=/usr/share/novnc/ 6080 localhost:5901
```

然后浏览器访问 `http://<Kali的IP>:6080/vnc.html`。

⚠️ **安全提醒**：noVNC/Guacamole 默认**没有传输加密**。
只在本机或可信内网使用；暴露到公网必须套 HTTPS 反代 + 认证，
并限制来源 IP。

💡 适用场景：云主机上跑 Kali（只有 SSH 端口开放），需要通过 SSH 隧道做本地转发访问：

```bash
ssh -L 6080:127.0.0.1:6080 用户@云主机
# 本地浏览器打开 http://127.0.0.1:6080/vnc.html
```

## 5. 无线网卡不工作怎么办

来源：[Troubleshooting Wireless Drivers](https://www.kali.org/docs/troubleshooting/troubleshooting-wireless-driver-issues/)

这是 Kali 新手最常卡住的地方。排查顺序：

### 5.1 网卡被识别了吗

```bash
lsusb                  # USB 设备（外置网卡看这里）
lspci -nnk | grep -A3 -i net    # PCI 设备 + 使用的内核驱动
rfkill list            # 是否被软/硬开关禁用
iw dev                 # 无线接口列表
ip link show
```

### 5.2 支持监听与注入吗

这是**做无线测试的硬门槛**，网卡芯片决定一切：

```bash
# 列出网卡支持的模式，找 MONITOR
iw list | grep -A 8 "Supported interface modes"

# 确认支持注入（需要至少一张支持注入的网卡）
sudo aireplay-ng --test wlan0
```

| 能力 | 命令 | 说明 |
|------|------|------|
| 监听模式 | `iw list` 里有 `MONITOR` | 抓包必需 |
| 注入 | `aireplay-ng --test` 成功 | 打解除认证、注入数据包必需 |
| 5 GHz | `iw list` 频段 | 双频卡更实用 |

⚠️ **虚拟机里 USB 无线网卡要直通**给 Kali（VirtualBox：设备 → USB → 勾选网卡），
否则 Kali 只能看到"虚拟的有线网卡"。

### 5.3 驱动问题

```bash
# 看该设备绑定了哪个驱动
lspci -nnk | grep -A3 Wireless
lsmod | grep -i -E 'rtl|ath|iwl|brcm|mt76'

# 内核日志里找错误
dmesg -T | grep -i -E 'firmware|wlan|wireless|rtl|ath'
```

常见原因与处理：

| 现象 | 原因 | 处理 |
|------|------|------|
| `dmesg` 报 `firmware failed to load` | 缺固件 | `sudo apt install firmware-<厂商>`（Kali 的 `non-free-firmware` 组件） |
| 网卡在 `rfkill list` 里是 blocked | 软/硬开关禁用 | `rfkill unblock all` |
| 没有 MONITOR 模式 | 芯片/驱动不支持 | 换网卡（用外置 USB 网卡） |
| 驱动冲突（如 `rtl8xxxu` vs `rtl8812au`） | 多驱动抢占设备 | 黑名单多余驱动（`/etc/modprobe.d/`），或用 `dkms` 编译专用驱动 |
| Kali 里网卡正常，宿主 Windows 里不行 | Windows 驱动接管了 | 在虚拟机设置里把 USB 设备直通给 Kali |

💡 **`airmon-ng check kill` 会杀掉 NetworkManager 等进程**，这会让你"网断了"。
这是设计行为（避免 NetworkManager 干扰监听模式），不是故障。
做无线测试时才用，测完 `sudo systemctl restart NetworkManager` 恢复。

## 6. 下载速度慢

来源：[Discovering Problems With Download Speed](https://www.kali.org/docs/troubleshooting/download-speed-issues/)

```bash
# 从官方镜像池测速
curl -o /dev/null -w "%{speed_download} bytes/s\n" http://http.kali.org/kali/dists/kali-rolling/Release

# 或直接用 wget 看速度
wget --output-document=/dev/null http://http.kali.org/kali/dists/kali-rolling/Release
```

处理思路：

1. 换镜像站（国内可用清华 TUNA、中科大 USTC 等，只改 `URIs` 字段）
2. 检查是否走了代理
3. 检查 IPv6 是否有问题（有时禁用 IPv6 反而更快）
   ```bash
   sudo sysctl -w net.ipv6.conf.all.disable_ipv6=1
   ```
4. 大镜像用 BitTorrent 下载（官方推荐 Everything 镜像走 BT）

## 🧪 练习

1. **网络分层排查演练**（在虚拟机里主动制造故障）
   ```bash
   ip -br addr && ip route
   sudo ip link set eth0 down && ping -c 1 1.1.1.1     # 观察
   sudo ip link set eth0 up
   sudo ip addr flush dev eth0 && sudo dhclient eth0    # 重新拿地址
   ```
2. **代理链路验证**
   ```bash
   # 起一个简单 HTTP 代理（用 Python 自带的）
   python3 -m http.server 8080 &
   export http_proxy="http://127.0.0.1:8080"
   curl -v http://example.com    # 观察走了代理
   unset http_proxy
   ```
3. **SSH 加固**
   ```bash
   sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication|pubkeyauthentication'
   ```
   逐条解释输出，并说明为什么用密钥比密码安全（提示：暴力破解的可行性差异）。
4. **兼容模式观察**
   ```bash
   kali-tweaks    # 切换 SSH 的 Strong Security / Wide Compatibility
   ls -l /etc/ssh/ssh_config.d/
   cat /etc/ssh/ssh_config.d/kali-wide-compat.conf 2>/dev/null
   ```
   对比切换前后文件的存在性，验证官方说的"通过创建/删除该文件实现"。
5. **SMB 协议观察**
   ```bash
   grep -E 'client min protocol' /etc/samba/smb.conf
   # 用 smbclient 连接一个只支持 SMB1 的老靶机（如 Metasploitable2）
   smbclient -L //靶机IP -N
   ```
