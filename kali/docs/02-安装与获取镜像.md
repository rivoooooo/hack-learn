## 1. 先看硬件够不够

官方给出的区间（[hard-disk-install](https://www.kali.org/docs/installation/hard-disk-install/)）：

| 场景 | 内存 | 磁盘 |
|------|------|------|
| 最小（纯 SSH 服务器，无桌面） | 128 MB（建议 512 MB） | 2 GB |
| 默认（Xfce + `kali-linux-default`） | ≥ 2 GB | 20 GB |
| 跑资源密集型工具（如 Burp Suite） | ≥ 8 GB（大型 Web 应用还要更多） | — |
| 官方通用建议 | — | **60 GB 可以满足任意组合并留有余量** |

### 安装尺寸实测表（Kali 2024.1 实测）

| 元包 / 桌面环境 | Xfce | GNOME | KDE | Headless |
|-----------------|------|-------|-----|----------|
| `kali-linux-core` | 3.7 G | 4.1 G | 5.2 G | 1.5 G |
| `kali-tools-top10` | 6.7 G | 7.0 G | 8.2 G | 5.0 G |
| `kali-linux-default` | 13 G | 13 G | 15 G | 13 G |
| `kali-linux-large` | 20 G | 20 G | 21 G | 19 G |
| `kali-linux-everything` | 34 G | 35 G | 36 G | 34 G |

最大组合 36 G，最小 1.5 G。💡 **虚拟机练手**：Xfce + `kali-linux-default`，给 80 GB 磁盘（动态分配）足够。

## 2. 下载镜像并验证（这一步不能跳）

### 2.1 必须验证的两件事

官方流程（[download-images-securely](https://www.kali.org/docs/introduction/download-images-securely/)）的顺序很重要：

1. **先验证 `SHA256SUMS` 文件的签名**（确认这个校验和清单确实是 Kali 官方出的）
2. **再验证镜像的 SHA256**（确认镜像和清单一致）

跳过第 1 步直接比对哈希是不够的——攻击者可以把恶意镜像和对应的假清单一起给你。

### 2.2 导入 Kali 官方签名密钥

```bash
# 方式一：从官方归档站获取
wget -q -O - https://archive.kali.org/archive-key.asc | gpg --import

# 方式二：从公钥服务器获取
gpg --keyserver hkps://keyserver.ubuntu.com --recv-key 827C8569F2518CC677FECA1AED65462EC8D5E4C5

# 核对指纹（必须与官方一致）
gpg --fingerprint 827C8569F2518CC677FECA1AED65462EC8D5E4C5
```

官方给出的指纹（2025 年的密钥）：

```text
pub   rsa4096 2025-04-17 [SC] [expires: 2028-04-17]
      827C 8569 F251 8CC6 77FE  CA1A ED65 462E C8D5 E4C5
uid           [ unknown] Kali Linux Archive Automatic Signing Key (2025)
```

⚠️ 指纹或密钥 ID 对不上就**立即停止**，重新确认下载源是不是官方镜像。

### 2.3 验证签名与镜像

```bash
# 下载校验和文件与它们的签名
wget -q https://cdimage.kali.org/current/SHA256SUMS{.gpg,}

# 验证 SHA256SUMS 本身是官方签发的
gpg --verify SHA256SUMS.gpg SHA256SUMS
```

期望输出中必须出现：

```text
gpg: Signature made Sun 20 Apr 2025 16:00:00 GMT
gpg:                using RSA key 827C8569F2518CC677FECA1AED65462EC8D5E4C5
gpg: Good signature from "Kali Linux Archive Automatic Signing Key (2025) ..."
```

> 那句 `WARNING: This key is not certified with a trusted signature!` 是正常的
> —— 它只表示你没有在本地信任网中签过这把钥匙，不代表签名无效。
> 关键看 **`Good signature`** 与**密钥 ID 是否匹配**。

```bash
# 最后校验镜像本身
sha256sum -c SHA256SUMS --ignore-missing 2>&1 | grep -i kali-linux
# 或手动比对
sha256sum kali-linux-2026.x-installer-amd64.iso
```

🔗 镜像站列表：<https://www.kali.org/get-kali/#kali-installer-images>（下载页会列出各国镜像）

## 3. 单系统安装流程

以官方 [hard-disk-install](https://www.kali.org/docs/installation/hard-disk-install/) 为例（裸机或虚拟机通用）。

### 3.1 前置条件

- amd64（x86_64/64 位）安装镜像
- 支持 CD/DVD 或 USB 启动
- **单块磁盘**（官方示例场景）
- 网络可出网（DHCP + DNS 正常）
- 数据已备份 —— ⚠️ **安装过程会清空磁盘**

### 3.2 准备清单（官方逐条）

1. 下载镜像（推荐 Installer）
2. 写入 DVD 或 U 盘
3. 备份设备上的重要数据到外部介质
4. 在 BIOS/UEFI 中设置从 CD/DVD/USB 启动
5. ⚠️ **在 UEFI 设置中关闭 Secure Boot** —— 官方原文：

   > Kali Linux 内核没有签名，不会被 Secure Boot 认可。

   （这与 [01 篇](01-Kali介绍与版本.md#2-三个最关键的设计决定)提到的自定义内核直接相关：打了注入补丁的内核无法通过微软签名链。）

### 3.3 启动与安装阶段

```text
启动介质
  └─ Kali 启动菜单
       ├─ Graphical install   ← 图形安装（推荐新手）
       ├─ Install             ← 文本模式安装
       └─ Live system         ← 仅 Live 镜像有：先体验，不安装
```

安装过程中的关键选择：

| 步骤 | 说明与建议 |
|------|-----------|
| 语言 / 地区 / 键盘 | 键盘布局选对，否则后面输入的密码可能不对 |
| 主机名 | 随意，但别用默认 `kali`（多机同网段会冲突） |
| 创建用户 | **这里创建的是普通用户**（非 root 策略），见 [01 篇](01-Kali介绍与版本.md#6-默认凭据) |
| 磁盘分区 | 见下节。想加密就选"使用整个磁盘并加密 LVM" |
| 元包选择 | 默认 `top10` + `default`；不选桌面环境即 headless |
| GRUB 安装位置 | 单系统装到磁盘 MBR/EFI 分区即可 |

💡 **U 盘写入命令**（Linux/macOS 下，⚠️ `of=` 写错会毁掉你的系统盘）：

```bash
# 先确认设备名，务必核对容量与型号
lsblk -o NAME,SIZE,MODEL,TRAN
# 假设 U 盘是 /dev/sdX（注意不是 /dev/sdX1）
sudo dd if=kali-linux-2026.x-installer-amd64.iso of=/dev/sdX bs=4M status=progress oflag=sync
sync
```

Windows 上可用 Rufus 或 [官方推荐的 USB 写入方式](https://www.kali.org/docs/usb/)。

## 4. 分区方案怎么选

| 方案 | 优点 | 缺点 | 适合 |
|------|------|------|------|
| 全盘单分区（`/` + swap） | 简单 | 重装要全丢 | 虚拟机、短期使用 |
| `/` + `/home` 分离 | 重装保留个人数据 | 需要预估分区大小 | 长期使用 |
| **LUKS 加密 + LVM** | 全盘加密、可动态调卷 | 每次开机输密码；忘记密码数据无法恢复 | 笔记本、存敏感数据 |
| BTRFS + 快照 | 秒级快照/回滚 | 复杂度高 | 想"炸了随时回滚"（[Kali Unkaputtbar](https://www.kali.org/docs/installation/btrfs/)） |

🔬 LUKS 的原理、`cryptsetup` 全套命令与恢复手段见 [07-加密磁盘与LUKS.md](07-加密磁盘与LUKS.md)。

⚠️ **加密磁盘的三个致命操作**：
- 输错密码超过 key slot 次数之后只能靠 recovery key
- `cryptsetup luksFormat` 会**不可逆地**清空该分区
- 没有备份 LUKS header 就重装 = 数据永久丢失

```bash
# 装完后第一时间备份 LUKS header（务必存到外部介质）
sudo cryptsetup luksHeaderBackup /dev/sda3 --header-backup-file luks-header-backup.img
```

## 5. 双系统

| 场景 | 关键点 | 官方文档 |
|------|--------|----------|
| Kali + Windows | 先装 Windows 再装 Kali；Windows 的快速启动与休眠会锁磁盘，需关闭；Secure Boot 需关闭 | [dual-boot-kali-with-windows](https://www.kali.org/docs/installation/dual-boot-kali-with-windows/) |
| Kali + 其它 Linux | 共用 ESP 分区、注意 GRUB 由谁接管 | [dual-boot-kali-with-linux](https://www.kali.org/docs/installation/dual-boot-kali-with-linux/) |
| Kali + macOS | 需要关闭 SIP、处理 T2/Apple Silicon 的兼容性；分区工具用 macOS 自带磁盘工具 | [dual-boot-kali-with-mac](https://www.kali.org/docs/installation/dual-boot-kali-with-mac/) |

⚠️ 双系统最常见的两个翻车点：
1. Windows 的**快速启动（Fast Startup）**没关 → Linux 挂载 NTFS 时报 dirty
2. 后装的系统覆盖了引导 → 需要修复 GRUB（见 [11-故障排查.md](11-故障排查.md)）

💡 更安全的替代：**虚拟机 + 快照**。除非你需要真正的硬件直通（无线注入、GPU、物理接口），
否则不建议为了玩 Kali 去动主力机的分区表。

## 6. 其它安装方式

### 最小化（Bare-bones）
只要 SSH，不要桌面，安装体积可低至 1.5 G。适合当跳板机/工具服务器。

```bash
# 装完之后手动补工具集
sudo apt update && sudo apt install -y kali-tools-top10
```

🔗 <https://www.kali.org/docs/installation/barebone-kali/>

### PXE 网络批量安装
适合实验室机房一次装几十台。需要自己搭 TFTP + HTTP + DHCP。

🔗 <https://www.kali.org/docs/installation/network-pxe/>

### BTRFS 快照方案（Kali Unkaputtbar）
用 BTRFS + snapper 之类方案，在升级/折腾前自动打快照，坏了直接回滚。

🔗 <https://www.kali.org/docs/installation/btrfs/>

### 旧 i386 镜像
官方仍提供老的 32 位镜像说明，适用于极老硬件。

🔗 <https://www.kali.org/docs/installation/installing-old-i386/>

## 🧪 练习

1. **完整走一遍校验流程**：下载当前 Kali Installer 镜像与 `SHA256SUMS`，导入官方 GPG 密钥，验证签名与哈希，把输出保存下来。（这一步在企业环境里是强制要求）
2. **测体积**：在虚拟机里分别用 `kali-linux-core` + headless 与 `kali-linux-default` + Xfce 装两次，用 `df -h /` 记录实际占用，和官方表格对比。
3. **故意破坏 GRUB 再修复**（在快照里做）：装完 Kali 后执行 `sudo grub-install` 的替代实验，或者用 Live 启动盘进入 rescue 模式，执行 `grub-install` + `update-grub`。
4. **LUKS 体验**：在虚拟机中做一次 LVM 加密安装；装完后备份 LUKS header；再尝试用 `cryptsetup luksDump` 观察 header 内容。
