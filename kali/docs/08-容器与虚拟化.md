## 核心知识

### 容器 vs 虚拟机：Kali 该选哪个

```text
虚拟机（VM）                         容器（Container）
┌──────────────┐                    ┌──────────────┐
│  Guest OS    │  ← 完整内核        │  应用进程     │
├──────────────┤                    ├──────────────┤
│  虚拟硬件     │                    │  命名空间    │
├──────────────┤                    ├──────────────┤
│  Hypervisor  │                    │ 宿主内核      │
├──────────────┤                    ├──────────────┤
│  Host OS     │                    │  Host OS     │
└──────────────┘                    └──────────────┘
```

**关键结论（官方文档隐含、渗透场景必须记住）**：

- **无线渗透必须用 VM 或裸机 + USB 网卡穿透**，容器**做不了**：无线注入需要宿主内核的 `cfg80211/mac80211` 与网卡驱动配合，容器再怎么写也拿不到 PCI/USB 设备直通。官方在 [11-故障排查](11-故障排查.md) 的无线排查页明说：「Kali 是 VM 吗？除非你的卡是 USB 的，否则不可用。」
- **容器共享宿主内核**：内核模块（NVIDIA、VirtualBox、部分 WiFi 驱动）在容器里 `modprobe` 是**无效的**（会影响宿主，或直接失败）。
- **网络命名空间隔离**：容器默认在独立 netns 内，`arp-scan`/`ettercap` 之类依赖**二层广播**的工具在 bridge 网络下行为与宿主不同；用 `--network host` 才能贴近宿主网络栈。
- **VM 的好处是完整内核**：可以自由 `modprobe`、开 monitor mode（配 USB 网卡）、跑嵌套虚拟化。

### 什么时候用容器

- CI/CD 里跑 `nmap`、`nikto`、`sqlmap` 等**纯用户态、纯网络工具**。
- 想快速起一堆一次性工具环境，用完即删。
- 想要「每周自动更新一次的工具镜像」而不用维护 VM。

### Kali 官方 Docker 镜像（重要）

所有官方 Kali Docker 镜像**都不带 `kali-linux-default` metapackage**。官方原话：需要自己 `apt update && apt -y install kali-linux-headless`。

| 镜像 | 对应分支 | 用途 |
|------|----------|------|
| `kalilinux/kali-rolling` | `kali-rolling` | **主推**，持续更新，等同默认安装 |
| `kalilinux/kali-last-release` | `kali-last-snapshot` | 跟着最后一次版本发布，下次发布前不更新 |
| `kalilinux/kali-bleeding-edge` | `kali-rolling` + `kali-bleeding-edge` | 同上但开了 bleeding-edge，很不稳定 |
| `kalilinux/kali-experimental` | `kali-rolling` + `kali-experimental` | 测试尚未就绪的更新 |
| `kalilinux/kali-dev` | `kali-dev` | 给 Kali 开发者合并 Debian 更新用 |

镜像**每周在 Docker Hub 更新一次**（<https://hub.docker.com/u/kalilinux/>）。镜像由 `kali-docker` 构建脚本 + GitLab CI 自动构建：
<https://gitlab.com/kalilinux/build-scripts/kali-docker/>

### 一个经典陷阱：APT 源与容器

容器里 **不许在 `kali-rolling` 上叠加 `kali-last-snapshot`**——两者都是完整发行版，同时开会互相打架。见 [06-内核与硬件驱动](06-内核与硬件驱动.md) 的分支说明。

## 关键文档精读

### Installing Docker on Kali Linux

- **它解决什么问题**：在 Kali 宿主上装 Docker Engine。
- **最大坑（官方原文）**：Kali 仓库里**已经有一个叫 `docker` 的包**（不是容器那个 Docker！）。所以必须装 **`docker.io`**：
  ```bash
  sudo apt update
  sudo apt install -y docker.io
  sudo systemctl enable docker --now
  docker          # 验证命令是否存在
  ```
- **免 sudo 用 docker**：
  ```bash
  sudo usermod -aG docker $USER
  # 然后必须完全注销再登录（log out / log in）才生效
  ```
- **验证方式**：
  ```bash
  docker --version          # 本机实测格式：Docker version 29.7.2, build ...
  docker info               # 无权限错误说明 docker 组已生效
  sudo systemctl status docker
  ```
- **可选：装 `docker-ce`**（来自 Docker 官方仓库）。因为 Kali 基于 Debian，要用 **Debian 当前 stable 版本**（写文档时为 `trixie`），而不是 Kali 自己的代号：
  ```bash
  echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/debian trixie stable" | \
    sudo tee /etc/apt/sources.list.d/docker.list
  curl -fsSL https://download.docker.com/linux/debian/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
  sudo apt update
  sudo apt install -y docker-ce docker-ce-cli containerd.io
  ```
- **坑**：`docker-ce` 的源里写错代号（写成 `kali-rolling`、`bookworm` 等）会导致依赖解析失败。

### Official Kali Linux Docker Images

- **它解决什么问题**：搞清该拉哪个官方镜像、它们对应什么分支。
- **操作步骤**：见上表。**别忘记装工具**：
  ```bash
  docker run -it kalilinux/kali-rolling
  # 容器内：
  apt update && apt -y install kali-linux-headless
  ```
- **验证方式**：
  ```bash
  docker images | grep kalilinux
  docker run --rm kalilinux/kali-rolling cat /etc/os-release
  ```
- **坑**：官方镜像**故意做得很稀疏**，第一反应「怎么啥工具都没有」是正常的，不是镜像坏了。

### Using Kali Linux Docker Images

- **它解决什么问题**：容器化 Kali 的最短使用路径。
- **操作步骤**（官方原文命令）：
  ```bash
  docker pull docker.io/kalilinux/kali-rolling
  docker run --tty --interactive kalilinux/kali-rolling
  # 进入容器后（提示符形如 ┌──(root㉿...)）
  apt update && apt -y install kali-linux-headless
  ```
- **验证方式**：
  ```bash
  docker ps -a          # 看容器状态
  docker exec -it <容器ID> bash
  ```
- **坑**：
  - 容器默认是 **root**（与宿主 Kali 非 root 不同）。
  - 容器退出后**改动全丢**（除 `commit` 或挂卷）。持久化要 `-v` 或自己 build。要当「工作环境」用就得 `docker commit` 或写 Dockerfile。

### Using Kali Linux Podman Images

- **它解决什么问题**：用 Podman（**无守护进程、默认 rootless**）跑 Kali 容器。
- **操作步骤**：Podman 官网有各系统安装指南；Debian 系一条命令：
  ```bash
  sudo apt update
  sudo apt install -y podman
  ```
  之后把 `docker` 换 `podman` 即可（CLI 兼容）：
  ```bash
  podman pull docker.io/kalilinux/kali-rolling
  podman run --tty --interactive kalilinux/kali-rolling
  ```
- **验证方式**：
  ```bash
  podman info
  podman images
  ```
- **坑**：rootless Podman 下**绑定 <1024 端口会失败**（无特权），且默认不能挂宿主网络命名空间。要在容器里跑需要原始套接字的工具，经常要 `--privileged` 或 `--cap-add=NET_RAW --cap-add=NET_ADMIN`。

### Kali Linux LXC/LXD Images

- **它解决什么问题**：用系统容器（比 Docker 更像「轻量 VM」，有完整 init 与持久化 rootfs）跑 Kali。
- **官方覆盖 4 种形态**：
  1. Ubuntu 宿主上的**命令行 Kali LXD 容器**
  2. Ubuntu 宿主上的**GUI Kali LXD 容器**
  3. Kali 宿主上的**特权（privileged）LXC 容器**
  4. Kali 宿主上的**非特权（unprivileged）LXC 容器**
- **核心差异**：
  - **特权容器**：容器内 root ≈ 宿主 root，能挂设备、`modprobe`，适合需要原始套接字的场景——但**逃逸风险极大**。
  - **非特权容器**：用 uid/gid 映射隔离，安全得多，但**不能操作宿主设备**（无线、内核模块基本无望）。
- **操作要点**：LXD 的镜像源需配置 Kali 的镜像服务器，具体 `lxc remote add` / `lxc launch` 命令请以官方原文为准：
  <https://www.kali.org/docs/containers/kalilinux-lxc-images/>
- **验证方式**：
  ```bash
  lxc list
  lxc exec <容器名> -- bash
  ```
- **坑**：非特权 LXD 容器里 `systemctl` 可能受限；GUI 需要额外配 X11/wayland 转发或 VNC。

### Installing VirtualBox Guest Addition (Guest Tools)

- **它解决什么问题**：改善 VirtualBox 里 Kali 的鼠标/屏幕集成与**共享文件夹**。
- **背景**：自 **Kali 2019.3** 起，安装器会**自动检测是否在 VM 里**，是的话自动安装 `virtualbox-guest-x11`；自 **Kali 2021.3** 起 Live 镜像也预装了。所以**大多数情况你什么都不用做**。
- **手动重装**（出问题时）：
  ```bash
  # 先确保系统是最新的
  sudo apt update
  sudo apt install -y --reinstall virtualbox-guest-x11
  sudo reboot -f
  ```
- **验证方式**：
  ```bash
  dpkg -l | grep virtualbox-guest
  lsmod | grep -i vbox
  ```
  共享文件夹：在 VBox 设置里加共享目录后，`sudo mount -t vboxsf <共享名> /mnt/share`。
- **坑**：要求 **VirtualBox 4.2.xx 或更高**。Guest Additions 版本与宿主 VirtualBox 主版本不一致时，共享文件夹与剪贴板会失效。

### Kali inside QEMU/LibVirt with virt-manager (Guest VM)

- **它解决什么问题**：在 Linux 上用 KVM/QEMU + `virt-manager` 图形界面跑 Kali。
- **要点**：先让宿主准备好 Debian 系虚拟化能力（`qemu-kvm`、`libvirt-daemon`、`virt-manager`、把用户加入 `libvirt` 组），具体命令以官方页面为准：
  <https://www.kali.org/docs/virtualization/install-qemu-guest-vm/>
- **验证方式**：
  ```bash
  virt-host-validate       # 检查 KVM / IOMMU / 设备直通能力
  systemctl status libvirtd
  groups | grep libvirt
  ```
- **坑**：KVM 需要宿主 CPU 开 VT-x/AMD-V；嵌套虚拟化需在宿主内核开 `kvm_intel nested=1` / `kvm_amd nested=1`。要直通 USB 无线网卡用 virt-manager 的“添加硬件 → USB Host Device”。

### Kali inside Proxmox (Guest VM)

- **它解决什么问题**：在 Proxmox VE 上跑 Kali。
- **官方给了 3 种形态**：
  1. 用官方预装 VM 镜像；
  2. 自己装成 **VM（full virtualization）**；
  3. 装成 **CT（container，LXC）**。
- **坑**：CT 形态 = LXC 容器，**共享宿主内核**，`modprobe` 与 USB 直通能力受限；要跑无线必须用 VM 形态 + USB 直通。

### Running Kali Linux as a Virtual Machine in Windows

- **它解决什么问题**：Windows 上的杀软/EDR 会把 Kali VM 里的渗透工具当成恶意软件，导致 VM 卡顿、文件被删。
- **做法**：在 Windows 安全中心里给 Kali 的 **VM 磁盘目录 / 虚拟化软件目录**添加**排除文件夹（Exclusion Folder）**。
- **⚠️ 法律与合规提示**：把目录加进杀软白名单会**降低宿主机的检测能力**。只在**明确授权的测试环境**里这么做，别在办公/生产机上照搬。

## 实操清单

- [ ] 决定形态：跑无线/内核模块 → VM 或裸机；跑纯用户态网络工具 → 容器
- [ ] 宿主装 Docker：`sudo apt install -y docker.io`（**不是 `docker`**）
- [ ] 加 docker 组后**注销重登**：`sudo usermod -aG docker $USER`
- [ ] 拉官方镜像并补装工具：`docker pull kalilinux/kali-rolling` → 容器内 `apt install -y kali-linux-headless`
- [ ] 需要二层扫描时用宿主网络：`docker run --network host ...`
- [ ] 需要原始套接字时用能力：`--cap-add=NET_RAW --cap-add=NET_ADMIN`（慎用 `--privileged`）
- [ ] 检查 VM 里 Guest Additions/Tools 是否已随安装自动装好
- [ ] 共享文件夹挂载测试：`sudo mount -t vboxsf <名称> /mnt/share`
- [ ] 用 `virt-host-validate` 确认宿主虚拟化能力
- [ ] 记录容器/VM 的网络模式（NAT / Bridged / Host-only），这决定扫描结果是否可信

## 排错

| 现象 | 原因 | 解决 |
|------|------|------|
| `docker: command not found`，但 `apt install docker` 成功 | 装的是同名的 `docker` 包，不是容器引擎 | `sudo apt install -y docker.io` |
| `permission denied while trying to connect to the Docker daemon` | 用户不在 `docker` 组，或没重新登录 | `sudo usermod -aG docker $USER` 后**注销重登** |
| 容器里 `modprobe` 失败 / 影响宿主 | 容器共享宿主内核 | 改用 VM，或接受不能用该模块 |
| 容器里无线工具看不到网卡 | 容器无设备直通 | 用 VM + USB 直通，或裸机 |
| `arp-scan` 在容器里扫不到东西 | bridge netns 隔离二层广播 | `--network host` |
| Podman 绑定 80 端口失败 | rootless 模式无法绑特权端口 | 用非特权端口（如 8080），或改用 `sudo podman` |
| VBox 共享文件夹看不到 | Guest Additions 未装/版本不匹配 | `sudo apt install -y --reinstall virtualbox-guest-x11` 后重启；统一主版本号 |
| VM 里 Kali 很卡、文件莫名消失 | Windows 杀软误报 | 给 VM 目录加杀软排除项（仅授权测试环境） |
| Kali VM 无声音 | 音频后端未配置 | 见 [11-故障排查](11-故障排查.md) 的 PipeWire 一节 |
| `docker-ce` 装不上 | Docker 源里的 Debian 代号写错 | 用 Debian **当前 stable** 代号（写文档时为 `trixie`） |
