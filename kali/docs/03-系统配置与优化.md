## 1. 非 root 策略与 sudo

### 官方怎么说的

[All about sudo](https://www.kali.org/docs/general-use/sudo/) 原文要点：

> 从 2020.1 起 Kali 默认切换为**有特权的非 root 用户**。
> 这意味着 **root 没有设置密码**，安装时创建的账户才是你要用的账户。
> 可以重新启用 root 访问，但**官方不推荐**。

### 三件必须搞清的事

| 问题 | 答案 |
|------|------|
| root 能直接登录吗？ | 不能，root 没有密码 |
| `sudo` 要输哪个密码？ | **当前用户的密码**（不是 root 的） |
| 该用 `sudo su` 还是 `sudo 命令`？ | 优先 `sudo 命令`，只在需要连续多条时用 `sudo -i` |

官方还特别提醒：

> sudo 很强大，可以完全控制系统，所以**不建议对每条命令都用 sudo**。

```bash
# 推荐：按需提权
sudo systemctl restart ssh

# 需要连续多条 root 操作时，开一个 root shell
sudo -i
# 或
sudo su -
exit        # 或 Ctrl+D 退出

# 查看自己能做什么
sudo -l
```

### 免密 sudo（谨慎）

```bash
sudo apt install -y kali-grant-root && sudo dpkg-reconfigure kali-grant-root
```

官方说明这个包会把用户加入一个受信任组，从而使用 sudo 时不需要密码。
⚠️ 官方原话：

> 如果有人拿到了这个用户账户的访问权，这会带来安全风险。

💡 值得学习的点：Kali 的这套设计本身就是一个权限模型教材。
在真实渗透中，"找到有 NOPASSWD 的 sudo 规则"是最常见的提权路径之一：

```bash
sudo -l                     # 往往直接暴露可利用的命令
sudo -l | grep -i nopasswd
```

## 2. 启用 root 账户（不推荐，但要知道怎么做）

来源：[Enabling Root](https://www.kali.org/docs/general-use/enabling-root/)

### 临时提权 vs 长期启用

| 需求 | 做法 | 说明 |
|------|------|------|
| 临时用一会 | `sudo su` 或 `sudo -i` | 输当前用户密码；`exit` / `Ctrl+D` 退出 |
| 已给 root 设过密码 | `su -` | 输 root 自己的密码 |
| 跨多个会话长期用 root | 见下方完整步骤 | 需要改配置 |

### 完整启用步骤

```bash
# 1. 给 root 设置密码（务必与当前用户密码不同）
sudo passwd
# 输入当前用户密码 → 输入新的 root 密码 → 再输一次
```

> 官方提醒：输入密码时屏幕不会回显任何字符，但按键是生效的。

```bash
# 2. 决定 root 从哪里登录
```

**（a）通过 SSH 登录 root**

```bash
grep PermitRootLogin /etc/ssh/sshd_config
```

`PermitRootLogin` 的可选值（`man sshd_config`）：

| 值 | 含义 |
|----|------|
| `no` | 完全禁止 root 用 SSH 登录 |
| `prohibit-password`（默认，旧别名 `without-password`） | 禁用密码与键盘交互认证，**只允许密钥登录** |
| `forced-commands-only` | 只允许执行指定命令 |
| `yes` | 允许密码登录 |

如果你已配好 root 的 SSH 密钥，取消注释那行即可；否则改成 `yes`（⚠️ 意味着 root 可以被密码爆破）：

```bash
sudo systemctl restart ssh
```

⚠️ **强烈建议**：不要设 `PermitRootLogin yes`。用普通用户 + `sudo`，或至少用密钥登录。

**（b）通过 GNOME / KDE 图形登录界面登录 root**

```bash
sudo apt -y install kali-root-login
```

官方说明这个包只在 **GNOME (GDM3) 和 KDE** 的登录提示符下需要；其它桌面环境不需要这一步。

💡 更安全的替代：用 `sudo -i` 或用 root 终端图标，而不是把 root 暴露为可登录账户。

## 4. 非 root 下会"变样"的工具

来源：[Packages That Behave Differently With Non-root](https://www.kali.org/docs/general-use/nonroot-behavioral-differences-in-packages/)

官方以 **Nmap** 为例说明：

| 身份 | 默认扫描方式 | 原理 |
|------|--------------|------|
| root | **TCP SYN 扫描**（`-sS`） | 使用原始套接字（raw socket），**只有 root 能用** |
| 非 root | **TCP connect 扫描**（`-sT`） | 完整的 `connect()` 系统调用 |

区别：

- SYN 扫描**提前结束三次握手**（收到 SYN/ACK 就发 RST），更隐蔽、更快
- connect 扫描**完整建立连接**，服务端日志里会留下完整连接记录，更容易被发现

```bash
# 不加 sudo：自动降级为 connect 扫描
nmap -p 80,443 target

# 加 sudo：使用 SYN 扫描
sudo nmap -p 80,443 target
```

💡 **记住这条规律**：凡是需要构造原始数据包的扫描，都需要 root。
这解释了为什么很多命令示例里带 `sudo`——不是习惯，是必须。

同理受影响的还有：`masscan`、部分 `hping3` 模式、无线相关工具（需要监听/注入模式）。

## 5. 切换桌面环境

来源：[Switching Desktop Environments](https://www.kali.org/docs/general-use/switching-desktop-environments/)

```bash
sudo apt update
sudo apt install -y kali-desktop-kde

# 切换默认会话管理器
sudo update-alternatives --config x-session-manager

sudo reboot
```

⚠️ **KDE 的已知冲突**（官方明确说明）：

> KDE 可以和其它 DE 共存，但按当前的包配置会有若干配置冲突。
> 例如同时装了 KDE 和 Xfce 时，**Xfce 无法选择光标**。
> 解决办法是移除 Xfce 只留 KDE，**官方不建议 KDE 与其它 DE 并存**。
> 注意这只适用于 KDE；**Xfce 和 GNOME 可以共存且无冲突**。

```bash
# kali-desktop-* 包被标记为 system protected，移除必须加参数
sudo apt purge --autoremove --allow-remove-essential kali-desktop-xfce
```

🔬 `--allow-remove-essential` 是 apt 的保护机制：默认不允许删除"必需"包，
因为删掉它们可能让系统无法启动。Kali 把桌面环境元包也标成了受保护，
所以换桌面时必须显式绕过——**这也是为什么换桌面前一定要打快照**。

## 6. X11 还是 Wayland？

来源：[Wayland](https://www.kali.org/docs/general-use/wayland/)（更新于 2026-03-11）

### 概念

| 名词 | 是什么 |
|------|--------|
| **X11 / X.Org** | 1984 年发布的传统显示服务器，至今广泛使用 |
| **Wayland** | X11 的替代者，2008 年首发，正在取代 X11 |
| **XWayland** | 兼容层，让 X11 应用能跑在 Wayland 桌面上 |

### 查自己在用什么

```bash
echo $XDG_SESSION_TYPE
# 输出 wayland 或 x11
```

### Kali 各桌面的现状（官方原文）

| 桌面 | 显示服务器 |
|------|-----------|
| **Xfce** | 使用 X11，**短期内不会改变**（官方给了 Xfce Wayland 路线图链接） |
| **GNOME** | 自 **Kali Linux 2025.4** 起，Wayland 是默认且**唯一**的显示服务器 |
| **KDE** | 自 **Kali Linux 2023.1** 起，Wayland 是默认显示服务器；出问题可在登录界面左下角 Desktop Session 选 `Plasma (X11)` 回退 |

⚠️ **对渗透测试的实际影响**（比"用哪个更好看"重要得多）：

- 很多**屏幕截图/录屏类工具**在 Wayland 下行为不同（需要走 portal / pipewire）
- 部分依赖全局键盘钩子的工具（改键、自动化）在 Wayland 下受限
- 老旧的 GUI 攻击工具（依赖 X11 特性）可能在 Wayland 下崩溃
- **Xfce 用户暂时不受影响**，这也是 Kali 默认选 Xfce 的原因之一

💡 遇到"工具能跑但界面异常/截不到屏"时，第一件事就是 `echo $XDG_SESSION_TYPE`。

## 7. 显示缩放（HiDPI / 字体过大）

来源：[HiDPI](https://www.kali.org/docs/general-use/hidpi/) 与 [Fixing DPI](https://www.kali.org/docs/general-use/fixing-dpi/)

### 一键方案（Xfce）

```bash
kali-hidpi-mode
```

官方说明：Kali 提供了 HiDPI 模式，会同时调整 **GTK、Qt 甚至 Java 界面**的缩放系数，
省得你逐个手工改。也可以从应用菜单里的 "Kali HiDPI mode" 启动。

> 虽然 `kali-hidpi-mode` 能在不重启会话的情况下修改缩放，
> 但**建议注销后重新登录**以确保所有更改生效。
>
> 该模式会把每个窗口缩放到 2 倍；某些显示器上 2 倍太大，
> 可以启用 HiDPI 模式后在 Xfce 显示设置里配自定义分数缩放，
> **推荐 1.3x–1.5x**。

### 手工方案（了解原理）

```bash
# GTK 全局缩放
echo export GDK_SCALE=2 >> ~/.xsessionrc
xfconf-query -c xfwm4 -p /general/theme -s Kali-Dark-xHiDPI
xfconf-query -c xsettings -p /Gdk/WindowScalingFactor -n -t 'int' -s 2
```

| 现象 | 对应文档 |
|------|----------|
| 东西太小 | [HiDPI](https://www.kali.org/docs/general-use/hidpi/) |
| 东西太大（字体过大） | [Fixing DPI](https://www.kali.org/docs/general-use/fixing-dpi/) |

## 8. Kali Undercover（伪装主题）

来源：[Kali Undercover](https://www.kali.org/docs/introduction/kali-undercover/)

Kali 2019.4 引入，把桌面主题变成类 **Windows 10** 的样子。

```bash
kali-undercover      # 切换；再执行一次即可还原
```

也可从桌面菜单找 "Kali Undercover Mode"。

**官方给出的用途**：在客户现场做测试时，避免路人看到"Kali 桌面"而误以为你在做坏事。
官方原文讲得很直白——因为一张壁纸导致"前面的隐蔽工作全都白费"。

⚠️ 注意：这**只是主题伪装**，不改变任何网络特征。
它不能改变你的 MAC 地址、User-Agent、流量特征。
真正需要隐蔽时要做的是流量层与主机层的处理，见 [07-嗅探与欺骗](../tools/tutorials/07-嗅探与欺骗/) 与 [12-基础设施与C2](../tools/tutorials/12-基础设施与C2/)。

## 9. 给 headless 环境加图形界面（RDP）

来源：[Setting up RDP with Xfce](https://www.kali.org/docs/general-use/xfce-with-rdp/)

适用场景：**WSL、Docker、云主机**等只有命令行的地方。

官方脚本的核心内容：

```bash
apt-get update
apt-get full-upgrade -y

# 安装 Xfce4 与 xrdp
apt-get install -y kali-desktop-xfce xorg xrdp xorgxrdp

# 让 xrdp 监听 3390 端口（避免与 Windows 自带 RDP 的 3389 冲突）
sed -i 's/port=3389/port=3390/g' /etc/xrdp/xrdp.ini
```

官方也提供了现成脚本：

```bash
wget https://gitlab.com/kalilinux/recipes/kali-scripts/-/raw/main/xfce4.sh
chmod +x xfce4.sh
sudo ./xfce4.sh
```

**在 Docker 里用**时，官方给的启动方式需要映射端口：

```bash
docker run -p 3390:3390 --expose=3390 --tty --interactive kalilinux/kali-rolling /bin/bash
```

官方提醒：用 Docker 时，跑脚本前先执行：

```bash
apt update && DEBIAN_FRONTEND=noninteractive apt install -y wget kali-linux-headless
```

用 AWS 等云主机时：**必须在安全组里放行对应端口，并限制来源 IP**。

⚠️ 把 RDP 暴露到公网是高风险操作。只在本地网络或通过 SSH 隧道访问：

```bash
# 本地端口转发，把远端 3390 隧道到本地 3390
ssh -L 3390:127.0.0.1:3390 用户@远端主机
```

## 🧪 练习

1. **理解 sudo 模型**
   ```bash
   id                        # 看自己的 UID/GID 与所属组
   sudo -l                   # 看 sudo 规则
   sudo cat /etc/sudoers | grep -v '^#'
   sudo ls /root              # 对比不加 sudo 的结果
   ```
2. **观察 root / 非 root 的扫描差异**（在靶场网络上）
   ```bash
   nmap -p 22 靶机IP          # 非 root：connect 扫描
   sudo nmap -p 22 靶机IP     # root：SYN 扫描
   # 加 -v 或在靶机上抓包，对比数据包数量与交互过程
   ```
3. **元包实验**：用 `apt-cache depends kali-linux-default` 看它到底依赖了多少包，估算体积。
4. **换桌面环境**（⚠️ 先在快照里做）：装 `kali-desktop-gnome`，用 `update-alternatives --config x-session-manager` 切换，重启观察；再试 KDE 的冲突场景。
5. **给容器加 GUI**：跑一个 `kalilinux/kali-rolling` 容器，按官方脚本装 xrdp + Xfce，从宿主机 RDP 连进去。
