# netdiscover（主动／被动 ARP 侦察）

> **一句话**：用 ARP 发现本地网段的主机——既能主动发包扫描，也能只监听、一个包都不发。
> **分类**：信息搜集 ｜ **Kali 包**：`netdiscover` ｜ **官方文档**：<https://github.com/netdiscover-scanner/netdiscover>

## 1. 它解决什么问题

netdiscover 最初是为**无线车辆侦察（wardriving）**写的：在没有 DHCP 服务器的网络里，怎么知道周围有哪些主机？答案是用 ARP。

它和 [arp-scan](arp-scan.md) 是同一类工具，区别在细节：

| 维度 | netdiscover | [arp-scan](arp-scan.md) |
|------|-------------|-------------------------|
| 交互界面 | **有实时全屏界面**（可看 ARP 请求/回复/唯一主机三个视图） | 纯命令行输出 |
| 被动模式 | **支持 `-p`，完全不发包** | 无（只能主动） |
| 自动扫常见内网 | 支持（不指定范围时扫 `192.168.0.0/16`、`172.16.0.0/12`、`10.0.0.0/8`） | 需要显式给范围 |
| 快速模式 | `-f`：只扫每个网段的少数地址来"探路" | 无 |
| 自定义 ARP 包字段 | 无 | 有（`--arpspa` 等一整套） |
| MAC 厂商库 | 有 | 有（OUI 更完整，`get-oui` 可更新） |

**一句话选型**：想"扫一遍看结果"用 arp-scan；想**被动监听、零流量**，或想要实时滚动的交互界面，用 netdiscover。

被动模式的价值在于：**防守方完全无法检测**，因为你不发任何包。

## 2. 工作原理

```text
   主动模式 (默认)                      被动模式 (-p)
        │                                   │
        │ 注入 ARP Request                  │ 只开启 pcap 抓包
        ▼                                   ▼
   ┌─────────────────────────────────────────────────┐
   │   libpcap 捕获 ARP 回复 / 全部 ARP 流量           │
   │   （-F 可自定义 pcap 过滤表达式，默认 "arp"）      │
   └──────────────────────┬──────────────────────────┘
                          │
   ┌──────────────────────┴──────────────────────────┐
   │  实时更新三个视图（交互模式）：                    │
   │    a 键：ARP 回复列表   ← 主动扫描结果            │
   │    r 键：ARP 请求列表   ← 别人发的请求（被动情报）  │
   │    u 键：唯一主机列表   ← 去重后的主机 + MAC + 厂商 │
   └──────────────────────┬──────────────────────────┘
                          │
                   -P（可解析输出）或 -L（先主动后被动）
```

关键机制：

- **源 IP 是伪造的**：主动模式下 netdiscover 默认把 ARP 请求的源 IP 设为 `x.x.x.67`（`-n` 可改，范围 2~253），**不是本机真实 IP**。这样做的目的是避免用真实 IP 去探测（减少暴露）。副作用：如果 .67 已被占用，会引发地址冲突，需要 `-n` 换一个。
- **自动扫描**：不给 `-r`/`-l`/`-p` 时，会依次扫 `192.168.0.0/16`、`172.16.0.0/12`、`10.0.0.0/8` 这三个常见内网段。**这是它和其他工具最大的行为差异——不加参数可能是非常大规模的操作！**
- **快速模式 `-f`**：只扫每个网段的少数几个地址（默认 1、100、154 等，见 `~/.netdiscover/fastips`），用来快速判断"哪些网段是活的"，再针对性细扫。
- **配置文件**：`~/.netdiscover/ranges`（自动扫描的网段列表）和 `~/.netdiscover/fastips`（快速模式的末位地址列表）。`-d` 可忽略它们。
- **被动模式的情报价值**：`r` 视图能看到**别人的 ARP 请求**——从中可以推断出其他主机正在访问谁、网关是谁，是纯"听"出来的拓扑图。

## 3. 安装与快速上手

```bash
sudo apt install netdiscover
netdiscover --help 2>&1 | head -30
man netdiscover
```

最小可用命令：

```bash
# 1) 指定网段扫描（最安全，规模明确）
sudo netdiscover -i eth1 -r 192.168.56.0/24

# 2) 纯被动监听，一个包都不发
sudo netdiscover -i eth1 -p

# 3) 可解析输出，脚本化
sudo netdiscover -i eth1 -r 192.168.56.0/24 -P
```

> ⚠️ **不要裸跑 `sudo netdiscover`**——不给范围时它会扫 `192.168.0.0/16` 等三个大网段，是百万级的发包量。永远显式加 `-r` 或 `-p`。

## 4. 核心参数详解

### 目标选择

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `-r <range>` | 扫描指定范围（CIDR，如 `192.168.0.0/24`、`192.168.0.0/12`） | **推荐用法**；同时被动捕获的结果也会一并显示 |
| `-l <file>` | 从文件读范围，一行一个 | 多网段批量 |
| `-p` | **被动模式**：不发任何包，只嗅探 | 零流量侦察，防守方不可检测 |
| （不给参数） | 自动扫描 `192.168.0.0/16`、`172.16.0.0/12`、`10.0.0.0/8` | **危险**：规模巨大，除非明确需要 |
| `-f` | 快速模式：每个网段只扫少数地址 | 快速探路，找出"哪些网段是活的" |
| `-m <file>` | 扫描已知 MAC 与主机名列表 | 与资产台账比对 |

### 网卡与过滤器

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `-i <device>` | 抓包与注入使用的网卡 | **强烈建议显式指定**，否则用第一个可用网卡 |
| `-F <filter>` | 自定义 pcap 过滤表达式（默认 `"arp"`） | 例如 `-F "arp or icmp"` |
| `-n <node>` | 扫描使用的源 IP 末位（2–253，默认 67） | 与该地址冲突时改掉 |
| `-R` | 跳过 root/权限检查 | 容器等特殊环境 |
| `-d` | 忽略 `~/.netdiscover/` 下的配置文件 | 想用默认网段列表时 |

### 时序与输出

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `-s <ms>` | 每个 ARP 请求之间的睡眠毫秒数（默认 1） | 调小提速（`-s 0.5`），丢包网络调大 |
| `-c <count>` | 每个 ARP 请求重复发送次数（默认 1） | 丢包网络用 `-c 2` 或 `3` |
| `-P` | 可解析输出（非交互），扫完即退出 | **脚本化必用** |
| `-L` | 同 `-P`，但主动扫描后继续被动捕获 | 想要"扫完还能听" |
| `-N` | 不打印表头（仅 `-P`/`-L` 下有效） | 纯数据输出 |
| `-S` | （已废弃）抑制睡眠，每 255 台才睡一次 | 不建议使用 |

### 交互模式快捷键

| 键 | 作用 |
|----|------|
| `a` | 显示 ARP 回复列表 |
| `r` | 显示 ARP 请求列表（被动情报） |
| `u` | 显示唯一主机列表 |
| `h` | 帮助界面 |
| `j` / `k` | 下移 / 上移 |
| `.` / `,` | 上翻页 / 下翻页 |
| `q` | 关闭帮助或退出程序 |

## 5. 实战演练

**环境**：本地 VirtualBox Host-Only 网络 `192.168.56.0/24`。攻击机 Kali（`192.168.56.10`，`eth1`）。靶机：宿主接口 `192.168.56.1`、Metasploitable2 `192.168.56.101`、DVWA `192.168.56.102`。

### 场景 1：主动扫描本地网段（最常用）

```bash
sudo netdiscover -i eth1 -r 192.168.56.0/24
```

预期界面片段（实时刷新）：

```text
 Currently scanning: Finished!   |   Screen View: Unique Hosts

 3 Captured ARP Req/Rep packets, from 3 hosts.   Total size: 180
 _____________________________________________________________________________
   IP            At MAC Address     Count     Len  MAC Vendor / Hostname
 -----------------------------------------------------------------------------
 192.168.56.1    0a:00:27:00:00:01      1      60  PCS Systemtechnik GmbH
 192.168.56.101  08:00:27:1a:2b:3c      1      60  PCS Systemtechnik GmbH
 192.168.56.102  08:00:27:4d:5e:6f      1      60  PCS Systemtechnik GmbH
```

解读：
- 按 `u` 看到的就是去重后的唯一主机列表。
- 按 `r` 能看到该网段里的 **ARP 请求**——如果有人在访问网关，会看到 `who-has <网关>` 的请求，从而推断出还有其他主机在活动。
- `Count` 列是收到的包数；如果某台主机 `Count` 远大于 1，值得留意（可能是 ARP 欺骗或 HA）。

### 场景 2：纯被动侦察（零流量）

```bash
sudo netdiscover -i eth1 -p
```

预期输出片段：

```text
 Currently scanning: ARP   |   Screen View: ARP Requests
_____________________________________________________________________________
   IP            At MAC Address     Count     Len  MAC Vendor / Hostname
 -----------------------------------------------------------------------------
 192.168.56.1    0a:00:27:00:00:01      4      60  PCS Systemtechnik GmbH
 192.168.56.101  08:00:27:1a:2b:3c      2      60  PCS Systemtechnik GmbH
 192.168.56.102  08:00:27:4d:5e:6f      1      60  PCS Systemtechnik GmbH
```

解读：**这一模式下 netdiscover 没有发送任何数据包**——它只是把网段里已有的 ARP 流量收集起来。缺点是需要有流量才能发现主机（刚开机的安静网段可能什么都没有）。这一模式在防守方视角是**完全不可检测的**。

### 场景 3：快速模式探路 + 可解析输出做流水线

```bash
# 第一步：快速模式判断哪些网段是活的
sudo netdiscover -i eth1 -r 192.168.56.0/24 -f

# 第二步：可解析输出存盘（-P 扫完即退出）
sudo netdiscover -i eth1 -r 192.168.56.0/24 -P -N | tee nd.txt

# 第三步：提取 IP 清单
awk '/^[0-9]/{print $1}' nd.txt | sort -u > ips.txt
wc -l ips.txt
```

预期输出片段（`-P -N`）：

```text
192.168.56.1    0a:00:27:00:00:01      1      60  PCS Systemtechnik GmbH
192.168.56.101  08:00:27:1a:2b:3c      1      60  PCS Systemtechnik GmbH
192.168.56.102  08:00:27:4d:5e:6f      1      60  PCS Systemtechnik GmbH
```

解读：`-P` 让 netdiscover 变成"扫完就退出的批处理工具"，`-N` 去掉表头，输出直接可管道处理。这是把 netdiscover 接入自动化流程的正确姿势。`-f` 快速模式适合在较大的网段上先探路（只扫每段的少数末位地址，比如网关）。

### 场景 4（进阶）：与 arp-scan 交叉验证 + 源地址冲突处理

```bash
# 如果扫描时报 "the source IP is already in use" 之类的冲突提示，换一个源 IP 末位
sudo netdiscover -i eth1 -r 10.1.0.0/16 -n 101 -s 0.5 -c 2

# 与 arp-scan 对比结果，取并集
sudo arp-scan -I eth1 --localnet --plain --quiet | awk '{print $1}' | sort -u > as.txt
sudo netdiscover -i eth1 -r 192.168.56.0/24 -P -N | awk '/^[0-9]/{print $1}' | sort -u > nd.txt
comm -3 as.txt nd.txt      # 显示两边不一致的主机
```

解读：
- `-n 101` 把扫描用的**伪源 IP 末位**改成 101（默认 67）。当默认地址已被占用时会触发 IP 冲突告警，必须换。
- `-s 0.5 -c 2` 是在丢包网络上提速与提准确率的平衡：发得更快，但每台发两次。
- `comm -3` 的结果值得看——**同一网段内两个工具结果不同**通常说明有主机的 ARP 响应不稳定（可能在做 ARP 抑制，或是虚拟化平台的特殊网络模式）。

## 6. 输出解读

| 字段 | 含义 | 下一步 |
|------|------|--------|
| `IP` | 主机地址 | 存入清单 |
| `At MAC Address` | 链路层地址 | 厂商识别、去重 |
| `Count` | 收到的 ARP 包数 | 异常高 → 怀疑 ARP 欺骗/HA |
| `Len` | 包长度（60 是标准 ARP） | 异常值 → 非标准实现或畸形包 |
| `MAC Vendor / Hostname` | 厂商信息 | 判断设备类型 |
| `Screen View: Unique Hosts` | 当前视图 | `a`/`r`/`u` 切换 |
| `Currently scanning: ARP` | 被动模式标识 | 确认没在发包 |
| `Finished!` | 主动扫描结束 | 结合 `-P` 时程序会退出 |

**判断要点**：

- **主动模式下"没响应"基本等于不在线**（同网段 ARP 是强制的），但注意 ARP 抑制、虚拟网络 NAT 模式会造成假阴性。
- **被动模式的空白不代表网段为空**，只代表"当前没人在通信"。
- **MAC 厂商 = 设备类型线索**：`08:00:27`（VirtualBox）、`00:0C:29`（VMware）、`00:15:5D`（Hyper-V）、`52:54:00`（QEMU/KVM）——一眼区分物理机与虚拟机，对攻击路径规划很有帮助。

## 7. 与其他工具配合

```bash
# 1) netdiscover -> nmap
sudo netdiscover -i eth1 -r 192.168.56.0/24 -P -N | awk '/^[0-9]/{print $1}' | sort -u > ips.txt
sudo nmap -sV -iL ips.txt --open -oA nd_scan

# 2) 先 nmap 找活主机，再用 netdiscover 补全（ARP 能发现禁 ping 的主机）
sudo nmap -sn 192.168.56.0/24 -oG - | awk '/Up$/{print $2}' > nmap_alive.txt
sudo netdiscover -i eth1 -r 192.168.56.0/24 -P -N | awk '/^[0-9]/{print $1}' | sort -u > arp_alive.txt
cat nmap_alive.txt arp_alive.txt | sort -u > all_alive.txt

# 3) 设备类型盘点
sudo netdiscover -i eth1 -r 192.168.56.0/24 -P -N | awk '{print $5,$6,$7}' | sort | uniq -c | sort -rn

# 4) 结合 nbtscan 补名字
nbtscan -f all_alive.txt
```

## 8. 常见坑与排错

| 现象 | 原因 | 解决 |
|------|------|------|
| 误跑了裸 `sudo netdiscover`，网段规模爆炸 | 不加参数会扫 3 个大内网段 | **Ctrl-C 停止**；以后永远显式加 `-r` 或 `-p` |
| 提示源 IP 已被占用 / 目标弹地址冲突告警 | 默认伪源 IP `x.x.x.67` 已被使用 | `-n 101` 换一个末位 |
| 结果为空 | 网卡选错 / 是 NAT 网络 / 目标在别的 VLAN | `-i` 显式指定；虚拟机改桥接或 Host-Only |
| `libnet` 相关报错 | 缺 libnet 库 | `sudo apt install --reinstall netdiscover` |
| 扫描很慢 | 默认 `-s 1`（每包睡 1ms） | `-s 0.5` 提速；大面积先 `-f` 探路 |
| 被动模式什么都不显示 | 网段当前没有 ARP 流量 | 等一会，或先用主动模式 |
| 屏幕乱码（重定向到文件时） | 交互界面使用终端控制字符 | 用 `-P` 或 `-L` 代替交互模式 |
| 结果不全，与 arp-scan 不一致 | 丢包或 ARP 抑制 | 加 `-c 2`；两个工具取并集 |
| `-N` 不生效 | `-N` 只在 `-P` 或 `-L` 下有效 | 加上 `-P` |
| 容器里跑不了 | 需要 CAP_NET_RAW | `-R` 跳过检查，或 `--cap-add=NET_RAW` |

## 9. 防御视角（蓝队）

- **主动模式可检测，被动模式不可检测**——这是最重要的区分：
  - **主动模式**：短时间内同一源 MAC 对整段地址发 ARP 请求。交换机/IDS 可对"单位时间内单源 ARP 请求数"设阈值告警。
  - **被动模式（`-p`）**：**不发任何包，无法从网络中检测**。防守方唯一能做的是让网段内少产生有用的 ARP 流量（即网络分段）。
- **源 IP 伪装会留下强信号**：netdiscover 用伪源 IP 发包，如果该地址**恰好被真实设备占用**，会触发 `IP 地址冲突` 告警（Windows 弹窗 + 事件日志）。这是非常明确的入侵指标，应直接告警。
- **缓解措施**：
  - **私有 VLAN / 端口隔离**：把同 VLAN 主机互相隔离（只能与网关通信），主动扫描只能看到网关。
  - **Dynamic ARP Inspection（DAI）** + **DHCP Snooping**：交换机只放行合法 IP-MAC 绑定，并记录非法 ARP。
  - **802.1X**：未认证设备无法接入，直接缩小战场。
  - 无线场景下开启 **客户端隔离**。
- **监控建议**：
  - `arpwatch` 监控 ARP 表变化的异常（尤其 MAC 与 IP 的绑定突变）。
  - 交换机的 ARP 速率限制（`arp rate-limit`）可抑制广播风暴式的扫描。
- **注意**：ARP 发现**只能缓解，不能根除**。任何在同一个广播域里的主机都能做这件事——这也是"网络分段"在防守中价值极高的原因。
