# CherryTree（层级笔记 / 报告草稿）

> **一句话**：一个把笔记存成**树形结构**的富文本编辑器——每个节点都能写富文本、贴代码、插图片、加超链接，最后导出成 HTML/PDF 交给客户。
> **分类**：报告与记录（Reporting）｜ **Kali 包**：`cherrytree`（命令 `cherrytree`）｜ **官方文档**：<https://www.giuspen.net/cherrytree/> ｜ 项目：<https://github.com/giuspen/cherrytree>

---

## 1. 它解决什么问题

渗透测试/红队的产出里，**记录与报告**占了一半工作量。用 Word 写会遇到几个具体问题：

| 痛点 | CherryTree 的做法 |
|------|-------------------|
| 十几个主机、几十个漏洞，文档越写越乱 | **树形结构**：主机 → 服务 → 漏洞，逐级展开 |
| 命令输出要贴，但格式全乱 | **代码框（CodeBox）节点**，等宽字体 + 语法高亮 |
| 想快速找到「上次那个 CVE 的利用命令」 | **全文搜索**（Ctrl+F）+ 标签（Tag） |
| 要交 HTML / PDF | **导出**功能（HTML、PDF、纯文本等） |
| 写一半下班，明天继续 | **单文件存储**（`.ctb`，SQLite 格式）+ 可选加密 |
| 想按模板复用 | **从模板新建文件**（每个客户一份） |

对比同类：

| 工具 | 定位 | 差异 |
|------|------|------|
| **CherryTree** | 个人层级笔记 | 桌面单机、上手快、适合**个人记录与报告草稿** |
| **`dradis`** | **协作式渗透报告平台** | Web 应用、多人协作、**可直接导入扫描器输出**、按模板出报告；见 [`dradis.md`](dradis.md) |
| Markdown + Git | 纯文本工作流 | 可版本化、可 diff，但没有富文本/树形导航 |
| Notion/语雀等 | 在线文档 | 需要网络与账号，数据在云端（**取证/敏感项目不建议**） |

**选型建议**：

- **一个人做小项目**：CherryTree（本机、离线、快）；
- **团队协作、要出正式报告**：Dradis；
- **两者可以并用**：CherryTree 记过程，Dradis 汇总出报告。

## 2. 工作原理

```
cherrytree（GTK 应用，Python 实现）
   │
   ├─ 数据模型：一棵**节点树**
   │     · 每个节点 = 一段富文本内容（可含代码框、图片、表格、超链接、附件）
   │     · 节点属性：名称、图标、前景/背景色、标签、是否只读
   │
   ├─ 存储格式：
   │     · .ctb  → SQLite 数据库（单文件、支持加密）
   │     · .ctx  → 压缩 XML（旧格式，仍可读写）
   │
   ├─ 编辑能力：富文本、等宽代码框（语法高亮）、表格、
   │             图片插入、内部链接（节点互跳）、外部链接、
   │             标签与书签、拼写检查
   │
   └─ 导入/导出：
         · 导入：CherryTree 文件、纯文本文件目录、HTML、Markdown
         · 导出：HTML（多文件/单文件）、PDF、纯文本、Markdown、
                 CherryTree（另存）
```

**关键设计**：

- **树形导航是效率的核心**：把「一次评估」当成一棵树（客户 → 主机 → 服务 → 发现 → 证据），**写报告时只是「把树填满」**，不需要再组织架构。
- **代码框（CodeBox）**：渗透记录中大量内容是命令与输出。代码框让它们**保持等宽、可高亮、可复制**，而不是被 Word 自动格式化毁掉。
- **单文件 + 加密**：`.ctb` 是 SQLite，**可以设口令加密**。这对含客户敏感信息（凭据、内网拓扑、漏洞细节）的笔记很重要——**但加密不等于合规**（见第 9 节）。
- **导入/导出只是"搬运"**：导出成 HTML/PDF 后**格式会简化**（复杂样式可能丢失），**不要把它当排版工具**。要精美排版，导出后用 Word/LaTeX 再加工，或用 Dradis 的模板出报告。

## 3. 安装与快速上手

```bash
sudo apt update
sudo apt install cherrytree
command -v cherrytree
cherrytree --version
```

```console
cherrytree 1.2.0
```

启动：

```bash
cherrytree &
```

**第一次使用的 5 步**：

```
1. File → New File            → 选个路径，命名 case-2026-001.ctb
2. 在左侧树里右键 → Add Node  → 建第一层节点（如 "01-范围与授权"）
3. 继续右键建子节点            → "02-信息搜集"、"03-漏洞"、"04-利用"、"05-后渗透"、"06-报告"
4. 在右侧写内容：
     · 普通文字：直接打字（支持富文本与标题样式）
     · 命令与输出：Insert → CodeBox（或工具栏按钮），粘贴进代码框
     · 图片：Insert → Image（贴截图）
5. 文件 → 保存（.ctb）
```

> **注意**：CherryTree 是**图形界面应用**，命令行的 `cherrytree` 只是启动它。真正的"参数"是菜单与快捷键。

## 4. 核心参数详解

CherryTree 没有有意义的命令行参数，下面给**菜单/快捷操作**与**关键设置**。

### 4.1 高频操作（**记住这些效率翻倍**）

| 目的 | 菜单路径 | 快捷键（常见） |
|------|----------|----------------|
| 新建文件 | `File → New File` | —— |
| 保存 | `File → Save` | `Ctrl+S` |
| **新建节点**（当前层之后） | 右键 → `Add Node` ／ 工具栏 | `Ctrl+Alt+N`（视版本） |
| **新建子节点** | 右键 → `Add Child Node` | —— |
| 新建同级节点（带名称） | 右键 → `Add Node After…` | —— |
| 重命名节点 | 右键 → `Rename` | `F2` |
| 删除节点 | 右键 → `Delete Node` | —— |
| **搜索** | `Search → Find in Nodes` | `Ctrl+F` |
| **插入代码框** | `Insert → CodeBox` | 工具栏 |
| 插入图片 | `Insert → Image`（也可直接粘贴） | —— |
| 插入表格 | `Insert → Table` | —— |
| 插入链接（外部 URL） | `Insert → Link` | —— |
| **链接到其它节点**（内部跳转） | `Insert → Link → Node` | —— |
| 设置节点图标/颜色 | 右键 → `Node Properties` | —— |
| 加标签（Tag） | 节点属性 / 标签面板 | —— |
| 书签 | `Bookmarks → Add Bookmark` | —— |
| **导出** | `File → Export` | —— |
| 导入 | `File → Import` | —— |
| 设置口令加密 | `File → Properties` / 另存时设置密码 | —— |
| 偏好设置 | `Edit → Preferences` | —— |

### 4.2 导出格式与用途

| 导出格式 | 用途 | 注意 |
|----------|------|------|
| **HTML**（单文件/多文件） | 交付、内网传阅 | 样式会简化；图片会另存或内嵌 |
| **PDF** | 交付给客户 | 中文需注意字体与渲染；复杂排版建议导出后二次加工 |
| **纯文本** | 快速复制到别处 | 丢失格式 |
| **Markdown** | 进 Git / 静态站点 | 代码框会转成围栏代码块 |
| **CherryTree**（另存） | 归档/模板 | —— |

### 4.3 适合渗透记录的节点结构模板（**直接抄**）

```
▸ 00-项目信息
    · 客户/项目名、授权范围（IP/域名/时间窗）、联系人、紧急联系人
    · 授权书要点摘录（哪些手法被允许、哪些不允许）
▸ 01-环境与目标
    · 攻击机配置、工具版本、网络拓扑（贴图）
    · 目标清单（IP/域名/端口）
▸ 02-信息搜集
    · 每台主机一个子节点：nmap 输出（代码框）、服务指纹
    · 目录/子域/账号枚举结果
▸ 03-漏洞发现
    · 每个漏洞一个子节点：标题、影响、复现步骤、证据（截图/输出）、修复建议
    · 用统一编号（如 VULN-001）便于在报告里引用
▸ 04-利用过程
    · 时间线 + 命令 + 输出（**代码框**）
    · 失败尝试也要记（对报告有价值）
▸ 05-后渗透与横向
    · 提权路径、凭据来源、横向路径（**脱敏**）
▸ 06-清理与收尾
    · 删除了什么（后门/计划任务/上传文件）、何时
▸ 07-报告素材
    · 指标、风险评级、管理层摘要草稿
```

**为什么这个结构有效**：**「写报告」变成「整理这棵树的顺序」**——因为过程记录（04/05）与报告素材（07）是**同源**的，不需要在结束后重新回忆。

## 5. 实战演练

> **环境声明**：以下使用**自建靶场**（自建 AD/虚拟机、TryHackMe、HTB、VulnHub）的演练过程作为记录对象。**笔记内容可能包含客户敏感信息，请按第 9 节的合规要求管理。**

### 场景 1：建立"一个项目一棵树"的记录习惯（从第一次动手就开始）

```bash
# 启动并新建项目笔记
cherrytree /evidence/notes/case-2026-001.ctb &
```

```console
（GUI 打开；文件不存在时会提示新建）
```

**Step 1：在树上建好骨架**

```
右键根 → Add Child Node  → "00-项目信息"
右键根 → Add Child Node  → "01-环境与目标"
右键根 → Add Child Node  → "02-信息搜集"
右键根 → Add Child Node  → "03-漏洞发现"
右键根 → Add Child Node  → "04-利用过程"
右键根 → Add Child Node  → "05-后渗透与横向"
右键根 → Add Child Node  → "06-清理与收尾"
右键根 → Add Child Node  → "07-报告素材"
```

**Step 2：在「00-项目信息」里写授权要点（**这是最重要的一节**）**

```
授权范围：192.168.56.0/24（内部演练网段）
时间窗：2026-03-01 09:00 ~ 2026-03-05 18:00
允许手法：端口扫描、漏洞验证、低风险利用、凭据复用
不允许：DoS、社工、破坏性利用、生产数据导出
紧急联系人：<姓名/电话>
授权编号：AUTH-2026-001
```

**解读**：**把「授权边界」放在树的最顶端**，因为它是**整个项目的法律与合规锚点**。测试中任何"要不要试一下"的犹豫，都应该回来读这一段。

**Step 3：收集到结果就立刻记录（**别攒到最后**）**

```bash
# 记录扫描结果时，直接复制终端输出（保持原样）
nmap -sV -p- 192.168.56.102 | tee /tmp/nmap_102.txt
```

在 CherryTree 的「02-信息搜集」下建子节点 `192.168.56.102` →
`Insert → CodeBox` → 粘贴输出：

```
Nmap scan report for 192.168.56.102
PORT     STATE SERVICE  VERSION
21/tcp   open  ftp      vsftpd 2.3.4
22/tcp   open  ssh      OpenSSH 4.7p1 Debian 8ubuntu1
80/tcp   open  http     Apache httpd 2.2.8
```

**解读**：**「过程记录」和「报告素材」是同源的**。如果你在测试时就记好了（含命令与输出），**写报告时只需要挑内容、调顺序、加结论**——工作量减少一半以上。

### 场景 2：写一条完整的漏洞记录（**可复制的模板**）

在「03-漏洞发现」下建子节点 `VULN-001 vsftpd 2.3.4 后门`，内容如下：

```
【标题】vsftpd 2.3.4 后门导致远程命令执行

【风险等级】Critical（CVSS 3.1: 9.8）
【受影响资产】192.168.56.102:21 (vsftpd 2.3.4)

【漏洞描述】
vsftpd 2.3.4 发行包中被植入后门：当用户名以 ":)" 结尾时，
服务在 6200 端口开一个 root shell。攻击者无需凭据即可获取
目标主机的最高权限。

【复现步骤】
1) 触发后门
   （此处插入 CodeBox）
   $ ftp 192.168.56.102
   Name: user:)
   $ nc 192.168.56.102 6200
   
2) 验证权限
   （CodeBox）
   # id
   uid=0(root) gid=0(root)

【证据】
（Insert → Image：终端截图，注意脱敏）

【影响分析】
- 直接获取 root，可读写全部数据、安装后门、横向移动
- 该服务对外暴露（不在防火墙后）

【修复建议】
1. 升级 vsftpd 到 3.0.3 以上（或发行版修复版本）
2. 如无 FTP 业务需求，直接卸载 vsftpd 并关闭 21 端口
3. 在防火墙层面限制 21/6200 的访问来源
4. 排查是否已被植入其它后门（参考清理章节）

【参考】
- CVE-2011-2523
- Exploit-DB: 17491
```

**解读**：**这条记录已经是一份完整的报告章节**。这份模板的价值在于**结构固定**：
`标题 → 等级 → 资产 → 描述 → 复现 → 证据 → 影响 → 修复 → 参考`
—— 写第 2 条、第 3 条时只需要填空，**不会漏项**。

**Step：用 CodeBox + 图片把「证据」做扎实**

| 证据类型 | 在 CherryTree 里怎么放 |
|----------|------------------------|
| 命令与输出 | **CodeBox**（保持等宽，可复制复现） |
| 截图 | `Insert → Image`（或直接 Ctrl+V 粘贴） |
| HTTP 请求/响应 | CodeBox（标注是请求还是响应） |
| 文件哈希 | CodeBox（`sha256sum` 输出） |
| 网络拓扑 | 用绘图工具画好 → 插入为图片 |

**⚠️ 脱敏提醒**：截图与输出里**经常带真实凭据、内网 IP、员工姓名**。记录时就要脱敏（见场景 3）。

### 场景 3：脱敏、加密、导出（交付前的三步）

**Step 1：脱敏（**在记录时就做，而不是交付前**）**

| 敏感内容 | 脱敏写法 |
|----------|----------|
| 明文口令 | `Passw0rd!` → `[REDACTED-PASSWORD]`（**只在绝对必要时记录"存在明文口令"这一事实**） |
| NT hash | `31d6cfe0...` → `31d6****（前 4 位留证）` |
| 内网 IP | `10.10.20.5` → 按客户要求（有时可保留，有时需脱敏） |
| 员工姓名 | `张三` → `财务部-用户A` |
| 客户域名 | 按授权约定（报告里可保留，公开材料必须脱敏） |

```bash
# 记录前先处理输出（示例：只保留必要行，避免粘贴整段敏感内容）
grep -E 'uid=|gid=|CVE|EDB-ID' /tmp/output.txt > /tmp/output_safe.txt
```

**Step 2：给笔记加密（**`.ctb` 支持设口令**）**

```
File → Save As… / File → Properties
  → 设置/修改密码（Password）
  → 保存为 .ctb
```

```console
（设置密码后，.ctb 内容加密；打开时需输入口令）
```

**解读**：**加密能防止笔记被随意读取，但不能替代合规**——口令丢失 = 数据丢失；而合规要求（访问控制、留存期限、销毁）是**流程问题**，工具解决不了。

**Step 3：导出（按交付对象选择格式）**

```
File → Export
  → Export to HTML        （内网传阅 / 归档）
  → Export to PDF         （交付客户，注意中文字体）
  → Export to Plain Text  （快速复制）
  → Export to Markdown    （进 Git 或静态站点）
```

```bash
# 导出后的产物检查（尤其是 PDF 的中文与图片是否正常）
ls -lh /evidence/notes/export/
```

**解读**：**导出的 PDF 一定要通读一遍**。常见问题：中文字体缺失（显示方块）、代码框换行错乱、图片丢失。**交付前逐页检查是专业习惯。**

**Step 4：把结果汇总进 Dradis（团队/正式报告场景）**

```bash
# Dradis 负责多人协作与按模板出报告
sudo dradis-start        # http://127.0.0.1:3000
```

```console
[*] Web UI: http://127.0.0.1:3000
```

在 Dradis 里把 CherryTree 中的每条「VULN-xxx」整理成 `Issue`（见 [`dradis.md`](dradis.md)），
最后由 Dradis 的模板生成统一格式的报告。

## 6. 输出解读

CherryTree 的输出就是**你自己的笔记**，所以"解读"主要在于**结构与完整性检查**。

### 6.1 一份合格的渗透笔记应包含

| 检查项 | 为什么重要 |
|--------|------------|
| **授权范围与时间窗**（树顶部） | 任何争议时的第一份依据 |
| **每台目标都有独立节点** | 避免遗漏资产；便于逐台跟进 |
| **每条漏洞都有：复现步骤 + 证据 + 影响 + 修复建议** | 报告的完整性；**修复建议是客户真正要的东西** |
| **命令与输出在 CodeBox 里**（不是普通段落） | 保证可复制、可复现 |
| **失败尝试也记录** | 「我试过 A 不行，所以走了 B」在报告里是有价值的判断依据 |
| **脱敏处理** | 合规底线 |
| **清理与收尾记录** | 证明「测试结束后移除了所有后门/上传文件」 |
| **时间戳**（关键动作） | 与客户日志对齐、便于事后核查 |

### 6.2 结构自检（快问快答）

| 问题 | 合格答案 |
|------|----------|
| 客户问「你测了哪些 IP」 | 打开「01-环境与目标」，一屏列出 |
| 客户问「这个漏洞怎么复现」 | 打开 VULN-xxx，命令可直接复制 |
| 客户问「你改动了什么」 | 打开「06-清理与收尾」 |
| 审核问「授权范围是什么」 | 打开「00-项目信息」 |
| 自己问「上次那个命令在哪」 | `Ctrl+F` 搜索 |

## 7. 与其他工具配合

```
① 侦察/扫描/利用（工具产出）
   nmap / gobuster / sqlmap / metasploit / impacket …
        │  输出 → 复制到 CherryTree 的 CodeBox
        ▼
② 过程记录（本文）
   CherryTree（树形笔记：主机 → 服务 → 漏洞 → 证据 → 修复建议）
        │
        ├─► 导出 HTML/PDF（交付初稿）
        ├─► 导出 Markdown（进 Git / 静态站点）
        └─► 整理到 Dradis（团队协作 + 模板化正式报告）  ← dradis.md
        │
③ 结果可视化/统计
   Cherrytree 写草稿 → Dradis 出正式报告 → 表格化指标
```

**与扫描器输出的衔接技巧**：

```bash
# 1) 把扫描输出落到文件（便于粘贴或导入）
nmap -sV -oN /tmp/nmap.txt 192.168.56.0/24
```

## 8. 常见坑与排错

| 报错/现象 | 原因 | 解决 |
|-----------|------|------|
| `cherrytree` 启动报 GTK/依赖错误 | 缺图形依赖或不在图形会话中 | 在图形环境运行；`sudo apt -f install` 补依赖 |
| 远程（SSH）启动失败 | 无 X 显示 | 用 `ssh -X`（X11 转发）或在本机 GUI 使用 |
| 中文显示为方块 | 缺中文字体 | `sudo apt install fonts-noto-cjk` |
| 粘贴代码后格式乱 | 直接粘进富文本区 | **用 `Insert → CodeBox`** 再粘贴 |
| 导出的 PDF 中文丢失 | 字体/渲染 | 装中文字体后重新导出；必要时改用 HTML 导出 |
| 导出的 HTML 图片丢失 | 多文件导出路径问题 | 选"单文件 HTML"（内嵌资源）或检查资源目录 |
| 文件打不开 | 格式不兼容/版本差异 | `.ctb` 是 SQLite，跨大版本可能不兼容 → **用同版本或导出为 HTML 归档** |
| 忘记口令 | `.ctb` 加密后无法恢复 | **无法找回**（设计如此）→ 口令与密钥一起备份在密码管理器里 |
| 多人同时编辑同一文件 | CherryTree 是单机应用 | 改文件会互相覆盖 → **团队协作用 Dradis** |
| 文件放 Git 里 diff 很差 | `.ctb` 是二进制 | 需要版本化就**导出 Markdown 再进 Git** |
| 笔记越来越大、越来越慢 | 单文件塞了太多内容（大量图片） | 按项目拆分文件；图片压缩后再插入 |
| 导出的报告被客户抱怨"信息泄露" | 未脱敏 | **在记录时就脱敏**（见场景 3），交付前逐页检查 |

## 9. 防御视角（蓝队 / 项目管理）

CherryTree 是**记录工具**，但它承载的内容是**极高敏感度的资产**——客户内网拓扑、漏洞细节、凭据、员工信息。

| 风险 | 后果 | 应对 |
|------|------|------|
| 笔记丢失/损坏 | 整个项目返工；无法证明做过什么 | **定期备份**（`.ctb` + 同步到加密存储）；重要节点导出 HTML 归档 |
| 笔记泄露 | **可能直接构成客户数据泄露事件** | **口令加密**；存放在加密磁盘/加密容器；不开云同步（除非合规允许） |
| 笔记被前员工带走 | 客户信息泄露 | 项目结束按合同**销毁副本**；离职交接流程覆盖"个人笔记文件" |
| 笔记里的真实凭据被误用 | 法律风险（超授权） | **记录时就脱敏**；在树顶部写明"不得用于授权范围外" |
| 时间窗外的操作被质疑 | 无法自证清白的操作 = 违规 | **在笔记中记录每个关键动作的时间戳**（这既是记录也是自证材料） |
| 缺少授权记录 | 争议时无法举证 | 「00-项目信息」里保存**授权书要点与编号** |

**给安全团队的三条建议**：

1. **把"记录规范"制度化**（本节的节点结构模板可以直接作为团队规范）；
2. **要求笔记加密 + 项目结束销毁**（并在合同中写明）；
3. **把「授权范围/时间窗/允许手法」作为模板的必填项**——这能显著减少超授权操作的风险。

## ⚠️ 法律与伦理

CherryTree 本身是**完全中立的笔记软件**，风险全部来自**你记了什么**：

- **未经授权的测试记录**：笔记会**成为你和客户的"犯罪证据"** —— 记录里有目标 IP、时间、使用的工具与命令。**未授权测试的记录会直接指向违法行为**（《刑法》第 285/286 条）。
- **客户数据与个人信息**：笔记中的凭据、员工信息、内网拓扑属于敏感数据，未妥善保管或超出授权范围使用，可能触发《个人信息保护法》《数据安全法》责任，并违反与客户的保密协议（NDA）。
- **凭据保存**：**不要保存明文口令**（除非客户明确要求且你有加密与销毁流程）。记录时脱敏是**专业标准**，也是**自我保护**。

**操作要求**：

1. **只记录你有授权测试的内容**；
2. **在树顶部写明授权范围、时间窗、允许手法**（这既是纪律也是自证）；
3. **笔记加密 + 加密存储 + 定期备份**；
4. **记录时就脱敏**（口令、hash、姓名、无关的个人信息）；
5. **项目结束按合同销毁副本**，并在笔记里记录"已销毁"（保留销毁确认）；
6. **不要在个人设备上留存客户敏感笔记**（或确保设备加密与访问控制达标）。
