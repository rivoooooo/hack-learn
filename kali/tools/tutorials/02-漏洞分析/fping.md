# fping（批量 ICMP 存活探测）

> **一句话**：一次给几百上千个目标发 ICMP echo，用轮转（round-robin）方式并发探测，输出为脚本友好格式。
> **分类**：漏洞分析 ｜ **Kali 包**：`fping` ｜ **官方文档**：<https://fping.org/>

## 1. 它解决什么问题

标准的 `ping` 是**串行**的：对一个目标等到超时或回复，再处理下一个。扫 254 台主机、每台 1 秒超时，就要 4 分钟——而且大部分时间在等待。

fping 的模型完全不同：**发出一批包后立刻处理下一个目标**，回包异步收集。同一个 C 段通常 1~2 秒扫完。

| 工具 | 探测方式 | 速度 | 输出 |
|------|---------|------|------|
| `ping` | ICMP，单目标，串行 | 慢 | 人类可读 |
| **fping** | ICMP，多目标，轮转并发 | **快** | **脚本友好（一行一结果）** |
| [nmap](../01-信息搜集/nmap.md) `-sn` | ICMP/ARP/TCP 多种 | 中 | 详细 |
| [arp-scan](../01-信息搜集/arp-scan.md) | ARP（二层） | 最快 | 只在同网段 |
| [masscan](../01-信息搜集/masscan.md) | 异步 TCP | 极快 | 端口级 |

**关键取舍**：fping 只做 ICMP，所以**禁 ping 的主机会漏掉**（假阴性）。要最完整的内网存活清单用 [arp-scan](../01-信息搜集/arp-scan.md)；要跨网段就用 [nmap](../01-信息搜集/nmap.md) `-sn -PS`（TCP SYN 探测）。fping 的强项是**极简的管道用法**——它是"存活清单生成器"。

> 注意：Kali 把 fping 归在 **漏洞分析（vulnerability）** 分类下（见 `data/kali-tools.tsv`），但它实际上是个网络探测工具。本教程按它的实际用途归入信息搜集的工作流里。

## 2. 工作原理

```text
   fping -a -g 192.168.56.0/24
        │
   ┌────┴──────────────────────────────────────────────────────┐
   │ ① -g 从网段生成目标列表（自动排除网络地址与广播地址）        │
   │    得到 [192.168.56.1, .2, ..., .254]                      │
   └────┬──────────────────────────────────────────────────────┘
        │
   ┌────┴──────────────────────────────────────────────────────┐
   │ ② 轮转发送（round-robin）                                  │
   │    - 给 .1 发一个 ICMP echo request                        │
   │    - 立刻给 .2 发，再 .3 …（不等回复）                      │
   │    - -i 控制相邻两个包之间的最小间隔（默认 10ms）            │
   │    - 全部发完后，回到起点继续发（如果 -r 还有重试额度）       │
   └────┬──────────────────────────────────────────────────────┘
        │
   ┌────┴──────────────────────────────────────────────────────┐
   │ ③ 异步接收与状态维护（需要 raw socket / CAP_NET_RAW）        │
   │    - 收到回复 → 标记该目标 alive，**从待查列表移除**          │
   │    - -t 内没回复 → 按 -B（默认 1.5）倍增等待时间后重发         │
   │    - 重试 -r 次（默认 3）仍无回复 → 标记 unreachable          │
   └────┬──────────────────────────────────────────────────────┘
        │
   ┌────┴──────────────────────────────────────────────────────┐
   │ ④ 输出（默认只打印不可达目标，这是最反直觉的一点）            │
   │    -a  只打印存活          -u  只打印不可达                  │
   │    -e  显示 RTT            -d  显示主机名而非 IP             │
   │    -c N 每个目标发 N 个包（打印每个回复 + 统计）              │
   │    -C N 同 -c 但统计格式面向自动化                           │
   │    -l  无限循环             -s  结束时打印累计统计            │
   └────────────────────────────────────────────────────────────────┘
```

几个要点：

- **默认输出"不可达"是被设计出来的**：这样你可以直接 `fping < list` 只看失败项。要看存活的必须显式加 `-a`——这是新手最常踩的坑。
- **`-i` 是最重要的性能参数**：默认包间隔 10ms，扫 /24 约 2.5 秒。调到 1ms 会快很多，但可能丢包（尤其老设备）。
- **`-t` + `-B` + `-r` 决定"慢目标"的额外开销**：默认 500ms × 1.5^n，重试 3 次。跨网段慢链路需要调大 `-t`。
- **`-g` 会自动排除网络地址与广播地址**，比手写范围更省心。
- **退出码可用于脚本判断**：`0` 全部可达、`1` 有主机不可达、`2` 有 IP 无法解析、`3` 参数错误、`4` 系统调用失败。

## 3. 安装与快速上手

```bash
sudo apt install fping
fping --version
man fping
```

最小可用命令：

```bash
# 1) 扫整个 C 段，只列存活主机
fping -a -g 192.168.56.0/24

# 2) 从 stdin 读目标列表
fping -a < hosts.txt

# 3) 每个目标发 5 个包，看丢包与延迟
fping -c 5 192.168.56.101 192.168.56.102
```

## 4. 核心参数详解

### 目标指定

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `<systems...>` | 目标列表（可多个） | 少量目标直接给 |
| `-g, --generate <addr/mask>` | 从网段或起止 IP 生成目标；**已有网段掩码时会排除网络地址与广播地址** | `-g 192.168.1.0/24` 或 `-g 192.168.1.1 192.168.1.254` |
| `-f, --file <file>` | 从文件读目标（**仅 root 可用**） | 非 root 用 `fping < file` 代替 |
| `-4, --ipv4` / `-6, --ipv6` | 限定名称解析与 IP 版本 | 双栈环境 |
| `-m, --all` | 对一个主机的**所有** IP 都发（配 `-A` 更好） | 多 A 记录 |

### 输出控制（最常改的一组）

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `-a, --alive` | **只显示存活的主机** | **几乎每次都要加** |
| `-u, --unreach` | 只显示不可达的主机 | 反向使用 |
| `-A, --addr` | 显示 IP 而非 DNS 名；配 `-d` 时同时给 IP 和主机名 | 想要原始 IP 时 |
| `-d, --rdns` | 强制做反向 DNS 解析（NAME→IP→NAME） | 想拿主机名时 |
| `-n, --name` | 目标给的是 IP 时做反向解析，输出主机名 | 与 `-d` 的区别见第 8 节 |
| `-e, --elapsed` | 显示往返时间 | 配合 `-a` 看延迟排行 |
| `-q, --quiet` | 不显示每个探测结果，只显示最终汇总；也不显示 ICMP 错误 | 脚本化 |
| `-Q, --squiet <sec>` | 类似 `-q`，但每隔 N 秒显示一次区间汇总 | 长时间监控 |
| `-s, --stats` | 退出时打印累计统计 | 留档 |
| `-D, --timestamp` | 给循环/计数模式的输出行加 Unix 时间戳 | 配合 `-l`/`-c`/`-C` |
| `-o, --outage` | 按丢包数与间隔计算"中断时长" | 网络收敛测试 |
| `-N, --netdata` | 输出适配 netdata 的格式（需 `-l -Q`） | 监控集成 |

### 时序与准确性

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `-c, --count <n>` | 每个目标发 n 个包，逐回复打印 + 末尾统计 | 测丢包/抖动 |
| `-C, --vcount <n>` | 类似 `-c`，但统计格式面向自动化 | **拿到每个包的 RTT 用这个** |
| `-l, --loop` | 无限循环发送（Ctrl-C 中断并打印统计） | 持续监控 |
| `-p, --period <ms>` | 循环/计数模式下，同一目标相邻包的间隔（默认 1000，最小 10） | 与 `-i` 区分：`-i` 是**任意两包**间隔，`-p` 是**同一目标**间隔 |
| `-i, --interval <ms>` | 任意两个发送包之间的最小间隔（默认 10，最小 1） | 提速关键；非 root 不得 <1ms（见 safe-limits） |
| `-t, --timeout <ms>` | 初始超时（默认 500ms）；后续超时 × `-B` | 跨网段/慢链路调大 |
| `-B, --backoff <n>` | 超时倍增因子（浮点，默认 1.5） | 一般不用改 |
| `-r, --retry <n>` | 重试次数（默认 3，不含首次） | 丢包环境加大 |
| `-b, --size <bytes>` | 载荷字节数（默认 56，最小 12） | MTU 相关测试 |
| `-M, --dontfrag` | 设置 DF（不分片）位 | **MTU 发现** |
| `-H, --ttl <n>` | 设置 IP TTL | — |
| `-O, --tos <n>` | 设置 TOS（十进制或 0xh） | — |
| `-R, --random` | 用随机字节填充载荷（而非全零） | 破解链路数据压缩 |
| `-S, --src <addr>` | 设置源地址 | 多网卡 |
| `-I, --iface <iface>` | 绑定网卡（需 SO_BINDTODEVICE 支持） | 多网卡 |
| `-x, --reachable <N>` | 可达主机数 ≥ N 时退出并返回真 | **脚本里的"健康检查"** |

### 其他

| 参数 | 作用 |
|------|------|
| `-h, --help` | 打印用法 |
| `-v, --version` | 打印版本 |

**`-C` 的输出格式**（这是自动化最喜欢的形式）：

```bash
$ fping -C 5 -q somehost
somehost : 91.7 37.0 29.2 - 36.8
```

格式是 `主机 : RTT1 RTT2 ... RTTn`，用 `-` 表示该次没收到回复。**直接可被 awk 处理**。

## 5. 实战演练

**环境**：本地 VirtualBox Host-Only 网络 `192.168.56.0/24`。攻击机 Kali（`192.168.56.10`）；靶机 Metasploitable2 `192.168.56.101`、DVWA `192.168.56.102`；宿主机接口 `192.168.56.1`。

> fping 只发 ICMP echo，属于最轻量的探测，但它同样是**主动扫描**。**只对你拥有或已获得书面授权的网段使用**；公网目标只有 `scanme.nmap.org` 这类明确允许扫描的地址才可以低频探测。下面所有演练都在上述自建内网中进行。

### 场景 1：一条命令拿到存活主机清单

```bash
fping -a -g 192.168.56.0/24 2>/dev/null
```

预期输出片段：

```text
192.168.56.1
192.168.56.10
192.168.56.101
192.168.56.102
```

解读：`-g` 生成整个 C 段（自动跳过 `.0` 和 `.255`），`-a` 只输出存活的主机。**这就是最快得到"活口清单"的方式**，几秒钟完成。生成的清单直接就能喂给 [nmap](../01-信息搜集/nmap.md)。

**带延迟信息的版本**：

```bash
fping -a -e -g 192.168.56.0/24 2>/dev/null | tee alive_rtt.txt
sort -k2 -n alive_rtt.txt | head -5     # 按 RTT 排序，最快的前 5 个
```

预期输出片段：

```text
192.168.56.10  0.043
192.168.56.1   0.412
192.168.56.101 0.523
192.168.56.102 0.498
```

### 场景 2：从文件读目标（非 root 的正确姿势）

```bash
# 第一步：用 nmap 或 arp-scan 产出候选清单
sudo arp-scan -I eth1 --localnet --plain --quiet | awk '{print $1}' > candidates.txt

# 第二步：非 root 用 stdin（-f 需要 root）
fping -a < candidates.txt > alive.txt
wc -l alive.txt

# 第三步：想知道主机名
fping -a -d < candidates.txt
```

预期输出片段：

```text
192.168.56.101
...
192.168.56.101 (metasploitable.lab)
```

解读：`-f` 需要 root，普通用户用 stdin 重定向即可。`-d` 强制反解，输出里会带主机名——这对资产识别很有用（但要注意反解会很慢，且内网 DNS 不一定有 PTR 记录）。

### 场景 3：测丢包与延迟分布（`-c` / `-C`）

```bash
# 每个目标发 10 个包
fping -c 10 -q 192.168.56.101 192.168.56.102
```

预期输出片段：

```text
192.168.56.101 : xmt/rcv/%loss = 10/10/0%, min/avg/max = 0.42/0.51/0.68
192.168.56.102 : xmt/rcv/%loss = 10/10/0%, min/avg/max = 0.44/0.49/0.61
```

**想要每个包的 RTT（自动化友好）**：

```bash
fping -C 5 -q 192.168.56.101 8.8.8.8
```

预期输出片段：

```text
192.168.56.101 : 0.42 0.51 0.48 - 0.68
8.8.8.8        : 12.3 11.8 - 12.1 11.9
```

解读：
- `xmt/rcv/%loss` = 发送数/接收数/丢包率。
- `min/avg/max` = 最小/平均/最大 RTT（毫秒）。
- `-C` 的输出里 `-` 表示该次无回复。上面 `192.168.56.101` 的第 4 个包丢了（内网偶发丢包，正常）。
- 用 `awk` 直接算平均丢包率：

```bash
fping -C 10 -q -g 192.168.56.0/24 2>/dev/null | \
  awk -F'[: ]+' '{for(i=2;i<=NF;i++) if($i!="-"&&$i!="") {s+=$i;n++}} END {print "平均 RTT:", s/n, "ms（基于", n, "个响应）"}'
```

### 场景 4：持续监控 + MTU 探测

```bash
# 持续监控一台关键主机（Ctrl-C 停止并打印统计）
fping -l -p 1000 192.168.56.101

# 用 DF 位找路径 MTU（逐步加大载荷直到不再有回复）
for s in 1472 1473 1500; do
  printf "size=%-6s " "$s"
  fping -M -b $s -c 1 -q 8.8.8.8 2>&1 | tail -1
done
```

预期输出片段（监控）：

```text
192.168.56.101 : [0], 84 bytes, 0.42 ms (0.42 avg, 0% loss)
192.168.56.101 : [1], 84 bytes, 0.51 ms (0.47 avg, 0% loss)
^C
192.168.56.101 : xmt/rcv/%loss = 2/2/0%, min/avg/max = 0.42/0.47/0.51
```

解读：
- `-l` 是**无限循环**，只有 Ctrl-C 能停；Ctrl-C 会触发统计打印（也可用 SIGQUIT）。
- MTU 探测中，`-M` 置 DF 位、`-b 1472` 对应 1500 字节的以太网帧（1472 + 8 ICMP + 20 IP = 1500）。如果 1473 开始无响应，说明路径 MTU 是 1500。

### 场景 5：脚本化的健康检查（`-x` + 退出码）

```bash
#!/bin/bash
# 网关 + 关键服务存活检查：要求至少 2 个可达才算健康
TARGETS="192.168.56.1 192.168.56.101 192.168.56.102"
if fping -x 2 -q $TARGETS 2>/dev/null; then
  echo "健康：至少 2 个目标可达"
else
  echo "告警：可达目标少于 2 个"
  exit 1
fi

# 用退出码判断（0=全可达, 1=部分不可达）
fping -q -g 192.168.56.0/24 >/dev/null 2>&1
case $? in
  0) echo "全部可达" ;;
  1) echo "存在不可达主机" ;;
  2) echo "有 IP 无法解析" ;;
  3) echo "参数错误" ;;
  4) echo "系统调用失败" ;;
esac
```

解读：`-x N` 直接把"可达主机数够不够"变成布尔判断，非常适合放进监控脚本或 CI 前置检查。退出码则适合区分不同的失败原因。

## 6. 输出解读

### 默认模式（无 `-c`/`-l`）

| 输出 | 含义 |
|------|------|
| `192.168.56.101 is alive` | 该目标有响应（**默认模式会打印存活项**） |
| `192.168.56.200 is unreachable` | 重试耗尽仍无响应 |
| 空输出 | 加了 `-a` 但没有任何目标存活；或加了 `-q` |

> 实测中更常见的是：**不加 `-a` 时输出大量 `is unreachable`，加 `-a` 后只输出 IP**。这是 fping 与 ping 最大的体验差异。

### 计数/循环模式

| 字段 | 含义 |
|------|------|
| `xmt/rcv/%loss` | 发送数 / 接收数 / 丢包率 |
| `min/avg/max` | 最小 / 平均 / 最大 RTT（毫秒） |
| `[n]` | 第 n 个包（从 0 开始） |
| `84 bytes` | 收到的包大小（含 IP 20 + ICMP 8 + 数据 56） |
| `-`（`-C` 输出中） | 该次探测无响应 |

### 退出码

| 码 | 含义 | 脚本里的用法 |
|----|------|-------------|
| `0` | 所有主机可达 | 成功分支 |
| `1` | 有主机不可达 | 告警分支 |
| `2` | 有 IP 地址无法解析 | 检查输入 |
| `3` | 命令行参数非法 | 检查参数 |
| `4` | 系统调用失败（常见于权限不足） | 检查 root/RAW socket 权限 |

### 判断要点

- **fping 报"不可达"不等于主机不在线**：目标可能禁 ICMP（很常见）。跨网段排查请用 [nmap](../01-信息搜集/nmap.md) `-sn -PS22,80,443`；同网段请用 [arp-scan](../01-信息搜集/arp-scan.md)。
- **`%loss` 在内网应该是 0**。出现 1%~5% 的丢包说明链路有问题（或用 `-i` 发太快被设备丢弃）。
- **`-i` 调太小会自造丢包**：`-i 1` 在老交换机上可能造成大量假"不可达"。加速后一定要用 `-c 10` 复验。

## 7. 与其他工具配合

```bash
# ★ 1) fping 生成存活清单 -> nmap 精扫（最经典的组合）
fping -a -g 192.168.56.0/24 2>/dev/null > alive.txt
sudo nmap -sV -iL alive.txt --open -oA fping_then_nmap

# 2) fping 与 arp-scan 互补，取并集降低假阴性
sudo arp-scan -I eth1 --localnet --plain --quiet | awk '{print $1}' | sort -u > arp_alive.txt
fping -a -q -g 192.168.56.0/24 2>/dev/null | sort -u > icmp_alive.txt
comm -3 arp_alive.txt icmp_alive.txt    # 只在一侧出现的主机 = 需要复核的目标

# 3) nmap 发现端口 -> 提取主机 -> fping 确认是否在线
sudo nmap -p445 --open -oG - 192.168.56.0/24 | awk '/445\/open/{print $2}' | sort -u > smb.txt
fping -a < smb.txt

# 4) 生成监控用的 RTT 时间序列
while true; do
  fping -C 1 -q 192.168.56.101 2>/dev/null | awk -v t="$(date +%s)" '{print t, $3}'
  sleep 60
done >> rtt_timeseries.log

# 5) 与 netdiscover/nbtscan 串联，补主机名
fping -a -g 192.168.56.0/24 2>/dev/null > alive.txt
nbtscan -f alive.txt
```

## 8. 常见坑与排错

| 现象 | 原因 | 解决 |
|------|------|------|
| 输出全是 `is unreachable`，看不到存活项 | 默认模式的行为，且没加 `-a` | 加 `-a` |
| `fping: can't create socket (must run as root?)` | ICMP 需要 raw socket | `sudo`；或 `setcap cap_net_raw+ep $(which fping)` |
| `-f` 报权限错误 | `-f` 仅 root 可用 | 用 stdin：`fping -a < file` |
| 明明在线的主机报 unreachable | 目标禁 ICMP | 改用 [arp-scan](../01-信息搜集/arp-scan.md)（同网段）或 [nmap](../01-信息搜集/nmap.md) `-PS`（跨网段） |
| 加速后丢包率飙升 | `-i` 设得太小，被交换机/目标丢弃 | `-i 5` 或更大；加 `-r 2` |
| 跨网段大量 unreachable | 默认 500ms 超时太短 | `-t 2000 -r 3` |
| `-n` 和 `-d` 分不清 | `-n`：目标是 IP 时做反解；`-d`：**强制**反解，即使给的是主机名（NAME→IP→NAME） | 想拿主机名用 `-d`；只给 IP 想要名字用 `-n` |
| `-l` 停不下来 | 无限循环 | Ctrl-C（会打印统计）；或 `kill` |
| 非 root 用 `-i 0.5`、`-p 5` 被拒 | 编译时启用了 safe-limits | 用 root，或用更大的间隔值 |
| 扫大网段（/16）非常慢 | 目标数 × 包间隔 | 先 `-g 10.0.0.0/24` 分段扫，或用 [masscan](../01-信息搜集/masscan.md) |
| IPv6 目标扫不到 | 默认可能只走 IPv4 | 显式 `-6`；注意 fping6 命令已在现代版本合并进 `fping -6` |

## 9. 防御视角（蓝队）

- **fping 的流量特征**：与 [nmap](../01-信息搜集/nmap.md) `-sn` 类似——从单个源 IP 对大量目标发 ICMP echo request，回包率可控，节奏均匀。
- **检测**：
  - **ICMP 速率**：正常主机很少对上百个不同 IP 发 ICMP。对"单源 IP 在 N 秒内访问的目标 IP 数量"做阈值是最直接的规则。
  - **ICMP 大小与内容**：fping 默认载荷 56 字节全零。有些 IDS 会对"I​​CMP payload 全零"的特征识别（但真 ping 也是全零，容易误判，仅供参考）。
  - **无应用层后续**：打完 ICMP 就没有任何 TCP 连接，这在流量基线上是明显的。
- **缓解**：
  - **限制 ICMP 速率**：`iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 1/s -j ACCEPT`，其余 DROP。这能抑制扫描速度但**不能阻止发现**。
  - **注意副作用**：完全禁 ping 会破坏 PMTUD（路径 MTU 发现），导致大包被静默丢弃、TCP 卡在握手后的数据传输阶段。**正确做法是"限速"而非"全禁"**。
  - **禁 ping 实际收益很低**：禁 ping 只是让 ICMP 扫描失效，攻击者用 TCP SYN（[nmap](../01-信息搜集/nmap.md) `-PS`）照样能发现主机。所以**不要把禁 ping 当成安全措施**——它的价值是减少噪声，不是防护。
- **对"禁 ICMP"的常见误解**：很多厂商文档把"禁用 ICMP echo"列为加固项，但这实际上会**降低可运维性**（无法做连通性监测）而安全收益接近于零。更合理的做法是：允许 ICMP echo，但限速并记录异常速率。
- **蓝队可用性**：fping 是很好的**网络健康巡检工具**——把关键资产列表丢给它做定时 RTT/丢包监控，比整套监控系统轻量得多。
